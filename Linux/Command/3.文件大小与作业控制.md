# 文件大小与作业控制命令

这类问题考察的是 Linux 日常排查能力。面试回答时要区分“文件逻辑大小”“实际占用磁盘块大小”和“Shell 作业”这几个概念。

## 1. 查看文件大小

常用命令：

```bash
ls -lh file
stat -c '%s bytes' file
du -h file
wc -c < file
```

区别：

| 命令 | 含义 | 适用场景 |
| --- | --- | --- |
| `ls -lh file` | 显示目录项中的文件长度，便于人读 | 快速查看普通文件大小 |
| `stat -c %s file` | 精确输出文件逻辑大小，单位字节 | 脚本中取文件大小 |
| `du -h file` | 显示实际占用磁盘块大小 | 排查磁盘空间占用 |
| `wc -c < file` | 读取文件内容并统计字节数 | 验证流式输入或管道数据大小 |

稀疏文件要特别注意：

```bash
truncate -s 1G sparse.dat
ls -lh sparse.dat
du -h sparse.dat
```

`ls` 看到的是逻辑大小，`du` 看到的是实际占用磁盘块大小。日志排查和磁盘容量告警通常更关注 `du`，协议字段、上传文件长度通常更关注 `stat` 或 `ls` 的逻辑大小。

## 2. 把程序放到后台运行

最直接的方式是在命令末尾加 `&`：

```bash
./server &
```

这会让命令成为当前 Shell 的后台作业。需要注意：它仍然和当前终端会话有关，终端关闭时可能收到 `SIGHUP`。

更稳定的后台方式：

```bash
nohup ./server > server.log 2>&1 &
disown -h %1
setsid ./server > server.log 2>&1 &
```

工程上长期运行的服务更推荐交给 `systemd`、Supervisor、Docker、Kubernetes 或进程管理平台，而不是只靠 `nohup`。

## 3. 查看当前终端的任务 PID 和状态

查看当前 Shell 管理的作业：

```bash
jobs -l
```

`jobs -l` 会展示作业号、PID、运行状态和命令，例如 `Running`、`Stopped`、`Done`。

查看当前终端上的进程：

```bash
ps -t "$(tty)" -o pid,ppid,stat,cmd
```

`jobs` 是 Shell 内建命令，只知道当前 Shell 启动和管理的作业；`ps` 从系统进程表查询，适合看当前终端关联的更多进程。

## 4. 前后台切换

常用流程：

```bash
./server
# 按 Ctrl-Z 暂停前台进程
jobs -l
bg %1
fg %1
```

含义：

1. `Ctrl-Z`：给前台进程发送 `SIGTSTP`，使其暂停。
2. `bg %1`：让编号为 1 的作业在后台继续运行。
3. `fg %1`：把编号为 1 的后台作业调回前台继续运行。
4. `kill %1`：向编号为 1 的作业发送信号。

`%1` 是作业号，不是 PID。需要操作进程号时直接使用 PID，例如 `kill 12345`。

## 5. 易错点

1. `cmd &` 只是后台运行，不等于守护进程。
2. 后台作业如果继续写终端，输出仍可能打乱当前命令行，最好重定向日志。
3. `jobs` 只能查看当前 Shell 的作业；换一个终端就看不到之前 Shell 的作业列表。
4. `fg`、`bg` 使用作业号，例如 `%1`；`ps`、`kill` 通常使用 PID。
5. `du` 和 `ls` 的结果不同不一定是错，可能是稀疏文件、文件系统块大小或硬链接导致的。

## 6. 面试回答模板

查看文件大小可以用 `ls -lh` 快速看逻辑大小，用 `stat -c %s` 在脚本里精确取字节数，用 `du -h` 看实际磁盘占用，用 `wc -c` 统计输入字节数。后台运行可以用 `cmd &`，查看当前 Shell 作业用 `jobs -l`，暂停后用 `bg %1` 放到后台、`fg %1` 调回前台。长期服务不能只依赖 `&`，还要考虑 `nohup`、`disown`、`systemd` 或容器编排。
