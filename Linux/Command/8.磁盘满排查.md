# Linux 磁盘满了如何排查

## 1. 问题背景与常见场景

磁盘满（No space left on device）是生产环境中常见的问题，可能导致：
- 应用无法写入日志
- 数据库无法持久化
- 服务崩溃或异常
- 容器无法创建或启动

面试中考察的是**系统化排查思路**，而不是简单背命令。

## 2. 排查思路总览

```
磁盘满问题排查流程：

1. 确认问题表象
   ↓
2. 定位哪个文件系统满了（df -h）
   ↓
3. 确认是磁盘块满还是 inode 满（df -i）
   ↓
4. 定位大目录/大文件（du、find）
   ↓
5. 检查特殊场景（已删除但未释放的文件）
   ↓
6. 清理或扩容
```

## 3. 详细排查步骤

### 3.1 第一步：确认问题表象

```bash
# 常见的报错信息
"No space left on device"
"Disk quota exceeded"
"ENOSPC: there is no space left on device"

# 检查错误日志
dmesg | grep -i "no space"
dmesg | grep -i "disk"
```

### 3.2 第二步：查看哪个文件系统满了

```bash
df -h
```

输出示例：

```text
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1       100G   95G   5G  95% /
/dev/sdb1       500G  500G    0 100% /data
tmpfs            16G   1.6G   15G  10% /dev/shm
```

关键点：
- `Use%` 接近 100% 的是问题分区
- `/data` 满比 `/` 满影响范围更小
- `tmpfs` 是内存文件系统，也可能被占满

### 3.3 第三步：检查 inode 是否满了

```bash
df -i
```

输出示例：

```text
Filesystem      Inodes  IUsed  IFree IUse% Mounted on
/dev/sda1      6553600  23456  6530144    1% /
/dev/sdb1      3276800  3276800       0  100% /data
```

**重要**：inode 满和磁盘块满表现相同（No space left），但原因不同：
- **磁盘块满**：存储空间耗尽
- **inode 满**：文件数量达到上限

inode 满的常见原因：
- 大量小文件（如缓存文件、临时文件）
- 文件系统创建时 inode 数量固定

### 3.4 第四步：定位大目录

```bash
# 查看根目录下各目录占用（不跨文件系统）
du -xhd1 /

# 查看 /var 目录占用
du -xhd1 /var

# 查看具体子目录
du -sh /var/log/*
du -sh /var/tmp/*
du -sh /home/*
```

参数解释：
- `-x`：不跨文件系统
- `-h`：人类可读
- `-d N`：目录深度
- `-s`：汇总

### 3.5 第五步：定位大文件

```bash
# 查找大于 1GB 的文件
find / -type f -size +1G -ls 2>/dev/null

# 查找大于 100MB 的文件
find / -type f -size +100M -ls 2>/dev/null

# 查找某个目录下的最大文件
find /var -type f -exec ls -lh {} \; | sort -k5 -h | tail -20
```

### 3.6 第六步：检查已删除但未释放的文件

这是**最容易被忽略**的场景：

```bash
# 查看已删除但仍被进程占用的文件
lsof +L1

# 查看某个进程的 fd
lsof -p <pid>

# 更详细的输出
lsof +L1 | awk '{print $NF}' | sort | uniq -c | sort -rn | head
```

原理：
- 文件被删除后，如果进程仍持有文件描述符
- 文件的磁盘空间不会立即释放
- 直到所有进程关闭该文件描述符

解决方案：
1. 重启相关进程
2. 截断文件（保留文件描述符但释放空间）：

```bash
# 找到正在写入已删除文件的进程
lsof +L1 | grep deleted

# 安全截断（不关闭 fd）
: > /proc/<pid>/fd/<fd>
```

## 4. 常见问题场景与解决方案

### 4.1 日志文件过大

```bash
# 查看日志目录
du -sh /var/log/*

# 查看最大的日志文件
ls -lhS /var/log/*.log

# 查看日志增长速度
du -h /var/log --time
```

解决方案：

```bash
# 1. 压缩历史日志
gzip /var/log/old.log

# 2. 使用 logrotate 管理日志
cat /etc/logrotate.conf
cat /etc/logrotate.d/nginx

# 3. 手动清理前先确认
find /var/log -name "*.log" -mtime +7 -ls
find /var/log -name "*.log" -mtime +7 -delete
```

### 4.2 数据库数据目录过大

```bash
# MySQL 数据目录
du -sh /var/lib/mysql/*

# PostgreSQL 数据目录
du -sh /var/lib/postgresql/*

# 清理二进制日志（MySQL）
PURGE BINARY LOGS BEFORE '2024-01-01';

# 清理 wal 文件（PostgreSQL）
pg_archivecleanup /wal/path 000000010000000000000001
```

### 4.3 临时文件和缓存

```bash
# /tmp 目录
du -sh /tmp
find /tmp -type f -atime +7 -ls  # 7天未访问的文件

# 用户缓存目录
du -sh ~/.cache/*

# apt 缓存（Debian/Ubuntu）
du -sh /var/cache/apt/archives
sudo apt-get clean

# yum 缓存（RHEL/CentOS）
du -sh /var/cache/yum
sudo yum clean all
```

### 4.4 Docker 占用过大

```bash
# 查看 Docker 磁盘使用
docker system df

# 详细分析
docker system df -v

# 清理
docker system prune -a      # 删除所有未使用的镜像、容器、网络
docker image prune -a       # 删除所有未使用的镜像
docker container prune      # 删除已停止的容器
docker volume prune         # 删除未使用的卷（谨慎！）
docker builder prune        # 删除 build 缓存

# 查看最大的镜像
docker images --format "{{.Repository}}\t{{.Size}}" | sort -k2 -h | tail -10
```

### 4.5 核心转储文件

```bash
# 查看 core 文件
find / -name "core.*" -ls 2>/dev/null

# 查看 core 文件配置
cat /proc/sys/kernel/core_pattern

# 临时关闭 core dump
ulimit -c 0

# 永久配置
echo "/tmp/core-%e-%p-%t" > /proc/sys/kernel/core_pattern
```

### 4.6 大日志文件快速清空

如果确定不需要日志内容，可以快速清空而不删除文件（避免应用报错）：

```bash
# 方法1：重定向到空设备
> /var/log/app.log

# 方法2：truncate
truncate -s 0 /var/log/app.log

# 方法3：使用 tee
tee /var/log/app.log < /dev/null

# 方法4：删除后重建（如果应用会重新创建）
rm /var/log/app.log
touch /var/log/app.log
```

## 5. 预防措施

### 5.1 监控告警

```bash
# 添加磁盘使用率监控到 crontab
crontab -e

# 每天检查，超过 80% 告警
0 0 * * * df -h | awk '$5 > 80 {print "Disk usage warning: " $0}' | mail -s "Disk Alert" admin@example.com
```

### 5.2 日志轮转配置

```bash
# /etc/logrotate.d/nginx
/var/log/nginx/*.log {
    daily              # 每天轮转
    missingok          # 忽略不存在文件
    rotate 14          # 保留 14 天
    compress            # 压缩历史日志
    delaycompress       # 延迟压缩
    notifempty         # 空文件不轮转
    create 0640 www-data adm  # 轮转后创建新文件权限
    sharedscripts       # 执行一次 postrotate
    postrotate
        /usr/sbin/nginx -s reload
    endscript
}
```

### 5.3 inode 监控

```bash
# 监控 inode 使用
df -i | awk '{if ($5 > 80) print $0}'

# 如果 inode 满，排查小文件
find / -xdev -type f -printf '%h\n' | sort | uniq -c | sort -rn | head -10
```

## 6. 面试高频问题

### Q1: du 和 df 显示不一致是什么原因？

**回答要点**：
- `du` 统计的是实际文件占用的空间
- `df` 统计的是文件系统层面的剩余空间
- **主要原因**：有进程持有已删除文件的 fd，导致空间不释放
- **解决方法**：`lsof +L1` 查找这类文件

### Q2: 如何定位占用磁盘最多的目录？

**回答要点**：
- 先用 `df -h` 确认问题分区
- 用 `du -xhd1` 从大目录层层拆分
- 重点关注 `/var`、`/tmp`、`/home`
- `find` 可以找大文件

### Q3: inode 满了怎么办？

**回答要点**：
- inode 满意味着文件数量达到上限
- 先用 `df -i` 确认
- 找大量小文件目录：`find / -xdev -type f | wc -l`
- 清理小文件或重新创建更大 inode 的文件系统

### Q4: 删除了文件但空间没释放？

**回答要点**：
- 进程持有文件描述符，文件实际未删除
- 用 `lsof +L1 | grep deleted` 定位
- 重启进程或截断文件：`> /proc/<pid>/fd/<fd>`

## 7. 总结

磁盘满排查的核心思路：

```
1. df -h 定位分区
2. df -i 确认类型（块 or inode）
3. du -xhd1 定位大目录
4. find 定位大文件
5. lsof +L1 检查已删除未释放
6. 清理 + 监控预防
```

关键命令速记：

| 命令 | 作用 |
| --- | --- |
| `df -h` | 看分区使用率 |
| `df -i` | 看 inode 使用率 |
| `du -xhd1` | 定位大目录 |
| `find -size +1G` | 找大文件 |
| `lsof +L1` | 查已删除未释放 |
| `truncate -s 0` | 快速清空文件 |
