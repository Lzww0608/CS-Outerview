`taskset` 是一个在 Linux 系统下的命令行工具，它的核心功能是**设置或查询一个进程的 CPU 亲和性 (CPU affinity)**。

简单来说，它允许你**“绑定”**一个程序（进程），强制它只在**你指定的 CPU 核心**上运行。

在多核心（Multi-Core）CPU 已经普及的今天，操作系统（如 Linux）的调度器（Scheduler）通常会自动决定哪个进程在哪个 CPU 核心上运行，并且为了效率（例如负载均衡），它可能会在不同的核心之间“迁移”进程。

`taskset` 命令就是用来干预这个过程的。



### 为什么需要 `taskset`？

你可能希望将某个进程绑定到特定 CPU 核心上，主要出于以下几个原因：

1. **性能优化（Performance Tuning）**：
   - **减少缓存失效（Cache Miss）**：当一个进程在 CPU 核心之间频繁切换时，它在原先核心的 CPU 缓存（L1, L2 cache）中的数据就会失效，新核心需要重新从内存加载数据，这会带来性能损耗。将进程绑定到单个核心可以最大化地利用该核心的缓存，这对于计算密集型或对延迟敏感的应用（如高性能网络服务、实时系统）非常重要。
   - **避免干扰**：你可以将一个非常重要的实时进程绑定到某个“专用”核心上，同时将其他不那么重要的“杂项”进程绑定到别的核心上，确保它们不会抢占这个重要进程的 CPU 时间。
2. **隔离（Isolation）**：
   - 在进行性能压测时，你可能想把测试工具本身（例如 `htop` 或日志收集器）绑定到一个核心上，把被测试的应用程序绑定到其他核心上，以确保监控工具不会干扰测试结果。

------



### `taskset` 的基本用法

`taskset` 的用法主要分两种：**启动一个新命令**，或者**修改一个已在运行的进程**。

它指定 CPU 核心的方式有两种：

- **CPU 列表（推荐，更直观）**：使用 `-c` 选项，后面跟上核心的编号（从 0 开始）。
  - `0,1,3`：表示在 CPU 0、1、3 上运行。
  - `0-3`：表示在 CPU 0、1、2、3 上运行。
  - `0,5-7`：表示在 CPU 0、5、6、7 上运行。
- **位掩码（Bitmask）**：这是默认方式，用一个十六进制数来表示。不常用，因为不直观。例如，`0x1` (二进制 `0001`) 表示 CPU 0，`0x3` (二进制 `0011`) 表示 CPU 0 和 1，`0x5` (二进制 `0101`) 表示 CPU 0 和 2。

### 常用示例

假设你有一个 4 核心的 CPU（编号为 0, 1, 2, 3）。

#### 示例 1：查询一个已在运行的进程的 CPU 亲和性

首先，你需要知道那个进程的 PID（Process ID）。假设我们要查询 PID 为 `12345` 的进程：

```
# -c 表示用 CPU 列表的方式显示
# -p 表示操作一个已存在的 PID
taskset -cp 12345
```

输出可能会是：

pid 12345's current affinity list: 0-3

（这表示它可以在所有 4 个核心上运行，这是默认情况）



#### 示例 2：修改一个已在运行的进程的 CPU 亲和性

假设我们想把 PID 为 `12345` 的进程**限制**在 CPU 0 和 CPU 1 上运行：

```bash
# -c 指定 CPU 列表 0,1
# -p 指定 PID 12345
taskset -cp 0,1 12345
```

输出会显示：

pid 12345's current affinity list: 0-3

pid 12345's new affinity list: 0,1



#### 示例 3：启动一个新命令，并指定它的 CPU 亲和性

假设你想运行一个计算密集型脚本 `my_script.sh`，并且你只想让它在 CPU 3 上运行，不让它干扰其他核心：

```bash
# -c 指定 CPU 列表 3
taskset -c 3 ./my_script.sh
```

这样，`my_script.sh` 及其创建的大多数子进程都会被限制在 CPU 3 上运行。
