# 6. 常用命令与磁盘满排查

Linux 命令类面试题通常考察日常排障能力。回答时不要只背命令名，要能说明在什么场景使用、看什么字段、下一步怎么定位。

## 1. 常见命令分类

| 分类 | 常用命令 | 作用 |
| --- | --- | --- |
| 文件目录 | `ls`、`cd`、`pwd`、`cp`、`mv`、`rm`、`mkdir` | 查看和操作文件目录 |
| 文本查看 | `cat`、`less`、`head`、`tail`、`grep`、`awk`、`sed` | 查看日志、过滤文本 |
| 磁盘空间 | `df`、`du`、`stat`、`find` | 查看文件系统和文件占用 |
| 进程状态 | `ps`、`top`、`htop`、`pidstat` | 查看进程和资源占用 |
| 网络连接 | `ss`、`netstat`、`lsof`、`curl`、`ping`、`traceroute` | 查看端口、连接和网络路径 |
| 系统资源 | `free`、`vmstat`、`iostat`、`sar` | 查看内存、CPU、磁盘 IO |
| 权限用户 | `chmod`、`chown`、`id`、`sudo` | 管理权限和用户 |
| 服务日志 | `systemctl`、`journalctl`、`dmesg` | 查看服务和内核日志 |

补充几个面试里容易混淆的命令：

```bash
df -h       # 看文件系统容量和使用率
df -i       # 看 inode 使用率
fdisk -l    # 看磁盘和分区表，不等价于看文件系统使用率
lsblk       # 看块设备、分区和挂载关系
alias ll='ls -alF'
unalias ll
type ll     # 判断 ll 是别名、函数还是外部命令
```

`fdisk` 更偏磁盘分区管理，`df` 才是看“某个挂载点还剩多少空间”。排查磁盘满时不要只背 `df`，还要能说出 `du` 用来定位目录、`lsof +L1` 用来查已删除但仍被进程占用的文件。

## 2. 网络怎么管理和排查

Linux 网络管理通常先看“地址、路由、端口、连通性、DNS、防火墙、抓包”。现代发行版优先使用 `ip` 和 `ss`，老系统上才更多看到 `ifconfig`、`route`、`netstat`。

```bash
ip addr
ip link
ip route
ss -lntp
ss -ant state established
ping 10.0.0.1
traceroute www.example.com
dig www.example.com
curl -v http://127.0.0.1:8080/health
tcpdump -i eth0 host 10.0.0.2 and port 443
```

常见排查顺序：

1. **网卡和地址**：`ip link` 看网卡是否 UP，`ip addr` 看 IP、掩码和是否有重复地址。
2. **路由**：`ip route` 看默认路由、目标网段路由和网关是否正确。
3. **端口监听**：`ss -lntp` 看服务是否监听在预期 IP 和端口上。
4. **连接状态**：`ss -ant` 观察 `ESTAB`、`SYN-SENT`、`TIME-WAIT`、`CLOSE-WAIT` 数量。
5. **DNS**：`dig` 或 `nslookup` 判断域名是否解析到预期地址。
6. **防火墙和安全组**：本机查 `iptables`、`nft`、`firewalld`，云上还要查安全组和 ACL。
7. **抓包确认事实**：`tcpdump` 看请求是否到达、是否有响应、是否重传或被 RST。

如果是网络配置管理，桌面或通用服务器常见 `nmcli` 管理 NetworkManager：

```bash
nmcli device status
nmcli connection show
nmcli connection up eth0
systemctl restart NetworkManager
```

生产环境重启网络服务会影响连接，执行前要确认机器接入方式、变更窗口和回滚方案。排查时要区分“本机没监听”“本机防火墙拦截”“路由不可达”“DNS 错误”“对端拒绝连接”和“链路丢包超时”，不同问题对应的处理完全不同。

## 3. `vmstat` 怎么看

`vmstat` 用来观察系统整体 CPU、内存、swap、I/O 和调度状态，常用：

```bash
vmstat 1
vmstat 1 5
```

重点字段：

| 字段 | 含义 | 常见判断 |
| --- | --- | --- |
| `r` | runnable 队列长度 | 长期大于 CPU 核数，说明 CPU 可能排队 |
| `b` | 不可中断睡眠任务数 | 常见于等待磁盘或内核 I/O |
| `free` | 空闲内存 | 要结合 buff/cache 看，不宜单独判断 |
| `si/so` | swap in/out | 持续非 0 通常说明内存压力较大 |
| `bi/bo` | 块设备读写 | 观察磁盘 I/O 活跃程度 |
| `in/cs` | 中断数/上下文切换数 | 突增可能和网络包、锁竞争、线程过多有关 |
| `us/sy/id/wa/st` | 用户态、内核态、空闲、I/O wait、虚拟化偷取 CPU | `wa` 高偏 I/O 等待，`sy` 高偏系统调用/内核开销 |

面试里可以说：`vmstat` 适合先做系统级判断。如果 `r` 高且 `id` 低，优先看 CPU；如果 `wa` 高、`b` 高，优先看磁盘或网络 I/O；如果 `si/so` 持续非 0，说明发生 swap，要继续用 `free`、`top`、`pidstat -r` 找内存压力来源。

## 3.1 系统命令执行很慢怎么排查

如果连 `ls`、`ps`、`top`、`ssh` 这类命令都变慢，要先判断慢在 CPU、内存、磁盘、网络文件系统还是认证/DNS。

常见路径：

1. **CPU 排队**：`uptime`、`top`、`vmstat 1` 看 load average、`r` 队列、`us/sy`。
2. **内存压力**：`free -h`、`vmstat 1` 看 `available`、`si/so`、OOM 日志。
3. **磁盘或文件系统慢**：`iostat -xz 1`、`iotop`、`df -h`、`dmesg` 看 I/O util、await、磁盘错误。
4. **目录文件过多**：`ls` 某个目录很慢时，可能是目录项太多、网络盘慢或 inode/cache 压力大。
5. **NFS/远程挂载卡顿**：`df`、`ls`、shell 补全可能卡在远程文件系统，需要看 `mount`、网络和 NFS 服务状态。
6. **DNS/认证慢**：`ssh`、`sudo` 慢可能和反向 DNS、LDAP、PAM、NSS 配置有关。
7. **进程或 fd 耗尽**：`ulimit -n`、`cat /proc/sys/fs/file-nr`、`ps -eLf | wc -l` 看资源耗尽。

真实排查时不要只说“用 top”。`top` 只能告诉你一部分 CPU 和内存事实；如果 `wa` 很高，要继续看 `iostat`；如果 `sy` 很高，要考虑系统调用、网络包、锁竞争；如果只有某个目录慢，要查目录规模、挂载点和底层存储。

## 4. top/free 里的 buffer 和 cache

`top` 或 `free` 里经常能看到 `buff/cache`，它不等于“被应用吃掉且不可释放的内存”。Linux 会尽量把空闲内存用于缓存，提高文件和块设备 I/O 性能。

常见概念：

1. **buffer**：更偏块设备元数据、块 I/O 缓冲，例如文件系统元数据、块设备读写缓冲。
2. **cache/page cache**：缓存文件内容页，程序读文件时如果命中 page cache，就不必访问磁盘。
3. **available**：估算在不明显影响系统运行的情况下还能给新程序使用的内存，通常比 `free` 更有参考价值。

为什么 buff/cache 看起来很大：

1. Linux 的策略是“内存不用也是浪费”，所以会用空闲内存做 page cache。
2. 当应用需要内存时，干净的 page cache 可以直接回收，脏页需要先回写。
3. 真正需要警惕的是 `available` 很低、swap in/out 持续发生、OOM 日志出现，而不是单纯 buff/cache 高。

排查内存压力时可以结合：

```bash
free -h
top
vmstat 1
cat /proc/meminfo
```

面试回答可以说：buffer/cache 是内核为 I/O 性能使用的缓存，很多情况下可回收；判断内存是否紧张要看 `available`、swap、OOM 和业务 RSS，而不是只看 `free` 很小。

## 5. vim 里怎么查找字符或字符串

在 vim 普通模式下：

```vim
/target      " 向后搜索 target
?target      " 向前搜索 target
n            " 跳到下一个匹配
N            " 跳到上一个匹配
*            " 搜索光标所在单词
#            " 反向搜索光标所在单词
```

常用设置：

```vim
:set hlsearch    " 高亮搜索结果
:set nohlsearch  " 取消高亮
:set ignorecase  " 忽略大小写
:set smartcase   " 搜索串含大写时区分大小写
```

如果只查找单个字符并在当前行移动，可以用 `f<char>` 向后跳到字符，`F<char>` 向前跳到字符，`;` 重复上一次字符查找，`,` 反向重复。

## 6. 看日志常用命令

实时看日志：

```bash
tail -f app.log
tail -F app.log
```

`-F` 比 `-f` 更适合日志轮转场景，因为它会按文件名重新打开。

按关键字过滤：

```bash
grep -n "ERROR" app.log
grep -C 3 "timeout" app.log
grep -E "ERROR|WARN" app.log
```

按时间或字段聚合：

```bash
awk '{print $1, $2, $NF}' app.log
awk '/ERROR/ {cnt[$5]++} END {for (k in cnt) print k, cnt[k]}' app.log
```

查看 systemd 服务日志：

```bash
journalctl -u nginx --since "1 hour ago"
journalctl -u app.service -f
```

排查线上问题时通常按这个顺序：先看错误率和时间点，再 grep 关键错误，再按 traceId/requestId 串联上下游日志。

## 7. 磁盘满了怎么排查

第一步，看哪个文件系统满了：

```bash
df -h
```

如果磁盘块没满但仍无法创建文件，看 inode：

```bash
df -i
```

第二步，定位大目录：

```bash
du -xhd1 /
du -xhd1 /var
du -sh /var/log/*
```

`-x` 表示不跨文件系统，避免把挂载的其他盘统计进来。

第三步，找大文件：

```bash
find /var -type f -size +1G -ls
```

如果要清理“修改时间超过一天”的文件，先打印确认，再删除：

```bash
find /tmp/app-cache -type f -mtime +1 -print
find /tmp/app-cache -type f -mtime +1 -delete
```

注意 Linux 上“创建时间”不一定可移植，很多场景实际用的是 `mtime`（内容修改时间）或 `ctime`（元数据变更时间）。线上删除前应先 `-print` 或输出到清单确认，避免路径写错造成误删。

第四步，检查“文件已删除但空间没释放”：

```bash
lsof +L1
```

如果进程还持有已删除文件的 fd，磁盘空间不会释放。处理方式通常是重启对应进程，或者在确认安全后清空 `/proc/<pid>/fd/<fd>` 指向的文件句柄。

## 8. 常见处理方式

1. **日志过大**：压缩、归档、清理历史日志，检查 logrotate 配置。
2. **systemd journal 过大**：

```bash
journalctl --disk-usage
journalctl --vacuum-time=7d
journalctl --vacuum-size=1G
```

3. **Docker 占用大**：

```bash
docker system df
docker image prune
docker container prune
docker volume prune
```

生产环境清理 Docker volume 前必须确认没有业务数据。

4. **小文件过多导致 inode 满**：定位小文件目录，清理临时文件或调整文件组织方式。
5. **核心转储过多**：检查 `core_pattern`、服务崩溃原因和 core 文件保留策略。

## 9. 易错点

1. 不要一上来就 `rm -rf`，先确认文件用途、归属服务和是否仍被进程占用。
2. 删除大文件后空间不释放，通常是进程还持有 fd。
3. `du` 统计目录占用，`df` 看文件系统剩余，二者口径不同。
4. inode 满和磁盘块满表现都可能是 `No space left on device`。
5. 日志清理要配合轮转策略，否则清完很快还会再次打满。

## 10. 面试回答模板

Linux 常用命令可以按文件、文本、进程、网络、磁盘和服务日志分类。网络问题先用 `ip addr/ip route` 看地址和路由，用 `ss -lntp` 看端口监听，用 `ping/traceroute/dig/curl` 分别确认连通性、路径、DNS 和应用响应，必要时用 `tcpdump` 抓包。系统压力可以用 `vmstat 1` 观察 runnable 队列、swap、I/O wait、上下文切换和 CPU 分布。`top/free` 里的 buff/cache 主要是内核缓存和 page cache，判断内存压力更应看 available、swap 和 OOM。vim 中 `/pattern` 向后搜索、`?pattern` 向前搜索，`n/N` 切换匹配项。看日志常用 `tail -F`、`grep`、`awk`、`journalctl`。磁盘满了先用 `df -h` 看挂载点，再用 `df -i` 判断 inode；接着用 `du -xhd1`、`find`、`lsof +L1` 定位大目录、大文件和已删除但仍被占用的文件。
