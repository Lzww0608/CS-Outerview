# 网卡收包到应用层

面试问“网卡收到以太网帧后，Linux 如何把数据交给应用层”，核心是把硬件、中断、协议栈、socket 缓冲区和应用 `recv/read` 串起来。

## 1. 整体链路

```text
网卡收到以太网帧
  -> DMA 写入内核收包 ring buffer
  -> 网卡触发中断或 NAPI 轮询
  -> 驱动构造 skb
  -> 二层处理，校验 MAC、VLAN、协议类型
  -> IP 层处理，校验 IP 头、分片重组、路由/本机投递
  -> TCP/UDP 层处理，按四元组找到 socket
  -> 数据进入 socket 接收缓冲区
  -> 唤醒等待队列，epoll ready list 产生可读事件
  -> 应用调用 recv/read，从内核拷贝到用户缓冲区
```

`skb`（socket buffer）是 Linux 网络协议栈里描述网络包的核心结构，里面保存数据指针、协议头偏移、设备、校验、时间戳等元信息。

## 2. 驱动和软中断

网卡通常不会让 CPU 一个字节一个字节搬运数据，而是通过 DMA 把帧写入内存中的接收队列。早期每个包都触发硬中断会造成中断风暴，Linux 常用 NAPI：

1. 低流量时由中断及时唤醒处理。
2. 高流量时关闭部分中断，改为软中断轮询一批包。
3. 批量处理可以降低中断开销，但会增加一点排队延迟。

协议栈处理通常发生在软中断上下文或相关内核线程中。高并发场景要关注软中断 CPU、RSS/RPS/RFS、网卡队列和中断亲和性。

## 3. 协议栈如何找到 socket

以 TCP 为例，内核会根据五元组或四元组定位连接：

```text
源 IP、源端口、目的 IP、目的端口、协议
```

处理过程包括：

1. 二层确认这是发给本机或可接收的帧。
2. IP 层确认目的 IP、本机路由、TTL、校验和、分片重组。
3. TCP 层校验端口、序列号、ACK、窗口、状态机。
4. 找到对应 established socket 后，把有效载荷追加到该 socket 的接收缓冲区。
5. 如果应用阻塞在 `recv` 或 `epoll_wait`，内核唤醒对应等待队列。

UDP 没有连接状态机，但也会按目的端口和绑定地址找到 socket，把一个 UDP datagram 放入接收队列。UDP 保留报文边界，TCP 不保留应用消息边界。

## 4. epoll 在链路中的位置

`epoll` 不负责收包，它只负责就绪通知。

当 TCP 接收缓冲区从不可读变为可读时，socket 等待队列上的回调会把 fd 放入 epoll 实例的 ready list。随后 `epoll_wait()` 返回可读事件，应用再调用 `recv()` 把数据从内核 socket 缓冲区拷贝到用户态 buffer。

因此：

1. `epoll_wait` 返回不代表数据已经到用户态。
2. `recv` 可能只读到部分字节。
3. ET 模式下要循环读到 `EAGAIN`。
4. 应用层仍要维护输入缓冲区和协议解析状态。

## 5. 真实排查关注点

1. **网卡层**：`ethtool -S eth0` 看丢包、错误、队列统计。
2. **软中断**：`top`、`mpstat -P ALL`、`/proc/softirqs` 看 `NET_RX` 是否集中在单核。
3. **协议栈**：`ss -s`、`netstat -s` 看重传、丢包、listen 队列。
4. **socket 缓冲区**：`ss -ntm` 看接收/发送队列。
5. **应用层**：看事件循环是否阻塞、是否及时 `recv`、是否有慢业务占住 I/O 线程。

## 6. 面试回答模板

网卡收到以太网帧后，通常通过 DMA 放入内核 ring buffer，然后由中断或 NAPI 轮询触发驱动处理。驱动构造 skb 后进入协议栈，二层处理 MAC/VLAN，IP 层做校验、分片重组和本机投递，TCP/UDP 层按端口和连接四元组找到 socket，把数据放入 socket 接收缓冲区。缓冲区变为可读后会唤醒等待队列，epoll 回调把 fd 加入 ready list，应用从 `epoll_wait` 得到事件后再调用 `recv/read` 拷贝到用户态。epoll 只是就绪通知，不负责真正搬运应用数据。
