# 3. read/write 错误与 SIGPIPE

网络服务器里 `read/recv/write/send` 返回错误不一定都是致命错误。面试时要把“暂时不可读写”“被信号打断”“对端关闭”“本端 fd 错误”区分开。

## 1. read/recv 常见返回值

```cpp
ssize_t n = recv(fd, buf, sizeof(buf), 0);
```

常见情况：

1. `n > 0`：读到 n 字节。TCP 是字节流，不保证对应对端一次 send。
2. `n == 0`：对端有序关闭写方向，通常表示收到 FIN。
3. `n < 0 && errno == EINTR`：被信号打断，可以重试。
4. `n < 0 && (errno == EAGAIN || errno == EWOULDBLOCK)`：非阻塞 fd 当前无数据，不是致命错误，等待下一次可读事件。
5. `n < 0 && errno == ECONNRESET`：对端异常关闭，连接被 reset。
6. `n < 0 && errno == EBADF`：fd 无效，通常是生命周期管理 bug。

ET 模式下读事件触发后要循环读到 `EAGAIN`，否则缓冲区里剩余数据可能不会再次触发事件。

### 阻塞和非阻塞 socket 下 read 有什么区别

同一个 `read/recv`，在阻塞 socket 和非阻塞 socket 上的返回语义不同：

| 场景 | 阻塞 socket | 非阻塞 socket |
| --- | --- | --- |
| 接收缓冲区有数据 | 立即返回读到的字节数 | 立即返回读到的字节数 |
| 接收缓冲区暂时无数据 | 线程睡眠等待，直到有数据、对端关闭、出错或被信号打断 | 立即返回 `-1`，`errno` 为 `EAGAIN/EWOULDBLOCK` |
| 对端正常关闭写方向 | 返回 `0` | 返回 `0` |
| 被信号打断 | 返回 `-1`，`errno=EINTR` | 返回 `-1`，`errno=EINTR` |

设置非阻塞通常使用：

```cpp
int flags = fcntl(fd, F_GETFL, 0);
fcntl(fd, F_SETFL, flags | O_NONBLOCK);
```

网络服务器常用非阻塞 fd 配合 `epoll`。原因是一个线程可以管理大量连接：fd 不可读写时不占住线程，而是把连接状态保存在应用层缓冲区和状态机中，等下次可读/可写事件再继续处理。

易错点：

1. 非阻塞读返回 `EAGAIN` 不是连接断开。
2. 阻塞读也可能提前返回，例如被信号打断或读到部分数据。
3. TCP 一次 `read` 返回的字节数只表示当前读到了多少，不表示一条业务消息完整。
4. ET 模式必须循环读到 `EAGAIN`；LT 模式虽然可以不一次读完，但通常也要尽量读空缓冲区，减少事件反复触发。

## 2. write/send 常见返回值

```cpp
ssize_t n = send(fd, data, len, 0);
```

常见情况：

1. `n > 0`：只表示写入内核发送缓冲区 n 字节，不代表对端应用已收到。
2. `0 < n < len`：部分写，需要记录偏移，后续继续发送。
3. `n < 0 && errno == EINTR`：被信号打断，可以重试。
4. `n < 0 && (errno == EAGAIN || errno == EWOULDBLOCK)`：发送缓冲区满，注册或等待可写事件。
5. `n < 0 && errno == EPIPE`：对端已关闭，继续写会触发 `SIGPIPE`。
6. `n < 0 && errno == ECONNRESET`：连接被 reset。

对非阻塞服务器来说，写缓冲区满时不应忙等，而应把未发送数据放入连接输出缓冲区，关注 `EPOLLOUT`，等可写后继续发送。

## 3. 对关闭 socket 写会发生什么

如果对端已经关闭连接，本端继续写可能出现：

1. 第一次写触发对端返回 RST，或本端还没感知到异常。
2. 后续写返回 `EPIPE`，并默认产生 `SIGPIPE`。
3. 如果进程没有处理 `SIGPIPE`，默认动作是终止进程。

常见处理方式：

```cpp
signal(SIGPIPE, SIG_IGN);              // 进程级忽略
send(fd, buf, len, MSG_NOSIGNAL);      // Linux 下单次发送禁止 SIGPIPE
```

工程上还要在事件循环里根据错误关闭连接、清理 epoll 事件、释放连接对象，避免 fd 复用导致误操作。

## 4. 协程和非阻塞 I/O 中什么时候切换

协程网络库通常把 fd 设置为非阻塞：

1. 读返回 `EAGAIN`：当前协程挂起，等待可读事件。
2. 写返回 `EAGAIN`：当前协程挂起，等待可写事件。
3. 事件循环通过 epoll/kqueue/io_uring 等机制发现 fd 就绪，再恢复协程。

这也是 gevent、Go netpoller、很多 C++ 协程网络库的核心思路：系统调用不能立即完成时不阻塞整个线程，而是让出执行权。

## 5. 面试回答模板

`read` 返回正数表示读到字节，返回 0 通常表示对端 FIN，返回 `EINTR` 可以重试，非阻塞 fd 返回 `EAGAIN/EWOULDBLOCK` 表示当前没数据，不是致命错误。`write` 可能部分写，也可能因为发送缓冲区满返回 `EAGAIN`，这时要缓存剩余数据并等待可写事件。对已经关闭的 socket 写可能返回 `EPIPE` 并触发 `SIGPIPE`，默认会杀死进程，所以服务器通常忽略 `SIGPIPE` 或使用 `MSG_NOSIGNAL`，再在应用层关闭连接并清理资源。
