# 硬链接、软链接与 chmod

Linux 文件系统面试里常把链接和权限一起问。核心要区分文件名、inode、目录项和权限位。

## 1. inode 和目录项

Linux 文件名不是文件本体。目录中保存的是“文件名 -> inode”的映射，inode 里记录文件类型、权限、属主、大小、时间戳、数据块位置等元数据。

```text
目录项: app.log -> inode 10086
inode: 权限、属主、数据块指针、link count
数据块: 文件内容
```

## 2. 硬链接

硬链接是在目录中新增一个文件名，让它指向同一个 inode：

```bash
ln app.log app.log.bak
```

特点：

1. 两个文件名地位相同，没有“原文件”和“快捷方式”的区别。
2. 修改任意一个名字看到的内容，另一个也会变化，因为底层是同一个 inode。
3. 删除一个名字只是 link count 减 1，只有计数为 0 且没有进程打开时，数据才会释放。
4. 通常不能跨文件系统创建硬链接。
5. 普通用户通常不能给目录创建硬链接，避免目录环破坏遍历语义。

## 3. 软链接

软链接也叫符号链接，本身是一个独立文件，内容是目标路径：

```bash
ln -s /var/log/app.log app.log.link
```

特点：

1. 软链接有自己的 inode。
2. 可以跨文件系统，也可以指向目录。
3. 目标被删除或路径变化后，软链接会变成悬空链接。
4. 访问软链接时，内核会继续解析它保存的路径。

### 3.1 为什么建了软链接后仍不能直接输入命令运行

软链接只是文件系统里的一个路径入口，不会自动改变 shell 的命令查找规则。命令行输入 `foo` 时，shell 通常按下面顺序处理：

1. 先判断是不是 shell 内置命令、函数或 alias。
2. 如果不是，再到 `PATH` 环境变量列出的目录里依次查找名为 `foo` 的可执行文件。
3. 找到后检查目标是否可执行，脚本还要检查 shebang，例如 `#!/usr/bin/env bash`。

所以即使创建了软链接，也可能不能直接输入命令运行：

```bash
ln -s /opt/tools/foo /tmp/foo
foo
```

如果 `/tmp` 不在 `PATH` 中，shell 就找不到 `foo`。可以用完整路径运行：

```bash
/tmp/foo
```

或者把软链接放到 `PATH` 中已有目录：

```bash
sudo ln -s /opt/tools/foo /usr/local/bin/foo
```

还要注意：

1. 目标文件必须有执行权限，例如 `chmod +x /opt/tools/foo`。
2. 如果软链接使用相对路径，解析位置和当前目录无关，而是相对软链接所在目录解析。
3. 如果目标是脚本但没有 shebang，直接执行可能失败，只能显式用解释器运行。
4. 如果所在文件系统以 `noexec` 挂载，即使权限正确也可能不能执行。

## 4. chmod 权限

`chmod` 修改文件模式位。常见三组权限：

```text
owner group others
rwx   rwx   rwx
```

数字表示：

| 权限 | 数值 |
| --- | --- |
| r | 4 |
| w | 2 |
| x | 1 |

示例：

```bash
chmod 755 run.sh   # owner rwx，group/others r-x
chmod 644 app.conf # owner rw-，group/others r--
```

目录权限要单独理解：

1. `r`：能列出目录项。
2. `w`：能在目录中创建、删除、重命名目录项。
3. `x`：能进入目录并解析其中路径。

所以只有目录 `r` 没有 `x`，通常只能看到名字，不能访问文件元数据；只有 `x` 没有 `r`，知道文件名时可以访问，但不能列目录。

## 5. 易错点

1. 硬链接共享 inode，软链接不共享 inode。
2. 删除源文件后，硬链接仍可访问数据；软链接可能失效。
3. 文件删除后磁盘空间不一定立即释放，可能还有硬链接或进程打开 fd。
4. `chmod` 改的是权限位，不改变文件属主；属主用 `chown` 修改。
5. 目录删除文件需要目录的写权限和执行权限，不只看文件本身权限。

## 6. 面试回答模板

硬链接是多个目录项指向同一个 inode，不能轻易跨文件系统，删除一个名字不会影响另一个名字访问数据；软链接是一个独立文件，内容保存目标路径，可以跨文件系统和指向目录，但目标路径不存在时会悬空。创建软链接不等于创建了可直接输入的命令，shell 只会在 `PATH` 目录里找可执行文件，所以软链接所在目录要在 `PATH` 中，目标还要有执行权限和正确 shebang。`chmod` 修改 owner、group、others 的 `rwx` 权限，数字上 `r=4,w=2,x=1`。目录的 `x` 表示能进入和解析路径，目录的 `w` 表示能增删目录项。
