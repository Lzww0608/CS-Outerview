# 3. 文件读取与定位

操作系统读取磁盘文件，表面上是应用调用 `read(fd, buf, n)`，实际会经过 VFS、文件系统、页缓存、块层和磁盘驱动等多个层次。

## 从路径到文件

当进程调用：

```c
int fd = open("/data/a.txt", O_RDONLY);
```

内核大致会做：

1. **路径解析**：从根目录或当前目录开始，逐级解析 `data`、`a.txt`。
2. **dentry 缓存**：目录项缓存保存“名字 -> inode”的映射，命中时可以减少磁盘访问。
3. **inode 定位**：inode 保存文件元数据，例如权限、大小、时间戳、数据块索引或 extents。
4. **权限检查**：根据当前进程的 uid/gid、文件权限、挂载参数等判断能否打开。
5. **创建打开文件对象**：内核创建 `struct file`，进程 fd 表中的整数 fd 指向这个打开文件对象。

所以，“知道文件路径后怎么知道文件在哪里”，核心就是：通过目录项逐级找到 inode，再通过 inode 中的块映射信息找到文件数据所在的磁盘块。

## 从文件偏移到磁盘块

读取文件时，内核不是直接拿路径去读磁盘，而是根据打开文件对象和当前偏移读：

1. 根据 `fd` 找到进程 fd 表中的 `struct file`。
2. 从 `struct file` 取出当前文件偏移 `f_pos`。
3. 根据偏移计算文件内的页号和页内偏移。
4. 先查 page cache：命中则直接从内核页缓存拷贝到用户缓冲区。
5. 未命中则通过文件系统把“文件逻辑块号”映射到“磁盘物理块号”。
6. 块层调度请求，磁盘驱动读取数据到 page cache。
7. 内核把 page cache 中的数据拷贝到用户态 `buf`。
8. 更新 `struct file` 里的 `f_pos`。

```text
fd -> struct file(f_pos) -> inode -> extents/blocks -> page cache -> block layer -> disk
```

## 指针偏移量存在哪里

如果这里的“指针偏移量”指文件读写位置，那么它主要存储在内核的打开文件对象 `struct file` 中，也就是 `f_pos`。

需要区分：

1. **fd 是进程 fd 表里的整数下标**，不是文件本身。
2. **open file description / struct file** 保存当前偏移、打开标志、引用计数等。
3. **inode** 保存文件元数据和数据块映射，不保存某个进程当前读到哪里。
4. `dup()` 或 `fork()` 后共享同一个打开文件对象时，文件偏移也会共享。
5. 使用 `pread/pwrite` 可以指定偏移读写，不修改共享的 `f_pos`，适合多线程并发读同一个文件。

## 真实场景

1. **顺序读大文件**：内核会使用预读机制，把后续页提前读入 page cache。
2. **随机读小块**：page cache 命中率较低时，磁盘寻址和 I/O 放大明显。
3. **数据库**：常用 `pread` 管理自己的页偏移，也可能使用 `O_DIRECT` 绕过 page cache，避免双缓存。
4. **日志系统**：顺序追加写能充分利用 page cache 和磁盘顺序写性能。

## 易错点

1. 文件路径不直接指向磁盘块，路径先解析到 inode。
2. inode 不是文件名，多个硬链接可以指向同一个 inode。
3. `read()` 读文件时可能只返回部分字节，应用要根据返回值处理。
4. 页缓存是文件 I/O 性能的关键，第二次读取同一文件可能不访问磁盘。
