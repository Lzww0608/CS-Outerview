# io_uring Polling 模式与 SPDK 对比分析

## 1. 问题背景

io_uring 的 Polling 模式和 SPDK（Storage Performance Development Kit）都是高性能存储 IO 方案，但定位和适用场景不同。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  方案定位：                                                │
│                                                             │
│  io_uring Polling：                                        │
│  • Linux 内核原生异步 IO                                   │
│  • 适合通用高性能存储                                      │
│  • 与现有系统集成简单                                      │
│                                                             │
│  SPDK：                                                   │
│  • 用户态 NVMe 驱动                                       │
│  • 专为低延迟存储设计                                     │
│  • 适合超高性能场景                                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 特性 | io_uring Polling | SPDK |
|------|-------------------|------|
| CPU 占用 | 中等 | 低 |
| 延迟 | 低（10-50μs） | 极低（5-20μs） |
| 吞吐量 | 高 | 极高 |
| 开发成本 | 低 | 高 |
| 通用性 | 好 | 差（仅 NVMe） |

## 5. 解决方案

### 5.1 io_uring Polling 配置

```c
#include <liburing.h>

struct io_uring ring;

// 初始化 Polling 模式
int setup_io_uring_poll() {
    struct io_uring_params params = {
        // 方式1：内核轮询（SQPOLL）
        .flags = IORING_SETUP_SQPOLL,
        .sq_thread_idle = 1000,  // 1秒空闲后休眠
        
        // 方式2：IO 轮询（IOPOLL）
        // .flags = IORING_SETUP_IOPOLL,
    };
    
    return io_uring_queue_init_params(256, &ring, &params);
}

// 使用固定文件描述符（减少开销）
int setup_fixed_file(int fd) {
    struct io_uring_sqe *sqe = io_uring_get_sqe(&ring);
    
    io_uring_prep_openat(sqe, AT_FDCWD, "/dev/nvme0n1",
                         O_RDONLY, 0);
    sqe->flags |= IOSQE_FIXED_FILE;
    
    io_uring_submit(&ring);
}
```

### 5.2 SPDK 配置

```c
#include <spdk/env.h>
#include <spdk/nvme.h>

struct spdk_nvme_ctrlr *ctrlr;

// 初始化 SPDK
int setup_spdk() {
    // 1. 初始化环境
    struct spdk_env_opts opts;
    spdk_env_opts_init(&opts);
    opts.name = "myapp";
    opts.shm_id = 0;
    spdk_env_init(&opts);
    
    // 2. 轮询线程
    struct spdk_cores_fn opts.poll_fn;
    opts.poll_fn.core = 0;  // 指定核心
    opts.poll_fn.fn = poll_fn;
    
    spdk_env_set_core_mask("0x1");  // 仅使用核心 0
    
    return 0;
}

// NVMe 提交读写
void nvme_read(struct spdk_nvme_qpair *qpair, 
               void *buf, uint64_t lba, uint32_t lba_count) {
    struct iovec iov = {
        .iov_base = buf,
        .iov_len = lba_count * 512
    };
    
    struct spdk_nvme_cmd cmd = {
        .opc = SPDK_NVME_OPC_READ,
        .nsid = 1,
        .prp1 = spdk_vtophys(buf),
    };
    
    spdk_nvme_ns_cmd_read(qpair->ns, qpair,
                          buf, lba, lba_count);
}
```

## 8. 实施步骤

### 8.1 io_uring Polling 实施

```bash
# 1. 检查内核版本（需要 5.1+）
uname -r

# 2. 检查 NVMe 驱动支持
cat /sys/block/nvme*/queue/io_poll_delay

# 3. 使用 fio 测试
fio --name=io_uring_poll \
    --filename=/dev/nvme0n1 \
    --rw=randread \
    --bs=4k \
    --iodepth=32 \
    --ioengine=io_uring \
    --fixedbufs=1 \
    --hipri=1
```

### 8.2 SPDK 实施

```bash
# 1. 安装依赖
apt install build-essential libaio-dev

# 2. 下载 SPDK
git clone https://github.com/spdk/spdk.git
cd spdk

# 3. 配置 DPDK
./configure --with-vhost --with-crypto

# 4. 编译
make -j$(nproc)

# 5. 运行 perf 测试
./build/examples/nvme_perf -q 32 -o 4096 -t 10 -w read
```

## 11. 总结

1. **io_uring Polling**：Linux 原生，通用高性能，易集成，延迟 10-50μs
2. **SPDK**：用户态 NVMe 驱动，极致性能，延迟 5-20μs
3. **选择原则**：通用场景选 io_uring，极致性能选 SPDK
4. **性能差异**：SPDK 快 30-50%，但 CPU 占用高 5-10 倍
5. **实践建议**：从 io_uring 开始，按需升级到 SPDK
