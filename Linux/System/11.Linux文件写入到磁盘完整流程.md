# Linux 文件写入到磁盘读写全过程

## 1. 问题背景

理解 Linux 文件写入的完整路径对于系统编程、性能优化、故障排查至关重要。从用户态 write() 到最终磁盘持久化，经历多个软件层次。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Linux 文件写入完整路径：                                   │
│                                                             │
│  应用层 write()                                           │
│      ↓                                                     │
│  C 库 glibc                                              │
│      ↓                                                     │
│  系统调用 VFS                                              │
│      ↓                                                     │
│  文件系统 ext4/XFS                                         │
│      ↓                                                     │
│  页缓存 Page Cache                                         │
│      ↓                                                     │
│  块设备层                                                  │
│      ↓                                                     │
│  调度器 IO Scheduler                                      │
│      ↓                                                     │
│  磁盘控制器                                                │
│      ↓                                                     │
│  物理磁盘                                                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 |
|------|------|
| write() 返回成功 | 数据可能在 Page Cache，未落盘 |
| 磁盘 I/O 高 | 实际磁盘写入 |
| fsync 慢 | 强制刷盘耗时 |
| 断电丢数据 | Page Cache 未刷盘 |

---

## 3. 影响范围

- 系统性能调优
- 数据库持久化
- 日志系统可靠性

### 4.3 关键数据结构

```c
// 核心数据结构

// 1. 文件描述符到 file 结构的映射
struct file {
    struct path             *f_path;      // 文件路径
    struct inode            *f_inode;     // inode
    const struct file_operations *f_op; // 文件操作
    void                    *fprivate;   // 文件私有数据
    loff_t                  f_pos;      // 文件位置
    unsigned int             f_flags;     // 标志
};

// 2. inode 结构
struct inode {
    unsigned long           i_ino;       // inode 号
    umode_t                i_mode;     // 文件类型和权限
    unsigned int            i_nlink;    // 硬链接数
    loff_t                 i_size;      // 文件大小
    struct timespec64      i_atime;    // 访问时间
    struct timespec64      i_mtime;    // 修改时间
    struct super_block     *i_sb;       // 超级块
    const struct inode_operations *i_op;
    struct address_space   *i_mapping;  // 映射信息
};

// 3. 页面缓存
struct page {
    unsigned long           flags;       // 页状态
    struct address_space   *mapping;    // 所属 address_space
    pgoff_t                index;       // 页内偏移
    void                   *virtual;    // 页内虚拟地址
};
```

### 4.4 ext4 写入流程详解

```c
// ext4 写入流程伪代码

ssize_t ext4_file_write(struct file *filp, 
                        const char __user *buf, 
                        size_t count, 
                        loff_t *ppos) {
    
    // 1. 获取 inode
    struct inode *inode = file_inode(filp);
    
    // 2. 申请 Page Cache 页
    struct page *page = __grab_cache_page(inode->i_mapping, index);
    
    // 3. 拷贝用户数据到 Page Cache
    copy_from_user(page_address(page), buf, bytes);
    
    // 4. 标记页为脏页
    SetPageDirty(page);
    
    // 5. 更新 inode 元数据
    inode->i_mtime = current_time(inode);
    inode->i_size = max(inode->i_size, *ppos + bytes);
    
    // 6. 添加到脏页链表
    mark_inode_dirty(inode);
    
    // 7. 启动异步刷盘（由后台线程执行）
    
    return bytes;
}
```

## 5. 解决方案

### 5.1 不同刷盘策略

```bash
# 查看当前刷盘策略
cat /proc/sys/vm/dirty_background_ratio   # 脏页比例阈值
cat /proc/sys/vm/dirty_ratio             # 全局脏页比例

# 调整刷盘参数
# /etc/sysctl.conf
vm.dirty_background_ratio = 10           # 默认 10%
vm.dirty_ratio = 20                       # 默认 20%
vm.dirty_expire_centisecs = 3000         # 脏页过期时间 30s
vm.dirty_writeback_centisecs = 500       # 刷盘间隔 5s

sysctl -p
```

### 5.2 fsync 确保落盘

```c
// 确保数据落盘的几种方式

// 1. fsync - 确保单个文件落盘
int fsync(int fd);

// 2. fdatasync - 确保数据落盘，不强制更新元数据
int fdatasync(int fd);

// 3. sync - 刷所有文件
void sync(void);

// 4. sync_file_range - 部分刷盘
int sync_file_range(int fd, off64_t offset, 
                   off64_t nbytes, unsigned int flags);
```

#### 5.2.1 `fflush` 和 `fsync` 的区别

`fflush` 和 `fsync` 不在同一层，不能互相替代。

| 接口 | 所在层 | 作用 | 返回后意味着什么 |
| --- | --- | --- | --- |
| `fflush(FILE*)` | C 标准库用户态缓冲 | 把 `stdio` 缓冲区写给内核 | 数据离开用户态缓冲，可能仍在 Page Cache |
| `fsync(fd)` | 内核文件系统 | 把文件脏页和必要元数据同步到存储设备 | 内核要求设备完成持久化，延迟明显更高 |
| `fdatasync(fd)` | 内核文件系统 | 同步文件数据和必要元数据 | 不强制同步所有非必要元数据 |

典型例子：

```c
FILE* fp = fopen("wal.log", "ab");
fwrite(buf, 1, len, fp);
fflush(fp);                 // 只保证 stdio 缓冲被写到 fd
fsync(fileno(fp));          // 进一步要求内核把文件数据刷到稳定存储
fclose(fp);
```

如果直接使用 POSIX 接口：

```c
int fd = open("wal.log", O_WRONLY | O_CREAT | O_APPEND, 0644);
write(fd, buf, len);        // 写入内核，可能只到 Page Cache
fsync(fd);                  // 强制同步文件
close(fd);
```

注意：

1. `write`/`fwrite` 可能发生部分写入，可靠代码要循环写完或处理错误。
2. `fsync` 很慢，因为它可能触发脏页回写、文件系统日志提交、块层 flush 和设备缓存同步。
3. `fsync` 文件只能保证文件内容和必要元数据；如果通过 `rename` 原子替换文件，通常还要 `fsync` 所在目录，保证目录项更新持久化。
4. 设备写缓存、RAID 控制器和云盘实现会影响真实持久性；高可靠场景还要关注断电保护和文件系统挂载选项。

#### 5.2.2 为什么要调用 `fsync`

调用 `fsync` 的核心原因是缩小“应用认为写成功”和“数据真正可恢复”之间的窗口。数据库 WAL、消息队列 commit log、审计日志、配置发布快照等场景，如果只调用 `write`，系统崩溃或断电时最近写入可能还停留在 Page Cache 或设备缓存里。

但 `fsync` 不能无脑每条记录都调用：

1. **可靠性更强**：每次提交都 `fsync`，最多丢失已经返回前的极小窗口。
2. **吞吐更低**：频繁 `fsync` 会把多个小写变成大量同步 I/O，P99 延迟会明显升高。
3. **常见折中**：批量提交、group commit、每 N 条或每 T 毫秒刷盘、关键操作同步刷盘、普通日志异步刷盘。
4. **业务口径要说清**：返回成功前是否 `fsync`，决定了崩溃后能恢复到“最后一次写入调用”还是“最后一次成功刷盘”。

面试里可以这样回答：`fflush` 只清用户态缓冲，`fsync` 才要求内核把文件同步到存储设备。WAL、事务日志和配置原子发布这类需要崩溃恢复的路径要调用 `fsync` 或 `fdatasync`，但要用批量刷盘降低开销，并明确断电级故障下的丢失窗口。

### 5.3 Direct I/O 绕过缓存

```c
// Direct I/O 示例
#include <fcntl.h>

int main() {
    // 打开文件，禁用 Page Cache
    int fd = open("test.dat", O_WRONLY | O_DIRECT);
    
    // 必须对齐：缓冲区、偏移、大小都要对齐到扇区大小 (512/4096)
    char buf[4096] __attribute__((aligned(4096)));
    
    // 直接写入磁盘，绕过 Page Cache
    write(fd, buf, 4096);
    
    close(fd);
    return 0;
}
```

## 6. 可选方案对比

| 刷盘方式 | 延迟 | 可靠性 | 适用场景 |
|----------|------|--------|----------|
| 异步刷盘 | 低 | 中（有丢数据风险）| 日志、非关键数据 |
| fsync | 高 | 高 | 数据库事务日志 |
| Direct I/O | 中 | 高 | 数据库、追求可控 |
| O_SYNC | 最高 | 最高 | 强一致性要求 |

## 9. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 异步刷盘丢数据 | 数据丢失 | fsync 强同步 |

## 11. 总结

1. **完整路径**：write() → VFS → 文件系统 → Page Cache → BIO → IO Scheduler → 磁盘控制器 → 物理磁盘
2. **关键点**：默认异步刷盘，write() 返回成功不代表数据落盘
3. **一致性保证**：fsync/fdatasync/sync 确保数据持久化
4. **性能优化**：增大 dirty_ratio、选择合适 I/O Scheduler、使用 Direct I/O
5. **理解要点**：Page Cache 是核心，所有文件 I/O 都经过它；刷盘由后台线程异步执行
