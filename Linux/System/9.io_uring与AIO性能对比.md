# io_uring 相比 AIO 性能深度分析

## 1. 问题背景

io_uring 是 Linux 5.1 引入的高性能异步 IO 接口，相比传统的 POSIX AIO（异步 IO）有显著性能优势，是现代高性能 IO 的首选方案。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  AIO vs io_uring：                                        │
│                                                             │
│  POSIX AIO：                                              │
│  • 2003 年提出，依赖 glibc 实现                          │
│  • 只支持 O_DIRECT                                        │
│  • 每次 IO 需系统调用                                     │
│                                                             │
│  io_uring：                                               │
│  • 2019 年引入，内核原生支持                              │
│  • 支持所有文件类型                                       │
│  • 批处理减少系统调用                                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | POSIX AIO | io_uring |
|------|-----------|----------|
| 系统调用次数 | 每次 IO 1 次 | 批处理可多次 |
| 延迟 | 较高 | 极低 |
| 扩展性 | 差 | 优秀 |
| 内存拷贝 | 多 | 少（零拷贝） |
| CPU 开销 | 高 | 低 |

## 4. 原因分析

### 4.1 POSIX AIO 架构

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  POSIX AIO 流程：                                         │
│                                                             │
│  用户态：                                                 │
│  ┌─────────────────────────────────────────────────────┐  │
│  │ aio_read() ──► 发起请求 ──► 返回              │  │
│  └─────────────────────────────────────────────────────┘  │
│                           ↓                                   │
│  内核态：                                                │
│  ┌─────────────────────────────────────────────────────┐  │
│  │ 接收请求 ──► 处理 ──► 完成通知                   │  │
│  └─────────────────────────────────────────────────────┘  │
│                           ↓                                   │
│  每一步都需要用户态/内核态切换                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 io_uring 架构

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  io_uring 核心设计：                                       │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐  │
│  │              Submission Queue (SQ)                   │  │
│  │  用户写入 IO 请求                                   │  │
│  └─────────────────────────────────────────────────────┘  │
│                           ↓                                   │
│  ┌─────────────────────────────────────────────────────┐  │
│  │              Ring Buffer (共享内存)                  │  │
│  │  用户态 ────────────────────────► 内核态         │  │
│  │  无需系统调用提交请求                             │  │
│  └─────────────────────────────────────────────────────┘  │
│                           ↓                                   │
│  ┌─────────────────────────────────────────────────────┐  │
│  │              Completion Queue (CQ)                   │  │
│  │  内核写入完成事件                                   │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 核心差异对比

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  POSIX AIO 问题：                                         │
│                                                             │
│  1. 每次 IO 都需要系统调用                                │
│     submit + wait = 2 次 syscall                          │
│                                                             │
│  2. 完成通知依赖 epoll（需额外系统调用）                │
│                                                             │
│  3. 只支持 O_DIRECT 磁盘 IO                             │
│     无法利用 Page Cache                                   │
│                                                             │
│  io_uring 优势：                                         │
│                                                             │
│  1. 批处理提交                                           │
│     一次 syscall 提交多个请求                            │
│                                                             │
│  2. 共享内存 ring buffer                                │
│     提交请求无需 syscall                                 │
│                                                             │
│  3. 内核旁路（IO_uring passthrough）                     │
│     NVMe 设备可直接 DMA 到用户空间                       │
│                                                             │
│  4. 轮询模式                                             │
│     无需等待中断，极低延迟                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 5. 解决方案

### 5.1 io_uring 基本使用

```c
#include <liburing.h>

#define QUEUE_DEPTH 256

struct io_uring ring;

// 初始化
int setup_io_uring() {
    struct io_uring_params params = {
        .flags = IORING_SETUP_SQPOLL,  // 内核轮询模式
        .sq_thread_idle = 2000,          // 轮询空闲超时(ms)
    };
    
    return io_uring_queue_init_params(QUEUE_DEPTH, &ring, &params);
}

// 提交读请求
int async_read(int fd, void *buf, size_t len, off_t offset) {
    struct io_uring_sqe *sqe = io_uring_get_sqe(&ring);
    
    io_uring_prep_read(sqe, fd, buf, len, offset);
    sqe->user_data = (uint64_t)buf;  // 用于识别完成事件
    
    io_uring_submit(&ring);  // 批量提交
    return 0;
}

// 获取完成事件
int wait_and_process() {
    struct io_uring_cqe *cqe;
    
    io_uring_wait_cqe(&ring, &cqe);
    
    if (cqe->res < 0) {
        // 处理错误
        fprintf(stderr, "IO error: %s\n", strerror(-cqe->res));
    } else {
        // 处理完成的数据
        void *buf = (void *)cqe->user_data;
        printf("Read %d bytes at %p\n", cqe->res, buf);
    }
    
    io_uring_cqe_seen(&ring, cqe);
    return cqe->res;
}
```

### 5.2 零拷贝实现

```c
// io_uring 零拷贝（SQE 提供固定缓冲区）
int zero_copy_read(int fd, struct iovec *iov, int iovcnt) {
    struct io_uring_sqe *sqe = io_uring_get_sqe(&ring);
    
    // 使用固定缓冲区（SQE 提供）
    io_uring_prep_read_fixed(sqe, fd, 
                              iov->iov_base, iov->iov_len, 
                              0, 0);  // 第 0 个固定缓冲区
    
    sqe->flags |= IOSQE_FIXED_FILE;
    
    io_uring_submit(&ring);
}
```

### 5.3 内核旁路（Passthrough）

```c
// NVMe 设备的内核旁路
int nvme_passthrough_setup() {
    struct io_uring_sqe *sqe = io_uring_get_sqe(&ring);
    
    // 直接发送 NVMe 命令
    io_uring_prep_write_fixed(sqe, fd,
                               buf, len, offset,
                               0,  // buffer index
                               IORING_OP_WRITE_FIXED);
    
    sqe->opcode = IORING_OP_WRITE_FIXED;
    sqe->flags = IOSQE_FIXED_FILE | IOSQE_NOWAIT;
}
```

## 7. 推荐方案

### 7.1 场景化推荐

| 场景 | 推荐配置 | 说明 |
|------|----------|------|
| 通用异步 IO | SQPOLL 模式 | 平衡性能和资源 |
| 超低延迟 | 轮询 + 固定文件 | 最低延迟 |
| 高 IOPS | 深度队列 + 批处理 | 最大化吞吐 |
| 混合负载 | SQPOLL + fixed | 灵活适应 |

### 7.2 配置建议

```c
// 推荐配置
struct io_uring_params params = {
    .flags = IORING_SETUP_SQPOLL |   // 内核轮询
             IORING_SETUP_CQOVERFLOW, // CQ 溢出处理
    .sq_thread_idle = 1000,           // 1秒空闲进入休眠
    .cq_entries = 2 * QUEUE_DEPTH,    // CQ 大小
};

// 或者使用 IOPOLL（轮询设备）
params.flags = IORING_SETUP_IOPOLL;
```

## 8. 实施步骤

### 8.1 迁移指南

```bash
# 1. 检查内核版本（需要 5.1+）
uname -r

# 2. 检查 io_uring 支持
cat /proc/sys/kernel/io_uring_disabled
# 0 = 启用, 1 = 禁用, 2 = 禁用非特权
```

### 8.2 代码迁移

```c
// 迁移前：POSIX AIO
struct aiocb cb = {
    .aio_fildes = fd,
    .aio_buf = buf,
    .aio_nbytes = len,
    .aio_offset = offset,
};

aio_read(&cb);
while (aio_error(&cb) == EINPROGRESS) {}

// 迁移后：io_uring
struct io_uring_sqe *sqe = io_uring_get_sqe(&ring);
io_uring_prep_read(sqe, fd, buf, len, offset);
io_uring_submit(&ring);
```

## 11. 总结

1. **核心优势**：批处理减少 syscall、共享内存 ring buffer、零拷贝支持
2. **开销减少**：主要减少用户态/内核态切换、内存拷贝次数
3. **性能提升**：IOPS 提升 2 倍，延迟降低 50%
4. **适用场景**：高 IOPS、低延迟应用
5. **实践建议**：使用 liburing 封装，注意内核版本要求
