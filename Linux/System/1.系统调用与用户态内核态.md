# 系统调用与用户态内核态

系统调用是用户程序请求操作系统内核服务的接口。普通业务代码运行在用户态，不能直接访问硬件、页表、内核数据结构和其他进程资源；当需要读写文件、网络收发、创建进程、申请内存映射等能力时，要通过系统调用陷入内核态。

## 用户态和内核态

CPU 通常提供不同特权级：

1. **用户态**：应用程序运行的低特权级，只能访问自己的用户空间地址和受限指令。
2. **内核态**：操作系统内核运行的高特权级，可以管理页表、设备、中断、调度器、文件系统和网络协议栈。

区分用户态和内核态的核心目的是隔离和保护：

1. 防止普通程序随意修改内核或其他进程内存。
2. 防止应用直接操作硬件导致系统不稳定。
3. 让内核统一管理资源、权限和调度。

## 系统调用的大致过程

以 `read(fd, buf, n)` 为例：

1. 用户程序调用 C 库封装的 `read()`。
2. C 库把系统调用号和参数放到约定寄存器中。
3. 执行 `syscall`/`sysenter`/`int 0x80` 等陷入指令。
4. CPU 从用户态切到内核态，跳转到系统调用入口。
5. 内核根据系统调用号分派到具体内核函数。
6. 内核校验 fd、权限、用户缓冲区地址等参数。
7. 内核执行实际读操作，必要时让线程睡眠等待 I/O。
8. 内核把返回值或错误码写回寄存器，切回用户态。
9. C 库根据返回值设置 `errno` 并返回给应用。

系统调用不是普通函数调用，它涉及特权级切换、寄存器保存恢复、参数校验和内核路径执行，因此比普通函数调用更贵。

## 哪些方式会进入内核态

常见入口：

1. **系统调用**：`read`、`write`、`open`、`socket`、`epoll_wait`、`mmap`、`fork`、`execve` 等。
2. **异常**：缺页异常、除零、非法指令、保护错误等。
3. **中断**：网卡收包、磁盘完成、定时器中断等硬件事件。
4. **信号处理返回路径**：信号投递和恢复也需要内核参与。

从应用视角看，最常被问的是系统调用、缺页异常和中断。

## 系统调用和库函数的区别

1. 系统调用是内核 ABI，真正进入内核。
2. 库函数是用户态封装，可能调用系统调用，也可能完全在用户态完成。
3. `malloc` 是库函数，不是系统调用；它会先在用户态分配器中找空闲块，不够时才通过 `brk/mmap` 向内核要虚拟内存。
4. `printf` 是库函数，通常先写用户态缓冲区，缓冲刷新时才可能调用 `write`。

## 性能注意事项

1. 高频小 I/O 会被系统调用开销放大，工程上常用批量读写、缓冲区、`readv/writev`。
2. 网络服务用 `epoll` 是为了一个线程等待多个 fd，减少线程阻塞和切换，不是让读写本身消失。
3. 零拷贝、`mmap`、`sendfile`、`io_uring` 等方案本质上都在减少用户态/内核态切换、数据拷贝或提交次数。
4. 系统调用可能被信号打断返回 `EINTR`，需要按接口语义决定是否重试。

## 易错点

1. 进入内核态不一定发生进程切换，系统调用可能很快返回原线程。
2. 发生阻塞系统调用时，线程可能被调度器挂起，再切换到其他线程执行。
3. 用户态指针传给内核时，内核必须校验和安全拷贝，不能直接信任。
4. `epoll_wait` 返回就绪事件，不代表数据已经拷贝到用户缓冲区，应用仍要 `read/recv`。

## 面试回答模板

系统调用是用户态程序请求内核服务的入口。应用代码不能直接操作硬件、页表和内核对象，所以读写文件、网络收发、创建进程、内存映射等都要通过系统调用陷入内核态。大致过程是：用户态把系统调用号和参数放入寄存器，执行陷入指令，CPU 切到内核态，内核校验参数并执行服务，再把结果返回用户态。用户态进入内核态的常见方式有系统调用、异常和硬件中断。系统调用比普通函数调用贵，工程上要通过批量、缓冲、零拷贝、I/O 多路复用或 io_uring 等方式降低开销。
