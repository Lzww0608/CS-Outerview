# 4. 操作系统核心职责

操作系统最核心的职责可以概括为两件事：**资源管理**和**隔离抽象**。它一方面管理 CPU、内存、磁盘、网络、设备等硬件资源，另一方面给应用提供进程、线程、虚拟内存、文件、socket、系统调用等稳定抽象。

## 1. 为什么说资源管理最核心

计算机硬件是有限共享资源：

1. CPU 同一时刻只能执行有限数量的线程。
2. 物理内存有限，需要分配、回收和换页。
3. 磁盘、网卡、显示、传感器等设备需要统一驱动和仲裁。
4. 多个应用同时运行时，不能互相破坏数据和权限。

操作系统通过调度器、内存管理、文件系统、网络协议栈、驱动和权限模型把这些资源管理起来。

## 2. 关键模块

| 模块 | 解决的问题 | 典型机制 |
| --- | --- | --- |
| 进程/线程管理 | 谁运行、何时运行、如何切换 | 调度器、时间片、优先级、上下文切换 |
| 内存管理 | 地址隔离和内存分配 | 虚拟内存、页表、缺页异常、伙伴系统、slab |
| 文件系统 | 持久化数据的组织 | inode、目录项、页缓存、VFS |
| 设备管理 | 硬件访问和中断处理 | 驱动模型、中断、DMA、总线 |
| 网络协议栈 | 主机间通信 | socket、TCP/IP、路由、网卡驱动 |
| 安全和权限 | 防止越权和破坏 | 用户/组、权限位、capability、namespace、cgroup |

如果只能选一个最关键能力，我会优先说**隔离**：虚拟内存和特权级把应用彼此隔离，也把用户态和内核态隔离开。没有隔离，一个程序的 bug 就可能破坏整个系统。

## 3. 系统调用的意义

应用不能直接操作硬件和内核对象，需要通过系统调用进入内核：

```text
用户态程序
-> syscall
-> 内核校验权限和参数
-> 操作进程、文件、网络、设备或内存
-> 返回结果
```

这既提供能力，也建立边界。文件读写、socket 收发、fork、mmap、ioctl 等都体现了“应用请求，内核仲裁”的设计。

## 4. 易错点

1. 操作系统不只是“调度 CPU”，还包括内存、I/O、文件、网络和设备。
2. 抽象不是为了隐藏一切细节，而是提供稳定接口，同时保留权限和隔离。
3. 高性能系统不是绕过 OS，而是理解 OS 的成本后使用批量、缓存、零拷贝、异步 I/O 等机制。
4. 内核越复杂，bug 影响越大，所以现代系统会用权限、命名空间、cgroup、seccomp 等继续细化隔离。

## 5. 面试回答模板

我认为操作系统最核心的是资源管理和隔离抽象。它通过调度器管理 CPU，通过虚拟内存和页表管理内存并隔离进程，通过 VFS 和文件系统管理持久化数据，通过驱动和中断管理硬件，通过网络协议栈提供通信能力。应用通过系统调用请求这些能力，内核负责权限检查和资源仲裁。如果必须选一个最重要的点，我会选隔离：用户态/内核态隔离和进程地址空间隔离保证了单个程序的问题不会轻易破坏整个系统。
