# 系统调用资源追踪与日志

系统函数申请的资源包括内存、文件描述符、socket、mmap 区、线程、锁、共享内存等。面试里问“怎么给系统函数申请资源写日志”，本质是在问如何追踪资源生命周期，定位泄漏、重复释放和异常路径。

## 1. 代码内封装

最推荐的工程方式是把资源获取和释放封装成统一接口，记录调用点、资源 ID 和释放结果。

```cpp
int open_logged(const char* path, int flags) {
    int fd = ::open(path, flags);
    LOG_INFO("open path={} fd={} errno={}", path, fd, errno);
    return fd;
}

void close_logged(int fd) {
    int ret = ::close(fd);
    LOG_INFO("close fd={} ret={} errno={}", fd, ret, errno);
}
```

C++ 里更进一步是用 RAII：

```cpp
class Fd {
public:
    explicit Fd(int fd = -1) : fd_(fd) {}
    ~Fd() {
        if (fd_ >= 0) {
            ::close(fd_);
        }
    }
private:
    int fd_;
};
```

这样异常返回、提前 return 时也能释放资源。

## 2. 宏和包装函数

对 `malloc/free`、`new/delete` 这类调用，可以通过宏或重载记录 `__FILE__`、`__LINE__`、大小和地址。

```cpp
#define MALLOC(sz) malloc_logged((sz), __FILE__, __LINE__)
#define FREE(p) free_logged((p), __FILE__, __LINE__)
```

这种方式侵入性强，但实现简单，适合自研框架、测试版本或嵌入式环境。

## 3. LD_PRELOAD / dlsym hook

不想改业务代码时，可以写一个动态库拦截 libc 函数：

```cpp
using malloc_fn = void* (*)(size_t);
static malloc_fn real_malloc =
    reinterpret_cast<malloc_fn>(dlsym(RTLD_NEXT, "malloc"));
```

运行时：

```bash
LD_PRELOAD=./libtrace_alloc.so ./server
```

优点是无需改业务代码；缺点是要处理递归调用、线程安全、初始化顺序、性能开销和静态链接失效等问题。

## 4. 外部追踪工具

线上或无法改代码时，可以用系统级工具：

| 工具 | 能看到什么 | 适用场景 |
| --- | --- | --- |
| `strace` | 系统调用参数、返回值、errno | 快速确认 `open/socket/mmap/close` 是否成对 |
| `ltrace` | 动态库函数调用 | 观察 libc、第三方库调用 |
| `perf` | 采样热点和调用栈 | 性能问题定位 |
| `bpftrace`/bcc | 低开销动态追踪用户态/内核态事件 | 生产环境追踪泄漏和高频系统调用 |
| `auditd` | 安全审计日志 | 文件访问、权限、合规审计 |

示例：

```bash
strace -ff -e trace=openat,close,mmap,munmap,socket,connect -p <pid>
```

## 5. 易错点

1. 日志本身也会申请内存和 fd，hook `malloc/open` 时容易递归。
2. 高频系统调用逐条同步写日志会严重影响性能，应该采样、聚合或写无锁缓冲。
3. 只记录申请不记录释放，无法判断泄漏。
4. 只看 fd 数增长不够，还要结合 `/proc/<pid>/fd`、`lsof`、`pmap`、`smaps` 看资源类型。
5. 线上追踪要有开关、限速和采样，避免排查工具把服务拖慢。

## 6. 面试回答模板

如果是自己写代码，最好封装系统调用或用 RAII 管理资源，在申请和释放时记录资源 ID、调用点、返回值和 errno。内存可以用宏、重载 `new/delete` 或统一 allocator 记录；文件、socket、mmap 可以封装 `open/close`、`socket/close`、`mmap/munmap`。如果不能改代码，可以用 `strace/ltrace` 快速看系统调用，用 `LD_PRELOAD + dlsym` hook libc 函数，生产环境更推荐 eBPF/bpftrace 低开销追踪。要注意日志递归、性能开销和申请释放成对分析。
