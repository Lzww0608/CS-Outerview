# 2. Linux Kernel 和普通程序的区别

Linux kernel 不是一个普通用户态程序。它运行在内核态，负责管理硬件、进程、内存、文件系统、网络协议栈和安全边界；普通应用运行在用户态，只能通过系统调用、设备文件、procfs/sysfs、netlink 等受控接口请求内核服务。

## 1. 运行环境不同

| 对比项 | 内核代码 | 用户态程序 |
| --- | --- | --- |
| 特权级 | 内核态，高权限 | 用户态，低权限 |
| 地址空间 | 内核地址空间 | 进程私有用户地址空间 |
| 依赖库 | 不能直接用 glibc/libstdc++ | 可使用标准库和第三方库 |
| 出错影响 | 可能导致 kernel panic 或系统不稳定 | 通常只影响当前进程 |
| 调试方式 | printk、ftrace、kgdb、crash、tracepoint | GDB、日志、core dump、ASan |
| 并发环境 | 中断、软中断、内核线程、进程上下文 | 线程、协程、事件循环 |

普通程序崩溃通常是进程退出；内核代码空指针、越界、睡眠位置错误或锁错误可能直接影响整机。

## 2. 内核开发的限制

内核代码要遵守一些用户态没有的约束：

1. **不能随便访问用户指针**：必须使用 `copy_from_user()`、`copy_to_user()`、`get_user()`、`put_user()`。
2. **不能在原子上下文睡眠**：中断处理、spinlock 持有期间不能调用可能睡眠的函数。
3. **内存分配要选对标志**：进程上下文可用 `GFP_KERNEL`，中断上下文通常只能用 `GFP_ATOMIC`。
4. **栈很小**：内核栈有限，不能放大数组或深递归。
5. **浮点使用受限**：内核一般避免使用浮点，涉及保存恢复 FPU 状态。
6. **ABI 稳定性不同**：用户态 ABI 很稳定，内核内部 API 可能随版本变化。

## 3. 用户态传参到内核态

以驱动 `ioctl` 为例，常见路径是：

```text
用户程序 ioctl(fd, cmd, arg)
-> C 库发起系统调用
-> CPU 切到内核态
-> VFS 根据 fd 找到 struct file
-> 调用驱动 file_operations.unlocked_ioctl
-> 驱动校验 cmd 和用户指针
-> copy_from_user 复制参数到内核缓冲区
-> 操作设备寄存器、队列或状态
-> copy_to_user 返回结果
-> 系统调用返回用户态
```

示例结构体要注意版本和长度：

```c
struct sensor_cfg {
    __u32 version;
    __u32 len;
    __u32 sample_rate;
    __u32 flags;
};
```

驱动接口设计时，不要直接暴露内核指针或依赖 C 结构体隐式布局长期不变。更稳妥的做法是保留 `version/len/reserved` 字段，处理 32/64 位兼容和大小端问题。

## 4. 真实场景

1. **字符设备驱动**：用户态通过 `/dev/xxx` 的 `open/read/write/ioctl/mmap` 访问设备。
2. **sysfs 参数**：简单配置暴露到 `/sys/class/...`，适合查看状态和少量配置。
3. **procfs 调试信息**：展示统计、状态、debug 信息，不适合做复杂 ABI。
4. **netlink**：网络子系统和用户态工具之间传结构化消息。
5. **mmap DMA buffer**：摄像头、显示、AI 加速器等大量数据避免反复拷贝。

## 5. 易错点

1. 内核态不能直接信任用户态传入的地址、长度和结构体内容。
2. `copy_from_user()` 返回的是未复制成功的字节数，不是普通 0/-1 错误码。
3. `printk` 太多会影响实时性和性能，量产要控制日志级别。
4. 内核 bug 的后果比用户态严重，必须用锁、引用计数和生命周期规则保护对象。
5. 不能把用户态经验简单搬到内核，例如大栈对象、异常、标准库容器都不适合。

## 6. 面试回答模板

Linux kernel 和普通程序最大的区别是运行特权级和责任范围不同。内核运行在内核态，可以管理硬件、中断、页表和调度；用户程序运行在用户态，只能通过系统调用等受控接口请求服务。内核代码不能直接用 glibc，不能随便访问用户指针，也不能在中断或持有 spinlock 时睡眠。用户态给内核传参通常通过系统调用进入 VFS 或具体子系统，驱动再用 `copy_from_user/copy_to_user` 安全交换数据。内核出错可能影响整机，所以要特别关注上下文、锁、内存分配和对象生命周期。
