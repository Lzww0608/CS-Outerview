# 1. Linux 内核裁剪与镜像体积

Linux 内核裁剪是指根据目标硬件和产品场景，关闭不需要的内核功能、驱动、文件系统、调试选项和协议栈，只保留启动和业务运行必需的能力。嵌入式面试问“裁剪后镜像多大”，重点不是背一个固定数字，而是说明体积由架构、配置、压缩方式、内置驱动和模块拆分共同决定。

## 1. 裁剪后镜像大小怎么看

常见内核产物包括：

| 产物 | 含义 | 说明 |
| --- | --- | --- |
| `vmlinux` | 未压缩、带符号的 ELF 内核 | 体积很大，调试用，不是最终烧录体积 |
| `Image` | 未压缩内核镜像 | ARM64 常见 |
| `zImage` / `Image.gz` | 压缩内核镜像 | 嵌入式启动常见，体积明显小于 `Image` |
| `uImage` | U-Boot 头 + 压缩内核 | 便于 U-Boot 识别加载 |
| `*.dtb` | 设备树二进制 | 描述板级硬件，不等于内核本体 |
| `rootfs` | 根文件系统 | BusyBox、库、应用和配置通常在这里 |

实际大小没有统一答案。一个嵌入式 ARM/ARM64 裁剪后的压缩内核可能是几 MB 到十几 MB；通用发行版内核加大量内置能力、调试信息和模块集合可能是几十 MB 甚至更多。回答时可以说：

```text
我不会只报固定值，会先看 arch、.config、压缩方式、驱动是 built-in 还是 module、
是否带 debug symbol，以及是否把 rootfs 算进镜像。
```

常用查看方式：

```bash
ls -lh arch/arm/boot/zImage
ls -lh arch/arm64/boot/Image.gz
size vmlinux
scripts/bloat-o-meter old-vmlinux new-vmlinux
```

## 2. 为什么要裁剪

嵌入式设备通常受 Flash、RAM、启动时间、功耗和安全面约束。裁剪的价值包括：

1. **减小存储占用**：镜像越小，Flash 分区压力越低，OTA 包也更小。
2. **降低内存占用**：内置代码、静态数据、驱动状态都会消耗内存。
3. **缩短启动时间**：少初始化无关驱动、总线、文件系统和协议栈。
4. **降低攻击面**：不用的网络协议、文件系统、调试接口不应暴露在产品中。
5. **提升稳定性**：少加载无关驱动，减少初始化失败、资源冲突和中断干扰。
6. **满足产品约束**：手机、路由器、IoT、车机对启动速度和资源占用都有明确指标。

## 3. 怎么裁剪

常见入口：

```bash
make defconfig
make menuconfig
make savedefconfig
```

裁剪方向：

1. **架构和平台**：只保留目标 SoC、板级平台、CPU 特性。
2. **驱动**：关闭不用的网卡、声卡、显示、存储、传感器、USB 子类。
3. **文件系统**：只保留产品实际用到的 ext4、squashfs、ubifs、tmpfs 等。
4. **网络协议**：关闭不用的 IPv6、隧道、Netfilter 扩展或调试协议。
5. **调试功能**：量产版本关闭 `DEBUG_KERNEL`、KASAN、lockdep、ftrace 等重型调试。
6. **built-in vs module**：启动必需驱动编进内核，非关键驱动做模块或不编译。

要注意：裁剪不是越小越好。启动阶段必须用到的存储控制器、根文件系统、console、时钟、pinctrl、GPIO、I2C/SPI 等如果裁掉，系统可能无法启动或无法挂载 rootfs。

## 4. 易错点

1. 把 `vmlinux` 体积当成最终烧录镜像体积。`vmlinux` 常带符号，和压缩后的 `zImage/Image.gz` 差异很大。
2. 只看内核本体，不看 dtb、initramfs、rootfs 和内核模块目录。
3. 把启动必需驱动做成模块，但 rootfs 还没挂载，导致模块无法加载。
4. 关闭调试选项后问题更难定位，开发版和量产版应使用不同配置。
5. 裁剪后没有跑启动、外设、休眠唤醒、OTA 和异常恢复测试。

## 5. 面试回答模板

Linux 内核裁剪后的大小没有固定值，取决于架构、`.config`、压缩格式、驱动是否内置、是否带调试信息，以及是否把 dtb/rootfs/module 算进去。嵌入式压缩内核常见是几 MB 到十几 MB，但我会用 `ls -lh zImage/Image.gz`、`size vmlinux` 和配置 diff 实际确认。裁剪的目的是降低 Flash/RAM 占用、缩短启动时间、减少攻击面和无关驱动风险。裁剪时通过 `menuconfig` 关闭不用的平台、驱动、文件系统、协议和调试功能，但启动必需的 console、存储、根文件系统和板级总线驱动不能裁掉。
