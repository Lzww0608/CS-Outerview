# 10. 进程、线程和协程

进程、线程和协程都是描述程序执行单元的概念，但它们所在的抽象层不同：进程偏资源隔离，线程偏 CPU 调度，协程偏用户态任务调度和异步流程表达。

## 1. 并发和并行

并发和并行经常一起出现，但含义不同：

1. **并发（Concurrency）**：多个任务在同一段时间内都处于推进状态，强调任务组织和调度。单核 CPU 通过时间片切换也能实现并发。
2. **并行（Parallelism）**：多个任务在同一时刻真正同时执行，强调硬件多核或多执行单元同时工作。

举例：

```text
单核 CPU 上 100 个连接交替处理：并发，但不是并行
8 核 CPU 上 8 个线程同时计算：并发，也是并行
单线程事件循环处理多个 socket：并发，但不是 CPU 并行
```

面试里可以补一句：并发是软件结构能力，并行是硬件执行能力；高并发系统不一定需要大量线程并行，I/O 密集服务更常用事件循环、线程池或协程减少阻塞等待。

## 2. 进程是什么

进程是操作系统进行资源分配和隔离的基本单位。一个进程通常拥有独立的虚拟地址空间、页表、文件描述符表、信号处理配置、堆、全局变量和代码段等资源。

在 Linux 中，进程和线程底层都由 `task_struct` 描述。进程创建常见方式是 `fork()`，子进程获得父进程地址空间的写时复制视图；真正执行新程序时通常再调用 `execve()`。

进程的特点：

1. **隔离性强**：一个进程崩溃通常不会直接破坏另一个进程的内存。
2. **创建和切换成本较高**：进程切换可能涉及地址空间切换、TLB 失效和更多内核状态维护。
3. **通信需要 IPC**：管道、消息队列、共享内存、Unix Domain Socket、TCP 等。
4. **适合强隔离场景**：多服务部署、浏览器多进程、安全沙箱、任务 worker。

## 3. 线程是什么

线程是 CPU 调度的基本执行单元。同一进程内的多个线程共享地址空间、堆、全局变量和文件描述符，但每个线程有自己的寄存器上下文、用户栈、内核栈、线程局部存储和调度状态。

Linux 上常见 pthread / `std::thread` 是 1:1 线程模型，即一个用户线程对应一个内核可调度实体，通常通过 `clone()` 创建，并使用 `CLONE_VM`、`CLONE_FILES`、`CLONE_SIGHAND` 等标志共享进程资源。

线程的特点：

1. **共享数据方便**：同进程线程可以直接访问同一块内存。
2. **并发风险更高**：共享内存会带来数据竞争、可见性、死锁和伪共享问题。
3. **切换比进程轻**：同进程线程切换通常不用切换页表，但仍要进入内核调度。
4. **适合并行计算和阻塞任务托管**：CPU 密集任务、线程池、同步库调用、阻塞 I/O 隔离。

## 4. 协程是什么

协程通常是由语言运行时或用户态调度器管理的轻量执行单元。协程切换一般不进入内核，只保存少量寄存器、栈指针、挂起点或协程帧，因此成本低于线程切换。

协程可以分为：

| 类型 | 核心机制 | 代表 |
| --- | --- | --- |
| 有栈协程 | 每个协程有独立调用栈，可在深层调用中挂起 | Go goroutine、Lua coroutine、libco |
| 无栈协程 | 编译器把函数转换为状态机，挂起点保存到协程帧 | C++20 coroutine、Rust async、Python async/await |

协程的特点：

1. **数量可以很多**：适合海量连接、爬虫、RPC、网关等 I/O 密集业务。
2. **切换成本低**：很多切换在用户态完成。
3. **通常依赖非阻塞 I/O**：网络库用 epoll/kqueue/io_uring 等机制等待 I/O 就绪，再恢复协程。
4. **不天然等于并行**：单线程事件循环里的协程是并发不是并行；Go goroutine 可以通过 G-M-P 调度到多个 OS 线程并行。

## 5. 三者对比

| 对比项 | 进程 | 线程 | 协程 |
| --- | --- | --- | --- |
| 管理者 | 操作系统 | 操作系统或线程库 | 语言运行时/用户态调度器 |
| 资源隔离 | 强 | 同进程内弱 | 通常共享线程和进程资源 |
| 调度层级 | 内核调度 | 内核调度 | 用户态调度，底层仍依赖线程 |
| 切换成本 | 高 | 中 | 低 |
| 通信方式 | IPC | 共享内存 + 同步原语 | channel、await、共享状态、事件循环 |
| 并行能力 | 多进程可并行 | 多线程可并行 | 取决于是否映射到多个线程 |
| 典型风险 | IPC 复杂、资源开销大 | 数据竞争、死锁、上下文切换 | 阻塞调用卡住事件循环、调度器复杂 |

### 5.1 为什么虚拟地址空间切换更耗时

同进程线程切换通常不需要切换虚拟地址空间，而跨进程切换通常要切换 `mm_struct` 和页表根。耗时主要来自：

1. **页表根切换**：CPU 要切到另一个进程的地址翻译上下文，例如 x86 上的 CR3。
2. **TLB 影响**：TLB 缓存的是虚拟页到物理页的翻译结果，换地址空间后旧翻译大多不能直接复用；现代 CPU 的 PCID/ASID 可以缓解，但不能消除全部影响。
3. **Cache 局部性下降**：新进程访问的代码和数据可能不在 L1/L2/L3 cache 中，产生更多 cache miss。
4. **内核调度路径成本**：保存/恢复寄存器、切换内核栈、更新调度状态和运行队列都需要时间。
5. **安全隔离成本**：地址空间隔离带来更强安全性，但也意味着跨进程共享数据要通过 IPC 或共享内存显式处理。

因此，线程切换通常比进程切换轻，不是因为线程没有上下文，而是同一进程线程共享地址空间，很多内存管理上下文可以复用。

### 5.2 进程和线程共享/不共享什么

同一进程内的线程共享大部分进程资源，但每个线程必须保留自己的执行现场。

| 内容 | 同一进程内线程是否共享 | 说明 |
| --- | --- | --- |
| 虚拟地址空间 | 共享 | 代码段、堆、全局变量、mmap 区通常共享 |
| 文件描述符表 | 共享 | 一个线程 `close(fd)` 会影响其他线程 |
| 当前工作目录、根目录 | 共享 | 属于进程级文件系统上下文 |
| 信号处理函数 | 共享 | 但每个线程可以有自己的信号屏蔽字 |
| 程序计数器/指令指针 | 不共享 | 每个线程执行到的位置不同 |
| 通用寄存器 | 不共享 | 上下文切换时分别保存和恢复 |
| 用户栈/内核栈 | 不共享 | 每个线程有自己的调用栈，语义上独立 |
| TLS 线程局部存储 | 不共享 | `thread_local`、`pthread_key` 等属于线程局部状态 |
| 调度状态 | 不共享 | 每个线程是独立可调度实体 |

不同进程之间默认不共享地址空间、堆、全局变量和用户栈，通信通常要通过 IPC；但也存在共享内存、mmap 共享映射、继承 fd、Unix Domain Socket 等显式共享方式。

面试易错点：说“线程不共享栈”是从语义和默认使用角度讲的；因为线程共享同一进程地址空间，一个线程如果拿到了另一个线程栈上对象的地址，技术上也能访问，但这通常是不安全的生命周期问题。

## 6. 协程和线程的阻塞问题

协程高并发的前提是阻塞点被运行时接管。以网络读写为例：

```text
协程调用 read
-> fd 非阻塞，返回 EAGAIN
-> 当前协程挂起
-> 事件循环 epoll_wait
-> fd 可读
-> 恢复协程继续执行
```

如果协程里直接调用没有被 runtime 托管的阻塞系统调用，承载它的线程可能被卡住，导致同一线程上的其他协程也无法运行。工程上常见处理方式：

1. 网络 I/O 使用非阻塞 fd 和事件循环。
2. 文件 I/O、DNS、压缩、加密等可能阻塞的任务放线程池。
3. CPU 密集任务控制并行度，避免占满事件循环线程。
4. 所有外部依赖都加超时和取消机制。

## 7. 真实场景如何选择

1. **需要强隔离**：用进程或容器，例如浏览器 tab、插件沙箱、用户代码执行。
2. **CPU 密集并行**：用多线程或多进程，按 CPU 核数控制并行度。
3. **大量 I/O 并发**：用 epoll + 线程池，或使用协程框架把异步流程写成同步风格。
4. **高可靠服务端**：常见组合是少量进程做隔离，每个进程内少量 I/O 线程，每个 I/O 线程承载大量连接或协程，阻塞任务下沉到 worker pool。

## 8. 易错点

1. 不要说“线程是资源分配单位”。更准确是进程偏资源容器，线程偏调度执行单元。
2. 不要说“协程一定不能并行”。单线程协程不能并行，但 Go goroutine 等可以调度到多个线程。
3. 协程不是操作系统直接调度的实体，底层仍要依赖线程获得 CPU。
4. 线程共享地址空间不代表线程栈不能被其他线程访问，只是语义上每个线程自己使用自己的栈。
5. 协程数量多不代表可以无限制创建，仍会消耗栈/协程帧、调度队列、连接和内存。

## 9. 面试回答模板

进程是资源分配和隔离单位，拥有独立虚拟地址空间，通信通常要走 IPC，隔离强但创建和切换成本高。线程是 CPU 调度执行单元，同一进程内线程共享地址空间和 fd，但有自己的栈、寄存器和 TLS，切换比进程轻，问题是要处理数据竞争和锁。协程是用户态轻量任务，由语言运行时调度，切换成本低，适合高并发 I/O；但协程本身不等于多核并行，阻塞调用必须交给非阻塞 I/O、事件循环或线程池托管。
