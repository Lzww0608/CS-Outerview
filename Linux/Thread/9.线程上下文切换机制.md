# 9. 线程上下文切换机制

线程上下文切换是 CPU 从当前线程切到另一个可运行线程时，保存旧线程执行状态并恢复新线程执行状态的过程。它由操作系统调度器完成，是内核级线程并发的基础。

## 1. 什么会触发线程切换

常见触发点包括：

1. 时间片用完，调度器抢占当前线程。
2. 线程执行阻塞系统调用，例如阻塞 `read`、`accept`、`futex wait`。
3. 线程等待锁、条件变量、信号量等同步对象。
4. 更高优先级线程被唤醒，内核决定抢占当前线程。
5. 当前线程主动调用 `sched_yield` 或睡眠接口。
6. 中断返回内核态时发现需要重新调度。

系统调用不一定导致线程切换。非阻塞 I/O、快速路径 mutex 加锁、读取时间等系统调用可能很快返回，仍由当前线程继续执行。

## 2. 切换时保存什么

线程切换至少涉及：

1. 通用寄存器、程序计数器、栈指针、状态寄存器。
2. 当前线程的内核栈位置和调度状态。
3. 浮点/SIMD 寄存器上下文，通常按需保存或延迟保存。
4. 调度器运行队列信息、优先级、时间片等元数据。
5. 如果切到不同进程，还可能切换页表、地址空间，并影响 TLB。

同一进程内的线程共享地址空间，所以一般不需要切换页表，这是线程切换通常比进程切换轻的主要原因。但它仍然要进入内核调度路径，并可能带来 cache/TLB 扰动。

## 3. 大致流程

```text
当前线程进入内核或被中断
-> 内核判断 need_resched
-> 保存当前线程寄存器和内核栈上下文
-> 更新线程状态，放回运行队列或等待队列
-> 调度器选择下一个可运行线程
-> 切换内核栈和调度上下文
-> 恢复新线程寄存器
-> 返回用户态继续执行
```

真实内核实现会包含优先级、负载均衡、CPU 亲和性、NUMA、实时调度类等更多细节。面试时抓住“保存旧上下文、选择新线程、恢复新上下文”即可。

## 4. 成本来源

线程切换的成本不只是几条保存寄存器的指令：

1. 内核调度路径本身有开销。
2. 被切出的线程热数据可能从 cache 中被挤出。
3. 跨核迁移会带来 cache line 重新获取和缓存一致性流量。
4. 跨进程切换可能导致 TLB 失效或地址空间切换成本。
5. 锁竞争导致的睡眠和唤醒会放大尾延迟。

因此高性能服务不是“线程越多越好”。线程数通常要和 CPU 核数、阻塞比例、I/O 模型和业务耗时配合设计。

## 5. 和协程切换的区别

协程切换通常由用户态运行时完成，保存的是协程恢复所需状态，例如栈指针、少量寄存器、挂起点或协程帧。它通常不进入内核，也不由 OS 调度器选择，因此成本更低。

但协程并不自动带来多核并行。如果一个线程承载很多协程，而某个协程调用了未被 runtime 接管的阻塞系统调用，整个线程都会被阻塞。工程上常把协程用于高并发 I/O，把 CPU 密集或阻塞任务交给线程池。

## 6. 面试回答模板

线程上下文切换是内核调度器保存当前线程寄存器、PC、栈指针、内核栈和调度状态，再恢复另一个线程上下文的过程。它可能由时间片耗尽、阻塞系统调用、锁等待、主动让出或更高优先级线程唤醒触发。同进程线程切换通常不切换地址空间，所以比进程切换轻，但仍要进入内核，并且会带来 cache、TLB、调度器和锁竞争成本。协程切换多在用户态完成，通常更轻，但需要配合非阻塞 I/O 或 runtime 调度，不能把阻塞调用直接塞进事件循环。
