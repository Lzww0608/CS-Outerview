# 6. 线程状态与状态转换

线程状态描述的是线程在调度器和同步原语中的运行位置。不同语言和操作系统命名略有差异，但面试通常按“新建、就绪、运行、阻塞、结束”来回答。

## 常见线程状态

| 状态 | 含义 | 例子 |
| --- | --- | --- |
| 新建 New | 线程对象创建，还未真正开始执行 | `std::thread` 构造前后的语言抽象 |
| 就绪 Ready | 可以运行，等待 CPU 调度 | 已在运行队列中 |
| 运行 Running | 正在 CPU 上执行 | 当前获得时间片 |
| 阻塞 Blocked/Waiting | 等待某个事件，暂时不能运行 | 等锁、条件变量、I/O、sleep |
| 结束 Terminated | 执行完毕或被取消 | 函数返回、异常终止 |

Linux 内核里进程和线程都用 `task_struct` 描述，常见状态包括 `TASK_RUNNING`、`TASK_INTERRUPTIBLE`、`TASK_UNINTERRUPTIBLE`、`TASK_STOPPED`、`EXIT_ZOMBIE` 等。需要注意，Linux 的 `TASK_RUNNING` 同时覆盖“正在运行”和“可运行等待调度”。

## 状态转换

```text
新建 -> 就绪 -> 运行 -> 结束
          ^      |
          |      v
        阻塞 <- 等锁/I-O/sleep
```

常见转换：

1. **就绪 -> 运行**：调度器选中该线程，分配 CPU。
2. **运行 -> 就绪**：时间片用完、被更高优先级线程抢占、主动 `yield`。
3. **运行 -> 阻塞**：等待锁、等待条件变量、阻塞 I/O、sleep。
4. **阻塞 -> 就绪**：等待事件发生，例如锁释放、I/O 就绪、定时器到期。
5. **运行 -> 结束**：线程函数返回或异常终止。

## 运行态能变成就绪态吗

能。运行态线程并不一定一直运行到阻塞或结束，它可能因为以下原因回到就绪态：

1. 时间片耗尽，被调度器抢占。
2. 更高优先级线程变为可运行，当前线程被抢占。
3. 当前线程主动调用 `sched_yield()` 或类似让出 CPU。
4. CPU 亲和性、负载均衡等调度策略导致迁移或重新排队。

这时线程仍然具备运行条件，只是暂时没有占用 CPU。

## 等待态可以收到信号吗

可以，但要区分等待类型。

Linux 中常见睡眠等待状态包括：

1. **可中断睡眠 `TASK_INTERRUPTIBLE`**：等待 I/O、条件或某些阻塞系统调用时，如果收到未屏蔽信号，可以被唤醒，系统调用可能返回 `-EINTR`。
2. **不可中断睡眠 `TASK_UNINTERRUPTIBLE`**：通常用于等待关键内核事件，例如某些磁盘 I/O。普通信号不会打断它，`ps` 中常显示为 `D` 状态。
3. **可杀死睡眠 `TASK_KILLABLE`**：介于两者之间，可响应致命信号，减少长期 D 状态无法杀死的问题。

应用层要注意：阻塞系统调用被信号打断后，可能返回 `EINTR`。是否重试取决于接口和业务语义，例如：

```cpp
ssize_t n;
do {
    n = read(fd, buf, sizeof(buf));
} while (n < 0 && errno == EINTR);
```

但不能所有场景都无脑重试，例如带超时的等待要重新计算剩余时间，退出信号也可能要求尽快结束。

## 易错点

1. 阻塞和就绪不同：阻塞是条件不满足，不能运行；就绪是能运行但没分到 CPU。
2. sleep 是主动等待时间，不适合代替条件变量做线程同步。
3. Linux 中 `TASK_RUNNING` 不等于一定正在 CPU 上运行，也可能只是可运行。
4. 用户态看到的线程状态可能是语言运行时抽象，不完全等同于内核状态。

## 面试回答模板

线程常见状态有新建、就绪、运行、阻塞和结束。就绪表示已经具备运行条件但还没拿到 CPU；运行表示正在 CPU 上执行；阻塞表示在等锁、I/O、条件变量或定时器。运行态可以变成就绪态，例如时间片用完、被更高优先级线程抢占或主动 yield；运行态也可以因为等待锁或 I/O 进入阻塞态。Linux 里 `TASK_RUNNING` 同时包含运行和就绪，要注意这个命名差异。
