# 5. 主线程等待子线程消费资源

## 1. 题目

主线程创建一个资源，交给子线程消费；在子线程消费完成之前，主线程需要 `wait` 住。要求不能忙等，不能依赖 `sleep` 猜时间。

这是一个一次性生产者-消费者同步问题。常见解法有：

1. `mutex + condition_variable`。
2. `std::promise + std::future`。
3. `std::latch` 或信号量。

面试中最推荐先写条件变量，因为它能体现对状态、锁、等待和通知的理解。

## 2. 条件变量实现

```cpp
#include <condition_variable>
#include <iostream>
#include <mutex>
#include <optional>
#include <string>
#include <thread>
#include <utility>

struct Resource {
    std::string data;
};

std::mutex m;
std::condition_variable cv_ready;
std::condition_variable cv_done;
std::optional<Resource> resource;
bool ready = false;
bool consumed = false;

void worker() {
    Resource local;

    {
        std::unique_lock<std::mutex> lock(m);
        cv_ready.wait(lock, [] {
            return ready;
        });

        local = std::move(*resource);
        resource.reset();
        ready = false;
    }

    std::cout << "consume: " << local.data << std::endl;

    {
        std::lock_guard<std::mutex> lock(m);
        consumed = true;
    }
    cv_done.notify_one();
}

int main() {
    std::thread t(worker);

    {
        std::lock_guard<std::mutex> lock(m);
        resource.emplace(Resource{"hello"});
        ready = true;
        consumed = false;
    }
    cv_ready.notify_one();

    {
        std::unique_lock<std::mutex> lock(m);
        cv_done.wait(lock, [] {
            return consumed;
        });
    }

    t.join();
    return 0;
}
```

## 3. 核心原理

这个设计里有两个状态：

1. `ready`：资源已经创建，可以被子线程消费。
2. `consumed`：资源已经被子线程消费完成，主线程可以继续。

两个条件变量分别对应两个阶段：

1. `cv_ready`：主线程通知子线程资源就绪。
2. `cv_done`：子线程通知主线程消费完成。

也可以只用一个条件变量，但分成两个条件变量更容易表达两个不同条件。

## 4. 为什么不能只 notify 不保存状态

`notify_one()` 是瞬时信号，不会记账。如果主线程先 notify，而子线程稍后才 wait，通知会丢失。正确做法是把真实条件写入状态变量，例如 `ready = true`，并用：

```cpp
cv.wait(lock, [] { return ready; });
```

这样即使通知先发生，子线程进入 `wait` 时也会先检查 `ready`，发现条件已满足后直接继续执行。

## 5. promise/future 实现

如果只是一次性等待结果，`promise/future` 更简洁：

```cpp
#include <future>
#include <iostream>
#include <string>
#include <thread>
#include <utility>

struct Resource {
    std::string data;
};

int main() {
    std::promise<void> done;
    std::future<void> fut = done.get_future();

    Resource resource{"hello"};

    std::thread t([r = std::move(resource), p = std::move(done)]() mutable {
        std::cout << "consume: " << r.data << std::endl;
        p.set_value();
    });

    fut.wait();
    t.join();
    return 0;
}
```

`future::wait()` 内部会阻塞当前线程，直到 promise 设置结果。它适合一次性完成通知，不适合复杂多轮生产消费队列。

## 6. 易错点

1. 主线程 wait 前必须有谓词，例如 `consumed`，否则可能丢通知。
2. 子线程消费资源时如果耗时较长，应把资源移动到局部变量后释放锁，避免主线程或其他线程长时间拿不到锁。
3. `notify_one()` 通常放在释放锁之后，减少被唤醒线程立刻竞争同一把锁的概率。
4. 如果子线程可能抛异常，也要保证通知主线程，否则主线程可能永久等待。
5. 多轮资源生产消费时，最好使用队列、停止标志和循环谓词，而不是单个 `optional`。
