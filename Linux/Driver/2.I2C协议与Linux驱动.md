# 2. I2C 协议与 Linux 驱动

I2C，也常写作 IIC，是一种两线制、同步、半双工、主从结构的低速板级总线。它常用于连接 PMIC、EEPROM、RTC、触摸芯片、摄像头 sensor、温湿度传感器等外设。

## 1. I2C 信号线和电气特性

I2C 只有两根核心信号线：

1. **SCL**：时钟线，由主机产生时钟。
2. **SDA**：数据线，双向传输数据。

两根线通常是开漏/开集输出，需要上拉电阻。设备只能主动拉低总线，释放后由上拉电阻拉高。这样多个设备可以共享总线，也支持仲裁。

电气上要关注：

1. 上拉电阻大小：太大上升沿慢，太小功耗和拉低电流大。
2. 总线电容：线长、器件数量、走线都会影响上升时间。
3. 电平兼容：1.8V、3.3V、5V 设备混用要做电平转换。
4. ACK/NACK：第 9 个时钟由接收方拉低 SDA 表示 ACK。

## 2. 常见速度模式

| 模式 | 典型速率 |
| --- | --- |
| Standard-mode | 100 kbit/s |
| Fast-mode | 400 kbit/s |
| Fast-mode Plus | 1 Mbit/s |
| High-speed mode | 3.4 Mbit/s |

真实板子能跑多快，不只看控制器配置，还受上拉、电容、走线、从设备能力和时序裕量影响。驱动里设备树常见配置：

```dts
i2c1 {
    clock-frequency = <400000>;
    sensor@1a {
        compatible = "vendor,sensor";
        reg = <0x1a>;
    };
};
```

## 3. 波形和协议流程

I2C 基本波形规则：

1. 总线空闲时，SCL 和 SDA 都为高。
2. **START**：SCL 高电平期间，SDA 从高变低。
3. **STOP**：SCL 高电平期间，SDA 从低变高。
4. 数据位在 SCL 低电平期间变化，在 SCL 高电平期间保持稳定。
5. 每传 8 bit 后，第 9 个 clock 传 ACK/NACK。

写寄存器常见流程：

```text
START
-> 设备地址 + Write
-> ACK
-> 寄存器地址
-> ACK
-> 数据
-> ACK
-> STOP
```

读寄存器常见流程：

```text
START
-> 设备地址 + Write
-> ACK
-> 寄存器地址
-> ACK
-> Repeated START
-> 设备地址 + Read
-> ACK
-> 读取数据
-> NACK
-> STOP
```

Repeated START 的意义是不中途释放总线，在同一次事务中先写寄存器地址再读数据。

## 4. Linux I2C 驱动结构

Linux I2C 分层大致是：

```text
I2C client driver
  -> I2C core
  -> I2C adapter driver
  -> SoC I2C controller
  -> SDA/SCL 总线
  -> I2C slave device
```

设备驱动通常实现 `i2c_driver`：

```c
static int demo_probe(struct i2c_client *client) {
    int ret;
    u8 reg = 0x00;

    ret = i2c_smbus_read_byte_data(client, reg);
    if (ret < 0)
        return ret;

    return 0;
}

static const struct of_device_id demo_of_match[] = {
    { .compatible = "vendor,demo-i2c" },
    {}
};

static struct i2c_driver demo_driver = {
    .probe = demo_probe,
    .driver = {
        .name = "demo_i2c",
        .of_match_table = demo_of_match,
    },
};
module_i2c_driver(demo_driver);
```

复杂读写可用 `i2c_transfer()` 发送多个 message：

```c
struct i2c_msg msgs[2] = {
    { .addr = client->addr, .flags = 0, .len = 1, .buf = &reg },
    { .addr = client->addr, .flags = I2C_M_RD, .len = len, .buf = buf },
};
ret = i2c_transfer(client->adapter, msgs, 2);
```

## 5. 常见问题排查

1. **无 ACK**：地址错、7 位/8 位地址混淆、设备未上电、reset 未释放、pinctrl 错。
2. **波形异常**：上拉不合适、SCL/SDA 接反、复用功能没切到 I2C、线太长。
3. **偶发失败**：速率过高、边沿慢、干扰、时序裕量不足。
4. **读值全 0/全 FF**：寄存器地址宽度错、大小端错、读写流程缺 repeated start。
5. **总线卡死**：从设备异常拉低 SDA，需要控制器恢复或 GPIO bit-bang 释放 9 个 clock。

## 6. 面试回答模板

I2C 是两线同步串行总线，SCL 是时钟，SDA 是数据，开漏输出配上拉电阻，总线空闲时两线为高。START 是 SCL 高时 SDA 下降，STOP 是 SCL 高时 SDA 上升，数据在 SCL 高电平期间保持稳定，每 8 bit 后有 ACK。常见速率有 100k、400k、1M 和 3.4M。Linux 中 I2C 分 client driver、I2C core、adapter driver 和控制器驱动，设备一般通过设备树 `compatible/reg/clock-frequency` 描述，驱动用 `i2c_smbus_*` 或 `i2c_transfer()` 读写。排查时软硬件都要看：驱动地址、设备树、pinctrl、clock、reset、供电，以及示波器/逻辑分析仪上的 START、地址、ACK 和时序。
