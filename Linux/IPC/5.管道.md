# 5. 管道

管道是 Unix/Linux 中最常见的进程间通信方式之一，本质是内核维护的一段 FIFO 字节流缓冲区。进程通过文件描述符读写管道，数据按写入顺序被读取。

## 匿名管道

匿名管道通过 `pipe()` 创建：

```c
int fds[2];
pipe(fds); // fds[0] 读端，fds[1] 写端
```

特点：

1. 没有文件系统路径，只能通过 fd 使用。
2. 通常用于有亲缘关系的进程，例如父进程 `fork()` 子进程后，把管道 fd 继承给子进程。
3. 半双工，常见用法是一个方向一个 pipe；双向通信需要两个 pipe。
4. 数据在内核缓冲区中，不落普通磁盘文件。

经典例子是 shell 管道：

```bash
cat a.txt | grep error
```

shell 会创建 pipe，再 fork 两个子进程，把前一个进程 stdout 接到管道写端，把后一个进程 stdin 接到管道读端。

### Shell 中 `|` 背后的系统调用

Linux 命令行里的 `|` 是匿名管道，不是命名管道。命名管道需要 `mkfifo` 创建路径，而 shell 管道只在内核中创建一段临时管道缓冲区。

以：

```bash
cat a.txt | grep error
```

为例，shell 典型流程如下：

1. `pipe()` 或 `pipe2()` 创建匿名管道，得到读端 fd 和写端 fd。
2. `fork()` 或 `clone()` 创建第一个子进程执行 `cat`。
3. 在 `cat` 子进程中用 `dup2(pipefd[1], STDOUT_FILENO)` 把标准输出重定向到管道写端。
4. 关闭子进程中不需要的管道 fd，然后 `execve()` 加载 `cat` 程序。
5. shell 再创建第二个子进程执行 `grep`。
6. 在 `grep` 子进程中用 `dup2(pipefd[0], STDIN_FILENO)` 把标准输入重定向到管道读端。
7. 关闭不需要的 fd，然后 `execve()` 加载 `grep` 程序。
8. 父 shell 关闭自己持有的管道读写端，并用 `waitpid()` 等待前台任务结束。

前一个命令的结果不会直接输出到屏幕，是因为它的 `STDOUT_FILENO` 已经不再指向终端设备，而是指向管道写端。后一个命令从自己的标准输入读取数据，而它的标准输入已经被接到管道读端。

易错点：

1. 默认只重定向 stdout，不重定向 stderr；如果前一个命令写标准错误，仍可能显示到屏幕。需要合并时可使用 `2>&1`。
2. 父子进程都要关闭不需要的读端或写端，否则读端可能迟迟等不到 EOF。
3. 管道传递的是字节流，命令之间约定的是文本行、二进制帧还是长度前缀，属于应用层协议。

## 命名管道 FIFO

命名管道通过 `mkfifo()` 或 `mkfifo` 命令创建，在文件系统中有路径：

```bash
mkfifo /tmp/my_fifo
```

特点：

1. 有路径名，无亲缘关系的进程也能通过路径打开同一个 FIFO。
2. 文件类型是 FIFO，不是普通文件；数据仍经过内核管道缓冲区。
3. 默认阻塞语义明显：只读打开会等写端，只写打开会等读端。
4. 适合简单单机进程间通知或流式数据传递。

典型使用流程：

```bash
mkfifo /tmp/my_fifo

# 终端 1，读端会阻塞等待写端
cat /tmp/my_fifo

# 终端 2，写入数据
echo "hello" > /tmp/my_fifo
```

C 代码里也可以把 FIFO 当成特殊文件打开：

```c
#include <fcntl.h>
#include <sys/stat.h>
#include <unistd.h>

mkfifo("/tmp/my_fifo", 0666);
int fd = open("/tmp/my_fifo", O_WRONLY);
write(fd, "hello\n", 6);
close(fd);
```

注意事项：

1. FIFO 路径存在于文件系统，`unlink` 后路径消失；已经打开的 fd 仍按内核对象生命周期工作。
2. 默认阻塞打开容易让程序卡住，服务端常配合 `O_NONBLOCK`、超时或事件循环。
3. FIFO 传的是字节流，没有消息边界；多写者时要关注 `PIPE_BUF` 原子写限制。
4. FIFO 适合本机简单通信，不适合复杂请求响应协议；复杂场景通常用 Unix Domain Socket。

## 匿名管道和命名管道区别

| 对比项 | 匿名管道 | 命名管道 FIFO |
| --- | --- | --- |
| 创建方式 | `pipe()` | `mkfifo()` |
| 是否有路径 | 没有 | 有 |
| 通信进程关系 | 通常要求亲缘关系 | 无亲缘关系也可以 |
| 生命周期 | fd 全部关闭后消失 | 路径存在直到删除 |
| 用途 | 父子进程通信、shell 管道 | 本机服务间简单通信 |

## 阻塞和非阻塞

1. 读空管道：阻塞模式会等待；非阻塞模式返回 `EAGAIN`。
2. 写满管道：阻塞模式会等待；非阻塞模式返回 `EAGAIN`。
3. 所有写端关闭后，读端 `read()` 返回 0，表示 EOF。
4. 所有读端关闭后，写端写入会触发 `SIGPIPE` 或返回 `EPIPE`。

## 易错点

1. 管道是字节流，没有消息边界；应用层要自己定义分隔符或长度。
2. `PIPE_BUF` 以内的单次写通常具备原子性，超过后可能和其他写入交错。
3. 父子进程使用管道后要关闭不需要的读端/写端，否则 EOF 不会按预期到来。
4. 管道适合本机简单通信，不适合复杂 RPC；复杂场景更推荐 Unix Domain Socket。
