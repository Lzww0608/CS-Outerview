# 5. 管道

管道是 Unix/Linux 中最常见的进程间通信方式之一，本质是内核维护的一段 FIFO 字节流缓冲区。进程通过文件描述符读写管道，数据按写入顺序被读取。

## 匿名管道

匿名管道通过 `pipe()` 创建：

```c
int fds[2];
pipe(fds); // fds[0] 读端，fds[1] 写端
```

特点：

1. 没有文件系统路径，只能通过 fd 使用。
2. 通常用于有亲缘关系的进程，例如父进程 `fork()` 子进程后，把管道 fd 继承给子进程。
3. 半双工，常见用法是一个方向一个 pipe；双向通信需要两个 pipe。
4. 数据在内核缓冲区中，不落普通磁盘文件。

经典例子是 shell 管道：

```bash
cat a.txt | grep error
```

shell 会创建 pipe，再 fork 两个子进程，把前一个进程 stdout 接到管道写端，把后一个进程 stdin 接到管道读端。

## 命名管道 FIFO

命名管道通过 `mkfifo()` 或 `mkfifo` 命令创建，在文件系统中有路径：

```bash
mkfifo /tmp/my_fifo
```

特点：

1. 有路径名，无亲缘关系的进程也能通过路径打开同一个 FIFO。
2. 文件类型是 FIFO，不是普通文件；数据仍经过内核管道缓冲区。
3. 默认阻塞语义明显：只读打开会等写端，只写打开会等读端。
4. 适合简单单机进程间通知或流式数据传递。

## 匿名管道和命名管道区别

| 对比项 | 匿名管道 | 命名管道 FIFO |
| --- | --- | --- |
| 创建方式 | `pipe()` | `mkfifo()` |
| 是否有路径 | 没有 | 有 |
| 通信进程关系 | 通常要求亲缘关系 | 无亲缘关系也可以 |
| 生命周期 | fd 全部关闭后消失 | 路径存在直到删除 |
| 用途 | 父子进程通信、shell 管道 | 本机服务间简单通信 |

## 阻塞和非阻塞

1. 读空管道：阻塞模式会等待；非阻塞模式返回 `EAGAIN`。
2. 写满管道：阻塞模式会等待；非阻塞模式返回 `EAGAIN`。
3. 所有写端关闭后，读端 `read()` 返回 0，表示 EOF。
4. 所有读端关闭后，写端写入会触发 `SIGPIPE` 或返回 `EPIPE`。

## 易错点

1. 管道是字节流，没有消息边界；应用层要自己定义分隔符或长度。
2. `PIPE_BUF` 以内的单次写通常具备原子性，超过后可能和其他写入交错。
3. 父子进程使用管道后要关闭不需要的读端/写端，否则 EOF 不会按预期到来。
4. 管道适合本机简单通信，不适合复杂 RPC；复杂场景更推荐 Unix Domain Socket。
