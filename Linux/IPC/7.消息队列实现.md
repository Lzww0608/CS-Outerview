# 7. 消息队列实现

## 1. Linux IPC 消息队列是什么

消息队列是一种内核维护的 IPC 对象。发送进程把一条消息复制到内核队列，接收进程再从内核队列取出消息。它和管道最大的区别是：消息队列保留消息边界，每次接收的是一条完整消息，而不是无边界字节流。

Linux 常见两套 API：

1. **System V 消息队列**：`msgget()`、`msgsnd()`、`msgrcv()`、`msgctl()`。
2. **POSIX 消息队列**：`mq_open()`、`mq_send()`、`mq_receive()`、`mq_notify()`、`mq_close()`。

## 2. System V 消息队列模型

System V 消息通常由消息类型和消息体组成：

```c
struct msgbuf {
    long mtype;
    char mtext[1024];
};
```

典型流程：

```c
int qid = msgget(key, IPC_CREAT | 0666);

struct msgbuf msg;
msg.mtype = 1;
snprintf(msg.mtext, sizeof(msg.mtext), "hello");
msgsnd(qid, &msg, strlen(msg.mtext) + 1, 0);

struct msgbuf out;
msgrcv(qid, &out, sizeof(out.mtext), 1, 0);

msgctl(qid, IPC_RMID, NULL);
```

内核侧会维护：

1. 队列 ID、权限、拥有者等元数据。
2. 消息链表或队列结构。
3. 队列总字节数、单消息大小限制、消息数量限制。
4. 等待发送者和等待接收者队列。

## 3. POSIX 消息队列模型

POSIX 消息队列有名字，通常形如 `/my_queue`，支持消息优先级：

```c
#include <fcntl.h>
#include <mqueue.h>

struct mq_attr attr;
attr.mq_flags = 0;
attr.mq_maxmsg = 1024;
attr.mq_msgsize = 256;
attr.mq_curmsgs = 0;

mqd_t mq = mq_open("/demo_mq", O_CREAT | O_RDWR, 0666, &attr);
mq_send(mq, "hello", 6, 10);

char buf[256];
unsigned prio = 0;
mq_receive(mq, buf, sizeof(buf), &prio);

mq_close(mq);
mq_unlink("/demo_mq");
```

优先级越高的消息通常越先被取出。POSIX 消息队列还可以用 `mq_notify()` 在队列从空变为非空时通知进程。

## 4. 消息队列怎么实现

从实现角度看，一个消息队列至少需要：

1. **队列元数据**：容量、消息大小、当前消息数、权限。
2. **消息存储区**：链表、环形数组或 slab 分配的小块消息。
3. **互斥保护**：内核中通常用自旋锁或 mutex 保护队列结构。
4. **等待队列**：队列为空时接收者阻塞，队列满时发送者阻塞。
5. **唤醒逻辑**：发送成功后唤醒等待接收者，接收成功后唤醒等待发送者。
6. **消息边界和选择规则**：按 FIFO、消息类型或优先级选择下一条消息。

伪代码：

```text
send(queue, msg):
    lock(queue.lock)
    while queue.full():
        sleep_on(queue.send_waiters, queue.lock)
    queue.push(msg)
    wake_one(queue.recv_waiters)
    unlock(queue.lock)

receive(queue):
    lock(queue.lock)
    while queue.empty():
        sleep_on(queue.recv_waiters, queue.lock)
    msg = queue.pop_by_rule()
    wake_one(queue.send_waiters)
    unlock(queue.lock)
    return msg
```

这里的 `sleep_on(waiters, lock)` 必须在释放锁和进入睡眠之间保证原子语义，否则会出现“检查为空后准备睡眠，但发送者刚好发消息并唤醒，接收者还没睡导致唤醒丢失”的问题。Linux 的等待队列、futex 和条件变量都在解决类似问题。

## 5. 和业务 MQ 的区别

Linux IPC 消息队列和 Kafka/RabbitMQ/RocketMQ 这类业务 MQ 不是一个层次：

1. Linux IPC 消息队列主要用于单机进程间通信。
2. Kafka/RabbitMQ 关注跨机器、持久化、消费组、重试、削峰、顺序性和高可用。
3. IPC 消息队列一般容量有限，不适合做大型业务消息堆积。

## 6. 易错点

1. 消息队列不是零拷贝，消息通常要从发送进程复制到内核，再从内核复制到接收进程。
2. System V 消息队列对象可能在进程退出后仍然存在，需要显式 `IPC_RMID` 删除。
3. 队列满时发送会阻塞，非阻塞模式会返回错误。
4. 消息队列适合小消息；大块数据更适合共享内存，消息队列只传元数据或 offset。
5. POSIX 消息队列的最大消息数、最大消息大小受系统参数限制。

## 7. 真实场景

如果要实现一个本机日志聚合器，可以让业务进程通过 Unix Domain Socket 或 POSIX 消息队列发送日志元数据；如果日志内容很大，可以把日志写入共享内存环形缓冲区，只在消息队列里传递 `{offset, length, level}`。这样既保留消息边界，又避免大日志反复复制。
