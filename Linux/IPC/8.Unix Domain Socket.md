# 8. Unix Domain Socket

## 1. 本地套接字是什么

Unix Domain Socket（UDS，本地套接字）是同一台机器上进程间通信的一种 socket。它使用 `AF_UNIX` / `AF_LOCAL` 地址族，不经过完整 TCP/IP 协议栈。

UDS 支持两种常用类型：

1. `SOCK_STREAM`：面向连接的字节流，语义类似 TCP。
2. `SOCK_DGRAM`：无连接数据报，保留消息边界，语义类似 UDP。

UDS 的地址可以是文件系统路径，也可以是 Linux 抽象命名空间地址。

## 2. 服务端 API 调用过程

流式 UDS 服务端典型流程：

```c
int fd = socket(AF_UNIX, SOCK_STREAM, 0);

struct sockaddr_un addr;
memset(&addr, 0, sizeof(addr));
addr.sun_family = AF_UNIX;
strncpy(addr.sun_path, "/tmp/demo.sock", sizeof(addr.sun_path) - 1);

unlink("/tmp/demo.sock");
bind(fd, (struct sockaddr*)&addr, sizeof(addr));
listen(fd, SOMAXCONN);

int conn = accept(fd, NULL, NULL);
char buf[1024];
ssize_t n = read(conn, buf, sizeof(buf));
write(conn, buf, n);

close(conn);
close(fd);
unlink("/tmp/demo.sock");
```

关键点：

1. `socket()` 创建本地套接字 fd。
2. `bind()` 绑定本地路径，路径会在文件系统中出现一个 socket 类型文件。
3. `listen()` 进入监听状态。
4. `accept()` 接受客户端连接，返回连接 fd。
5. `read/write` 或 `send/recv` 传输数据。
6. 退出时关闭 fd，并删除 socket 路径。

## 3. 客户端 API 调用过程

```c
int fd = socket(AF_UNIX, SOCK_STREAM, 0);

struct sockaddr_un addr;
memset(&addr, 0, sizeof(addr));
addr.sun_family = AF_UNIX;
strncpy(addr.sun_path, "/tmp/demo.sock", sizeof(addr.sun_path) - 1);

connect(fd, (struct sockaddr*)&addr, sizeof(addr));

write(fd, "hello", 5);
char buf[1024];
read(fd, buf, sizeof(buf));

close(fd);
```

客户端和 TCP 客户端类似，只是地址族和地址结构不同。

## 4. 数据报 UDS

数据报模式不需要 `listen/accept`，常用 `sendto/recvfrom`：

```c
int fd = socket(AF_UNIX, SOCK_DGRAM, 0);
bind(fd, (struct sockaddr*)&local_addr, sizeof(local_addr));
sendto(fd, data, len, 0, (struct sockaddr*)&peer_addr, sizeof(peer_addr));
recvfrom(fd, buf, sizeof(buf), 0, NULL, NULL);
```

数据报 UDS 保留单条消息边界，适合通知、日志、小控制消息。

## 5. UDS 的优势

1. 比 TCP loopback 少了 IP 层路由、分片、校验等协议栈成本。
2. API 和网络 socket 接近，容易迁移已有网络编程模型。
3. 支持通过 `sendmsg/recvmsg` 传递文件描述符。
4. 可以配合 `epoll` 做高并发本机服务。
5. 文件系统路径可以配合权限控制访问。

传递 fd 的典型场景是 master 进程打开文件、socket 或设备 fd，再把 fd 传给 worker 进程处理。

## 6. 本地 socket 是否经过 TCP/IP 协议栈

面试里问“Socket 本地通信是否需要通过 TCP/IP 协议栈”时，要先区分两类本地通信：

1. `AF_UNIX` / `AF_LOCAL`：Unix Domain Socket，不经过完整 TCP/IP 协议栈，不做 IP 路由、IP 分片、TCP 拥塞控制、TCP 重传等网络层和传输层逻辑。数据仍然经过内核 socket 层和内核缓冲区，但路径是本机 IPC。
2. `AF_INET` + `127.0.0.1` / `localhost`：TCP loopback，使用 TCP/IP 协议栈，只是数据走 loopback 虚拟网卡，不经过物理网卡。它仍有 TCP 建连、序号、确认、拥塞控制、端口管理等语义。

因此，“socket” 只是统一 API，不等于一定走 TCP/IP。关键看地址族：

```c
socket(AF_UNIX, SOCK_STREAM, 0); // 本机 IPC，不走完整 TCP/IP
socket(AF_INET, SOCK_STREAM, 0); // IPv4 TCP，即使连 127.0.0.1 也走 TCP/IP
```

工程选择：

1. 同机服务间 RPC、守护进程控制、fd 传递，优先考虑 UDS。
2. 希望客户端和服务端代码未来平滑扩展到跨机器，或需要复用 TCP 代理/网关能力，可以用 loopback TCP。
3. 极致吞吐的大块数据共享，不应只靠 UDS，可以考虑共享内存 + eventfd/futex 通知。

## 7. 本机 socket 通信的代价和层次

如果面试追问“本机用 socket 做进程间通信有什么不好”，要先说明这里的 socket 可能是两种：

1. `AF_INET + 127.0.0.1`：走 TCP/IP loopback。
2. `AF_UNIX`：走 Unix Domain Socket。

本机 TCP loopback 的问题主要是协议栈路径偏重：

1. 需要 TCP 建连、端口管理、序号、ACK、拥塞控制、重传等传输层语义。
2. 数据要经过用户态和内核态拷贝、socket 缓冲区、协议栈处理和 loopback 虚拟设备。
3. 对大块数据共享不友好，吞吐和延迟通常不如共享内存加事件通知。
4. 需要处理粘包拆包、连接关闭、TIME_WAIT、backlog、fd 上限等网络编程问题。

UDS 比 loopback TCP 轻，但也不是零成本：

1. 仍然有系统调用、内核缓冲区、用户态/内核态切换和数据拷贝。
2. 流式 UDS 仍然没有消息边界，需要应用层包头。
3. 文件系统路径模式要处理权限、路径长度、旧 socket 文件清理。
4. 只适合同机通信，未来如果要跨机器，需要切换协议或加一层抽象。

如果问“本机 socket 会经过七层模型哪些层”，可以这样回答：

1. **应用层**：进程自己的协议、序列化、请求响应语义。
2. **传输层**：如果是 `AF_INET` TCP loopback，会经过 TCP；如果是 UDS，不经过 TCP。
3. **网络层**：如果是 `127.0.0.1`，会经过 IP 路由和 loopback；如果是 UDS，不经过 IP。
4. **数据链路层/物理层**：loopback 只有内核虚拟回环设备路径，不经过真实网卡和物理链路；UDS 更是本机 IPC 路径。

工程上，同机小消息 RPC、控制命令、fd 传递可以用 UDS；跨机器或需要统一网络治理时用 TCP；大块共享数据或极低延迟场景可以用共享内存承载数据，再用 `eventfd`、futex、信号量或 UDS 发送通知。

## 8. 易错点

1. UDS 流式模式也是字节流，没有消息边界，需要长度字段或分隔符。
2. 绑定文件路径前通常要先 `unlink` 旧 socket 文件，否则 `bind` 可能失败。
3. 路径长度受 `sockaddr_un.sun_path` 限制，Linux 通常是 108 字节左右。
4. 进程退出不会自动删除 socket 路径文件，需要清理。
5. UDS 只适合同机通信，不能跨机器。
6. `localhost` TCP 和 UDS 都是本机通信，但前者仍走 TCP/IP，后者是本机 IPC。

## 9. 面试回答模板

本地套接字用 `socket(AF_UNIX, type, 0)` 创建。服务端一般是 `socket -> unlink旧路径 -> bind -> listen -> accept -> read/write -> close -> unlink`；客户端是 `socket -> connect -> read/write -> close`。它比 TCP loopback 更轻，因为不走完整网络协议栈，还支持 `sendmsg/recvmsg` 传递文件描述符。注意 `AF_INET` 连接 `127.0.0.1` 仍然走 TCP/IP，只是不经过物理网卡；`AF_UNIX` 才是本机 IPC 路径。流式 UDS 没有消息边界，工程上要自己设计包头或长度字段。
