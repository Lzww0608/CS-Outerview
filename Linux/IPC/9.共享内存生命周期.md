# 9. 共享内存生命周期

共享内存是把同一段物理页映射到多个进程的虚拟地址空间中，让多个进程像访问普通内存一样访问同一份数据。它通常是单机 IPC 中吞吐最高的方式，因为数据不需要在用户态和内核态之间反复拷贝。

## 1. 共享内存的核心原理

普通进程之间地址空间隔离，虚拟地址相同也不代表指向同一物理页。共享内存的关键是：内核创建一个可共享的内存对象，然后让多个进程的页表都映射到这组物理页。

简化理解：

```text
进程 A 虚拟地址 0x7000... -> 物理页 P1/P2/P3
进程 B 虚拟地址 0x5000... -> 物理页 P1/P2/P3
```

两个进程看到的虚拟地址可以不同，但背后的物理页相同。所以共享内存里不要保存普通指针，应该保存相对共享段起始地址的偏移量。

## 2. 创建和映射流程

Linux 常见两套接口：

1. **POSIX 共享内存**：`shm_open` + `ftruncate` + `mmap`。
2. **System V 共享内存**：`shmget` + `shmat` + `shmdt` + `shmctl`。

POSIX 共享内存示例流程：

```cpp
#include <fcntl.h>
#include <sys/mman.h>
#include <unistd.h>

int fd = shm_open("/demo_shm", O_CREAT | O_RDWR, 0666);
ftruncate(fd, 4096);

void* p = mmap(nullptr, 4096,
               PROT_READ | PROT_WRITE,
               MAP_SHARED,
               fd,
               0);

close(fd); // 映射建立后 fd 可以关闭，映射仍然存在
```

生命周期可以拆成五步：

1. **创建对象**：创建共享内存对象或打开已有对象。
2. **设置大小**：POSIX 共享内存通常用 `ftruncate` 设置长度。
3. **映射到地址空间**：用 `mmap(MAP_SHARED)` 或 `shmat` 得到本进程可访问地址。
4. **读写和同步**：按约定写入结构化数据，配合锁、信号量、eventfd 或原子变量同步。
5. **解除映射和销毁对象**：用 `munmap/shmdt` 解除映射，用 `shm_unlink/shmctl(IPC_RMID)` 删除共享对象。

## 3. 使用和同步

共享内存只解决“数据放在哪里”，不解决“并发访问是否安全”。多个进程同时读写同一块内存时，仍然要处理互斥、可见性和顺序。

常见同步方式：

1. **进程间 mutex**：`pthread_mutexattr_setpshared(PTHREAD_PROCESS_SHARED)`，mutex 对象放在共享内存中。
2. **POSIX 信号量**：命名信号量 `sem_open`，或放在共享内存中的未命名信号量。
3. **eventfd**：共享内存传数据，eventfd 负责通知，适合配合 epoll。
4. **futex**：在共享内存里的整数上等待和唤醒，适合实现低开销同步原语。
5. **原子变量 + ring buffer**：单生产者单消费者或多生产者多消费者场景可设计无锁队列。

单生产者单消费者的常见协议：

```text
共享内存:
  header: read_index, write_index, capacity
  data: fixed-size ring buffer

生产者:
  判断队列未满
  写 data[write_index]
  release-store 更新 write_index
  eventfd 通知消费者

消费者:
  acquire-load 读取 write_index
  读取 data[read_index]
  更新 read_index
```

## 3.1 哪种 IPC 最快

大块数据传输时，共享内存通常是最快的 IPC 方式，因为数据不需要在内核和用户态之间反复拷贝，多个进程可以直接访问同一段物理内存映射。

但“最快”要结合场景理解：

1. 共享内存适合高吞吐、大消息、低拷贝场景，但必须额外解决同步、生命周期和一致性问题。
2. 管道、消息队列、Unix Domain Socket 更容易使用，适合控制消息和中小消息传递。
3. Unix Domain Socket 通常比 TCP loopback 少协议栈开销，还支持文件描述符传递。
4. 很小的通知事件可以用 eventfd、futex 等机制配合共享内存完成。

生产系统里常见做法是“共享内存传数据 + eventfd/futex/信号量做通知”，既减少数据拷贝，又避免忙等。

## 4. 销毁和异常恢复

解除映射和销毁对象是两件事：

1. `munmap` 或 `shmdt` 只是让当前进程不再映射这段内存。
2. `shm_unlink` 或 `IPC_RMID` 是删除共享内存名字或标记对象删除。
3. 只要还有进程映射或持有引用，底层内存可能不会立刻释放。

进程崩溃时要考虑：

1. 崩溃进程可能写了一半数据，读者需要版本号、提交位或校验和发现不完整消息。
2. 崩溃进程可能持有进程间锁，建议使用 robust mutex、锁超时或 watchdog。
3. 共享内存对象可能残留在 `/dev/shm` 或 System V IPC 表里，需要清理脚本或启动时自检。
4. 多版本结构升级时要在共享段 header 中保存 magic、version、size 和 feature flags。

## 5. 易错点

1. 共享内存里不能直接保存 `std::string`、`std::vector`、普通指针这类进程地址相关对象，除非使用共享内存专用 allocator 和 offset pointer。
2. `volatile` 不能解决多进程同步问题，应使用原子变量、锁或明确的内存屏障语义。
3. `MAP_SHARED` 只保证映射共享，不保证写入操作的事务性。
4. `mmap` 返回地址每个进程可能不同，不能把地址值作为跨进程协议字段。
5. 缓存行伪共享会让高频计数器性能很差，header 字段要考虑 cache line 对齐。

## 6. 真实场景

1. **高频行情/日志采集**：生产者把消息写入共享内存 ring buffer，消费者批量读取并落盘。
2. **多进程服务状态表**：Nginx、数据库或网关进程共享限流、连接、缓存状态。
3. **大模型或大文件只读共享**：多个 worker 映射同一份只读文件，减少重复内存占用。
4. **本机高性能 RPC**：共享内存传大块数据，eventfd 或 Unix Domain Socket 传控制事件。

## 7. 面试回答模板

共享内存的原理是多个进程把同一个内核共享内存对象映射到各自虚拟地址空间，虚拟地址可以不同，但页表最终指向同一批物理页。POSIX 共享内存通常是 `shm_open` 创建、`ftruncate` 设置大小、`mmap(MAP_SHARED)` 映射、读写时配合同步原语，最后 `munmap` 和 `shm_unlink` 清理。它吞吐高是因为避免数据拷贝，但同步、一致性、生命周期和异常恢复都要自己处理，尤其不能在共享段里保存普通指针。
