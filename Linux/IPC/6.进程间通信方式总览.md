# 6. 进程间通信方式总览

## 1. 为什么需要 IPC

进程之间默认拥有独立虚拟地址空间，一个进程不能直接访问另一个进程的普通内存。进程间通信（IPC）就是让多个进程交换数据、传递事件或完成同步的机制。

面试回答可以按两个维度分类：

1. **数据怎么传**：字节流、消息、共享内存、套接字。
2. **怎么同步**：阻塞等待、信号、信号量、互斥锁、eventfd、futex。

## 2. 常见 IPC 方式

| 方式 | 典型 API | 特点 | 适用场景 |
| --- | --- | --- | --- |
| 匿名管道 | `pipe()` | 内核 FIFO 字节流，通常用于父子进程 | shell 管道、父子进程单向通信 |
| 命名管道 FIFO | `mkfifo()` | 有文件路径，无亲缘关系进程也能打开 | 简单本机服务通知 |
| 消息队列 | `msgget/msgsnd/msgrcv`、`mq_open/mq_send/mq_receive` | 保留消息边界，可按类型或优先级取消息 | 小消息、控制命令、异步任务 |
| 共享内存 | `shmget/shmat`、`shm_open/mmap` | 数据不经内核复制，吞吐最高 | 大数据块、高频低延迟通信 |
| 信号量 | `semget/semop`、`sem_init/sem_wait` | 用于进程/线程同步，不适合传输大数据 | 共享资源计数、共享内存同步 |
| 信号 | `kill/sigaction` | 异步通知，携带信息少 | 退出、重载配置、异常通知 |
| Unix Domain Socket | `socket(AF_UNIX)` | 本机 socket，支持流/数据报/传 fd | 本机 RPC、守护进程通信 |
| eventfd | `eventfd()` | 64 位计数器 fd，适合事件通知 | epoll 唤醒、跨线程/进程通知 |
| 文件锁 | `flock/fcntl` | 通过文件协调进程 | 简单互斥、单实例启动 |

## 3. 如何选择

1. **只做简单父子进程数据流**：匿名管道。
2. **无亲缘关系进程简单传字节流**：FIFO 或 Unix Domain Socket。
3. **需要保留消息边界和优先级**：POSIX/System V 消息队列。
4. **大数据、高吞吐、低延迟**：共享内存 + eventfd/futex/信号量通知。
5. **需要本机 RPC、传递 fd、双向通信**：Unix Domain Socket。
6. **只需要通知，不需要传大量数据**：eventfd 或 signal。

## 4. 性能理解

性能瓶颈主要来自三类成本：

1. **数据拷贝**：管道、消息队列、UDS 通常需要用户态和内核态之间拷贝；共享内存避免数据拷贝。
2. **系统调用**：每次 `read/write/send/recv` 都要进入内核，可以通过批量、非阻塞 I/O、`epoll`、`io_uring` 降低成本。
3. **调度切换**：阻塞等待会触发线程/进程调度，低竞争时优先使用用户态原子操作，竞争时再进入内核等待队列。

## 5. 易错点

1. 共享内存只是传数据快，同步仍要自己设计，否则会出现数据竞争。
2. 管道和 TCP 一样是字节流，没有消息边界。
3. 消息队列有消息边界，但内核队列容量有限，写满后会阻塞或返回 `EAGAIN`。
4. Unix Domain Socket 通信不走完整 IP 协议栈，但仍然是内核参与的 IPC，不等同于共享内存零拷贝。
5. signal 适合通知，不适合承载复杂业务数据。

## 6. 面试回答模板

进程间通信方式包括管道、FIFO、消息队列、共享内存、信号量、信号、Unix Domain Socket、eventfd 和文件锁。管道/FIFO 适合简单字节流，消息队列适合保留消息边界的异步小消息，共享内存吞吐最高但需要额外同步，Unix Domain Socket 适合本机 RPC 和 fd 传递，eventfd 常用于事件通知。选择时主要看是否需要消息边界、是否传大数据、是否双向通信、是否要求低延迟和是否需要跨无亲缘关系进程。
