# 9. 内存性能测试与评价

内存性能不能只看“占用了多少内存”，还要看访问延迟、吞吐、分配释放成本、缓存命中、缺页和 NUMA 访问等指标。面试回答时要先说明测试目标，再选择工具和评价口径。

## 核心指标

| 指标 | 含义 | 常见影响 |
| --- | --- | --- |
| RSS | 进程实际驻留在物理内存中的页 | 内存占用、是否接近 OOM |
| VSZ/VIRT | 进程虚拟地址空间大小 | mmap、预留地址空间，不等于真实物理占用 |
| minor page fault | 页表已可建立但不需要磁盘 I/O 的缺页 | 首次访问匿名页、页缓存映射 |
| major page fault | 需要磁盘 I/O 的缺页 | 性能抖动明显，通常要重点关注 |
| cache miss | CPU cache 未命中 | 数据结构局部性、随机访问 |
| memory bandwidth | 单位时间可读写内存数据量 | 大数组扫描、序列化、拷贝 |
| allocation latency | 单次分配/释放耗时 | 高频小对象、内存池、allocator |
| NUMA remote access | 跨 NUMA 节点访问内存 | 多路 CPU 服务器上的延迟和带宽下降 |

## 常用工具

### 1. 观察进程内存占用

```bash
ps -o pid,ppid,rss,vsz,stat,cmd -p <pid>
top -p <pid>
pmap -x <pid>
```

`top`/`ps` 适合看趋势，`pmap -x` 适合看虚拟内存区域分布，例如堆、栈、共享库、匿名映射。

### 2. 观察系统内存压力

```bash
free -h
vmstat 1
pidstat -r -p <pid> 1
```

重点看：

1. 是否频繁 swap。
2. `vmstat` 中 `si/so` 是否持续非零。
3. `pidstat -r` 中 RSS 是否持续上涨，判断是否可能泄漏。

### 3. 用 `perf` 看缓存和缺页

```bash
perf stat -e cache-references,cache-misses,page-faults,major-faults ./app
```

如果 `cache-misses` 很高，可能是链表、哈希冲突、随机访问、大对象跨 cache line 等问题；如果 `major-faults` 明显，说明性能瓶颈可能已经转向磁盘 I/O 或内存压力。

### 4. 测试内存带宽和延迟

常见工具：

1. `stream`：经典内存带宽测试，关注 Copy、Scale、Add、Triad。
2. `mbw`：简单测试内存拷贝带宽。
3. `sysbench memory`：压测内存读写吞吐。
4. `lmbench`：可测内存延迟、带宽、系统调用等指标。
5. `stress-ng --vm`：制造内存压力，观察服务退化情况。

示例：

```bash
sysbench memory --memory-block-size=1M --memory-total-size=10G run
stress-ng --vm 4 --vm-bytes 70% --timeout 60s
```

### 5. 分析堆内存和分配器

常见工具：

1. `valgrind --tool=massif`：分析堆峰值和增长路径。
2. `heaptrack`：分析 C/C++ 堆分配热点。
3. AddressSanitizer/LeakSanitizer：定位越界、use-after-free、泄漏。
4. jemalloc/tcmalloc profiling：线上服务常用于统计分配热点和碎片。

## 测试方法

1. 先定义场景：测占用、吞吐、延迟、泄漏，还是 allocator 性能。
2. 固定输入规模和硬件环境，避免 CPU 频率、NUMA、后台任务干扰结果。
3. 做预热，避免首次缺页、动态链接、缓存冷启动影响主要数据。
4. 多次运行，看平均值、p95/p99 和波动，而不是只看单次结果。
5. 数据规模要覆盖 cache 内和 cache 外两类情况；只测小数组容易把 CPU cache 当成内存性能。
6. 对比优化前后时只改变一个变量，例如只换容器、只换 allocator、只加内存池。

## 真实场景

1. `vector` 顺序扫描通常比 `list` 更快，因为连续内存具有更好的缓存局部性。
2. 高频小对象分配可以用对象池、slab、jemalloc/tcmalloc 降低锁竞争和碎片。
3. 日志、网络包、序列化场景要关注内存拷贝次数，必要时使用零拷贝、缓冲区复用、批处理。
4. 多 NUMA 节点机器上要关注线程绑核和内存本地性，否则远端内存访问会拉高延迟。

## 面试回答模板

测试内存性能要先明确目标。如果看占用，用 `top/ps/pmap/pidstat`；如果看系统压力，用 `free/vmstat`；如果看缓存和缺页，用 `perf stat`；如果看带宽和延迟，用 `stream/sysbench/lmbench`；如果看堆分配和泄漏，用 `heaptrack`、`massif`、ASan/LSan 或 allocator profiling。评价时不能只看 RSS，还要结合 page fault、cache miss、分配延迟、带宽、p99 波动和 NUMA 访问，最后用固定输入和重复实验对比优化前后。
