# 11. VMA、Page Cache 与换页

这类问题常把虚拟内存、`vm_area_struct`、Page Cache、LRU 和 swap 串在一起问。回答时要区分：VMA 管虚拟地址区间，页表管虚拟页到物理页映射，Page Cache 管文件页缓存，换入换出是内存压力下的页回收行为。

## 1. vm_area_struct 是什么

`vm_area_struct`（VMA）描述进程虚拟地址空间中的一段连续区间，例如代码段、堆、栈、动态库映射、文件 `mmap`、匿名 `mmap`。

一个 VMA 通常包含：

1. 起始和结束虚拟地址。
2. 读、写、执行、共享/私有等权限。
3. 关联文件和文件偏移，匿名映射则没有具体文件。
4. 所属进程 `mm_struct`。
5. 用于查找和管理的树/链表节点。

Linux 新版本使用 maple tree 管理 VMA，旧版本常说红黑树和链表。面试里可以回答：VMA 是虚拟区间元数据，不等于物理页；真正访问时还要通过页表和缺页异常建立物理页映射。

## 2. 怎么查看 VMA 数量

每一行 `/proc/<pid>/maps` 通常对应一个 VMA。可以这样看：

```bash
cat /proc/<pid>/maps
wc -l /proc/<pid>/maps
pmap -x <pid>
cat /proc/sys/vm/max_map_count
```

`vm.max_map_count` 限制单进程最多拥有的 VMA 数量。大量小文件 `mmap`、频繁创建线程栈、碎片化匿名映射，都可能让 VMA 数量过高。

## 3. Page Cache 怎么管理

Page Cache 是内核用来缓存文件数据页的机制。读文件时，数据通常先进入 Page Cache，再拷贝给用户态；写文件时，数据先写入 Page Cache 并标记为脏页，之后由内核异步回写到磁盘。

关键点：

1. 文件页按 inode 和文件偏移组织，内核能通过 address_space/xarray 找到对应缓存页。
2. 多个进程读同一个文件，可以共享同一份 Page Cache。
3. `mmap` 文件映射访问的也是 Page Cache 中的文件页。
4. 脏页由 writeback 线程按策略刷盘，`fsync` 可以要求更强的落盘语义。
5. 内存不足时，干净文件页可以直接丢弃，需要时从磁盘重读；脏页必须先回写。

## 4. 什么时候发生换入换出

换入通常发生在缺页异常：

1. 访问的匿名页被换出到 swap，需要从 swap 读回。
2. 访问的文件页不在 Page Cache，需要从文件读入。
3. COW 写入共享页，需要分配新物理页并复制。

换出通常发生在内存压力下：

1. 空闲页低于水位线，`kswapd` 后台回收。
2. 分配路径发现内存不足，触发 direct reclaim。
3. cgroup 内存达到限制，回收该 cgroup 的页。

回收优先级大致是：先回收容易丢弃的干净文件页，再考虑脏页回写和匿名页 swap。真实策略还会考虑 active/inactive LRU、页冷热、脏页比例、NUMA、cgroup 和 swappiness。

## 5. LRU 和 Page Cache 的关系

Linux 不维护精确 LRU，而是用 active/inactive 等队列近似冷热：

1. 新进入的文件页可能先放到 inactive。
2. 再次被访问后可能晋升到 active。
3. 回收时优先扫描 inactive。
4. 顺序读大文件时，内核会尽量避免把真正热页全部冲掉。

所以 Page Cache 不是“有空内存才缓存一下”，而是 Linux 内存管理的重要组成部分。`free` 里看到 buff/cache 很大通常是正常的，内核可以在需要时回收。

## 6. 面试回答模板

`vm_area_struct` 描述的是进程虚拟地址空间的一段连续映射，比如堆、栈、动态库、文件 mmap。可以通过 `/proc/<pid>/maps` 查看，行数通常就是 VMA 数量，也可以看 `vm.max_map_count` 限制。Page Cache 是文件页缓存，read/write 和文件 mmap 都会使用它；干净文件页在内存压力下可以直接丢弃，脏页要先回写。换入通常由缺页异常触发，可能从文件或 swap 读入；换出发生在内存压力下，由 kswapd 或 direct reclaim 扫描 active/inactive LRU，回收文件页或把匿名页写入 swap。
