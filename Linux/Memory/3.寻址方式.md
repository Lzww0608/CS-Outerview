

- **页式 (Paging)**：纯“技术”划分。像把一本厚书**强行按每 4KB (4096 字节) 裁开**。
- **段式 (Segmentation)**：纯“逻辑”划分。像把一本书按“第一章”、“第二章”、“附录”来划分，**每章（段）长度不同**。
- **段页式 (Segmented-Paging)**：二者结合。先按“章”分（段），再把**每一章按每 4KB 裁开**（页）。

------



### 1. 页式寻址 (Paging)

页式管理把逻辑空间和物理空间都划分为**大小固定**的块。

- 逻辑空间中的块叫 **页 (Page)**。
- 物理空间中的块叫 **页框 (Frame)** 或物理页。

**关键数据结构：页表 (Page Table)**

- 页表的作用是：记录 **逻辑页号** $p$ 对应 **物理页框号** $f$。



#### 寻址过程：

1. **CPU 给出逻辑地址**，这个地址被分为两部分：

   > **逻辑地址 = (页号 p, 页内偏移 d)**

2. **查询页表**：

   - 系统使用 **页号 p** 作为索引，去**页表 (Page Table)** 中查找。
   - 从页表中找到 p 对应的 **页框号 f**。（*可以想象成 f = PageTable[p]*）

3. **组合成物理地址**：

   - 得到 f 后，系统将其与**页内偏移 d** “拼接”起来。
   - **物理地址 = (页框号 f, 页内偏移 d)**

- **优点**：简单高效，没有外部碎片。
- **缺点**：有内部碎片（一个 5KB 的程序要占两个 4KB 的页框）。

------



### 2. 段式寻址 (Segmentation)

段式管理是按照程序的**逻辑结构**来划分的，比如代码段、数据段、堆栈段。

- 每个**段 (Segment)** 的**长度是可变**的。

**关键数据结构：段表 (Segment Table)**

- 段表不仅要记录段的**起始地址（基址）**，还要记录段的**长度（段长）**，用于地址越界保护。
- 表项内容：**(段基址 Base, 段长 Limit)**



#### 寻址过程：

1. **CPU 给出逻辑地址**，这个地址被分为两部分：

   > **逻辑地址 = (段号 s, 段内偏移 d)**

2. **查询段表**：

   - 系统使用 **段号 s 作为索引，去段表 (Segment Table)** 中查找。
   - 从段表中找到 s 对应的 **(段基址 Base, 段长 Limit)**。（*entry = SegmentTable[s]*）

3. **地址检查（保护）**：

   - **非常关键的一步**：比较**段内偏移 d** 和 **段长 Limit**。
   - 如果 `d > limit`，说明地址越界，触发“段错误 (Segment Fault)”异常。

4. **计算物理地址**：

   - 如果检查通过（`d < Limit`），则计算物理地址。
   - **物理地址 = 段基址 Base + 段内偏移 d**

- **优点**：逻辑清晰，易于共享（如共享代码段）和保护。
- **缺点**：会产生外部碎片（内存中留下很多小块空闲区）。

------



### 3. 段页式寻址 (Segmented-Paging)

段页式是前两者的结合，试图取长补短：**先分段，再在每个段内部进行分页**。

**关键数据结构：段表 + 页表**

- **段表 (Segment Table)**：现在它不存物理基址，而是存这个段对应的**页表的基址**。
- **页表 (Page Table)**：**每个段都有一个自己的页表**。



#### 寻址过程（最复杂）：

1. **CPU 给出逻辑地址**，这个地址被分为三部分：

   > **逻辑地址 = (段号 s, 页号 p, 页内偏移 d)**

2. **第一次查询：查段表**：

   - 系统使用 **段号 s** 去查**段表**。
   - 找到 s 对应的条目，获得该**段的页表 (Page Table) 的物理基址**。

3. **第二次查询：查页表**：

   - 使用上一步得到的**页表基址**，再加上 **页号 p** 作为索引，找到这个**段专属的页表**。
   - 从这个页表中，找到 p 对应的 **页框号 f**。

4. **组合成物理地址**：

   - 得到 f 后，将其与**页内偏移 d 组合。
   - **物理地址 = (页框号 f, 页内偏移 d)**

- **优点**：结合了段式的逻辑性和页式的空间高效性。
- **缺点**：寻址**非常慢**，需要两次查表（访问内存）。

------



### 总结对比

| **特性**     | **页式 (Paging)**       | **段式 (Segmentation)**    | **段页式 (Segmented-Paging)**   |
| ------------ | ----------------------- | -------------------------- | ------------------------------- |
| **划分单位** | **页 (Page)**，大小固定 | **段 (Segment)**，大小可变 | 先分段，段内再分页              |
| **逻辑地址** | (页号 p, 偏移 d)        | (段号 s, 偏移 d)           | (段号 s, 页号 p, 偏移 d)        |
| **查询表**   | 1 个页表                | 1 个段表                   | 1 个段表 + 多个页表             |
| **寻址公式** | 物理地址 = f + d        | 物理地址 = Base + d        | 物理地址 = f + d (需要两级查找) |
| **碎片**     | **内部**碎片            | **外部**碎片               | 内部碎片 (在页内)               |
| **寻址次数** | 1 次查表                | 1 次查表 (+ 1 次计算)      | **2 次查表**                    |
