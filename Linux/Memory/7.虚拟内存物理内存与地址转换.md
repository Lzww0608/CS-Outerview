# 7. 虚拟内存、物理内存与地址转换

## 1. 物理内存和虚拟内存

**物理内存**是真实 RAM，由物理页框组成。

**虚拟内存**是操作系统给每个进程提供的独立地址空间。进程看到的是连续、私有的虚拟地址，真实物理页可以分散、不连续，甚至暂时还没有分配。

虚拟内存的核心价值：

1. **隔离**：每个进程有独立地址空间，互不直接破坏。
2. **保护**：页表项有读、写、执行、用户/内核等权限位。
3. **按需分配**：申请虚拟地址不等于立刻占用物理内存。
4. **共享**：动态库代码页、共享内存、文件 mmap 可以映射到多个进程。
5. **扩展**：通过换页和文件映射，让程序的地址空间不受物理内存线性限制。

## 2. 物理地址和虚拟地址

1. **虚拟地址**：程序指针看到的地址，例如 `0x7ffe...`。
2. **物理地址**：内存总线访问 RAM 的真实地址。
3. **地址转换**：CPU 访问虚拟地址时，MMU 查询 TLB/页表，把虚拟页号转换成物理页框号，再加页内偏移得到物理地址。

```text
虚拟地址 = 虚拟页号 + 页内偏移
物理地址 = 物理页框号 + 页内偏移
```

## 2.1 TLB 为什么快

TLB 可以理解为“页表项的硬件缓存”。页表本身在内存里，多级页表一次地址翻译可能要访问多级页表节点；TLB 在 CPU 内部，通常是小容量、全相联或组相联的高速结构，命中时可以直接得到虚拟页到物理页框的映射。

访问流程：

```text
虚拟地址
  -> 用虚拟页号查 TLB
  -> 命中：直接得到物理页框号
  -> 未命中：硬件 page table walk 查询多级页表，再回填 TLB
```

TLB 快的原因：

1. **位置近**：TLB 位于 CPU/MMU 附近，比访问内存中的页表快得多。
2. **缓存粒度合适**：缓存的是页级映射，一个 TLB 项通常覆盖 4KB 或更大的页面。
3. **局部性强**：程序短时间内会反复访问相邻代码、栈、堆对象，同一批页的映射会被重复命中。
4. **避免多次访存**：多级页表未命中时可能需要多次内存访问，TLB 命中可以绕过这个过程。

易错点：TLB 缓存的是地址翻译结果，不是普通数据；进程切换、页表修改、权限变化可能导致 TLB 失效或刷新。现代 CPU 会用 ASID/PCID 等机制减少跨进程切换造成的 TLB 全量失效。

## 2.2 进程虚拟地址空间分布

从低地址到高地址看，普通进程的用户态地址空间通常包含：

1. 代码段、只读数据段、`.data`、`.bss`。
2. heap，通常随 `brk` 向高地址增长。
3. mmap 区，用于动态库、文件映射、匿名大块内存和共享内存。
4. stack，通常向低地址增长。
5. 更高地址处是内核地址空间，用户态不能直接访问。

这只是逻辑模型，真实布局会受 ASLR、PIE、线程栈、架构位数和内核配置影响。共享库映射区的代码页可以被多个进程共享，可写数据页则通常通过私有映射和写时复制隔离。

## 2.3 每个进程虚拟内存有多大

进程虚拟地址空间的上限主要由 CPU 架构、操作系统位数、内核配置和进程资源限制共同决定，不等于机器物理内存大小。

常见理解：

1. **32 位进程**：理论虚拟地址空间是 4GB。传统 32 位 Linux 常见用户态 3GB、内核态 1GB；也可能配置成 2G/2G 等布局。
2. **64 位进程**：理论地址空间极大，但硬件和内核通常只实现部分虚拟地址位。x86-64 常见用户态可用范围远大于实际物理内存，具体还受 canonical address、内核版本和 `ulimit` 限制。
3. **单次分配限制**：还会受 `ulimit -v`、cgroup memory、overcommit 策略、地址空间碎片、映射数量上限等影响。
4. **VIRT 不等于 RSS**：进程可以拥有很大的虚拟映射，但只有实际访问并驻留的页面才算物理内存占用。

面试里可以回答：32 位进程通常最多看到 4GB 虚拟地址空间，但用户态可用常少于 4GB；64 位进程的虚拟地址空间远大于物理内存，真正能用多少还要看资源限制和工作集是否能被物理内存、swap、文件映射支撑。

## 3. VIRT、RES、SHR

`top` 里的常见指标：

1. **VIRT**：进程拥有的虚拟地址空间大小，包括尚未实际分配物理页的部分。
2. **RES/RSS**：当前常驻物理内存大小，即真正在 RAM 里的部分。
3. **SHR**：RES 中可与其他进程共享的部分，例如共享库代码页、共享内存映射。

因此 VIRT 大不一定代表占用物理内存多，排查内存压力更常看 RSS/RES、PSS 和 cgroup 内存。

## 4. 2GB 内存运行 4GB 程序

如果程序“大小 4GB”指虚拟地址空间或文件映射总量，那么 2GB 物理内存也可能运行：

1. 程序按需分页，只有被访问的页面才需要进入物理内存。
2. 可执行文件、动态库、mmap 文件可以按页加载。
3. 不活跃匿名页可以被换出到 swap。
4. 多个进程共享的只读代码页不需要重复占用物理页。

如果程序工作集长期超过 2GB，系统会频繁缺页和换页，出现抖动，性能会急剧下降，甚至 OOM。

## 5. 不使用虚拟内存能不能运行

没有虚拟内存也不是完全不能运行程序，但会失去现代 OS 的关键能力：

1. 每个程序必须直接管理物理地址，装载和重定位复杂。
2. 进程隔离弱，一个程序越界可能破坏另一个程序或内核。
3. 物理内存碎片会更严重，难以给大程序分配连续空间。
4. 无法自然支持按需分页、mmap、共享库、copy-on-write。

在嵌入式或早期系统里可以没有完整虚拟内存，但通用操作系统依赖虚拟内存来实现隔离、保护、共享和按需加载。

即使物理内存大于 4GB，通用操作系统也不会因此放弃虚拟内存。原因是虚拟内存不只是“扩大容量”，还负责进程隔离、权限保护、地址空间布局、动态库共享、`mmap`、写时复制和按需加载。物理内存很大只能降低换页压力，不能替代虚拟内存的隔离和抽象能力。

## 5.1 有了虚拟内存就一定能实现内存隔离吗

虚拟内存是进程隔离的基础，但不是隔离的全部条件。真正的隔离依赖 MMU、页表权限、CPU 特权级、内核正确性和设备访问控制共同成立。

正常情况下，一个用户进程不能直接访问另一个进程的私有页，原因是：

1. 每个进程有独立页表，虚拟地址相同也可能映射到不同物理页。
2. 页表项有用户/内核、读写执行等权限位，用户态访问无权限页会触发异常。
3. 系统调用进入内核后，由内核检查参数、权限和对象所有权。

但仍然存在隔离边界被打破或被主动共享的场景：

1. **共享内存和 `mmap`**：多个进程可以有意映射同一物理页，需要同步保证一致性。
2. **内核漏洞或驱动漏洞**：用户态通过漏洞提权后，虚拟内存隔离会失效。
3. **DMA 设备访问**：没有 IOMMU 保护时，设备可能直接读写物理内存。
4. **侧信道攻击**：缓存、分支预测、TLB 等微架构状态可能泄露信息。
5. **页表权限配置错误**：例如错误地把内核页或只读页映射为用户可写。

所以面试回答可以说：虚拟内存提供隔离的地址空间和权限机制，是现代 OS 内存隔离的基础；但隔离是否可靠，还取决于硬件 MMU、内核实现、IOMMU、共享映射管理和安全漏洞防护。

## 6. 面试回答模板

物理内存是真实 RAM，虚拟内存是操作系统给每个进程抽象出来的独立地址空间。程序里的指针是虚拟地址，CPU 通过 MMU、TLB 和页表把虚拟页号翻译成物理页框号。虚拟内存的价值是隔离、权限保护、按需分配、共享和换页。32 位进程理论上是 4GB 地址空间但用户态通常少于 4GB，64 位进程地址空间远大于物理内存，实际可用还受资源限制和工作集影响。2GB 物理内存可以运行虚拟地址空间 4GB 的程序，是因为只有实际访问的页才需要驻留内存，不活跃页可以换出或来自文件映射；但如果工作集超过物理内存，会频繁缺页甚至 OOM。即使物理内存超过 4GB，通用 OS 仍然需要虚拟内存来做隔离、保护、共享库、mmap 和 COW。
