# 5. 页面置换算法

## 1. 什么是页面置换

虚拟内存系统中，进程访问的虚拟页不一定都在物理内存里。当发生缺页中断且没有足够空闲页框时，操作系统需要选择一个物理页换出，把新页面换入，这个选择策略就是页面置换算法。

目标：

1. 降低缺页率。
2. 避免频繁换入换出导致抖动。
3. 控制算法维护成本。
4. 尽量保留未来更可能被访问的页面。

## 2. 常见算法

| 算法 | 思想 | 优点 | 缺点 |
| --- | --- | --- | --- |
| OPT | 淘汰未来最久不会访问的页 | 理论最优 | 需要知道未来，无法真实实现 |
| FIFO | 淘汰最早进入内存的页 | 简单 | 可能淘汰热点页，有 Belady 异常 |
| LRU | 淘汰最久未访问的页 | 利用时间局部性 | 精确实现成本高 |
| Clock | 用访问位近似 LRU | 成本低，工程常用 | 只是近似 |
| LFU | 淘汰访问次数最少的页 | 关注频率 | 老热点可能长期占用 |
| 2Q / Active-Inactive | 新页先进入冷队列，二次访问再晋升 | 抗顺序扫描污染 | 实现比 FIFO/LRU 复杂 |

## 3. OPT

OPT 淘汰未来最长时间不会被访问的页面。它只用于理论分析，用来衡量其他算法和最优结果的差距。

```text
如果未来访问序列是 1,2,3,1,2,4
当前内存有 1,2,3，需要换入 4
未来 3 不再访问，所以淘汰 3
```

真实系统不知道未来访问序列，所以不能实现真正的 OPT。

## 4. FIFO

FIFO 按进入内存的先后顺序淘汰最老页面。

优点是实现简单，只需要队列；缺点是完全不考虑页面是否刚刚被访问，可能把热点页淘汰掉。

FIFO 还可能出现 Belady 异常：分配更多页框，缺页次数反而增加。

## 5. LRU

LRU 淘汰最长时间没有被访问的页面。它利用了时间局部性：最近访问过的页面未来更可能再次访问。

精确 LRU 需要每次访问都更新页面顺序，硬件和锁开销都很高。因此操作系统一般使用近似 LRU，而不是每次内存访问都维护一个精确链表。

## 6. Clock 算法

Clock 是 LRU 的工程近似。每个页有一个访问位，页面组织成环形队列，指针像时钟一样扫描：

1. 如果访问位为 1，清零并跳过，给第二次机会。
2. 如果访问位为 0，选择该页淘汰。

```text
hand -> [page, ref=1] 清零跳过
hand -> [page, ref=0] 淘汰
```

Clock 不需要每次访问移动节点，只依赖硬件或内核维护访问位，成本更低。

## 7. Linux 的思路

Linux 不使用纯 FIFO 或精确 LRU，而是维护 active/inactive 等 LRU 近似队列：

1. 新页面通常先进入 inactive。
2. 被再次访问后可能晋升到 active。
3. 回收时优先扫描 inactive。
4. 文件页和匿名页会有不同回收策略。

这样可以避免一次大文件顺序扫描把真正热点页全部冲掉。

## 8. 易错点

1. 页面置换不是缓存淘汰的孤立问题，还涉及脏页回写、匿名页 swap、文件页丢弃、NUMA 等。
2. LRU 理论好，但精确实现成本高，OS 常用近似算法。
3. FIFO 简单但可能出现 Belady 异常。
4. 脏页换出前可能要写回磁盘，成本比干净页更高。
5. 物理内存不足时频繁缺页会造成抖动，CPU 大量时间耗在换页上。

## 9. 面试回答模板

页面置换是在缺页且没有空闲物理页时，选择一个页面换出去。理论最优是 OPT，但需要知道未来；FIFO 简单但可能淘汰热点页并有 Belady 异常；LRU 利用时间局部性，但精确维护成本高；Clock 用访问位给页面第二次机会，是 LRU 的低成本近似。Linux 这类系统通常使用 active/inactive 队列等近似 LRU 策略，并考虑脏页、文件页、匿名页和扫描污染问题。
