# mmap 原理与应用场景

`mmap` 是把文件、设备或匿名内存映射到进程虚拟地址空间的系统调用。映射完成后，应用可以像访问普通内存一样访问这段地址，内核负责在缺页时把对应页加载进内存，或把脏页回写到文件。

## 1. 基本概念

常见形式：

```c
void* p = mmap(nullptr, length,
               PROT_READ | PROT_WRITE,
               MAP_SHARED,
               fd,
               offset);
```

关键参数：

1. `addr`：期望映射地址，通常传 `nullptr` 让内核选择。
2. `length`：映射长度，按页粒度管理。
3. `prot`：读、写、执行权限，例如 `PROT_READ/PROT_WRITE`。
4. `flags`：共享或私有映射，例如 `MAP_SHARED/MAP_PRIVATE`。
5. `fd`：被映射的文件描述符；匿名映射可用 `MAP_ANONYMOUS`。
6. `offset`：文件偏移，通常要求按页大小对齐。

释放映射使用：

```c
munmap(p, length);
```

## 2. 核心原理

`mmap` 建立的是虚拟内存区域 VMA，不一定马上读取文件内容或分配物理页。

简化流程：

```text
mmap
  -> 内核创建 VMA，记录文件、偏移、权限和映射方式
访问映射地址
  -> 触发缺页异常
  -> 内核从 page cache 或文件读取对应页
  -> 建立页表映射
写入 MAP_SHARED 页
  -> 标记脏页
  -> 后续由 msync、writeback 或 munmap/close 等路径回写
```

`MAP_PRIVATE` 使用写时复制。进程第一次写入时，内核复制一份私有物理页，修改不会回写原文件。

## 3. 与 read/write 的区别

| 对比项 | `read/write` | `mmap` |
| --- | --- | --- |
| 访问方式 | 显式系统调用读写用户缓冲区 | 像访问内存一样读写 |
| 数据拷贝 | 文件页缓存到用户缓冲区通常有一次拷贝 | 用户直接访问映射页，少一次显式拷贝 |
| 缺页成本 | 调用时集中发生 | 第一次访问页时发生 page fault |
| 随机访问 | 需要 `lseek/pread` | 指针偏移访问更自然 |
| 错误表现 | 系统调用返回错误码 | 可能在访问时触发 `SIGBUS/SIGSEGV` |
| 编程复杂度 | 边界清晰 | 需要处理页对齐、同步、生命周期 |

`mmap` 不是一定比 `read/write` 快。顺序小文件读取、一次性扫描、访问模式简单时，`read` 加大缓冲区可能更稳定；大文件随机访问、多进程共享、零拷贝式读多写少场景更适合 `mmap`。

## 4. 应用场景

1. **大文件随机访问**：索引文件、字典文件、模型参数、只读配置。
2. **进程间共享内存**：多个进程映射同一个文件或 `shm_open` 对象，配合锁、信号量、eventfd、futex 做同步。
3. **数据库和存储引擎**：部分系统用 mmap 访问数据页，但也要处理 page fault、回写和内存压力。
4. **加载动态库和可执行文件**：内核通过文件映射按页加载代码段和只读数据段。
5. **用户态内存分配器**：大块分配常通过匿名 `mmap` 获取虚拟地址空间。

## 5. 几个 G 文件能不能一次 new 到内存

不建议为了读取几个 G 的文件直接 `new char[file_size]` 一次性装入内存。能不能成功取决于进程虚拟地址空间、连续可用地址范围、物理内存、swap、cgroup/容器限制、`ulimit` 和系统 overcommit 策略；即使申请成功，首次触碰页面时也可能触发大量缺页、换页或 OOM。

更稳妥的设计：

1. **顺序处理**：用固定大小缓冲区循环 `read/pread`，例如每次 4 MB 或 16 MB，适合日志扫描、校验、上传下载。
2. **随机访问**：使用 `mmap` 映射文件，让内核按页加载；大文件可以分窗口映射，避免长期占用过大的虚拟区间。
3. **结构化处理**：如果只需要少量索引或差异行，不要加载全量内容，先构建偏移索引、hash 分块或按行流式比较。
4. **避免尾延迟抖动**：延迟敏感服务要关注 major page fault、page cache 污染和内存回收，必要时用后台任务、限速或独立进程处理大文件。
5. **容错**：`mmap` 文件被截断后访问可能 `SIGBUS`，流式读取则要处理短读、EINTR、EAGAIN 和磁盘错误。

面试里可以回答：大文件不是“能不能申请到一块大内存”这么简单，关键是访问模式。如果顺序扫描，用分块读取更可控；如果随机访问或多进程共享，`mmap` 更自然；如果只是找差异或做索引，应尽量只读必要的块。

## 6. 注意事项

1. `offset` 和映射范围要按页对齐，文件长度不足时访问可能触发 `SIGBUS`。
2. `MAP_SHARED` 只保证共享映射可见，不能替代互斥、内存序和一致性协议。
3. `msync` 可以主动刷脏页，但不等于业务事务提交，需要自己设计 WAL、校验和、版本号等机制。
4. `mmap` 访问的成本可能隐藏在缺页异常里，P99 延迟敏感服务要关注 major fault。
5. 映射文件被截断、fd 生命周期、进程崩溃持锁、跨进程指针地址不同，都是共享内存常见坑。

## 7. 面试回答模板

`mmap` 把文件或匿名内存映射到进程虚拟地址空间，调用时主要创建 VMA，实际物理页通常在首次访问时通过缺页异常建立映射。文件映射会经过 page cache，`MAP_SHARED` 写入会形成脏页并回写文件，`MAP_PRIVATE` 写入走写时复制。相比 `read/write`，`mmap` 适合大文件随机访问、多进程共享和减少显式拷贝，但它会引入 page fault、页对齐、`SIGBUS`、刷盘一致性和同步复杂度，不是所有场景都更快。
