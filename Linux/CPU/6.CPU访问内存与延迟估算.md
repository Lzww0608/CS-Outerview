# CPU访问内存与延迟估算

CPU 访问内存不是“CPU 直接读 DRAM”这么简单。一次普通 load/store 可能经过寄存器、地址生成单元、L1/L2/L3 Cache、TLB、页表、内存控制器、NUMA 节点和内存总线。面试里问这类问题，重点通常是看你能否把硬件局部性、虚拟内存和多核拓扑串起来。

项目中已有独立的 [CPU 三级缓存与缓存一致性](./5.CPU三级缓存与缓存一致性.md) 和 [NUMA](./2.NUMA.md) 文档，这里重点补充“CPU 如何访问内存、如何估算延迟、后端开发怎么联系实际”。

## 1. CPU 如何访问内存

以访问一个虚拟地址为例，可以简化成下面流程：

```text
指令发起 load/store
-> CPU 生成虚拟地址
-> 查 TLB 做虚拟地址到物理地址转换
-> TLB 命中：得到物理地址
-> TLB 未命中：硬件或内核按多级页表查找，必要时触发缺页异常
-> 查 L1/L2/L3 Cache
-> Cache 命中：直接返回缓存行数据
-> Cache 未命中：通过内存控制器访问 DRAM
-> 数据以缓存行粒度填入 Cache，再交给寄存器或执行单元
```

几个关键点：

1. 程序里看到的是虚拟地址，真正上总线访问的是物理地址。
2. TLB 缓存的是页表翻译结果，减少每次访问都查多级页表的成本。
3. Cache 缓存的是数据和指令，通常按缓存行传输，常见缓存行大小是 64B。
4. 寄存器是 CPU 内部最快的存储位置，但容量极小；Cache 和内存负责承接更大的工作集。

## 2. CPU 如何加速内存访问

内存访问比 CPU 指令执行慢得多，现代处理器主要靠层次化缓存和预测机制隐藏延迟：

1. **寄存器分配**：编译器尽量把热点变量放在寄存器，减少内存读写。
2. **多级 Cache**：L1 最快但容量小，L2/L3 逐级增大但延迟更高。
3. **TLB**：缓存虚拟页到物理页的映射，避免频繁走多级页表。
4. **局部性利用**：时间局部性让刚访问过的数据更可能再次命中 Cache；空间局部性让相邻数据随缓存行一起加载。
5. **预取**：硬件预取器或软件 prefetch 提前把顺序访问的数据拉进 Cache。
6. **乱序执行和内存级并行**：CPU 在等待内存时执行其他不依赖该结果的指令。
7. **大页 Huge Page**：扩大单个 TLB 项覆盖范围，降低 TLB miss，适合大内存工作集。
8. **减少内核态切换和拷贝**：批量系统调用、零拷贝、`mmap`、`io_uring` 可以减少切换和数据搬运成本。

工程上常见优化不是“手动控制 Cache”，而是让数据结构更顺序、更紧凑、更少跨页。例如数组遍历通常比链表遍历更容易命中 Cache；热点计数器要避免伪共享；大对象扫描要关注 TLB miss 和 NUMA 远程访问。

## 3. TLB、页表和缺页

虚拟地址到物理地址的转换依赖页表。多级页表节省空间，但一次完整 page walk 可能要访问多次内存，所以 CPU 使用 TLB 缓存最近的转换结果。

```text
虚拟地址 = 虚拟页号 + 页内偏移
TLB[虚拟页号] -> 物理页号
物理地址 = 物理页号 + 页内偏移
```

TLB miss 不等于 page fault：

1. **TLB miss**：TLB 没缓存映射，但页表里有合法映射，补入 TLB 后继续执行。
2. **Minor page fault**：页不在当前页表有效项里，但不需要磁盘 I/O，例如匿名页首次分配、COW、已有页缓存映射。
3. **Major page fault**：需要从磁盘或 swap 读入页面，延迟远高于普通内存访问。
4. **非法访问**：权限错误或地址非法，内核通常向进程发送 `SIGSEGV`。

面试里说“页表、TLB 能加速内存访问”时要严谨：页表本身不是加速器，它提供地址映射和保护；真正加速地址转换的是 TLB。多级页表甚至会让一次 miss 的成本变高。

## 4. 多核拓扑和 NUMA 意识

现代服务器通常由多个核心组成一个或多个 CPU Socket，每个 Socket 连接自己的本地内存控制器。NUMA（Non-Uniform Memory Access）表示不同 CPU 访问不同内存位置的延迟不完全一致。

面试回答可以抓住这几点：

1. CPU 访问本节点本地内存延迟最低。
2. 跨 Socket 访问远程节点内存要走互联链路，延迟更高、带宽更低。
3. 线程频繁迁移会破坏 Cache 热度，也可能导致“线程在节点 0 跑，数据在节点 1”的远程访问。
4. 高并发服务的内存分配、线程绑定、网络中断亲和性都可能受 NUMA 影响。

常见工具和策略：

1. `lscpu`、`numactl --hardware` 查看 CPU、Socket、NUMA 节点拓扑。
2. `numactl --cpunodebind --membind` 绑定计算和内存节点。
3. `taskset`、`sched_setaffinity` 控制线程 CPU 亲和性。
4. 网络服务可让网卡中断、业务线程和内存分配尽量落在同一 NUMA 节点。

更完整的 NUMA 设计和部署策略见 [NUMA](./2.NUMA.md)。

## 5. 访问 100m 外内存要多久

这个问题考的是估算能力。电信号或光在介质中的传播速度不是无限的，粗略可以用光速估算下界：

```text
单程传播时间约等于 100m / (3 * 10^8 m/s) = 333ns
如果需要请求-响应往返，传播延迟下界约 666ns
```

实际系统还要叠加链路编码、交换设备、协议栈、控制器排队、序列化和处理时间，所以不会只有传播时间。这个数量级已经远大于本机 L1/L2 Cache，也明显高于本机 DRAM 常见访问延迟。

常见数量级可以这样记：

| 操作 | 粗略量级 |
| --- | --- |
| L1 Cache | 1ns 级 |
| L2 Cache | 数 ns |
| L3 Cache | 10ns 级 |
| 本机 DRAM | 几十到一百多 ns |
| 跨 Socket 远程内存 | 通常高于本地 DRAM |
| 100m 物理距离往返传播下界 | 约 666ns |
| SSD I/O | us 到 ms 级 |
| 机械磁盘 I/O | ms 级 |

面试里不要死背精确数字，不同 CPU、内存频率、拓扑和负载差异很大。能说明“传播下界 + 系统开销 + 数量级对比”更重要。

## 6. 后端开发里的真实应用

1. **缓存友好数据结构**：高频路径优先使用连续数组、结构体压缩、批量处理，减少链式随机访问。
2. **避免伪共享**：多个线程高频更新的计数器要按缓存行对齐或分片。
3. **分片和本地聚合**：全局计数器改成 per-thread/per-cpu 分片，读时再聚合，降低原子竞争。
4. **线程池亲和性**：固定工作线程、减少任务跨核迁移，让 Cache 和 NUMA 本地性更稳定。
5. **大页和内存池**：数据库、缓存、搜索引擎常用大页或内存池降低 TLB miss 和分配器碎片。
6. **减少系统调用**：网络服务通过批量读写、连接复用、零拷贝、异步 I/O 降低用户态和内核态切换成本。

## 7. 易错点

1. 页表负责映射和权限，TLB 才是地址转换缓存。
2. Cache 命中以缓存行为单位，访问一个字节也可能拉取整条缓存行。
3. 原子操作也会触发缓存一致性流量，高竞争下可能比互斥锁更慢。
4. NUMA 不是“多个 CPU 排成一排”，而是 CPU、内存控制器和节点本地性的拓扑问题。
5. CPU 核心数没有固定答案，消费级、工作站、服务器差异很大；面试回答应说看具体 CPU 和 Socket 拓扑。
6. 减少用户态/内核态切换能提升 I/O 路径性能，但它和 CPU 访问 DRAM 的 Cache/TLB 优化不是同一层问题。

## 8. 面试回答模板

CPU 访问内存时会先执行地址生成，用 TLB 把虚拟地址翻译成物理地址，再按 L1、L2、L3、内存控制器逐级查找数据。加速手段主要是寄存器、多级 Cache、TLB、预取、乱序执行和利用局部性；操作系统层面还有大页、减少系统调用、零拷贝等优化。多核服务器还要考虑 NUMA，本地内存和远程内存延迟不同，所以高性能后端会关注线程亲和性、内存分配节点、伪共享和分片计数。访问远距离内存时，传播延迟本身就有下界，例如 100m 往返仅光速下界就约 666ns，真实系统还要叠加协议和排队开销。
