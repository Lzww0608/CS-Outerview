# LD_PRELOAD 攻击与防护

`LD_PRELOAD` 是 Linux 动态链接器提供的预加载机制。程序启动时，动态链接器会优先加载 `LD_PRELOAD` 指定的共享库，并在符号解析时让这些库里的函数优先于普通动态库生效。

这本来用于调试、性能分析和函数拦截，但如果攻击者能控制进程环境变量或预加载库路径，就可以劫持 `open`、`read`、`write`、`connect`、`execve` 等 libc 函数，达到隐藏文件、窃取参数、修改网络连接或绕过业务逻辑的目的。

## 1. 攻击原理

动态链接程序启动的大致过程是：

1. 内核加载 ELF 可执行文件。
2. 如果 ELF 依赖动态链接器，内核把控制权交给 `/lib64/ld-linux-*.so.*`。
3. 动态链接器读取依赖库、环境变量和运行时搜索路径。
4. 如果存在 `LD_PRELOAD`，先加载其中的 `.so`。
5. 解析符号时，预加载库中的同名符号优先被绑定。

典型劫持代码如下：

```cpp
#define _GNU_SOURCE
#include <dlfcn.h>
#include <fcntl.h>
#include <stdarg.h>

extern "C" int open(const char* path, int flags, ...) {
    static auto real_open = reinterpret_cast<int (*)(const char*, int, mode_t)>(
        dlsym(RTLD_NEXT, "open")
    );

    mode_t mode = 0;
    if (flags & O_CREAT) {
        va_list ap;
        va_start(ap, flags);
        mode = va_arg(ap, int);
        va_end(ap);
    }

    // 可以在这里记录、篡改或拒绝某些文件访问。
    return real_open(path, flags, mode);
}
```

运行时只要指定：

```bash
LD_PRELOAD=/tmp/hook.so ./app
```

`app` 调用 `open` 时就会先进入预加载库中的 `open`。

## 2. 哪些场景容易被利用

1. 启动脚本把用户输入直接拼到环境变量里。
2. 服务端执行外部命令时继承了不可信环境变量。
3. 定时任务、CI、运维脚本在可写目录加载共享库。
4. 插件系统允许上传或指定 `.so`，但没有做签名和路径限制。
5. 容器内进程以过高权限运行，攻击者能修改启动环境或挂载路径。

`LD_PRELOAD` 只影响动态链接程序。静态链接程序、不走 glibc 动态链接器的程序，或者进入 secure-execution 模式的 setuid/setgid 程序，行为会不同。glibc 在 secure-execution 模式下会忽略或限制很多危险环境变量。

## 3. 防护方式

### 3.1 清理启动环境

服务进程启动前应使用白名单环境变量，而不是继承完整用户环境：

```cpp
clearenv();
setenv("PATH", "/usr/sbin:/usr/bin:/sbin:/bin", 1);
setenv("LANG", "C.UTF-8", 1);
```

如果必须保留环境变量，也要显式删除：

```cpp
unsetenv("LD_PRELOAD");
unsetenv("LD_LIBRARY_PATH");
unsetenv("LD_AUDIT");
```

### 3.2 固定可执行文件和库路径

1. 用绝对路径启动关键程序。
2. 避免从 `/tmp`、当前目录、用户可写目录加载 `.so`。
3. 对插件目录设置严格权限，普通用户不可写。
4. 对生产二进制和共享库做哈希校验或签名校验。

### 3.3 限制运行权限

1. 服务进程使用最小权限账号运行。
2. 容器中关闭不必要的特权、挂载和 capabilities。
3. 使用 seccomp、AppArmor、SELinux 限制危险系统调用和文件访问。
4. 对核心服务启用只读根文件系统或不可变部署目录。

### 3.4 运行时检测

排查可疑预加载时可以看：

```bash
tr '\0' '\n' < /proc/<pid>/environ | grep LD_
cat /etc/ld.so.preload
ldd /path/to/app
```

如果怀疑函数被劫持，还可以结合 `strace`、`LD_DEBUG=libs,symbols`、文件完整性校验和进程内存映射 `/proc/<pid>/maps` 分析。

## 4. 易错点

1. 只删除 `LD_PRELOAD` 不够，`LD_LIBRARY_PATH`、`LD_AUDIT`、运行时插件路径也可能被利用。
2. `LD_PRELOAD` 防护不是业务鉴权的替代品，攻击者一旦能控制进程启动环境，说明边界已经被突破。
3. 静态链接可以减少动态符号劫持面，但会牺牲动态升级和安全补丁便利性。
4. `RTLD_DEEPBIND` 可以改变部分符号查找顺序，但不是通用安全方案。
5. setuid 程序会触发动态链接器安全限制，但普通服务进程不会自动获得这种保护。

## 5. 面试回答模板

`LD_PRELOAD` 是动态链接器的预加载机制，指定的共享库会在普通依赖库之前加载，符号解析也更靠前。攻击者如果能控制环境变量或库文件，就可以定义同名函数劫持 libc 调用，实现隐藏文件、篡改网络连接或窃取参数。防护思路是启动时清理不可信环境变量，固定二进制和库路径，避免从可写目录加载 `.so`，用最小权限、seccomp/AppArmor/SELinux 限制运行环境，并通过 `/proc/<pid>/environ`、`/etc/ld.so.preload`、`ldd` 和 `/proc/<pid>/maps` 做排查。
