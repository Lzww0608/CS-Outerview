# 6. Linux task_struct 独有与共享成员分析

## 1. 问题背景

Linux 内核中，进程和线程都使用 `task_struct` 作为调度实体。理解哪些成员是每个 task_struct 独有的，哪些是线程组共享的，是理解 Linux 进程/线程模型的关键。

假设条件：本文档基于 Linux 5.x 内核源码进行分析，线程组通过 `clone()` 系统调用配合 `CLONE_VM`、`CLONE_FILES` 等标志创建。

## 2. 问题现象

在理解 Linux 进程/线程模型时，常见困惑：

1. 进程和线程的 `task_struct` 有何区别
2. 为什么所有线程共享同一个 PID
3. 线程组 ID (TGID) 和线程 ID (PID/TID) 的关系
4. 哪些资源在线程间共享，哪些是隔离的

## 3. 影响范围

| 维度 | 说明 |
| --- | --- |
| 进程隔离性 | 独立地址空间带来资源隔离 |
| 线程协作性 | 共享地址空间便于数据共享 |
| 资源消耗 | 共享程度影响内存占用 |
| 调试复杂度 | 共享资源导致问题排查困难 |

## 4. 原因分析

### 4.1 task_struct 核心结构

内核源码：`include/linux/sched.h`

**线程组共享成员 (Thread Group Shared)**

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `tgid` | pid_t | 线程组 ID，所有线程共享 |
| `group_leader` | task_struct* | 指向主线程 |
| `mm` | mm_struct* | 地址空间，线程共享 |
| `active_mm` | mm_struct* | 活跃地址空间 |
| `files` | files_struct* | 打开文件表，线程共享 |
| `signal` | signal_struct* | 信号描述符，线程共享 |
| `sighand` | sighand_struct* | 信号处理函数，线程共享 |
| `fs` | fs_struct* | 当前目录、根目录等 |
| `nsproxy` | nsproxy* | 命名空间 |
| `cred` | cred* | UID/GID/capabilities |

**每个 task_struct 独有成员 (Per-task)**

| 成员 | 类型 | 说明 |
| --- | --- | --- |
| `pid` | pid_t | 线程 ID，每个线程唯一 |
| `stack` | void* | 内核栈 |
| `thread` | thread_struct | CPU 寄存器保存区 |
| `se` | sched_entity | CFS 调度实体 |
| `rt` | sched_rt_entity | RT 调度实体 |
| `state` | volatile long | 进程/线程状态 |
| `exit_state` | int | 退出状态 |
| `cpus_mask` | cpumask_t | 可运行的 CPU 核 |
| `stack_canary` | unsigned long | 栈保护 |
| `cpu_timers` | list_head | Per-task 定时器链表 |
| `real_parent` | task_struct* | 父进程 |
| `parent` | task_struct* | 当前父进程 |
| `pids` | pid_link[] | PID 链表 |
| `io_context` | io_context* | I/O 上下文 |

### 4.2 共享 vs 独有成员详解

#### 线程组共享成员

**1. 地址空间 - mm_struct**

```c
struct mm_struct *mm;        // 所有线程共享同一个地址空间
struct mm_struct *active_mm; // 当前活跃地址空间
```

验证方法：
```
$ cat /proc/PID/task/TID/maps
同一进程的所有线程 maps 内容相同
```

**2. 文件描述符表 - files_struct**

```c
struct files_struct *files;
```

验证方法：
```
$ ls -la /proc/PID/fd
同一进程所有线程看到相同的 fd 列表
```

**3. 信号 - signal_struct**

```c
struct signal_struct *signal;   // 共享信号描述符
struct sighand_struct *sighand; // 共享信号处理函数
```

**4. 线程组 ID**

```c
pid_t tgid;                      // 所有线程 tgid 相同
struct task_struct *group_leader; // 主线程指针
```

验证方法：
```
$ cat /proc/PID/status | grep -E "Pid|Tgid"
Pid: 1234 (TID)
Tgid: 1234 (主线程 PID)
```

#### 每个 task_struct 独有成员

**1. 线程 ID - pid**

```c
pid_t pid;                        // 每个线程唯一
```

验证方法：
```
$ ps -eLf | grep PID
PID  PPID  LWP  NLWP
1234  1    1234    4    (主线程)
1234  1    1235    4    (子线程1)
1234  1    1236    4    (子线程2)
```

**2. 内核栈 - stack**

```c
void *stack;                       // 每个线程独立的内核栈
```

x86_64 默认栈大小：8KB，可以通过 `ulimit -s` 查看/修改。

**3. 寄存器上下文 - thread_struct**

```c
struct thread_struct thread;       // CPU 寄存器保存
```

包含：RIP, RSP, RBP, RAX, RBX... 上下文切换时保存/恢复。

**4. 调度实体**

```c
struct sched_entity se;           // CFS 调度实体
struct sched_rt_entity rt;         // RT 调度实体
struct sched_dl_entity dl;         // Deadline 调度实体
```

每个线程有独立的调度实体，调度器管理的是这些实体。

**5. 进程状态**

```c
volatile long state;              // R/S/D/Z/T/I
int exit_state;                   // 退出状态
```

**6. CPU 亲和性**

```c
cpumask_t cpus_mask;              // 允许运行的 CPU 核
```

可以通过 `sched_setaffinity()` 设置。

### 4.3 内存布局图解

```
进程地址空间
+---------------------------------------------------------------+
|                        mm_struct (共享)                        |
|  代码段 | 数据段 | BSS | 堆 | mmap | 用户栈                   |
+---------------------------------------------------------------+
|                        files_struct (共享)                     |
|  fd[0] -> stdin, fd[1] -> stdout, fd[2] -> stderr, ...       |
+---------------------------------------------------------------+
|                       signal_struct (共享)                      |
|  pending signals | signal handlers                             |
+---------------------------------------------------------------+
+---------------------------------------------------------------+
|  主线程 task_struct    |  线程1 task_struct    |  线程2 task_struct  |
|  pid=1234              |  pid=1235              |  pid=1236            |
|  tgid=1234             |  tgid=1234             |  tgid=1234           |
|  mm=0xffff... (共享)   |  mm=0xffff... (共享)   |  mm=0xffff... (共享) |
|  stack=0x... (独有)    |  stack=0x... (独有)    |  stack=0x... (独有)   |
|  thread_struct (独有)  |  thread_struct (独有)  |  thread_struct (独有) |
|  sched_entity (独有)   |  sched_entity (独有)   |  sched_entity (独有)  |
+---------------------------------------------------------------+
```

## 5. 解决方案

### 5.1 通过 /proc 验证共享/独有

```bash
# 1. 查看进程的线程
ls /proc/PID/task/

# 2. 查看主线程 (PID = TGID) 的内存映射
cat /proc/PID/maps

# 3. 查看子线程 (TID != TGID) 的内存映射，应该相同
cat /proc/PID/task/TID/maps

# 4. 对比文件描述符，应该相同
ls /proc/PID/fd/
ls /proc/PID/task/TID/fd/

# 5. 查看状态差异
cat /proc/PID/status
cat /proc/PID/task/TID/status
```

### 5.2 编写验证程序

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <pthread.h>
#include <sys/syscall.h>

pid_t gettid(void) {
    return syscall(SYS_gettid);
}

void *thread_func(void *arg) {
    pid_t pid = getpid();
    pid_t tid = gettid();
    printf("Thread PID=%d, TID=%d, Tgid=%d\n", pid, tid, pid);
    return NULL;
}

int main() {
    pid_t main_pid = getpid();
    pid_t main_tid = gettid();
    printf("Main thread: PID=%d, TID=%d\n", main_pid, main_tid);
    
    pthread_t t1, t2;
    pthread_create(&t1, NULL, thread_func, NULL);
    pthread_create(&t2, NULL, thread_func, NULL);
    
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    return 0;
}
```

编译运行：
```bash
gcc -o verify_task_struct verify_task_struct.c -lpthread
./verify_task_struct
```

## 7. 推荐方案

日常开发验证推荐组合命令：
```bash
echo "=== 进程信息 ==="
ps -ef | grep process_name

echo "=== 线程信息 ==="
cat /proc/PID/status | grep -E "Name|Pid|Tgid|Threads"

echo "=== 各线程状态 ==="

    echo "--- $(basename $tid) ---"
    cat $tid/status | grep -E "State|Name"
done
```

深度分析建议使用 gdb 查看内核对象：
```bash
sudo gdb -p PID
(gdb) p task->mm
(gdb) p task->files
(gdb) p task->tgid
```

### 常见误区

1. 误区: 所有线程共享同一个 PID
   正确: 每个线程有唯一 TID，主线程的 TID = TGID = PID

2. 误区: 线程没有独立的栈
   正确: 每个线程有独立的内核栈和用户栈

3. 误区: 共享 mm 就是共享所有内存
   正确: 共享的是地址空间布局，物理页是 COW 的

## 10. 验证方式

创建多线程测试程序：
```c
#include <pthread.h>
#include <stdio.h>
#include <unistd.h>

void* worker(void* arg) {
    int id = *(int*)arg;
    printf("Thread %d: PID=%d, TID=%lu\n", id, getpid(), pthread_self());
    return NULL;
}

int main() {
    pthread_t t1, t2, t3;
    int ids[] = {1, 2, 3};
    printf("Main: PID=%d, TID=%lu\n", getpid(), pthread_self());
    pthread_create(&t1, NULL, worker, &ids[0]);
    pthread_create(&t2, NULL, worker, &ids[1]);
    pthread_create(&t3, NULL, worker, &ids[2]);
    pthread_join(t1, NULL);
    pthread_join(t2, NULL);
    pthread_join(t3, NULL);
    return 0;
}
```

### 线程组共享成员 (TGID 级别)

| `group_leader` | 主线程指针 |
| `mm` | 地址空间 |
| `files` | 文件描述符表 |

### 每个 task_struct 独有成员

| 成员 | 说明 |
| --- | --- |
| `pid` | 线程 ID |
| `stack` | 内核栈 |
| `thread` | 寄存器上下文 |

### 面试回答模板

Linux 中进程和线程底层都使用 `task_struct`，区别在于共享资源的程度不同。

线程组共享的资源包括：`mm_struct`（地址空间）、`files_struct`（文件描述符表）、`signal_struct`（信号描述符）、`fs_struct`（文件系统信息）和 `cred`（权限信息）。这些通过 `clone()` 时传入 `CLONE_VM`、`CLONE_FILES` 等标志实现共享。

每个 task_struct 独有的包括：`pid`（线程 ID）、内核栈 `stack`、寄存器上下文 `thread_struct`、调度实体 `sched_entity` 和进程状态 `state`。

用户态看到的"进程 PID"实际上是主线程的 TID，所有线程的 TGID 都等于主线程的 PID，所以看起来所有线程共享同一个 PID。
