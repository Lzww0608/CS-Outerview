# 2. 进程状态与查看

Linux 下查看进程状态，核心是确认进程是否存在、处于什么状态、由谁启动、占用哪些资源，以及是否卡在 CPU、I/O、锁或网络上。

## 1. 根据进程名找 PID

常用命令：

```bash
pgrep nginx
pgrep -af "my_server"
pidof nginx
ps -ef | grep my_server
```

区别：

1. `pgrep` 适合按进程名查 PID，`-f` 会匹配完整命令行。
2. `pidof` 适合查可执行文件名对应的 PID。
3. `ps -ef | grep` 通用但容易把 `grep` 自己也匹配出来，脚本里优先用 `pgrep`。

## 2. 查看进程状态

```bash
ps -o pid,ppid,stat,comm,wchan -p <pid>
cat /proc/<pid>/status
top -p <pid>
top -H -p <pid>
```

`STAT` 常见含义：

| 状态 | 含义 |
| --- | --- |
| `R` | Running 或 runnable，正在运行或在运行队列等待 CPU |
| `S` | Interruptible sleep，可中断睡眠，常见于等待事件 |
| `D` | Uninterruptible sleep，不可中断睡眠，常见于等待磁盘或内核 I/O |
| `T` | Stopped，被暂停或被 ptrace 跟踪 |
| `Z` | Zombie，进程已退出但父进程未回收 |
| `I` | Idle kernel thread，空闲内核线程 |

附加标记里，`l` 表示多线程，`+` 表示前台进程组，`<` 表示高优先级，`N` 表示低优先级。

## 3. 真实排查思路

1. 进程不存在：确认服务是否崩溃、被 OOM killer 杀掉或被 systemd/K8s 重启。
2. `R` 很多：看 CPU 是否打满，结合 `top -H`、`perf top`、火焰图定位热点。
3. `D` 状态：重点查磁盘、NFS、块设备、内核 I/O，`kill -9` 也可能暂时杀不掉。
4. `S` 但服务无响应：看线程栈是否卡在锁、条件变量、网络读写或下游调用。
5. `Z` 僵尸进程：父进程没有 `wait/waitpid` 回收，需要修复父进程回收逻辑。

常用组合：

```bash
ps -eLo pid,tid,stat,pcpu,comm,wchan | head
cat /proc/<pid>/limits
ls -l /proc/<pid>/fd
```

## 4. 面试回答模板

Linux 查已知进程名的 PID，我会优先用 `pgrep -af name` 或 `pidof name`，也可以用 `ps -ef | grep name`。查看状态用 `ps -o pid,ppid,stat,wchan,comm -p pid`、`top -p pid`、`top -H -p pid` 和 `/proc/<pid>/status`。状态里 `R` 表示运行或可运行，`S` 是可中断睡眠，`D` 是不可中断 I/O 等待，`Z` 是僵尸进程。排查时要结合 CPU、线程栈、fd、日志和 `/proc` 信息判断是 CPU 打满、I/O 卡住、锁等待还是进程已经异常退出。
