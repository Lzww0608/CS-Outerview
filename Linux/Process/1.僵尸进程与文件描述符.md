# 1. 僵尸进程与文件描述符

## 1. 僵尸进程是什么

僵尸进程是已经退出、但父进程还没有回收其退出状态的子进程。

子进程退出后，内核会释放它的大部分资源，例如地址空间、打开文件等，但会保留一小段进程表信息：

1. PID。
2. 退出码。
3. 资源使用统计。
4. 给父进程 `wait/waitpid` 回收所需的信息。

在 `ps` 中通常显示为 `Z` 或 `<defunct>`。

## 2. 为什么会出现僵尸进程

父进程创建子进程后，没有调用：

```c
wait()
waitpid()
```

来获取子进程退出状态，就会导致僵尸进程暂时存在。

如果父进程也退出，孤儿僵尸进程会被 `init` 或 `systemd` 接管并回收。

## 3. 如何处理僵尸进程

1. 父进程主动 `wait/waitpid`。
2. 注册 `SIGCHLD` 处理函数，在信号处理或主循环中回收。
3. 使用双重 fork，让孙进程被 init/systemd 接管。
4. 服务端进程要避免只 fork 不回收。

示例：

```c
#include <sys/wait.h>
#include <unistd.h>

void reapChildren() {
    while (waitpid(-1, nullptr, WNOHANG) > 0) {
    }
}
```

## 4. 孤儿进程是什么

孤儿进程是父进程已经退出、但子进程仍在运行的进程。它和僵尸进程不是一回事：

1. 孤儿进程仍然是活的，还在占用 CPU、内存、fd 等正常运行资源。
2. 僵尸进程已经退出，只剩下等待父进程回收的少量进程表信息。
3. 孤儿进程通常会被 `init` 或 `systemd` 接管，新的父进程负责在它退出时回收状态。
4. 孤儿进程本身不一定是异常；后台服务、守护进程、双重 fork 都会有意利用这种接管机制。

示例场景：

```c
pid_t pid = fork();
if (pid > 0) {
    _exit(0);   // 父进程退出
}

// 子进程继续运行，成为孤儿进程，随后被 init/systemd 接管
sleep(60);
```

面试中可以这样区分：

| 对比项 | 僵尸进程 | 孤儿进程 |
| --- | --- | --- |
| 子进程状态 | 已退出 | 仍在运行 |
| 父进程状态 | 父进程还在但没 wait | 原父进程已经退出 |
| 主要风险 | PID/进程表资源泄漏 | 长期运行可能变成无人管理任务 |
| 处理方式 | 父进程 wait 或由 init/systemd 回收 | 通常由 init/systemd 接管，关注日志、退出和资源清理 |

## 5. 文件描述符是什么

文件描述符 fd 是进程 fd 表中的一个非负整数下标。它指向内核中的打开文件对象。

可以理解为三层：

```text
fd 整数
-> 进程 fd 表
-> 内核打开文件对象 struct file
-> inode/socket/pipe 等底层对象
```

fd 不只表示普通文件，也可以表示：

1. socket。
2. pipe。
3. eventfd。
4. epoll fd。
5. timerfd。
6. 设备文件。

这也是 Unix “一切皆文件”的工程基础。

## 6. fd 的生命周期和易错点

1. `open/socket/pipe` 返回 fd。
2. `read/write/send/recv` 通过 fd 操作内核对象。
3. `close(fd)` 关闭当前进程 fd 表中的引用。
4. `fork()` 会复制 fd 表，父子进程 fd 指向同一个打开文件对象。
5. `exec()` 默认保留 fd，除非设置 `FD_CLOEXEC`。
6. fd 泄漏会导致 `Too many open files`。
7. fd 被关闭后可能被复用，异步代码里要小心 stale fd。

## 7. fork 后文件描述符共享

父进程 `open()` 一个文件后再 `fork()`，子进程会复制父进程的 fd 表。因此子进程里可以使用同一个 fd 编号访问文件。

需要区分两个层次：

```text
父进程 fd 表[3] ----\
                    -> 同一个 open file description(struct file) -> inode
子进程 fd 表[3] ----/
```

关键语义：

1. 父子进程的 fd 表是两份，但 fd 表项指向同一个内核打开文件对象。
2. `close(fd)` 只关闭当前进程 fd 表中的这个引用；子进程 close 不会让父进程的 fd 失效，反过来也一样。
3. 打开文件对象里保存文件偏移 `f_pos`，父子进程共享这个偏移。
4. 如果父进程读到第 10 个字节后再 fork，子进程继续 `read()` 会从第 11 个字节开始读，也就是从当前共享偏移继续。
5. 如果父子进程并发读同一个共享 fd，偏移会互相影响；需要独立偏移时应分别 `open()`，或者使用 `pread()` 指定偏移读取。

示例：

```c
int fd = open("data.txt", O_RDONLY);
char buf[10];
read(fd, buf, 10);  // f_pos 变为 10

pid_t pid = fork();
if (pid == 0) {
    char c;
    read(fd, &c, 1);  // 从偏移 10 处读 1 字节，读完偏移变为 11
    close(fd);        // 只关闭子进程自己的 fd 表项
    _exit(0);
}
```

易错点：

1. fd 数字相同不代表是同一张 fd 表；父子进程 fd 表相互独立。
2. close 影响引用计数，不会跨进程直接删除对方 fd。
3. 共享的是打开文件对象，所以文件偏移和打开标志会共享。
4. `O_APPEND` 写日志时偏移由内核追加语义控制，比手动 lseek 后 write 更安全。
5. `FD_CLOEXEC` 只影响 `exec()` 后是否继承，不影响 `fork()` 时复制。

## 8. 面试回答模板

僵尸进程是子进程已经退出，但父进程还没有通过 `wait/waitpid` 回收退出状态，内核保留了 PID、退出码等少量信息。孤儿进程是父进程先退出而子进程还在运行，通常会被 `init/systemd` 接管。解决僵尸进程的方法是父进程及时 wait，或处理 `SIGCHLD`，也可以用双重 fork。文件描述符是进程 fd 表的整数下标，指向内核打开文件对象，普通文件、socket、pipe、epoll 都可以用 fd 表示。fd 要及时 close，并注意 fork/exec 继承和 fd 泄漏。
