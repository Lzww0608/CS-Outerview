# 4. Linux 进程模型与 PCB

进程模型描述操作系统如何表示、调度和管理一个正在运行的程序。传统教材把进程控制块称为 PCB（Process Control Block）；在 Linux 内核中，进程和线程都主要由 `task_struct` 描述。

## 1. 进程由哪些部分组成

一个用户态进程通常可以从两个角度理解：

1. **用户态地址空间**：代码段、只读数据、数据段、BSS、堆、mmap 区、用户栈、共享库映射等。
2. **内核态管理信息**：PID、进程状态、调度信息、寄存器上下文、打开文件、信号处理、内存描述符、权限、命名空间和 cgroup 等。

教材里的 PCB 不是单纯保存“代码段、堆、栈”，而是保存操作系统管理进程所需的元数据。代码段、堆、栈在 Linux 里主要由虚拟内存区域 VMA 和页表描述，PCB 通过指针关联到这些结构。

## 2. Linux 的 task_struct

Linux 用 `task_struct` 表示一个可调度任务。它包含或关联的信息很多，面试里可以按类别回答：

| 类别 | 典型信息 | 作用 |
| --- | --- | --- |
| 身份信息 | `pid`、`tgid`、父进程、进程组、会话 | 标识进程/线程和父子关系 |
| 状态信息 | running、sleeping、stopped、zombie 等 | 调度和状态查看 |
| 调度信息 | 优先级、调度策略、时间片、运行队列节点 | 决定何时获得 CPU |
| CPU 上下文 | 程序计数器、栈指针、通用寄存器等保存区 | 上下文切换时保存和恢复 |
| 内存信息 | `mm_struct`、VMA、页表 | 描述进程虚拟地址空间 |
| 文件系统信息 | `files_struct`、`fs_struct` | 打开 fd、当前目录、根目录、umask |
| 信号信息 | `sighand_struct`、pending signal、signal mask | 信号处理和进程终止 |
| 权限信息 | uid、gid、capabilities、seccomp | 安全和访问控制 |
| 资源控制 | rlimit、namespace、cgroup | 限制资源并做隔离 |

Linux 内核维护可调度任务集合，调度器通过运行队列管理 runnable 任务；父子进程、线程组、PID hash、链表和红黑树等结构用于不同维度的查找和管理。面试里说“操作系统维护一个进程列表，列表里是 PCB”可以作为抽象理解，但 Linux 实现不是只有一个简单线性列表。

## 3. PID、TGID 和线程

Linux 里线程和进程底层都叫 task。区别主要来自共享哪些资源：

1. 普通 `fork()` 创建的子进程有新的 `task_struct`，通常有独立 `mm_struct`，地址空间通过写时复制共享物理页。
2. `pthread_create()` 底层通常通过 `clone()` 创建任务，并带上 `CLONE_VM`、`CLONE_FILES`、`CLONE_SIGHAND` 等标志，共享地址空间、文件表和信号处理。
3. 同一线程组里的多个线程有不同内核 task id，但共享同一个线程组 ID（TGID），用户态通常把 TGID 看作进程 PID。

可以这样理解：

```text
进程 = 资源容器 + 至少一个可调度任务
线程 = 同一资源容器内的可调度任务
```

所以 Linux 的“进程/线程”不是两个完全不同的内核对象，而是 `clone()` 时共享资源程度不同的 task。

## 4. 上下文切换保存什么

进程或线程切换时，内核需要保存当前任务的 CPU 执行状态，并恢复下一个任务的状态。典型内容包括：

1. 程序计数器/指令指针。
2. 栈指针。
3. 通用寄存器。
4. 内核栈位置。
5. 调度相关状态。
6. 必要时切换地址空间和页表。

同一进程内线程切换通常不需要切换 `mm_struct` 和页表，因此比跨进程切换更轻；跨进程切换可能导致 TLB 失效和缓存局部性下降。协程切换如果完全在用户态完成，通常只保存少量寄存器、栈指针或协程帧，不进入内核调度，成本更低。

## 5. fork 和写时复制

`fork()` 创建子进程时，父子进程的虚拟地址空间看起来相同，但物理页不会立刻完整复制。内核会复制页表，并把共享物理页标记为只读：

```text
fork 后：
父进程虚拟页 -> 同一个物理页，只读
子进程虚拟页 -> 同一个物理页，只读

某一方写入：
触发 page fault
-> 内核分配新物理页
-> 复制旧页内容
-> 更新写入方页表为可写
```

读共享页不会触发复制；写入才触发复制。这里的“写”包括修改堆、栈、全局变量、私有匿名映射等私有页。文件共享映射、共享内存和 fd 指向的内核对象有各自语义，不能简单套用“所有内容写时复制”。

真实项目里，`fork()` 后立即 `exec()` 很高效，因为子进程几乎不写父进程地址空间；多线程程序中 `fork()` 后子进程只保留调用线程，通常应尽快 `exec()`，避免继承锁状态导致死锁。

## 6. 如何观察进程模型

用户态可以通过 `/proc` 观察 Linux 暴露的进程信息：

```bash
cat /proc/<pid>/status
cat /proc/<pid>/maps
ls -l /proc/<pid>/fd
cat /proc/<pid>/sched
```

常见对应关系：

1. `/proc/<pid>/status`：PID、PPID、线程数、状态、内存概要、权限等。
2. `/proc/<pid>/maps`：代码段、堆、栈、共享库、mmap 区等 VMA。
3. `/proc/<pid>/fd`：打开文件描述符。
4. `/proc/<pid>/task`：线程组内的所有 task。
5. `/proc/<pid>/sched`：调度相关统计。

这些信息能帮助排查内存增长、fd 泄漏、线程数异常、僵尸进程和调度延迟。

## 7. 易错点

1. 不要把 PCB 理解成保存完整进程内存内容；PCB 保存管理元数据，内存内容由地址空间和页表管理。
2. Linux 线程也是 task，不是完全独立的一套内核结构。
3. `fork()` 的 COW 复制的是私有页，fd 指向的打开文件对象不是 COW。
4. 父子进程虚拟地址可以相同，但映射到的物理页会在写入后分离。
5. 同进程线程共享地址空间，但每个线程仍有自己的寄存器上下文和栈。

## 8. 面试回答模板

进程可以看作资源容器加可调度执行流。教材里的 PCB 在 Linux 中主要对应 `task_struct`，其中包含 PID、父子关系、状态、调度信息、寄存器上下文、内存描述符、文件描述符表、信号、权限、namespace 和 cgroup 等。代码段、数据段、堆、栈这些用户态内存由 `mm_struct`、VMA 和页表描述，`task_struct` 通过指针关联。Linux 线程和进程底层都是 task，区别在于 `clone()` 时是否共享地址空间、文件表、信号处理等资源。`fork()` 创建子进程时通过写时复制共享物理页，读不复制，写时触发缺页异常并复制页面。
