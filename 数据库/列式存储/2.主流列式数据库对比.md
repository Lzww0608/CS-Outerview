## 二、ClickHouse

### 2.1 产品介绍

ClickHouse 是俄罗斯 Yandex 公司开源的列式数据库，专为 OLAP 场景设计，以高性能著称。

```text
核心特点：
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  1. 列式存储 + 向量化执行                                  │
│     - 减少 IO，只读取需要的列                              │
│     - SIMD 指令加速计算                                   │
│                                                             │
│  2. 向量化查询引擎                                        │
│     - Pipeline 并行执行                                   │
│     - 多核 CPU 利用率高                                    │
│                                                             │
│  3. MergeTree 表引擎家族                                  │
│     - 高效的数据合并和压缩                                │
│     - 支持实时数据写入                                    │
│                                                             │
│  4. 分片副本架构                                         │
│     - 分布式并行查询                                      │
│     - 数据副本冗余                                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 三、Apache Druid

### 3.1 产品介绍

Apache Druid 是一个专为 OLAP 场景设计的实时分析型数据库，以高并发实时摄取和低延迟查询著称。

```text
核心特点：
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  1. 实时数据摄取                                          │
│     - Kafka/Kinesis 直接对接                              │
│     - 秒级数据可见                                        │
│                                                             │
│  2. 预聚合（Roll-up）                                    │
│     - 预先聚合数据，减少查询计算量                        │
│     - 大幅降低存储和查询成本                              │
│                                                             │
│  3. 列式存储 + 倒排索引                                  │
│     - 高效的过滤查询                                      │
│     - 支持复杂维度组合                                    │
│                                                             │
│  4. 数据分片 + 副本                                      │
│     - 时间分片（按天/小时分片）                          │
│     - 数据副本冗余                                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 核心架构

```text
┌─────────────────────────────────────────────────────────────┐
│                    Druid 架构                                │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐  │
│  │                  Ingestion Layer                      │  │
│  │        (Kafka/自定义数据源 → Real-time Node)       │  │
│  └─────────────────────────────────────────────────────┘  │
│                           │                                │
│                           ▼                                │
│  ┌─────────────────────────────────────────────────────┐  │
│  │                   Historical Node                     │  │
│  │              (历史数据存储 + 查询)                    │  │
│  └─────────────────────────────────────────────────────┘  │
│                           │                                │
│                           ▼                                │
│  ┌─────────────────────────────────────────────────────┐  │
│  │                   Broker Node                        │  │
│  │              (查询路由 + 结果聚合)                   │  │
│  └─────────────────────────────────────────────────────┘  │
│                           │                                │

│  │              (元数据管理 + 负载均衡)                 │  │
│  └─────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
```

### 3.3 适用场景

## 六、DuckDB

DuckDB 是一个嵌入式分析型数据库，专为 OLAP 场景设计，可以作为进程内库使用。

```text
│     - 零运维开销                                            │
│                                                             │
│  2. 向量化执行引擎                                          │
│     - 高效的列式处理                                        │
│     - SIMD 加速                                            │
│                                                             │
│  3. 完整 SQL 支持                                          │
│     - PostgreSQL 兼容语法                                    │
│     - 窗口函数、CTE、复杂 JOIN                             │
│                                                             │
│  4. 数据格式                                                │
│     - 原生支持 Parquet、ORC、CSV                          │

│                                                             │

```

### 6.2 适用场景

- 数据分析笔记本（ Jupyter/Python）

- 嵌入式分析应用
- 小型数据分析团队
- 数据验证和探索


## 八、面试常见问题

### Q1: ClickHouse 和 Druid 的区别？

ClickHouse 追求极致查询性能，适合离线分析；Druid 追求实时摄取，适合实时监控场景。Druid 有内置的实时节点和预聚合，ClickHouse 更依赖批量导入。

### Q2: Snowflake 为什么性能不是最优？

Snowflake 定位是企业级数据仓库，优先考虑易用性、多租户隔离和弹性伸缩。牺牲部分性能换取更好的用户体验和运维便利性。

### Q3: DuckDB 适合生产环境吗？

DuckDB 主要定位是嵌入式分析和数据探索，不适合大规模分布式场景。对于小规模数据分析、边缘计算、研究环境非常合适。

### Q4: 如何选择列式数据库？

1. 实时性要求高 → Druid
2. 查询性能要求极高 → ClickHouse
3. 云原生 + 多租户 → Snowflake/BigQuery
4. 嵌入式 + 零运维 → DuckDB

---

## 九、总结

1. **ClickHouse**：性能之王，适合离线分析大规模数据
2. **Druid**：实时摄取专家，适合监控和流数据分析
3. **Snowflake**：云原生易用，适合企业数据仓库
4. **DuckDB**：嵌入式轻量，适合研究和边缘计算
5. **选型关键**：根据实时性、性能、规模、运维能力综合选择
