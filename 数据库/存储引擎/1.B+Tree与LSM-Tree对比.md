# 1. B+Tree 与 LSM-Tree 对比

B+Tree 和 LSM-Tree 是存储引擎中最常见的两类结构。B+Tree 偏向原地更新和低读放大，LSM-Tree 偏向追加写和后台合并。面试里要能从读放大、写放大、空间放大、并发控制和真实场景选择几个角度回答。

## 1. B+Tree

B-Tree/B+Tree 的核心思想是多路平衡搜索树。数据库里常说的 B+Tree 通常有这些特点：

1. 非叶子节点只保存 key 和孩子指针。
2. 叶子节点保存完整记录或记录指针。
3. 叶子节点按 key 有序，并通过链表连接，适合范围扫描。
4. 节点大小通常对齐磁盘页或缓存页，扇出高，树高低。

优点：

1. 点查路径短，通常只需要几层页访问。
2. 范围查询天然顺序扫描叶子页。
3. 更新后数据较快处于可读位置，读放大低。

缺点：

1. 随机写会修改分散页面，可能导致随机 I/O。
2. 插入、删除可能触发页分裂、合并和父节点更新。
3. 并发写需要仔细做 latch 管理。

## 2. LSM-Tree

LSM-Tree 把随机写转成内存写和磁盘顺序写。典型写入路径：

```text
Write -> WAL -> MemTable -> Immutable MemTable -> SSTable -> Compaction
```

SSTable 内部按 key 有序，不同层级通过 compaction 合并旧版本、删除墓碑和控制文件数量。

优点：

1. 写入先追加 WAL，再写内存结构，前台写入吞吐高。
2. Flush 和 compaction 主要是顺序 I/O，适合 SSD/HDD 批量写。
3. 易于压缩、分层、冷热分离和 Bloom Filter 加速。

缺点：

1. 读可能查 MemTable、Immutable MemTable、多层 SSTable，存在读放大。
2. compaction 会反复读写数据，存在写放大。
3. 旧版本和 tombstone 清理前会占空间，存在空间放大。
4. compaction 可能造成尾延迟抖动。

## 3. `latch crabbing`

`latch crabbing` 是 B+Tree 并发控制中的一种锁耦合技术。它的目标是在从根走到叶子的过程中保证结构安全，同时尽早释放上层节点 latch，降低并发冲突。

基本思路：

1. 先持有父节点 latch。
2. 找到要进入的子节点后，先获取子节点 latch。
3. 判断子节点是否“安全”。
4. 如果安全，就释放父节点 latch，只保留子节点 latch 继续向下。
5. 如果不安全，可能保留祖先路径上的 latch，以便处理分裂或合并。

“安全”的含义取决于操作：

1. 插入时，子节点未满，插入不会导致分裂。
2. 删除时，子节点元素数高于下限，删除不会导致借位或合并。
3. 查找时，一般只需要读 latch，可以一路读耦合并快速释放父节点。

常见优化是 optimistic crabbing：先按读 latch 或乐观方式走到叶子，如果发现叶子不安全，再从根用写 latch 重走，减少大多数普通操作的写锁范围。

## 4. 读放大、写放大、空间放大

| 维度 | B+Tree | LSM-Tree |
| --- | --- | --- |
| 读放大 | 点查通常树高次页访问，范围扫顺序叶子页 | 可能查多层 SSTable，需 Bloom Filter、block cache、索引块降低放大 |
| 写放大 | WAL + 数据页修改 + 页分裂/合并；随机写较多 | WAL + Flush + 多轮 Compaction；同一数据可能被重写多次 |
| 空间放大 | 页内碎片、旧版本取决于 MVCC/undo | 多版本、tombstone、compaction 未完成文件 |
| 写入延迟 | 受页 latch、随机页修改、刷盘影响 | 前台写快，但 compaction 可能制造尾延迟 |
| 范围查询 | 很强，叶子链表天然有序 | LSM 也有序，但可能跨多层、多文件归并 |

## 5. 如何选型

1. **读多写少、范围查询多、事务索引**：B+Tree 更常见，例如 InnoDB。
2. **写多、日志型、KV、时间序写入**：LSM-Tree 更合适，例如 LevelDB、RocksDB、HBase、Cassandra。
3. **强事务 + 复杂 SQL**：优先成熟关系型 B+Tree 引擎。
4. **高写入吞吐 + 简单 key-value 访问**：优先 LSM KV。
5. **点查多的 LSM**：要关注 Bloom Filter、block cache、level compaction、prefix extractor。
6. **范围扫多的 LSM**：要控制层数、文件重叠、compaction 策略和 value 分离带来的随机读。

## 6. 面试回答模板

B+Tree 是页组织的多路平衡树，读路径短、范围查询好，但随机写会修改分散页面，页分裂和并发 latch 是重点。`latch crabbing` 是从根到叶加锁时先拿子节点 latch，再在确认子节点安全后释放父节点，既保证分裂合并安全，又减少锁范围。LSM-Tree 则把写入变成 WAL + MemTable + SSTable 顺序写，前台写很快，但读要查多层文件，compaction 带来读放大、写放大和空间放大。读多范围多偏 B+Tree，写多 KV 偏 LSM。
