# 6.SQL 语句分类：DDL、DML、DCL

SQL 语句通常可以按操作对象分为 DDL、DML、DCL、DQL、TCL。面试里常问 DDL、DML、DCL 的区别，以及后台消费脚本如何判断一条语句属于哪一类。

## 1. DDL

DDL（Data Definition Language）是数据定义语言，用来定义或修改数据库对象结构。

常见语句：

```sql
CREATE DATABASE db;
CREATE TABLE t (...);
ALTER TABLE t ADD COLUMN c INT;
DROP TABLE t;
TRUNCATE TABLE t;
RENAME TABLE t1 TO t2;
CREATE INDEX idx_name ON t(c);
DROP INDEX idx_name ON t;
```

DDL 关注的是库、表、字段、索引、视图、存储过程等对象的结构变化。MySQL 中很多 DDL 会触发隐式提交，因此不能简单当作普通事务内语句处理。

## 2. DML

DML（Data Manipulation Language）是数据操作语言，用来操作表中的数据行。

常见语句：

```sql
INSERT INTO t(id, name) VALUES (1, 'a');
UPDATE t SET name = 'b' WHERE id = 1;
DELETE FROM t WHERE id = 1;
REPLACE INTO t(id, name) VALUES (1, 'c');
```

DML 关注的是数据内容变化。对于 Canal 这类 binlog 订阅工具，如果 binlog 使用 ROW 模式，DML 通常会表现为行级变更事件，比如 `INSERT`、`UPDATE`、`DELETE` 对应的 row event。

## 3. DCL

DCL（Data Control Language）是数据控制语言，主要用于权限和安全控制。

常见语句：

```sql
GRANT SELECT ON db.* TO 'user'@'%';
REVOKE SELECT ON db.* FROM 'user'@'%';
CREATE USER 'user'@'%' IDENTIFIED BY 'pwd';
ALTER USER 'user'@'%' IDENTIFIED BY 'new_pwd';
DROP USER 'user'@'%';
SET PASSWORD FOR 'user'@'%' = 'pwd';
```

DCL 的核心是用户、权限、认证和访问控制。判断 DCL 时不能只看是否修改了系统表，因为不同 MySQL 版本的权限存储方式可能变化，应该按 SQL 语义或解析结果判断。

## 4. 其他分类

| 类型 | 含义 | 常见语句 |
| --- | --- | --- |
| DQL | Data Query Language，数据查询语言 | `SELECT` |
| TCL | Transaction Control Language，事务控制语言 | `BEGIN`、`COMMIT`、`ROLLBACK`、`SAVEPOINT` |

## 5. 后台脚本怎么判断语句类型？

如果脚本消费的是结构化事件，优先使用事件类型，不要自己用字符串硬匹配。

### 5.1 消费 Canal/binlog 事件

如果是 Canal 解析后的事件，通常可以直接看事件类型：

```text
INSERT / UPDATE / DELETE -> DML
CREATE / ALTER / ERASE / TRUNCATE / RENAME / CINDEX / DINDEX -> DDL
QUERY 类型事件 -> 需要进一步解析 SQL
```

不同客户端封装的枚举名字可能略有差异，但思路都是先看结构化 event type。

### 5.2 消费原始 SQL

如果只能拿到 SQL 文本，推荐使用 SQL Parser，例如按 MySQL 方言解析 AST，再根据 AST 节点类型判断。

简化判断逻辑：

```text
去掉注释和前导空白
    -> 解析第一个关键字
    -> CREATE/ALTER/DROP/TRUNCATE/RENAME -> DDL
    -> INSERT/UPDATE/DELETE/REPLACE -> DML
    -> GRANT/REVOKE/CREATE USER/ALTER USER/DROP USER/SET PASSWORD -> DCL
    -> SELECT/SHOW/EXPLAIN/DESC -> DQL 或管理类查询
    -> BEGIN/COMMIT/ROLLBACK/SAVEPOINT -> TCL
```

## 6. 易错点

1. **不要用 contains 判断**：例如 SQL 注释、字符串字面量里可能包含 `drop`、`grant` 等词。
2. **要处理注释和空白**：`/* comment */ ALTER TABLE ...` 不能被误判。
3. **要处理多语句**：一次输入可能包含多条 SQL，需要拆分后逐条判断。
4. **CREATE USER 是 DCL 语义**：虽然以 `CREATE` 开头，但它不是普通建表 DDL。
5. **TRUNCATE 常归为 DDL**：它删除表数据，但语义上会重建或快速清空表结构关联的数据页，MySQL 中也会隐式提交。
6. **Online DDL 仍是 DDL**：即使用 `ALGORITHM=INPLACE` 或 gh-ost/pt-osc，也要按结构变更处理。

## 7. 面试回答模板

DDL 是数据定义语言，操作库表结构，比如 `CREATE`、`ALTER`、`DROP`、`TRUNCATE`；DML 是数据操作语言，操作表里的行数据，比如 `INSERT`、`UPDATE`、`DELETE`；DCL 是数据控制语言，主要处理用户和权限，比如 `GRANT`、`REVOKE`、`CREATE USER`。

如果后台消费的是 Canal 或 binlog 解析后的事件，最好直接根据事件类型判断 DDL/DML，而不是解析 SQL 字符串。只有拿到的是原始 SQL 时，才用 SQL Parser 或至少按首关键字分类，并注意注释、多语句、`CREATE USER`、`TRUNCATE` 这类容易误判的情况。
