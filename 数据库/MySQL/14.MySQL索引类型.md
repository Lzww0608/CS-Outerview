# MySQL 索引类型

MySQL 的索引可以从数据结构、约束语义、字段数量和存储位置多个角度分类。面试里不要只列“主键、唯一、普通”，最好能说明它们解决什么问题、底层结构和使用限制。

## 按约束语义分类

| 类型 | 含义 | 典型用途 |
| --- | --- | --- |
| 主键索引 `PRIMARY KEY` | 唯一且非空，一张表只能有一个 | 行唯一标识、InnoDB 聚簇索引 |
| 唯一索引 `UNIQUE` | 值唯一，可用于业务唯一约束 | 手机号、邮箱、订单号 |
| 普通索引 `INDEX` | 只加速查询，不保证唯一 | 高频过滤字段 |
| 全文索引 `FULLTEXT` | 面向文本关键词检索 | 文章、标题、描述 |
| 空间索引 `SPATIAL` | 面向 GIS 空间数据 | 地理位置、几何对象 |

InnoDB 中如果没有显式主键，会选择第一个非空唯一索引作为聚簇索引；如果也没有，会生成隐藏 row id。因此生产表建议显式定义短、稳定、趋势递增的主键。

## 按字段数量分类

### 单列索引

只包含一个字段：

```sql
CREATE INDEX idx_user_id ON orders(user_id);
```

适合单字段高频过滤，但多个单列索引不等价于一个设计良好的联合索引。

### 联合索引

包含多个字段：

```sql
CREATE INDEX idx_user_status_time
ON orders(user_id, status, created_at);
```

联合索引按照字段顺序排序，遵守最左前缀法则。它常用于组合过滤、排序、分组和覆盖查询。

### 前缀索引

对字符串前 N 个字符建索引：

```sql
CREATE INDEX idx_email_prefix ON user(email(12));
```

适合长字符串，但不能完整支持精确唯一性判断，区分度要通过数据评估。

## 按存储结构分类

### B+ 树索引

InnoDB 默认索引结构，适合：

1. 等值查询。
2. 范围查询。
3. 排序和分组。
4. 最左前缀匹配。

InnoDB 主键索引是聚簇索引，叶子节点保存整行数据；二级索引叶子节点保存二级索引 key 和主键值。

### Hash 索引

Memory 引擎支持 Hash 索引。InnoDB 有自适应哈希索引，但不是用户显式创建的普通 Hash 索引。

Hash 索引适合等值查询，不适合：

1. 范围查询。
2. 排序。
3. 最左前缀匹配。

### 倒排索引

全文索引通常使用倒排索引思想，把词项映射到文档列表，适合关键词检索。它不同于 B+ 树索引，不适合普通范围查询。

## 聚簇索引和二级索引

InnoDB 中：

1. **聚簇索引**：表数据按主键索引组织，叶子节点保存完整行。
2. **二级索引**：叶子节点保存二级索引列和主键值。
3. 二级索引查询完整行时，需要先查二级索引拿主键，再回到聚簇索引查整行，这叫回表。

覆盖索引可以避免回表：

```sql
SELECT user_id, status
FROM orders
WHERE user_id = 1;
```

如果查询字段都在联合索引中，就可能只查二级索引完成。

## 易错点

1. 唯一索引不等于主键索引，唯一索引可以有多个，主键只能一个且非空。
2. InnoDB 表数据本身就是按聚簇索引组织的，不是索引和数据完全分离。
3. 多个单列索引通常不能替代联合索引。
4. 前缀索引会降低索引长度，但可能降低区分度。
5. Hash 索引不支持范围和排序，B+ 树才是 InnoDB 普通索引主力。

## 面试回答模板

MySQL 索引可以按语义分为主键索引、唯一索引、普通索引、全文索引、空间索引；按字段数量分为单列索引、联合索引、前缀索引；按结构主要有 B+ 树索引、Hash 索引和全文倒排索引。InnoDB 默认使用 B+ 树，主键索引是聚簇索引，叶子节点保存整行；二级索引叶子节点保存索引列和主键，查整行可能回表。联合索引要遵守最左前缀，覆盖索引可以减少回表。Hash 索引适合等值，不适合范围和排序。
