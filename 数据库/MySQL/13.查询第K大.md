# 查询第 K 大

查询第 K 大的行，要先明确“第 K 大”按哪个字段排序、是否允许并列、是否要返回整行，以及 K 是否从 1 开始。不同语义对应不同 SQL。

## 基础写法：ORDER BY + LIMIT OFFSET

如果只要求按某个字段排序后取第 K 行，且 K 从 1 开始：

```sql
SELECT *
FROM employee
ORDER BY salary DESC, id ASC
LIMIT 1 OFFSET :k_minus_1;
```

MySQL 也可以写成：

```sql
SELECT *
FROM employee
ORDER BY salary DESC, id ASC
LIMIT :k_minus_1, 1;
```

注意加上稳定的第二排序字段，例如 `id`，否则同薪资行之间顺序不确定。

## 第 K 大的不重复值

如果问的是“第 K 大薪资”，并列薪资只算一次：

```sql
SELECT DISTINCT salary
FROM employee
ORDER BY salary DESC
LIMIT 1 OFFSET :k_minus_1;
```

如果还要返回这个薪资对应的所有员工：

```sql
SELECT *
FROM employee
WHERE salary = (
    SELECT salary
    FROM (
        SELECT DISTINCT salary
        FROM employee
        ORDER BY salary DESC
        LIMIT 1 OFFSET :k_minus_1
    ) AS t
);
```

MySQL 中派生表 `t` 用来避免部分版本对同层 `LIMIT` 子查询的限制和优化器改写问题。

## 窗口函数写法

MySQL 8.0 支持窗口函数。

### 第 K 行

```sql
SELECT *
FROM (
    SELECT e.*,
           ROW_NUMBER() OVER (ORDER BY salary DESC, id ASC) AS rn
    FROM employee e
) AS t
WHERE rn = :k;
```

### 第 K 大不重复排名

```sql
SELECT *
FROM (
    SELECT e.*,
           DENSE_RANK() OVER (ORDER BY salary DESC) AS rnk
    FROM employee e
) AS t
WHERE rnk = :k;
```

区别：

1. `ROW_NUMBER()`：每行编号，遇到并列也递增。
2. `RANK()`：并列同名次，但会跳号。
3. `DENSE_RANK()`：并列同名次，不跳号，适合“第 K 大不重复值”。

## 性能优化

如果表很大，应围绕排序字段建索引：

```sql
CREATE INDEX idx_salary_id ON employee(salary DESC, id ASC);
```

这样可以按索引顺序扫描，减少 filesort。需要注意：

1. `OFFSET` 很大时仍然要跳过前面 K-1 行，成本可能很高。
2. 深分页可以改成基于游标的 seek pagination，例如记住上一页最后的 `(salary, id)`。
3. 如果要返回很多非索引字段，可能发生大量回表。
4. 排序字段有 NULL 时，要明确 NULL 排序规则。

## 易错点

1. 不写 `ORDER BY` 就没有“第 K 大”的确定语义。
2. 并列值是否算同一名次要提前说明。
3. `LIMIT k, 1` 中的 `k` 是偏移量，不是第 K 条；第 K 条偏移量是 `K-1`。
4. 大 OFFSET 不是常数时间，线上深分页要谨慎。
5. 只按非唯一字段排序时，结果可能不稳定，建议加主键兜底。

## 面试回答模板

如果只是取排序后的第 K 行，可以用 `ORDER BY score DESC, id ASC LIMIT K-1, 1`；如果是第 K 大不重复值，要先 `DISTINCT score` 再排序取第 K 个，或者 MySQL 8.0 用 `DENSE_RANK()`。并列是否算同一名次要说清楚。性能上要给排序字段和兜底主键建联合索引，例如 `(score DESC, id ASC)`，但大 OFFSET 仍然要跳过很多行，深分页更适合用游标条件继续扫。
