# 29. 书籍作者关系表设计

场景：设计一个书籍管理系统，需要存储书和作者的对应关系。一本书可能有多个作者，一个作者也可能有多个不同名字，例如“鲁迅”和“周树人”。核心思路是：**作者不是一个名字，而是一个真实的人或实体；名字只是作者的别名属性**。

因此不能直接在书表里保存作者名，也不应该只建 `book_author(book_id, author_name)`，否则“鲁迅”和“周树人”会被当成两个不同作者，后续查询、合并、统计和去重都会出问题。

## 1. 表设计思路

推荐至少拆成四张表：

```text
books              书籍表
authors            作者实体表
author_names       作者名称/别名表
book_authors       书籍-作者关系表
```

关系如下：

```text
books 1 --- N book_authors N --- 1 authors
authors 1 --- N author_names
```

这样可以同时解决两个问题：

1. 一本书有多个作者：通过 `book_authors` 多对多关系解决。
2. 一个作者有多个名字：通过 `author_names` 一对多关系解决。

关键点是：**作者 ID 才代表真实作者，名字只是作者的属性**。

## 2. 书籍表

`books` 保存书籍的稳定信息，不直接存作者名。

```sql
CREATE TABLE books (
    book_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    title VARCHAR(255) NOT NULL,
    isbn VARCHAR(32) UNIQUE,
    publisher VARCHAR(255),
    publish_date DATE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;
```

示例：

```text
book_id | title
--------|---------
1       | 呐喊
2       | 朝花夕拾
```

## 3. 作者实体表

`authors` 表示一个真实作者实体，不直接依赖某个名字。

```sql
CREATE TABLE authors (
    author_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    remark TEXT,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;
```

示例：

```text
author_id | remark
----------|----------------
1         | 中国现代文学作家
```

这里的 `author_id = 1` 表示同一个人：周树人，也就是鲁迅。

## 4. 作者名称表

`author_names` 保存作者的本名、笔名、别名、外文名等。一个作者可以有多个名字。

```sql
CREATE TABLE author_names (
    name_id BIGINT PRIMARY KEY AUTO_INCREMENT,
    author_id BIGINT NOT NULL,
    name VARCHAR(255) NOT NULL,
    name_type VARCHAR(50),
    is_primary BOOLEAN DEFAULT FALSE,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP,

    CONSTRAINT fk_author_names_author
        FOREIGN KEY (author_id) REFERENCES authors(author_id),
    UNIQUE KEY uk_author_name (author_id, name),
    KEY idx_name (name)
) ENGINE=InnoDB;
```

示例：

```text
name_id | author_id | name   | name_type | is_primary
--------|-----------|--------|-----------|------------
1       | 1         | 鲁迅   | 笔名      | true
2       | 1         | 周树人 | 本名      | false
```

不要给 `name` 单独加全局唯一约束，因为不同作者可能重名。更合理的是：

```sql
UNIQUE KEY uk_author_name (author_id, name)
```

它表示同一个作者名下不能重复录入同一个名字。如果业务需要按名字搜索作者，可以给 `name` 建普通索引，再由人工或业务规则处理同名作者。

## 5. 书籍-作者关系表

一本书可以有多个作者，一个作者也可以写多本书，所以需要中间表。

```sql
CREATE TABLE book_authors (
    book_id BIGINT NOT NULL,
    author_id BIGINT NOT NULL,
    author_order INT DEFAULT 1,
    credited_name_id BIGINT NULL,

    PRIMARY KEY (book_id, author_id),
    KEY idx_author_id (author_id),
    KEY idx_book_order (book_id, author_order),

    CONSTRAINT fk_book_authors_book
        FOREIGN KEY (book_id) REFERENCES books(book_id),
    CONSTRAINT fk_book_authors_author
        FOREIGN KEY (author_id) REFERENCES authors(author_id),
    CONSTRAINT fk_book_authors_credited_name
        FOREIGN KEY (credited_name_id) REFERENCES author_names(name_id)
) ENGINE=InnoDB;
```

字段含义：

1. `book_id`：书籍 ID。
2. `author_id`：真实作者实体 ID。
3. `author_order`：作者顺序，用于展示第一作者、第二作者等。
4. `credited_name_id`：该书实际署名使用的名字，可为空。

`credited_name_id` 很有用，因为同一个作者在不同书上可能使用不同署名。

示例：

```text
book_id | author_id | author_order | credited_name_id
--------|-----------|--------------|----------------
1       | 1         | 1            | 1
2       | 1         | 1            | 1
```

这表示《呐喊》和《朝花夕拾》的作者都是 `author_id = 1`，署名使用的是 `name_id = 1`，也就是“鲁迅”。

## 6. 查询一本书的作者

查询《呐喊》的作者署名：

```sql
SELECT
    b.title,
    an.name AS credited_name,
    ba.author_order
FROM books b
JOIN book_authors ba ON b.book_id = ba.book_id
LEFT JOIN author_names an ON ba.credited_name_id = an.name_id
WHERE b.title = '呐喊'
ORDER BY ba.author_order;
```

结果：

```text
title | credited_name | author_order
------|---------------|-------------
呐喊  | 鲁迅          | 1
```

如果允许 `credited_name_id` 为空，展示时可以回退到作者主名称：

```sql
SELECT
    b.title,
    COALESCE(cn.name, pn.name) AS display_name,
    ba.author_order
FROM books b
JOIN book_authors ba ON b.book_id = ba.book_id
LEFT JOIN author_names cn ON ba.credited_name_id = cn.name_id
LEFT JOIN author_names pn
    ON pn.author_id = ba.author_id
   AND pn.is_primary = TRUE
WHERE b.title = '呐喊'
ORDER BY ba.author_order;
```

## 7. 查询某个作者的所有名字

```sql
SELECT
    a.author_id,
    an.name,
    an.name_type,
    an.is_primary
FROM authors a
JOIN author_names an ON a.author_id = an.author_id
WHERE a.author_id = 1
ORDER BY an.is_primary DESC, an.name_id;
```

结果：

```text
author_id | name   | name_type | is_primary
----------|--------|-----------|------------
1         | 鲁迅   | 笔名      | true
1         | 周树人 | 本名      | false
```

## 8. 约束和易错点

1. 不要把作者名直接存到 `books` 表，否则无法表达多作者，也难以维护作者别名。
2. 不要只建 `book_author(book_id, author_name)`，名字不是作者实体，同一个人多个名字会被拆成多个人。
3. `author_names.name` 不要全局唯一，不同作者可能重名。
4. `book_authors` 的主键通常用 `(book_id, author_id)`，防止同一本书重复绑定同一个作者。
5. 如果一本书同一个作者可能以多个身份出现，例如作者兼译者，需要在关系表中增加 `role` 字段，并把主键改成 `(book_id, author_id, role)` 或使用独立关系 ID。
6. 如果要强约束 `credited_name_id` 必须属于当前 `author_id`，单独外键 `credited_name_id -> author_names(name_id)` 还不够，可以给 `author_names` 增加唯一键 `(author_id, name_id)`，再在 `book_authors(author_id, credited_name_id)` 上建组合外键。
7. 如果要求每个作者只能有一个主名称，MySQL 没有通用的部分唯一索引，可以在业务层保证，或增加独立 `primary_name_id` 字段放到 `authors` 表中。

组合外键的写法可以是：

```sql
ALTER TABLE author_names
ADD UNIQUE KEY uk_author_name_id (author_id, name_id);

ALTER TABLE book_authors
ADD CONSTRAINT fk_book_authors_author_credited_name
FOREIGN KEY (author_id, credited_name_id)
REFERENCES author_names(author_id, name_id);
```

## 9. 面试回答模板

我不会把作者名直接放在书表里，因为作者不是字符串，而是一个真实实体。表结构会拆成四张：`books` 存书，`authors` 存作者实体，`author_names` 存作者的本名、笔名和别名，`book_authors` 存书和作者的多对多关系。这样一本书多个作者靠中间表解决，一个作者多个名字靠别名表解决。关系表里还可以放 `author_order` 表示作者顺序，放 `credited_name_id` 表示这本书实际署名用哪个名字。名字字段不做全局唯一，只做 `(author_id, name)` 唯一，因为不同作者可能重名。核心原则是用 `author_id` 表示真实作者，名字只是作者的属性。
