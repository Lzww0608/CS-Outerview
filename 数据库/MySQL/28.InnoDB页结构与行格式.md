# 28. InnoDB 页结构与行格式

面试里问“InnoDB 的数据结构、存储引擎是什么格式”，通常想听到两层：逻辑上 InnoDB 表是聚簇 B+ 树，物理上 InnoDB 以表空间、段、区、页、记录来组织数据。

## 1. InnoDB 的整体存储层次

InnoDB 常见层次如下：

```text
表空间 tablespace
  -> 段 segment
      -> 区 extent
          -> 页 page
              -> 行记录 record
```

含义：

1. **表空间**：数据文件，例如独立表空间里的 `.ibd` 文件。
2. **段**：按用途划分的空间管理单位，例如索引段、回滚段。
3. **区**：连续页组成的分配单位，默认一个区通常是 1MB。
4. **页**：InnoDB 读写磁盘和 Buffer Pool 缓存的基本单位，默认 16KB。
5. **记录**：页中保存的行数据或索引记录。

InnoDB 的一张表如果有主键，表数据本身就按主键组织在聚簇索引 B+ 树的叶子页里；二级索引也是 B+ 树，但叶子记录保存二级索引列和主键值。

## 2. 数据页里有什么

一个 InnoDB 数据页不是简单的“行数组”，它包含页头、系统记录、用户记录、页目录和校验信息。

```text
File Header
Page Header
Infimum / Supremum
User Records
Free Space
Page Directory
File Trailer
```

关键点：

1. `Infimum` 和 `Supremum` 是页内最小、最大哨兵记录，方便页内链表维护。
2. 用户记录在页内按主键或索引 key 有序组织。
3. 页目录保存部分记录槽位，用于页内二分查找。
4. 同一层 B+ 树页之间通过前后指针连接，叶子页链表支持范围扫描。
5. `File Trailer` 包含校验和等信息，用于发现页损坏或半写问题。

## 3. 行记录格式

现代 InnoDB 常见行格式有：

| 行格式 | 特点 | 典型情况 |
| --- | --- | --- |
| `REDUNDANT` | 早期格式，兼容历史版本 | 很少新建使用 |
| `COMPACT` | 紧凑格式，减少冗余字段 | 老版本常见 |
| `DYNAMIC` | 大字段更倾向页外存储 | MySQL 5.7/8.0 常见默认 |
| `COMPRESSED` | 页压缩，降低存储占用 | 读多、冷数据，需评估 CPU |

以 `COMPACT/DYNAMIC` 思路理解，一条记录大致包含：

1. **变长字段长度列表**：记录 `varchar/varbinary` 等变长字段长度。
2. **NULL 标记位图**：记录哪些列为 `NULL`。
3. **记录头信息**：包含删除标记、下一条记录偏移、记录类型等。
4. **隐藏列**：如果没有显式主键会有隐藏 row id；聚簇记录还包含事务 ID 和回滚指针，用于 MVCC。
5. **真实列数据**：用户定义的列值。

大字段如 `TEXT/BLOB/很长的 VARCHAR` 不一定完整放在聚簇索引页内。`DYNAMIC` 行格式更倾向把大字段放到溢出页，记录里保存指向页外数据的指针，从而减少聚簇索引页膨胀。

## 4. 聚簇索引和二级索引记录的差别

聚簇索引叶子记录保存完整行：

```text
primary key + hidden trx_id + roll_pointer + all columns
```

二级索引叶子记录保存：

```text
secondary key + primary key
```

所以二级索引查完整行时，需要先在二级索引里拿到主键，再回聚簇索引查整行，这就是回表。覆盖索引能避免回表，因为查询需要的列已经都在二级索引记录里。

## 5. 易错点

1. InnoDB 表不是“数据文件一份、索引文件一份”的 MyISAM 模型；InnoDB 表数据本身就是聚簇索引。
2. 页是 InnoDB 的基本 I/O 单位，不是每读一行都直接读磁盘一次。
3. 主键过长会放大所有二级索引，因为二级索引叶子记录要保存主键值。
4. 随机主键会导致页分裂和 Buffer Pool 扰动，趋势递增主键通常更友好。
5. `DYNAMIC` 行格式并不代表所有列都在页外，只有大字段更可能溢出到外部页。
6. Buffer Pool 缓存的是页，索引越宽、页越分散，缓存命中率越容易下降。

## 6. 面试回答模板

InnoDB 逻辑上用 B+ 树组织表和索引，主键索引是聚簇索引，叶子页保存完整行；二级索引叶子页保存二级 key 和主键，查整行可能回表。物理上 InnoDB 按表空间、段、区、页、记录组织数据，默认页大小 16KB，Buffer Pool 缓存的也是页。页里有页头、系统哨兵记录、用户记录、空闲区、页目录和校验信息。行格式常见有 COMPACT、DYNAMIC、COMPRESSED，记录里包含变长字段长度、NULL 位图、记录头、隐藏事务字段和真实列数据。大字段可能放到溢出页，主键设计会影响聚簇索引页分裂和二级索引大小。
