# 按年份分表的跨表查询与 LIMIT 实现

## 1. 问题背景

按年份分表是数据库分表中常见的策略，特别适用于日志表、订单表、交易表等具有明显时间属性的数据。按年份分表后，同一年的数据在同一表中，不同年份在不同表中。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  按年份分表结构示例：                                       │
│                                                             │
│  orders_2025                                               │
│  orders_2026                                               │
│  orders_2027                                               │
│                                                             │
│  查询场景：                                                │
│  SELECT * FROM orders WHERE create_time BETWEEN ...       │
│  LIMIT 20 OFFSET 100                                      │
│                                                             │
│  问题：如何高效地跨表查询并合并 LIMIT 结果？               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 |
|------|------|
| 跨年数据分散 | 查询 25年12月 和 26年1月 需要查两个表 |
| LIMIT 实现困难 | 无法直接对多个表的结果做 LIMIT |
| OFFSET 语义复杂 | OFFSET 100 是跨表共 100 条还是每个表 100 条 |
| 数据分布不均 | 各年份数据量差异大，查询结果难以预估 |

---

## 3. 影响范围

- 日志查询系统（跨年日志搜索）
- 订单系统（跨年订单统计）
- 财务报表（跨年数据汇总）
- 数据归档场景（热数据转冷数据）

## 4. 原因分析

### 4.1 跨表查询的核心问题

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  LIMIT 跨表实现的难点：                                     │
│                                                             │
│  问题 1: 各表独立 LIMIT                                    │
│  SELECT * FROM orders_2025 LIMIT 100                      │
│  SELECT * FROM orders_2026 LIMIT 100                      │
│  合并后可能有 200 条，但我们只想要 100 条                 │
│                                                             │
│  问题 2: OFFSET 处理复杂                                  │
│  LIMIT 100 OFFSET 200                                     │
│  需要跳过 200 条后取 100 条，跨表如何定义"跳过"          │
│                                                             │
│  问题 3: 排序一致性                                       │
│  不同表按时间排序后合并，顺序如何保证                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 典型错误方案

```sql
-- 错误方案 1: 直接 UNION 后 LIMIT
SELECT * FROM orders_2025
UNION ALL
SELECT * FROM orders_2026
LIMIT 100;
-- 问题：不会按全局排序，可能返回错误结果

-- 错误方案 2: 各表 LIMIT 后再 LIMIT
SELECT * FROM (
    SELECT * FROM orders_2025 LIMIT 200
    UNION ALL
    SELECT * FROM orders_2026 LIMIT 200
) t
LIMIT 100;
-- 问题：可能漏掉某些记录，如果 2025 只有 50 条
```

## 5. 解决方案

### 5.1 方案一：应用层归并

```python
class CrossYearQuery:
    """
    应用层归并：查询各表后在应用层合并排序
    """
    
    def __init__(self, db_pool):
        self.db_pool = db_pool
    
    def query_with_limit(self, year_months: list, limit: int, offset: int = 0):
        """
        跨年分页查询
        
        Args:
            year_months: 查询的年月列表，如 ['2025-12', '2026-01']
            limit: 每页数量
            offset: 偏移量
        
        Returns:
            分页结果和总数
        """
        # 1. 并行查询各表
        results = []
        total_count = 0
        
        for year_month in year_months:
            year, month = year_month.split('-')
            table_name = f"orders_{year}"
            
            # 查询该表的数据
            query = f"""
                SELECT * FROM {table_name}
                WHERE YEAR(create_time) = {year}
                  AND MONTH(create_time) = {month}
                ORDER BY create_time DESC
            """
            
            with self.db_pool.connect() as conn:
                rows = conn.execute(query).fetchall()
                results.extend(rows)
                total_count += len(rows)
        
        # 2. 应用层排序和分页
        results.sort(key=lambda x: x.create_time, reverse=True)
        
        # 3. 应用层 LIMIT/OFFSET
        paginated = results[offset:offset + limit]
        
        return {
            'data': paginated,
            'total': total_count,
            'has_more': offset + limit < total_count
        }
```

### 5.2 方案二：游标分页（推荐）

```python
class CursorPagination:
    """
    游标分页：使用时间戳 + ID 作为游标，避免 OFFSET
    """
    
    def query_by_cursor(self, start_time, end_time, limit: int, cursor: dict = None):
        """
        基于游标的分页查询
        
        cursor 格式: {'last_time': timestamp, 'last_id': id}
        """
        query = """
            SELECT * FROM orders
            WHERE create_time >= %s AND create_time < %s
        """
        params = [start_time, end_time]
        
        if cursor:
            # 使用游标继续查询
            query += """
                AND (create_time < %s 
                     OR (create_time = %s AND id < %s))
            """
            params.extend([cursor['last_time'], cursor['last_time'], cursor['last_id']])
        
        query += """
            ORDER BY create_time DESC, id DESC
            LIMIT %s
        """
        params.append(limit + 1)  # 多查一条判断是否有更多
        
        results = self.db.execute(query, params)
        
        # 判断是否有下一页
        has_more = len(results) > limit
        if has_more:
            results = results[:limit]
        
        # 生成下一页游标
        next_cursor = None
        if has_more and results:
            last = results[-1]
            next_cursor = {
                'last_time': last.create_time,
                'last_id': last.id
            }
        
        return {
            'data': results,
            'next_cursor': next_cursor,
            'has_more': has_more
        }
```

### 5.3 方案三：异步并行查询 + 堆排序合并

```python
import heapq
from concurrent.futures import ThreadPoolExecutor
from dataclasses import dataclass
from typing import List

@dataclass
class Order:
    id: int
    create_time: str
    amount: float

class HeapMergeQuery:
    """
    使用堆排序高效合并多个表的查询结果
    """
    
    def __init__(self, db_pools: dict):
        self.db_pools = db_pools  # 每个表一个连接池
    
    def merge_query(self, tables: List[str], limit: int, offset: int = 0):
        """
        并行查询 + 堆排序合并
        
        时间复杂度: O(n log k)，n=总记录数，k=表数量
        """
        # 1. 并行查询每张表，按排序字段获取数据
        def fetch_from_table(table_name):
            query = f"""
                SELECT * FROM {table_name}
                ORDER BY create_time DESC
                LIMIT %s
            """
            # 每张表最多取 limit + offset 条（减少数据传输）
            with self.db_pools[table_name].connect() as conn:
                return conn.execute(query, [limit + offset]).fetchall()
        
        # 2. 并行执行
        with ThreadPoolExecutor(max_workers=len(tables)) as executor:
            futures = {table: executor.submit(fetch_from_table, table) 
                      for table in tables}
            table_results = {table: future.result() 
                            for table, future in futures.items()}
        
        # 3. 使用堆合并排序
        # 堆元素: (create_time, table_index, row_index)
        heap = []
        for i, table in enumerate(tables):
            if table_results[table]:
                row = table_results[table][0]
                heapq.heappush(heap, (-row.create_time.timestamp(), i, 0, row))
        
        merged = []
        while heap and len(merged) < limit + offset:
            neg_time, table_idx, row_idx, row = heapq.heappop(heap)
            
            # 跳过 offset
            if len(merged) >= offset:
                merged.append(row)
            
            # 取下一条
            next_row_idx = row_idx + 1
            if next_row_idx < len(table_results[tables[table_idx]]):
                next_row = table_results[tables[table_idx]][next_row_idx]
                heapq.heappush(heap, (-next_row.create_time.timestamp(), 
                                       table_idx, next_row_idx, next_row))
        
        return merged
```

### 5.4 方案四：时间边界预处理

```python
class TimeRangeQuery:
    """
    时间范围预处理：预计算各表数据分布
    """
    
    def __init__(self, db):
        self.db = db
    
    def query_with_hint(self, start_time, end_time, limit: int, offset: int = 0):
        """
        利用数据分布提示优化查询
        """
        # 1. 查询元数据表获取各表数据量
        meta_query = """
            SELECT table_name, 
                   MIN(create_time) as min_time,
                   MAX(create_time) as max_time,
                   COUNT(*) as row_count
            FROM order_meta
            WHERE time_range OVERLAPS (%s, %s)
            GROUP BY table_name
        """
        
        table_hints = self.db.execute(meta_query, [start_time, end_time]).fetchall()
        
        # 2. 根据偏移量计算需要查询哪些表、查多少条
        # 假设均匀分布，可以精确计算
        total_needed = limit + offset
        results = []
        
        for hint in table_hints:
            table_name = hint['table_name']
            row_count = hint['row_count']
            
            # 计算该表需要查多少条
            # （实际中需要根据时间范围比例计算）
            per_table = int(total_needed * (row_count / hint['total_count']))
            per_table = max(per_table, 10)  # 最少查 10 条
            
            query = f"""
                SELECT * FROM {table_name}
                WHERE create_time >= %s AND create_time < %s
                ORDER BY create_time DESC
                LIMIT %s
            """
            
            rows = self.db.execute(query, [start_time, end_time, per_table]).fetchall()
            results.extend(rows)
        
        # 3. 合并排序取 LIMIT
        results.sort(key=lambda x: x.create_time, reverse=True)
        return results[offset:offset + limit]
```

### 7.2 混合策略

```python
class HybridPagination:
    """
    混合分页策略：
    - 小偏移量：直接使用 OFFSET
    - 大偏移量：自动切换游标分页
    """
    
    THRESHOLD = 1000  # 阈值
    
    def query(self, query: str, page: int, page_size: int):
        offset = (page - 1) * page_size
        
        if offset < self.THRESHOLD:
            # 小偏移量，直接使用 OFFSET
            return self._query_with_offset(query, limit=page_size, offset=offset)
        else:
            # 大偏移量，使用游标
            return self._query_with_cursor(
                query, 
                limit=page_size, 
                cursor=self._page_to_cursor(page)
            )
```

## 9. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 数据倾斜 | 年份间数据量差异大 | 预分区 + 动态调整 |
| 内存溢出 | 大量数据加载到内存 | 流式处理 + 分批获取 |
| 查询超时 | 多表查询耗时长 | 并行查询 + 超时控制 |
| 游标失效 | 数据删除导致游标无效 | 定期清理 + 软删除 |

## 11. 总结

1. **跨表 LIMIT 本质**：多表结果合并后再分页，无法直接 SQL 实现
2. **推荐方案**：游标分页，避免 OFFSET 性能问题
3. **替代方案**：应用层归并（简单场景）、堆排序合并（高性能场景）
4. **优化点**：并行查询、预计算数据分布、流式处理
5. **核心原则**：根据数据量和性能要求选择合适的分页策略，生产环境优先游标分页
