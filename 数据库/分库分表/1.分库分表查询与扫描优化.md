# 1. 分库分表查询与扫描优化

分库分表是把单表或单库的数据按规则拆到多个物理库、物理表中，目的是降低单库单表容量、写入吞吐和索引维护压力。它提升的是整体容量和并发能力，但会让查询路由、分页、聚合、事务和扫描任务变复杂。

## 常见路由方式

1. **哈希分片**：按 `user_id % N`、`order_id % N` 路由，数据分布更均匀，适合点查。
2. **范围分片**：按时间、ID 区间拆分，适合归档和时间范围查询，但容易有热点。
3. **复合分片**：先按时间拆大区，再按用户或订单哈希拆表，兼顾冷热数据和负载均衡。
4. **映射表 / 全局索引**：当查询条件不是分片键时，通过 `order_id -> shard`、`payment_id -> order_id` 等映射表先定位分片。

## 跨库联表查询怎么做

不同 DB 库的表不建议直接依赖数据库层面的跨库 join。它会带来网络放大、锁等待、事务边界不清晰、优化器无法全局选择最优计划等问题。工程上通常先判断查询是否能被改造成“同分片查询”。

1. **按同一个分片键建模**：例如订单表、订单明细表都按 `order_id` 或 `user_id` 分片，让高频 join 落在同一个库或同一个分片内。
2. **先定位再回源**：如果查询条件不是分片键，先查映射表、全局二级索引、搜索引擎或缓存，拿到目标分片和主键后再查真实数据。
3. **应用层 join**：各分片并行查询小结果集，在服务层按主键合并。适合结果集可控的场景，不适合无边界大表 join。
4. **反范式冗余**：把列表页常用字段冗余到主表、宽表或读模型中，减少线上链路 join 次数。
5. **异步同步到查询侧**：通过 binlog、MQ、CDC 把多表数据同步到 ES、ClickHouse、宽表或物化视图，复杂查询走查询侧系统。
6. **离线或报表任务**：跨库大 join、全量统计不要打在线库，应进入离线数仓或只读副本。

面试中可以强调：跨库 join 不是不能做，而是要把它从“数据库即席 join”改成“路由定位、读模型、异步同步、应用层小结果集合并”的组合设计。

## 分库分表下如何扫描订单

订单扫描通常用于超时关单、状态补偿、对账、数据修复等后台任务。直接全库全表扫会造成数据库抖动，正确做法是让扫描任务可分片、可限速、可恢复。

1. **按分片并行扫描**：每个 shard 独立维护扫描进度，例如 `last_id`、`last_create_time`，避免单线程串行扫完整集群。
2. **按条件走索引**：为扫描场景建立组合索引，例如 `(status, expire_time, id)`，扫描 `status='UNPAID' AND expire_time < now()` 的订单。
3. **小批量分页**：使用游标分页，不使用大 offset。

```sql
SELECT id
FROM orders_03
WHERE status = 'UNPAID'
  AND expire_time < NOW()
  AND id > ?
ORDER BY id
LIMIT 500;
```

4. **分布式任务调度**：给每个分片分配 owner，使用租约或任务表防止多个节点重复扫同一个分片。
5. **幂等处理**：扫描出来的订单只做条件更新，例如 `UNPAID -> CLOSED`，重复扫描不会产生副作用。
6. **兜底和限流**：扫描任务要限制 QPS、批大小和单次执行时间，避免抢占线上交易请求资源。

## 如何降低平均查询时间

1. **查询带分片键**：接口设计尽量让核心查询带上 `user_id` 或 `order_id`，避免广播查询。
2. **减少 fan-out**：非分片键查询先查映射表、搜索引擎或聚合表，再回源到具体分片。
3. **并行查询并合并**：必须跨分片查询时，各分片并行执行，再在应用层做 topN、排序和聚合。
4. **冷热分离**：近期订单放在线上库，历史订单归档到冷库或 OLAP，减少热库扫描量。
5. **索引覆盖**：列表页只查必要字段，尽量使用覆盖索引，详情页再按主键回表。
6. **避免深分页**：使用 `search_after`、游标、上一页最后一个排序键继续查。
7. **分片数和连接池匹配**：分片过少会打满单库，分片过多会放大连接、路由和聚合成本。

## LIMIT OFFSET 与深分页优化

`LIMIT offset, size` 的问题是数据库通常仍要沿着索引扫描并丢弃前 `offset` 行，然后再返回 `size` 行。`offset` 越大，扫描和排序成本越高；在分库分表下，如果每个分片都做深分页，再把结果汇总，放大更明显。

更稳妥的做法是游标分页，也叫 seek pagination：

```sql
SELECT id, create_time, amount
FROM orders_03
WHERE user_id = ?
  AND (create_time, id) < (?, ?)
ORDER BY create_time DESC, id DESC
LIMIT 20;
```

设计要点：

1. 排序字段必须稳定，常用 `(create_time, id)`，`id` 用来打破同一时间的并列。
2. 建立匹配排序和过滤条件的联合索引，例如 `(user_id, create_time, id)`。
3. 第一页不带游标，后续页把上一页最后一条记录的排序键传回来。
4. 如果跨分片分页，每个分片维护自己的游标或拉取小批量候选，再在应用层归并 topN。
5. 跳页需求可以限制最大页数，或使用搜索引擎、缓存快照、异步导出，不要让用户任意跳到百万页。

面试回答可以总结为：分库分表后，点查靠路由，非分片键查询靠映射/索引服务减少广播，后台扫描按 shard 并行小批量推进，所有处理都要可重试、可恢复、幂等。
