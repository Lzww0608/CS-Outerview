# 手机号末位分表取模策略分析

## 1. 问题背景

手机号末位分表是一种常见的分表策略，使用手机号最后一位数字（0-9）进行取模，将数据分散到 10 个表中。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  手机号末位分表结构：                                       │
│                                                             │
│  用户手机号: 13812345678                                   │
│  分表键: 手机号末位 = 8                                    │
│  路由到表: user_8                                          │
│                                                             │
│  分表数量: 10 张表 (末位 0-9)                             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 |
|------|------|
| 为什么用手机号 | 不用其他字段作为分表键？ |
| 为什么取模 0-9 | 为什么是 10 个表？ |
| 为什么用末位 | 末位分布均匀吗？ |
| 能否用其他位数 | 用手机号前几位不行吗？ |

- 用户注册和登录（按手机号查询用户）
- 短信验证和营销（按手机号发送短信）
- 用户数据分析（按手机号维度统计）

## 4. 原因分析

### 4.1 为什么选择手机号作为分表键

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  分表键选择原则：                                           │
│                                                             │
│  1. 高频查询字段                                          │
│    • 登录场景：手机号是主要登录方式                        │
│    • 验证场景：短信发送基于手机号                          │
│                                                             │
│  2. 均匀分布                                              │
│    • 手机号本身包含 0-9 的均匀分布                        │
│    • 不会产生热点问题                                     │
│                                                             │
│  3. 固定不变                                              │
│    • 用户 ID 可能变化                                     │
│    • 手机号变更频率低                                     │
│                                                             │
│  4. 唯一性保证                                            │
│    • 手机号天然唯一                                       │
│    • 不需要额外唯一性处理                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 为什么取模 0-9（10 个表）

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  取模 0-9 的原因：                                         │
│                                                             │
│  1. 手机号末位天然支持 0-9                                │
│     • 中国手机号 11 位，末位是数字 0-9                     │
│     • 不需要额外计算，直接取用                              │
│                                                             │
│  2. 分布均匀性                                            │
│     • 手机号末位分布接近均匀（各 10%）                    │
│     • 避免数据倾斜                                        │
│                                                             │
│  3. 简单高效                                              │
│     • 路由计算：phone % 10                                │
│     • 无需复杂的哈希函数                                  │
│                                                             │
│  4. 扩展性考虑                                            │
│     • 10 是人类习惯的数字（十进制）                       │
│     • 便于理解和维护                                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 为什么用末位而不是其他位

```python
# 手机号格式：138 1234 5678

# 分析各位置分布均匀性

phone = "13812345678"

# 方案1：使用末位
last_digit = int(phone[-1])  # 8
# 分布：0-9 各约 10%，均匀 ✓

# 方案2：使用中间位
mid_digit = int(phone[5])  # 第6位
# 分析：中间位可能与号段相关，分布不均 ✗

# 方案3：使用前几位
prefix = int(phone[:3])  # 138
# 问题：只有有限种组合（如 138, 139, 188 等），不均匀 ✗

# 方案4：使用中间 4 位
mid4 = phone[3:7]  # 1234
# 问题：这是运营商分配的号段，分布不均匀 ✗

# 方案5：计算整个号码的哈希
hash_value = hash(phone) % 10
# 可行，但多了一步计算，不够直接 ✓
```

### 4.4 分布均匀性验证

```python
import random

def simulate_distribution():
    """
    模拟手机号末位分布
    假设手机号末位是 0-9 均匀分布
    """
    # 模拟 100 万个手机号
    count = 1_000_000
    samples = [random.randint(0, 9) for _ in range(count)]
    
    # 统计各数字出现次数
    from collections import Counter
    distribution = Counter(samples)
    
    print("手机号末位分布模拟（100万样本）：")
    print("-" * 40)
    for digit in range(10):
        cnt = distribution[digit]
        pct = cnt / count * 100
        bar = "█" * int(pct / 2)
        print(f"  {digit}: {cnt:>7} ({pct:>5.2f}%) {bar}")
    
    # 计算标准差
    percentages = [distribution[d] / count * 100 for d in range(10)]
    import statistics
    std = statistics.stdev(percentages)
    print(f"\n标准差: {std:.2f}%")
    print(f"结论: 分布{'均匀' if std < 1 else '不均匀'}")
```

## 5. 解决方案

### 5.1 分表路由实现

```python
class PhoneSharding:
    """
    手机号末位分表路由
    """
    
    TABLE_COUNT = 10  # 10 张表
    
    @classmethod
    def get_table_name(cls, phone: str) -> str:
        """
        根据手机号获取分表名
        
        Args:
            phone: 手机号字符串
        
        Returns:
            表名，如 user_8
        """
        # 去除空格和非数字
        phone = ''.join(filter(str.isdigit, phone))
        
        # 取末位数字
        last_digit = int(phone[-1])
        
        return f"user_{last_digit}"
    
    @classmethod
    def get_table_index(cls, phone: str) -> int:
        """
        获取表索引 0-9
        """
        phone = ''.join(filter(str.isdigit, phone))
        return int(phone[-1])
    
    @classmethod
    def get_all_tables(cls) -> list:
        """获取所有分表名"""
        return [f"user_{i}" for i in range(cls.TABLE_COUNT)]
```

### 5.2 SQL 路由

```python
class SQLRouter:
    """
    SQL 自动路由：根据手机号自动路由到对应表
    """
    
    def route_sql(self, sql: str, params: dict) -> str:
        """
        路由单表 SQL
        """
        # 提取手机号参数
        phone = params.get('phone')
        if not phone:
            raise ValueError("phone 参数必填")
        
        table_name = PhoneSharding.get_table_name(phone)
        
        # 替换表名
        return sql.replace("{table}", table_name)
    
    def route_batch_sql(self, sql: str, phone_list: list) -> dict:
        """
        路由批量 SQL（查询所有分表）
        """
        results = {}
        
        for phone in phone_list:
            table_name = PhoneSharding.get_table_name(phone)
            
            if table_name not in results:
                results[table_name] = {
                    'sql': sql.replace("{table}", table_name),
                    'phones': []
                }
            
            results[table_name]['phones'].append(phone)
        
        return results
```

### 5.3 分表后查询

```python
class UserQuery:
    """
    分表后查询实现
    """
    
    def __init__(self, db_pool):
        self.db_pool = db_pool
    
    def find_by_phone(self, phone: str):
        """根据手机号查询用户（单表查询）"""
        table_name = PhoneSharding.get_table_name(phone)
        
        sql = f"SELECT * FROM {table_name} WHERE phone = %s"
        return self.db_pool.execute(sql, [phone])
    
    def send_sms_batch(self, phone_list: list, message: str):
        """
        批量发送短信（多表并发查询）
        """
        import concurrent.futures
        
        # 按表分组
        table_phones = {}
        for phone in phone_list:
            table = PhoneSharding.get_table_name(phone)
            table_phones.setdefault(table, []).append(phone)
        
        # 并发查询各表
        def query_table(table, phones):
            sql = f"SELECT * FROM {table} WHERE phone IN %s"
            return self.db_pool.execute(sql, [phones])
        
        with concurrent.futures.ThreadPoolExecutor() as executor:
            futures = {
                executor.submit(query_table, table, phones): table
                for table, phones in table_phones.items()
            }
            
            results = []
            for future in concurrent.futures.as_completed(futures):
                results.extend(future.result())
        
        return results
```

### 7.2 特殊情况处理

```python
class PhoneShardingWithValidation:
    """
    带验证的手机号分表
    """
    
    # 中国手机号正则
    PHONE_PATTERN = r'^1[3-9]\d{9}$'
    
    @classmethod
    def validate_phone(cls, phone: str) -> bool:
        """验证手机号格式"""
        import re
        return bool(re.match(cls.PHONE_PATTERN, phone))
    
    @classmethod
    def get_table_name(cls, phone: str) -> str:
        """带验证的表名获取"""
        if not cls.validate_phone(phone):
            raise ValueError(f"无效手机号: {phone}")
        
        return PhoneSharding.get_table_name(phone)
```

## 10. 验证方式

```python
def verify_sharding_distribution():
    """
    验证分表均匀性
    """
    # 查询各表数据量
    distribution = {}
    total = 0
    
    for i in range(10):
        count = db.execute(f"SELECT COUNT(*) as cnt FROM user_{i}")
        distribution[i] = count
        total += count
    
    # 计算偏离度
    expected = total / 10
    
    print("分表数据分布：")
    print("-" * 40)
    for i, cnt in distribution.items():
        pct = cnt / total * 100
        expected_pct = 10.0
        deviation = abs(pct - expected_pct)
        status = "✓" if deviation < 2 else "⚠"
        
        bar = "█" * int(pct / 2)
        print(f"  user_{i}: {cnt:>7} ({pct:>5.2f}%) {bar} {status}")
    
    # 判断是否均匀
    max_deviation = max(abs(cnt/total*100 - 10) for cnt in distribution.values())
    if max_deviation < 2:
        print("\n✅ 分布均匀")
    else:
        print(f"\n⚠️ 分布不均匀，最大偏离 {max_deviation:.2f}%")
```

## 11. 总结

1. **为什么用手机号**：高频查询字段、分布均匀、固定不变、唯一性保证
2. **为什么取模 0-9**：末位天然 0-9、分布均匀（各 10%）、计算简单、符合十进制习惯
3. **为什么用末位**：分布最均匀，中间位受号段影响，前几位分布不均
4. **核心优势**：无需哈希计算、直接取用、实现简单
5. **潜在风险**：需验证实际分布、考虑手机号变更场景、添加格式校验
