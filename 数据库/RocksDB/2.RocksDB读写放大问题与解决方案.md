# RocksDB 读写放大问题与解决方案

## 1. 问题背景

RocksDB 是基于 LSM Tree 的键值存储引擎，在高并发写入场景下表现优异，但存在读写放大问题，影响存储性能和寿命。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  读写放大问题：                                            │
│                                                             │
│  • 读放大：一次读取需多次磁盘 IO                         │
│  • 写放大：写入 1B 数据实际写入磁盘 > 1B              │
│                                                             │
│  这两个问题直接影响：                                     │
│  • SSD 写入寿命                                          │
│  • 查询延迟                                               │
│  • 存储成本                                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 | 影响 |
|------|------|------|
| 读取延迟高 | 查询需扫描多层 | 用户体验下降 |
| 写入放大 | 写入量远超实际数据 | SSD 磨损加快 |
| 空间放大 | 实际占用远超数据量 | 存储成本上升 |
| Compaction 频繁 | 后台合并操作重 | 系统资源占用高 |

## 4. 原因分析

### 4.1 LSM Tree 结构

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  LSM Tree 层级结构：                                      │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐  │
│  │                   Lmax (如 L7)                      │  │
│  │                   数据量: 10 * base                 │  │
│  ├─────────────────────────────────────────────────────┤  │
│  │                   L6                                │  │
│  │                   数据量: 10 * base                 │  │
│  ├─────────────────────────────────────────────────────┤  │
│  │                   ...                               │  │
│  ├─────────────────────────────────────────────────────┤  │
│  │                   L2                                │  │
│  │                   数据量: 10 * base                 │  │
│  ├─────────────────────────────────────────────────────┤  │
│  │                   L1                                │  │
│  │                   数据量: 1 * base                  │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
│  base = MemTable 大小                                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 读放大原因

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  读放大分析：                                             │
│                                                             │
│  读取流程：                                                │
│  1. 查 MemTable                                          │
│  2. 查 L0（可能有重叠）                                  │
│  3. 查 L1                                                │
│  4. 查 L2 ... Lmax                                       │
│                                                             │
│  最坏情况：N+1 次 IO（N=层级数）                        │
│                                                             │
│  放大倍数 ≈ 层数 × 2（布隆过滤器 + 数据）             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 写放大原因

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  写放大分析：                                             │
│                                                             │
│  触发场景：                                                │
│  1. MemTable 刷盘（1x）                                 │
│  2. L0 → L1 合并（10x）                                 │
│  3. Ln → Ln+1 合并（10x）                               │
│                                                             │
│  总写放大 ≈ 层数 × 合并因子                              │
│                                                             │
│  例如 7 层 LSM Tree：                                     │
│  写放大可达 30-50x                                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 5. 解决方案

### 5.1 读放大优化

| 方法 | 原理 | 效果 |
|------|------|------|
| 布隆过滤器 | 快速判断 Key 不存在 | 减少无效 IO |
| 短连接读 | 直接读取最新数据 | 跳过历史层级 |
| 索引优化 | 分区索引减少扫描 | 定位加速 |
| 缓存 | LRU/ARC 缓存热点 | 减少磁盘 IO |

#### 布隆过滤器实现

```c
// RocksDB 布隆过滤器配置
Options options;

// 每个 SST 文件独立的布隆过滤器
options.prefix_extractor.reset(
    NewBloomFilterPolicy(10, false)  // 10bit/key
);

// 或者使用 ribbon 过滤器（支持删除）
options.filter_policy.reset(
    NewRibbonFilterPolicy(10, false)
);
```

### 5.2 写放大优化

| 方法 | 原理 | 效果 |
|------|------|------|
| 减小层数 | 减少合并路径 | 降低 30-50% |
| Tiered Compaction | 只合并相邻层 | 降低 50%+ |
| 跳过合并 | 不合并大文件 | 降低 70%+ |
| 增量合并 | 分批小量合并 | 平滑 IO |

#### Tiered Compaction 配置

```c
// RocksDB Tiered Compaction 配置
Options options;

// 使用 Tiered Compaction（适合写入密集型）
options.compaction_style = kCompactionStyleTiered;

// 设置 Compaction 选项
TieredCompactionOptions tiered_opts;
tiered_opts.max_num_levels = 7;
tiered_opts.stop_writes_trigger = 32;  // 触发后台合并
tiered_opts.level_multiplier = 10;    // 每层数据量倍数

options.TOPTS.compaction_config = tiered_opts;
```

#### Universal Compaction 配置

```c
// Universal Compaction（减少写放大）
Options options;
options.compaction_style = kCompactionStyleUniversal;

// Universal Compaction 选项
UniversalCompactionOptions universal_opts;
universal_opts.size_ratio = 1;        // 文件大小比例
universal_opts.min_merge_width = 2;    // 最少合并文件数
universal_opts.max_size_amplification_percent = 200;  // 最大空间放大

options.UCOPTS = universal_opts;
```

### 5.3 空间放大优化

```c
// 限制空间放大
Options options;

// 设置最大空间放大（默认 100%）
options.max_bytes_for_level_multiplier = 10;  // 每层最大容量
options.max_bytes_for_level_base = 256 * 1024 * 1024;  // L1 基准

// 开启空间保留（减少压缩期间空间抖动）
options.db_write_buffer_size = 256 * 1024 * 1024;
options.write_buffer_manager.reset(
    new WriteBufferManager(256 * 1024 * 1024)
);
```

## 6. 可选方案对比

| 优化方法 | 读放大 | 写放大 | 空间放大 | 适用场景 |
|----------|--------|--------|----------|----------|
| Level Compaction | 中 | 高 | 低 | 读密集型 |
| Tiered Compaction | 中 | 低 | 高 | 写密集型 |
| Bloom Filter | 降低 | - | - | 全场景 |
| 减小层数 | 降低 | 降低 | - | 全场景 |
| 增量合并 | - | 降低 | - | 全场景 |
| SSD 优化 | - | - | - | 全场景 |

## 7. 推荐方案

### 7.1 场景化推荐

| 场景 | 推荐配置 | 优先级 |
|------|----------|--------|
| 写入密集型 | Tiered Compaction + 减少层数 | 高 |
| 读取密集型 | Level Compaction + Bloom Filter | 高 |
| 空间受限 | Level Compaction + 限制层大小 | 中 |
| 通用场景 | Universal Compaction | 中 |

### 7.2 推荐配置

```c
// 推荐配置模板

Options options;

// 1. Compaction 策略
options.compaction_style = kCompactionStyleUniversal;
options.compaction_style = kCompactionStyleTiered;  // 写入密集

// 2. 布隆过滤器
options.prefix_extractor.reset(
    NewBloomFilterPolicy(10, false)
);

// 3. 缓存
options.block_cache = NewLRUCache(1024 * 1024 * 1024);  // 1GB

// 4. 写缓冲
options.write_buffer_size = 128 * 1024 * 1024;  // 128MB
options.max_write_buffer_number = 3;

// 5. 层配置
options.max_bytes_for_level_multiplier = 10;
options.num_levels = 6;
```

### 8.3 配置调整

```c
// 分阶段调整

// 阶段 1：开启布隆过滤器
options.filter_policy.reset(NewBloomFilterPolicy(10, false));

// 阶段 2：调整 Compaction 策略
options.compaction_style = kCompactionStyleTiered;

// 阶段 3：优化缓存和缓冲
options.block_cache = NewLRUCache(2 * 1024 * 1024 * 1024);
options.write_buffer_size = 256 * 1024 * 1024;

// 阶段 4：减少层数
options.num_levels = 5;
```

## 9. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Compaction 策略变更 | 空间放大增加 | 预留足够空间 |
| 布隆过滤器内存 | 内存占用增加 | 合理配置大小 |
| 减少层数 | 读放大可能增加 | 配合缓存使用 |
| Tiered 空间放大 | 存储占用高 | 监控空间使用 |

## 10. 验证方式

```python
# 读写放大测试

def test_rw_amplification():
    """测试读写放大"""
    
    # 写入测试
    write_size = 10 * 1024 * 1024  # 10MB
    actual_write = measure_actual_disk_write()
    
    write_amp = actual_write / write_size
    print(f"Write Amplification: {write_amp:.2f}x")
    
    # 读取测试
    read_count = 10000
    io_count = measure_disk_reads()
    
    read_amp = io_count / read_count
    print(f"Read Amplification: {read_amp:.2f}x")
    
    # 空间测试
    data_size = measure_data_size()
    disk_usage = measure_disk_usage()
    
    space_amp = disk_usage / data_size
    print(f"Space Amplification: {space_amp:.2f}x")


def benchmark_compaction():
    """测试不同 Compaction 策略"""
    
    strategies = [
        'level',
        'universal',
        'tiered'
    ]
    
    results = {}
    
    for strategy in strategies:
        options = rocksdb.Options()
        
        if strategy == 'level':
            options.compaction_style = rocksdb.kCompactionStyleLevel
        elif strategy == 'universal':
            options.compaction_style = rocksdb.kCompactionStyleUniversal
        else:
            options.compaction_style = rocksdb.kCompactionStyleTiered
        
        # 运行基准测试
        results[strategy] = run_benchmark(options)
    
    return results
```

## 11. 总结

1. **读放大原因**：LSM Tree 多层查询 + 无布隆过滤器
2. **写放大原因**：Compaction 合并重写数据
3. **核心优化**：布隆过滤器、Tiered Compaction、减少层数
4. **场景选择**：写入密集用 Tiered，读取密集用 Level + Bloom
5. **实践建议**：分阶段调整，充分测试验证
