# 2. 分区、分片、副本与分片键

## 1. 分区和分片的区别

ClickHouse 中分区和分片是两个层面的概念。

| 概念 | 作用范围 | 主要目的 | 常见键 |
| --- | --- | --- | --- |
| 分区 Partition | 单张本地表内部 | 数据裁剪、生命周期管理、减少扫描 | 日期、月份、业务周期 |
| 分片 Shard | 集群多个节点之间 | 水平扩容、分摊存储和计算 | 用户 ID hash、设备 ID hash、租户 ID |
| 副本 Replica | 同一个 shard 内多份数据 | 高可用、容灾、读扩展 | 不需要业务键 |

一句话：分区解决一张表内部怎么组织数据，分片解决数据怎么分布到多台机器，副本解决同一份数据有几份。

## 2. 分区 Partition

分区通过 `PARTITION BY` 指定，日志和时序数据最常见的是按天或按月：

```sql
PARTITION BY toYYYYMMDD(event_time)
```

分区的作用：

1. 查询时按分区裁剪，减少扫描范围。
2. 删除历史数据时可以按分区快速 drop。
3. TTL 和冷热分层更容易管理。
4. 降低单个 part 管理成本。

分区不要太细。按小时甚至分钟分区可能造成分区和 part 数量爆炸，影响 merge 和元数据管理。

## 3. 分片 Shard

分片是把数据水平拆到多个节点。对外通常通过 `Distributed` 表写入和查询，ClickHouse 根据 sharding key 决定数据写到哪个 shard。

分片的作用：

1. 扩展存储容量。
2. 扩展写入吞吐。
3. 扩展查询计算能力。
4. 降低单机热点和磁盘压力。

如果只有分区没有分片，数据仍然在单机或单 shard 上，无法解决集群水平扩展问题。

## 4. 副本 Replica

副本是同一个 shard 的多份相同数据，通常用 `ReplicatedMergeTree` 实现。

副本数量选择：

1. **1 副本**：成本低，但节点故障会影响可用性和数据安全。
2. **2 副本**：生产常见平衡，能容忍一台副本故障。
3. **3 副本**：可用性更高，适合核心数据，但存储和复制成本更高。

ClickHouse 多副本的主要作用：

1. 高可用：一个 replica 故障，另一个 replica 继续服务。
2. 数据冗余：降低磁盘或节点故障风险。
3. 读扩展：查询可在多个 replica 之间负载均衡。
4. 运维友好：滚动升级、重启、迁移时降低影响。

## 5. 分片键怎么选

分片键会影响数据分布、查询效率和热点风险。

好的分片键通常满足：

1. **高基数**：可选值足够多，例如 `user_id`、`device_id`、`trace_id`。
2. **分布均匀**：hash 后各 shard 数据量接近。
3. **稳定不变**：写入后不会修改。
4. **贴合查询**：高频查询能命中单个或少量 shard。
5. **避免热点**：不能让某个大客户、某个时间段集中打到一个 shard。

日志场景常见设计：

```sql
PARTITION BY toYYYYMMDD(event_time)
ORDER BY (app_id, event_time, user_id)
SHARD BY cityHash64(user_id)
```

如果经常按 `trace_id` 查全链路日志，也可以考虑：

```sql
SHARD BY cityHash64(trace_id)
```

这样同一个 trace 的日志更可能落到同一个 shard，查询时减少跨 shard 聚合。

## 6. 不推荐的分片键

1. **只按时间分片**：新数据集中写入当前时间分片，容易形成热点。
2. **低基数字段**：例如 `level`、`status`，会导致数据倾斜。
3. **随机数**：写入均匀，但按用户或 trace 查询时必须广播所有 shard。
4. **频繁变更字段**：ClickHouse 更适合追加写，分片键不应依赖可变状态。

## 7. 分区、排序键和分片键的配合

三者职责不同：

1. `PARTITION BY` 用于按时间或业务周期裁剪和管理数据。
2. `ORDER BY` 决定本地表内数据排序和稀疏索引效率。
3. sharding key 决定数据落到哪个 shard。

不要把它们混为一谈。比如日志表常按天分区，按 `(app_id, event_time, trace_id)` 排序，按 `cityHash64(trace_id)` 或 `cityHash64(user_id)` 分片。

## 8. 面试回答模板

ClickHouse 里分区是本地表内部的数据组织方式，常按日期分区，主要用于查询裁剪和历史数据 TTL；分片是集群级别把数据拆到多台机器，主要用于水平扩展；副本是在同一个 shard 内保存多份数据，主要用于高可用和读扩展。分片键要选高基数、分布均匀、稳定且贴合查询的字段，日志场景可以按 `user_id`、`device_id` 或 `trace_id` hash 分片，避免只按时间分片导致热点。
