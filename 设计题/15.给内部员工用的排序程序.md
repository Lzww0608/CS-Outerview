# 15. 给内部员工用的排序程序

## 1. 题目理解

“设计一个给字节内部员工用的排序程序”不能只回答快排、归并排序。更合理的理解是：做一个内部工具，让员工上传或选择一份数据，按指定字段、类型、顺序和规则进行排序，并输出可下载结果。

需要先澄清：

1. 数据规模：几 MB、几 GB，还是 TB 级。
2. 数据格式：CSV、JSONL、Excel、日志、数据库表。
3. 排序规则：单字段、多字段、升降序、空值规则、字符串自然排序。
4. 使用形态：命令行、Web 页面、平台任务。
5. 是否需要权限、审计、脱敏和结果留存。

## 2. 功能设计

核心功能：

1. 数据导入：上传文件、选择 HDFS/对象存储路径、选择数据库查询结果。
2. Schema 识别：识别列名、类型、分隔符、编码、时间格式。
3. 排序配置：选择排序字段、升降序、稳定排序、空值优先/末尾。
4. 任务执行：小文件内存排序，大文件外部排序。
5. 结果输出：生成新文件，保留原始文件，支持下载或写回存储。
6. 任务管理：进度、取消、重试、失败原因、历史记录。

## 3. 小数据排序

小数据可以直接内存排序：

```text
读取数据 -> 解析成 Record -> 构造 Comparator -> stable_sort -> 输出
```

比较器要支持多字段：

```text
ORDER BY dept ASC, level DESC, join_time ASC
```

比较过程：

1. 先比较 `dept`。
2. 相同再比较 `level`。
3. 相同再比较 `join_time`。
4. 全部相同则保持原顺序，保证稳定性。

## 4. 大数据外部排序

如果数据无法全部放入内存，用外部归并排序：

1. 按固定内存预算读取一批数据。
2. 在内存中排序，写成有序临时分片。
3. 重复直到所有输入都处理完。
4. 对多个有序分片做 k 路归并。
5. 输出最终有序文件。
6. 删除临时文件。

```text
大文件 -> chunk1 sort -> run1
     -> chunk2 sort -> run2
     -> chunk3 sort -> run3
run1/run2/run3 -> k-way merge -> result
```

工程优化：

1. 分片大小按内存水位动态调整。
2. 临时文件压缩，降低磁盘占用。
3. k 路归并使用最小堆。
4. 对象存储读写使用分片上传。
5. 超大任务交给 Spark/Flink/MapReduce。

## 5. 架构设计

```text
Web/CLI
  -> API Server
  -> Job Queue
  -> Sort Worker
  -> Object Storage / HDFS / DB
  -> Metadata DB
```

组件职责：

1. **API Server**：鉴权、参数校验、创建排序任务。
2. **Job Queue**：削峰和异步执行，例如 Kafka、Redis Stream、内部任务队列。
3. **Sort Worker**：执行内存排序或外部排序。
4. **Metadata DB**：保存任务状态、输入输出路径、排序配置、错误信息。
5. **Storage**：保存原始文件、临时分片和结果文件。

## 6. 安全和内部工具要求

内部员工工具也要考虑安全：

1. SSO 登录，按部门和数据等级授权。
2. 输入文件大小、行数、字段数限制。
3. 敏感字段识别和脱敏预览。
4. 操作审计：谁在什么时候排序了什么数据。
5. 结果文件设置过期时间，避免长期留存敏感数据。
6. worker 使用沙箱和资源配额，防止单任务打爆机器。

## 7. 易错点

1. 不要只说“用快排”，内部工具的关键是数据规模、稳定性、输入输出、权限和失败恢复。
2. 字符串排序要明确字典序、自然排序、大小写和 locale。
3. 时间字段要统一时区和格式，否则排序结果可能错误。
4. 浮点数和空值比较要有清晰规则。
5. 大文件排序要避免全量加载内存。

## 8. 面试回答模板

我会先把它当成内部数据排序平台设计。小文件直接解析后用稳定排序，多字段比较器支持升降序、类型转换和空值规则；大文件使用外部归并排序，先分块内存排序写临时 run，再用最小堆做 k 路归并。架构上用 Web/CLI 提交任务，API Server 做鉴权和参数校验，任务队列异步派发给 Sort Worker，结果写对象存储，元数据记录任务状态。内部员工工具还要考虑 SSO、权限、审计、敏感数据脱敏、资源配额和结果过期。
