# Cache Locality（缓存局部性）

## 定义与作用
缓存局部性是指程序访问内存时呈现的时间和空间集中特性，利用这一特性可以让 CPU 缓存（L1/L2/L3）有效工作，解决 CPU 与内存之间 100 倍以上的速度差距问题。

## 核心原理
- **时间局部性**：刚刚访问过的数据在短时间内很可能再次被访问，因此将其保留在缓存中
- **空间局部性**：访问某个地址时，其相邻地址也很可能很快被访问，因此缓存以 64 字节 Cache Line 为单位整块加载
- CPU 缓存采用分层设计，容量越小速度越快：L1（32KB，~1ns）< L2（256KB，~4ns）< L3（MB 级，~15ns）< 主存（~100ns）

## 软硬件协同点
1. **硬件预取器**：CPU 内置的 Stride Prefetcher 检测连续内存访问模式，自动预加载后续 Cache Line 到缓存；软件需配合按顺序访问内存
2. **缓存替换策略**：硬件采用 LRU（最近最少使用）或其近似算法管理缓存淘汰，软件通过循环交换（Loop Interchange）、循环分块（Loop Tiling）等变换提高缓存命中率
3. **编译器优化**：GCC 的 `-floop-interchange`、`-floop-block` 等选项自动调整数据访问模式以适配缓存层次结构
4. **硬件缓存一致性协议**：MESI 协议保证多核间缓存一致性，但同时带来总线流量开销，软件需通过数据结构设计减少跨核缓存共享

## 典型应用场景
1. **矩阵乘法优化**：OpenBLAS 通过 64x64 分块将矩阵乘法的缓存命中率从 5% 提升到 95%，性能提升 10 倍以上
2. **数据库索引结构**：B+ 树节点大小设计为 4KB（正好填满多个 Cache Line），叶子节点连续存储，确保范围查询时空间局部性最大化
