## 1. 🧭 核心定位与价值
- **一句话本质**：通过精心安排数据的访问顺序和存储布局，让 CPU 缓存（L1/L2/L3）成为数据供给的主力通道，将内存访问延迟从 ~100ns 压缩到 ~1ns，释放数量级性能潜力。
- **软硬件协同点**：硬件提供分层缓存结构和自动预取器，但它只能基于"过去的访问模式"推测未来。软件的职责是**让访问模式变得可预测**——顺序访问、分块访问、紧凑布局——让硬件预取器和缓存替换策略发挥最大效用。缓存优化是"软件引导硬件"的经典范式。

## 2. 🌳 前置知识树 (Prerequisites)
- **CPU 缓存层次结构**：理解 L1 指令/数据缓存分离、L2 私有缓存、L3 共享缓存的容量、延迟、带宽差异，以及 Cache Line（64 字节）的概念。
- **内存对齐与结构体布局**：数据如何在内存中排列直接影响每次 Cache Line 加载能带回多少有效数据，结构体填充（Padding）是空间局部性的敌人。
- **渐近分析与算法复杂度**：缓存友好的算法往往有相同的时间复杂度但常数项小一个数量级，需要理解"墙钟时间"而非仅理论复杂度。

## 3. 🗺️ 进阶学习路径 (Learning Path)

### 阶段一：机制理解 (What & How)
1. **两种局部性的物理意义**
   - **时间局部性**：同一个数据被反复访问，第一次加载到缓存后，后续访问直接命中。优化手段：循环不变量外提、寄存器变量、数据复用。
   - **空间局部性**：访问了地址 A 后很快访问 A 附近的地址，硬件以 64 字节 Cache Line 为单位整块加载，一次加载供多次使用。优化手段：数据结构紧凑化、按存储顺序遍历。
   - 直觉校验：C 语言二维数组 `a[i][j]`，按行优先遍历（i 在外层）比列优先（j 在外层）在大矩阵下可达 **50~100 倍**性能差异。

2. **缓存工作的三个核心参数**
   - **容量 (Capacity)**：每层缓存能存多少数据。L1d 通常 32KB，L2 256KB~1MB，L3 几 MB 到几十 MB。
   - **相联度 (Associativity)**：N 路组相联 = 一个内存地址可以映射到 N 个 Cache Line 位置。全相联灵活但慢，直接映射快但冲突多。现代 CPU 通常 L1 为 8 路、L2 为 16 路。
   - **替换策略**：当缓存满了淘汰谁。实际是 Pseudo-LRU 或 Tree-PLRU，不是真 LRU。理解这一点有助于解释某些"反直觉"的性能波动。

3. **硬件预取器：CPU 的自动导航**
   - **Stride Prefetcher（步长预取）**：检测到等步长访问模式后自动预加载后续 Cache Line。对顺序数组遍历非常有效。
   - **Next Line Prefetcher**：简单粗暴，访问了第 N 行就预取 N+1 行。
   - **Streamer Prefetcher**：更复杂的流检测，支持多个并发流。
   - 软件视角：**只要你顺序访问，硬件会帮你预取**。如果你随机访问，预取器完全无能为力——这就是随机 I/O 比顺序慢 100 倍的硬件根源。

### 阶段二：性能剖析 (Why Fast)
1. **Cache Miss 的三种类型（3C 模型）**
   - **Cold Miss（冷启动失效）**：第一次访问，数据从未加载过。不可避免，但可以通过预取减少。
   - **Capacity Miss（容量失效）**：工作集大于缓存容量，数据被挤出去了。解决方案：缩小工作集（数据压缩、精简结构）或分块（Tiling）。
   - **Conflict Miss（冲突失效）**：工作集小于缓存，但多个数据映射到同一组（Set），互相挤兑。N 路组相联只能容纳 N 个同组地址。极端情况下，即使缓存只用了 1% 也会频繁失效。
   - 诊断方法：改变数据大小但保持访问模式，Miss 率突然跳变则是 Capacity，呈周期性波动则是 Conflict。

2. **循环变换：算法层面的缓存优化武器库**
   - **Loop Interchange（循环交换）**：交换内外层循环顺序，将列优先改为行优先。最简单也最有效，编译器在 -O3 下会自动尝试。
   - **Loop Tiling / Blocking（循环分块）**：将大矩阵切成小块，让每个小块能放进 L2 缓存。矩阵乘法经典优化：从 ijk 三重循环的 O(N^3) 次内存访问降到 O(N^3/√B) 次。
   - **Loop Fusion（循环合并）**：将两个遍历同一数组的循环合并，减少一次完整的数组加载，提升时间局部性。
   - **Loop Fission / Distribution（循环分裂）**：将一个做太多事的循环拆开，让每个子循环的工作集更小，提高缓存命中率。

3. **Roofline Model：定位性能瓶颈的北斗七星**
   - 计算强度 (Arithmetic Intensity) = 浮点运算次数 / 字节访问数（FLOP/Byte）。
   - Roofline 图：纵轴是性能（FLOPS），横轴是计算强度。两条天花板线：内存带宽墙（斜率 = 内存带宽）和计算峰值墙（水平线）。
   - 你的程序落在哪个区域？在带宽墙左侧是内存 bound，优化方向是减少内存访问；在计算墙右侧是计算 bound，优化方向是减少运算量或使用更多 SIMD。
   - 缓存优化的核心目标：把程序从"带宽墙左侧"推到"计算墙右侧"，让 CPU 不再饿死在数据供给上。

### 阶段三：局限与妥协 (Trade-offs)
1. **缓存优化的代码可读性代价**
   - 分块后的循环从 3 层变成 6 层，代码复杂度显著上升。
   - 分块大小是平台相关的：针对 L2=256KB 调优的参数，在 L2=1MB 的 CPU 上可能不是最优。
   - 经验法则：分块大小取缓存容量的 70~80%，留出余量给其他变量和预取。

2. **时间局部性与空间局部性的权衡**
   - 有时候为了时间局部性需要牺牲空间局部性，反之亦然。
   - 例如：行优先存储的矩阵做转置运算，无论怎么安排访问顺序，总有一方是列优先的。解决方案：使用分块转置——每个块内部虽然还是有一次列访问，但块的大小远小于缓存容量，冲突被限制在块内。

3. **多核共享缓存的争抢问题**
   - L3 缓存是所有核心共享的。多线程程序如果每个线程的工作集都很大，会互相挤占 L3，导致每个线程的有效缓存容量下降。
   - 这就是为什么某些程序在多核下的加速比低于线性——不是计算瓶颈，而是缓存争抢。
   - 诊断工具：`perf stat -e LLC-loads,LLC-load-misses` 观察 Last Level Cache 命中率。

## 4. 🛠️ 实验与调试指南 (Hands-on & Profiling)

### 观测工具
- **`perf stat -e cache-references,cache-misses,LLC-load-misses`**：快速评估整体缓存命中率和末级缓存失效情况。
- **`perf c2c`**：Linux 4.10+ 引入的专用工具，专门分析缓存到缓存的访问和伪共享，输出详细的 Cache Line 级别的热点分析。
- **Valgrind / Cachegrind**：通过模拟 CPU 缓存来精确统计每个函数、每行代码的缓存命中/失效数，无需硬件支持但运行慢 10~100 倍。
- **`likwid-topology` / `likwid-bench`**：LIKWID 工具套件，精确测量各级缓存的实际带宽和延迟，验证理论值。

### 关键指标
| 指标 | 含义 | 理想值 |
|------|------|--------|
| **L1d 命中率** | L1 数据缓存命中比例 | > 95% 为优秀 |
| **LLC Miss 率** | 末级缓存失效比例 | < 5% 为良好 |
| **每字节计算量** | FLOP / Byte | 越高越偏向计算密集 |
| **IPC（每周期指令数）** | CPU 流水线利用率 | 内存 bound 时通常 < 1.0 |

### 实操练习
1. 写一个 4096x4096 的二维数组遍历，分别用行优先和列优先两种方式求和，用 `perf stat` 对比 cache-misses 和运行时间，计算加速比。
2. 实现矩阵乘法的三个版本：朴素版、循环交换版、分块版（64x64 分块）。用 `perf stat -e LLC-load-misses` 验证末级缓存失效数的下降。
3. 使用 Cachegrind 分析你项目中的一个热点函数，查看是哪些代码行导致了最多的缓存失效，思考优化方向。

## 5. 📚 推荐阅读与扩展 (Resources)

### 源码级指引
- **OpenBLAS `kernel/x86_64/` 目录**：查看 `sgemm_kernel_*.S` 等汇编内核，学习工业级矩阵乘法如何做极致的寄存器分块和缓存分块优化。单精度 4x16 内核用满 AVX2 向量寄存器。
- **Linux 内核 `mm/` 目录**：`page_alloc.c` 中的伙伴系统、`slab.c` 中的 Slab 分配器，都是为了提高缓存局部性而设计的内存管理机制。
- **RocksDB `table/block_based/` 目录**：BlockBasedTable 的设计——数据按 4KB Block 组织、Block 内前缀编码、Bloom Filter——全部都是围绕"减少磁盘 I/O + 提高缓存命中"展开的。

### 关联技术
- **预取（Prefetching）**：软件预取（`__builtin_prefetch`）与硬件预取的配合与取舍，是缓存局部性优化的进阶话题。
- **Cache-Oblivious Algorithm（缓存遗忘算法）**：不需要知道缓存大小也能在任意缓存层次上高效运行的算法设计，代表了缓存优化的理论巅峰。
