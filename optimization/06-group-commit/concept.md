# Group Commit（组提交）

## 定义与作用
组提交是数据库和存储系统中将多个并发事务的持久化操作合并执行的技术，解决高并发下 fsync 调用次数过多导致的磁盘 IO 瓶颈问题。

## 核心原理
- 事务提交必须保证 WAL（Write-Ahead Log）持久化到磁盘，而 fsync 是昂贵操作（HDD ~10ms，SSD ~0.1ms）
- 当多个事务并发提交时，让第一个事务执行 fsync，其他事务等待；第一个完成后，所有等待的事务都已间接持久化，无需各自 fsync
- 本质是用少量延迟换取吞吐率的大幅提升，一个 fsync 服务 N 个事务，每个事务的平均 fsync 开销降为 1/N

## 软硬件协同点
1. **磁盘 IOPS 硬限制**：HDD 随机写 IOPS 约 100-200，不使用组提交的数据库 TPS 上限就是 200；组提交后 TPS 可达到数万
2. **操作系统缓冲区合并**：多个事务的 WAL 记录在 Page Cache 中连续存放，一次 fsync 触发的是大块顺序写，充分利用磁盘带宽
3. **NVMe 多队列配合**：现代 SSD 支持多个提交队列，组提交的批量请求可分发到不同队列并行处理，硬件并行度进一步提升
4. **中断合并（Interrupt Coalescing）**：磁盘控制器可配置中断合并，等待多个 IO 完成后触发一次中断，与组提交的批量思想形成双层加速

## 典型应用场景
1. **MySQL InnoDB 组提交**：MySQL 5.6 引入三阶段组提交（Flush 阶段、Sync 阶段、Commit 阶段），支持上千并发连接下单机 TPS 从 200 提升到 50000
2. **RocksDB WAL 组提交**：RocksDB 的 Manifest Writer 使用条件变量实现写操作分组，一次 fsync 完成所有等待线程的 WAL 持久化
