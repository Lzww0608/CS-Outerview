# mmap（内存映射）

## 定义与作用
mmap 将文件或设备直接映射到进程虚拟地址空间，通过内存读写完成文件操作，消除系统调用开销和数据拷贝，解决随机访问大文件时传统 IO 性能低下问题。

## 核心原理
- mmap 建立进程虚拟地址到文件物理页的映射，实际数据加载由缺页异常（Page Fault）按需触发
- 访问映射内存时，CPU MMU 自动完成地址翻译，数据直接在 Page Cache 中操作，无需 read/write 系统调用
- 写回由内核 pdflush 线程异步完成，也可通过 msync 主动触发同步

## 软硬件协同点
1. **MMU 地址翻译硬件**：CPU 的内存管理单元（MMU）自动完成虚拟地址到物理地址的翻译，TLB（Translation Lookaside Buffer）缓存翻译结果，降低地址转换开销
2. **Page Cache 直接访问**：mmap 直接操作内核 Page Cache，数据在用户态和内核态共享同一份物理内存，避免了 read/write 的两次拷贝
3. **缺页异常硬件触发**：访问未加载的页面时，CPU 触发 Page Fault 异常，内核中断处理程序负责从磁盘加载页面并更新页表，整个过程对应用透明
4. **脏页标记硬件支持**：x86 页表项中的 Dirty 位由硬件自动设置，内核扫描脏页时无需软件跟踪，msync 时仅回写真正修改过的页面

## 典型应用场景
1. **数据库存储引擎**：MongoDB WiredTiger 使用 mmap 管理整个数据集，随机访问延迟比 pread 降低 30%，且代码复杂度显著降低
2. **共享内存 IPC**：父子进程通过 mmap MAP_SHARED 建立共享内存区域，配合 futex 实现高性能进程间通信，吞吐量比 socket 高 10 倍
