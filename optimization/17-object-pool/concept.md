# Object Pool（对象池）

## 定义与作用
对象池预先分配并复用一组对象，避免频繁的内存分配/释放和构造/析构开销，解决高并发场景下内存分配器锁竞争和碎片化问题。

## 核心原理
- 初始化时创建 N 个对象放入空闲链表，请求对象时从链表取，释放时放回链表
- 避免了每次创建对象的 malloc/mmap 系统调用（~1us）和构造函数开销
- 消除了频繁小内存分配导致的内存碎片化，长时间运行的程序性能稳定
- 对于多线程场景，每个线程有独立的线程局部对象池（TLS Pool），完全无锁

## 软硬件协同点
1. **缓存预热与局部性**：对象池内的对象在内存中连续存储，访问时空间局部性好，Cache Line 命中率高；预热阶段将所有对象访问一遍，提前加载到缓存
2. **TLB 命中优化**：对象池使用连续的大内存块（或巨页分配），减少地址翻译的 TLB Miss 次数，内存访问延迟降低 20-30%
3. **分配器锁竞争规避**：默认 malloc 是线程安全的，内部有全局锁；高并发下锁竞争导致性能随线程数增加反而下降；线程局部对象池完全无锁
4. **硬件预取配合**：对象池内连续排列的对象可被 CPU 硬件预取器识别，提前加载到缓存，消除 Cache Miss 的等待时间

## 典型应用场景
1. **游戏服务器实体管理**：Unity/Unreal 游戏服务器使用对象池管理游戏对象（怪物、子弹、特效），对象创建/销毁延迟从 ms 级降到 us 级，GC 停顿完全消除
2. **数据库连接池**：C3P0/HikariCP 等连接池预创建数据库连接，避免每次请求建立 TCP 连接的三次握手和认证开销，Web 请求响应时间降低 50%
