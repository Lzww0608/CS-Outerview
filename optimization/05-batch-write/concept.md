# Batch Write（批量写入）

## 定义与作用
批量写入是将多次小的写操作合并成一次大的写操作，减少系统调用次数和 I/O 开销，解决随机写导致的存储设备性能低下问题。

## 核心原理
- 每次写操作都有固定开销：系统调用上下文切换（~1us）、文件系统元数据更新、存储设备寻址开销
- 将 N 次小写入合并成一次，固定开销被分摊到 N 个数据上，有效吞吐率近似线性提升
- 对于 HDD，顺序写比随机写快 100 倍以上；对于 SSD，批量写可减少擦写次数和 Write Amplification

## 软硬件协同点
1. **系统调用批量化**：通过 writev() 单次调用写入多个缓冲区，减少用户态到内核态的切换次数，上下文切换开销从 N 次降为 1 次
2. **存储设备队列深度**：SSD 内部有多个并行处理单元（NAND 通道），通过 NCQ（Native Command Queuing）一次提交多个写请求，硬件并行度可提升 4-8 倍
3. **文件系统块对齐**：批量写入数据大小需对齐到文件系统块大小（通常 4KB），避免 Read-Modify-Write 循环；硬件扇区大小（传统 512B，现代 4KB）也需考虑
4. **Page Cache 回写机制**：内核的 pdflush 线程自动将脏页按 LBA 地址排序后批量写入磁盘，应用通过 `sync_file_range()` 可精细控制回写时机和批次大小

## 典型应用场景
1. **消息队列持久化**：Kafka 将多个生产者的消息先写入内存缓冲区，积累到 16KB 或 1ms 超时后批量刷盘，单机写入吞吐从 1 万条/s 提升到 100 万条/s
2. **数据库 WAL 写入**：PostgreSQL 将多个事务的 WAL 记录累积到 WAL Buffer 中，按 8KB 块大小批量写入 WAL 文件，事务提交延迟从 ms 级降到 us 级
