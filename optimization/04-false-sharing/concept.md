# False Sharing（伪共享）

## 定义与作用
伪共享是多核系统中多个独立变量恰好位于同一 64 字节 Cache Line 内，导致一个核写操作使其他核的缓存失效，引发"缓存一致性风暴"，严重降低多线程性能。

## 核心原理
- CPU 缓存以 64 字节 Cache Line 为管理单位，缓存一致性协议（MESI）以 Cache Line 为粒度跟踪状态
- 当某个核修改 Cache Line 内的任意字节时，该 Cache Line 在其他所有核的副本都会被标记为 Invalid
- 其他核再次访问该 Cache Line 时，必须从 L3 或主存重新加载，耗时是缓存命中的 10-100 倍
- 问题的核心：多个线程读写**不同**变量，但这些变量**物理上相邻**，导致不必要的缓存失效

## 软硬件协同点
1. **MESI 协议硬约束**：硬件无法区分同一 Cache Line 内不同字段的访问独立性，必须由软件通过数据布局设计避免
2. **缓存对齐填充**：在频繁写的变量之间插入 64 字节填充（Padding），确保每个变量独占一个 Cache Line，使用 `__attribute__((aligned(64)))` 或 C++ `hardware_destructive_interference_size`
3. **编译器重排风险**：编译器可能优化掉看似无用的填充字节，需使用 `volatile` 或特殊编译属性防止优化
4. **硬件性能计数器**：通过 perf 的 `cache-misses`、`cache-references` 等事件量化伪共享的影响，定位热点 Cache Line

## 典型应用场景
1. **无锁队列计数器隔离**：Disruptor 框架为生产者/消费者序列计数器各自添加 7*8=56 字节填充，确保与其他变量不在同一 Cache Line，吞吐量提升 5 倍以上
2. **多线程统计计数器**：Linux 内核的 per-CPU 计数器，每个 CPU 核维护自己的计数变量，只有汇总时才跨核访问，彻底消除伪共享
