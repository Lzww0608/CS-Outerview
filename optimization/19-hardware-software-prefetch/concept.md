# Hardware Prefetch / Software Prefetch（硬件/软件预取）

## 定义与作用
硬件/软件预取是在数据真正被访问前，提前将其从内存加载到 CPU 缓存的技术，消除 Cache Miss 带来的 100ns 以上等待时间，解决计算密集型程序中内存带宽成为瓶颈的问题。

## 核心原理
- **硬件预取**：CPU 内置的预取器（如 Stride Prefetcher、Stream Prefetcher）检测连续内存访问模式，自动提前加载下一个 Cache Line
- **软件预取**：程序员通过 `_mm_prefetch` 等内建函数显式告诉 CPU 哪些数据很快会被访问，由编译器插入 PREFETCH 指令
- 预取的关键是"提前量"：太早预取会导致数据被淘汰，太晚则无法掩盖延迟，理想提前量是 100-200 个时钟周期
- 预取不阻塞 CPU 执行，只是向内存控制器发出请求，数据到达后自动放入缓存

## 软硬件协同点
1. **硬件预取器阈值**：x86 可通过 MSR（Model Specific Register）配置预取器的触发阈值和预取距离；针对内存密集型应用可调大预取距离
2. **软件预取指令编码**：PREFETCH 指令有不同级别（T0/T1/T2/NTA），对应放入 L1/L2/L3 缓存或非临时提示，编译器根据数据重用距离选择合适级别
3. **编译器自动插入**：GCC 的 `-fprefetch-loop-arrays` 选项在循环中自动插入预取指令，通常能带来 10-30% 的性能提升
4. **硬件预取与软件预取协同**：硬件处理简单的连续访问模式，软件处理复杂的非连续访问（如链表遍历、矩阵分块），两者配合可达到 90% 以上的缓存命中率

## 典型应用场景
1. **矩阵乘法优化**：OpenBLAS 在分块矩阵乘法中，提前一个循环迭代预取下一个子矩阵的数据，计算与内存访问完全重叠，单核心浮点利用率从 40% 提升到 90%
2. **数据库索引遍历**：LevelDB 遍历跳表（Skip List）时，预取当前节点的下两层指针，将随机访问的 Cache Miss 延迟掩盖在计算中，遍历速度提升 40%
