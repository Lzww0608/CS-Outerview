# Zero-Copy（零拷贝）

## 定义与作用
零拷贝是避免数据在内核缓冲区与用户缓冲区之间不必要拷贝的技术，将文件传输的 CPU 开销降低 70% 以上，解决传统 IO 路径中数据多次拷贝的性能瓶颈。

## 核心原理
- 传统 read + write 路径：磁盘 → 内核 Page Cache → 用户缓冲区 → 内核 Socket 缓冲区 → 网卡，共 4 次数据拷贝和 4 次上下文切换
- 零拷贝通过让内核直接在两个缓冲区之间传输数据，绕过用户态，将拷贝次数减少到 2 次甚至 0 次
- 关键技术包括：sendfile、splice、mmap + write、DMA Gather Copy（网卡支持时）

## 软硬件协同点
1. **DMA 直接内存访问**：磁盘控制器和网卡控制器支持 DMA，无需 CPU 参与即可在内存与外设间传输数据；零拷贝本质是让 DMA 直接在内核缓冲区之间搬运数据
2. **网卡 Scatter-Gather 支持**：现代网卡支持从多个内存地址收集数据并组装成网络报文（Scatter-Gather DMA），此时 sendfile 可做到真正的零 CPU 数据拷贝（CPU 只传递指针，不碰数据）
3. **Page Cache 与页缓存共享**：零拷贝依赖文件已缓存在 Page Cache 中，若文件未命中缓存，sendfile 会触发阻塞读取，此时零拷贝收益被抵消
4. **TCP 校验和卸载**：网卡硬件计算 TCP 校验和，CPU 无需扫描整个报文，配合零拷贝实现端到端的数据路径卸载

## 典型应用场景
1. **静态文件服务器**：Nginx 使用 sendfile 传输静态资源，单机 10Gbps 网卡可跑满（约 1GB/s），而传统 read/write 只能达到 300MB/s
2. **Kafka 消息传输**：Kafka broker 到消费者的数据传输使用零拷贝，消费端几乎不消耗 CPU，单机可支持百万级消息消费速率
