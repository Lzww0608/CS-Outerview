# epoll

## 定义与作用
epoll 是 Linux 特有的 I/O 多路复用机制，通过内核态事件表和回调机制实现高并发网络连接管理，解决传统 select/poll 线性扫描导致的 C10K 性能瓶颈问题。

## 核心原理
- 内核维护一个事件表（红黑树）存储被监控的文件描述符，通过 epoll_ctl 增删改
- 每个文件描述符上注册回调函数，IO 事件触发时内核自动将其加入就绪链表
- epoll_wait 直接返回就绪链表，时间复杂度 O(1)，而 select/poll 是 O(N)
- 支持水平触发（LT）和边沿触发（ET）两种模式，边沿触发配合非阻塞 IO 可实现最高性能

## 软硬件协同点
1. **中断回调机制**：网卡接收数据包后触发硬中断，内核中断处理程序调用 epoll 的回调函数，将 socket 标记为就绪，整个过程无需轮询
2. **网卡多队列（RSS）**：支持 Receive Side Scaling 的网卡可将不同流的报文分发到不同 CPU 核的中断队列，每个核运行独立的 epoll，实现真正的并行处理
3. **TCP 状态硬件卸载**：智能网卡（SmartNIC）可卸载 TCP 连接状态管理，epoll 直接从网卡硬件获取就绪事件，进一步降低 CPU 开销
4. **Copy_UserPage 优化**：epoll 就绪事件通过 `copy_to_user` 一次拷贝到用户空间，事件结构小（12 字节），批量返回时摊销开销极低

## 典型应用场景
1. **Nginx 事件驱动架构**：Nginx 使用 epoll 的 ET 模式管理数万并发连接，单台 16 核服务器可支撑 100 万并发 HTTP 连接
2. **Redis 网络层**：Redis 单线程模型基于 epoll 实现 IO 多路复用，虽然是单线程，但 IO 等待时间几乎为零，单机可达到 10 万+ QPS
