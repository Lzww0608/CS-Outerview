# CPU Affinity（CPU 亲和性）

## 定义与作用
CPU 亲和性是将线程或进程绑定到特定 CPU 核心运行的技术，减少线程迁移导致的缓存失效和上下文切换开销，解决多线程调度随机性导致的性能不稳定问题。

## 核心原理
- 默认情况下，Linux 调度器会将线程在不同核心间迁移以平衡负载，但每次迁移会导致该线程的 L1/L2 缓存全部失效
- 通过 sched_setaffinity 系统调用设置线程的 CPU 掩码，强制线程只在指定核心上运行
- 亲和性分为软亲和性（调度器倾向但不强制）和硬亲和性（强制绑定）
- 合理的亲和性设置可将缓存命中率从 60% 提升到 95% 以上

## 软硬件协同点
1. **缓存层次感知**：L1/L2 缓存是每个核心私有，L3 是同一 CPU 插槽共享，绑定到同一核心可最大化私有缓存命中率；跨核绑定会导致缓存失效
2. **NUMA 架构配合**：多 CPU 插槽系统中，内存也分 NUMA 节点；线程绑定到某个核心的同时，内存也应分配到对应 NUMA 节点，避免跨节点内存访问
3. **中断亲和性设置**：通过 `/proc/irq/N/smp_affinity` 将网卡中断绑定到特定核心，再将处理该中断的应用线程绑定到同一核心，利用缓存亲和性提升网络性能
4. **调度域与调度类**：Linux 内核的调度域（Scheduling Domain）层级结构与硬件拓扑对应，亲和性设置本质是限制线程可运行的调度域范围

## 典型应用场景
1. **DPDK 轮询模式驱动**：DPDK 将每个网卡队列绑定到独立 CPU 核，该核 100% 轮询硬件队列，不参与操作系统调度，报文处理延迟从 10us 降到 1us
2. **高频交易系统**：交易线程绑定到单个核心，关闭该核心的节能和动态调频（C-state/P-state），确保指令执行延迟稳定在 1-2ns，排除操作系统调度干扰
