# 金铲铲七天登录奖励测试用例设计

## 1. 问题背景

金铲铲之战是一款自走棋手游，七天登录奖励是常见的运营活动，用于提升用户留存和活跃度。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  活动假设：                                                │
│                                                             │
│  • 连续登录 7 天，每天领取奖励                            │
│  • 奖励包括：金币、皮肤碎片、英雄碎片等                   │
│  • 中断登录需重新计数（可配置）                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 | 影响 |
|------|------|------|
| 奖励丢失 | 网络波动导致奖励未到账 | 用户投诉 |
| 计数错误 | 登录天数显示错误 | 活动体验差 |
| 重复领取 | 弱网下多次点击导致重复 | 资源损失 |
| 边界出错 | 跨天登录边界处理不当 | 奖励丢失 |

## 4. 原因分析

### 4.1 弱网场景

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  弱网导致的问题：                                         │
│                                                             │
│  1. 请求超时                                              │
│     • 服务器已处理，客户端超时                             │
│     • 用户刷新页面，误以为未领取                           │
│                                                             │
│  2. 数据不一致                                            │
│     • 客户端显示未领取                                    │

│                                                             │
│  3. 重复提交                                             │
│     • 用户多次点击                                        │
│     • 服务器幂等处理失败                                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 6. 可选方案对比

### 6.1 幂等方案对比

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| 请求 ID 去重 | 唯一请求 ID 防重复 | 简单 | 需要客户端配合 |
| 状态机校验 | 检查当前状态转移 | 严谨 | 实现复杂 |
| 时间窗口去重 | 固定时间窗口内只处理一次 | 容错高 | 可能漏发 |

## 9. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 奖励超发 | 经济损失 | 幂等校验 |
| 奖励漏发 | 用户流失 | 补发机制 |
| 时区 bug | 部分用户异常 | 多时区测试 |
| 缓存不一致 | 显示错误 | 服务端优先 |
