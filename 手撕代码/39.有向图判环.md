# 有向图判环

有向图判环常见做法有两种：DFS 三色标记和拓扑排序。面试里如果只要求判断是否有环，DFS 写法更直接；如果还要给出合法依赖顺序，拓扑排序更自然。

## 1. DFS 三色标记

状态定义：

1. `0`：未访问。
2. `1`：正在当前 DFS 路径中。
3. `2`：已经访问完成，后续不需要重复搜索。

如果搜索某条边时遇到状态为 `1` 的节点，说明回到了当前递归栈上的节点，存在有向环。

```cpp
#include <vector>
using namespace std;

class Solution {
public:
    bool hasCycle(int n, const vector<vector<int>>& graph) {
        vector<int> color(n, 0);
        for (int i = 0; i < n; ++i) {
            if (color[i] == 0 && dfs(i, graph, color)) {
                return true;
            }
        }
        return false;
    }

private:
    bool dfs(int u, const vector<vector<int>>& graph, vector<int>& color) {
        color[u] = 1;
        for (int v : graph[u]) {
            if (color[v] == 1) {
                return true;
            }
            if (color[v] == 0 && dfs(v, graph, color)) {
                return true;
            }
        }
        color[u] = 2;
        return false;
    }
};
```

复杂度：

1. 时间复杂度：`O(V + E)`。
2. 空间复杂度：`O(V)`，递归栈最坏也是 `O(V)`。

## 2. 拓扑排序

Kahn 算法维护所有入度为 0 的节点。如果最终弹出的节点数小于总节点数，说明剩余节点互相依赖，存在环。

```cpp
#include <queue>
#include <vector>
using namespace std;

bool hasCycleByTopo(int n, const vector<vector<int>>& graph) {
    vector<int> indeg(n, 0);
    for (int u = 0; u < n; ++u) {
        for (int v : graph[u]) {
            ++indeg[v];
        }
    }

    queue<int> q;
    for (int i = 0; i < n; ++i) {
        if (indeg[i] == 0) {
            q.push(i);
        }
    }

    int visited = 0;
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        ++visited;
        for (int v : graph[u]) {
            if (--indeg[v] == 0) {
                q.push(v);
            }
        }
    }

    return visited != n;
}
```

## 3. 易错点

1. 无向图判环和有向图判环不同，无向图 DFS 需要记录父节点，有向图需要记录递归栈状态。
2. DFS 不能只用 `visited`，否则无法区分“当前路径中”和“已经安全完成”。
3. 图可能不连通，要从每个未访问节点启动搜索。
4. 递归深度可能过大，工程中可改成显式栈或拓扑排序。

## 4. 面试回答模板

有向图判环我会用 DFS 三色标记：未访问、访问中、访问完成。遍历边时如果遇到访问中的节点，说明回到当前递归路径，存在环；如果遇到访问完成的节点可以跳过。复杂度是 `O(V+E)`。如果题目还需要依赖执行顺序，可以用拓扑排序，最终无法弹出所有节点就说明有环。
