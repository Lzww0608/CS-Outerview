# 司机订单最大价值分配

## 题目

有若干司机和若干订单，给定司机接某个订单能获得的价值。每个订单最多分配一次，订单可以不分配，通常每个司机也最多接一个订单，求总价值最大的分配方案。

这是一个带权二分图匹配问题。面试中如果数据规模小，可以用状态压缩 DP；规模大时应回答匈牙利算法或最小费用最大流。

## 状态压缩 DP

设司机数为 `m`，订单数为 `n`，`value[i][j]` 表示司机 `i` 接订单 `j` 的价值。订单可以漏，所以司机也可以不接单。

当 `n` 不大时，用 bitmask 表示哪些订单已经被分配：

```text
dp[i][mask] = 处理前 i 个司机，已分配订单集合为 mask 时的最大价值
```

转移：

1. 第 `i` 个司机不接单：`dp[i + 1][mask] = max(dp[i + 1][mask], dp[i][mask])`
2. 第 `i` 个司机接未分配订单 `j`：`dp[i + 1][mask | (1 << j)] = max(..., dp[i][mask] + value[i][j])`

## 代码

```cpp
#include <algorithm>
#include <iostream>
#include <vector>
using namespace std;

int maxAssignValue(const vector<vector<int>>& value) {
    int m = static_cast<int>(value.size());
    int n = value.empty() ? 0 : static_cast<int>(value[0].size());

    int states = 1 << n;
    const int NEG = -1e9;
    vector<int> dp(states, NEG);
    dp[0] = 0;

    for (int i = 0; i < m; ++i) {
        vector<int> next = dp;
        for (int mask = 0; mask < states; ++mask) {
            if (dp[mask] == NEG) {
                continue;
            }

            for (int j = 0; j < n; ++j) {
                if ((mask & (1 << j)) == 0) {
                    int newMask = mask | (1 << j);
                    next[newMask] = max(next[newMask], dp[mask] + value[i][j]);
                }
            }
        }
        dp.swap(next);
    }

    return *max_element(dp.begin(), dp.end());
}

int main() {
    int m, n;
    cin >> m >> n;
    vector<vector<int>> value(m, vector<int>(n));
    for (int i = 0; i < m; ++i) {
        for (int j = 0; j < n; ++j) {
            cin >> value[i][j];
        }
    }

    cout << maxAssignValue(value) << endl;
    return 0;
}
```

## 复杂度

```text
时间复杂度: O(m * n * 2^n)
空间复杂度: O(2^n)
```

适合订单数较小的手撕题。如果 `n` 很大，状态压缩不可用。

## 大规模方案

1. **最大权二分图匹配 / KM 算法**：适合完整二分图、每个司机最多一个订单、每个订单最多一个司机。订单可漏可以补 0 价值虚拟订单或允许不匹配。
2. **最小费用最大流**：适合有容量、区域、时间窗、司机等级、订单可拆等复杂约束。
3. **在线派单系统**：通常不是一次性全局最优，而是滚动窗口内做候选召回、打分排序和局部匹配，要兼顾实时性、公平性和取消率。

## 易错点

1. “订单可以漏”不代表司机必须接单，转移里要保留不接单分支。
2. 如果价值可能为负，不接单分支更重要，否则会错误强制分配负收益订单。
3. 如果一个司机可以接多个订单，状态和约束会变成背包或路径规划问题，不再是普通二分匹配。
4. 大规模线上派单还要考虑距离、预计到达时间、司机状态、订单超时、区域供需和公平性。
