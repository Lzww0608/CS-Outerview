# 固定长度前缀匹配单词

题目：给定一个单词集合，多次查询“长度固定且具有某个前缀的单词”，如何高效返回结果。

## 1. 直接扫描

最简单做法是每次遍历所有单词：

```text
word.size() == len && word.starts_with(prefix)
```

单次查询复杂度是 `O(total_chars)`，实现简单，适合单词量小或查询次数少的场景。

## 2. 按长度分桶 + 排序

如果查询很多，可以先按单词长度分桶，每个桶内部排序：

```text
unordered_map<int, vector<string>> byLen
byLen[len] 中只保存长度为 len 的单词，并按字典序排序
```

查询时只访问目标长度的桶，然后用二分找到前缀范围：

```cpp
#include <algorithm>
#include <string>
#include <unordered_map>
#include <vector>

class PrefixIndex {
public:
    explicit PrefixIndex(const std::vector<std::string>& words) {
        for (const auto& word : words) {
            byLen_[static_cast<int>(word.size())].push_back(word);
        }
        for (auto& [len, bucket] : byLen_) {
            std::sort(bucket.begin(), bucket.end());
        }
    }

    std::vector<std::string> query(int len, const std::string& prefix) const {
        auto it = byLen_.find(len);
        if (it == byLen_.end()) {
            return {};
        }

        const auto& bucket = it->second;
        std::string right = nextPrefix(prefix);
        auto l = std::lower_bound(bucket.begin(), bucket.end(), prefix);
        auto r = right.empty()
            ? bucket.end()
            : std::lower_bound(bucket.begin(), bucket.end(), right);
        return std::vector<std::string>(l, r);
    }

private:
    static std::string nextPrefix(std::string s) {
        for (int i = static_cast<int>(s.size()) - 1; i >= 0; --i) {
            if (s[i] != char(127)) {
                ++s[i];
                s.resize(i + 1);
                return s;
            }
        }
        return "";
    }

    std::unordered_map<int, std::vector<std::string>> byLen_;
};
```

构建复杂度主要是排序，查询复杂度是 `O(log m + k)`，其中 `m` 是目标长度桶大小，`k` 是返回结果数量。

## 3. Trie 方案

如果前缀查询非常频繁，或者需要逐字符输入自动补全，可以使用 Trie。每个节点表示一个前缀，节点上可以维护：

1. 以该前缀开头的单词数量。
2. 按长度分组的单词列表或计数。
3. Top K 热门候选，便于搜索框补全。

Trie 查询前缀是 `O(prefix_length)`，但如果要返回所有匹配单词，仍然要遍历结果数量 `k`。空间开销通常比排序分桶更高，适合读多写少的词典、搜索提示、敏感词前缀索引等场景。

## 4. 易错点

1. 固定长度是强约束，先按长度分桶能显著减少候选集合。
2. 只用 HashMap 存完整单词无法高效支持前缀范围查询。
3. 字典序二分要构造前缀上界，例如 `[prefix, nextPrefix(prefix))`。
4. 如果包含 Unicode，需要按编码规则处理前缀和上界，不能简单对 `char` 加一。

## 5. 面试回答模板

查询次数少时直接扫描即可；查询次数多时，我会按单词长度分桶并对桶内字符串排序，查询固定长度时只在对应桶里用二分找 `[prefix, nextPrefix(prefix))` 的范围，复杂度是 `O(log m + k)`。如果是搜索补全这类大量前缀查询，可以改用 Trie，在节点上维护长度分组或 Top K 候选。
