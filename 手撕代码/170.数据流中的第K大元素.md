# 170. 数据流中的第 K 大元素

题目类似 LCR 059：维护一个数据流，构造时给定初始数组和整数 `k`，每次调用 `add(val)` 后返回当前数据流中的第 `k` 大元素。

## 1. 思路

维护一个大小为 `k` 的小根堆：

1. 堆里始终保存当前最大的 `k` 个元素。
2. 堆顶是这 `k` 个元素里最小的，也就是整个数据流的第 `k` 大。
3. 新元素到来时：
   - 如果堆大小小于 `k`，直接入堆。
   - 如果 `val` 大于堆顶，说明它应该进入前 `k` 大，弹出堆顶后放入 `val`。
   - 如果 `val` 小于等于堆顶，它不影响第 `k` 大，忽略。

示意：

```text
k = 3
数据流当前前 3 大: [9, 7, 5]
小根堆存储: [5, 7, 9]
堆顶 5 就是第 3 大
```

## 2. C++ 实现

```cpp
#include <queue>
#include <vector>

class KthLargest {
public:
    KthLargest(int k, std::vector<int>& nums) : k_(k) {
        for (int x : nums) {
            add(x);
        }
    }

    int add(int val) {
        if (heap_.size() < static_cast<size_t>(k_)) {
            heap_.push(val);
        } else if (val > heap_.top()) {
            heap_.pop();
            heap_.push(val);
        }
        return heap_.top();
    }

private:
    int k_;
    std::priority_queue<int, std::vector<int>, std::greater<int>> heap_;
};
```

`std::priority_queue` 默认是大根堆，要求小根堆时要使用 `std::greater<int>`。

## 3. 复杂度

设当前数据流长度为 `n`：

1. 构造函数：逐个调用 `add`，时间 `O(n log k)`，空间 `O(k)`。
2. 单次 `add`：最多一次入堆和出堆，时间 `O(log k)`。
3. 返回第 `k` 大：直接取堆顶，时间 `O(1)`。

## 4. 易错点

1. 这里是第 `k` 大，不是第 `k` 小，所以要用大小为 `k` 的小根堆。
2. 堆里只需要保留前 `k` 大，不需要保存全部数据流。
3. 初始数组也要通过 `add` 进入同一套逻辑，避免构造阶段和增量阶段规则不一致。
4. 如果数据可能重复，重复值要按元素个数计算，不要用 `set` 去重。
5. 面试题通常保证调用 `add` 时数据量至少能形成第 `k` 大；如果工程代码不保证，要定义空堆或不足 `k` 个元素时的返回策略。

## 5. 扩展

1. **静态数组只求一次第 K 大**：可以用 Quickselect，平均 `O(n)`。
2. **需要频繁删除任意元素**：普通堆不适合，可以用平衡树、双堆懒删除或支持 order statistic 的结构。
3. **海量数据流 Top K**：单机用小根堆；分布式场景先各分片求局部 Top K，再汇总求全局 Top K。
4. **滑动窗口第 K 大**：需要同时支持过期删除，常用双堆懒删除、平衡树或 Fenwick/线段树加离散化。

## 6. 面试回答模板

这题用大小为 `k` 的小根堆。堆中始终保存当前数据流最大的 `k` 个数，堆顶就是第 `k` 大。新元素来时，如果堆不足 `k` 个就直接放入；如果堆满且新值大于堆顶，就弹出堆顶再插入新值；否则忽略。每次 `add` 的时间复杂度是 `O(log k)`，空间复杂度是 `O(k)`，适合动态数据流。
