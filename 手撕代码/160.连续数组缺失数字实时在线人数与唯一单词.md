# 160. 连续数组缺失数字、实时在线人数与唯一单词

这三题分别考察：

1. 有序数组上的二分和数学性质。
2. 海量日志流上的实时状态统计。
3. 文件流式处理、集合去重、哈希表原理。

## 1. 找连续递增数组里缺的数字

### 题目

给定一个严格递增数组，原本应该是连续整数，但中间缺了一个数字，找出缺失的数字。

例如：

```text
输入: [3, 4, 5, 7, 8]
输出: 6
```

先问清楚边界：

1. 是否只缺一个数字。
2. 数组是否严格递增。
3. 是否知道原始起点和终点。
4. 缺失数字是否可能在首尾之外。

下面默认：数组内部缺一个数字，数组严格递增，且相邻正常差值为 1。

### 方法一：二分查找

如果数组从 `start = nums[0]` 开始，那么没有缺失时：

```text
nums[i] == start + i
```

一旦缺了一个数，从缺失位置开始：

```text
nums[i] > start + i
```

所以可以二分找第一个不满足 `nums[i] == start + i` 的位置。

```cpp
#include <vector>
using namespace std;

int missingInIncreasingArray(const vector<int>& nums) {
    int n = static_cast<int>(nums.size());
    if (n < 2) {
        return -1; // 信息不足，面试里可和面试官约定返回值
    }

    int start = nums[0];
    int left = 0;
    int right = n - 1;

    while (left < right) {
        int mid = left + (right - left) / 2;
        if (nums[mid] == start + mid) {
            left = mid + 1;
        } else {
            right = mid;
        }
    }

    return start + left;
}
```

复杂度：

```text
时间复杂度：O(log n)
额外空间：O(1)
```

### 方法二：求和

如果知道完整区间 `[L, R]`，可以用等差数列求和：

```cpp
#include <numeric>
#include <vector>
using namespace std;

long long missingBySum(const vector<int>& nums, int left, int right) {
    long long expected = 1LL * (left + right) * (right - left + 1) / 2;
    long long actual = 0;
    for (int x : nums) {
        actual += x;
    }
    return expected - actual;
}
```

求和法是 `O(n)`，实现简单，但要注意整数溢出。面试里如果数组有序，二分更能体现利用输入性质。

### 易错点

1. 如果缺失可能在数组首尾之外，只靠 `nums[0]` 和 `nums[n-1]` 无法判断，需要给定原始范围。
2. 如果缺多个数字，二分返回的是第一个缺口，不是所有缺失数字。
3. 如果数组不是严格递增，`nums[i] - i` 的单调性可能被破坏。
4. 求和法要用 `long long`，大范围整数容易溢出。

## 2. 10 亿用户网站实时统计每秒在线人数

### 题目

一个 10 亿用户的网站，用户每次登录、登出都会打印日志：

```text
userid time login/logout
```

如何实时获取每一秒内在线人数？

这题本质是流式状态统计。先区分两个口径：

1. **在线会话数**：一个用户多端登录算多个在线。
2. **在线用户数**：一个用户多端登录仍算一个在线用户。

如果题目只给 `userid` 没有 `session_id`，通常默认统计在线用户数；但真实系统最好有 `session_id/device_id`，否则多端、重复登录、异常断开都难以准确处理。

### 最简单模型：事件增量

如果日志可靠、严格有序、没有重复、一个用户不会重复登录：

```text
login  -> +1
logout -> -1
```

每秒在线人数：

```text
online_count[sec] = online_count[sec - 1] + delta_sum[sec]
```

单机伪代码：

```cpp
#include <cstdint>
#include <string>
#include <unordered_map>

enum class Action { Login, Logout };

struct Event {
    std::uint64_t userId;
    std::int64_t second;
    Action action;
};

class OnlineCounter {
public:
    void onEvent(const Event& e) {
        long long delta = e.action == Action::Login ? 1 : -1;
        deltaBySecond_[e.second] += delta;
    }

    long long emitUntil(std::int64_t second) {
        while (lastEmittedSecond_ < second) {
            ++lastEmittedSecond_;
            currentOnline_ += deltaBySecond_[lastEmittedSecond_];
            // 真实系统这里写入 Redis/ClickHouse/TSDB 或推送给订阅方
        }
        return currentOnline_;
    }

private:
    std::unordered_map<std::int64_t, long long> deltaBySecond_;
    std::int64_t lastEmittedSecond_ = -1;
    long long currentOnline_ = 0;
};
```

这个版本只能说明核心数学关系，真实线上不能只这么做。

### 真实系统架构

推荐链路：

```text
应用服务器
-> 登录/登出日志
-> Kafka / Pulsar
-> Flink / Spark Streaming
-> Keyed State: user_id -> online state
-> 每秒 delta 聚合
-> Redis / TSDB / ClickHouse
-> Dashboard / API
```

### 精确在线用户数怎么做

每个用户维护状态：

```text
user_id -> {
  online: bool,
  last_event_time,
  last_event_id,
  session_count
}
```

处理逻辑：

```text
login:
  if user was offline:
      online = true
      emit +1 at event.second
  else:
      no delta, or session_count++ if统计会话

logout:
  if user was online:
      online = false
      emit -1 at event.second
  else:
      ignore or record abnormal logout
```

如果支持多端登录，应维护 `session_count`：

```text
login:  session_count 从 0 -> 1 时在线用户数 +1
logout: session_count 从 1 -> 0 时在线用户数 -1
```

### 10 亿用户状态怎么存

如果只是在线/离线 bit：

```text
10 亿 bit ≈ 125 MB
```

单纯 bitmap 在内存上可行，但真实系统还需要多端 session、时间戳、去重 ID、分布式容错，因此通常用流处理状态后端：

1. Flink Keyed State + RocksDB StateBackend。
2. Redis Cluster 保存活跃用户集合或 bitmap。
3. RoaringBitmap 保存在线用户集合快照。
4. ClickHouse/TSDB 保存每秒结果，不保存全部用户状态。

### 乱序、重复和延迟

日志系统一定要处理：

1. **乱序事件**：用 event time + watermark，允许迟到窗口。
2. **重复日志**：用 `event_id` 或 `(user_id, session_id, action, time)` 去重。
3. **丢失 logout**：用心跳或 session TTL 补偿。
4. **服务重启**：状态要 checkpoint，不能只在进程内存。
5. **跨机房**：同一用户事件要按 user_id 分区，保证同一 key 顺序处理。

### 查询每秒在线人数

流处理任务输出：

```text
second -> online_count
```

存储选择：

1. Redis：保存最近几分钟/几小时的秒级值，适合实时看板。
2. ClickHouse：保存长期明细和聚合结果，适合分析。
3. Prometheus/TSDB：保存在线人数指标，适合监控告警。

### 面试回答模板

我会把登录登出看成事件流。最简单情况下，登录是 `+1`，登出是 `-1`，每秒在线人数等于上一秒在线人数加上这一秒 delta。但 10 亿用户真实系统要处理重复、乱序、多端登录和异常断开。架构上用 Kafka 接日志，Flink 按 `user_id` keyBy，状态里保存用户是否在线或 session_count；当状态从离线变在线时对对应秒发 `+1`，从在线变离线时发 `-1`，再按秒聚合 delta，累加成 `second -> online_count` 写入 Redis/TSDB/ClickHouse。乱序用 event time + watermark，重复用 event_id 去重，logout 丢失用心跳或 TTL 补偿，状态用 checkpoint 保证恢复。

## 3. 文件每行一个单词，找到唯一出现的单词

### 题目

文件中每一行都有一个单词，找出唯一出现的单词。

这里也要先问清楚：

1. 是“只有一个单词出现一次，其他都出现两次”吗？
2. 还是“找出所有出现次数为 1 的单词”？
3. 文件能不能放进内存？
4. 单词是否区分大小写，是否需要去掉换行和标点？

### 情况一：只有一个单词出现一次，其他都出现两次

内存足够时，可以用 `unordered_set` 做开关：

```text
第一次见到：放入 set
第二次见到：从 set 删除
最后 set 里剩下的就是只出现一次的单词
```

```cpp
#include <fstream>
#include <string>
#include <unordered_set>

std::string findSingleWordPairCase(const std::string& path) {
    std::ifstream in(path);
    std::unordered_set<std::string> seen;
    std::string word;

    while (std::getline(in, word)) {
        if (word.empty()) {
            continue;
        }
        auto it = seen.find(word);
        if (it == seen.end()) {
            seen.insert(word);
        } else {
            seen.erase(it);
        }
    }

    if (seen.size() != 1) {
        return ""; // 输入不满足“唯一一个单词出现一次”的假设
    }
    return *seen.begin();
}
```

复杂度：

```text
时间复杂度：平均 O(n)
空间复杂度：O(d)，d 是未配对的不同单词数量
```

### 情况二：找出所有出现次数为 1 的单词

如果其他单词不一定都出现两次，就必须计数：

```cpp
#include <fstream>
#include <string>
#include <unordered_map>
#include <vector>

std::vector<std::string> findWordsAppearOnce(const std::string& path) {
    std::ifstream in(path);
    std::unordered_map<std::string, int> cnt;
    std::string word;

    while (std::getline(in, word)) {
        if (!word.empty()) {
            ++cnt[word];
        }
    }

    std::vector<std::string> ans;
    for (const auto& [w, c] : cnt) {
        if (c == 1) {
            ans.push_back(w);
        }
    }
    return ans;
}
```

### 文件太大怎么办

如果内存放不下哈希表或 set，用哈希分桶：

```text
顺序扫描原文件
-> bucket = hash(word) % N
-> 写入 bucket_i.tmp
-> 逐个处理 bucket 文件
-> 在单桶内用 set 或 map 找唯一出现单词
```

相同单词一定落到同一个桶，所以不会跨桶拆散。

如果要求输出按字典序，可以用外部排序：

```text
分块排序
-> 多路归并
-> 相同单词连续出现
-> 扫描统计连续段长度
-> 输出长度为 1 的单词
```

### set 的原理是什么

要看语言和容器：

1. C++ `std::set` 通常是红黑树，元素有序，查找/插入/删除 `O(log n)`。
2. C++ `std::unordered_set` 是哈希表，元素无序，平均查找/插入/删除 `O(1)`。
3. Java `HashSet` 底层是 `HashMap`，平均 `O(1)`。
4. Python `set` 是开放寻址哈希表，平均 `O(1)`。

这题如果只需要判断是否出现过，通常说的 set 更适合用哈希集合，也就是 `unordered_set`/`HashSet`。

### 哈希原理是什么

哈希表的核心流程：

```text
key -> hash(key) -> bucket index -> 冲突处理 -> 存取元素
```

关键点：

1. 哈希函数把字符串映射成整数。
2. 通过取模或位运算定位桶。
3. 不同 key 可能落到同一个桶，叫哈希冲突。
4. 冲突可以用链地址法或开放寻址法解决。
5. 元素太多时要扩容 rehash，降低装载因子。

复杂度：

```text
理想平均：O(1)
冲突严重最坏：O(n)
```

工程注意：

1. 哈希相同不代表字符串相等，最终必须比较原始 key。
2. 哈希表内存开销比数组大，有桶、节点、指针、装载因子和分配器开销。
3. 外部输入作为 key 时要注意恶意哈希冲突，可以使用带随机种子的 hash。
4. 大文件场景不能默认全量哈希表放得下，要先估算不同单词数量和平均长度。

### 面试回答模板

如果题目保证只有一个单词出现一次，其他都出现两次，我会用哈希 set 做开关：第一次读到单词就插入，第二次读到就删除，最后 set 里剩下的就是答案，平均 `O(n)` 时间。如果题目是找所有出现次数为 1 的单词，就要用哈希表计数，最后遍历计数表输出 `count == 1` 的单词。文件太大时不能把全量 set/map 放内存，我会按 `hash(word) % N` 分桶，相同单词一定进入同一桶，再逐桶处理；或者外部排序后扫描连续相同单词。set 如果指 `unordered_set/HashSet`，底层是哈希表，依赖 hash 函数定位桶，冲突用链表、树或开放寻址解决，平均查找插入删除 `O(1)`，但最坏可能退化。
