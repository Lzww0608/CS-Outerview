# 大量有序数据合并

题目：有很多份已经排好序的数据，要求合并成一份有序数据，并说明在数据量很大时如何优化。

## 1. 内存足够时用 K 路归并

如果有 `k` 个有序数组或有序流，总元素数为 `N`，可以维护一个大小为 `k` 的小根堆。堆里保存每个数据源当前最小元素，每次弹出全局最小值，再从同一数据源读入下一个元素。

```cpp
#include <queue>
#include <vector>
using namespace std;

vector<int> mergeSortedArrays(const vector<vector<int>>& arrays) {
    struct Node {
        int value;
        int arrayIndex;
        int elementIndex;
    };

    struct Cmp {
        bool operator()(const Node& a, const Node& b) const {
            return a.value > b.value; // 小根堆
        }
    };

    priority_queue<Node, vector<Node>, Cmp> heap;
    for (int i = 0; i < static_cast<int>(arrays.size()); ++i) {
        if (!arrays[i].empty()) {
            heap.push({arrays[i][0], i, 0});
        }
    }

    vector<int> ans;
    while (!heap.empty()) {
        Node cur = heap.top();
        heap.pop();
        ans.push_back(cur.value);

        int nextIndex = cur.elementIndex + 1;
        if (nextIndex < static_cast<int>(arrays[cur.arrayIndex].size())) {
            heap.push({arrays[cur.arrayIndex][nextIndex], cur.arrayIndex, nextIndex});
        }
    }
    return ans;
}
```

复杂度：

1. 时间复杂度：`O(N log k)`。
2. 空间复杂度：`O(k)`，堆中每个数据源最多一个当前元素。

## 2. 数据量很大时怎么优化

当数据无法全部放入内存时，问题就变成外部排序或外部归并，重点是减少随机 I/O 和控制内存占用。

1. **顺序读写**：每个输入文件用缓冲区顺序读取，输出文件批量顺序写入，避免频繁小 I/O。
2. **分批归并**：如果文件数太多，先按批次合并成中间有序文件，再做下一轮归并。
3. **控制堆大小**：一次归并的路数受内存、文件描述符数量和磁盘吞吐限制，不是越大越好。
4. **败者树**：当 `k` 很大时，败者树可以减少比较次数，很多外部排序实现会用它替代普通堆。
5. **压缩块**：冷数据或网络传输场景可按块压缩，读取时解压到缓冲区再归并。
6. **异步预读**：CPU 处理当前缓冲区时，后台线程预读下一批数据，隐藏 I/O 延迟。

## 3. 分布式场景

如果数据分布在多台机器上，可以先本地归并，再做全局归并：

1. 每台机器对本地多个有序分片做 K 路归并。
2. 按 key 范围做 range partition，把不同范围发往不同下游节点。
3. 每个下游节点只负责一个 key 范围内的有序归并。
4. 最终按范围顺序拼接结果。

这样可以避免所有数据集中到一台机器。缺点是需要处理数据倾斜，如果某个 key 范围特别热，需要进一步拆分范围或使用采样估计分区边界。

## 4. 变体问题

1. **只要 Top K**：不需要完整归并，可以对每个有序源只读取必要前缀，结合小根堆或大根堆求结果。
2. **需要去重**：归并过程中记录上一个输出值，相同值跳过即可。
3. **需要稳定性**：堆节点中加入数据源编号和原始位置作为 tie breaker。
4. **输入是链表**：就是合并 K 个升序链表，仍然用最小堆或分治合并。
5. **输入是日志**：按时间戳归并时要考虑不同机器时钟偏差，必要时使用逻辑时间或水位线。

## 5. 易错点

1. 普通双路归并逐个合并 `k` 份数据，最坏可能退化到 `O(kN)`。
2. K 路归并的堆里不应该放所有元素，只放每路当前元素。
3. 大文件场景瓶颈通常是 I/O，不是算法比较次数，缓冲区和顺序读写很关键。
4. 文件数很多时要关注 fd 限制，不能一次打开无限多文件。
5. 外部归并要能断点恢复，中间文件命名、校验和清理策略要明确。

## 6. 面试回答模板

大量有序数据合并本质是 K 路归并。内存足够时，用大小为 `k` 的小根堆，每次取全局最小元素并推进对应数据源，时间 `O(N log k)`，空间 `O(k)`。如果数据量很大，就按外部归并处理，每路用缓冲区顺序读，输出批量顺序写，文件数过多时分批多轮合并，必要时用败者树降低比较成本。分布式场景下先本地归并，再按 key 范围分区做全局归并，并用采样和拆分范围处理数据倾斜。
