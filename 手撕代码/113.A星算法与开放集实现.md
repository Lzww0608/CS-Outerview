# A* 算法与开放集实现

A*（A-star）是图搜索和路径规划中常见的最短路径算法。它在 Dijkstra 的“当前已知最短距离”基础上加入启发式估计，让搜索更倾向于朝目标方向扩展。

## 1. 核心定义

对每个节点维护三个值：

```text
g(n): 从起点到 n 的已知代价
h(n): 从 n 到终点的估计代价
f(n): g(n) + h(n)
```

A* 每次从开放集（open set）里取 `f` 最小的节点扩展。已经确定或不再需要重复扩展的节点放入关闭集（closed set）。

在网格地图里，常见启发函数：

1. 四方向移动：曼哈顿距离 `abs(x1 - x2) + abs(y1 - y2)`。
2. 八方向移动：对角距离或欧几里得距离。
3. 有障碍和地形代价时，`h` 不能高估真实最短距离，否则可能失去最优性。

## 1.1 Dijkstra 和 A* 的关系

Dijkstra 可以看成 `h(n) = 0` 的 A*。它只根据已经走过的代价 `g(n)` 扩展节点，因此适合不知道目标方向、需要从一个源点求到多个点最短路的场景。

| 对比项 | Dijkstra | A* |
| --- | --- | --- |
| 优先级 | `g(n)` | `g(n) + h(n)` |
| 启发函数 | 不需要 | 需要设计，且不能高估真实代价才能保证最优 |
| 适用场景 | 非负权图、单源最短路、路网距离表 | 明确起点终点的路径规划、地图寻路 |
| 搜索范围 | 可能向所有方向均匀扩散 | 更偏向目标方向，通常扩展节点更少 |
| 风险 | 有负权边时不适用 | `h` 设计不当会失去最优性或退化 |

如果面试问“为什么不用 A* 替代 Dijkstra”，可以回答：A* 的优势依赖一个足够好的启发函数；没有明确终点、需要多目标距离、图不是几何空间、或启发函数很弱时，A* 可能退化成 Dijkstra，还增加实现复杂度。

## 2. 基本流程

```text
open.push(start)
g[start] = 0

while open 不空:
    cur = open.pop_min_f()
    if cur == target:
        根据 parent 回溯路径

    if cur 已经在 closed:
        continue
    closed.add(cur)

    for next in cur 的邻居:
        if next 是障碍或已关闭:
            continue
        new_g = g[cur] + cost(cur, next)
        if next 没访问过或 new_g 更小:
            g[next] = new_g
            parent[next] = cur
            open.push_or_update(next, new_g + h(next))
```

`parent` 用来回溯路径，`g` 用来判断是否找到了更短路线。

## 3. 开放集用有序数组还是最小堆

面试里常追问“如果维护有序数组，插入是 `O(log n)` 吗”。二分只能找到插入位置，真正插入仍要移动元素。

| 结构 | 取最小 `f` | 插入 | 删除/更新任意节点 | 适用场景 |
| --- | --- | --- | --- | --- |
| 无序数组 | `O(n)` | `O(1)` | `O(n)` | open 很小，实现简单 |
| 有序数组 | `O(1)` | 查找位置 `O(log n)`，移动 `O(n)` | `O(n)` | open 小且取最小非常频繁 |
| 最小堆 | `O(log n)` 弹出 | `O(log n)` | 无索引时 `O(n)`；带位置索引 `O(log n)` | open 较大，最常用 |
| 红黑树/有序集合 | `O(log n)` | `O(log n)` | `O(log n)` | 需要删除或更新任意节点 |

工程里常用最小堆。若发现同一个节点更短路径，简化做法是把新记录再次入堆，弹出旧记录时发现它不是当前最优 `g` 就跳过，这叫 lazy deletion。这样实现简单，但堆里会有过期条目。

## 4. C++ 简化实现

```cpp
#include <algorithm>
#include <cmath>
#include <queue>
#include <unordered_map>
#include <vector>

struct Point {
    int x;
    int y;
    bool operator==(const Point& other) const {
        return x == other.x && y == other.y;
    }
};

struct PointHash {
    size_t operator()(const Point& p) const {
        return (static_cast<size_t>(p.x) << 32) ^ static_cast<unsigned>(p.y);
    }
};

struct State {
    Point p;
    int g;
    int f;
};

struct Cmp {
    bool operator()(const State& a, const State& b) const {
        return a.f > b.f; // priority_queue 默认大根堆，这里反过来做小根堆
    }
};

int heuristic(Point a, Point b) {
    return std::abs(a.x - b.x) + std::abs(a.y - b.y);
}

std::vector<Point> astar(const std::vector<std::vector<int>>& grid,
                         Point start, Point target) {
    std::priority_queue<State, std::vector<State>, Cmp> open;
    std::unordered_map<Point, int, PointHash> dist;
    std::unordered_map<Point, Point, PointHash> parent;

    auto inside = [&](Point p) {
        return p.x >= 0 && p.x < static_cast<int>(grid.size()) &&
               p.y >= 0 && p.y < static_cast<int>(grid[0].size());
    };

    dist[start] = 0;
    open.push({start, 0, heuristic(start, target)});

    const int dirs[4][2] = {{1, 0}, {-1, 0}, {0, 1}, {0, -1}};

    while (!open.empty()) {
        State cur = open.top();
        open.pop();

        if (cur.g != dist[cur.p]) {
            continue; // lazy deletion: 过期堆元素
        }
        if (cur.p == target) {
            std::vector<Point> path;
            for (Point p = target; !(p == start); p = parent[p]) {
                path.push_back(p);
            }
            path.push_back(start);
            std::reverse(path.begin(), path.end());
            return path;
        }

        for (auto& d : dirs) {
            Point nxt{cur.p.x + d[0], cur.p.y + d[1]};
            if (!inside(nxt) || grid[nxt.x][nxt.y] == 1) {
                continue;
            }
            int ng = cur.g + 1;
            if (!dist.count(nxt) || ng < dist[nxt]) {
                dist[nxt] = ng;
                parent[nxt] = cur.p;
                open.push({nxt, ng, ng + heuristic(nxt, target)});
            }
        }
    }
    return {};
}
```

真实手写时可以用二维数组保存 `dist` 和 `parent`，避免 `unordered_map<Point,...>` 的模板细节干扰。

## 5. 易错点

1. `h` 高估真实代价时，A* 可能更快，但不保证最短路径。
2. 有序数组的插入不是 `O(log n)`，二分后还要移动元素。
3. 最小堆不擅长更新任意节点；可以用 lazy deletion，或额外维护节点到堆下标的映射。
4. 如果边权不是统一的 1，`g` 要加真实地形代价，不能只加步数。
5. 游戏里要考虑动态障碍、单位半径、碰撞体积和路径平滑，算法找到的格子路径不一定能直接用于移动。

## 6. 真实场景

1. 游戏 NPC 寻路、战棋格子移动、地图导航。
2. 机器人路径规划。
3. 网格或路网中的启发式最短路。

在游戏服务端或客户端中，A* 常配合导航网格、分层寻路、JPS、路径缓存和局部避障。大地图上不应每帧对所有单位完整跑 A*，通常要限频、分帧、缓存或先做粗粒度路径，再局部修正。

## 7. 面试回答模板

A* 是带启发式函数的最短路径搜索。每个节点维护 `g`、`h`、`f=g+h`，每次从开放集中取 `f` 最小的节点扩展。只要启发函数不高估真实距离，就能保证找到最短路径。开放集通常用最小堆，插入和弹出是 `O(log n)`；有序数组虽然取最小是 `O(1)`，但插入要移动元素，整体是 `O(n)`。在游戏寻路里还要考虑动态障碍、路径平滑、寻路频率和缓存。
