## 统计概率—30万人，抽10万人，写一个生成[0,2^16-1]的16位字符的函数

要实现一个公平的抽奖程序，核心要点有两个：

1.  **公平性**：每个员工被抽中的概率必须完全相等，即 10万 / 30万 = 1/3。
2.  **随机性**：抽奖结果是不可预测的。

此外，我们还需要考虑程序的**效率**（时间复杂度和空间复杂度），尤其是在处理30万员工这样规模的数据时。

我将提供几种解决方案，从简单直接到最优解，并分析它们的优劣。

### 0. 准备工作：一个满足要求的随机数生成器

题目给定的`rand()`只能生成0-65535的整数，无法直接覆盖1-30万的范围。我们需要先构建一个能生成更大范围随机数的函数。一个常见的方法是拼接多个`rand()`的结果。

```cpp
#include <cstdlib> // For rand()
#include <climits> // For RAND_MAX

// 生成一个 [0, n-1] 范围的随机整数
// 使用拒绝采样法来保证公平性，避免模运算带来的偏差
unsigned int generate_random_in_range(unsigned int n) {
    if (n == 0) return 0;

    // RAND_MAX 通常是 32767 或 2147483647，这里我们假设是 32767
    unsigned int range = RAND_MAX + 1;
    unsigned int num_rand_calls = 1;
    while (range < n) {
        range *= (RAND_MAX + 1);
        num_rand_calls++;
        // 防止溢出，对于30万这个级别一般不会
    }

    unsigned int limit = range / n * n;
    unsigned int result;
    
    do {
        result = 0;
        for (unsigned int i = 0; i < num_rand_calls; ++i) {
            result = result * (RAND_MAX + 1) + rand();
        }
    } while (result >= limit);

    return result % n;
}
```
**说明**：这个`generate_random_in_range(n)`函数可以公平地生成`[0, n-1]`的随机数。为了避免`rand() % n`造成的分布不均（当`RAND_MAX+1`不是`n`的整数倍时），我用了**拒绝采样法**，这是保证公平性的关键细节。

在C++11及以后，我们其实有更好的工具`std::mt19937`和`std::uniform_int_distribution`，它们能更高效、更优质地完成这件事。但在面试中，展示手写一个公平的范围随机数生成器的能力是一个加分项。

```cpp
#include <random>

// 使用C++11标准库实现，更佳实践
std::mt19937 rng(std::random_device{}()); // 高质量随机数引擎

unsigned int modern_rand(unsigned int n) {
    if (n == 0) return 0;
    std::uniform_int_distribution<unsigned int> dist(0, n - 1);
    return dist(rng);
}
```
接下来的算法中，我们假设已经有了一个名为`rand_int(n)`的函数，可以公平地生成`[0, n-1]`的随机整数。

### 方案一：暴力抽选法 (Shuffle and Pick)

**思路**：
1.  创建一个包含1到30万所有工卡号的数组。
2.  将这个数组进行完全随机的洗牌（Shuffle）。
3.  取出数组的前10万个元素作为中奖号码。

**代码实现**：
```cpp
#include <iostream>
#include <vector>
#include <numeric>
#include <algorithm>
#include <random>

// 假设 modern_rand(n) 已定义
unsigned int modern_rand(unsigned int n);

void lottery_shuffle(int total_employees, int num_winners) {
    std::vector<int> employees(total_employees);
    std::iota(employees.begin(), employees.end(), 1); // 填充 1, 2, ..., 300000

    // Fisher-Yates shuffle
    std::shuffle(employees.begin(), employees.end(), rng);

    std::cout << "Winning employee IDs:\n";
    for (int i = 0; i < num_winners; ++i) {
        std::cout << employees[i] << " ";
    }
    std::cout << std::endl;
}
```
**分析**：
*   **公平性**：完美。Fisher-Yates洗牌算法保证了每个元素出现在任何位置的概率是相等的。
*   **时间复杂度**：`O(N)`，其中N是总员工数。`std::iota`是O(N)，`std::shuffle`也是O(N)。
*   **空间复杂度**：`O(N)`。我们需要一个数组来存储所有30万个员工的ID。
*   **缺点**：当N非常巨大时（比如几亿人），`O(N)`的空间复杂度可能是无法接受的。对于30万这个量级，`300000 * 4 bytes ≈ 1.2 MB`，完全可以接受。但面试官可能希望看到更优的解法。

### 方案二：随机抽样法 (Sampling)

**思路**：
当我们不想存储所有员工时，可以反向思考：每次随机抽取一个员工，如果他还没被抽中，就算他中奖。

**代码实现**：
```cpp
#include <unordered_set>

void lottery_sampling(int total_employees, int num_winners) {
    std::unordered_set<int> winners;
    while (winners.size() < num_winners) {
        int candidate = modern_rand(total_employees) + 1; // 生成 [1, 300000] 的ID
        winners.insert(candidate);
    }

    std::cout << "Winning employee IDs:\n";
    for (int winner_id : winners) {
        std::cout << winner_id << " ";
    }
    std::cout << std::endl;
}
```
**分析**：
*   **公平性**：完美。每次都是从全体员工中等概率抽取。
*   **空间复杂度**：`O(K)`，其中K是中奖人数（10万）。这比方案一要好。
*   **时间复杂度**：**不确定，但期望是`O(K)`**。随着中奖集合`winners`越来越大，抽到重复ID的概率也越来越高，`while`循环会执行更多次。这个过程被称为“**生日问题**”。在`K`远小于`N`时，性能很好。但当`K`接近`N`时，性能会急剧下降。对于`K=10万, N=30万`，碰撞概率已经不低了，性能会有所折损，但仍然可用。
*   **缺点**：时间复杂度不稳定。

### 方案三：蓄水池抽样 (Reservoir Sampling) - 空间最优

**思路**：
如果员工ID是以数据流的形式一个一个给出的，或者我们想在一次遍历中完成抽样，蓄水池抽样是标准解法。

1.  创建一个大小为K（10万）的“蓄水池”数组，用来存放中奖者。
2.  先用前K个员工的ID填满这个蓄水池。
3.  然后，从第K+1个员工开始遍历到第N个员工：
    *   对于第`i`个员工，生成一个`[0, i-1]`的随机数`j`。
    *   如果`j`小于K，那么就用第`i`个员工的ID替换掉蓄水池中第`j`个位置的ID。
    *   否则，什么都不做。
4.  遍历结束后，蓄水池中的K个ID就是中奖者。

**代码实现**：
```cpp
void lottery_reservoir_sampling(int total_employees, int num_winners) {
    std::vector<int> reservoir(num_winners);
    // 1. Fill the reservoir with the first K employees
    for (int i = 0; i < num_winners; ++i) {
        reservoir[i] = i + 1;
    }

    // 2. Iterate through the rest of the employees
    for (int i = num_winners; i < total_employees; ++i) {
        int j = modern_rand(i + 1); // Random number in [0, i]
        if (j < num_winners) {
            reservoir[j] = i + 1;
        }
    }

    std::cout << "Winning employee IDs:\n";
    for (int winner_id : reservoir) {
        std::cout << winner_id << " ";
    }
    std::cout << std::endl;
}
```
**分析**：
*   **公平性**：完美。可以数学证明，遍历结束后，每个员工留在蓄水池中的概率都是`K/N`。
*   **时间复杂度**：`O(N)`。需要完整遍历一次所有员工。
*   **空间复杂度**：`O(K)`。这是该算法最大的优势。
*   **适用场景**：非常适合处理无法一次性载入内存的海量数据流。在本题中，虽然数据量不大，但它展示了一种更通用的解决方案。

### 方案四：Knuth 算法S (最优解)

**思路**：
这是Donald Knuth提出的一个非常巧妙的算法，结合了前面几种方法的优点。它在一次遍历中，以正确的概率决定是否“录取”当前员工。

遍历从1到N的每个员工`i`，我们想知道，对于剩下的`N-i+1`个员工，我们还需要选出多少个中奖者 `K_rem`。当前员工`i`被选中的概率应该是 `K_rem / (N-i+1)`。

**代码实现**：
```cpp
void lottery_knuth_s(int total_employees, int num_winners) {
    std::vector<int> winners;
    winners.reserve(num_winners);

    int remaining_winners = num_winners;
    int remaining_employees = total_employees;

    for (int i = 1; i <= total_employees; ++i) {
        // Decide whether to select employee i
        if (modern_rand(remaining_employees) < remaining_winners) {
            winners.push_back(i);
            remaining_winners--;
        }
        remaining_employees--;

        if (remaining_winners == 0) {
            break; // Optimization: already found all winners
        }
    }

    std::cout << "Winning employee IDs:\n";
    for (int winner_id : winners) {
        std::cout << winner_id << " ";
    }
    std::cout << std::endl;
}
```

**分析**：
*   **公平性**：完美。第`i`个员工被选中的概率精确地等于“剩余所需名额 / 剩余总人数”。
*   **时间复杂度**：`O(N)`。在最坏情况下，需要遍历所有员工。
*   **空间复杂度**：`O(K)`。
*   **优点**：代码逻辑非常清晰，而且对于`K`远小于`N`的情况，它经常会提前结束循环，实际运行时间通常优于蓄水池抽样。
