# 92. 线程安全 HashMap 实现

题目：实现一个能解决冲突的 HashMap，并说明如何保证线程安全。

## 1. 基础版：链地址法解决冲突

链地址法用桶数组保存链表。发生哈希冲突时，把 key-value 放到同一个桶的链表中。

```cpp
#include <functional>
#include <list>
#include <mutex>
#include <shared_mutex>
#include <stdexcept>
#include <utility>
#include <vector>
using namespace std;

template <typename K, typename V, typename Hash = std::hash<K>>
class HashMap {
public:
    explicit HashMap(size_t bucketCount = 16)
        : buckets_(bucketCount), size_(0) {}

    void put(const K& key, const V& value) {
        if ((size_ + 1.0) / buckets_.size() > maxLoadFactor_) {
            rehash(buckets_.size() * 2);
        }

        auto& bucket = buckets_[indexOf(key)];
        for (auto& [k, v] : bucket) {
            if (k == key) {
                v = value;
                return;
            }
        }
        bucket.push_back({key, value});
        ++size_;
    }

    bool get(const K& key, V& value) const {
        const auto& bucket = buckets_[indexOf(key)];
        for (const auto& [k, v] : bucket) {
            if (k == key) {
                value = v;
                return true;
            }
        }
        return false;
    }

    bool erase(const K& key) {
        auto& bucket = buckets_[indexOf(key)];
        for (auto it = bucket.begin(); it != bucket.end(); ++it) {
            if (it->first == key) {
                bucket.erase(it);
                --size_;
                return true;
            }
        }
        return false;
    }

private:
    size_t indexOf(const K& key) const {
        return hasher_(key) % buckets_.size();
    }

    void rehash(size_t newBucketCount) {
        vector<list<pair<K, V>>> newBuckets(newBucketCount);
        for (auto& bucket : buckets_) {
            for (auto& kv : bucket) {
                size_t idx = hasher_(kv.first) % newBucketCount;
                newBuckets[idx].push_back(std::move(kv));
            }
        }
        buckets_.swap(newBuckets);
    }

    vector<list<pair<K, V>>> buckets_;
    size_t size_;
    double maxLoadFactor_ = 0.75;
    Hash hasher_;
};
```

平均复杂度接近 `O(1)`，但冲突严重时桶内链表可能退化为 `O(n)`。工程上可以控制装载因子、优化哈希函数，或在链表过长时树化。

## 2. 简单线程安全：一把读写锁

最直接的线程安全方式是在整个 HashMap 上加 `shared_mutex`：

1. `get` 使用共享锁，允许多个读并发。
2. `put`、`erase`、`rehash` 使用独占锁。
3. 扩容时必须独占整个表，避免读线程访问正在搬迁的桶数组。

```cpp
template <typename K, typename V, typename Hash = std::hash<K>>
class ConcurrentHashMapSimple {
public:
    bool get(const K& key, V& value) const {
        shared_lock<shared_mutex> lk(mu_);
        return map_.get(key, value);
    }

    void put(const K& key, const V& value) {
        unique_lock<shared_mutex> lk(mu_);
        map_.put(key, value);
    }

    bool erase(const K& key) {
        unique_lock<shared_mutex> lk(mu_);
        return map_.erase(key);
    }

private:
    mutable shared_mutex mu_;
    HashMap<K, V, Hash> map_;
};
```

这种方式实现简单、正确性好，适合读多写少且并发量不极端的场景。缺点是写操作和扩容会阻塞所有读写。

## 3. 更高并发：分段锁或桶锁

如果并发写较多，可以把锁粒度缩小到分段：

```text
segment = hash(key) % segment_count
每个 segment 有自己的桶数组和锁
不同 segment 的 key 可以并发读写
```

分段锁要注意：

1. 每个 segment 独立计数和扩容，避免全表扩容阻塞所有线程。
2. 查询只锁目标 segment。
3. 统计全局 size 时要么遍历所有 segment，要么用原子计数。
4. 如果操作涉及多个 key，必须按 segment 编号固定加锁顺序，避免死锁。

桶锁也类似，但锁数量更多，内存开销更大。高性能实现还会结合开放寻址、RCU、读写锁、Hazard Pointer、Epoch GC 等机制。

## 4. 易错点

1. `std::vector` 扩容会移动桶数组，扩容期间不能让读线程无锁访问旧桶。
2. 只给链表节点加锁不够，桶数组 rehash 也必须同步。
3. 返回内部引用或迭代器会破坏线程安全，最好返回拷贝或让调用方持有锁句柄。
4. `size++` 要受锁保护或使用原子变量，但原子 size 不能替代结构修改锁。
5. 哈希函数和相等比较要一致：两个相等 key 必须能在同一查找逻辑下命中。

## 5. 如果要求按插入顺序遍历

普通 HashMap 只保证平均 `O(1)` 查找，不保证遍历顺序。如果题目要求“插入时解决冲突，并且遍历顺序和插入顺序一致”，可以使用 HashMap + 双向链表，也就是类似 `LinkedHashMap` 的结构：

```text
bucket array: key -> 链表节点迭代器
doubly linked list: 保存所有 key-value 的插入顺序
```

插入新 key 时，把节点追加到双向链表尾部，并把节点迭代器放入桶中；更新已有 key 时只改 value，默认不改变插入顺序；删除 key 时，同时从桶链和顺序链表中删除节点。这样查找、插入、删除平均仍是 `O(1)`，按插入顺序遍历是 `O(n)`。

线程安全版本要注意全局顺序链表会成为共享资源。最简单做法是全表读写锁；如果使用分段锁，仍然需要一个额外的全局顺序锁来保护链表追加和删除，否则不同 segment 的插入顺序无法一致。高并发场景下如果不强依赖全局顺序，应该避免这个需求，因为它会削弱分段锁的并发优势。

## 6. 真实场景选择

1. **低并发或面试手写**：链地址法 + 全局读写锁，逻辑清楚。
2. **读多写少配置缓存**：全局 `shared_mutex` 足够，或者用不可变快照 + 原子替换。
3. **高并发 KV 缓存**：分段锁、桶锁、读写锁或成熟并发容器。
4. **极致性能路径**：考虑 folly、TBB、absl 等成熟容器，不轻易自研无锁 HashMap。

## 7. 面试回答模板

我会先用桶数组加链表实现 HashMap，哈希到同一个桶的元素挂在链表里，装载因子超过阈值时 rehash 扩容。线程安全最简单是全表读写锁：读操作共享锁，写入、删除、扩容独占锁。更高并发可以做分段锁，每个 segment 独立维护桶和锁，降低写冲突。要特别注意 rehash 期间不能让读线程访问被移动的桶数组，返回内部引用也会破坏线程安全。
