# 渐进式哈希

渐进式哈希（Progressive Rehashing / Incremental Rehashing）是 Redis 字典扩容采用的策略。普通哈希表扩容时需要一次性把所有元素从旧表迁移到新表，遇到亿级数据量会卡住主线程。渐进式哈希将迁移分摊到多次操作中，每次只迁移少量桶，避免单次操作长时间阻塞。

## 核心思想

```text
普通 rehash：
  扩容时一次性把所有元素迁移到新表
  时间复杂度 O(N)，N 大时阻塞严重

渐进式 rehash：
  同时维护两个哈希表 ht[0] (旧) 和 ht[1] (新)
  设置 rehash_idx 记录当前迁移到哪个桶
  每次对字典的操作（增删改查）都顺便迁移 1 个桶
  迁移完成后释放 ht[0]，将 ht[1] 设为新的 ht[0]
```

## C++ 实现

```cpp
#include <vector>
#include <list>
#include <utility>
#include <functional>

template<typename K, typename V>
class ProgressiveHashMap {
private:
    using Bucket = std::list<std::pair<K, V>>;

    std::vector<Bucket> ht_[2];  // 两个哈希表
    int size_[2] = {0, 0};        // 各表元素数
    int rehash_idx_ = -1;         // -1 表示未在 rehash，否则是当前迁移到的桶

    size_t hash(const K& key, int table) const {
        return std::hash<K>{}(key) % ht_[table].size();
    }

    bool isRehashing() const { return rehash_idx_ != -1; }

    // 启动 rehash：分配新表
    void startRehash(size_t new_size) {
        ht_[1].clear();
        ht_[1].resize(new_size);
        rehash_idx_ = 0;
    }

    // 单步 rehash：迁移 n 个桶
    void rehashStep(int n = 1) {
        if (!isRehashing()) return;

        int empty_visited = 0;
        while (n > 0 && size_[0] > 0) {
            // 跳过空桶，避免无限循环
            while (rehash_idx_ < (int)ht_[0].size() &&
                   ht_[0][rehash_idx_].empty()) {
                rehash_idx_++;
                if (++empty_visited > 10) return;  // 单次最多访问 10 个空桶
            }
            if (rehash_idx_ >= (int)ht_[0].size()) break;

            // 迁移整个桶到 ht[1]
            for (auto& kv : ht_[0][rehash_idx_]) {
                size_t idx = hash(kv.first, 1);
                ht_[1][idx].push_back(std::move(kv));
                size_[1]++;
                size_[0]--;
            }
            ht_[0][rehash_idx_].clear();
            rehash_idx_++;
            n--;
        }

        // 迁移完成
        if (size_[0] == 0) {
            ht_[0] = std::move(ht_[1]);
            ht_[1].clear();
            rehash_idx_ = -1;
        }
    }

    // 检查是否需要扩容
    void checkExpand() {
        if (isRehashing()) return;
        double load = (double)size_[0] / ht_[0].size();
        if (load >= 1.0) {
            startRehash(ht_[0].size() * 2);
        }
    }

public:
    ProgressiveHashMap(size_t init_size = 16) {
        ht_[0].resize(init_size);
    }

    void put(const K& key, const V& val) {
        checkExpand();
        if (isRehashing()) rehashStep(1);  // 顺便迁移 1 个桶

        // 新元素插入到 ht[1]，老元素更新所在表
        int target = isRehashing() ? 1 : 0;

        // 先查找是否已存在（两个表都要查）
        for (int t = 0; t <= (isRehashing() ? 1 : 0); t++) {
            size_t idx = hash(key, t);
            for (auto& kv : ht_[t][idx]) {
                if (kv.first == key) {
                    kv.second = val;
                    return;
                }
            }
        }

        // 不存在则插入到目标表
        size_t idx = hash(key, target);
        ht_[target][idx].push_back({key, val});
        size_[target]++;
    }

    bool get(const K& key, V& val) {
        if (isRehashing()) rehashStep(1);

        // 两个表都要查
        for (int t = 0; t <= (isRehashing() ? 1 : 0); t++) {
            if (ht_[t].empty()) continue;
            size_t idx = hash(key, t);
            for (auto& kv : ht_[t][idx]) {
                if (kv.first == key) {
                    val = kv.second;
                    return true;
                }
            }
        }
        return false;
    }

    bool erase(const K& key) {
        if (isRehashing()) rehashStep(1);

        for (int t = 0; t <= (isRehashing() ? 1 : 0); t++) {
            if (ht_[t].empty()) continue;
            size_t idx = hash(key, t);
            auto& bucket = ht_[t][idx];
            for (auto it = bucket.begin(); it != bucket.end(); ++it) {
                if (it->first == key) {
                    bucket.erase(it);
                    size_[t]--;
                    return true;
                }
            }
        }
        return false;
    }

    int size() const { return size_[0] + size_[1]; }
};
```

## Redis 中的实现要点

```text
1. dict 结构维护 dictht ht[2] 两个表
2. rehashidx 记录迁移进度，-1 表示未 rehash
3. 触发条件:
   - 负载因子 >= 1 且未在做 BGSAVE/BGREWRITEAOF
   - 负载因子 >= 5（强制 rehash）
4. 每次 dict 操作触发 _dictRehashStep（迁移 1 个桶）
5. serverCron 定时任务也会主动 rehash 1ms
6. 查找时两个表都要查，先 ht[0] 再 ht[1]
7. 新元素一律插入 ht[1]，保证 ht[0] 元素只减不增
```

## 易错点

```text
1. 必须同时维护两个表的查找/删除逻辑
2. 新增元素插入到 ht[1]，否则永远无法完成迁移
3. 空桶要跳过，但单次跳过数量要有上限避免长时间阻塞
4. rehash 完成后要正确释放 ht[0] 并交换
5. 并发场景下要加锁保护 rehash_idx 和两个表
6. 缩容也用渐进式 rehash（负载因子过低时）
```

## 复杂度分析

```text
单次操作: O(1) 摊销（增删改查 + 1 次桶迁移）
总迁移时间: O(N)，但摊销到 N 次操作中
内存峰值: O(N)，因为同时维护新旧两个表
```

## 应用场景

```text
1. Redis 字典扩容（最经典）
2. 大型缓存系统的扩容
3. 任何不能接受单次长阻塞的哈希表场景
4. 在线数据迁移（数据库扩容、分片重平衡）
```

面试核心：理解 "把 O(N) 一次性操作分摊到 N 次 O(1) 操作中" 的思想，能讲清楚两表共存期间的查找/插入/删除逻辑。
