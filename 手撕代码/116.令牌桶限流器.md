# 116. 令牌桶限流器

## 题目

实现一个简易令牌桶：桶容量为 `capacity`，令牌按 `rate` 个/秒生成。每个请求消耗一个令牌，令牌足够则放行，否则拒绝。

## 思路

不需要后台线程定时加令牌。请求到来时根据当前时间和上次刷新时间计算应该补充多少令牌：

```text
tokens = min(capacity, tokens + elapsed * rate)
```

然后判断 `tokens >= cost`。

## C++ 代码

```cpp
#include <algorithm>
#include <chrono>
#include <mutex>

class TokenBucket {
public:
    TokenBucket(double capacity, double rate)
        : capacity_(capacity),
          tokens_(capacity),
          rate_(rate),
          last_(Clock::now()) {}

    bool allow(double cost = 1.0) {
        std::lock_guard<std::mutex> guard(mu_);
        refill();
        if (tokens_ < cost) {
            return false;
        }
        tokens_ -= cost;
        return true;
    }

private:
    using Clock = std::chrono::steady_clock;

    void refill() {
        auto now = Clock::now();
        std::chrono::duration<double> elapsed = now - last_;
        tokens_ = std::min(capacity_, tokens_ + elapsed.count() * rate_);
        last_ = now;
    }

    std::mutex mu_;
    double capacity_;
    double tokens_;
    double rate_;
    Clock::time_point last_;
};
```

## 易错点

1. 用 `steady_clock`，不要用可被系统校时调整的墙上时间。
2. 多线程下 `tokens` 和 `last` 必须一起加锁或用原子 CAS 设计。
3. 桶容量控制突发流量，补充速率控制平均流量。
4. 分布式限流要用 Redis Lua、网关或集中式限流服务，不能靠每台机器各自本地桶。

## 面试回答模板

令牌桶的核心是按固定速率补充令牌，请求到来时先根据时间差惰性补充，再消耗令牌。容量决定最大突发，速率决定长期平均 QPS。相比漏桶，令牌桶允许短时突发；相比滑动窗口，它实现简单、内存少，但窗口内精确性较弱。
