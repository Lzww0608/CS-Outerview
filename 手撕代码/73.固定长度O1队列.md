# 固定长度 O(1) 队列

固定长度队列要求 `push` 和 `pop` 都是 `O(1)`，最常见实现是环形数组，也叫 circular buffer 或 ring buffer。

## 1. 核心思路

维护一个固定大小数组和两个指针：

1. `head` 指向队头元素。
2. `tail` 指向下一个可写位置。
3. `size` 记录当前元素数量。

每次移动指针都取模：

```text
next = (idx + 1) % capacity
```

这样数组尾部用完后可以回到数组头部，避免移动元素。

## 2. C++ 实现

```cpp
#include <stdexcept>
#include <vector>

template <class T>
class FixedQueue {
public:
    explicit FixedQueue(size_t capacity)
        : data_(capacity), capacity_(capacity) {
        if (capacity == 0) {
            throw std::invalid_argument("capacity must be positive");
        }
    }

    bool push(const T& value) {
        if (full()) {
            return false;
        }
        data_[tail_] = value;
        tail_ = (tail_ + 1) % capacity_;
        ++size_;
        return true;
    }

    bool pop(T& out) {
        if (empty()) {
            return false;
        }
        out = data_[head_];
        head_ = (head_ + 1) % capacity_;
        --size_;
        return true;
    }

    bool empty() const {
        return size_ == 0;
    }

    bool full() const {
        return size_ == capacity_;
    }

    size_t size() const {
        return size_;
    }

private:
    std::vector<T> data_;
    size_t capacity_ = 0;
    size_t head_ = 0;
    size_t tail_ = 0;
    size_t size_ = 0;
};
```

## 3. 支持 pushAll 的环形缓冲区

如果题目要求 `pushAll`，要先明确语义：容量不足时是全部失败、能写多少写多少，还是覆盖旧数据。面试里最稳妥的是提供“尽可能写入，返回实际写入数量”的非阻塞接口。

下面实现支持 `push`、`pop` 和 `pushAll`：

```cpp
#include <algorithm>
#include <cstddef>
#include <stdexcept>
#include <vector>

template <class T>
class RingBuffer {
public:
    explicit RingBuffer(size_t capacity)
        : data_(capacity), capacity_(capacity) {
        if (capacity == 0) {
            throw std::invalid_argument("capacity must be positive");
        }
    }

    bool push(const T& value) {
        return pushAll(&value, 1) == 1;
    }

    size_t pushAll(const T* values, size_t count) {
        if (values == nullptr || count == 0) {
            return 0;
        }

        size_t n = std::min(count, capacity_ - size_);
        size_t first = std::min(n, capacity_ - tail_);
        std::copy(values, values + first, data_.begin() + static_cast<std::ptrdiff_t>(tail_));
        std::copy(values + first, values + n, data_.begin());

        tail_ = (tail_ + n) % capacity_;
        size_ += n;
        return n;
    }

    bool pop(T& out) {
        if (empty()) {
            return false;
        }
        out = data_[head_];
        head_ = (head_ + 1) % capacity_;
        --size_;
        return true;
    }

    bool empty() const {
        return size_ == 0;
    }

    bool full() const {
        return size_ == capacity_;
    }

    size_t size() const {
        return size_;
    }

private:
    std::vector<T> data_;
    size_t capacity_ = 0;
    size_t head_ = 0;
    size_t tail_ = 0;
    size_t size_ = 0;
};
```

`pushAll` 的核心是处理“尾部连续空间不够，需要从数组头继续写”的情况：

```text
可写数量 n = min(count, capacity - size)
第一段写 [tail, capacity)
第二段写 [0, 剩余数量)
tail = (tail + n) % capacity
```

易错点：

1. `pushAll` 要返回实际写入数量，否则调用方不知道是否发生截断。
2. 写入跨越数组尾部时要拆成两段，不能一次线性拷贝。
3. `pushAll` 和 `pop` 如果并发调用，需要锁或 SPSC/MPMC 无锁设计；单线程环形缓冲区本身不线程安全。
4. 对复杂对象批量写入时，要考虑拷贝异常和对象生命周期；底层高性能实现常用未初始化存储和 placement new。

## 4. 为什么是 O(1)

1. `push` 只写入 `tail` 位置并移动 `tail`。
2. `pop` 只读取 `head` 位置并移动 `head`。
3. 不需要搬移数组元素。
4. 空间提前分配，容量固定，不发生扩容。

`pushAll` 对单个元素不是 `O(1)`，它的复杂度是 `O(k)`，`k` 是实际写入数量；但相比循环调用 `push`，它可以减少分支判断和取模次数，适合网络收包、日志批量写入、音视频帧批量缓存等场景。

## 5. 判空和判满

常见两种设计：

1. **维护 `size`**：`size == 0` 为空，`size == capacity` 为满。实现直观，但多维护一个字段。
2. **浪费一个槽位**：`head == tail` 为空，`(tail + 1) % capacity == head` 为满。实现常见于底层 ring buffer，但可用容量是 `capacity - 1`。

面试手写时维护 `size` 最不容易出错。

## 6. 真实场景

1. 生产者消费者队列。
2. 网络收发缓冲区。
3. 日志异步队列。
4. 音视频帧缓冲。
5. 嵌入式系统的固定内存消息队列。

多线程场景下，普通环形队列还需要加锁或使用原子变量。单生产者单消费者可以用 SPSC 无锁 ring buffer；多生产者多消费者需要更复杂的序号、CAS 和内存序设计。

## 7. Go 并发安全实现

如果面试要求“支持并发安全的入队和出队”，最稳妥的手写方案是环形数组加 `mutex + condition variable`。锁保护 `head/tail/size`，队列满时生产者等待 `notFull`，队列空时消费者等待 `notEmpty`。

```go
package queue

import "sync"

type CircularQueue[T any] struct {
    mu       sync.Mutex
    notEmpty *sync.Cond
    notFull  *sync.Cond

    buf        []T
    head, tail int
    size       int
}

func NewCircularQueue[T any](capacity int) *CircularQueue[T] {
    if capacity <= 0 {
        panic("capacity must be positive")
    }
    q := &CircularQueue[T]{buf: make([]T, capacity)}
    q.notEmpty = sync.NewCond(&q.mu)
    q.notFull = sync.NewCond(&q.mu)
    return q
}

func (q *CircularQueue[T]) Enqueue(v T) {
    q.mu.Lock()
    defer q.mu.Unlock()

    for q.size == len(q.buf) {
        q.notFull.Wait()
    }
    q.buf[q.tail] = v
    q.tail = (q.tail + 1) % len(q.buf)
    q.size++
    q.notEmpty.Signal()
}

func (q *CircularQueue[T]) Dequeue() T {
    q.mu.Lock()
    defer q.mu.Unlock()

    for q.size == 0 {
        q.notEmpty.Wait()
    }
    v := q.buf[q.head]
    var zero T
    q.buf[q.head] = zero // 避免引用类型元素长期占用内存
    q.head = (q.head + 1) % len(q.buf)
    q.size--
    q.notFull.Signal()
    return v
}
```

注意点：

1. `Cond.Wait()` 必须放在 `for` 循环里，防止虚假唤醒或被唤醒后条件已被其他 goroutine 改变。
2. 入队、出队仍然是 `O(1)`，但并发下会有锁竞争。
3. 如果只要求非阻塞接口，可以在队满或队空时直接返回 `false`，不使用条件变量。
4. 高性能 SPSC 队列可以用原子变量实现，但 MPMC 无锁队列要处理 ABA、内存序和缓存行伪共享，面试手写不建议直接展开。

## 8. 面试回答模板

固定长度、`push/pop` 都要求 `O(1)`，我会用环形数组实现。数组容量固定，维护 `head`、`tail` 和 `size`，入队写 `tail` 后 `tail = (tail + 1) % capacity`，出队读 `head` 后同样取模移动，不移动元素，所以时间复杂度是 `O(1)`。如果有 `pushAll`，我会先定义容量不足时的语义，通常返回实际写入数量；实现时按尾部剩余空间拆成两段拷贝，再一次性更新 `tail` 和 `size`。如果追问并发，再说明单线程版本不线程安全，多线程要加 mutex，或者在 SPSC 场景下用无锁 ring buffer。
