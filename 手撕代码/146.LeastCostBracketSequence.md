# 146. Least Cost Bracket Sequence

题目常见版本：给定一个括号串，字符可能是 `'('`、`')'` 或 `'?'`。每个 `'?'` 替换成 `'('` 有成本 `a`，替换成 `')'` 有成本 `b`，要求得到合法括号序列，并使总代价最小；如果无解，返回 `-1`。

## 1. 贪心思路

先把所有 `'?'` 都当成 `')'`，这样初始成本最低或至少有统一基准。扫描字符串时维护括号平衡值 `balance`：

1. `'('` 让 `balance++`。
2. `')'` 让 `balance--`。
3. `'?'` 先替换成 `')'`，成本加 `b`，`balance--`，同时记录如果把它改成 `'('` 需要额外增加的成本 `a - b`。

合法括号序列要求任意前缀 `balance >= 0`，最终 `balance == 0`。如果扫描过程中 `balance < 0`，说明当前右括号太多，必须从之前见过的 `'?'` 中挑一个改成 `'('`。为了总代价最小，应该选择额外成本 `a - b` 最小的那个 `'?'` 翻转。

翻转一次会让该位置从 `')'` 变为 `'('`，因此当前和后续前缀的 `balance` 增加 `2`。

## 2. C++ 实现

```cpp
#include <functional>
#include <queue>
#include <string>
#include <utility>
#include <vector>
using namespace std;

long long leastCostBracketSequence(
    string& s,
    const vector<int>& leftCost,
    const vector<int>& rightCost
) {
    priority_queue<
        pair<int, int>,
        vector<pair<int, int>>,
        greater<pair<int, int>>
    > candidates; // {extraCost, index}

    long long cost = 0;
    int balance = 0;
    int qid = 0;

    for (int i = 0; i < (int)s.size(); ++i) {
        if (s[i] == '(') {
            ++balance;
        } else if (s[i] == ')') {
            --balance;
        } else {
            int a = leftCost[qid];
            int b = rightCost[qid];
            ++qid;

            s[i] = ')';
            cost += b;
            --balance;
            candidates.push({a - b, i});
        }

        if (balance < 0) {
            if (candidates.empty()) {
                return -1;
            }
            auto [extra, idx] = candidates.top();
            candidates.pop();
            s[idx] = '(';
            cost += extra;
            balance += 2;
        }
    }

    return balance == 0 ? cost : -1;
}
```

复杂度：每个 `'?'` 最多入堆、出堆一次，时间复杂度 `O(n log n)`，空间复杂度 `O(n)`。

## 3. 为什么贪心正确

当某个前缀 `balance < 0` 时，如果不把这个前缀中的某个 `'?'` 改成 `'('`，当前前缀必然非法，后面的字符无法修复已经非法的前缀。因此必须立即翻转一个已经出现过的 `'?'`。

在所有可翻转候选中，翻转任意一个对当前和后续 `balance` 的贡献都是 `+2`，唯一差异是额外成本 `a - b`。所以选择额外成本最小的候选不会更差，局部最优可以安全地累积成全局最优。

## 4. 易错点

1. 最终 `balance != 0` 也无解，即使扫描过程中没有负数。
2. 堆里只能放已经扫描过的 `'?'`，因为未来的 `'?'` 不能修复当前非法前缀。
3. 额外成本 `a - b` 可能为负数，表示改成 `'('` 反而更便宜，堆仍然适用。
4. 如果字符串长度是奇数，可以提前返回无解。
5. 成本可能很大，总代价建议用 `long long`。

## 5. 面试回答模板

我会先把所有问号都替换成右括号，并把右括号成本加入答案，同时把每个问号改成左括号的额外成本 `a-b` 放进小根堆。扫描过程中维护括号平衡值，如果某个前缀平衡值变成负数，说明必须把之前的某个问号改成左括号才能修复前缀，此时选择小根堆里额外成本最小的那个翻转，平衡值加 2。最后如果平衡值为 0 就得到最小成本，否则无解。
