# 固定容量最大值广告缓存

题目：本地缓存最多保存 `N` 条广告数据，插入超过容量时淘汰最早进入的数据，同时要求快速查询当前 value 最大的广告。

## 1. 核心思路

这个问题同时有两个要求：

1. 按进入时间淘汰最老元素。
2. `O(1)` 查询当前最大值。

可以组合两个队列：

```text
普通队列 q：保存真实插入顺序，用来淘汰最老元素
单调队列 maxq：按 value 从大到小保存候选最大值
```

插入新元素时，先从 `maxq` 尾部弹出所有 value 小于等于新元素的节点，因为这些旧节点既更早过期，值又不大，不可能再成为最大值。然后把新元素放入 `q` 和 `maxq`。当容量超过 `N` 时，从 `q` 头部淘汰最老元素；如果它正好也是 `maxq` 的头部，就同步弹出。

## 2. C++ 实现

```cpp
#include <cstddef>
#include <deque>
#include <optional>

struct AdItem {
    long long id;
    int value;
};

class FixedAdCache {
public:
    explicit FixedAdCache(size_t capacity) : capacity_(capacity) {}

    void push(int value) {
        if (capacity_ == 0) {
            return;
        }

        AdItem item{nextId_++, value};
        q_.push_back(item);

        while (!maxq_.empty() && maxq_.back().value <= value) {
            maxq_.pop_back();
        }
        maxq_.push_back(item);

        if (q_.size() > capacity_) {
            AdItem expired = q_.front();
            q_.pop_front();
            if (!maxq_.empty() && maxq_.front().id == expired.id) {
                maxq_.pop_front();
            }
        }
    }

    std::optional<int> maxValue() const {
        if (maxq_.empty()) {
            return std::nullopt;
        }
        return maxq_.front().value;
    }

private:
    size_t capacity_;
    long long nextId_ = 0;
    std::deque<AdItem> q_;
    std::deque<AdItem> maxq_;
};
```

每个元素最多入队、出队一次，所以插入的摊还复杂度是 `O(1)`，查询最大值是 `O(1)`，空间复杂度是 `O(N)`。

## 3. 易错点

1. 不能只用一个普通队列，否则查询最大值要扫描 `O(N)`。
2. 单调队列里需要保存唯一 `id`，只比较 value 会误删重复值。
3. 使用 `<=` 弹出尾部旧值可以让相同 value 保留最新元素，减少过期判断压力；使用 `<` 也可以，但要保留更多重复候选。
4. 如果缓存还要按广告 ID 更新或删除，需要额外 HashMap 记录有效性，单调队列弹出时跳过已经失效的节点。
5. 多线程读写本地缓存时，要用互斥锁或读写锁保护两个队列的一致性。

## 4. 真实场景应用

广告系统、本地热点配置和排行榜小窗口缓存里，经常要在容量受限时保留最近数据，并快速取最高优先级对象。这个结构适合“只追加、按时间淘汰、查询窗口最大值”的场景；如果需要按任意 key 删除、按分数排序分页，则应考虑 `std::map`、堆 + 懒删除或 Redis zset。

## 5. 面试回答模板

我会用普通队列维护插入顺序，用单调递减队列维护最大值候选。插入新元素时，把单调队列尾部所有不大于新值的元素弹掉，再插入新值；容量超限时从普通队列头部淘汰，如果被淘汰元素也是单调队列头部，就同步弹出。这样插入摊还 `O(1)`，查询最大值 `O(1)`，空间 `O(N)`。
