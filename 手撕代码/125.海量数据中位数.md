# 125. 海量数据中位数

## 题目

有大量整数数据，单机内存无法全部装下，如何求中位数？

## 方案一：外部排序

如果需要精确中位数，最直接方案是外部排序：

1. 把数据切成内存能处理的小块。
2. 每块读入内存排序，写成有序临时文件。
3. 对所有有序文件做多路归并。
4. 归并到第 `n/2` 个元素时得到中位数，不必输出完整排序结果。

优点是精确、通用；缺点是磁盘 I/O 成本高。

## 方案二：值域分桶

如果整数值域有限，例如 32 位整数，可以按高位分桶：

1. 第一遍扫描，按高 16 位统计每个桶数量。
2. 根据累计数量找到中位数所在桶。
3. 第二遍只处理该桶内数据，再按低 16 位计数或排序。
4. 通过桶内偏移找到精确中位数。

这种方法本质是用值域换内存，适合整数、IP、时间戳这类可分桶数据。

## 方案三：分布式处理

数据分散在多台机器时：

1. 每台机器先统计本地数量、最小值、最大值或本地直方图。
2. 协调节点合并直方图，定位目标值域。
3. 各机器再次过滤目标值域内数据，继续细分或返回候选。
4. 最终在候选集合内求精确中位数。

如果允许近似，可以用 t-digest、KLL sketch、GK quantile summary 等分位数摘要，内存更小，适合监控和实时分析。

## 易错点

1. TopK 小根堆适合求前 K 大，但中位数 K 可能是 `n/2`，堆会占用太多内存。
2. 如果数据总量未知，要先统计数量或使用近似分位数结构。
3. 分桶要处理负数，可以偏移到无符号空间，或按补码有序映射。
4. 分布式场景要关注数据倾斜，目标桶过大时继续二级分桶。

## 面试回答模板

精确中位数可以用外部排序或值域分桶。外部排序把数据切块排序后多路归并，归并到第 `n/2` 个即可；如果是整数值域，可以先按高位分桶统计数量，定位中位数所在桶，再对这个桶二次分桶或排序。分布式时各机器先统计直方图，协调节点合并定位目标区间，再让各机器返回候选。若业务允许近似，可以用 t-digest 或 KLL 这类分位数摘要。
