# 126. 定长数组实现 KV 缓存

## 题目

只给一个定长一维数组，实现一个简单 key-value 缓存。要求支持 `put/get/delete`，并说明哈希冲突和空间不足时怎么处理。

## 思路

如果不能使用链表和额外动态内存，可以使用开放寻址。最简单的是线性探测：

```text
idx = hash(key) % capacity
冲突时 idx = (idx + 1) % capacity
```

删除不能直接把槽位设为空，否则会截断后续探测链。需要使用三态标记：

1. `EMPTY`：从未使用。
2. `USED`：当前有数据。
3. `DELETED`：曾经使用过，后来删除。

## C++ 简化实现

```cpp
#include <functional>
#include <optional>
#include <string>
#include <vector>
using namespace std;

class FixedKVCache {
public:
    explicit FixedKVCache(size_t cap) : table_(cap) {}

    bool put(const string& key, int value) {
        if (table_.empty()) return false;
        size_t firstDeleted = table_.size();
        size_t start = hash<string>{}(key) % table_.size();

        for (size_t step = 0; step < table_.size(); ++step) {
            size_t idx = (start + step) % table_.size();
            Slot& s = table_[idx];

            if (s.state == USED && s.key == key) {
                s.value = value;
                return true;
            }
            if (s.state == DELETED && firstDeleted == table_.size()) {
                firstDeleted = idx;
            }
            if (s.state == EMPTY) {
                size_t target = (firstDeleted == table_.size()) ? idx : firstDeleted;
                table_[target] = Slot{USED, key, value};
                ++size_;
                return true;
            }
        }

        if (firstDeleted != table_.size()) {
            table_[firstDeleted] = Slot{USED, key, value};
            ++size_;
            return true;
        }
        return false; // 空间真的满了
    }

    optional<int> get(const string& key) const {
        if (table_.empty()) return nullopt;
        size_t start = hash<string>{}(key) % table_.size();
        for (size_t step = 0; step < table_.size(); ++step) {
            const Slot& s = table_[(start + step) % table_.size()];
            if (s.state == EMPTY) return nullopt;
            if (s.state == USED && s.key == key) return s.value;
        }
        return nullopt;
    }

    bool erase(const string& key) {
        if (table_.empty()) return false;
        size_t start = hash<string>{}(key) % table_.size();
        for (size_t step = 0; step < table_.size(); ++step) {
            Slot& s = table_[(start + step) % table_.size()];
            if (s.state == EMPTY) return false;
            if (s.state == USED && s.key == key) {
                s.state = DELETED;
                s.key.clear();
                --size_;
                return true;
            }
        }
        return false;
    }

private:
    enum State { EMPTY, USED, DELETED };
    struct Slot {
        State state = EMPTY;
        string key;
        int value = 0;
    };

    vector<Slot> table_;
    size_t size_ = 0;
};
```

## 空间不够怎么办

定长数组没有扩容能力时，必须提前定义策略：

1. **返回失败**：适合缓存外还有权威数据源的场景。
2. **淘汰旧数据**：结合 FIFO、LRU、LFU 或随机淘汰，但需要额外元数据。
3. **限制负载因子**：开放寻址负载因子太高后探测长度急剧上升，通常超过 0.7 就要扩容或拒绝写入。
4. **分段/多表**：多组固定数组降低冲突，但本质仍需要容量规划。

如果允许动态内存，链地址法更容易处理高冲突；如果必须固定数组，开放寻址更符合约束。

## 易错点

1. 删除不能直接置空，要用 tombstone。
2. 线性探测容易形成聚集，冲突严重时性能退化。
3. 查询遇到 `DELETED` 不能停，遇到 `EMPTY` 才能停。
4. 缓存不是数据库，空间满时可以拒绝或淘汰，但要保证返回语义清晰。
