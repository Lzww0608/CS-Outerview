# 任务依赖调度器实现

## 题目描述
给定一组任务 tasks，每个任务包含：
- id：任务的唯一标识。
- action：一个返回 Promise 的异步函数，代表任务的执行逻辑。
- deps：一个字符串数组，代表该任务依赖的其他任务 id。

要求:
1. **执行顺序**：只有当一个任务的所有依赖任务都执行完成后，该任务才能开始执行。如果没有依赖（deps 为空），则该任务为 “入口任务”，可以立即执行。
2. **并行性**：在满足依赖条件的情况下，尽可能多地并行执行任务（例如：A 和 B 互不依赖，它们应该同时启动）。
3. **输出结果**：函数执行完毕后，返回一个 Map，其中 key 是任务 id，value 是 action 执行后的结果。
4. **异常处理**：如果任务之间存在循环依赖，导致无法完成所有任务，请抛出错误。

---

## 题目分析

### 核心需求
给定一组任务，每个任务包含：
- **id**：任务唯一标识
- **action**：异步执行函数，返回Promise
- **deps**：依赖的其他任务id数组

要求：
1. **依赖执行**：任务必须在所有依赖完成后才能执行
2. **最大并行**：无依赖的任务同时执行
3. **结果返回**：返回Map<taskId, result>
4. **异常处理**：检测循环依赖并抛出错误

### 核心算法
这是典型的**有向无环图(DAG)拓扑排序**问题：
1. **节点**：每个任务是图的节点
2. **边**：依赖关系A→B表示A必须在B之前执行
3. **入度**：每个任务剩余未完成的依赖数量
4. **拓扑排序**：得到合法的执行顺序
5. **并发执行**：在满足依赖的前提下并行执行任务

### 复杂度分析
- **时间复杂度**：O(N + E)，N是任务数，E是依赖边数
- **空间复杂度**：O(N)，存储入度、邻接表、结果Map

## C++ 实现

### 实现思路
C++20提供了协程和`std::future`，我们使用：
- `std::unordered_map`存储任务、入度、邻接表、结果
- `std::queue`维护就绪队列（入度为0的任务）
- `std::async`并行执行任务
- 拓扑排序检测循环依赖

```cpp
#include <iostream>
#include <vector>
#include <unordered_map>
#include <unordered_set>
#include <queue>
#include <future>
#include <stdexcept>
#include <string>
#include <any>

using namespace std;

// 任务结构体
struct Task {
    string id;
    function<any()> action; // 同步版，也可以用future版
    vector<string> deps;
};

class TaskScheduler {
public:
    unordered_map<string, any> run(const vector<Task>& tasks) {
        // 1. 构建图和入度表
        unordered_map<string, int> in_degree;
        unordered_map<string, vector<string>> adj; // 邻接表：u→v表示u是v的依赖
        unordered_map<string, function<any()>> task_map;

        // 初始化
        for (const auto& task : tasks) {
            task_map[task.id] = task.action;
            in_degree[task.id] = task.deps.size();
            for (const auto& dep : task.deps) {
                adj[dep].push_back(task.id);
                // 检查依赖是否存在
                if (!task_map.count(dep) && !in_degree.count(dep)) {
                    throw invalid_argument("Task " + dep + " not found");
                }
            }
        }

        // 2. 拓扑排序检测循环依赖
        queue<string> q;
        unordered_map<string, int> temp_in = in_degree;
        int count = 0;

        for (const auto& [id, deg] : temp_in) {
            if (deg == 0) q.push(id);
        }

        while (!q.empty()) {
            auto u = q.front(); q.pop();
            count++;
            for (const auto& v : adj[u]) {
                if (--temp_in[v] == 0) q.push(v);
            }
        }

        if (count != tasks.size()) {
            throw runtime_error("Circular dependency detected");
        }

        // 3. 并发执行任务
        unordered_map<string, any> results;
        unordered_map<string, shared_future<any>> futures;
        queue<string> ready_queue;

        // 重置入度
        for (const auto& [id, deg] : in_degree) {
            if (deg == 0) ready_queue.push(id);
        }

        mutex mtx;
        condition_variable cv;
        atomic<int> completed = 0;

        // 工作线程函数
        auto worker = [&]() {
            while (completed < tasks.size()) {
                unique_lock<mutex> lock(mtx);
                cv.wait(lock, [&]() { return !ready_queue.empty() || completed == tasks.size(); });
                
                if (completed == tasks.size()) break;
                if (ready_queue.empty()) continue;

                string task_id = ready_queue.front();
                ready_queue.pop();
                lock.unlock();

                // 执行任务
                any result = task_map[task_id]();

                lock.lock();
                results[task_id] = result;
                completed++;

                // 更新依赖该任务的其他任务的入度
                for (const auto& v : adj[task_id]) {
                    if (--in_degree[v] == 0) {
                        ready_queue.push(v);
                    }
                }

                cv.notify_all();
            }
        };

        // 启动多个工作线程（和CPU核心数一致）
        int num_threads = thread::hardware_concurrency();
        vector<thread> threads;
        for (int i = 0; i < num_threads; i++) {
            threads.emplace_back(worker);
        }

        // 等待所有线程完成
        for (auto& t : threads) {
            t.join();
        }

        return results;
    }
};

// 测试用例
int main() {
    try {
        // 测试1：正常依赖
        vector<Task> tasks1 = {
            {"A", []() { return 1; }, {}},
            {"B", []() { return 2; }, {}},
            {"C", []() { return 3; }, {"A", "B"}},
            {"D", []() { return 4; }, {"C"}}
        };

        TaskScheduler scheduler;
        auto res1 = scheduler.run(tasks1);
        cout << "Test 1 results:" << endl;
        cout << "A: " << any_cast<int>(res1["A"]) << endl;
        cout << "B: " << any_cast<int>(res1["B"]) << endl;
        cout << "C: " << any_cast<int>(res1["C"]) << endl;
        cout << "D: " << any_cast<int>(res1["D"]) << endl;

        // 测试2：循环依赖
        vector<Task> tasks2 = {
            {"A", []() { return 1; }, {"B"}},
            {"B", []() { return 2; }, {"A"}}
        };
        auto res2 = scheduler.run(tasks2); // 应该抛出异常
    } catch (const exception& e) {
        cout << "Error: " << e.what() << endl;
    }

    return 0;
}
```

## Golang 实现

### 实现思路
Go原生支持goroutine和channel，实现更简洁：
- 使用`sync.WaitGroup`等待所有任务完成
- 使用`sync.Mutex`保护共享资源
- 使用goroutine并行执行任务
- 拓扑排序检测循环依赖

```go
package main

import (
	"errors"
	"fmt"
	"sync"
)

// Task 任务结构体
type Task struct {
	ID     string
	Action func() interface{}
	Deps   []string
}

// TaskScheduler 调度器
type TaskScheduler struct {
	tasks   map[string]Task
	inDegree map[string]int
	adj     map[string][]string
	results map[string]interface{}
	wg      sync.WaitGroup
	mu      sync.Mutex
}

func NewTaskScheduler() *TaskScheduler {
	return &TaskScheduler{
		tasks:   make(map[string]Task),
		inDegree: make(map[string]int),
		adj:     make(map[string][]string),
		results: make(map[string]interface{}),
	}
}

// Run 执行任务
func (s *TaskScheduler) Run(tasks []Task) (map[string]interface{}, error) {
	// 1. 初始化数据结构
	for _, task := range tasks {
		s.tasks[task.ID] = task
		s.inDegree[task.ID] = len(task.Deps)
		for _, dep := range task.Deps {
			s.adj[dep] = append(s.adj[dep], task.ID)
		}
	}

	// 2. 检测循环依赖（拓扑排序）
	tempIn := make(map[string]int)
	for k, v := range s.inDegree {
		tempIn[k] = v
	}

	queue := []string{}
	for id, deg := range tempIn {
		if deg == 0 {
			queue = append(queue, id)
		}
	}

	count := 0
	for len(queue) > 0 {
		u := queue[0]
		queue = queue[1:]
		count++
		for _, v := range s.adj[u] {
			tempIn[v]--
			if tempIn[v] == 0 {
				queue = append(queue, v)
			}
		}
	}

	if count != len(tasks) {
		return nil, errors.New("circular dependency detected")
	}

	// 3. 并发执行任务
	readyChan := make(chan string, len(tasks))
	for id, deg := range s.inDegree {
		if deg == 0 {
			readyChan <- id
			s.wg.Add(1)
		}
	}

	// 启动工作协程
	workerNum := 4 // 可以调整
	for i := 0; i < workerNum; i++ {
		go s.worker(readyChan)
	}

	s.wg.Wait()
	close(readyChan)

	return s.results, nil
}

// worker 工作协程
func (s *TaskScheduler) worker(readyChan chan string) {
	for taskID := range readyChan {
		// 执行任务
		result := s.tasks[taskID].Action()

		s.mu.Lock()
		s.results[taskID] = result

		// 更新依赖该任务的其他任务的入度
		for _, v := range s.adj[taskID] {
			s.inDegree[v]--
			if s.inDegree[v] == 0 {
				s.wg.Add(1)
				readyChan <- v
			}
		}

		s.mu.Unlock()
		s.wg.Done()
	}
}

func main() {
	// 测试1：正常依赖
	tasks1 := []Task{
		{
			ID:     "A",
			Action: func() interface{} { return 1 },
			Deps:   []string{},
		},
		{
			ID:     "B",
			Action: func() interface{} { return 2 },
			Deps:   []string{},
		},
		{
			ID:     "C",
			Action: func() interface{} { return 3 },
			Deps:   []string{"A", "B"},
		},
		{
			ID:     "D",
			Action: func() interface{} { return 4 },
			Deps:   []string{"C"},
		},
	}

	scheduler := NewTaskScheduler()
	res1, err := scheduler.Run(tasks1)
	if err != nil {
		fmt.Printf("Error: %v\n", err)
		return
	}

	fmt.Println("Test 1 results:")
	fmt.Printf("A: %v\n", res1["A"])
	fmt.Printf("B: %v\n", res1["B"])
	fmt.Printf("C: %v\n", res1["C"])
	fmt.Printf("D: %v\n", res1["D"])

	// 测试2：循环依赖
	tasks2 := []Task{
		{
			ID:     "A",
			Action: func() interface{} { return 1 },
			Deps:   []string{"B"},
		},
		{
			ID:     "B",
			Action: func() interface{} { return 2 },
			Deps:   []string{"A"},
		},
	}

	scheduler2 := NewTaskScheduler()
	res2, err := scheduler2.Run(tasks2)
	if err != nil {
		fmt.Printf("Test 2 expected error: %v\n", err)
	} else {
		fmt.Println("Test 2 failed: no error detected")
	}
}
```

## 核心考点总结

### 1. 数据结构设计
- **入度表**：记录每个任务剩余未完成的依赖数
- **邻接表**：记录任务的后继任务（依赖该任务的其他任务）
- **就绪队列**：存储可以立即执行的任务（入度为0）
- **结果Map**：存储任务执行结果

### 2. 关键算法
- **拓扑排序**：检测循环依赖，判断是否存在合法执行顺序
- **生产者-消费者模型**：多个工作线程/协程从就绪队列取任务执行
- **同步机制**：互斥锁保护共享资源，条件变量/channel通知就绪任务

### 3. 常见优化
- **动态调整并行度**：根据CPU核心数调整工作线程数
- **任务优先级**：为高优先级任务分配更多资源
- **失败重试**：任务执行失败时重试机制
- **超时控制**：防止单个任务执行过长阻塞整个流程

### 4. 面试常见问题
- Q: 如何检测循环依赖？
  A: 拓扑排序，如果最终执行的任务数不等于总任务数，说明存在环
- Q: 如何保证最大并行度？
  A: 就绪队列中任务一出现就立即执行，没有顺序限制
- Q: 如何处理任务执行异常？
  A: 可以实现中断机制，某个任务失败时终止所有相关任务或标记失败
- Q: 时间复杂度是多少？
  A: O(N + E)，N是任务数，E是依赖边数
