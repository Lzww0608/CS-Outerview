# 165. 40 亿 32 位整数存在性判断

题目：有 40 亿个随机排列的 32 位整数，判断目标 `X` 是否存在，内存限制 1GB。

## 1. 核心思路

32 位整数的取值空间最多是 `2^32`。用一个 bit 表示某个整数是否出现，需要：

```text
2^32 bit = 2^29 byte = 512 MB
```

1GB 内存足够放下一个完整位图。因此可以流式读取输入，把每个整数映射到位图下标并置位，最后检查 `X` 对应 bit。

## 2. signed int 如何映射

如果输入是无符号 32 位整数，直接把值当下标即可。

如果输入是有符号 `int32_t`，可以转换成 `uint32_t` 后使用其二进制表示：

```cpp
uint32_t idx = static_cast<uint32_t>(x);
```

这样负数也能映射到 `0` 到 `2^32 - 1` 的空间。只要插入和查询用同一种映射，就不会出错。

## 3. C++ 实现

```cpp
#include <cstdint>
#include <iostream>
#include <vector>
using namespace std;

class BitSet32 {
public:
    BitSet32() : bits_(1ULL << 26, 0) {} // 2^32 bits / 64 = 2^26 uint64_t

    void set(uint32_t x) {
        bits_[x >> 6] |= (1ULL << (x & 63));
    }

    bool test(uint32_t x) const {
        return (bits_[x >> 6] & (1ULL << (x & 63))) != 0;
    }

private:
    vector<uint64_t> bits_;
};

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    uint64_t n = 0;
    cin >> n;

    BitSet32 bitmap;
    for (uint64_t i = 0; i < n; ++i) {
        int32_t value = 0;
        cin >> value;
        bitmap.set(static_cast<uint32_t>(value));
    }

    int32_t target = 0;
    cin >> target;
    cout << (bitmap.test(static_cast<uint32_t>(target)) ? 1 : 0) << '\n';
    return 0;
}
```

## 4. 复杂度

```text
时间复杂度: O(N)
空间复杂度: 512MB 左右
```

## 5. 为什么不用哈希表或排序

1. `unordered_set<int>` 存 40 亿个整数远超 1GB，节点、桶、装载因子都有额外开销。
2. 排序需要存下全部数据或做外部排序，判断存在性没有必要。
3. 位图空间只和值域有关，不和输入数量直接相关，适合完整 32 位整数值域。

## 6. 可扩展方案

如果内存小于 512MB：

1. **分桶多轮扫描**：按高位把整数分桶到磁盘，再只加载目标 `X` 所在桶的位图。
2. **布隆过滤器**：内存更省，但有误判率，只能回答“可能存在/一定不存在”。
3. **外部排序**：排序后二分或归并查找，但 I/O 成本更高。
4. **Roaring Bitmap**：数据稀疏或局部分布明显时可能更省内存，但全值域随机数据不一定比普通 bitmap 好。

## 7. 面试回答模板

40 亿个 32 位整数的值域是 `2^32`，用 bitmap 表示只需要 `2^32 / 8 = 512MB`，1GB 内存足够。流式读取每个数，把它映射成 `uint32_t` 下标并置位，最后检查目标 `X` 的 bit 是否为 1。哈希表会因为桶和节点开销超内存；排序没有必要。如果内存不够 512MB，可以按高位分桶多轮处理，或用布隆过滤器接受误判。
