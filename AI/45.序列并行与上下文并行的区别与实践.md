# 45. 序列并行与上下文并行的区别与实践

## 1. 问题背景

在大模型训练和推理中，长序列场景（如长文档理解、代码生成、多轮对话）带来了巨大的显存压力。序列并行（Sequence Parallelism, SP）和上下文并行（Context Parallelism, CP）是两种解决长序列显存瓶颈的并行策略，但它们的设计目标和实现方式有显著差异。

**假设条件**：本文档基于 Transformer 架构（以 Llama、Mistral 为代表），假设使用 8~16 张 GPU 的分布式训练/推理环境，序列长度从 4K 到 128K 不等，上下文中涉及的通信主要基于 NCCL。

## 2. 问题现象

1. **长序列显存爆炸**：序列长度增加时，激活值显存呈线性增长，单 GPU 无法容纳。
2. **序列并行效率低**：简单沿 batch 维度切分无法高效处理变长序列。
3. **上下文信息丢失**：并行切分后，Attention 跨分片计算需要额外通信，导致上下文碎片化。
4. **负载不均衡**：不同序列长度差异大，导致 GPU 间负载不均。
5. **通信瓶颈**：AllReduce/AllGather 通信量随序列长度增加而增加。

## 3. 影响范围

| 影响维度 | 程度 | 说明 |
| --- | --- | --- |
| 最大可训练序列长度 | 高 | 直接决定能否支持长序列场景 |
| 训练吞吐量 | 中 | 通信和同步增加开销 |
| 显存利用率 | 高 | 激活值切分优化显存峰值 |
| 模型质量 | 中 | 不当切分可能丢失上下文信息 |
| 工程复杂度 | 中 | 多种并行策略组合增加调度难度 |

## 4. 原因分析

### 4.1 序列并行的本质

**序列并行（SP）**沿序列维度（Sequence Dimension）对输入进行切分，每张 GPU 只处理序列的一部分。

```python
# 序列并行示意
# 输入: [batch, seq_len, hidden] -> 切分 -> [batch, seq_len/8, hidden]
input_ids = input_ids.chunk(num_gpus, dim=1)  # 按序列维度切分

# 每 GPU 独立计算（除 Attention 外）
for gpu_id in range(num_gpus):
    local_input = input_ids[gpu_id]
    # LayerNorm, Linear, FFN 可以独立计算
    output = transformer_layer(local_input)
```

**问题**：Attention 计算需要完整的序列信息，分片后必须 AllGather 汇聚，导致额外通信。

### 4.2 上下文并行的设计

**上下文并行（CP）**专门针对 Attention 阶段优化，将 KV Cache 按头维度（Head Dimension）切分，每个 GPU 负责一部分 attention head 的计算。

```python
# 上下文并行示意（Megatron-SP）
# 将 head 维度切分到不同 GPU
# Q: [batch, num_heads/8, seq_len, head_dim]
# K, V: [batch, num_heads/8, seq_len, head_dim]

# 每个 GPU 计算部分 head 的 attention
local_attn = flash_attn(
    q=local_q,  # 本地 Q
    k=full_k,   # 需要 AllGather 获取完整 K
    v=full_v,   # 需要 AllGather 获取完整 V
)
```

**问题**：需要额外通信获取完整的 K/V，且 attention scores 的 all-reduce 增加开销。

### 4.3 两者的核心区别

| 维度 | 序列并行（SP） | 上下文并行（CP） |
| --- | --- | --- |
| 切分维度 | Sequence (seq_len) | Head (num_heads) |
| 通信模式 | AllGather 聚合序列 | AllGather 聚合 KV |
| 显存节省 | 激活值、注意力矩阵 | 主要是 KV Cache |
| 通信量 | O(seq_len) | O(seq_len * head_dim) |
| 适用场景 | 长序列训练 | 超长序列推理 |

### 4.4 显存占用对比

```
假设: batch=1, seq_len=32K, hidden=4096, num_heads=32, head_dim=128

序列并行（SP=8）：
- 每 GPU 序列长度: 32K/8 = 4K
- Attention 矩阵: [4K, 32K]（本地 vs 全局）
- 显存节省: 8 倍激活值

上下文并行（CP=8）：
- 每 GPU head 数: 32/8 = 4
- KV Cache: [batch, 4, seq_len, head_dim]（每个 head 独立）
- 显存节省: 主要在 KV Cache，8 倍

关键区别：
- SP 节省的是 QKt 矩阵空间
- CP 节省的是 KV Cache 空间
```

## 5. 解决方案

### 5.1 序列并行（Megatron-SP）

```python
# Megatron-DeepSpeed 序列并行配置
ds_config = {
    "sequence_parallel": {
        "enabled": True,
        "sequence_parallel_size": 8,  # SP 组大小
    }
}

# 核心实现逻辑
class SequenceParallelLinear(torch.nn.Module):
    def forward(self, x):
        # x: [batch, seq_len/8, hidden]
        
        # AllReduce 聚合梯度（训练时）
        if self.training and self.sequence_parallel:
            x = AllReduce.apply(x)
        
        # 本地计算
        output = F.linear(x, self.weight, self.bias)
        
        return output
```

### 5.2 上下文并行（DeepSpeed-Ulysses）

```python
# DeepSpeed Ulysses 上下文并行
class UlyssesContextParallel(torch.nn.Module):
    def __init__(self, cp_size=8):
        super().__init__()
        self.cp_size = cp_size
    
    def forward(self, q, k, v):
        # Q 在本地，K/V 需要聚合
        # Q: [batch, num_heads/8, seq_len, head_dim]
        # K, V: [batch, num_heads/8, seq_len, head_dim]
        
        # AllToAll 通信：将 K/V 聚合
        k_gathered = all_to_all_tensor(k, self.cp_size)
        v_gathered = all_to_all_tensor(v, self.cp_size)
        
        # 计算部分 attention
        local_attn = flash_attn(q, k_gathered, v_gathered)
        
        # 结果需要 AllToAll 重分布
        output = all_to_all_tensor(local_attn, self.cp_size)
        
        return output
```

### 5.3 混合并行：SP + TP + PP

```python
# 典型混合并行配置（以 64 GPU 为例）
# TP=8, PP=4, SP=2, CP=1
# 或 TP=4, PP=4, SP=4, CP=1

parallelism_config = {
    "tensor_parallelism": 8,    # 张量并行
    "pipeline_parallelism": 4,  # 流水线并行
    "sequence_parallelism": 2,  # 序列并行
}

# 计算总并行度: 8 * 4 * 2 = 64 GPU

# Attention 层使用 SP
class AttentionWithSP(torch.nn.Module):
    def __init__(self, config):
        super().__init__()
        self.sp_size = get_sequence_parallel_size()
    
    def forward(self, x, mask=None):
        # x: [batch, seq_len/8, hidden]
        
        # 计算 QKV
        q, k, v = self.compute_qkv(x)
        
        # 序列并行：聚合序列维度
        # 在 Attention 前同步所有分片
        q = AllGather.apply(q)
        k = AllGather.apply(k)
        v = AllGather.apply(v)
        
        # 计算 Attention
        attn = flash_attn(q, k, v, mask)
        
        # 切回本地序列长度
        attn = attn.chunk(self.sp_size, dim=1)[get_data_parallel_rank()]
        
        return attn
```

### 5.4 Ring Attention：通信最优的上下文并行

```python
# Ring Attention 实现
class RingAttention(torch.nn.Module):
    def __init__(self, num_devices):
        super().__init__()
        self.num_devices = num_devices
    
    def forward(self, q, k, v):
        """
        q, k, v 已按 num_devices 切分
        Ring 方式逐步传递 K/V，计算分布式 attention
        """
        seq_len = q.shape[2]
        chunk_size = seq_len // self.num_devices
        
        # 本地 Q 与全局 K/V 的分段 attention
        output = torch.zeros_like(q)
        
        k_buffer = k.clone()
        v_buffer = v.clone()
        
        for step in range(self.num_devices):
            # 计算本地 Q 与当前 k_buffer 的 attention
            local_attn = flash_attn(
                q[:, :, step*chunk_size:(step+1)*chunk_size],
                k_buffer, v_buffer
            )
            output[:, :, step*chunk_size:(step+1)*chunk_size] = local_attn
            
            # Ring 传递 K/V 到下一个设备
            k_buffer = torch.cat([k_buffer[:,:,chunk_size:], k_buffer[:,:,:chunk_size]], dim=2)
            v_buffer = torch.cat([v_buffer[:,:,chunk_size:], v_buffer[:,:,:chunk_size]], dim=2)
        
        return output
```

## 6. 可选方案对比

| 方案 | 显存节省 | 通信开销 | 实现复杂度 | 适用场景 |
| --- | --- | --- | --- | --- |
| Megatron-SP | 中等（激活值） | 中等（AllGather） | 低 | 中等长度序列训练 |
| DeepSpeed-Ulysses | 高（KV Cache） | 中等（AllToAll） | 中 | 长序列推理 |
| Ring Attention | 高（KV Cache） | 低（Ring 通信） | 高 | 超长序列（百万 token） |
| SP + TP 混合 | 高（多层优化） | 高（多重通信） | 高 | 大模型千亿参数训练 |
| 纯 CP | 高（KV Cache） | 中等 | 中 | KV Cache 瓶颈场景 |

## 7. 推荐方案

**推荐方案：Megatron-SP 用于训练 + Ring Attention 用于超长序列推理**

理由：
1. Megatron-SP 实现成熟，与 TP/PP 兼容性最好，训练场景首选。
2. Ring Attention 在超长序列（如 100K+ tokens）场景下通信最优。
3. 混合方案根据硬件拓扑和序列长度动态选择。

**实施优先级**：
1. 首先在训练中启用 Megatron-SP，与 TP/PP 联合调优。
2. 推理阶段根据序列长度选择 CP 或 Ring Attention。
3. 对于超长序列（如代码生成场景），优先考虑 Ring Attention。

### 步骤 3：实现 Ring Attention

```python
# ring_attention.py
import torch
import torch.nn.functional as F

def ring_attention_forward(q, k, v, causal=True):
    """
    q, k, v: [batch, num_heads, seq_len, head_dim]
    已按 ring_size 切分 seq_len 维度
    """
    assert q.shape == k.shape == v.shape
    batch, num_heads, seq_len, head_dim = q.shape
    ring_size = get_ring_size()
    chunk_size = seq_len // ring_size
    
    output = torch.zeros_like(q)
    
    k_buf = k.clone()
    v_buf = v.clone()
    
    for ring_idx in range(ring_size):
        # 计算当前 chunk 的 attention
        start = ring_idx * chunk_size
        end = (ring_idx + 1) * chunk_size
        
        if causal:
            mask = torch.triu(torch.ones(seq_len, seq_len, device=q.device), diagonal=1).bool()
            mask = mask[start:end, :]
        else:
            mask = None
        
        attn_chunk = F.scaled_dot_product_attention(
            q[:, :, start:end],
            k_buf, v_buf,
            attn_mask=mask
        )
        output[:, :, start:end] = attn_chunk
        
        # Ring 通信：传递 k_buf 和 v_buf
        k_buf = torch.cat([k_buf[:, :, chunk_size:], k_buf[:, :, :chunk_size]], dim=2)
        v_buf = torch.cat([v_buf[:, :, chunk_size:], v_buf[:, :, :chunk_size]], dim=2)
    
    return output
```

## 9. 风险与注意事项

| 风险 | 缓解措施 |
| --- | --- |
| SP 通信开销抵消显存节省 | 确保通信带宽足够（NVLink > PCIe） |
| Ring Attention 延迟累积 | 使用 Lookback 或 Paged Attention 优化 |
| 混合并行死锁 | 使用框架提供的自动调度器，避免手写复杂调度 |
| 变长序列负载不均 | 使用 sequence packing 填充到固定长度 |
| 精度损失 | 确保 all-reduce 使用正确的 reduce 模式 |

## 11. 总结

序列并行（SP）和上下文并行（CP）是解决长序列显存问题的两种互补策略。SP 沿序列维度切分，主要节省激活值显存；CP 沿头维度切分，主要节省 KV Cache 显存。

**核心要点回顾**：
- SP 切分 seq_len 维度，CP 切分 num_heads 维度。
- SP 需要 AllGather 聚合序列，CP 需要 AllGather/AllToAll 聚合 KV。
- Ring Attention 是超长序列（100K+ tokens）的最优选择。
- 混合并行（SP + TP + PP）是千亿参数大模型训练的标准配置。
- 策略选择应根据序列长度、显存瓶颈和硬件拓扑动态调整。
