# 65. 向量检索相似度计算与索引选型

面试题：向量检索依靠什么计算相似度。考察 embedding 向量之间相似度的数学定义、不同距离度量的差异、以及在向量数据库中的索引选型。

## 1. 三种主流相似度

向量检索的本质是把文本/图片/音频映射成高维向量后，找出和查询向量最相似的 Top-K 个向量。"相似度"有三种主流定义：

| 方法 | 公式 | 范围 | 特点 |
| --- | --- | --- | --- |
| 余弦相似度 (Cosine Similarity) | cos(θ) = A·B / (\|A\| × \|B\|) | [-1, 1]，越大越相似 | 只看方向，不看模长 |
| 点积 (Dot Product / Inner Product) | A·B = Σ aᵢbᵢ | (-∞, +∞)，越大越相似 | 同时考虑方向和模长 |
| 欧氏距离 (Euclidean / L2) | dist = sqrt(Σ(aᵢ-bᵢ)²) | [0, +∞)，越小越相似 | 看绝对距离 |

### 1.1 余弦相似度

```text
cos(θ) = (A · B) / (||A|| · ||B||)
```

几何意义：两个向量夹角的余弦值。夹角越小越相似。

- 0° (cos=1)：方向相同，完全相似。
- 90° (cos=0)：正交，完全不相关。
- 180° (cos=-1)：方向相反。

为什么 RAG 默认选余弦相似度：

1. 文本 embedding 后向量模长可能受文本长度影响（长文本向量模长更大）。
2. 余弦只关心语义方向，不被模长干扰。
3. 标准化后的向量做点积 = 余弦相似度，计算高效。

### 1.2 点积相似度

```text
A · B = a₁b₁ + a₂b₂ + ... + aₙbₙ
```

如果向量都做了 L2 归一化（||A|| = ||B|| = 1），点积就等于余弦相似度。这是大部分向量库底层的实现技巧：

1. 入库时先把向量归一化。
2. 查询向量也归一化。
3. 直接算点积，无需重复算分母。

未归一化的点积场景：推荐系统中，模长可能编码了"热度"或"流行度"信息，此时希望热门 item 得分更高，就用未归一化点积。

### 1.3 欧氏距离

```text
dist(A, B) = sqrt((a₁-b₁)² + (a₂-b₂)² + ... + (aₙ-bₙ)²)
```

衡量两个向量在空间中的"直线距离"。距离越小越相似。

使用场景：

1. 图像 embedding（颜色、纹理特征）。
2. 数值特征向量（用户画像、传感器数据）。
3. KMeans 等聚类算法。

文本场景较少用 L2，因为模长干扰大。

### 1.4 选哪个

| 场景 | 推荐 |
| --- | --- |
| 文本 RAG | 余弦相似度（或归一化点积） |
| 推荐系统 | 点积（保留热度信息）|
| 图像/数值 | 欧氏距离或余弦 |

工程实操：用 OpenAI、bge、m3e 等文本 embedding 模型，默认选余弦相似度。模型卡通常会写明推荐度量。

## 2. 数学等价关系

L2 归一化后，三种度量有简单关系：

```text
设 ||A|| = ||B|| = 1
余弦 = A·B
L2² = ||A-B||² = ||A||² + ||B||² - 2A·B = 2 - 2·cos
```

所以归一化后，L2 距离平方和余弦相似度是单调反相关的，排序结果完全等价。这就是为什么很多向量库只实现内积索引（IP），用户自己归一化即可。

## 3. 暴力搜索的瓶颈

最朴素的检索方式：query 向量和库中每条向量逐个算相似度，取 Top-K。

时间复杂度：O(N × D)，N 是向量数，D 是维度。

百万级向量 × 1536D × 实时查询 = 不可接受的延迟。需要 ANN（Approximate Nearest Neighbor，近似最近邻）索引。

## 4. ANN 索引算法

### 4.1 IVF (Inverted File Index)

倒排文件索引。原理：

1. 对所有向量做 KMeans 聚类，分成 nlist 个簇。
2. 每个簇有一个中心向量。
3. 查询时先比较 query 和所有簇中心，选最近的 nprobe 个簇。
4. 只在这 nprobe 个簇内做暴力搜索。

参数：

- `nlist`：簇数，典型 sqrt(N) 到 4×sqrt(N)。
- `nprobe`：查询时搜索的簇数。越大精度高但慢。

适合：百万到千万级向量，对精度和速度有平衡要求。

### 4.2 HNSW (Hierarchical Navigable Small World)

分层导航小世界图。原理：

1. 把向量组织成多层图，每层节点稀疏程度不同。
2. 上层稀疏，下层密集。
3. 查询时从顶层开始贪婪搜索，逐层下降到底层得到 Top-K。

参数：

- `M`：每个节点的邻居数，典型 16-64。
- `ef_construction`：建图时的候选数。
- `ef_search`：查询时的候选数。

特点：

- 精度高，召回率通常 > 95%。
- 内存占用大（要存图结构）。
- 不支持高效删除（需要重建）。

适合：高精度要求场景、千万级以下。

### 4.3 PQ (Product Quantization)

乘积量化。原理：

1. 把高维向量切成 M 段子向量。
2. 每段做 KMeans 聚类（如 256 个簇），用簇 ID 代替原始子向量。
3. 一个 D 维 float 向量被压缩成 M 个 byte。

特点：

- 压缩率高（1536 维 float = 6KB，PQ 后 = 32-96B）。
- 检索精度有损失。
- 通常和 IVF 组合：IVF_PQ。

适合：超大规模向量（亿级以上）、内存受限。

### 4.4 索引算法对比

| 索引 | 召回率 | 速度 | 内存 | 适合规模 |
| --- | --- | --- | --- | --- |
| Flat（暴力） | 100% | 慢 | 1× | 小于 10 万 |
| IVF_FLAT | 90-99% | 中 | 1× | 百万-千万 |
| HNSW | 95-99% | 快 | 2-3× | 百万-千万 |
| IVF_PQ | 80-95% | 快 | 0.1× | 亿级 |
| IVF_HNSW | 高 | 快 | 大 | 千万级 |

## 5. 检索性能优化

### 5.1 维度选择

维度越高，理论精度越高，但：

1. 存储成本线性增长。
2. 计算成本线性增长。
3. 维度灾难：高维空间中距离区分度降低。

实践：768D 或 1024D 是性价比较高的选择，1536D 在通用场景已够用。需要更高精度可以用 reranker 弥补。

### 5.2 元数据过滤

实际查询通常带条件：`tenant_id=?` 或 `category in (...)`。两种实现方式：

1. **Pre-filter**：先按 metadata 过滤出候选集，再做向量检索。候选集大时精度差。
2. **Post-filter**：先向量检索 Top-K，再按 metadata 过滤。K 不够大时可能返回 0 条。

Milvus、Qdrant 等支持**带过滤的向量检索**：在 ANN 索引内部就考虑过滤条件，效率高于纯 pre/post filter。

### 5.3 批量查询

多个 query 并行检索，利用 SIMD 和缓存局部性。FAISS 的 batch query 接口可以把 10 个 query 的延迟压到接近 1 个。

### 5.4 GPU 加速

FAISS 支持 GPU 索引，单 GPU 可以处理千万级向量的实时检索。延迟和吞吐都比 CPU 提升 10 倍以上。代价是显存占用和资源成本。

## 6. 与 Rerank 的关系

向量检索的核心权衡：召回率 vs 速度。

实际工程的标准做法：

```text
向量检索（高召回，Top 50-100，速度优先）
    -> Rerank（精度优先，Top 3-5）
    -> LLM 生成
```

向量检索的 ANN 索引可以接受一定精度损失（IVF_PQ），最终精度由 Rerank 保证。这样既能控制成本又能保证效果。

## 7. 易错点

1. 用未归一化的向量做余弦：要么先归一化再算点积，要么手动除以模长。
2. 用余弦做 L2 索引：度量不匹配，召回精度大幅下降。
3. nprobe 设置过小：召回率掉到 70% 以下。
4. HNSW ef_search 设置过小：高 QPS 下精度下降。
5. 维度选错：768D embedding 用了 1536D 索引，浪费资源。
6. 删除频繁的场景用 HNSW：HNSW 不支持高效删除，需要定期重建。
7. 元数据过滤用 post-filter：过滤后不足 Top-K，返回结果不完整。

## 8. 总结

向量检索的相似度计算主要有三种：余弦相似度（看方向）、点积（方向+模长）、欧氏距离（绝对距离）。文本 RAG 场景默认用余弦，工程上常先归一化向量再算点积等价实现。当向量规模超过 10 万时必须用 ANN 索引：IVF 适合百万-千万级，HNSW 精度最高但内存大，PQ 用于亿级压缩存储，常组合成 IVF_PQ 或 IVF_HNSW。性能优化围绕维度选择、批量查询、元数据过滤和 GPU 加速展开。最终精度由召回 + Rerank 两阶段保证。
