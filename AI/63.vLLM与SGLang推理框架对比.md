# 63. vLLM与SGLang推理框架对比

## 1. 问题背景

vLLM 和 SGLang 是当前最流行的两个开源 LLM 推理框架，都基于 PagedAttention 实现高吞吐推理，但在设计哲学、特性和适用场景上有显著差异。面试常考两者的核心区别、PageAttention 原理、以及各自的技术特性。

**假设条件**：本文档基于 vLLM 0.6+ 和 SGLang 0.3+ 版本，假设使用 NVIDIA A100/H100 GPU，推理场景为 LLM 自回归生成。

## 2. 问题现象

1. **框架选择困难**：vLLM 和 SGLang 都支持 PagedAttention，不知道选哪个
2. **PageAttention 原理不清楚**：分页管理 KV Cache 的具体机制
3. **SGLang 的 RadixAttention 是什么**：与前缀缓存的关系
4. **两者的性能差异**：在不同场景下谁更快

## 3. 影响范围

| 影响维度 | 程度 | 说明 |
| --- | --- | --- |
| 推理吞吐 | 高 | 框架选择直接影响服务吞吐 |
| 部署成本 | 高 | 高吞吐 = 更少 GPU = 更低成本 |
| 开发效率 | 中 | API 和功能差异影响集成成本 |
| 功能覆盖 | 中 | 不同框架支持的功能不同 |

### 4.2 PageAttention 原理

`
┌──────────────────────────────────────────────────────────────┐
│              PageAttention 工作原理                           │
├──────────────────────────────────────────────────────────────┤
│ 核心思想：类比 OS 虚拟内存分页管理                           │
│                                                              │
│ 传统方式：为每个请求预分配最大长度的连续显存                 │
│   → 显存碎片严重，利用率低（~30%）                          │
│   → 无法灵活分配和回收                                      │
│                                                              │
│ PagedAttention：                                             │
│   1. KV Cache 按固定大小 block 分配（如 16 tokens/block）    │
│   2. Block Table 记录逻辑 block → 物理 block 映射           │
│   3. 逻辑上连续的 KV Cache，物理上可以不连续                 │
│   4. 请求完成时释放 block，新请求立即可用                    │
│                                                              │
│   请求 A 的 KV Cache:                                       │
│     逻辑: [Block 0] [Block 1] [Block 2]                     │
│     物理: [Pool:3]  [Pool:7]  [Pool:1]                      │
│                                                              │
│   请求 B 的 KV Cache:                                       │
│     逻辑: [Block 0] [Block 1]                               │
│     物理: [Pool:5]  [Pool:2]                                │
│                                                              │
│   Block Pool (物理内存池):                                   │
│     [0:free] [1:A-2] [2:B-1] [3:A-0]                       │
│     [4:free] [5:B-0] [6:free] [7:A-1]                      │
│                                                              │
│ 前缀共享（Prefix Caching）：                                │
│   两个请求的 system prompt 相同 → 共享物理 block            │
│   逻辑: A=[Block 0][Block 1][Block 2]                       │
│         B=[Block 0][Block 1][Block 3]  ← 前2个block共享     │
│   物理: A=[Pool:3][Pool:7][Pool:1]                          │
│         B=[Pool:3][Pool:7][Pool:8]  ← 引用计数管理          │
└──────────────────────────────────────────────────────────────┘
`

### 4.3 SGLang 的 RadixAttention

`
RadixAttention 是 SGLang 的核心创新：

传统 Prefix Cache (vLLM APC)：
  → 需要精确匹配前缀 token 序列
  → 线性扫描匹配，效率一般

RadixAttention (SGLang)：
  → 使用 Radix Tree（基数树）管理所有请求的 KV Cache
  → Radix Tree 自动合并公共前缀
  → 新请求插入时自动复用已有 KV Cache block
  → 支持部分前缀匹配（不仅仅是完整前缀）
  → 引用计数 + LRU 淘汰策略

优势场景：
  1. 多轮对话：前几轮的 KV Cache 自动复用
  2. Agent Workflow：system prompt + 工具描述高度相同
  3. Tree-of-Thought：多个分支共享前缀
  4. 多候选采样：同一个 prompt 多次采样，prefill 只做一次
`

## 5. 解决方案

| 方案 | 吞吐 | 前缀复用效率 | 结构化输出 | 生态成熟度 |
| --- | --- | --- | --- | --- |
| vLLM | 高 | 中（APC） | 支持 | 最高 |
| SGLang | 高 | 高（RadixAttention） | 原生支持 | 高 |
| TensorRT-LLM | 最高 | 中 | 有限 | 中 |
| LMDeploy | 高 | 中 | 有限 | 中 |

## 6. 可选方案对比

| 维度 | vLLM | SGLang | TensorRT-LLM |
| --- | --- | --- | --- |
| 部署难度 | 低 | 低 | 高 |
| 灵活性 | 高 | 高 | 低 |
| 极致性能 | 高 | 高 | 最高 |
| 社区活跃 | 最活跃 | 活跃 | 活跃 |
| Agent 支持 | 一般 | 原生 | 有限 |

## 7. 推荐方案

- **通用推理服务**：vLLM，生态最成熟，社区支持最好
- **Agent/结构化生成**：SGLang，RadixAttention 和原生结构化输出是杀手级特性
- **极致性能**：TensorRT-LLM，但开发成本高

## 8. 实施步骤

1. 评估推理场景（聊天/Agent/结构化/多模态）
2. 选择框架并部署
3. 配置 PagedAttention、Continuous Batching、Prefix Cache
4. 性能调优：block_size、max_num_seqs、gpu_memory_utilization
5. 监控：吞吐、延迟、KV Cache 利用率

## 9. 风险与注意事项

- **vLLM 的 APC 在高并发下可能退化**：大量不同前缀的请求使缓存命中率下降
- **SGLang 的 RadixAttention 有额外 CPU 开销**：树维护和匹配操作
- **两者的量化支持不完全一致**：特定量化格式需确认兼容性
- **版本迭代快**：API 可能变化，需关注 release notes

## 10. 验证方式

1. 吞吐：对比相同硬件下两个框架的 tokens/s
2. 首 Token 延迟：TTFT (Time To First Token)
3. KV Cache 利用率：监控 block 使用率和缓存命中率
4. 结构化输出：测试 JSON/Regex 约束的准确率和延迟

## 11. 总结

vLLM 和 SGLang 都基于 PagedAttention 实现高吞吐推理。vLLM 是通用推理引擎，生态最成熟；SGLang 以 RadixAttention（基数树前缀复用）和原生结构化输出为特色，更适合 Agent 和多轮对话场景。PageAttention 的核心是类比 OS 虚拟内存的分页管理，用 Block Table 映射逻辑到物理 block，消除显存碎片。面试核心考点：PageAttention 原理、RadixAttention vs APC、两者特性差异和适用场景。
