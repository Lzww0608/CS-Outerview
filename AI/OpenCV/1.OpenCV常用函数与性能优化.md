# OpenCV 常用函数与性能优化

OpenCV 是常用的计算机视觉基础库，覆盖图像读写、颜色空间转换、滤波、几何变换、特征提取、目标检测、视频处理和 DNN 推理等能力。面试里问“用过哪些 OpenCV 函数”和“速度如何”，不要只报函数名，要能说明数据结构、性能瓶颈和优化手段。

## 1. 常用模块和函数

### 图像读写和基础操作

1. `cv::imread`：读取图片，注意默认读取为 BGR。
2. `cv::imwrite`：保存图片，速度受编码格式、压缩参数和磁盘 I/O 影响。
3. `cv::Mat`：核心图像矩阵，内部有引用计数，普通赋值多为浅拷贝。
4. `cv::split` / `cv::merge`：通道拆分和合并。
5. `cv::copyTo` / `clone`：显式深拷贝图像数据。

### 颜色空间和预处理

1. `cv::cvtColor`：BGR、RGB、GRAY、HSV、YUV 等颜色空间转换。
2. `cv::resize`：缩放图像，常用插值有 `INTER_NEAREST`、`INTER_LINEAR`、`INTER_AREA`、`INTER_CUBIC`。
3. `cv::GaussianBlur`、`cv::medianBlur`、`cv::bilateralFilter`：去噪和平滑。
4. `cv::threshold`、`cv::adaptiveThreshold`：阈值分割。
5. `cv::equalizeHist`、CLAHE：直方图均衡和局部对比度增强。

### 边缘、轮廓和形态学

1. `cv::Canny`：边缘检测。
2. `cv::findContours`：提取轮廓。
3. `cv::boundingRect`、`cv::minAreaRect`：计算外接矩形。
4. `cv::morphologyEx`、`cv::erode`、`cv::dilate`：开闭运算、腐蚀、膨胀。
5. `cv::HoughLines`、`cv::HoughCircles`：霍夫线/圆检测。

### 几何变换和视频

1. `cv::getAffineTransform`、`cv::warpAffine`：仿射变换。
2. `cv::getPerspectiveTransform`、`cv::warpPerspective`：透视变换。
3. `cv::remap`：按映射表重采样，常用于畸变矫正。
4. `cv::VideoCapture`：读取摄像头或视频流。
5. `cv::VideoWriter`：写视频，速度受编码器和磁盘影响。

## 2. cv::Mat 的拷贝语义

`cv::Mat` 是 OpenCV 面试高频点。它包含矩阵头、尺寸、步长、数据指针和引用计数。

```cpp
cv::Mat a = cv::imread("a.jpg");
cv::Mat b = a;        // 浅拷贝，共享同一份像素数据
cv::Mat c = a.clone(); // 深拷贝，复制像素数据
```

浅拷贝很快，但修改共享数据会影响其他 `Mat` 视图：

```cpp
cv::Mat roi = a(cv::Rect(0, 0, 100, 100)); // ROI 通常也是浅视图
roi.setTo(cv::Scalar(0, 0, 255));          // 会修改原图对应区域
```

工程上要区分“只读视图”和“独立副本”。跨线程处理同一张图时，如果一个线程会写，最好 `clone()` 或明确加锁/分片，避免数据竞争。

## 3. OpenCV 速度如何

OpenCV 通常比手写朴素循环快，因为它大量使用 SIMD、缓存友好的实现和多线程后端；但速度不是固定结论，取决于图像尺寸、算法复杂度、内存访问、编译选项和硬件。

常见瓶颈：

1. **图像编解码**：`imread/imwrite` 可能慢在 JPEG/PNG 编解码和磁盘 I/O。
2. **内存带宽**：大图 `resize/cvtColor/filter` 常受内存读写限制。
3. **算法复杂度**：双边滤波、模板匹配、特征匹配、DNN 推理比简单阈值更重。
4. **数据拷贝**：频繁 `clone()`、通道拆分、格式转换会放大内存开销。
5. **未启用优化构建**：没有开启 Release、SIMD、TBB/OpenMP、IPP、CUDA 等会明显变慢。

## 4. 性能优化方法

1. **使用 Release 构建**：Debug 下 OpenCV 和业务代码都会明显慢。
2. **减少不必要拷贝**：能用 ROI 视图就不用 `clone()`，但要保证生命周期和写入安全。
3. **复用输出 buffer**：循环处理中提前分配 `cv::Mat dst`，避免每帧重复分配。
4. **减少格式转换**：统一颜色空间和数据类型，避免 BGR/RGB/GRAY 来回转换。
5. **选择合适插值**：缩小时常用 `INTER_AREA`，实时预览可用更快的 `INTER_LINEAR` 或 `INTER_NEAREST`。
6. **利用并行能力**：OpenCV 可配合 TBB/OpenMP，业务层也可按帧或 ROI 并行，但要避免过度线程嵌套。
7. **使用硬件加速**：可考虑 `cv::cuda::GpuMat`、OpenCL `UMat`、DNN CUDA/OpenVINO/TensorRT 后端。
8. **用工具量化**：用 `cv::TickMeter`、perf、VTune、Nsight 找真实瓶颈。

示例：

```cpp
cv::TickMeter tm;
tm.start();

cv::Mat gray;
cv::cvtColor(frame, gray, cv::COLOR_BGR2GRAY);
cv::GaussianBlur(gray, gray, cv::Size(5, 5), 1.5);
cv::Canny(gray, edges, 80, 160);

tm.stop();
std::cout << "pipeline cost: " << tm.getTimeMilli() << " ms\n";
```

## 5. 易错点

1. OpenCV 默认颜色顺序是 BGR，不是 RGB。
2. `cv::Mat b = a` 是浅拷贝，不是复制像素。
3. ROI 共享原图数据，修改 ROI 会修改原图。
4. GPU 不一定更快，小图或频繁 CPU/GPU 拷贝会抵消收益。
5. 多线程调用 OpenCV 函数不代表访问同一个 `Mat` 写数据是安全的。
6. 只说“OpenCV 很快”不够，要说明是否启用 SIMD、多线程、IPP/CUDA，以及瓶颈在计算还是 I/O。

## 6. 面试回答模板

我常用的 OpenCV 函数包括 `imread/imwrite`、`cvtColor`、`resize`、`GaussianBlur`、`threshold`、`Canny`、`findContours`、`morphologyEx`、`warpAffine/warpPerspective`、`VideoCapture` 等。OpenCV 的速度通常比手写朴素实现快，因为底层做了 SIMD、多线程和平台优化，但真实性能取决于图像大小、算法复杂度、编译选项和是否有硬件加速。优化时我会先用 `TickMeter` 定位耗时，再减少拷贝和格式转换、复用 buffer、使用 ROI、选择合适插值，并在必要时用 TBB/OpenMP、CUDA、OpenCL 或 OpenVINO/TensorRT 后端。
