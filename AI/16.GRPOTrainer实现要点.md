# 16. GRPO Trainer 实现要点

手写 GRPO Trainer 不要求写出完整分布式训练系统，重点是讲清楚 rollout、reward、group advantage、policy loss、KL 和参数更新这几步。

## 1. 输入和组件

一个最小 GRPO Trainer 需要：

1. `actor_model`：当前要训练的策略模型。
2. `ref_model`：冻结的参考模型，用于 KL 约束。
3. `tokenizer`：prompt/response 编解码。
4. `reward_fn`：规则奖励或奖励模型。
5. `num_generations`：每个 prompt 采样多少个 response。
6. `old_logprobs`：采样时策略的 token logprob。
7. `kl_coef`：KL 惩罚系数。
8. `clip_range`：策略比值裁剪范围。

## 2. 核心流程

```text
for prompts in dataloader:
    responses = rollout(actor, prompts, G)
    rewards = reward_fn(prompts, responses)
    advantages = group_normalize(rewards)

    new_logprobs = actor.logprob(prompts, responses)
    ref_logprobs = ref.logprob(prompts, responses)
    ratio = exp(new_logprobs - old_logprobs)

    pg_loss = clipped_policy_gradient(ratio, advantages)
    kl = new_logprobs - ref_logprobs
    loss = pg_loss + kl_coef * kl
    backward_and_step(loss)
```

GRPO 的关键是 `group_normalize`：同一个 prompt 的 G 个 response 放在一个 group 内做 reward 标准化。

```text
adv_i = (reward_i - mean(group_rewards)) / (std(group_rewards) + eps)
```

## 3. PyTorch 风格伪代码

```python
def compute_group_advantage(rewards, group_size, eps=1e-6):
    # rewards: [batch * group_size]
    r = rewards.view(-1, group_size)
    mean = r.mean(dim=1, keepdim=True)
    std = r.std(dim=1, keepdim=True)
    adv = (r - mean) / (std + eps)
    return adv.view(-1)


def grpo_loss(new_logp, old_logp, ref_logp, adv, mask, clip_eps, kl_coef):
    # new_logp/old_logp/ref_logp: [N, T]
    # adv: [N], sequence-level advantage
    # mask: [N, T], 1 for valid response tokens
    ratio = torch.exp(new_logp - old_logp)
    adv = adv[:, None]

    unclipped = ratio * adv
    clipped = torch.clamp(ratio, 1 - clip_eps, 1 + clip_eps) * adv
    pg = -torch.minimum(unclipped, clipped)

    # simple per-token KL approximation
    kl = new_logp - ref_logp
    loss = pg + kl_coef * kl
    loss = (loss * mask).sum() / mask.sum().clamp_min(1)
    return loss
```

真实实现还要注意：

1. `old_logp` 必须是 rollout 时 actor 的 logprob，不能用更新后的模型重算冒充。
2. 只在 response token 上算 loss，prompt token 要 mask 掉。
3. 不同 response 长度不同，要 padding 并用 mask。
4. reward 是 sequence-level，但 loss 是 token-level 时，要把 advantage 广播到 response token。
5. KL 可以用不同近似形式，工程实现要和框架一致。

## 4. Dynamic Sampling

如果某个 group 的 reward 全 0 或全 1：

```text
mean 有值，但 std 接近 0
advantage 全部接近 0
policy gradient 没有有效区分度
```

处理方法：

1. 跳过该 group，不参与本轮更新。
2. 对该 prompt 重新采样更多 response。
3. 替换 prompt，保持 batch 中有效 group 比例。
4. 调整 temperature/top-p 增加探索。
5. 使用过程奖励或格式奖励增加区分度。

DAPO 的 dynamic sampling 就是这类思想的系统化做法：过滤低信息量 group，提高有效样本利用率。

## 5. 工程实现难点

1. **rollout 吞吐**：生成最耗时，通常接 vLLM/SGLang。
2. **权重同步**：actor 更新后 rollout engine 要同步新权重。
3. **显存管理**：actor、ref、reward、rollout KV cache 都吃显存。
4. **分布式调度**：用 Ray 或类似系统分配不同 worker。
5. **奖励可靠性**：数学题要规范答案提取，代码题要沙箱跑测试。
6. **稳定性**：监控 entropy、KL、reward mean/std、response length、clip fraction。

## 6. 面试回答模板

GRPO Trainer 的核心流程是：对每个 prompt 采样 G 个 response，计算每个 response 的 reward；在同一个 prompt 的 group 内做 reward 标准化得到 advantage；然后用 actor 新 logprob 和 rollout 时 old logprob 计算 ratio，做 clipped policy gradient；再用 reference model 的 logprob 加 KL 约束，最后只在 response token 上反传更新 actor。如果 group 全对或全错，advantage 没有区分度，可以用 dynamic sampling 跳过或重采样，也可以提高 temperature、调整题目难度或引入更细粒度 reward。
