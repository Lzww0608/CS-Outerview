# 8. DeepSeek 与大模型基础原理

面试里问“DeepSeek 原理”时，不建议只背某个模型版本的参数或榜单。更稳妥的回答方式是先讲大语言模型的通用原理，再结合 DeepSeek 系模型常见的公开技术关键词，例如 Transformer、MoE、注意力优化、强化学习推理、推理加速和工程落地。

不同 DeepSeek 版本的细节会变化，回答时应避免把某个版本的技术报告内容泛化成所有模型的共同特征。

## 1. 大语言模型的基本工作方式

主流大语言模型通常是自回归语言模型：给定前文 token，预测下一个 token 的概率分布。

```text
文本 -> tokenizer -> token id
     -> embedding
     -> 多层 Transformer Decoder
     -> logits
     -> softmax / sampling
     -> 下一个 token
```

核心组件：

1. **Tokenizer**：把文本切成 token，中文、英文、代码和符号的切分效率会影响上下文长度和成本。
2. **Embedding**：把离散 token 映射成向量。
3. **Self-Attention**：让当前位置关注上下文中相关位置，建模长距离依赖。
4. **FFN / MLP**：对每个 token 的表示做非线性变换，提升表达能力。
5. **Residual + LayerNorm**：稳定深层网络训练。
6. **LM Head**：输出词表中每个 token 的概率。

生成时模型不是一次性写完整答案，而是逐 token 生成。每生成一个 token，都会把它追加到上下文中，再预测下一个 token。

## 2. MoE 的意义

MoE（Mixture of Experts）是大模型常见扩展方式之一。它把 FFN 部分拆成多个专家网络，每个 token 只激活其中少数几个专家。

```text
token hidden state
  -> router / gate
  -> top-k experts
  -> weighted combine
```

优势：

1. 总参数量可以很大，但每个 token 实际激活参数较少，推理计算成本相对可控。
2. 不同专家可以学习不同模式，例如代码、数学、语言风格或领域知识。
3. 在同等计算预算下，模型容量更高。

代价：

1. 路由不均衡会导致部分专家过热，训练需要负载均衡损失或容量控制。
2. 分布式训练和推理会产生跨卡通信，工程复杂度高。
3. 小 batch 或低并发推理时，专家调度开销可能抵消部分收益。

## 3. 注意力和 KV Cache

Transformer 的注意力计算会随上下文长度增长而变贵。推理时常用 KV Cache 缓存历史 token 的 key/value，避免每生成一个 token 都重新计算全部历史状态。

```text
prefill: 计算输入 prompt 的全部 KV
decode : 每次只计算新 token 的 Q/K/V，并复用历史 KV
```

KV Cache 的效果：

1. 显著降低多轮生成的重复计算。
2. 让首 token 延迟和后续 token 生成速度成为两个不同指标。
3. 上下文越长，KV Cache 占用显存越多，需要配合分页 KV、量化、上下文压缩或批处理策略。

DeepSeek 系模型公开资料中经常会出现注意力压缩或注意力结构优化相关概念。面试里可以抽象回答为：目标是在不明显损失效果的情况下，降低长上下文注意力和 KV Cache 的显存/计算成本。

## 4. 推理模型和强化学习

推理型大模型更关注数学、代码、逻辑推断、多步骤规划等任务。常见训练链路包括：

1. **预训练**：用大规模通用语料学习语言和知识。
2. **监督微调**：用高质量指令数据让模型学会按指令回答。
3. **偏好对齐或强化学习**：用奖励信号优化回答质量、安全性或推理表现。

强化学习并不是让模型“真的理解世界”，而是通过奖励函数鼓励某些输出模式。例如在数学和代码任务上，可以用答案正确性、测试用例通过率、格式约束等作为奖励信号。

易错点：

1. 推理能力增强不等于所有事实都可靠，仍然可能幻觉。
2. 长链路推理会增加 token 成本和延迟。
3. 线上业务不应无条件展示模型内部推理过程，应区分最终答案、解释和审计日志。

## 5. 工程落地时关注什么

把 DeepSeek 或其他大模型接入业务时，重点不是“模型名字”，而是完整链路：

1. **任务类型**：问答、代码生成、客服、检索增强、分类、摘要、Agent。
2. **部署方式**：云 API、私有化部署、混合部署。
3. **效果评测**：准确率、召回率、幻觉率、拒答率、人工满意度。
4. **性能指标**：首 token 延迟、输出 token/s、并发、上下文长度、显存占用。
5. **成本控制**：模型分级、缓存、短 prompt、批处理、量化、小模型兜底。
6. **安全合规**：敏感信息脱敏、权限过滤、内容安全、审计日志。

在 RAG 场景中，大模型不应直接依赖自身记忆回答企业内部知识，而是通过检索拿到相关文档片段，再基于片段生成答案。这样能降低幻觉，并且便于引用溯源和权限控制。

## 6. DeepSeek 系列怎么区分

面试里如果追问“DeepSeek 系列每代有什么创新”，可以按公开技术报告中的定位区分，不要把所有版本混成一个模型。

| 系列 | 重点 | 面试可讲点 |
| --- | --- | --- |
| DeepSeek-VL | 视觉语言理解 | 混合视觉编码器、视觉-语言预训练、真实场景图文理解 |
| DeepSeek-V2 | 高效 MoE LLM | DeepSeekMoE、MLA 等用于提高训练和推理效率的结构 |
| DeepSeek-V3 | 大规模 MoE 语言模型 | 671B 总参数、每 token 激活部分专家、MLA、DeepSeekMoE、工程化高效训练 |
| DeepSeek-R1 | 推理模型 | 通过强化学习激发数学、代码、STEM 等可验证任务推理能力，出现 self-reflection、verification 等推理模式 |

其中几个高频关键词：

1. **DeepSeekMoE**：通过专家路由扩大总参数量，每个 token 只激活部分专家，提升容量和计算效率。
2. **MLA**：Multi-head Latent Attention，目标是压缩或优化 KV 表示，降低长上下文推理中的 KV cache 成本。
3. **RL for reasoning**：对数学、代码等可验证任务用规则 reward 或 verifiable reward 训练，减少对人工链路标注的依赖。
4. **Distillation**：把大推理模型产生的推理能力迁移到更小模型，降低部署成本。

易错点：

1. DeepSeek-R1 的重点是 RL 推理，不是视觉语言模型。
2. DeepSeek-VL 的重点是图文理解，不应拿 R1 的 RL 细节解释 VL。
3. MoE 的“总参数”不等于每个 token 的实际计算参数，回答参数规模时要区分 total parameters 和 activated parameters。
4. MLA、MoE、RL 都是不同层面的技术：注意力结构、模型容量结构、后训练方法。

## 7. 面试回答模板

DeepSeek 本质上还是大语言模型体系的一类实现，底层通常可以从 tokenizer、自回归生成、Transformer Decoder、注意力、FFN、KV Cache 这些基础模块讲起。DeepSeek 系模型常被讨论的点包括 MoE 提升参数容量与计算效率、注意力或 KV Cache 优化降低长上下文成本，以及通过监督微调和强化学习增强推理能力。工程上我不会只看模型名，而会评估任务效果、延迟、吞吐、上下文长度、部署成本、安全合规和可观测性；如果是企业知识问答，还会结合 RAG、权限过滤、引用溯源和离线评测集来保证答案可靠。
