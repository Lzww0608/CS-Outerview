# 41. FSDP 核心原理与 ZeRO-3 区别

## 1. 问题背景

FSDP（Fully Sharded Data Parallel）和 ZeRO-3 都是大模型分布式训练的核心技术，用于解决单卡显存不足的问题。两者都基于参数分片，但实现方式和通信策略有所不同。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  分布式训练显存问题：                                      │
│                                                             │
│  单卡 80GB：A100                                            │
│  GPT-3 175B 模型：需要 ~350GB 存储                        │
│  解决方案：参数分片到多卡                                  │
│                                                             │
│  技术对比：                                                │
│  • ZeRO-3：微软 DeepSpeed 的实现                          │
│  • FSDP：PyTorch 原生实现                                 │
│  • 核心思想相同：分片存储 + AllGather                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 |
|------|------|
| 单卡 OOM | 模型参数装不下 |
| Batch size 小 | 受限显存无法增大 |
| 通信瓶颈 | 跨步延迟高 |
| 内存碎片 | 显存利用率低 |

---

## 3. 影响范围

- 超大模型训练（>7B 参数）
- 多节点分布式训练
- 混合专家模型（MoE）
- 流水线并行场景

## 4. 原因分析

### 4.1 ZeRO-3 原理

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  ZeRO-3 分片策略：                                        │
│                                                             │
│  每个 GPU 只保存 1/3 的参数：                             │
│  • ZeRO-1：优化器状态分片 (1/3)                         │
│  • ZeRO-2：优化器 + 梯度分片 (1/3)                      │
│  • ZeRO-3：参数 + 梯度 + 优化器状态全分片 (1/N)       │
│                                                             │
│  前向/反向传播流程：                                       │
│  1. AllGather：收集当前层参数                            │
│  2. 本地计算                                              │
│  3. 释放参数                                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 FSDP 原理

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  FSDP 分片策略：                                          │
│                                                             │
│  与 ZeRO-3 相同：                                         │
│  • 参数、梯度、优化器状态全分片                          │
│  • 每卡只保存 1/N                                        │
│                                                             │
│  不同点：                                                  │
│  • Sharding Strategy：可配置 per-layer / hybrid         │
│  • Communication：重叠优化更好                          │
│  • CPU Offload：支持更灵活                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 通信模式对比

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  ZeRO-3 通信模式：                                        │
│                                                             │
│  Forward:                                                │
│  [GPU0] ──AllGather──► [所有 GPU 获得完整参数]          │
│       │                                                   │
│       ▼                                                   │
│  [本地计算]                                              │
│       │                                                   │
│       ▼                                                   │
│  [释放参数]                                              │
│                                                             │
│  Backward:                                               │
│  [类似前向]                                               │
│                                                             │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  FSDP 通信模式：                                         │
│                                                             │
│  • 使用 _all_gather 获取参数                             │
│  • 使用 reduce_scatter 同步梯度                         │
│  • 通信与计算重叠更高效                                  │
│  • 支持resharding（参数在GPU间流动）                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 5. 解决方案

### 5.1 PyTorch FSDP 实现

```python
# PyTorch FSDP 基本用法

import torch
import torch.nn as nn
import torch.distributed as dist
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP
from torch.distributed.fsdp import ShardingStrategy, MixedPrecision
from torch.distributed.fsdp.wrap import transformer_auto_wrap_policy

def setup():
    # 初始化分布式
    dist.init_process_group(backend='nccl')
    local_rank = int(os.environ['LOCAL_RANK'])
    torch.cuda.set_device(local_rank)

def create_fsdp_model(model, local_rank):
    # 包装策略
    auto_wrap_policy = functools.partial(
        transformer_auto_wrap_policy,
        transformer_layer_cls={TransformerEncoderLayer}
    )
    
    # 混合精度
    mixed_precision = MixedPrecision(
        param_dtype=torch.float16,
        reduce_dtype=torch.float16,
        buffer_dtype=torch.float16,
    )
    
    # 创建 FSDP 模型
    model = FSDP(
        model,
        sharding_strategy=ShardingStrategy.FULL_SHARD,  # ZeRO-3 类似
        auto_wrap_policy=auto_wrap_policy,
        mixed_precision=mixed_precision,
        device_id=torch.cuda.current_device(),
        use_orig_params=True,  # 保持原始参数顺序
    )
    
    return model

# 训练循环
def train_step(model, batch, optimizer):
    optimizer.zero_grad()
    
    output = model(batch)
    loss = output.loss
    
    # FSDP 自动处理梯度同步
    loss.backward()
    optimizer.step()
```

### 5.3 Sharding Strategy 对比

```python
# FSDP 支持的 Sharding Strategy

from torch.distributed.fsdp import ShardingStrategy

# FULL_SHARD: 完整分片（类似 ZeRO-3）
# - 前向：AllGather 参数
# - 反向：AllGather 参数，ReduceScatter 梯度
fsdp_model = FSDP(model, sharding_strategy=ShardingStrategy.FULL_SHARD)

# SHARD_GRAD_OP: 只分片优化器状态和梯度
fsdp_model = FSDP(model, sharding_strategy=ShardingStrategy.SHARD_GRAD_OP)

# NO_SHARD: 不分片（类似 DDP）
fsdp_model = FSDP(model, sharding_strategy=ShardingStrategy.NO_SHARD)

# HYBRID_SHARD: 节点内全分片，节点间不通信
fsdp_model = FSDP(model, sharding_strategy=ShardingStrategy.HYBRID_SHARD)

# HYBRID_ZERO1: 优化器状态分片，但参数不跨节点
fsdp_model = FSDP(model, sharding_strategy=ShardingStrategy._HYBRID_SHARD_ZERO1)
```

## 10. 验证方式

```python
# 验证 FSDP 正确性

def verify_fsdp():
    import torch.distributed as dist
    
    # 1. 验证梯度同步
    for name, param in model.named_parameters():
        if param.grad is not None:
            # 所有 rank 的梯度应该相同
            grad_tensor = param.grad.clone()
            dist.all_reduce(grad_tensor)
            grad_tensor /= dist.get_world_size()
            
            assert torch.allclose(param.grad, grad_tensor)
    
    # 2. 验证参数同步
    dist.all_reduce(param.data, op=dist.ReduceOp.SUM)
    param.data /= dist.get_world_size()
    
    # 3. 验证显存占用
    memory_allocated = torch.cuda.memory_allocated()
    memory_reserved = torch.cuda.memory_reserved()
    print(f"GPU memory: {memory_allocated / 1e9:.2f}GB")
```

## 11. 总结

1. **核心原理**：参数分片到多卡，每卡只保存 1/N
2. **ZeRO-3**：DeepSpeed 实现，stage 3 全分片
3. **FSDP**：PyTorch 原生实现，配置更灵活
4. **主要区别**：框架不同，API 不同，生态不同
5. **选择建议**：PyTorch 生态用 FSDP，DeepSpeed 生态用 ZeRO-3
