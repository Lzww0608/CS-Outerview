# 61. MHA、GQA、MQA注意力机制对比

## 1. 问题背景

Transformer 的 Multi-Head Attention (MHA) 是标准注意力机制，每个 attention head 都有独立的 Q/K/V 投影。但在推理场景中，KV Cache 的显存占用随 head 数线性增长，成为瓶颈。MQA (Multi-Query Attention) 和 GQA (Grouped-Query Attention) 通过减少 KV head 数来降低显存和访存量，同时尽量保持模型质量。面试常考三者的原理、区别、适用场景，以及推理时前向张量维度变化过程。

**假设条件**：本文档基于 Transformer Decoder 架构的 LLM，假设 hidden_dim = D, num_q_heads = H, head_dim = d = D/H。

## 2. 问题现象

1. **MHA 的 KV Cache 显存太大**：每个 head 都要缓存 K/V，长序列推理显存爆炸
2. **MQA 质量损失明显**：所有 Q head 共享一组 K/V，信息容量下降
3. **GQA 如何平衡**：分组共享 K/V，组数如何选择
4. **推理时维度变化不清楚**：prefill/decode 每一层的张量 shape 变化

## 3. 影响范围

| 影响维度 | 程度 | 说明 |
| --- | --- | --- |
| 推理显存 | 高 | KV head 数直接决定 KV Cache 大小 |
| 推理吞吐 | 高 | 减少 KV head → 减少访存 → 提高 decode 吞吐 |
| 模型质量 | 中 | KV head 减少可能影响精度 |
| 训练速度 | 低 | 训练时计算量不变，仅影响推理 |

## 4. 原因分析

### 4.1 三种注意力机制对比

`
┌──────────────────────────────────────────────────────────────┐
│                 MHA / GQA / MQA 对比                         │
├──────────┬──────────────────┬────────────────┬───────────────┤
│ 维度     │ MHA              │ GQA            │ MQA           │
├──────────┼──────────────────┼────────────────┼───────────────┤
│ Q heads  │ H                │ H              │ H             │
│ KV heads │ H                │ G (G < H)      │ 1             │
│ KV head数│ 与Q相同          │ 分组共享       │ 所有Q共享1组  │
│ KV Cache │ 最大             │ 中等           │ 最小          │
│ 模型质量 │ 最好             │ 接近MHA        │ 有损失        │
│ 推理速度 │ 最慢(访存密集)   │ 较快           │ 最快          │
│ 代表模型 │ GPT-3, Llama-1   │ Llama-2/3      │ PaLM, Falcon  │
│          │ BERT             │ Mistral        │ StarCoder     │
└──────────┴──────────────────┴────────────────┴───────────────┘

KV head 数对比（以 num_q_heads=64 为例）：
  MHA: 64 个 KV head → KV Cache = 64 × seq_len × head_dim × 2 × dtype_size
  GQA: 8 个 KV head (group=8) → KV Cache 降为 1/8
  MQA: 1 个 KV head → KV Cache 降为 1/64
`

### 4.2 推理时前向张量维度变化过程

以 Llama-2-70B (GQA, num_q_heads=64, num_kv_heads=8, head_dim=128, hidden_dim=8192) 为例：

`
输入 token_ids: [batch, seq_len]

每层的前向过程：

1. Embedding: [batch, seq_len] → [batch, seq_len, hidden_dim=8192]

2. QKV 投影:
   Q = x @ Wq → [batch, seq_len, num_q_heads × head_dim] = [B, S, 8192]
   K = x @ Wk → [batch, seq_len, num_kv_heads × head_dim] = [B, S, 1024]
   V = x @ Wv → [batch, seq_len, num_kv_heads × head_dim] = [B, S, 1024]

3. Reshape:
   Q → [batch, num_q_heads, seq_len, head_dim] = [B, 64, S, 128]
   K → [batch, num_kv_heads, seq_len, head_dim] = [B, 8, S, 128]
   V → [batch, num_kv_heads, seq_len, head_dim] = [B, 8, S, 128]

4. GQA 中 K/V 扩展（repeat_kv）:
   K: [B, 8, S, 128] → repeat → [B, 64, S, 128]
   V: [B, 8, S, 128] → repeat → [B, 64, S, 128]
   每个 KV head 被复制 H/G = 8 次，供同组的 Q head 使用

5. Attention 计算:
   scores = Q @ K^T / sqrt(head_dim) → [B, 64, S, S]
   probs = softmax(scores) → [B, 64, S, S]
   attn_out = probs @ V → [B, 64, S, 128]

6. Reshape + O 投影:
   attn_out → [B, S, 8192]
   output = attn_out @ Wo → [B, S, 8192]

7. FFN (SwiGLU):
   up   = x @ Wu → [B, S, 28672]  (intermediate_size)
   gate = x @ Wg → [B, S, 28672]
   down = (silu(gate) * up) @ Wd → [B, S, 8192]

8. 残差连接: output = x + attn_out + ffn_out
`

### 4.3 Prefill vs Decode 维度差异

`
Prefill 阶段（处理完整 prompt）：
  Q: [B, 64, S_prompt, 128]   S_prompt 可能很大 (如 4096)
  K: [B, 8, S_prompt, 128]
  scores: [B, 64, S_prompt, S_prompt]  ← 大矩阵，计算密集

Decode 阶段（逐步生成，每次 1 token）：
  Q: [B, 64, 1, 128]          只有 1 个新 token
  K: [B, 8, S_total, 128]     S_total 是已生成的全部 token
  scores: [B, 64, 1, S_total]  ← 行向量，访存密集
  → 每步只需 1 × S_total 的 Attention，但需要读取全部 KV Cache
`

### 4.4 GQA 的 repeat_kv 实现

`python
def repeat_kv(hidden_states: torch.Tensor, n_rep: int) -> torch.Tensor:
    """将 KV head 复制 n_rep 次以匹配 Q head 数"""
    batch, num_kv_heads, seq_len, head_dim = hidden_states.shape
    if n_rep == 1:
        return hidden_states
    # [B, KV_heads, S, D] → [B, KV_heads, n_rep, S, D] → [B, Q_heads, S, D]
    hidden_states = hidden_states[:, :, None, :, :].expand(
        batch, num_kv_heads, n_rep, seq_len, head_dim
    )
    return hidden_states.reshape(batch, num_kv_heads * n_rep, seq_len, head_dim)

# GQA: n_rep = num_q_heads // num_kv_heads = 64 // 8 = 8
# MHA: n_rep = 1 (Q heads = KV heads)
# MQA: n_rep = num_q_heads (只有 1 个 KV head)
`

## 5. 解决方案

| 方案 | KV Cache 节省 | 质量影响 | 推理加速 | 代表模型 |
| --- | --- | --- | --- | --- |
| MHA | 基线 | 无 | 基线 | GPT-3, BERT |
| GQA (8组) | 8x | 微小 (<1%) | 1.5~2x | Llama-2/3, Mistral |
| GQA (4组) | 16x | 小 (~1%) | 2~3x | 部分定制模型 |
| MQA | 64x | 中等 (2~5%) | 3~4x | PaLM, Falcon |

## 6. 可选方案对比

| 维度 | MHA | GQA | MQA |
| --- | --- | --- | --- |
| KV Cache 显存 | 1x | 1/G | 1/H |
| Decode 延迟 | 高 | 中 | 低 |
| 模型精度 | 最高 | 接近MHA | 有损失 |
| 实现复杂度 | 低 | 中 | 低 |
| 适用场景 | 短序列/训练 | 通用推理 | 极致推理速度 |

## 7. 推荐方案

**新模型默认使用 GQA**：在 num_q_heads 和 num_kv_heads 之间取平衡。Llama-2/3 的实践表明 GQA 几乎不影响模型质量，但显著降低推理成本。推荐 
um_kv_heads = 8 对于 64+ Q heads 的模型。

## 8. 实施步骤

1. 评估当前模型 MHA 的 KV Cache 占比
2. 选择 GQA 的分组数（通常 4~16 组）
3. 修改模型 config，训练新模型或转换已有模型
4. 推理时实现 repeat_kv 逻辑
5. 对比 MHA/GQA 的精度和推理性能

## 9. 风险与注意事项

- **GQA 分组数太少会损失精度**：一般不低于 4 组
- **repeat_kv 不增加实际计算量**：只是数据复制，但影响访存量
- **从 MHA 转换到 GQA 需要重新训练**：不能简单合并 KV head
- **MQA 在大模型上质量损失可接受**：但在小模型上损失明显

## 10. 验证方式

1. 精度：对比 MHA/GQA/MQA 在 benchmark 上的困惑度和下游任务分数
2. 推理：测量 decode 阶段的 KV Cache 显存占用和吞吐
3. 维度推导：在白板上推导完整的前向张量维度变化过程

## 11. 总结

MHA 每个 Q head 有独立 KV head，KV Cache 最大但质量最好；MQA 所有 Q head 共享一组 KV，KV Cache 最小但有质量损失；GQA 是折中方案，每 G 个 Q head 共享一组 KV，几乎不损失质量但显著减少 KV Cache。面试核心考点：三者的 KV head 数差异、推理时前向张量维度变化推导（特别是 GQA 的 repeat_kv）、prefill/decode 阶段的维度差异、GQA 分组数的选择。
