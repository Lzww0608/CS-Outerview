# 62. 模型分组量化与高阶量化方法

## 1. 问题背景

模型量化通过降低权重和/或激活的数值精度来减少显存占用和加速推理。面试常考分组量化（Group-wise Quantization）的分组策略和精度对齐方法，以及 GPTQ、AWQ、SmoothQuant、FP8 等高阶量化方法的原理与适用场景，还有 Tensor Core 计算是否引入误差。

**假设条件**：本文档基于 Transformer 架构的 LLM 推理场景，假设使用 NVIDIA A100/H100 GPU，量化框架包括 AutoGPTQ、AutoAWQ、vLLM、TensorRT-LLM。

## 2. 问题现象

1. **全层量化精度损失大**：整层用同一 scale 和 zero-point，outlier 拉大量化范围导致精度崩塌
2. **分组量化怎么分组**：按多大粒度分组，如何对齐精度
3. **高阶量化方法太多**：GPTQ/AWQ/SmoothQuant/FP8 怎么选
4. **Tensor Core 量化计算是否有误差**：INT8 Tensor Core 和 FP16 Tensor Core 结果是否一致

## 3. 影响范围

| 影响维度 | 程度 | 说明 |
| --- | --- | --- |
| 推理显存 | 高 | INT4 量化可减少 4x 权重显存 |
| 推理吞吐 | 高 | 量化后可用 Tensor Core INT8 加速 |
| 模型精度 | 高 | 量化方法选择直接决定精度损失 |
| 部署灵活性 | 中 | 不同硬件支持不同量化格式 |

## 4. 原因分析

### 4.1 量化基础：Per-Tensor vs Per-Channel vs Per-Group

`
┌──────────────────────────────────────────────────────────────┐
│              量化粒度对比                                     │
├──────────────┬──────────────────┬────────────────────────────┤
│ 粒度         │ 量化参数         │ 精度 / 显存开销            │
├──────────────┼──────────────────┼────────────────────────────┤
│ Per-Tensor   │ 整层 1 组 s, z   │ 精度最低，参数开销最小     │
│ Per-Channel  │ 每行/列 1 组     │ 精度较高，参数开销小       │
│ Per-Group    │ 每 G 元素 1 组   │ 精度最高，参数开销较大     │
│              │ (G=128 常见)     │                            │
└──────────────┴──────────────────┴────────────────────────────┘

Per-Tensor 量化（最简单，精度最差）：
  scale = (max_val - min_val) / (qmax - qmin)
  q_val = round(val / scale + zero_point)

  问题：如果一行有 outlier（如最大值 100，其余值在 [-1, 1]），
  scale 会被 outlier 拉大，[-1, 1] 范围内的值量化后只剩 1~2 个有效 bit。

Per-Group 量化（分组策略）：
  将每行权重按 G 个元素一组，每组独立计算 scale 和 zero_point：
  权重 shape: [out_features, in_features]
  分组后: [out_features, in_features / G] 组量化参数
  
  G = 128 时（常见选择）：
  - 每个 group 内的值范围更小 → 量化精度更高
  - 量化参数开销: 2 × out_features × in_features / 128 bytes (约 1.5% 额外开销)
  - 精度对齐: 解量化时按组恢复，组间边界需连续处理

精度对齐的关键：
  1. 分组大小 G 越小，精度越高，但量化参数越多
  2. G 的选择需平衡精度和参数开销，通常 64~256
  3. 激活值一般用 Per-Token 或 Per-Channel，权重用 Per-Group
  4. 量化后要做校准（Calibration）：用代表性数据集统计激活值范围
`

### 4.2 高阶量化方法

`
┌──────────────────────────────────────────────────────────────┐
│              高阶量化方法对比                                 │
├──────────┬──────────────────┬────────────────┬───────────────┤
│ 方法     │ 核心思想         │ 量化精度       │ 适用场景      │
├──────────┼──────────────────┼────────────────┼───────────────┤
│ GPTQ     │ Hessian 近似     │ INT4/INT3      │ 权重量化      │
│          │ 逐层最优量化     │ 精度较高       │ 离线量化      │
│          │ 补偿量化误差     │                │               │
├──────────┼──────────────────┼────────────────┼───────────────┤
│ AWQ      │ 激活感知         │ INT4           │ 权重量化      │
│          │ 保护重要通道权重  │ 精度高         │ 离线量化      │
│          │ 不需要训练数据   │                │               │
├──────────┼──────────────────┼────────────────┼───────────────┤
│ Smooth-  │ 激活值 outlier   │ W8A8           │ 权重+激活量化 │
│ Quant    │ 迁移到权重       │                │ 在线/离线     │
│          │ 数学等价变换     │                │               │
├──────────┼──────────────────┼────────────────┼───────────────┤
│ FP8      │ 原生 FP8 格式    │ E4M3/E5M2      │ 训练+推理     │
│ (H100)   │ 硬件原生支持     │ 精度接近BF16   │ H100 专属     │
├──────────┼──────────────────┼────────────────┼───────────────┤
│ QAT      │ 训练中模拟量化   │ 任意           │ 精度最高      │
│          │ 量化感知训练     │                │ 需要训练      │
└──────────┴──────────────────┴────────────────┴───────────────┘
`

`python
# GPTQ 核心：Hessian 引导的逐列量化
# 对每列权重，量化后用 Hessian 信息补偿剩余列的误差
def gptq_quantize(W, H_inv, block_size=128):
    """GPTQ 逐列量化"""
    Q = torch.zeros_like(W)
    Err = torch.zeros_like(W)
    
    for i in range(0, W.shape[1], block_size):
        end = min(i + block_size, W.shape[1])
        w_block = W[:, i:end].clone()
        
        # 量化当前 block
        q_block = quantize(w_block)  # INT4 量化
        Q[:, i:end] = q_block
        
        # 计算量化误差
        err_block = (w_block - q_block) / torch.diag(H_inv[i:end])
        Err[:, i:end] = err_block
        
        # 将误差补偿到后续列（Hessian 加权）
        W[:, end:] -= err_block @ H_inv[i:end, end:]
    
    return Q

# AWQ 核心：保护重要通道
# 观察：权重中只有 ~1% 的通道对激活值输出影响最大
# 策略：对重要通道的权重做缩放后再量化
def awq_quantize(W, X, group_size=128):
    """AWQ 激活感知量化"""
    # 计算每个通道的重要性分数
    importance = X.abs().mean(dim=0)  # 按输入维度统计激活值大小
    
    # 搜索最优缩放因子
    best_scale = search_optimal_scale(W, importance, group_size)
    
    # 缩放后量化
    W_scaled = W * best_scale.unsqueeze(0)
    Q = quantize_group(W_scaled, group_size)
    
    return Q, best_scale

# SmoothQuant 核心：激活值 outlier 迁移到权重
# 数学等价：Y = X @ W = (X * s) @ (W / s)  (s 是逐通道缩放因子)
def smooth_quant(W, X):
    """SmoothQuant 激活-权重平衡"""
    # 统计激活值和权重的最大值
    x_max = X.abs().max(dim=0).values  # 逐通道激活最大值
    w_max = W.abs().max(dim=0).values  # 逐通道权重最大值
    
    # 计算平滑因子
    s = (x_max.pow(0.5)) / (w_max.pow(0.5) + 1e-8)
    
    # 平滑变换
    W_smooth = W / s.unsqueeze(0)  # 权重缩小
    X_smooth = X * s.unsqueeze(0)  # 激活放大（减少 outlier）
    
    # 现在两者都可以安全地 INT8 量化
    return W_smooth, X_smooth
`

### 4.3 Tensor Core 计算是否引入误差

`
┌──────────────────────────────────────────────────────────────┐
│           Tensor Core 误差来源分析                            │
├──────────────────────────────────────────────────────────────┤
│ 1. 确实引入误差，但误差来源和大小不同：                       │
│                                                              │
│  FP16 Tensor Core:                                           │
│    • 输入 FP16，累加 FP32，输出 FP16                         │
│    • 误差来自：FP16 输入表示范围有限 + 最终截断到 FP16       │
│    • 误差量级：~1e-3 相对误差                                │
│                                                              │
│  INT8 Tensor Core:                                           │
│    • 输入 INT8，累加 INT32，输出 INT32/FP16                  │
│    • 误差来自：INT8 量化精度损失（仅 256 个离散值）          │
│    • 误差量级：~1e-2 相对误差                                │
│                                                              │
│  FP8 (E4M3/E5M2) Tensor Core (H100):                        │
│    • E4M3: 4 bit 指数, 3 bit 尾数 → 精度类似 FP16           │
│    • E5M2: 5 bit 指数, 2 bit 尾数 → 范围类似 FP16           │
│    • 误差量级：E4M3 ~5e-3, E5M2 ~1e-2                      │
│                                                              │
│ 2. 误差是否可接受：                                          │
│    • 训练：FP16/FP8 Tensor Core 误差通常可接受，            │
│      因为梯度下降有噪声容忍度                                │
│    • 推理：INT8 量化误差需校准验证，                        │
│      特定层（如 Attention Score）对精度更敏感                │
│    • 累积效应：多层推理误差累积，                            │
│      但通常不会指数增长                                      │
│                                                              │
│ 3. 误差不是 Tensor Core 独有的：                             │
│    • CUDA Core 的 FP16 计算也有舍入误差                     │
│    • 差异在于 Tensor Core 的矩阵乘使用不同的                │
│      内部累加和融合策略                                      │
│    • 同一模型用 Tensor Core 和 CUDA Core 的                 │
│      结果可能有微小差异（~1e-5 量级）                        │
└──────────────────────────────────────────────────────────────┘
`

## 5. 解决方案

| 方案 | 显存节省 | 精度损失 | 实现复杂度 | 推荐场景 |
| --- | --- | --- | --- | --- |
| INT4 GPTQ | 4x | 1~3% | 中 | 离线量化，vLLM 部署 |
| INT4 AWQ | 4x | <1% | 低 | 推理首选，兼容性好 |
| W8A8 SmoothQuant | 2x | <1% | 中 | 在线量化，延迟敏感 |
| FP8 (H100) | 2x | <0.5% | 低 | H100 训练+推理 |
| QAT | 可变 | 最小 | 高 | 精度敏感场景 |

## 6. 可选方案对比

| 维度 | GPTQ | AWQ | SmoothQuant | FP8 |
| --- | --- | --- | --- | --- |
| 量化对象 | 权重 INT4 | 权重 INT4 | 权重+激活 INT8 | 权重+激活 FP8 |
| 需要校准数据 | 是 | 是 | 是 | 否 |
| 量化时间 | 慢（数小时） | 快（分钟级） | 快 | 即时 |
| 硬件要求 | 通用 GPU | 通用 GPU | 通用 GPU | H100+ |
| 推理加速 | 2~3x | 2~3x | 1.5~2x | 2x |

## 7. 推荐方案

- **通用推理**：AWQ INT4，精度高、速度快、vLLM 原生支持
- **延迟敏感**：SmoothQuant W8A8，权重和激活同时量化
- **H100 部署**：FP8，硬件原生支持，几乎无精度损失
- **极致压缩**：GPTQ INT4，支持更低位宽（INT3/INT2）

## 8. 实施步骤

1. 选择量化方法和目标精度
2. 准备校准数据集（512~1024 条代表性样本）
3. 运行量化脚本（auto-gptq / autoawq / smoothquant）
4. 验证量化精度（perplexity + 下游任务评测）
5. 部署到推理框架（vLLM / TensorRT-LLM）
6. 端到端性能测试

## 9. 风险与注意事项

- **分组量化的分组大小影响精度和参数开销**：G 越小精度越高但参数越多
- **INT4 量化对某些模型精度影响大**：小模型（<7B）和特殊架构需额外验证
- **Tensor Core INT8 量化有精度损失**：不能假设量化后结果完全一致
- **FP8 需要 H100+ 硬件**：A100 不支持 FP8 Tensor Core
- **量化后 KV Cache 也需考虑**：权重量化后 KV Cache 可能成为新瓶颈

## 10. 验证方式

1. Perplexity：对比量化前后在 WikiText/PG-19 上的困惑度
2. 下游任务：MMLU、HumanEval、GSM8K 等评测集
3. 数值对比：量化前后输出余弦相似度 > 0.99
4. 性能：吞吐提升、延迟降低、显存减少

## 11. 总结

分组量化通过缩小量化粒度（每 G 个元素独立量化参数）显著提高量化精度，G=128 是常见选择。高阶量化方法中，GPTQ 用 Hessian 近似逐列量化补偿误差，AWQ 保护激活重要的权重通道，SmoothQuant 将激活 outlier 迁移到权重实现 W8A8 量化，FP8 是 H100 原生支持的训练+推理量化格式。Tensor Core 计算确实引入误差（INT8 约 1%，FP16 约 0.1%），但在训练和推理中通常可接受，需校准验证。
