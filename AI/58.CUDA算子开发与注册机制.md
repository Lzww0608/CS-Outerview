# 58. CUDA算子开发与注册机制

## 1. 问题背景

在大模型推理和训练中，标准 PyTorch 算子往往无法满足性能需求，需要开发自定义 CUDA 算子（Custom CUDA Kernel）来替代。面试中常考的 CUDA 算子开发包括 Top-K、Sort、Reduce 等基础算子的 GPU 实现，以及如何通过 pybind11/TORCH_LIBRARY 将算子注册到 PyTorch 生态中调用。

**假设条件**：本文档基于 CUDA 12.x + PyTorch 2.x 生态，假设使用 NVIDIA A100/H100 GPU，算子开发面向 LLM 推理加速场景。

## 2. 问题现象

1. **PyTorch 原生 Top-K 性能不足**：`torch.topk` 在大 vocab 场景（如 128K vocab）下成为采样瓶颈
2. **多小算子 launch 开销大**：多个独立 kernel 调用，GPU 利用率低
3. **显存带宽瓶颈**：标准实现频繁读写 HBM，计算效率差
4. **注册流程混乱**：不同框架（PyTorch/TensorFlow）注册方式不同，容易踩坑

## 3. 影响范围

| 影响维度 | 程度 | 说明 |
| --- | --- | --- |
| 推理采样性能 | 高 | Top-K 是采样阶段核心算子 |
| 算子开发效率 | 高 | 注册机制决定了算子能否被框架调用 |
| 模型部署灵活性 | 中 | 自定义算子需要跨平台兼容 |
| 调试难度 | 中 | CUDA kernel 错误难以定位 |

## 4. 原因分析

### 4.1 CUDA Top-K 实现原理

Top-K 问题：从 N 个元素中找出最大的 K 个元素。CPU 上常用堆（`O(N log K)`），GPU 上需要利用并行性：

```
┌─────────────────────────────────────────┐
│         CUDA Top-K 实现策略             │
├─────────────────────────────────────────┤
│ 1. Bitonic Sort（双调排序）             │
│    • 数据并行排序网络                    │
│    • O(N log²N) 比较                    │
│    • 适合 K 较大时                       │
│                                         │
│ 2. Block-level Heap + Grid Reduce       │
│    • 每个 Block 维护大小为 K 的堆       │
│    • 每个 Thread 处理多个元素           │
│    • Block 结果做 Grid 级 Reduce        │
│    • 适合 K 较小时                       │
│                                         │
│ 3. Warp-level Reduction                │
│    • 利用 Warp Shuffle 原语             │
│    • 32 线程内高效 Top-K                │
│    • 适合 K ≤ 32                        │
└─────────────────────────────────────────┘
```

```cuda
// Block-level Top-K 实现（简化版）
// 每个 Block 处理一段输入，维护大小为 K 的堆
__global__ void topk_kernel(
    const float* __restrict__ input,
    float* __restrict__ values,
    int* __restrict__ indices,
    int N, int K
) {
    // Shared memory 存储每个 block 的 Top-K 候选
    extern __shared__ float smem[];
    int* smem_idx = (int*)(smem + K * blockDim.x);

    int tid = threadIdx.x;
    int gid = blockIdx.x * blockDim.x + tid;

    // 初始化每个 thread 的 Top-K 为 -inf
    for (int i = 0; i < K; i++) {
        smem[tid * K + i] = -FLT_MAX;
        smem_idx[tid * K + i] = -1;
    }
    __syncthreads();

    // 每个 thread 遍历自己的元素，维护小顶堆
    for (int i = gid; i < N; i += blockDim.x * gridDim.x) {
        float val = input[i];
        if (val > smem[tid * K]) {  // 比堆顶大
            // 替换堆顶并下沉调整
            smem[tid * K] = val;
            smem_idx[tid * K] = i;
            heap_sift_down(smem + tid * K, smem_idx + tid * K, K);
        }
    }
    __syncthreads();

    // Block 级归约：合并所有 thread 的 Top-K
    // ... warp shuffle 或 serial reduce
}
```

### 4.2 Warp 指令与 Warp Shuffle

Warp 是 GPU 调度的基本单位，32 个线程组成一个 Warp，以锁步（lockstep）方式执行同一条指令。

```
┌──────────────────────────────────────────────┐
│            Warp 级指令与原语                  │
├──────────────────────────────────────────────┤
│ Warp Shuffle 指令：                          │
│   __shfl_sync(mask, var, srcLane)            │
│   → 从指定 lane 读取变量                     │
│                                              │
│   __shfl_up_sync(mask, var, delta)           │
│   → 从上方 delta 距离的 lane 读取            │
│   __shfl_down_sync(mask, var, delta)         │
│   → 从下方 delta 距离的 lane 读取            │
│   __shfl_xor_sync(mask, var, laneMask)       │
│   → 与 laneMask 异或的 lane 交换             │
│                                              │
│ 典型应用场景：                               │
│   1. Warp 级规约（Reduce）：Sum/Max/Min     │
│   2. Warp 级 Top-K：配合堆或排序网络        │
│   3. 矩阵乘分块内数据共享                    │
│   4. 前缀和（Scan / Prefix Sum）             │
│   5. Broadcast：一个值广播到 warp 所有 lane  │
└──────────────────────────────────────────────┘
```

```cuda
// Warp 级求和规约（利用 shuffle）
__device__ float warp_reduce_sum(float val) {
    for (int offset = 16; offset > 0; offset >>= 1) {
        val += __shfl_down_sync(0xffffffff, val, offset);
    }
    return val;
}

// Warp 级求最大值
__device__ float warp_reduce_max(float val) {
    for (int offset = 16; offset > 0; offset >>= 1) {
        float other = __shfl_down_sync(0xffffffff, val, offset);
        val = fmaxf(val, other);
    }
    return val;
}

// Warp Shuffle 除了规约还可以做：
// 1. 前缀和（Scan）
__device__ float warp_exclusive_scan(float val) {
    // Step 1: 从前 1 个 lane 获取
    float sum = __shfl_up_sync(0xffffffff, val, 1);
    if (threadIdx.x % 32 > 0) val += sum;
    // Step 2: 从前 2 个 lane 获取
    sum = __shfl_up_sync(0xffffffff, val, 2);
    if (threadIdx.x % 32 > 1) val += sum;
    // Step 3: 从前 4 个 lane 获取
    sum = __shfl_up_sync(0xffffffff, val, 4);
    if (threadIdx.x % 32 > 3) val += sum;
    // Step 4: 从前 8 个 lane 获取
    sum = __shfl_up_sync(0xffffffff, val, 8);
    if (threadIdx.x % 32 > 7) val += sum;
    // Step 5: 从前 16 个 lane 获取
    sum = __shfl_up_sync(0xffffffff, val, 16);
    if (threadIdx.x % 32 > 15) val += sum;
    return val;
}
```

### 4.3 算子融合原理

算子融合（Kernel Fusion / Operator Fusion）是将多个独立 GPU kernel 合并为一个 kernel 执行，减少中间结果的 HBM 读写和 kernel launch 开销。

```
┌──────────────────────────────────────────────────────┐
│               算子融合原理                            │
├──────────────────────────────────────────────────────┤
│ 融合前：                                             │
│   Input → [Kernel1] → HBM → [Kernel2] → HBM → Out  │
│   2 次 kernel launch + 2 次 HBM 写 + 2 次 HBM 读   │
│                                                      │
│ 融合后：                                             │
│   Input → [Fused Kernel] → Out                      │
│   1 次 kernel launch + 1 次 HBM 写 + 1 次 HBM 读   │
│                                                      │
│ 收益来源：                                           │
│   1. 减少 HBM 访问次数（最大收益）                   │
│   2. 减少 kernel launch 开销（约 2~5μs/launch）     │
│   3. 中间结果可在 SRAM/寄存器中复用                  │
│   4. 编译器可做指令级优化                            │
└──────────────────────────────────────────────────────┘
```

常见融合模式：
- **Epilogue 融合**：GEMM + Bias + Activation（如 ReLU/GELU/SiLU）融合为一个 kernel
- **Attention 融合**：QK^T + Softmax + Dropout + AV 融合为 FlashAttention
- **Normalization 融合**：LayerNorm/RMSNorm + Residual + Dropout 融合
- **量化融合**：Dequant + GEMM + Quant 融合

### 4.4 算子融合开发流程

```
1. 性能分析 → 定位瓶颈算子（nsight compute / ncu）
2. 融合机会识别 → 查看相邻算子的数据流
3. 设计融合策略 → 确定融合边界和 SRAM 使用方案
4. 编写 CUDA Kernel → 手写或使用 Triton
5. 注册到框架 → pybind11 / TORCH_LIBRARY
6. 正确性验证 → 对比 PyTorch 原生结果
7. 性能验证 → ncu profile 对比
```

### 4.5 pybind11 算子注册

```cpp
// my_kernel.cu - CUDA 算子实现
__global__ void my_topk_kernel(...) { /* ... */ }

// my_kernel.cpp - Host 端接口
void launch_my_topk(torch::Tensor input, torch::Tensor values,
                    torch::Tensor indices, int k) {
    // 调用 CUDA kernel
    my_topk_kernel<<<grid, block, smem_size, stream>>>(
        input.data_ptr<float>(),
        values.data_ptr<float>(),
        indices.data_ptr<int>(),
        input.numel(), k
    );
}

// 绑定到 PyTorch
TORCH_LIBRARY(my_ops, m) {
    m.def("my_topk(Tensor input, int k) -> (Tensor, Tensor)");
}

TORCH_LIBRARY_IMPL(my_ops, CUDA, m) {
    m.impl("my_topk", &launch_my_topk);
}
```

```python
# Python 端调用
import torch
torch.ops.my_ops.my_topk(input_tensor, k=5)
```

## 5. 解决方案

| 方案 | 优点 | 缺点 | 适用场景 |
| --- | --- | --- | --- |
| PyTorch 原生算子 | 开发成本低，兼容性好 | 性能不够极致 | 原型验证 |
| 手写 CUDA Kernel | 性能最优 | 开发和调试成本高 | 性能瓶颈算子 |
| Triton | 开发效率高，接近手写性能 | 灵活性不如 CUDA | 大部分融合场景 |
| CUDA Templates | 复用 CUTLASS 组件 | 学习曲线陡 | GEMM/Conv 类算子 |
| torch.compile | 自动融合 | 不支持复杂自定义逻辑 | 简单算子融合 |

## 6. 可选方案对比

| 维度 | 手写 CUDA | Triton | torch.compile |
| --- | --- | --- | --- |
| 开发效率 | 低（1~2 周/算子） | 中（2~3 天/算子） | 高（自动） |
| 性能上限 | 最高 | 高 | 中等 |
| 调试难度 | 高 | 中 | 低 |
| 灵活性 | 最高 | 高 | 低 |
| 可移植性 | 低 | 中 | 高 |

## 7. 推荐方案

- **性能瓶颈算子**：手写 CUDA Kernel + CUTLASS 组件，通过 TORCH_LIBRARY 注册
- **一般融合场景**：Triton 实现，开发效率高且性能接近手写
- **简单融合**：torch.compile 自动融合

## 8. 实施步骤

1. 使用 `ncu` 或 `torch.profiler` 定位性能瓶颈算子
2. 分析数据流，识别融合机会
3. 选择实现方式（CUDA/Triton）
4. 实现融合 kernel 并注册到框架
5. 正确性测试：对比 PyTorch 原生结果，`torch.allclose` 验证
6. 性能测试：`ncu` 对比 roofline，确认逼近算力或带宽上限

## 9. 风险与注意事项

- **Warp Shuffle 要求同一 Warp 内所有线程参与**：分支导致未定义行为
- **Shared Memory 银行冲突**：影响实际带宽，需用 padding 避免
- **算子注册的 dispatch 机制**：CUDA 和 CPU 实现需分别注册
- **PyTorch 版本兼容性**：TORCH_LIBRARY 接口在不同版本间有差异
- **数值精度**：融合后中间结果不落 HBM，可能因浮点结合性差异导致微小数值偏差

## 10. 验证方式

1. 正确性：对比融合前后的输出，`torch.allclose(rtol=1e-3, atol=1e-5)`
2. 性能：`ncu --set full` 分析 kernel 的 SM 利用率、HBM 带宽利用率
3. 端到端：推理吞吐提升比例，首 Token 延迟降低比例

## 11. 总结

CUDA 算子开发是大模型推理优化的核心技能。面试常考 Top-K 的并行实现策略（Bitonic Sort / Block-Heap / Warp Reduction）、Warp Shuffle 的应用场景（规约、前缀和、数据共享）、算子融合的原理（减少 HBM 访问）和开发流程（瓶颈分析→融合设计→实现→注册→验证）。注册机制方面，TORCH_LIBRARY 是 PyTorch 2.x 推荐方式，配合 pybind11 可实现 C++/CUDA 算子的无缝集成。
