# 47. Agent 系统死循环防护机制

## 1. 问题背景

Agent 系统通过 LLM 驱动多步推理和工具调用来完成复杂任务。在执行过程中，Agent 可能因为以下原因进入死循环：

1. **工具调用循环**：Agent 反复调用同一个工具但结果未收敛
2. **规划循环**：Agent 不断制定、执行、撤销计划，无法完成任务
3. **LLM 幻觉循环**：Agent 产生自我强化的错误推理
4. **外部环境不变循环**：外部状态未变化，Agent 重复相同操作
5. **上下文污染循环**：错误信息在上下文中累积并放大

死循环会导致资源浪费、任务失败，严重时可能导致系统崩溃或产生大量错误输出。

**假设条件**：本文档基于通用的 Agent 系统架构（如 ReAct、Plan-Execute），假设系统具备基本的执行环境能力（超时控制、计数器、状态持久化等）。

## 2. 问题现象

Agent 进入死循环时通常表现为：

1. **执行时间异常长**：单个任务执行时间远超预期
2. **工具调用次数激增**：相同或相似工具被反复调用
3. **上下文持续膨胀**：历史记录快速累积
4. **输出结果重复**：Agent 反复输出相似或相同的响应
5. **资源占用攀升**：CPU、内存或 Token 消耗异常
6. **响应质量下降**：输出越来越混乱或偏离原始目标

## 3. 影响范围

| 影响维度 | 程度 | 说明 |
| --- | --- | --- |
| 用户体验 | 高 | 任务长时间无响应或失败 |
| 系统资源 | 高 | Token 浪费、内存泄漏、算力浪费 |
| 服务稳定性 | 中 | 资源耗尽可能影响其他任务 |
| 数据准确性 | 中 | 循环输出可能导致错误数据 |
| 成本控制 | 高 | LLM API 调用成本急剧上升 |

## 4. 原因分析

### 4.1 死循环的根本原因

**1. 缺乏外部变化感知**
```
Agent 执行 -> 工具调用 -> 外部状态未变化 -> Agent 认为未完成 -> 再次执行
```

**2. 条件判断失效**
```text
while (condition) {
    action();
    // condition 永远为 true，因为缺少退出条件更新
}
```

**3. 上下文错误累积**
```text
错误信息A -> 推理错误B -> 基于B推理错误C -> 错误累积放大
```

**4. 工具选择循环**
```text
工具A失败 -> 工具B失败 -> 工具A -> 工具B -> 无限循环
```

### 4.2 常见触发场景

1. **数据库操作**：UPDATE 后未验证结果，反复执行
2. **API 调用**：依赖外部状态，但外部状态不变
3. **文件操作**：权限问题或路径问题导致操作失败
4. **网络请求**：超时、重试逻辑不当
5. **多 Agent 协作**：Agent 间相互等待或重复任务

## 5. 解决方案

### 5.1 层级防护机制

建立多层防护机制，形成纵深防御：

```text
┌─────────────────────────────────────────────────┐
│              L7: 用户主动中断                     │
├─────────────────────────────────────────────────┤
│              L6: 异常熔断机制                      │
├─────────────────────────────────────────────────┤
│              L5: 任务超时控制                      │
├─────────────────────────────────────────────────┤
│              L4: 循环检测与终止                    │
├─────────────────────────────────────────────────┤
│              L3: 资源配额管理                      │
├─────────────────────────────────────────────────┤
│              L2: 执行状态追踪                      │
├─────────────────────────────────────────────────┤
│              L1: 基础防护（超时、计数器）          │
└─────────────────────────────────────────────────┘
```

### 5.2 具体防护措施

#### 5.2.1 基础防护层（L1）

```python
class LoopProtection:
    def __init__(self, max_iterations=50, max_time_seconds=300):
        self.max_iterations = max_iterations
        self.max_time_seconds = max_time_seconds
        self.iteration_count = 0
        self.start_time = None
    
    def check(self):
        self.iteration_count += 1
        if self.iteration_count > self.max_iterations:
            raise LoopDetectedError(f"迭代次数超过限制: {self.max_iterations}")
        
        if self.start_time and (time.time() - self.start_time) > self.max_time_seconds:
            raise TimeoutError(f"执行时间超过限制: {self.max_time_seconds}")
```

#### 5.2.2 执行状态追踪（L2）

```python
class ExecutionTracker:
    def __init__(self):
        self.execution_history = []
        self.state_signatures = {}
    
    def record_step(self, action, observation, result):
        signature = self._compute_signature(action, observation)
        self.execution_history.append({
            'action': action,
            'observation': observation,
            'result': result,
            'signature': signature
        })
        
        if signature in self.state_signatures:
            self.state_signatures[signature] += 1
            if self.state_signatures[signature] > 3:
                return True  # 检测到重复
        else:
            self.state_signatures[signature] = 1
        return False
    
    def _compute_signature(self, action, observation):
        # 使用哈希提取关键特征
        content = f"{action}{observation}"
        return hashlib.md5(content.encode()).hexdigest()[:16]
```

#### 5.2.3 资源配额管理（L3）

```python
class ResourceQuota:
    def __init__(self, max_tokens=100000, max_tool_calls=100, max_cost=10.0):
        self.max_tokens = max_tokens
        self.max_tool_calls = max_tool_calls
        self.max_cost = max_cost
        self.used_tokens = 0
        self.tool_call_count = 0
        self.total_cost = 0.0
    
    def check(self):
        if self.used_tokens > self.max_tokens:
            raise QuotaExceededError("Token 配额超限")
        if self.tool_call_count > self.max_tool_calls:
            raise QuotaExceededError("工具调用次数超限")
        if self.total_cost > self.max_cost:
            raise QuotaExceededError("成本超限")
```

#### 5.2.4 循环检测与终止（L4）

```python
class CycleDetector:
    def __init__(self, similarity_threshold=0.85, window_size=5):
        self.similarity_threshold = similarity_threshold
        self.window_size = window_size
        self.recent_states = deque(maxlen=window_size)
    
    def check_cycle(self, new_state):
        # 添加新状态
        self.recent_states.append(new_state)
        
        if len(self.recent_states) < 3:
            return False
        
        # 检测循环模式
        for i in range(len(self.recent_states)):
            for j in range(i + 2, len(self.recent_states)):
                window_i = list(self.recent_states)[i:]
                window_j = list(self.recent_states)[j:]
                
                if self._similar(window_i, window_j):
                    return True
        return False
    
    def _similar(self, seq1, seq2):
        if len(seq1) != len(seq2):
            return False
        
        matches = sum(s1 == s2 for s1, s2 in zip(seq1, seq2))
        return matches / len(seq1) >= self.similarity_threshold
```

#### 5.2.5 任务超时控制（L5）

```python
class TimeoutController:
    def __init__(self, task_timeout=600, step_timeout=30):
        self.task_timeout = task_timeout
        self.step_timeout = step_timeout
    
    def should_terminate(self, context):
        if context.elapsed_time > self.task_timeout:
            return True, "任务执行超时"
        
        step_time = context.last_step_duration
        if step_time > self.step_timeout * 3:  # 连续超时
            return True, "步骤执行超时"
        
        return False, None
```

#### 5.2.6 异常熔断机制（L6）

```python
class CircuitBreaker:
    def __init__(self, failure_threshold=5, recovery_timeout=60):
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.failure_count = 0
        self.last_failure_time = None
        self.state = "CLOSED"  # CLOSED, OPEN, HALF_OPEN
    
    def record_failure(self):
        self.failure_count += 1
        self.last_failure_time = time.time()
        
        if self.failure_count >= self.failure_threshold:
            self.state = "OPEN"
            return True  # 触发熔断
        return False
    
    def should_allow(self):
        if self.state == "CLOSED":
            return True
        
        if self.state == "OPEN":
            if time.time() - self.last_failure_time > self.recovery_timeout:
                self.state = "HALF_OPEN"
                return True
            return False
        
        if self.state == "HALF_OPEN":
            return True  # 允许尝试
        
        return False
```

## 6. 可选方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
| --- | --- | --- | --- |
| 简单计数器 | 实现简单，资源消耗低 | 无法识别语义相似循环 | 轻量级 Agent |
| 状态签名检测 | 能识别语义重复 | 需要状态序列化 | 中等复杂度任务 |
| 相似度分析 | 能识别近似重复 | 计算开销大 | 需要精确控制的场景 |
| 多层防护 | 全面覆盖 | 实现复杂 | 生产环境 |
| 外部监控 | 实时响应 | 需要额外基础设施 | 大规模部署 |

## 7. 推荐方案

**综合推荐：多层防护 + 状态签名检测**

```python
class AgentLoopProtection:
    def __init__(self):
        self.protection = LoopProtection(max_iterations=50)
        self.tracker = ExecutionTracker()
        self.quota = ResourceQuota()
        self.cycle_detector = CycleDetector()
        self.timeout = TimeoutController()
        self.circuit_breaker = CircuitBreaker()
    
    def check(self, context):
        # 按优先级执行检查
        checks = [
            ("熔断", lambda: (not self.circuit_breaker.should_allow(), "系统熔断中")),
            ("资源", lambda: (False, self.quota.check())),
            ("超时", lambda: self.timeout.should_terminate(context)),
            ("循环", lambda: (self.cycle_detector.check_cycle(context.state), "检测到循环模式")),
            ("迭代", lambda: (False, self.protection.check())),
        ]
        
        for name, check_fn in checks:
            is_terminate, msg = check_fn
            if is_terminate:
                self.circuit_breaker.record_failure()
                return False, f"{name}: {msg}"
        
        return True, None
```

## 9. 风险与注意事项

### 9.1 误杀风险

**问题**：正常的长任务可能被误判为死循环

**缓解措施**：
1. 任务类型分级配置
2. 可配置的阈值参数
3. 人工审批通道
4. 白名单机制

```python
class AdaptiveProtection:
    def __init__(self):
        self.base_config = {"max_iterations": 50}
        self.task_configs = {
            "quick_task": {"max_iterations": 10},
            "complex_analysis": {"max_iterations": 200},
            "code_generation": {"max_iterations": 100},
        }
    
    def get_config(self, task_type):
        return self.task_configs.get(task_type, self.base_config)
```

### 9.2 逃逸风险

**问题**：恶意 Agent 可能绕过防护机制

**缓解措施**：
1. 服务端强制执行，不能依赖客户端
2. 多层级验证
3. 审计日志

### 9.3 上下文截断风险

**问题**：防护触发时可能丢失关键状态

**缓解措施**：
1. 检查点保存
2. 优雅降级
3. 状态摘要输出

```python
def graceful_termination(self, context):
    # 保存检查点
    checkpoint = {
        "step": context.current_step,
        "state": context.get_state_summary(),
        "history": context.get_history_summary(),
        "error": "Loop detected"
    }
    
    # 输出摘要
    return {
        "status": "terminated",
        "checkpoint": checkpoint,
        "message": f"任务在第{checkpoint['step']}步因循环检测被终止"
    }
```

## 11. 总结

Agent 系统死循环是一个多层面的工程问题，需要建立纵深防护机制：

1. **基础层**：计数器、超时控制、资源配额
2. **检测层**：状态签名、相似度分析、循环模式识别
3. **控制层**：熔断机制、任务中断、优雅降级
4. **用户层**：主动中断、进度反馈、状态摘要

推荐采用多层级防护策略，根据任务复杂度配置不同阈值，并通过监控和告警持续优化防护参数。关键是平衡"防止死循环"和"不误杀正常长任务"两个目标。
