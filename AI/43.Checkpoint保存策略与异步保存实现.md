# 43. Checkpoint保存策略与异步保存实现

## 1. 问题背景

在大模型训练过程中，Checkpoint（训练快照）是防止训练中断导致进度丢失的关键机制。由于大模型 checkpoint 体积庞大（从数十 GB 到数 TB 不等），同步保存会显著阻塞训练流程，影响 GPU 利用率。

**假设条件**：本文档基于 PyTorch 生态（FSDP、DeepSpeed）、千亿参数级别大模型训练场景，假设使用分布式文件系统（如 HDFS、NFS、CephFS）作为 checkpoint 存储后端，训练集群规模为 8~64 张 GPU。

## 2. 问题现象

1. **保存时间过长**：单次 checkpoint 保存耗时从几分钟到数十分钟不等，严重影响训练效率。
2. **GPU 利用率骤降**：保存期间所有 GPU 必须同步等待，利用率归零或降至个位数。
3. **训练中断风险集中**：保存过程中如果发生节点故障，会丢失整个 checkpoint，导致回退到上一个保存点。
4. **存储压力**：频繁保存大量 checkpoint 占用大量存储空间。
5. **版本管理混乱**：缺乏统一的 checkpoint 版本管理，容易出现版本错乱或覆盖。

## 3. 影响范围

| 影响维度 | 程度 | 说明 |
| --- | --- | --- |
| 训练效率 | 高 | 同步保存直接阻塞训练，计算资源浪费 |
| 故障恢复成本 | 高 | checkpoint 间隔越大，故障后重训时间越长 |
| 存储成本 | 中 | 多版本 checkpoint 占用大量分布式存储 |
| 工程复杂度 | 中 | 异步保存、版本管理增加了系统复杂度 |
| 运维负担 | 中 | checkpoint 验证、清理需要额外工具链 |

## 4. 原因分析

### 4.1 同步保存的阻塞特性

传统的 checkpoint 保存采用同步 IO 模式：

```python
# 同步保存（阻塞）
torch.save(model.state_dict(), "checkpoint.pt")  # GPU 等待写入完成
save_optimizer_state()  # 同样阻塞
```

保存过程中，GPU 必须等待数据完全写入存储后才能继续训练。

### 4.2 模型规模与 IO 带宽不匹配

- 百亿参数模型以 BF16 保存，单个 checkpoint 约 200GB。
- 假设网络文件系统带宽为 10 GB/s，保存也需要 ~20 秒。
- 如果使用 HDD 或远程 NFS，带宽更低，保存时间可能达到分钟级。

### 4.3 分布式训练中的同步点

在 FSDP 或流水线并行中，所有 rank 必须同时保存，且通常需要保存到同一个分布式文件系统，IO 竞争严重。

### 4.4 保存策略缺乏自适应

大多数实现使用固定步数间隔保存，无法根据训练阶段、显存使用、IO 负载动态调整。

## 5. 解决方案

### 5.1 异步保存架构

**核心思路**：将保存操作从训练 critical path 中分离，使用独立进程或线程处理 IO。

```python
import threading
import queue
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP

class AsyncCheckpointManager:
    def __init__(self, save_dir, queue_size=2):
        self.save_dir = save_dir
        self.checkpoint_queue = queue.Queue(maxsize=queue_size)
        self.save_thread = threading.Thread(target=self._save_worker, daemon=True)
        self.save_thread.start()
    
    def _save_worker(self):
        while True:
            checkpoint_data = self.checkpoint_queue.get()
            if checkpoint_data is None:
                break
            step, model_state, optimizer_state = checkpoint_data
            path = f"{self.save_dir}/checkpoint_{step}.pt"
            self._save_to_disk(path, model_state, optimizer_state)
    
    def _save_to_disk(self, path, model_state, optimizer_state):
        # 使用 safetensors 格式加速保存
        from safetensors.torch import save_file
        save_file(model_state, path.replace(".pt", ".safetensors"))
        torch.save(optimizer_state, path.replace(".safetensors", "_opt.pt"))
    
    def save_async(self, step, model, optimizer):
        """非阻塞保存，模型状态已在保存前完成分片聚合"""
        model_state = model.state_dict()
        optimizer_state = optimizer.state_dict()
        
        # 放入队列，如果队列满则阻塞等待
        self.checkpoint_queue.put((step, model_state, optimizer_state))
    
    def flush(self):
        """强制同步，等待所有保存任务完成"""
        self.checkpoint_queue.join()
```

### 5.2 分层存储策略

**热数据**：最新 checkpoint 保存在本地 SSD，支持快速恢复。
**温数据**：定期同步到网络文件系统（NFS/HDFS）。
**冷数据**：长期归档到对象存储（AWS S3、MinIO）。

```python
class TieredCheckpointStorage:
    def __init__(self):
        self.local_dir = "/tmp/checkpoints"
        self.remote_dir = "hdfs:///ml/checkpoints"
        self.archive_dir = "s3://ml-archive/checkpoints"
    
    def save(self, step, state_dicts):
        # 1. 先保存到本地 SSD（快速）
        local_path = f"{self.local_dir}/ckpt_{step}"
        torch.save(state_dicts, local_path)
        
        # 2. 异步上传到 HDFS（后台）
        threading.Thread(
            target=self._upload_to_remote,
            args=(local_path, f"{self.remote_dir}/ckpt_{step}"),
            daemon=True
        ).start()
        
        # 3. 定期归档到对象存储
        if step % 1000 == 0:
            self._archive_to_cold_storage(step)
```

### 5.3 增量保存与分片上传

**只保存增量变化**：

```python
class IncrementalCheckpoint:
    def __init__(self):
        self.base_ckpt = None
        self.delta_history = []
    
    def save_incremental(self, step, model, base_step=100):
        # 定期保存全量 checkpoint
        if step % base_step == 0:
            full_state = model.state_dict()
            torch.save(full_state, f"ckpt_{step}.pt")
            self.base_ckpt = step
            self.delta_history = []  # 重置增量历史
        else:
            # 只保存与上一个 checkpoint 的差异
            delta = self._compute_delta(model)
            self.delta_history.append((step, delta))
            torch.save(self.delta_history, f"delta_{self.base_ckpt}_{step}.pt")
    
    def restore(self, target_step):
        base_state = torch.load(f"ckpt_{self.base_ckpt}.pt")
        deltas = [d for s, d in self.delta_history if s <= target_step]
        return self._apply_deltas(base_state, deltas)
```

### 5.4 通信与保存重叠

利用 FSDP 的分片特性，在收集参数进行保存时，同时触发其他操作：

```python
# DeepSpeed 异步 checkpoint 示例
from deepspeed.runtime.checkpoint_engine.torch.save_engine import TorchSaveEngine

class OverlapCheckpointEngine(TorchSaveEngine):
    def __init__(self, config):
        super().__init__(config)
        self.copy_stream = torch.cuda.Stream()
    
    def save(self, state_dict, path):
        # 使用独立 CUDA 流复制数据
        with torch.cuda.stream(self.copy_stream):
            # 复制到临时 buffer
            temp_buffer = {k: v.cpu().clone() for k, v in state_dict.items()}
        
        # 主计算流继续训练
        torch.cuda.current_stream().wait_stream(self.copy_stream)
        
        # 后台线程写入磁盘
        threading.Thread(target=torch.save, args=(temp_buffer, path)).start()
```

## 6. 可选方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
| --- | --- | --- | --- |
| 线程池异步保存 | 实现简单，改动小 | Python GIL 限制，CPU bound | 小规模训练 |
| 独立进程保存 | 绕过 GIL，可完全并行 | IPC 开销，状态序列化复杂 | 中等规模 |
| 独立 CUDA 流复制 + 后台线程 | GPU 无需等待 IO | 需要额外显存 buffer | 大规模 FSDP |
| 分层存储 | 平衡速度与成本 | 需要额外存储基础设施 | 长期训练项目 |
| 增量 checkpoint | 大幅减少保存数据量 | 恢复逻辑复杂 | 超大规模模型 |

## 7. 推荐方案

**推荐方案：独立进程 + 层级存储 + 智能间隔**

理由：
1. 独立进程方案稳定性最高，不受训练进程崩溃影响。
2. 分层存储兼顾恢复速度和长期存储成本。
3. 智能间隔可以根据训练阶段动态调整保存频率。

**实施优先级**：
1. 首先实现基于独立进程的异步保存。
2. 配置本地 SSD + HDFS 分层存储。
3. 根据训练稳定性设置自适应保存间隔（如前 1000 步每 100 步保存，之后每 500 步保存）。

### 步骤 2：实现异步保存模块

创建 `checkpoint/async_saver.py`：

```python
import os
import queue
import threading
import torch
from pathlib import Path

class AsyncCheckpointSaver:
    """独立进程异步保存器"""
    
    def __init__(self, save_dir, max_queue_size=2):
        self.save_dir = Path(save_dir)
        self.save_dir.mkdir(parents=True, exist_ok=True)
        
        # 父子进程通信队列
        self.task_queue = queue.Queue(maxsize=max_queue_size)
        self.result_queue = queue.Queue()
        
        # 启动保存进程
        self.save_process = threading.Thread(
            target=self._worker_loop,
            daemon=True,
            name="AsyncCheckpointSaver"
        )
        self.save_process.start()
    
    def _worker_loop(self):
        """后台保存线程"""
        while True:
            task = self.task_queue.get()
            if task is None:  # 停止信号
                break
            
            step, state_dict, metadata = task
            try:
                self._save_checkpoint(step, state_dict, metadata)
                self.result_queue.put(("success", step))
            except Exception as e:
                self.result_queue.put(("error", step, str(e)))
            finally:
                self.task_queue.task_done()
    
    def _save_checkpoint(self, step, state_dict, metadata):
        """实际保存逻辑"""
        ckpt_path = self.save_dir / f"checkpoint_{step}"
        
        # 使用 safetensors 格式加速
        from safetensors.torch import save_file
        tensors = {k: v for k, v in state_dict.items() if torch.is_tensor(v)}
        save_file(tensors, str(ckpt_path) + ".safetensors")
        
        # 保存元数据
        torch.save(metadata, str(ckpt_path) + "_meta.pt")
    
    def save(self, step, state_dict, metadata=None):
        """非阻塞保存"""
        metadata = metadata or {}
        metadata["step"] = step
        metadata["timestamp"] = torch.cuda.Event(enable_timing=True)
        
        self.task_queue.put((step, state_dict, metadata))
    
    def wait(self):
        """等待所有保存完成"""
        self.task_queue.join()
    
    def shutdown(self):
        self.task_queue.put(None)
        self.save_process.join(timeout=10)
```

### 步骤 4：配置分层存储

```python
# storage/tiered.py
import shutil
from pathlib import Path

class TieredStorage:
    def __init__(self, local_dir, remote_dir, archive_dir=None):
        self.local = Path(local_dir)
        self.remote = Path(remote_dir)
        self.archive = Path(archive_dir) if archive_dir else None
    
    def sync_to_remote(self, step):
        """异步同步到远程存储"""
        src = self.local / f"checkpoint_{step}"
        dst = self.remote / f"checkpoint_{step}"
        
        def _copy():
            shutil.copytree(src, dst, dirs_exist_ok=True)
            # 清理本地旧 checkpoint（保留最近 2 个）
            self._cleanup_local(keep_recent=2)
        
        threading.Thread(target=_copy, daemon=True).start()
    
    def _cleanup_local(self, keep_recent=2):
        """清理本地旧 checkpoint"""
        ckpts = sorted(self.local.glob("checkpoint_*"))
        for ckpt in ckpts[:-keep_recent]:
            shutil.rmtree(ckpt)
```

### 步骤 5：设置智能保存间隔

```python
class AdaptiveSaveInterval:
    def __init__(self, base_interval=100, min_interval=50, max_interval=1000):
        self.base = base_interval
        self.min = min_interval
        self.max = max_interval
        self.loss_history = []
    
    def should_save(self, step, loss):
        self.loss_history.append(loss)
        
        # 早期训练密集保存
        if step < 1000:
            return step % self.min == 0
        
        # 检测 loss spike，提前保存
        if len(self.loss_history) > 10:
            recent_std = torch.std(torch.tensor(self.loss_history[-10:]))
            if abs(loss - self.loss_history[-1]) > 3 * recent_std:
                return True
        
        return step % self.base == 0
```

## 9. 风险与注意事项

| 风险 | 缓解措施 |
| --- | --- |
| 保存进程崩溃丢失数据 | 定期同步到可靠存储，保存前做完整性校验 |
| 版本不一致 | 使用原子写入（先写 .tmp 再 rename） |
| 恢复时找不到 checkpoint | 保存后立即验证元数据，记录最新可用 checkpoint |
| 存储空间耗尽 | 设置存储配额，定期清理老旧 checkpoint |
| GPU 显存被 buffer 占用 | 使用 CPU 内存作为临时存储，避免占用 GPU 显存 |

## 11. 总结

Checkpoint 保存策略需要在训练效率和故障恢复成本之间取得平衡。异步保存通过将 IO 操作从训练 critical path 中分离，可以显著减少 GPU 空转时间。

**核心要点回顾**：
- 同步保存是训练效率的主要瓶颈之一。
- 异步保存通过独立进程或线程实现非阻塞 IO。
- 分层存储兼顾恢复速度和存储成本。
- 智能保存间隔可以根据训练阶段动态调整。
- 完整性校验和故障恢复演练是必不可少的验证手段。
