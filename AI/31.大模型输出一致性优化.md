# 大模型输出一致性优化

## 1. 问题背景

大语言模型（LLM）在实际应用中经常遇到同一输入在不同调用时输出结果不一致的问题。这在生产环境中会导致用户体验不稳定、结果不可复现、评测困难等问题。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  问题场景：                                                 │
│                                                             │
│  用户输入："给我写一个排序算法"                             │
│                                                             │
│  第1次输出：冒泡排序（C++实现）                             │
│  第2次输出：快速排序（Python实现）                         │
│  第3次输出：归并排序（Java实现）                           │
│                                                             │
│  期望：输出一致稳定                                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 2. 问题现象

| 现象 | 描述 | 示例 |
|------|------|------|
| 回答内容差异 | 相同问题不同回答 | 排序算法版本不同 |

## 4. 原因分析

### 4.1 随机性来源

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  LLM 输出随机性的根本原因：                                 │
│                                                             │
│  1. Sampling 采样过程                                      │
│     • Top-k 采样：随机选择前 k 个 token                    │
│     • Top-p (Nucleus)：按概率阈值采样                       │
│     • Temperature：控制概率分布平滑度                       │
│                                                             │
│  2. 模型内部随机性                                         │
│     • 注意力计算的 Softmax 随机性                          │
│     • 批处理并行计算的微小差异                             │
│                                                             │
│  3. 硬件和精度                      │
│     • GPU 浮点运算非确定性                                │
│     • INT8/FP16 量化误差                                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 核心原理

```python
# LLM 生成过程的随机性

def generate_with_sampling(logits, temperature=1.0, top_k=50, top_p=0.9):
    """
    采样过程的随机性来源
    """
    # 1. Temperature: 平滑或尖锐化概率分布
    # temperature = 0: greedy, 完全确定性
    # temperature > 1: 平滑分布，增加随机性
    probs = softmax(logits / temperature)
    
    # 2. Top-k: 限制候选 token 数量
    # 随机从 top-k 中选择
    top_k_probs = top_k_filter(probs, k=top_k)
    
    # 3. Top-p: 按概率阈值采样
    # 随机选择累积概率达到阈值的 token
    top_p_probs = nucleus_sampling(probs, p=top_p)
    
    # 4. 最终采样: numpy.random.choice 是随机的
    selected_token = random_choice(top_p_probs)
    
    return selected_token
```

## 5. 解决方案

### 5.1 参数调优方案

```python
# 方案1: Temperature 调优
def generate_stable_temperature(prompt, model, temp=0.1):
    """
    低 Temperature 提高一致性
    - temp = 0.0: greedy search，完全确定
    - temp = 0.1~0.3: 低随机性，保持一定多样性
    - temp = 0.7~1.0: 高随机性，创意写作
    """
    response = model.generate(
        prompt,
        temperature=temp,
        do_sample=False  # 关闭采样，强制 greedy
    )
    return response

# 方案2: Top-k 和 Top-p 调优
def generate_stable_nucleus(prompt, model):
    """
    Nucleus 采样 + 保守参数
    """
    response = model.generate(
        prompt,
        temperature=0.3,
        top_p=0.9,      # 降低累积概率阈值
        top_k=20,       # 减少候选数量
        do_sample=True
    )
    return response
```

def generate_structured_output(prompt: str, model) -> CodeOutput:
    """
    使用结构化输出保证格式一致
    """
    # 调用支持结构化输出的模型 API
    response = model.generate(
        prompt,
        response_format=CodeOutput,  # 模型必须按 schema 输出
    )
    return response

### 5.5 结果缓存和复用

```python
# 方案6: Semantic Cache

import hashlib
from sentence_transformers import SentenceTransformer

class SemanticCache:
    """
    语义缓存：对相似问题返回缓存结果
    """
    def __init__(self, similarity_threshold=0.95):
        self.cache = {}  # hash -> response
        self.embedder = SentenceTransformer('all-MiniLM-L6-v2')
        self.similarity_threshold = similarity_threshold
    
    def get_cache_key(self, prompt: str) -> str:
        """生成缓存键"""
        return hashlib.md5(prompt.encode()).hexdigest()
    
    def find_similar(self, prompt: str):
        """查找相似问题"""
        prompt_embedding = self.embedder.encode(prompt)
        for cached_prompt, response in self.cache.items():
            cached_embedding = self.embedder.encode(cached_prompt)
            similarity = cosine_similarity(prompt_embedding, cached_embedding)
            if similarity >= self.similarity_threshold:
                return response
        return None
    
    def generate(self, prompt: str, model):
        """带缓存的生成"""
        # 1. 检查缓存
        cached = self.find_similar(prompt)
        if cached:
            return cached
        
        # 2. 生成新结果
        response = model.generate(prompt)
        
        # 3. 存入缓存
        self.cache[prompt] = response
        return response
```

### 7.2 多层一致性保障

```python
class StableLLMGenerator:
    """
    多层一致性保障生成器
    """
    def __init__(self, model):
        self.model = model
        self.cache = SemanticCache()
        self.system_prompt = STABLE_SYSTEM_PROMPT
    
    def generate(self, prompt: str) -> str:
        # 1. 先检查缓存
        cached = self.cache.find_similar(prompt)
        if cached:
            return cached
        
        # 2. 使用稳定参数生成
        response = self.model.generate(
            prompt,
            system_prompt=self.system_prompt,
            temperature=0.1,
            top_p=0.9,
            response_format=CodeOutput  # 结构化约束
        )
        
        # 3. 后处理验证
        response = self.validate_and_format(response)
        
        # 4. 存入缓存
        self.cache.cache[prompt] = response
        
        return response
    
    def validate_and_format(self, response):
        """验证输出格式并规范化"""
        # 确保输出符合预期格式
        return format_consistent(response)
```

## 9. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Temperature 过低 | 过于保守，创造性丧失 | 根据场景调整 |

| 提示词冲突 | 结构化要求相互矛盾 | 简化提示词 |

## 10. 验证方式

### 10.1 一致性测试脚本

```python
import nltk
from collections import Counter

def calculate_consistency_score(responses: list[str]) -> float:
    """
    计算输出一致性得分
    """
    # 1. 文本相似度
    similarities = []
    for i in range(len(responses)):
        for j in range(i + 1, len(responses)):
            sim = nltk.translate.bleu_score.sentence_bleu(
                responses[i], responses[j]
            )
            similarities.append(sim)
    
    avg_similarity = sum(similarities) / len(similarities)
    
    # 2. 结构一致性
    structures = [extract_structure(r) for r in responses]
    structure_consistency = len(set(structures)) / len(structures)
    
    # 3. 关键词重合度
    all_keywords = [extract_keywords(r) for r in responses]
    keyword_overlap = calculate_overlap(all_keywords)
    
    # 综合得分
    score = (avg_similarity * 0.4 + 
             (1 - structure_consistency) * 0.3 + 
             keyword_overlap * 0.3)
    
    return score

# 验证结果
responses = [generate("写一个排序算法") for _ in range(10)]
score = calculate_consistency_score(responses)
print(f"一致性得分: {score:.2f}")  # 0.8+ 表示一致性良好
```

## 11. 总结

1. **核心方法**：Temperature + Top-p 调优、提示词工程、结构化输出、模型微调、语义缓存
2. **推荐方案**：Temperature=0.1 + top_p=0.9 + 结构化输出 + 语义缓存
3. **实施顺序**：先参数调优 → 再提示词约束 → 结构化输出 → 缓存优化
4. **验证指标**：BLEU/ROUGE 相似度、结构一致性、关键词重合度
5. **核心原则**：根据场景平衡一致性和创造性，生产环境优先一致性
