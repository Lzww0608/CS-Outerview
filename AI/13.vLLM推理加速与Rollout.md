# 13. vLLM 推理加速与 Rollout

vLLM 是面向大语言模型推理服务的高吞吐引擎。它在 RLHF/GRPO 训练中常用来加速 rollout，也就是为 prompt 批量生成 responses。

## 1. vLLM 解决什么问题

LLM 推理分两阶段：

```text
prefill: 处理 prompt，生成历史 KV cache
decode : 每步生成一个 token，复用历史 KV cache
```

长上下文和多并发下，KV cache 是主要显存瓶颈。如果传统实现为每条请求预留连续最大长度 KV 内存，会产生严重碎片和浪费。

vLLM 的核心思想是把 KV cache 按 block 管理，类似操作系统分页，让不同请求的 KV 存在非连续 block 中，从而提升显存利用率和批处理吞吐。

## 2. PagedAttention

PagedAttention 把每条序列的 KV cache 拆成固定大小 block，用 block table 记录逻辑 token 到物理 block 的映射。

```text
sequence logical blocks
  -> block table
  -> physical KV blocks in GPU memory
```

优势：

1. 降低 KV cache 内部碎片。
2. 支持更灵活的动态 batch。
3. 便于实现 prefix sharing、parallel sampling、beam search 等共享 KV 场景。
4. 同样显存下能容纳更多并发请求。

注意：vLLM 版本演进很快，具体 attention kernel、调度器和 cache 管理实现会变化；面试回答抓住 block KV cache 和动态调度即可，不要把某个版本源码细节当成永久结论。

## 3. Continuous Batching

普通 batch 往往等一批请求全部结束后再处理下一批。LLM 生成长度不一，短请求会等长请求，GPU 利用率低。

Continuous batching 会在 decode 过程中动态加入新请求、移除完成请求：

```text
step t: batch = A, B, C
B 完成
新请求 D 加入
step t+1: batch = A, C, D
```

这能提高在线服务和 rollout 的吞吐，代价是调度和 KV 管理更复杂。

## 4. vLLM 在 RLHF/RLVR 中的作用

PPO、GRPO、DAPO 都需要大量生成样本：

```text
prompt -> policy rollout -> response -> reward -> policy update
```

如果 rollout 用普通 Hugging Face generate，采样会成为瓶颈。vLLM 通过 PagedAttention、continuous batching、prefix cache、CUDA graph、量化等能力提高生成吞吐。

训练系统需要额外处理：

1. **权重同步**：actor 更新后，rollout engine 要拿到新权重。
2. **colocate 或分离**：训练和推理可以在同 GPU 或不同 GPU 上跑。
3. **采样参数**：temperature、top-p、max tokens 直接影响探索和训练信号。
4. **显存竞争**：rollout 的 KV cache 和训练的参数/激活显存要协调。
5. **异步流水线**：生成、奖励、训练尽量重叠，减少 GPU 空转。

## 5. vLLM、SGLang、TensorRT-LLM 怎么选

1. **vLLM**：生态广、接入方便，适合在线服务和 RL rollout。
2. **SGLang**：强调结构化生成、agentic workflow、server-based rollout 等场景。
3. **TensorRT-LLM**：偏 NVIDIA 生产部署优化，追求极致推理性能，但构建和模型适配更重。

真实项目一般根据模型支持、吞吐、延迟、部署复杂度、量化支持和训练框架集成来选。

## 6. 易错点

1. vLLM 是推理引擎，不负责训练反向传播。
2. PagedAttention 主要优化 KV cache 显存管理，不是改变 Transformer 数学定义。
3. Rollout 加速不等于 RL 总体一定快，reward、训练更新、权重同步也可能成为瓶颈。
4. temperature 太低会降低探索，太高会增加无效样本，要结合 reward 分布调。
5. 版本差异很大，面试回答要避免死背内部函数名。

## 7. 面试回答模板

vLLM 主要用于高吞吐 LLM 推理。它的核心思想是 PagedAttention，把 KV cache 拆成 block，用 block table 管理逻辑到物理的映射，减少连续内存预留带来的碎片；再配合 continuous batching，让不同长度请求可以动态进入和退出 batch，提高 GPU 利用率。在 GRPO/PPO 这类 RL 训练里，vLLM 常用于 rollout 生成，训练框架如 TRL 或 verl 负责算法和反向传播。真正的系统瓶颈还包括 reward 计算、权重同步、训练更新和显存调度。
