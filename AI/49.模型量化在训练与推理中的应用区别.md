# 49. 模型量化在训练与推理中的应用区别

## 1. 问题背景

模型量化通过将高精度浮点数（FP32）转换为低精度整数（INT8/INT4）或低精度浮点数（FP16/BF16），在保持模型能力的同时降低显存占用和加速推理。然而，量化在训练阶段和推理阶段的应用方式、目标和挑战存在显著差异。

**假设条件**：本文档基于 Transformer 架构（大语言模型、视觉 Transformer），假设使用 PyTorch + CUDA 生态，训练框架涉及 DeepSpeed/Megatron，推理引擎涉及 TensorRT/vLLM，量化方案涵盖 QAT（训练中量化）、PTQ（训练后量化）、动态量化、静态量化等。

## 2. 问题现象

### 训练阶段问题

1. **显存压力**：大模型训练需要存储 FP32 权重、FP32 梯度、FP32 优化器状态，显存占用是参数量的 12~16 倍。
2. **计算效率低**：FP32 矩阵乘法比 INT8 慢 2~4 倍。
3. **混合精度训练开销**：需要额外维护 FP32 master weights 和梯度 loss scaling。

### 推理阶段问题

1. **延迟过高**：FP32 推理无法满足实时性要求。
2. **部署成本高**：高精度模型需要高端 GPU，部署成本居高不下。
3. **量化精度损失**：直接量化（PTQ）可能导致模型精度显著下降。

## 3. 影响范围

| 影响维度 | 训练阶段 | 推理阶段 |
| --- | --- | --- |
| 显存占用 | 高（12~16x 参数） | 高（影响可部署模型大小） |
| 计算速度 | 中（受限于通信） | 高（直接决定延迟） |
| 模型精度 | 高（量化误差累积） | 高（精度损失可能不可接受） |
| 工程复杂度 | 中（框架支持成熟） | 高（需要大量调参） |
| 适用场景 | 大模型分布式训练 | 边缘部署、实时推理 |

## 4. 原因分析

### 4.1 训练量化的目标

训练阶段量化主要解决显存问题，允许使用 BF16/FP16 计算加速，同时保持 FP32 精度：

```python
# 混合精度训练（训练量化）
model = model.cuda().half()  # 使用 FP16

# 前向和反向使用 BF16/FP16
with torch.cuda.amp.autocast(dtype=torch.bfloat16):
    output = model(input)
    loss = criterion(output, target)
    
# 优化器状态仍使用 FP32
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-4)
# Adam 内部状态：一阶矩、二阶矩仍为 FP32

# Loss scaling 防止 BF16 下溢
scaler = torch.cuda.amp.GradScaler()
scaled_loss = scaler.scale(loss)
scaled_loss.backward()
scaler.step(optimizer)
scaler.update()
```

### 4.2 推理量化的目标

推理阶段量化主要解决延迟和吞吐量问题，追求极致效率：

```python
# 训练后量化（PTQ）
import torch.quantization

# 动态量化（权重 INT8，激活 FP32）
quantized_model = torch.quantization.quantize_dynamic(
    model, {torch.nn.Linear}, dtype=torch.qint8
)

# 静态量化（INT8）
model.qconfig = torch.quantization.get_default_qconfig('fbgemm')
torch.quantization.prepare(model, inplace=True)
torch.quantization.convert(model, inplace=True)
```

### 4.3 两者的核心区别

| 维度 | 训练量化 | 推理量化 |
| --- | --- | --- |
| 量化对象 | 主要是激活和梯度 | 主要是权重和激活 |
| 精度要求 | 较高（BPTT 需要精度） | 可接受一定损失 |
| 时机 | 训练过程中 | 训练后或训练中（QAT） |
| 校准数据 | 不需要 | 需要代表性数据集 |
| 反向传播 | 必须支持 | 不需要 |
| 优化器状态 | 需要高精度 | 不需要 |

### 4.4 量化误差的累积效应

```
训练阶段：
- 量化误差通过反向传播逐步修正
- 梯度累积天然平滑量化噪声
- 可学习参数会适应低精度表示

推理阶段：
- 量化误差一次性累积，无法修正
- 输入分布变化放大量化误差
- 极端值（outlier）对 INT8 量化影响大
```

## 5. 解决方案

### 5.1 训练量化：混合精度 + BF16

```python
# DeepSpeed 混合精度训练
ds_config = {
    "fp16": {
        "enabled": True,
        "loss_scale": 0,
        "loss_scale_window": 1000,
        "initial_scale_power": 16,
    },
    "bf16": {"enabled": True},  # 优先使用 BF16
}

model, optimizer, _, _ = deepspeed.initialize(
    model=model,
    optimizer=optimizer,
    config=ds_config,
)

# 训练循环
for batch in dataloader:
    loss = model(batch)
    model.backward(loss)
    model.step()
```

### 5.2 训练量化：QAT（量化感知训练）

```python
# PyTorch QAT
import torch.quantization

# Step 1: 在模型中插入 FakeQuant 节点
model.train()
model.qconfig = torch.quantization.get_default_qat_qconfig('fbgemm')
torch.quantization.prepare_qat(model, inplace=True)

# Step 2: 使用代表性数据进行校准训练
for epoch in range(num_epochs):
    for batch in calibration_data:
        output = model(batch)
        loss = criterion(output)
        loss.backward()

# Step 3: 冻结 BN 统计，转换模型
model.eval()
torch.quantization.convert(model, inplace=True)
```

### 5.3 推理量化：TensorRT INT8

```python
# tensorrt_int8.py
import tensorrt as trt

# Step 1: 生成校准数据集
calibration_data = load_calibration_data()

# Step 2: 创建 INT8 Builder

    with open('model.onnx', 'rb') as f:
        parser.parse(f.read())

# Step 5: 设置校准器
config.int8_calibrator = MyCalibrator(calibration_data)

# Step 6: 构建引擎

```

## 6. 可选方案对比

| 方案 | 量化精度 | 精度损失 | 实现难度 | 适用场景 |
| --- | --- | --- | --- | --- |
| BF16 混合精度 | 高 | 无 | 低 | 训练首选 |
| FP16 混合精度 | 中 | 极低 | 低 | 训练备选 |
| INT8 PTQ | 低 | 1~5% | 中 | 推理首选 |
| INT4 PTQ | 极低 | 5~15% | 高 | 极致压缩 |
| QAT | 中低 | 0.5~2% | 高 | 高精度推理 |
| FP8 (Hopper) | 高 | 无 | 低 | H100 训练/推理 |
| AWQ | 中 | 1~3% | 低 | LLM 推理 |

## 7. 推荐方案

**训练推荐：BF16 混合精度 + ZeRO-3**
- BF16 动态范围大于 FP16，精度损失更小
- ZeRO-3 进一步减少显存占用
- 几乎无需调参，框架支持成熟

**推理推荐：INT8 PTQ（TensorRT）或 AWQ（vLLM）**
- INT8 PTQ 实现简单，效果稳定
- AWQ 对 LLM 友好，精度损失小
- 根据部署环境选择 TensorRT 或 vLLM

## 9. 风险与注意事项

| 风险 | 缓解措施 |
| --- | --- |
| BF16 loss spike | 使用 GradScaler，监控 loss scale |
| INT8 精度崩溃 | 使用 QAT 或多校准数据 |
| INT4 严重退化 | 敏感层保持 INT8 或 FP16 |
| 校准数据偏差 | 使用多样化校准数据，覆盖分布 |
| 硬件不支持 | 检查 GPU 架构（A100+ 支持 INT8） |

## 10. 验证方式

```python
def validate_quantization(original_model, quantized_model, test_loader):
    """验证量化正确性"""
    # 精度对比
    orig_correct = 0
    quant_correct = 0
    
    with torch.no_grad():
        for x, y in test_loader:
            orig_out = original_model(x)
            quant_out = quantized_model(x)
            
            orig_correct += (orig_out.argmax(1) == y).sum().item()
            quant_correct += (quant_out.argmax(1) == y).sum().item()
    
    orig_acc = orig_correct / len(test_loader.dataset)
    quant_acc = quant_correct / len(test_loader.dataset)
    
    print(f"原始精度: {orig_acc:.4f}")
    print(f"量化精度: {quant_acc:.4f}")
    print(f"精度损失: {(orig_acc - quant_acc):.4f}")
    
    # 验证：精度损失 < 1%
    assert (orig_acc - quant_acc) < 0.01, "量化精度损失过大"
```

## 11. 总结

训练量化和推理量化虽然都使用量化技术，但目标、方法和挑战不同。训练量化主要解决显存问题，采用 BF16/FP16 混合精度；推理量化追求极致效率，采用 INT8/INT4 量化。

**核心要点**：
- 训练量化：BF16 为主，ZeRO-3 分片，配合 QAT 可进一步优化。
- 推理量化：INT8 PTQ 为首选，AWQ 对 LLM 友好。
- 量化误差在训练中可修正，在推理中累积。
- 量化后务必验证精度损失，确保可接受范围。
