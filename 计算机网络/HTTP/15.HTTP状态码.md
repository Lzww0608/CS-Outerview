# 15. HTTP 状态码

HTTP 状态码是服务端对请求处理结果的标准化表达。它位于响应报文的状态行中，例如：

```http
HTTP/1.1 404 Not Found
```

状态码不是业务错误码本身，而是 HTTP 层语义；真实业务系统通常会在响应体中再放业务错误码和错误信息。

## 状态码分类

| 范围 | 类型 | 含义 |
| --- | --- | --- |
| `1xx` | 信息响应 | 请求已接收，继续处理 |
| `2xx` | 成功 | 请求被成功接收、理解和处理 |
| `3xx` | 重定向 | 客户端需要进一步操作 |
| `4xx` | 客户端错误 | 请求本身有问题或客户端无权限 |
| `5xx` | 服务端错误 | 服务端处理请求时出错 |

## 常见状态码

### 2xx

1. `200 OK`：请求成功，最常见。
2. `201 Created`：资源创建成功，常用于 POST 创建资源。
3. `204 No Content`：成功但没有响应体，常用于删除或更新成功。

### 3xx

1. `301 Moved Permanently`：永久重定向，搜索引擎和客户端可缓存新地址。
2. `302 Found`：临时重定向。
3. `304 Not Modified`：资源未修改，客户端可使用本地缓存。

### 4xx

1. `400 Bad Request`：请求格式错误，例如 JSON 不合法、参数类型错误。
2. `401 Unauthorized`：未认证或认证失效，需要登录、Token、Basic Auth 等认证信息。
3. `403 Forbidden`：已认证但无权限访问。
4. `404 Not Found`：资源不存在，可能是 URL 不存在，也可能是业务资源不存在。
5. `405 Method Not Allowed`：HTTP 方法不允许，例如只支持 GET 却发送 POST。
6. `409 Conflict`：资源状态冲突，例如版本号不一致、重复创建。
7. `429 Too Many Requests`：请求过多，常用于限流。

### 5xx

1. `500 Internal Server Error`：服务端内部错误。
2. `502 Bad Gateway`：网关或代理从上游拿到非法响应。
3. `503 Service Unavailable`：服务暂不可用，例如过载、维护、限流降级。
4. `504 Gateway Timeout`：网关等待上游超时。

## 401、403、404 的区别

1. `401` 重点是“你还没有通过认证”。
2. `403` 重点是“你已经被识别，但没有权限”。
3. `404` 重点是“资源不存在”。部分系统为了安全，会把无权限资源伪装成 `404`，避免暴露资源存在性。

## 易错点

1. 不要所有业务失败都返回 `200`，否则网关、监控、重试、缓存都很难正确工作。
2. 认证失败优先考虑 `401`，权限不足用 `403`，参数错误用 `400`。
3. 服务端异常不要滥用 `400`；客户端无法修复的问题应返回 `5xx`。
4. `404` 不一定代表服务器挂了，只代表目标资源或路由不存在。
5. `503` 通常可以配合 `Retry-After` 告诉客户端稍后重试。
6. `304` 响应没有完整响应体，依赖 `ETag` 或 `Last-Modified` 等缓存机制。

## 真实场景

1. 网关限流时返回 `429` 或 `503`，客户端根据错误类型决定是否退避重试。
2. 登录态过期返回 `401`，前端跳转登录或刷新 Token。
3. 已登录但无权限返回 `403`，前端展示权限不足。
4. 服务发布或上游超时时，Nginx/API Gateway 可能返回 `502/504`，排查方向是网关到上游链路。
5. RESTful API 创建资源成功常用 `201`，删除成功且无返回内容常用 `204`。

## 面试回答模板

HTTP 状态码按类别分为 `1xx` 信息、`2xx` 成功、`3xx` 重定向、`4xx` 客户端错误和 `5xx` 服务端错误。常见的 `404` 表示资源不存在，`403` 表示已认证但无权限，`401` 表示未认证，`500` 是服务端内部错误，`502/504` 多见于网关访问上游失败或超时。工程上状态码要和 HTTP 语义一致，业务错误码可以放在响应体里，否则监控、缓存、网关限流和客户端重试都会失真。
