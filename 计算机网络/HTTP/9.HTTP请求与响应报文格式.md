# 9. HTTP请求与响应报文格式

## 1. HTTP 报文整体结构

HTTP/1.x 报文是文本协议，分为：

```text
起始行
Header1: value
Header2: value

Body
```

起始行和头部之间用 CRLF（`\r\n`）分隔，头部和正文之间用一个空行分隔。请求报文和响应报文最大的区别在于起始行不同：

1. 请求报文起始行是**请求行**。
2. 响应报文起始行是**状态行**。

## 2. HTTP 请求报文格式

顺序如下：

```text
请求行
请求头
空行
请求体
```

示例：

```http
POST /api/users?id=100 HTTP/1.1
Host: example.com
User-Agent: curl/8.0
Accept: application/json
Content-Type: application/json
Content-Length: 18

{"name":"alice"}
```

### 请求行

请求行格式：

```text
Method Request-Target HTTP-Version
```

1. **Method**：请求方法，例如 `GET`、`POST`、`PUT`、`DELETE`、`HEAD`、`OPTIONS`。
2. **Request-Target**：请求目标，常见是 path + query，例如 `/api/users?id=100`。
3. **HTTP-Version**：协议版本，例如 `HTTP/1.1`。

### 请求头

请求头是键值对，用于描述客户端能力、认证信息、请求体格式、缓存策略等。

常见请求头：

1. `Host`：目标主机，HTTP/1.1 必须携带。
2. `User-Agent`：客户端信息。
3. `Accept`：客户端可接受的响应媒体类型。
4. `Accept-Encoding`：客户端支持的压缩方式，例如 `gzip`、`br`。
5. `Content-Type`：请求体格式，例如 `application/json`。
6. `Content-Length`：请求体字节数。
7. `Authorization`：认证凭证。
8. `Cookie`：客户端携带的会话状态。

### 请求体

请求体不是所有方法都有。常见于 `POST`、`PUT`、`PATCH`，可以是 JSON、表单、文件等。

## 3. HTTP 响应报文格式

顺序如下：

```text
状态行
响应头
空行
响应体
```

示例：

```http
HTTP/1.1 200 OK
Date: Sat, 25 Apr 2026 12:00:00 GMT
Server: nginx
Content-Type: application/json
Content-Length: 27
Cache-Control: no-cache

{"id":100,"name":"alice"}
```

### 状态行

状态行格式：

```text
HTTP-Version Status-Code Reason-Phrase
```

1. **HTTP-Version**：协议版本。
2. **Status-Code**：状态码，例如 `200`、`301`、`400`、`404`、`500`。
3. **Reason-Phrase**：原因短语，例如 `OK`、`Not Found`。

### 响应头

常见响应头：

1. `Date`：响应生成时间。
2. `Server`：服务端软件信息。
3. `Content-Type`：响应体格式。
4. `Content-Length`：响应体字节数。
5. `Set-Cookie`：服务端下发 Cookie。
6. `Cache-Control`：缓存策略。
7. `ETag`：资源版本标识。
8. `Location`：重定向目标地址。

### 响应体

响应体承载真正返回的数据，例如 HTML、JSON、图片、文件流。`204 No Content`、`304 Not Modified` 等响应通常没有响应体。

## 4. Body 长度如何确定

HTTP/1.1 中接收方要知道 body 到哪里结束，常见方式：

1. `Content-Length`：明确指定 body 字节数。
2. `Transfer-Encoding: chunked`：分块传输，每块前面带长度，最后用 0 长度块结束。
3. 连接关闭：HTTP/1.0 常见方式，但不利于连接复用。

`Content-Length` 和 `Transfer-Encoding: chunked` 不应同时混用，否则容易引发请求走私等安全问题。

## 5. HTTP/2 和 HTTP/3 的区别

HTTP/2 和 HTTP/3 不再使用 HTTP/1.x 这种纯文本起始行 + 头部 + 空行 + body 的线性报文格式：

1. **HTTP/2**：把语义拆成二进制帧，例如 HEADERS 帧和 DATA 帧，并支持多路复用。
2. **HTTP/3**：语义类似 HTTP/2，但运行在 QUIC 之上，使用 QUIC stream 传输。

面试问“HTTP 报文格式”时，通常默认指 HTTP/1.1。

## 6. 易错点

1. 请求报文第一行是请求行，不是状态行。
2. 响应报文第一行是状态行，不是请求行。
3. 头部和 body 之间必须有空行。
4. `GET` 语义上通常不带 body，但协议并非完全禁止；工程上不要依赖 GET body。
5. `Content-Type` 描述 body 格式，`Accept` 描述客户端希望接收的格式。

## 7. 面试回答模板

HTTP/1.1 请求报文按顺序是请求行、请求头、空行、请求体。请求行包含方法、请求目标和协议版本，例如 `GET /index.html HTTP/1.1`。响应报文按顺序是状态行、响应头、空行、响应体。状态行包含协议版本、状态码和原因短语，例如 `HTTP/1.1 200 OK`。头部是键值对，body 是否存在由方法、状态码和 `Content-Length` 或 `Transfer-Encoding` 等字段决定。
