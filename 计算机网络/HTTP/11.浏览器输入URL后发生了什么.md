# 11. 浏览器输入 URL 后发生了什么

浏览器输入 URL 后，完整链路可以按“解析 URL -> 找到 IP -> 建立连接 -> 发送请求 -> 服务端处理 -> 浏览器渲染”来回答。面试时不要只说 HTTP 请求，要覆盖 DNS、TCP/TLS、缓存、服务端和渲染。

## 完整流程

1. **URL 解析**：浏览器解析 scheme、host、port、path、query、fragment；补全默认协议和端口，例如 HTTPS 默认 443。
2. **检查缓存和策略**：浏览器可能先看 HSTS、缓存、Service Worker、预连接、代理配置。
3. **DNS 解析**：查浏览器缓存、系统缓存、hosts、递归 DNS，最终拿到目标 IP。
4. **建立连接**：
   - HTTP/1.1、HTTP/2 通常基于 TCP，先三次握手。
   - HTTPS 还要做 TLS 握手，验证证书并协商会话密钥。
   - HTTP/3 基于 QUIC/UDP，传输握手和 TLS 1.3 结合。
5. **发送请求**：浏览器构造请求行、请求头、Cookie、请求体；HTTP/2/3 会以 frame 形式传输。
6. **经过网络链路**：数据经过本机协议栈、网卡、交换机、路由器、NAT、负载均衡、网关等。
7. **服务端处理**：反向代理或网关接收请求，转发给应用服务，应用访问缓存、数据库、对象存储或下游 RPC。
8. **返回响应**：服务端返回状态码、响应头、响应体；可能带缓存控制、压缩、分块传输等。
9. **浏览器处理响应**：根据 Content-Type、状态码、缓存策略处理资源。
10. **页面渲染**：HTML 解析生成 DOM，CSS 生成 CSSOM，合成 Render Tree，布局、绘制、合成；遇到 JS、CSS、图片等资源继续发起子请求。

## HTTPS 链路重点

HTTPS 不是简单“先 HTTP 后加密”，而是：

```text
DNS -> TCP 三次握手 -> TLS 握手 -> 加密 HTTP 请求/响应
```

TLS 握手会完成：

1. 协商协议版本和加密套件。
2. 校验证书链、域名和有效期。
3. 生成对称会话密钥。
4. 后续 HTTP 数据用对称加密传输。

## 缓存相关

浏览器可能在真正发网络请求前就命中缓存：

1. **强缓存**：`Cache-Control: max-age`、`Expires` 未过期，直接使用本地缓存。
2. **协商缓存**：带 `If-None-Match` / `If-Modified-Since` 请求服务端，命中则返回 `304`。
3. **Service Worker**：可以拦截请求并返回缓存、离线资源或自定义响应。

## 易错点

1. 输入 URL 后不一定马上发网络请求，缓存、HSTS、Service Worker 都可能改变流程。
2. DNS 返回的可能是 CDN、负载均衡或就近机房 IP，不一定是源站。
3. HTTP/2 多路复用复用连接，不代表 TCP 层没有队头阻塞。
4. Keep-Alive 场景下，后续请求可能复用已有 TCP/TLS 连接，不重复握手。
5. 页面“首屏慢”可能卡在 DNS、建连、TLS、服务端、下载、JS 执行、布局绘制任一阶段。

## 面试回答模板

浏览器输入 URL 后，先解析 URL，检查缓存、HSTS、代理和 Service Worker；然后做 DNS 解析拿到 IP；如果是 HTTP/1.1 或 HTTP/2，先建立 TCP 连接，HTTPS 还要做 TLS 握手和证书校验；之后发送 HTTP 请求，服务端经网关、应用、缓存、数据库等处理后返回响应；浏览器根据状态码和缓存策略处理响应，再解析 HTML/CSS/JS，构建 DOM/CSSOM、布局、绘制并继续加载子资源。
