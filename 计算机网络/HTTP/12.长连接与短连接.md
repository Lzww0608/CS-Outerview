# 12. 长连接与短连接

长连接和短连接描述的是连接复用策略。短连接通常是一次请求响应后关闭连接；长连接会在一次建连后复用同一条连接发送多个请求。

## 短连接

短连接流程：

```text
TCP 握手 -> 请求 -> 响应 -> TCP 挥手
```

优点：

1. 实现简单，连接生命周期清晰。
2. 服务端长期维护的连接少。
3. 对低频、简单请求足够。

缺点：

1. 每个请求都要重复 TCP 握手，HTTPS 还要重复 TLS 握手或恢复。
2. 高并发下容易产生大量 `TIME_WAIT`、端口和 fd 压力。
3. 延迟高，吞吐差。

## 长连接

长连接流程：

```text
TCP/TLS 握手 -> 请求1/响应1 -> 请求2/响应2 -> ... -> 空闲超时或主动关闭
```

优点：

1. 复用 TCP/TLS 连接，减少握手 RTT 和 CPU 成本。
2. 降低端口、连接建立和关闭开销。
3. 适合 HTTP Keep-Alive、HTTP/2、多次 RPC、数据库连接池、WebSocket 等。

缺点：

1. 服务端需要维护更多 fd、内存、连接状态和心跳。
2. 空闲连接要有超时回收策略。
3. 大量长连接需要 epoll/kqueue/io_uring 等事件驱动模型，而不是一连接一线程。

## HTTP 中的长连接

1. HTTP/1.0 默认短连接，可通过 `Connection: keep-alive` 使用长连接。
2. HTTP/1.1 默认长连接，除非 `Connection: close`。
3. HTTP/2 在一个连接上支持多个 stream 多路复用。
4. HTTP/3 基于 QUIC，在 UDP 上实现连接、加密和 stream。

## Connection 选项的作用

`Connection` 是逐跳首部（hop-by-hop header），只对当前这一段连接有效，不会端到端透传到最终服务。它常见作用有两个：

1. 控制连接是否复用：`Connection: keep-alive` 或 `Connection: close`。
2. 声明哪些逐跳首部只对当前连接有效，代理转发时应移除这些首部。

示例：

```http
Connection: keep-alive
```

表示希望当前 TCP 连接在本次响应后继续复用。

```http
Connection: close
```

表示本次响应后关闭连接。HTTP/1.1 默认长连接，因此服务端想关闭时通常会显式返回 `Connection: close`。

逐跳首部示例：

```http
Connection: Upgrade
Upgrade: websocket
```

表示当前 HTTP 连接要升级为 WebSocket。代理如果不参与升级，不能盲目把逐跳语义当成端到端语义转发。

## 易错点

1. 长连接不等于连接永远不关，要设置 idle timeout、keepalive、最大请求数等。
2. TCP Keepalive 是内核探活机制，HTTP Keep-Alive 是应用层连接复用策略，两者不是一回事。
3. 长连接减少建连成本，但会增加服务端连接状态维护成本。
4. 短连接高并发时，主动关闭方可能出现大量 `TIME_WAIT`。
5. `Connection` 是逐跳首部，经过代理时要按规范处理，不能当成端到端业务首部。

## 面试回答模板

短连接是每次请求都新建连接，请求响应后关闭，简单但握手和关闭开销大；长连接是一次建连后复用连接，能减少 TCP/TLS 握手和端口消耗，适合多次请求、RPC、数据库连接池和 WebSocket。HTTP 里的 `Connection` 用来表达当前这一跳连接的控制语义，例如 `keep-alive`、`close`、`Upgrade`，它是逐跳首部，不是端到端首部。长连接要关注 fd、内存、心跳、空闲超时和事件驱动模型，短连接要关注 `TIME_WAIT` 和端口耗尽。
