# SSE 与 FTP 流式传输对比

## 1. 问题背景

SSE（Server-Sent Events）和 FTP 都是"流式传输"相关技术，但它们是完全不同的协议，适用于不同场景。两者都叫流式传输，有什么区别？

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  两者对比：                                                │
│                                                             │
│  SSE (Server-Sent Events)                                  │
│  • 基于 HTTP 协议                                          │
│  • 服务端 → 客户端 单向推送                               │
│  • 用于实时数据更新                                       │
│                                                             │
│  FTP (File Transfer Protocol)                              │
│  • 独立的应用层协议                                        │
│  • 双向文件传输                                           │
│  • 用于文件下载上传                                       │
│                                                             │
│  共同点：数据以流的形式传输                                │
│  本质区别：协议、目的、方向完全不同                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 疑问 | 描述 |
|------|------|
| 都是流式传输？ | 是的，但"流"的内容和用途不同 |
| 都在 TCP 上运行？ | SSE 基于 HTTP/TCP，FTP 用自己的控制和数据通道 |
| 实时性一样吗？ | SSE 是实时推送，FTP 是批量传输 |
| 断点续传？ | FTP 支持，SSE 不支持 |

---

## 3. 影响范围

- 实时 Web 应用（SSE）
- 文件传输系统（FTP/SFTP/FTPS）
- 混合场景：文件上传进度推送

## 4. 原因分析

### 4.1 SSE 详解

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  SSE 工作原理：                                            │
│                                                             │
│  HTTP/1.1 或 HTTP/2 连接                                  │
│       │                                                    │
│       ▼                                                    │
│  服务端 ──event: message──► 客户端                        │
│       │                                                    │
│       ▼                                                    │
│  Content-Type: text/event-stream                         │
│                                                             │
│  特点：                                                   │
│  • 单向：服务端 → 客户端                                  │
│  • 基于 HTTP，无需特殊端口                                │
│  • 自动重连                                               │
│  • 文本协议（UTF-8）                                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

```bash
# SSE 服务端示例（Node.js）
const http = require('http');

http.createServer((req, res) => {
    res.writeHead(200, {
        'Content-Type': 'text/event-stream',
        'Cache-Control': 'no-cache',
        'Connection': 'keep-alive'
    });
    
    // 每秒发送数据
    setInterval(() => {
        res.write(`data: ${new Date().toISOString()}\n\n`);
    }, 1000);
}).listen(3000);
```

### 4.2 FTP 详解

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  FTP 工作原理：                                            │
│                                                             │
│  控制连接：21 端口（命令通道）                             │
│       │                                                    │
│       ▼                                                    │
│  客户端 ◄────► 服务端                                     │
│       │                                                    │
│  数据连接：动态端口（数据通道）                            │
│       │                                                    │
│       ▼                                                    │
│  主动模式(PORT) / 被动模式(PASV)                         │
│                                                             │
│  特点：                                                   │
│  • 双通道：控制 + 数据                                    │
│  • 支持断点续传                                           │
│  • 二进制/文本模式                                       │
│  • 独立协议（不是 HTTP）                                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 核心区别对比

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  SSE vs FTP 核心区别：                                     │
│                                                             │
│  ┌────────────┬─────────────────────────────────────────┐ │
│  │ 维度        │ SSE               │ FTP                  │ │
│  ├────────────┼─────────────────────────────────────────┤ │
│  │ 协议        │ HTTP              │ FTP (独立)          │ │
│  │ 方向        │ 单向(服务端→客户端)│ 双向                 │ │
│  │ 用途        │ 实时数据推送       │ 文件传输            │ │
│  │ 端口        │ 80/443            │ 21 + 动态端口        │ │
│  │ 断点续传    │ 不支持             │ 支持                │ │
│  │ 数据格式    │ 文本事件流         │ 原始字节流          │ │
│  │ 防火墙      │ 友好              │ 复杂(双通道)        │ │
│  │ 重连        │ 自动               │ 需手动              │ │
│  └────────────┴─────────────────────────────────────────┘ │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.4 为什么都有"流式"

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  "流式"的不同含义：                                        │
│                                                             │
│  SSE 的流：                                               │
│  • HTTP 长连接，持续推送文本事件                          │
│  • 数据是连续的、小块的消息                                │
│  • 如：股票价格、实时日志、通知                          │
│                                                             │
│  FTP 的流：                                               │
│  • TCP 字节流，批量传输文件                               │
│  • 数据是连续的、完整的文件                                │
│  • 如：下载安装包、上传备份                               │
│                                                             │
│  共同点：数据不需要完整即可开始传输                        │
│  不同点：SSE 是"消息流"，FTP 是"字节流"                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

```html
        };
    </script>

</html>
```

### 5.3 SFTP vs FTPS（安全版本）

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  FTP 安全变体：                                            │
│                                                             │
│  FTPS (FTP over TLS/SSL)                                  │
│  • 在标准 FTP 基础上加密                                  │
│  • 使用 990(控制) + 989(数据) 端口                       │
│  • 与 HTTPS 相同的 TLS 加密                                │
│                                                             │
│  SFTP (SSH File Transfer Protocol)                         │
│  • 基于 SSH 协议                                           │
│  • 使用 SSH 的 22 端口                                    │
│  • 完整的文件传输功能 + SSH 安全特性                      │
│  • 与 FTP 协议完全不同                                    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 6. 可选方案对比

| 方案 | 适用场景 | 优点 | 缺点 |
|------|----------|------|------|
| SSE | 实时推送、监控面板 | 简单、HTTP 兼容 | 单向、无断点续传 |
| WebSocket | 双向实时通信 | 全双工、低延迟 | 复杂度高、需特殊处理 |
| FTP | 大文件传输 | 成熟、断点续传 | 防火墙问题、慢 |
| SFTP | 安全文件传输 | 加密、简单 | 速度受 SSH 影响 |
| HTTP 下载 | 普通文件下载 | 简单、CDN 友好 | 无断点续传标准 |

## 8. 实施步骤

### 8.1 SSE 实施

```python
# Python Flask SSE 实现
from flask import Flask, Response, stream_with_context
import time

app = Flask(__name__)

@app.route('/events')
def sse():
    @stream_with_context
    def generate():
        while True:
            yield f"data: {time.time()}\n\n"
            time.sleep(1)
    
    return Response(generate(), 
                   mimetype='text/event-stream',
                   headers={'Cache-Control': 'no-cache'})

# 测试
# curl -N http://localhost:5000/events
```

### 8.2 FTP/SFTP 实施

```python
# Python FTP 实现
from ftplib import FTP

def upload_file(ftp_server, file_path):
    ftp = FTP(ftp_server)
    ftp.login('username', 'password')
    
    with open(file_path, 'rb') as f:
        ftp.storbinary(f'STOR {file_path}', f)
    
    ftp.quit()

# Python SFTP 实现
import paramiko

def upload_sftp(sftp_server, file_path):
    ssh = paramiko.SSHClient()
    ssh.connect(sftp_server, username='user', password='pass')
    
    sftp = ssh.open_sftp()
    sftp.put(file_path, '/remote/' + file_path)
    
    sftp.close()
    ssh.close()
```

## 9. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| FTP 防火墙 | 数据连接失败 | 使用被动模式或 NAT 穿越 |
| SSE 断开 | 消息丢失 | 客户端重连 + 消息确认 |
| FTP 传输中断 | 文件不完整 | 断点续传 |
| SFTP 端口 | SSH 端口被封 | 走标准 443 或 VPN |

## 11. 总结

1. **SSE vs FTP**：虽然都涉及流式传输，但 SSE 是 HTTP 应用层协议（实时消息），FTP 是独立文件传输协议（批量文件）
2. **核心区别**：SSE 单向实时推送，FTP 双向批量传输
3. **适用场景**：SSE 用于实时监控/推送，FTP/SFTP 用于文件传输
4. **选择原则**：实时消息选 SSE，大文件传输选 SFTP/FTP
5. **本质理解**：SSE 是"消息流"，FTP 是"字节流"，"流式"只是传输方式相同，用途完全不同
