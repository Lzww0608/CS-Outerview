# HTTPS 握手过程与证书链验证

## 1. 问题背景

HTTPS 是 HTTP over TLS/SSL，通过加密保障数据传输安全。理解握手过程和证书验证机制是网络安全的基础。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  HTTPS 核心目标：                                          │
│                                                             │
│  1. 身份验证：确认服务器身份                              │
│  2. 密钥交换：协商对称加密密钥                            │
│  3. 数据加密：加密后续通信                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 |
|------|------|
| 证书无效 | "您的连接不是私密连接" |
| 证书过期 | 浏览器报警告 |
| 自签名证书 | 浏览器不信任 |
| 中间人攻击 | 证书验证失败 |

---

## 3. 影响范围

- Web 安全浏览
- API 通信安全
- 证书管理运维

### 4.2 证书链验证机制

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  证书链结构：                                              │
│                                                             │
│  根证书（Root CA）                                        │
│      │ 自签名，浏览器内置                                  │
│      ▼                                                     │
│  中间证书（Intermediate CA）                              │
│      │ 由根 CA 签发                                       │
│      ▼                                                     │
│  终端证书（Server Certificate）                            │
│      │ 由中间 CA 签发                                     │
│      ▼                                                     │
│  服务器域名证书                                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 证书验证流程

```python
def verify_certificate(cert_chain, domain):
    """
    证书链验证步骤
    """
    # 1. 完整性检查
    for i in range(len(cert_chain) - 1):
        current_cert = cert_chain[i]
        next_cert = cert_chain[i + 1]
        
        # 验证签名
        if not verify_signature(current_cert, next_cert):
            raise CertificateError("签名验证失败")
    
    # 2. 有效期检查
    for cert in cert_chain:
        if not is_valid_time(cert):
            raise CertificateError("证书已过期或未生效")
    
    # 3. 域名检查
    leaf_cert = cert_chain[0]
    if not match_domain(leaf_cert, domain):
        raise CertificateError("域名不匹配")
    
    # 4. 信任链检查
    root_cert = cert_chain[-1]
    if not is_trusted(root_cert):
        raise CertificateError("根证书不受信任")
    
    return True
```

### 4.4 如果 CA 不权威会怎样

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  CA 不权威的情况：                                         │
│                                                             │
│  场景 1：自签名证书                                       │
│  • 根证书不在浏览器信任列表                               │
│  • 浏览器显示"不受信任"                                  │
│  • 用户需手动信任才能继续                                 │
│                                                             │
│  场景 2：被吊销的证书                                     │
│  • CA 维护 CRL (Certificate Revocation List)              │
│  • 或提供 OCSP (Online Certificate Status Protocol)       │
│  • 浏览器检查发现已吊销，拒绝连接                         │
│                                                             │
│  场景 3：中间人攻击                                       │
│  • 攻击者伪造证书                                         │
│  • 但无法用真实 CA 的私钥签名                             │
│  • 浏览器验证签名失败，报警                               │
│                                                             │
│  场景 4：CA 被入侵                                        │
│  • 不法分子用 CA 私钥签发假证书                          │
│  • 震惊世界的 " DigiNotar 事件 "                        │
│  • 浏览器紧急移除该 CA 根证书                             │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 5. 解决方案

### 5.1 证书配置示例

```nginx
# Nginx HTTPS 配置示例

server {
    listen 443 ssl;
    server_name example.com;
    
    # 证书配置
    ssl_certificate     /path/to/server.crt;      # 终端证书
    ssl_certificate_key /path/to/server.key;      # 私钥
    
    # 证书链（中间证书拼接在终端证书后）
    # cat server.crt intermediate.crt > fullchain.crt
    
    # 加密套件配置
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256;
    ssl_prefer_server_ciphers on;
    
    # HSTS 配置
    add_header Strict-Transport-Security "max-age=31536000" always;
}
```

### 5.2 证书自动续期

```yaml
# Let's Encrypt + Certbot 自动续期

# 安装
apt install certbot python3-certbot-nginx

# 申请证书
certbot --nginx -d example.com -d www.example.com

# 自动续期配置
systemctl enable certbot.timer
systemctl start certbot.timer
```

## 7. 推荐方案

### 7.1 生产环境推荐

```yaml
# HTTPS 生产配置建议

https_config:
  # 证书选择
  certificate:
    provider: "lets_encrypt"  # 或商业 CA
    validation: "dns_challenge"
    
  # TLS 配置
  tls:
    min_version: "TLSv1.2"
    preferred: "TLSv1.3"
    cipher_suites:
      - "TLS_AES_256_GCM_SHA384"
      - "ECDHE-RSA-AES256-GCM-SHA384"
      - "ECDHE-RSA-AES128-GCM-SHA256"
    
  # 安全头
  headers:
    HSTS: "max-age=31536000; includeSubDomains"
    CSP: "default-src 'self'"
    X-Frame-Options: "DENY"
```

## 11. 总结

1. **握手核心**：ClientHello → ServerHello → 证书交换 → 密钥协商 → 加密通信
2. **证书链**：根证书（内置）+ 中间证书 + 终端证书，三层签名验证
3. **CA 不权威后果**：浏览器不信任，显示安全警告，无法建立 HTTPS 连接
4. **安全机制**：签名验证 + 有效期 + 域名匹配 + CRL/OCSP 吊销检查
5. **最佳实践**：使用 Let's Encrypt + 自动续期 + TLS 1.2/1.3 + HSTS
