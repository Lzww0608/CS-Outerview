# 10. HTTPS 加密

## 1. HTTPS 加密解决什么问题

HTTPS = HTTP + TLS。它主要解决三类问题：

1. **机密性**：传输内容被加密，中间人无法直接读取 HTTP 内容。
2. **完整性**：报文被篡改会被发现。
3. **身份认证**：客户端通过证书链验证服务端是否真的是目标域名。

HTTPS 不是单纯“用公钥加密全部数据”。真实流程是：非对称密码用于身份认证和密钥协商，对称密码用于加密大量应用数据。

## 2. TLS 加密的基本流程

以 TLS 1.3 为例：

1. 客户端发送 `ClientHello`，带支持的 TLS 版本、加密套件、随机数、key share、SNI 等。
2. 服务端返回 `ServerHello`，选择算法并返回自己的 key share。
3. 双方用 ECDHE 等密钥交换算法计算共享密钥。
4. 服务端发送证书和签名，客户端验证证书链、域名、有效期、吊销状态等。
5. 双方通过 HKDF 派生握手密钥和应用数据密钥。
6. 后续 HTTP 请求响应使用对称加密算法传输，例如 AES-GCM 或 ChaCha20-Poly1305。

## 3. 为什么不用 RSA 直接加密所有数据

1. 非对称加密性能远低于对称加密。
2. 大数据加密不适合直接用 RSA。
3. TLS 1.3 已移除静态 RSA 密钥交换，强制使用具备前向安全性的临时密钥交换。
4. ECDHE 可以保证即使服务器私钥将来泄露，历史会话数据也难以被解密。

## 4. 证书验证做了什么

客户端验证服务端证书时，通常关注：

1. 证书链是否能追溯到受信任 CA。
2. 证书域名是否匹配访问域名。
3. 证书是否过期。
4. 证书用途是否符合服务端认证。
5. 证书是否被吊销，工程上可能通过 OCSP、CRL 或 OCSP Stapling。

如果 DNS 被污染到错误 IP，但攻击者没有目标域名的合法证书，TLS 证书校验会失败。这也是 HTTPS 能缓解 DNS 劫持后伪站攻击的原因。

## 5. 对称加密、非对称加密、摘要和签名

HTTPS 里几类密码学工具分工不同：

1. **对称加密**：AES-GCM、ChaCha20-Poly1305，加密应用数据，性能高。
2. **非对称密钥交换**：ECDHE，用于协商共享密钥。
3. **数字签名**：服务端用证书私钥签名握手上下文，客户端用证书公钥验证身份。
4. **摘要/HKDF**：用于完整性校验、密钥派生和握手 transcript 绑定。

## 6. 易错点

1. HTTPS 不是只用非对称加密；应用数据主要用对称加密。
2. 证书用于身份认证，不是用来加密所有 HTTP 内容。
3. TLS 1.3 不再使用静态 RSA 密钥交换。
4. HTTPS 不能阻止 DNS 解析被篡改，但能阻止没有合法证书的伪站完成 TLS 验证。
5. 0-RTT 有重放风险，只适合幂等请求。

## 7. 面试回答模板

HTTPS 本质是 HTTP over TLS。握手阶段，客户端和服务端通过 ECDHE 协商共享密钥，并通过服务端证书完成身份认证；双方再用 HKDF 派生出会话密钥。真正传输 HTTP 数据时使用 AES-GCM 或 ChaCha20-Poly1305 这类对称加密，性能更好。证书链、域名、有效期和签名验证保证客户端连到的是目标服务端；同时 TLS 还能保证报文完整性，防止中间人篡改。
