# 2. DNS 解析过程与调度算法

DNS 的作用是把域名解析为 IP 地址。一次访问里，DNS 解析通常发生在 TCP 建连之前；解析结果会被浏览器、操作系统、递归 DNS、权威 DNS 等多级缓存共同影响。

## DNS 解析过程

以访问 `www.example.com` 为例：

1. **浏览器缓存**：浏览器先查自己的 DNS cache。
2. **系统缓存和 hosts**：浏览器交给操作系统，系统检查本地 DNS 缓存和 `hosts` 文件。
3. **递归解析器**：本机向配置的 Local DNS / 递归 DNS 发起查询，例如运营商 DNS、公司 DNS、公共 DNS。
4. **根域名服务器**：递归 DNS 如果没有缓存，会问根服务器 `.com` 的顶级域服务器地址。
5. **顶级域服务器**：递归 DNS 再问 `.com` 服务器，拿到 `example.com` 的权威 DNS 地址。
6. **权威 DNS**：递归 DNS 问权威 DNS，获得 `www.example.com` 的 A/AAAA/CNAME 等记录。
7. **返回并缓存**：递归 DNS 按 TTL 缓存结果，再返回给客户端；客户端也会按自己的策略缓存。

```text
Browser -> OS/hosts -> Recursive DNS -> Root -> TLD -> Authoritative DNS -> IP
```

## 递归查询和迭代查询

1. **递归查询**：客户端把问题交给递归 DNS，要求它给最终答案。客户端只和递归 DNS 交互。
2. **迭代查询**：递归 DNS 向根、顶级域、权威 DNS 逐级查询，每一级返回下一跳线索或最终记录。

面试里可以说：客户端到 Local DNS 常见是递归查询；Local DNS 到根/TLD/权威 DNS 常见是迭代查询。

## 常见 DNS 记录

| 记录 | 含义 | 场景 |
| --- | --- | --- |
| A | 域名到 IPv4 | `example.com -> 1.2.3.4` |
| AAAA | 域名到 IPv6 | IPv6 访问 |
| CNAME | 域名别名 | CDN、灰度域名、服务迁移 |
| NS | 域的权威 DNS | 域名托管 |
| MX | 邮件服务器 | 邮件投递 |
| TXT | 文本记录 | 域名验证、SPF、DKIM |

## DNS 算法有哪些

面试里问“DNS 算法”通常不是指 DNS 协议内部的加密算法，而是指 DNS 解析和调度策略：

1. **轮询 Round Robin**：一个域名返回多个 IP，按顺序或随机轮换。简单，但不感知后端健康和距离。
2. **加权轮询**：按机房容量、机器权重返回不同概率的 IP。
3. **就近访问 GeoDNS**：根据客户端递归 DNS 出口 IP 或 EDNS Client Subnet 判断地域，返回近机房 IP。
4. **延迟优先**：结合探测系统，返回 RTT 更低的节点。
5. **健康检查剔除**：权威 DNS 或 GSLB 检测后端健康，故障时不再返回对应 IP。
6. **一致性哈希/分片调度**：在部分内部 DNS 或服务发现系统中，把用户或业务 key 稳定映射到节点，减少切换抖动。
7. **CNAME 到 CDN/GSLB**：业务域名先 CNAME 到 CDN 或全局负载均衡域名，由后者进一步调度。

## TTL 的影响

TTL 决定 DNS 记录在缓存中的存活时间。

1. TTL 太长：缓存命中率高、解析压力低，但故障切换和变更生效慢。
2. TTL 太短：切换快，但权威 DNS 和递归 DNS 压力增加，客户端也可能不严格遵守很短 TTL。
3. 真实生产中常配合健康检查、GSLB、CDN 和多级缓存做权衡。

## 易错点

1. DNS 解析结果不是浏览器每次都向权威 DNS 查，缓存很重要。
2. 用户实际暴露给权威 DNS 的可能是递归 DNS IP，不一定是用户真实 IP；EDNS Client Subnet 可以缓解但有隐私和兼容问题。
3. DNS 负载均衡不等于连接级负载均衡，客户端和递归 DNS 缓存可能让流量不完全均匀。
4. DNS 使用 UDP 53 为主，但大响应、区域传送、DNS over TCP 等场景会用 TCP。
5. HTTPS 不能防止 DNS 被污染，但证书校验可以阻止无合法证书的伪站完成 TLS。

## 面试回答模板

DNS 解析会先查浏览器、系统、hosts、本地递归 DNS 缓存；没有命中时，递归 DNS 逐级问根域、顶级域和权威 DNS，拿到 A/AAAA/CNAME 记录后按 TTL 缓存并返回。DNS 调度常见有轮询、加权轮询、GeoDNS、延迟优先、健康检查剔除和 CDN/GSLB。工程上要注意 TTL 与故障切换的权衡，以及递归 DNS 缓存导致的流量不均和切换延迟。
