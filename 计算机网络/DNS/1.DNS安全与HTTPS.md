# 1. DNS 安全与 HTTPS

DNS 负责把域名解析成 IP，但传统 DNS 查询大多是明文 UDP，容易被监听、污染、劫持或伪造响应。HTTPS 负责保护客户端和服务器之间的传输内容，并通过证书校验服务器身份。

## HTTPS 能否防住 DNS 攻击

结论：**HTTPS 不能阻止 DNS 被污染或劫持，但可以阻止攻击者在没有合法证书的情况下伪装成目标 HTTPS 站点。**

例如用户访问 `https://example.com`：

1. 如果 DNS 被攻击，返回了攻击者 IP。
2. 浏览器仍然会在 TLS 握手中校验证书是否属于 `example.com`。
3. 攻击者如果没有 `example.com` 的合法证书，TLS 握手会失败或浏览器报证书错误。
4. 如果用户忽略证书告警，或者 CA/证书链被攻破，仍然可能被攻击。

所以 HTTPS 保护的是“连接到的服务器是否能证明自己是这个域名”，不是保护 DNS 查询过程本身。

## 常见 DNS 攻击

1. **DNS 污染**：注入伪造响应，让客户端拿到错误 IP。
2. **DNS 劫持**：运营商、路由器或恶意软件篡改解析结果。
3. **DNS 缓存投毒**：污染递归 DNS 缓存，使大量用户拿到错误结果。
4. **域名劫持**：攻击域名注册商账号或 DNS 托管平台，直接修改权威记录。

## 防护方式

1. **HTTPS 证书校验**：防止错误 IP 上的攻击者伪造目标站点。
2. **HSTS**：强制浏览器使用 HTTPS，降低被降级到 HTTP 的风险。
3. **DNSSEC**：对 DNS 记录做签名校验，防止解析记录被篡改，但部署复杂。
4. **DoH / DoT**：把 DNS 查询放到 HTTPS/TLS 中，防止本地网络窃听和篡改 DNS 查询。
5. **证书透明度 CT**：帮助发现异常签发证书。
6. **客户端证书锁定/公钥锁定**：移动端 App 可做证书或公钥 pinning，但要设计好轮换和灾备。

## 面试回答模板

HTTPS 本身不能防止 DNS 解析结果被篡改，因为 DNS 发生在建连之前。但 HTTPS 的证书校验能防止攻击者拿错误 IP 冒充目标域名：如果攻击者没有目标域名的合法证书，TLS 校验会失败。要保护 DNS 解析过程，需要 DNSSEC、DoH/DoT、可信递归 DNS 等方案；移动端还可以结合证书 pinning 提升抗中间人能力。
