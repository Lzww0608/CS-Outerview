# 12. 网络字节序与主机字节序

字节序描述多字节整数在内存中的字节排列顺序。网络通信、二进制协议和跨平台文件格式必须约定字节序，否则不同 CPU 架构上的程序会把同一段字节解释成不同数值。

## 1. 大端和小端

假设整数 `0x12345678` 占 4 个字节：

```text
大端序：12 34 56 78
小端序：78 56 34 12
```

1. **大端序**：高位字节放在低地址。
2. **小端序**：低位字节放在低地址。
3. **主机字节序**：本机 CPU 和 ABI 使用的字节序，常见 x86/x86_64 是小端。
4. **网络字节序**：网络协议规定的字节序，通常是大端序。

网络字节序和主机字节序“和什么有关”：主机字节序和 CPU 架构、ABI 有关；网络字节序和协议规范有关。IP、TCP、UDP 首部里的多字节整数一般按网络字节序传输。

## 2. 为什么网络要统一字节序

网络通信双方可能运行在不同硬件上。如果直接把内存里的整数发出去，小端机器和大端机器会解析出不同结果。

例如端口号 `8080` 十六进制是 `0x1F90`：

```text
网络字节序：1F 90
小端主机内存：90 1F
```

如果小端机器不转换就发送端口字段，接收方按网络字节序解析会得到错误端口。

## 3. 常用转换函数

POSIX 提供一组函数处理主机序和网络序转换：

```cpp
#include <arpa/inet.h>
#include <cstdint>

uint16_t port = 8080;
uint32_t ip = 0x7F000001; // 127.0.0.1

uint16_t net_port = htons(port); // host to network short
uint32_t net_ip = htonl(ip);     // host to network long

uint16_t host_port = ntohs(net_port); // network to host short
uint32_t host_ip = ntohl(net_ip);     // network to host long
```

含义：

1. `htons`：host to network short，通常处理 16 位端口。
2. `htonl`：host to network long，通常处理 32 位 IPv4 地址或长度字段。
3. `ntohs`：network to host short。
4. `ntohl`：network to host long。

如果本机本来就是大端，这些函数可能什么都不做；如果本机是小端，它们会交换字节。代码不应手写判断平台再决定是否转换，直接调用标准函数更稳。

## 4. 协议设计中的注意事项

设计二进制协议时，应该明确：

1. 多字节整数使用大端还是小端，建议统一使用网络字节序。
2. 字符串是否带长度，长度字段自身也要规定字节序。
3. 浮点数不要直接跨平台裸传，优先转成整数定点数、字符串或使用 Protobuf/FlatBuffers 等序列化框架。
4. 不要直接发送 C/C++ 结构体内存，因为结构体有 padding、对齐、字节序和 ABI 差异。
5. 对协议头字段做边界校验，避免长度字段被错误字节序解析成超大值。

## 5. 易错点

1. 只有多字节字段才有字节序问题，单字节 `char` 没有大小端问题。
2. 字节序不同于位序，面试中通常讨论的是字节排列。
3. 网络字节序通常是大端，不随本机 CPU 改变。
4. `inet_addr`、`inet_pton` 等接口返回的地址通常已经是网络字节序，不要重复 `htonl`。
5. 日志打印网络序整数前，先转回主机序，否则数值可能看起来错误。

## 6. 面试回答模板

主机字节序是本机 CPU/ABI 存储多字节整数的方式，常见 x86 是小端；网络字节序是网络协议统一规定的字节序，通常是大端。因为通信双方可能架构不同，所以 TCP/IP 首部里的端口、长度、序号等多字节字段都按网络字节序传输。写 socket 程序时，端口用 `htons/ntohs`，IPv4 地址或 32 位字段用 `htonl/ntohl`。设计二进制协议时不要直接发送结构体内存，要显式规定字段长度、字节序和对齐方式。
