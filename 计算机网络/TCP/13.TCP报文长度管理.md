# 13. TCP 报文长度管理

TCP 是面向字节流的协议，不保留应用层消息边界。面试里问“TCP 报文长度怎么管理”，核心不是回答“有一个固定长度字段”，而是说明 TCP 如何通过缓冲区、MSS、窗口和拥塞控制把连续字节流拆成适合网络传输的报文段。

## 1. TCP 没有应用消息边界

应用层多次调用 `send()`，接收端不一定按同样次数 `recv()` 到数据：

```text
send("hello")
send("world")
```

接收端可能看到：

```text
"helloworld"
"he" + "lloworld"
"hello" + "world"
```

这就是常说的粘包、拆包问题。本质原因是 TCP 只保证字节流有序可靠，不保证应用层一次写入对应一次读取。

应用层协议必须自己定义消息边界，例如：

1. 固定长度报文。
2. 分隔符协议，例如 Redis RESP 的 `\r\n`。
3. 长度前缀，例如 `length + body`。
4. 上层协议帧，例如 HTTP/2 frame、WebSocket frame。

## 2. MSS 如何限制 TCP segment

MSS（Maximum Segment Size）表示 TCP segment 中数据部分的最大长度，不包含 TCP 头和 IP 头。常见以太网 IPv4 场景：

```text
MTU = 1500
IP header = 20
TCP header = 20
MSS = 1460
```

三次握手时双方会在 SYN 报文里通过 TCP option 交换 MSS，实际发送时通常取双方通告值和本地路径限制中的较小值。

如果应用写入 100KB 数据，TCP 不会把它当成一个报文发送，而是根据 MSS、发送窗口、拥塞窗口和网卡 offload 情况拆成多个 segment。

## 3. 发送端如何决定发多少

发送端实际能发送的数据受多个因素共同限制：

```text
可发送数据量 <= min(接收窗口 rwnd, 拥塞窗口 cwnd, 发送缓冲区数据量)
```

1. **发送缓冲区**：应用写入的数据先进入内核发送缓冲区。
2. **MSS**：限制单个 TCP segment 的数据大小。
3. **接收窗口 rwnd**：接收端通告自己还能接收多少数据，负责流量控制。
4. **拥塞窗口 cwnd**：发送端根据网络拥塞状况维护，负责拥塞控制。
5. **Nagle 算法**：小包场景下可能合并发送，减少小报文数量。

如果设置 `TCP_NODELAY`，可以关闭 Nagle 算法，降低小消息延迟，但可能增加小包数量和协议开销。

## 4. 大包 Offload

现代内核和网卡还会使用 TSO/GSO/GRO 等 offload 技术：

1. **TSO/GSO**：内核协议栈或网卡把大块 TCP 数据延后切分成多个 segment。
2. **GRO/LRO**：接收侧把多个 segment 合并后再交给上层协议栈处理。

因此抓包时看到的包长、应用写入大小和网卡真正发出的帧大小可能不一致。排查时要区分“应用层数据长度”“内核协议栈 segment”和“链路层帧”。

## 5. 和 UDP 的区别

UDP 是数据报协议，一次 `sendto()` 通常对应一个 UDP datagram，接收端一次 `recvfrom()` 读取一个 datagram。如果接收缓冲区太小，超出的部分可能被截断。

TCP 是字节流协议，应用层必须自定义消息边界；UDP 有报文边界，但大 datagram 容易触发 IP 分片，丢失风险更高。

## 6. 真实场景

1. **HTTP/1.1**：通过 `Content-Length` 或 `Transfer-Encoding: chunked` 表达消息边界。
2. **RPC 协议**：常用 4 字节长度前缀 + body，服务端先读长度再读完整 body。
3. **高频小消息**：可根据延迟需求决定是否设置 `TCP_NODELAY`。
4. **大文件传输**：应用层只需要持续写入，内核会按 MSS、窗口和拥塞控制拆分发送。

## 7. 易错点

1. TCP header 里没有“整个应用消息长度”字段。
2. MSS 不是 MTU，MSS 不包含 IP/TCP 头。
3. 一次 `send()` 成功只表示数据进入内核缓冲区，不表示对端应用已经处理。
4. 粘包不是 TCP 的 bug，而是字节流语义要求应用层定义帧格式。
5. `recv()` 返回多少字节取决于缓冲区、当前到达数据和阻塞模式，不等于发送端写入大小。

## 8. 面试回答模板

TCP 是字节流协议，应用层消息没有天然边界，所以报文长度管理分两层看：传输层通过 MSS、发送缓冲区、接收窗口、拥塞窗口和 Nagle 算法决定每次发送多少字节；应用层则要自己设计消息边界，比如固定长度、分隔符、长度前缀或协议帧。MSS 通常在三次握手里协商，常见以太网 IPv4 下是 1460 字节。大数据写入时 TCP 会拆成多个 segment，小数据写入可能被合并，所以网络程序必须处理粘包和拆包。
