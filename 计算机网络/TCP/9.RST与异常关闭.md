# RST 与异常关闭

TCP 的 `RST` 表示 Reset，用于立即重置连接。它和 `FIN` 的语义不同：`FIN` 是正常半关闭，表示“我这边没有数据要发了”；`RST` 是异常终止，表示“这个连接状态不成立，立刻放弃”。

## 1. 什么时候会收到 RST

常见场景如下：

1. **连接不存在**：客户端连接一个没有进程监听的端口，服务端内核通常回复 `RST`。
2. **对端异常关闭**：对端设置 `SO_LINGER` 且超时时间为 0 后关闭 socket，内核会直接发送 `RST`。
3. **向已关闭连接继续发数据**：对端已经关闭连接，本端还继续发送数据，可能收到 `RST`。
4. **半连接或全连接队列异常**：服务端过载、队列溢出或配置开启特殊策略时，可能直接重置部分连接。
5. **中间设备注入**：防火墙、负载均衡、代理、NAT 设备发现策略不允许或状态丢失时，可能代发 `RST`。
6. **收到无法匹配当前连接状态的报文段**：例如序列号、四元组、连接状态不符合内核 TCP 状态机预期。

### 端口扫描和防火墙里的 RST

`RST` 也经常出现在安全和诊断场景里：

1. **端口扫描**：扫描器向目标端口发送 `SYN`。如果端口关闭，目标主机通常返回 `RST`；如果端口开放，会返回 `SYN+ACK`。这也是 SYN scan 判断端口状态的基础。
2. **防火墙拒绝连接**：防火墙可以选择静默丢弃包，也可以主动回 `RST`。回 `RST` 的好处是调用方能更快失败；静默丢弃则会让调用方等待超时。
3. **连接状态丢失**：NAT、负载均衡或防火墙重启后状态表丢失，后续包无法匹配已有连接，也可能被重置。

工程排查时不能只看到 `RST` 就断定是应用主动关闭，要结合抓包里的发送方 IP/MAC、TTL、序列号和中间设备日志判断 `RST` 是目标主机发出的，还是链路中的设备注入的。

## 2. FIN 和 RST 的区别

| 对比项 | FIN | RST |
| --- | --- | --- |
| 语义 | 正常关闭发送方向 | 异常重置连接 |
| 是否保留已收数据 | 通常保留，应用仍可读取缓冲区数据 | 往往直接报错，未读数据可能被丢弃 |
| 状态机 | 进入四次挥手相关状态 | 连接立即释放 |
| 应用表现 | `read` 返回 0 表示 EOF | `read/write` 返回错误，例如 `ECONNRESET` |

面试时可以强调：`RST` 不保证优雅交付剩余数据，所以不能把它当成正常关闭协议使用。

## 3. 不想走四次挥手，如何直接关闭连接

正常 `close()` 通常会触发 FIN 四次挥手。如果希望立即放弃连接，可以设置 `SO_LINGER` 为开启且超时时间为 0，关闭时内核会发送 `RST`，直接重置连接：

```c
struct linger ling;
ling.l_onoff = 1;
ling.l_linger = 0;
setsockopt(fd, SOL_SOCKET, SO_LINGER, &ling, sizeof(ling));
close(fd);
```

这种方式的语义是异常关闭，不是优雅关闭：

1. 本端未发送完成的数据可能被丢弃。
2. 对端通常会看到 `ECONNRESET`、`Connection reset by peer`。
3. 对端内核接收缓冲区里未被应用读取的数据也可能受影响。
4. 适合协议错误、攻击连接、超时连接、进程快速清理等场景，不适合正常业务响应完成后的关闭。

如果只是“不再发送但还想读对端剩余数据”，应该使用 `shutdown(fd, SHUT_WR)` 做半关闭，而不是 RST。

## 4. 报文段为什么会滞留

TCP 报文段在网络中滞留，通常来自以下原因：

1. **路由排队**：路由器、交换机、网关在拥塞时会排队缓存分组。
2. **链路层重传**：无线网络、移动网络或隧道链路可能在链路层重传，拉长端到端时延。
3. **路径变化**：路由收敛或负载均衡路径变化可能导致旧分组比新分组晚到。
4. **中间设备缓存**：代理、NAT、防火墙、隧道网关可能暂存或重放部分分组。
5. **发送端重传**：发送端认为丢包后重传，旧报文段和新报文段可能同时在网络里存在。

这也是 TCP 需要序列号、确认号、MSL、TIME_WAIT 的原因：旧连接的迟到报文不能污染新连接。

## 5. 排查思路

1. 客户端日志看错误码：`ECONNRESET`、`EPIPE`、`Connection reset by peer`。
2. 服务端看是否主动异常关闭、进程崩溃、超时踢连接或负载均衡重置。
3. 抓包确认 `RST` 的发送方、序列号和时刻。
4. 检查 backlog、accept 速度、连接数、文件描述符上限和中间设备超时策略。

## 6. 面试回答模板

`RST` 是 TCP 的异常重置报文，常见于连接不存在、对端异常关闭、向已关闭连接继续发送、队列或中间设备策略异常等场景。它和 `FIN` 最大区别是：`FIN` 是正常半关闭，应用还能读完缓冲区数据；`RST` 是立即终止，应用通常看到 `ECONNRESET`。如果不想走四次挥手，可以设置 `SO_LINGER` 的 `l_onoff=1`、`l_linger=0` 后 `close`，让内核发送 RST，但这会丢弃未发送数据，只适合异常关闭。网络中的报文段可能因为路由排队、链路重传、路径变化、中间设备缓存或发送端重传而滞留，所以 TCP 需要序列号和 TIME_WAIT 来避免旧报文污染新连接。
