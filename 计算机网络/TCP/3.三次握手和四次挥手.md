# 3.TCP 三次握手和四次挥手

TCP 是面向连接的可靠传输协议。三次握手用于建立连接，四次挥手用于关闭连接。

## 1. 三次握手过程

```text
1. Client -> Server: SYN, seq = x
2. Server -> Client: SYN + ACK, seq = y, ack = x + 1
3. Client -> Server: ACK, ack = y + 1
```

状态变化：

```text
Client: CLOSED -> SYN_SENT -> ESTABLISHED
Server: CLOSED -> LISTEN -> SYN_RCVD -> ESTABLISHED
```

三次握手完成后，双方都确认了两件事：

1. 自己的发送能力和接收能力正常。
2. 对方的发送能力和接收能力正常。

同时，双方交换初始序列号 ISN，后续可靠传输依赖这个序列号空间。

## 2. 为什么不能两次握手？

两次握手的问题是服务端无法确认客户端是否收到了自己的 `SYN+ACK`，也就无法确认客户端的接收能力和服务端自己的发送能力。

还有一个经典问题是旧连接请求：

1. 客户端之前发出的旧 `SYN` 因网络延迟滞留。
2. 旧 `SYN` 到达服务端后，如果两次握手就建立连接，服务端会错误创建连接。
3. 三次握手要求客户端再回一个 ACK，客户端收到旧连接的 `SYN+ACK` 后可以识别异常并拒绝。

所以三次握手是建立可靠双向通信所需的最少交互次数。

## 3. 四次挥手过程

TCP 是全双工协议，两个方向的数据流要分别关闭，因此通常需要四次挥手。

```text
1. 主动关闭方 -> 被动关闭方: FIN
2. 被动关闭方 -> 主动关闭方: ACK
3. 被动关闭方 -> 主动关闭方: FIN
4. 主动关闭方 -> 被动关闭方: ACK
```

状态变化：

```text
主动关闭方:
ESTABLISHED -> FIN_WAIT_1 -> FIN_WAIT_2 -> TIME_WAIT -> CLOSED

被动关闭方:
ESTABLISHED -> CLOSE_WAIT -> LAST_ACK -> CLOSED
```

## 4. 为什么挥手通常是四次？

因为 TCP 是全双工的。

主动关闭方发送 `FIN` 只表示“我没有数据要发了”，但它仍然可以接收对方的数据。被动关闭方收到 `FIN` 后先回 `ACK`，表示已经知道对方不再发送数据。此时被动关闭方可能还有数据没发完，所以不能立刻发送自己的 `FIN`。

等被动关闭方应用层也调用 `close()`，确认自己也没有数据要发了，才发送自己的 `FIN`。主动关闭方再回最后一个 `ACK`。

如果被动关闭方收到 `FIN` 后刚好也没有数据要发送，第二次 ACK 和第三次 FIN 可能合并成一个报文，但协议语义上仍然是两个动作。

## 5. TIME_WAIT 的作用

主动关闭方发送最后一个 ACK 后进入 `TIME_WAIT`，等待 2MSL。

作用：

1. **保证可靠关闭**：如果最后一个 ACK 丢失，被动关闭方会重传 FIN，主动关闭方还能再次回复 ACK。
2. **防止旧报文污染新连接**：等待旧连接中的延迟报文在网络中自然消失，避免相同四元组的新连接收到旧数据。

## 6. 常见异常状态

| 状态 | 出现位置 | 含义 |
| --- | --- | --- |
| `SYN_SENT` | 客户端 | 已发 SYN，等待 SYN+ACK |
| `SYN_RCVD` | 服务端 | 已收到 SYN 并回复 SYN+ACK，等待 ACK |
| `CLOSE_WAIT` | 被动关闭方 | 对方已关闭发送方向，本端应用还没 close |
| `LAST_ACK` | 被动关闭方 | 本端已发 FIN，等待最后 ACK |
| `TIME_WAIT` | 主动关闭方 | 等待 2MSL 后彻底关闭 |

如果服务端大量 `CLOSE_WAIT`，通常说明应用层没有及时关闭 socket。大量 `TIME_WAIT` 则常见于主动关闭连接的一方，尤其是短连接高并发场景。

## 7. 面试回答模板

TCP 三次握手是：客户端发 `SYN`，服务端回 `SYN+ACK`，客户端再回 `ACK`。它的目的不是简单通知对方“我要连接”，而是确认双方收发能力，并交换初始序列号。不能两次握手，是因为服务端无法确认客户端是否收到了自己的响应，也容易受旧 SYN 报文影响。

四次挥手是：主动关闭方发 `FIN`，被动关闭方回 `ACK`；等被动关闭方也没有数据要发时，再发 `FIN`，主动关闭方回 `ACK`。之所以通常是四次，是因为 TCP 是全双工，两个方向要分别关闭。主动关闭方最后进入 `TIME_WAIT`，主要是为了处理最后 ACK 丢失时对方重传 FIN，以及避免旧连接报文干扰新连接。
