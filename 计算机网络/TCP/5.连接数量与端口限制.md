# 5. TCP 连接数量与端口限制

## 1. TCP 连接由什么唯一标识

一条 TCP 连接由四元组唯一标识：

```text
源 IP, 源端口, 目的 IP, 目的端口
```

只要四元组不同，内核就可以区分不同连接。

## 2. 一个客户端最多能连接多少个服务端

如果客户端连接的是同一个服务端同一个端口，那么主要受本机临时端口范围限制。

Linux 可以查看：

```bash
cat /proc/sys/net/ipv4/ip_local_port_range
```

常见范围类似：

```text
32768 60999
```

也就是大约 2.8 万个临时端口。每个出站连接需要占用一个本地源端口，所以对同一个目的 IP:Port 的并发连接数大致受临时端口数量限制。

但如果连接不同的目的 IP 或目的端口，同一个本地端口可以复用，因为四元组仍然不同。因此“一个客户端最多连多少服务端”没有固定答案，除了端口范围，还受以下限制：

1. 文件描述符上限：`ulimit -n`、`fs.file-max`。
2. 本机内存：每个 TCP socket 都有控制块、收发缓冲区。
3. CPU 和网卡能力。
4. NAT 网关或安全设备的连接跟踪表容量。
5. `TIME_WAIT` 占用端口导致短连接场景端口回收变慢。

## 3. 一个服务器最多能接受多少个客户端连接

服务端可以用同一个监听端口接受大量客户端连接，因为每条已建立连接的四元组不同：

```text
客户端A IP:Port -> 服务端IP:80
客户端B IP:Port -> 服务端IP:80
客户端C IP:Port -> 服务端IP:80
```

服务端最大连接数主要受系统资源限制，而不是监听端口只能被一个连接占用。

关键限制：

1. **fd 上限**：每个连接至少占用一个 fd。
2. **内存**：socket 结构、协议控制块、收发缓冲区、应用层连接对象。
3. **accept 队列**：`somaxconn`、应用 `listen(backlog)`、SYN backlog。
4. **CPU**：协议栈处理、加解密、业务逻辑、上下文切换。
5. **网络带宽**：连接数高不等于吞吐足够。
6. **应用模型**：一连接一线程会先被线程栈和调度开销打垮；高并发服务通常使用非阻塞 I/O + epoll/Reactor。

## 4. 常用排查命令

```bash
ulimit -n
cat /proc/sys/net/ipv4/ip_local_port_range
cat /proc/sys/net/core/somaxconn
ss -ant state established | wc -l
ss -s
```

如果经过 NAT，还要看网关的连接跟踪：

```bash
cat /proc/sys/net/netfilter/nf_conntrack_max
```

## 5. 面试回答模板

TCP 连接由四元组唯一标识。客户端如果连同一个服务端同一个端口，最大并发数主要受本地临时端口范围限制，通常是几万级；如果连不同目的 IP 或端口，同一个源端口可以复用，因为四元组不同。服务端监听一个端口可以接受很多客户端连接，已建立连接靠客户端 IP 和端口区分，真正限制来自 fd 上限、socket 内存、accept 队列、CPU、带宽和应用 I/O 模型。
