# 1. 抓包与网络故障定位

网络问题排查的核心是按层缩小范围：先确认本机配置和连通性，再看路由、DNS、端口、TLS、应用协议，最后用抓包验证真实报文。

## 1. Linux 下抓包

常用工具是 `tcpdump`：

```bash
tcpdump -i eth0 host 10.0.0.2 and port 443
tcpdump -i any tcp port 8080 -nn -vv
tcpdump -i eth0 -w out.pcap host 10.0.0.2
```

常见用法：

1. `-i` 指定网卡，容器或复杂路由场景可以先用 `-i any`。
2. `host/port/tcp/udp` 用 BPF 表达式过滤流量。
3. `-nn` 不做 DNS 和端口名解析，避免排查时引入额外噪声。
4. `-w` 保存为 pcap，用 Wireshark 离线分析。

排查 TCP 问题时重点看：三次握手是否完成、是否有重传、是否收到 RST、窗口是否为 0、TLS 握手在哪一步失败。

## 2. Windows 下抓包

常见选择：

1. **Wireshark + Npcap**：图形化分析最常用，适合看 TCP 流、TLS 握手、HTTP 报文和重传。
2. **pktmon**：Windows 自带工具，可采集数据包并转换为 pcapng。
3. **netsh trace**：用于系统级网络跟踪，适合没有安装第三方工具的机器。

示例：

```powershell
pktmon start --capture --pkt-size 0
pktmon stop
pktmon pcapng PktMon.etl -o out.pcapng
```

Windows 上还要关注防火墙、代理、VPN、Npcap 驱动权限和网卡选择，抓错网卡会导致“看起来没有包”。

## 2.1 HTTP 和 HTTPS 抓包怎么看

抓 HTTP 包时，通常可以直接看到请求行、Header、Body 和响应状态码：

```bash
tcpdump -i any -nn -s 0 -A 'tcp port 80 and host 10.0.0.2'
tcpdump -i any -nn -s 0 -w http.pcap 'host 10.0.0.2 and port 80'
```

Wireshark 里可以用 `http`、`tcp.stream eq 3`、`ip.addr == 10.0.0.2` 等过滤条件，再 Follow TCP Stream 查看完整请求响应。

抓 HTTPS 包时，只抓网络包默认只能看到 TCP/TLS 层信息，看不到 HTTP 明文。能直接分析的内容包括：

1. TCP 三次握手是否成功。
2. TLS ClientHello、ServerHello、证书、SNI、ALPN、TLS 版本和密码套件。
3. 握手失败告警、证书链错误、连接被 RST 或超时。
4. 加密后的 Application Data 包大小、方向和时间间隔。

如果需要看 HTTPS 明文，常见方式有：

1. **本机代理解密**：使用 Charles、Fiddler、mitmproxy，让客户端信任代理 CA，代理再转发到真实服务。
2. **浏览器会话密钥**：设置 `SSLKEYLOGFILE`，让 Chrome/Firefox 输出 TLS 会话密钥，再导入 Wireshark 解密。
3. **服务端侧日志或网关日志**：在 Nginx、API 网关、应用日志里记录请求摘要，避免抓包直接解密生产流量。
4. **测试环境临时关闭 TLS 或使用内部证书**：只适合受控环境，不能用于生产绕过安全。

易错点：

1. HTTPS 不是“抓不到包”，而是抓到的是密文；仍然能定位握手、证书、SNI、ALPN、重传和断连问题。
2. 代理解密需要客户端信任代理证书，移动端还可能有证书固定（certificate pinning）导致代理失败。
3. TLS 1.3 前向安全场景下，只有服务端私钥通常不能离线解密历史流量，使用 `SSLKEYLOGFILE` 更可靠。
4. 生产环境抓包要控制范围和权限，避免采集 Cookie、Token、个人信息等敏感数据。

## 3. 网络问题常见原因

按层排查：

1. **物理/链路层**：网线、Wi-Fi、网卡 down、VLAN 配置、MTU 不一致。
2. **网络层**：IP 配置错误、路由缺失、网关不可达、ARP 异常、NAT 配置错误。
3. **传输层**：端口未监听、防火墙丢包、SYN backlog 满、连接被 RST、TIME_WAIT/CLOSE_WAIT 过多。
4. **DNS**：域名解析错误、缓存污染、内网 DNS 不可达、解析到错误机房。
5. **TLS/HTTPS**：证书过期、域名不匹配、协议版本或密码套件不兼容、SNI 错误。
6. **应用层**：反向代理路由错误、Host 头错误、鉴权失败、限流、上游超时、服务返回 4xx/5xx。
7. **性能类问题**：丢包、重传、带宽打满、Bufferbloat、拥塞控制、下游慢导致请求堆积。

## 4. 排查顺序

1. `ip addr` / `ip route` 看本机地址和路由。
2. `ping` 看基本连通性，`traceroute` / `mtr` 看路径和丢包。
3. `dig` / `nslookup` 看 DNS 解析。
4. `ss -lntp` / `netstat -ano` 看端口监听和连接状态。
5. `curl -v` / `openssl s_client` 看 HTTP/TLS 细节。
6. `tcpdump` / Wireshark 抓包确认请求是否发出、对端是否响应、哪里重传或断开。

## 5. 面试回答模板

Linux 抓包我会用 `tcpdump`，例如 `tcpdump -i eth0 host 1.2.3.4 and port 443 -nn -w out.pcap`，再用 Wireshark 看握手、重传、RST 和 TLS。Windows 上常用 Wireshark + Npcap，也可以用系统自带的 `pktmon` 或 `netsh trace`。网络问题要按层排查：本机 IP/路由、DNS、端口监听、防火墙、TCP 状态、TLS 证书、反向代理和应用返回码。抓包的价值是确认事实：包有没有出去、有没有回来、在哪一层失败。
