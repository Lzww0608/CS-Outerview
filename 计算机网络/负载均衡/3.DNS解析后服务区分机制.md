# DNS 解析后服务区分：端口与路径路由

## 1. 问题背景

当用户请求登录服务时，DNS 解析返回服务器 IP 后，该 IP 需要知道请求应该路由到登录服务而非订单服务。这个过程涉及多层网络路由机制。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  请求流程：                                                │
│                                                             │
│  用户 ──► DNS 解析 ──► IP ──► 端口 ──► 服务              │
│                                                             │
│  关键问题：IP 如何区分不同服务？                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 | 影响 |
|------|------|------|
| 端口区分 | 不同服务监听不同端口 | 简单直接 |
| 路径区分 | 不同 URL 路径路由到不同服务 | 灵活 |
| Host 区分 | 不同域名路由到不同服务 | 常见 |
| IP 区分 | 不同 VIP 路由到不同服务 | 高可用 |

## 5. 解决方案

### 5.1 Nginx 配置

```nginx
# /etc/nginx/nginx.conf

http {
    # 订单服务
    upstream order_backend {
        server 192.168.1.101:8080;
        server 192.168.1.102:8080;
    }
    
    # 登录服务
    upstream login_backend {
        server 192.168.1.103:8080;
        server 192.168.1.104:8080;
    }
    
    server {
        listen 80;
        server_name api.example.com;
        
        # 基于路径路由
        location /api/order {
            proxy_pass http://order_backend;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
        }
        
        location /api/login {
            proxy_pass http://login_backend;
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
        }
    }
}
```

### 5.2 七层网关路由

```python
# 使用 Python 实现简单网关
from flask import Flask, request, jsonify

app = Flask(__name__)

# 服务端点
SERVICES = {
    'order': 'http://192.168.1.101:8080',
    'login': 'http://192.168.1.103:8080',
    'user': 'http://192.168.1.105:8080',
}

@app.route('/<service>/<path:path>', methods=['GET', 'POST'])
def route_request(service, path):
    if service not in SERVICES:
        return jsonify({'error': 'Service not found'}), 404
    
    # 转发到对应服务
    target_url = f"{SERVICES[service]}/{path}"
    
    # 使用 requests 转发（实际生产用 http 客户端）
    # response = requests.request(
    #     method=request.method,
    #     url=target_url,
    #     headers={k: v for k, v in request.headers if k != 'Host'},
    #     data=request.get_data()
    # )
    # return response.content, response.status_code
    
    return jsonify({
        'service': service,
        'path': path,
        'target': target_url
    })

if __name__ == '__main__':
    app.run(host='0.0.0.0', port=80)
```

### 5.3 四层端口配置

```bash
# Docker Compose 多服务端口配置
version: '3.8'

services:
  # 订单服务
  order-service:
    image: order-service:latest
    ports:
      - "8081:8080"  # 外部 8081 -> 内部 8080
    
  # 登录服务
  login-service:
    image: login-service:latest
    ports:
      - "8082:8080"  # 外部 8082 -> 内部 8080
    
  # Nginx 网关
  nginx:
    image: nginx:latest
    ports:
      - "80:80"       # HTTP
      - "443:443"     # HTTPS
    depends_on:
      - order-service
      - login-service
```

## 6. 可选方案对比

### 6.1 路由方式对比

| 方案 | 层级 | 优点 | 缺点 |
|------|------|------|------|
| 端口区分 | 四层 | 简单，性能高 | 端口不美观 |
| 路径区分 | 七层 | 统一入口，灵活 | 路径可能泄露服务名 |
| Host 区分 | 七层 | 语义清晰 | 需要多域名 |
| IP 区分 | 四层 | 隔离好 | IP 管理复杂 |

### 6.2 方案对比

```text

│  • API 网关 ──► 路径区分                                 │
│  • 多环境隔离 ──► Host 区分                              │
│  • 高性能场景 ──► 端口区分                               │
```

## 8. 实施步骤

### 8.1 Nginx 配置步骤

```bash
# 1. 安装 Nginx
apt install nginx

# 2. 配置反向代理
cat > /etc/nginx/conf.d/api-gateway.conf << 'EOF'
server {
    listen 80;
    server_name api.example.com;
    
    location /api/order {
        proxy_pass http://order-backend;
    }
    
    location /api/login {
        proxy_pass http://login-backend;
    }
    
    location /api/user {
        proxy_pass http://user-backend;
    }
}
EOF

# 3. 测试并重载
nginx -t && nginx -s reload
```

## 9. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 路径冲突 | 请求无法路由 | 规范路径设计 |
| 单点故障 | 网关挂了全挂 | 高可用部署 |
| 性能瓶颈 | 网关成为瓶颈 | 水平扩展 |
| 安全风险 | 路径遍历攻击 | 输入校验 |

## 11. 总结

1. **DNS 只解析 IP**：不区分服务，服务区分在端口或应用层
2. **四层区分**：不同端口路由到不同服务
3. **七层区分**：基于 URL 路径或 Host 头路由
4. **推荐方案**：七层网关（Nginx/Envoy）统一入口，内部按路径路由
5. **关键点**：服务发现 + 负载均衡 + 路由规则
