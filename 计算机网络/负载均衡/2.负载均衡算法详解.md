## 二、轮询算法 (Round Robin)

### 2.1 算法原理

轮询是最简单的负载均衡算法，按顺序依次将请求分配到每个后端服务器。

```c
// 简单轮询实现
struct RoundRobinLB {
    Backend** backends;
    int count;
    int current_index;
    pthread_mutex_t mutex;
};

Backend* round_robin_select(RoundRobinLB* lb) {
    pthread_mutex_lock(&lb->mutex);
    lb->current_index = (lb->current_index + 1) % lb->count;
    Backend* selected = lb->backends[lb->current_index];
    pthread_mutex_unlock(&lb->mutex);
    return selected;
}
```

### 2.2 优缺点

| 优点 | 缺点 |
|------|------|
| 实现简单 | 无法感知服务器性能差异 |
| 开销低 | 无法处理服务器权重 |
| 请求均匀分布 | 短连接下可能不均匀 |
| 无状态，易于分布式部署 | - |

### 2.3 应用场景

- 后端服务器配置相同
- 请求耗时相近
- 短连接 HTTP 场景

## 三、加权轮询 (Weighted Round Robin)

### 3.1 算法原理

根据服务器权重比例分配请求，性能好的服务器分配更多请求。

```c
// 加权轮询实现
struct WeightedRoundRobinLB {
    Backend** backends;
    int count;
    int current_index;
};

Backend* weighted_round_robin_select(WeightedRoundRobinLB* lb) {
    // 初始化权重桶
    static int* weight_bucket = NULL;
    static int bucket_size = 0;
    
    if (bucket_size == 0) {
        bucket_size = 0;
        for (int i = 0; i < lb->count; i++) {
            bucket_size += lb->backends[i]->weight;
        }
        weight_bucket = malloc(sizeof(int) * bucket_size);
        
        int idx = 0;
        for (int i = 0; i < lb->count; i++) {
            for (int j = 0; j < lb->backends[i]->weight; j++) {
                weight_bucket[idx++] = i;
            }
        }
    }
    
    lb->current_index = (lb->current_index + 1) % bucket_size;
    return lb->backends[weight_bucket[lb->current_index]];
}
```

### 3.2 优缺点

| 优点 | 缺点 |
|------|------|
| 考虑服务器性能差异 | 需要手动配置权重 |
| 权重可动态调整 | 权重调整后需重建哈希桶 |
| 简单有效 | 权重相同时退化为普通轮询 |

### 3.3 应用场景

- 服务器配置不同（CPU、内存）
- 服务器性能差异较大
- 混合云场景（本地+云端）

## 四、最少连接 (Least Connections)

### 4.1 算法原理

将请求分配给当前活动连接数最少的服务器。

```c
// 最少连接实现
struct LeastConnectionsLB {
    Backend** backends;
    int count;
    pthread_mutex_t mutex;
};

Backend* least_connections_select(LeastConnectionsLB* lb) {
    pthread_mutex_lock(&lb->mutex);
    
    Backend* best = NULL;
    int min_connections = INT_MAX;
    
    for (int i = 0; i < lb->count; i++) {
        Backend* b = lb->backends[i];
        if (!b->is_healthy) continue;
        
        if (b->active_connections < min_connections) {
            min_connections = b->active_connections;
            best = b;
        }
    }
    
    if (best) {
        best->active_connections++;
    }
    
    pthread_mutex_unlock(&lb->mutex);
    return best;
}

// 连接释放时调用
void release_connection(LeastConnectionsLB* lb, Backend* backend) {
    pthread_mutex_lock(&lb->mutex);
    if (backend->active_connections > 0) {
        backend->active_connections--;
    }
    pthread_mutex_unlock(&lb->mutex);
}
```

### 4.2 优缺点

| 优点 | 缺点 |
|------|------|
| 动态适应服务器负载 | 需要维护连接状态 |
| 适合长连接场景 | 并发控制开销 |
| 自适应请求耗时差异 | 可能导致负载倾斜 |

### 4.3 应用场景

- 长连接场景（WebSocket、游戏）
- 请求处理时间差异大
- TCP 连接复用

## 五、加权最少连接 (Weighted Least Connections)

### 5.1 算法原理

结合服务器权重和当前连接数进行分配。

```c
Backend* weighted_least_connections_select(WeightedLeastConnectionsLB* lb) {
    Backend* best = NULL;
    double best_score = DBL_MAX;
    
    for (int i = 0; i < lb->count; i++) {
        Backend* b = lb->backends[i];
        if (!b->is_healthy) continue;
        
        // 计算综合评分：连接数/权重
        double score = (double)b->active_connections / b->weight;
        
        if (score < best_score) {
            best_score = score;
            best = b;
        }
    }
    
    if (best) {
        best->active_connections++;
    }
    
    return best;
}
```

### 5.2 优缺点

| 优点 | 缺点 |
|------|------|
| 结合性能和连接数 | 计算复杂度略高 |
| 适合异构环境 | 需要维护权重和连接数 |
| 动态适应 | - |

## 六、源 IP 哈希 (Source IP Hash)

### 6.1 算法原理

基于客户端 IP 地址计算哈希值，将请求分配到对应服务器，实现会话保持。

```c
// 源 IP 哈希实现
Backend* source_ip_hash_select(SourceIPHashLB* lb, uint32_t client_ip) {
    // 使用 CRC32 计算哈希
    uint32_t hash = crc32(0, (uint8_t*)&client_ip, sizeof(client_ip));
    int index = hash % lb->count;
    
    // 检查服务器健康状态
    if (lb->backends[index]->is_healthy) {
        return lb->backends[index];
    }
    
    // 服务器不可用，线性探测找可用服务器
    for (int i = 1; i < lb->count; i++) {
        int probe = (index + i) % lb->count;
        if (lb->backends[probe]->is_healthy) {
            return lb->backends[probe];
        }
    }
    
    return NULL;
}
```

### 6.2 优缺点

| 优点 | 缺点 |
|------|------|
| 会话保持 | 需要特殊处理服务器变更 |
| 无需 Cookie | 哈希不均匀可能导致负载倾斜 |
| 简单有效 | 服务器不可用时需要重哈希 |

### 6.3 应用场景

- 无法使用 Cookie 的客户端
- 简单的会话保持需求
- 四层负载均衡

## 七、一致性哈希 (Consistent Hashing)

### 7.1 算法原理

使用环形哈希空间，最小化服务器变更时的请求迁移。

```c
// 一致性哈希实现
struct ConsistentHashLB {
    map<uint32_t, Backend*> circle;      // 哈希环
    vector<uint32_t> sorted_keys;          // 排序后的哈希值
    Backend** backends;
    int count;
    int virtual_nodes;                      // 虚拟节点数
};

uint32_t hash_string(const char* str) {
    uint32_t hash = 5381;
    int c;
    while (c = *str++) {
        hash = ((hash << 5) + hash) + c;
    }
    return hash;
}

Backend* consistent_hash_select(ConsistentHashLB* lb, const char* key) {
    uint32_t hash = hash_string(key);
    
    // 二分查找第一个 >= hash 的节点
    auto it = upper_bound(lb->sorted_keys.begin(), 
                          lb->sorted_keys.end(), hash);
    
    if (it == lb->sorted_keys.end()) {
        // 环尾部，回 到头部
        it = lb->sorted_keys.begin();
    }
    
    return lb->circle[*it];
}

// 添加虚拟节点
void add_virtual_nodes(ConsistentHashLB* lb) {
    for (int i = 0; i < lb->count; i++) {
        for (int v = 0; v < lb->virtual_nodes; v++) {
            char vnode_name[256];
            snprintf(vnode_name, sizeof(vnode_name), 
                    "%s#%d", lb->backends[i]->name, v);
            
            uint32_t hash = hash_string(vnode_name);
            lb->circle[hash] = lb->backends[i];
            lb->sorted_keys.push_back(hash);
        }
    }
    sort(lb->sorted_keys.begin(), lb->sorted_keys.end());
}
```

### 7.2 虚拟节点

```text
┌─────────────────────────────────────────────────────────────┐
│                    一致性哈希环                               │
│                                                             │
│                    ┌──────────────┐                        │
│                   │    Server A    │ (真实节点)              │
│                   └───────┬──────┘                        │
│                           │                                  │
│              ┌────────────┼────────────┐                   │
│              │            │            │                    │
│    ┌─────────┴┐  ┌──────┴──────┐  ┌─┴─────────┐         │
│    │ A#1 A#2   │  │ B#1 B#2 B#3│  │ C#1 C#2   │         │
│    │(虚拟节点)  │  │  (虚拟节点)  │  │ (虚拟节点)  │         │
│    └───────────┘  └─────────────┘  └───────────┘         │
│                                                             │
│    A#1 → Server A, A#2 → Server A                         │
│    B#1/B#2/B#3 → Server B                                 │
│    C#1/C#2 → Server C                                      │
└─────────────────────────────────────────────────────────────┘
```

### 7.3 优缺点

| 优点 | 缺点 |
|------|------|
| 服务器变更时迁移量小 | 实现相对复杂 |
| 天然负载均衡 | 虚拟节点配置麻烦 |
| 适合分布式缓存 | 不保证绝对均匀 |

### 7.4 应用场景

- 分布式缓存（Redis Cluster）
- CDN 内容分发
- 微服务路由

## 八、最短响应时间 (Shortest Response Time)

### 8.1 算法原理

基于历史响应时间分配请求，响应快的服务器获得更多请求。

```c
// 指数加权移动平均 (EWMA)
struct ResponseTimeLB {
    Backend** backends;
    int count;
    double* avg_response_times;    // EWMA 平滑后的平均响应时间
    int* request_counts;           // 请求计数
    double alpha;                   // EWMA 平滑因子 (0 < alpha <= 1)
};

Backend* shortest_response_time_select(ResponseTimeLB* lb) {
    Backend* best = NULL;
    double best_score = DBL_MAX;
    
    for (int i = 0; i < lb->count; i++) {
        Backend* b = lb->backends[i];
        if (!b->is_healthy) continue;
        
        double score = lb->avg_response_times[i];
        
        if (score < best_score) {
            best_score = score;
            best = b;
        }
    }
    
    return best;
}

// 记录响应时间
void record_response_time(ResponseTimeLB* lb, int backend_id, 
                          double response_time) {
    // EWMA: avg = alpha * new + (1 - alpha) * old
    lb->avg_response_times[backend_id] = 
        lb->alpha * response_time + 
        (1 - lb->alpha) * lb->avg_response_times[backend_id];
    
    lb->request_counts[backend_id]++;
}
```

### 8.2 优缺点

| 优点 | 缺点 |
|------|------|
| 用户体验更好 | 需要持续收集响应时间 |
| 动态适应服务器状态 | 可能导致响应时间波动 |
| 适合延迟敏感场景 | 计算开销中等 |

### 8.3 应用场景

- API 服务
- 用户体验敏感的应用
- 混合云场景

## 九、随机算法 (Random)

### 9.1 算法原理

随机选择后端服务器。

```c
Backend* random_select(RandomLB* lb) {
    int index = rand() % lb->count;
    Backend* selected = lb->backends[index];
    
    if (selected->is_healthy) {
        return selected;
    }
    
    // 健康检查失败，随机选一个健康的
    for (int i = 0; i < lb->count; i++) {
        int probe = rand() % lb->count;
        if (lb->backends[probe]->is_healthy) {
            return lb->backends[probe];
        }
    }
    
    return NULL;
}
```

### 9.2 优缺点

| 优点 | 缺点 |
|------|------|
| 实现极简单 | 无法保证均匀分布（小样本） |
| 开销极低 | 不适合精确负载均衡 |
| 适合无状态服务 | - |

### 10.1 综合对比

| 算法 | 复杂度 | 状态 | 会话保持 | 适用场景 |

## 十一、面试常见问题

### Q1: 什么是最少连接算法？

最少连接算法将请求分配给当前活动连接数最少的服务器，适合长连接场景（如 WebSocket、游戏服务器），可以避免某些服务器过载。

### Q2: 一致性哈希解决了什么问题？

普通哈希当服务器变更时，几乎所有请求都需要重新路由。一致性哈希通过环形哈希空间和虚拟节点，使得服务器变更时只需要迁移少量请求，适合分布式缓存和 CDN 场景。

### Q3: 加权轮询和加权最少连接的区别？

加权轮询根据服务器性能配置固定权重，请求按权重比例分配；加权最少连接在此基础上考虑当前连接数，动态调整分配。简单理解：加权轮询适合请求耗时相近的场景，加权最少连接适合请求耗时差异大的场景。

### Q4: 如何实现平滑的加权轮询？

普通的加权轮询可能短时间连续选中同一个服务器。平滑加权轮询通过动态调整当前权重，确保分配更均匀：每次选中后减少该服务器剩余权重，权重归零时重置。

## 十二、总结

1. **轮询系**：简单高效，适合配置相同的服务器
2. **最少连接系**：动态适应，适合长连接和请求耗时差异大的场景
3. **哈希系**：会话保持，适合缓存和分布式系统
4. **响应时间系**：用户体验优先，适合延迟敏感的应用
5. **实际选型**：根据服务器配置、请求特性、会话需求综合考虑
