# 1. DDoS 攻击与防护

DDoS（Distributed Denial of Service，分布式拒绝服务）是攻击者控制大量主机、代理或反射源，同时向目标发起流量或请求，耗尽目标带宽、连接表、CPU、内存或后端依赖，使正常用户无法访问服务。

## 1. DDoS 攻击分类

| 类型 | 攻击目标 | 例子 |
| --- | --- | --- |
| 流量型 | 带宽、链路、清洗入口 | UDP Flood、反射放大攻击 |
| 协议型 | 网络协议栈、连接状态表 | SYN Flood、ACK Flood、分片攻击 |
| 应用层 | Web 服务、数据库、缓存、业务接口 | HTTP Flood、CC 攻击、慢速请求 |

真实攻击常常是混合型，例如先用 UDP Flood 打满带宽，再用 HTTP Flood 压垮应用。

## 2. 常见攻击方式

### SYN Flood

攻击者大量发送 SYN，但不完成三次握手，导致服务端半连接队列被占满。

常见防护：

1. 开启 SYN Cookie。
2. 调整 backlog 和半连接队列参数。
3. 对异常源 IP、异常速率做限流。
4. 在四层负载均衡或高防清洗层提前过滤。

更细地说，SYN Flood 消耗的是服务端为半连接维护的状态。正常三次握手中，服务端收到 SYN 后要记录客户端地址、端口、初始序列号、MSS、窗口扩大等信息，并回复 `SYN+ACK`，等待客户端最后 ACK。攻击者如果伪造源地址或故意不回 ACK，服务端会在 `SYN_RECV` 状态保留这些半连接，直到重传超时或队列被挤满。

Linux 常见观察和参数：

```bash
ss -ant state syn-recv
netstat -s | grep -i listen
sysctl net.ipv4.tcp_syncookies
sysctl net.ipv4.tcp_max_syn_backlog
sysctl net.core.somaxconn
```

SYN Cookie 的核心思想是：队列压力大时，服务端不保存半连接状态，而是把必要状态编码进 `SYN+ACK` 的初始序列号中。客户端回 ACK 后，服务端再校验 cookie 并创建连接。它能显著缓解半连接队列被打满，但也有取舍：可编码的信息有限，部分 TCP option 支持会受影响，因此通常作为压力下的兜底机制。

工程防护要分层：

1. **内核参数**：开启 `tcp_syncookies`，调大 `tcp_max_syn_backlog`、`somaxconn`，合理设置 SYN 重传次数。
2. **接入层**：LVS/Nginx/SLB 承担连接入口，配合连接速率限制和黑白名单。
3. **清洗层**：大流量攻击必须在高防、Anycast 或运营商侧清洗，否则源站带宽会先被打满。
4. **业务层**：控制连接总数、握手后认证、空闲超时和异常来源封禁，避免攻击从四层转成七层。

易错点：

1. `listen(backlog)` 主要控制全连接队列，不等于半连接队列的全部容量。
2. SYN Cookie 不是万能开关，攻击流量大到打满带宽时，内核参数没有机会发挥作用。
3. 只看 `ESTABLISHED` 连接数不够，SYN Flood 重点要看 `SYN_RECV`、重传、丢包和 backlog 溢出。
4. 真实攻击常混合 SYN Flood、ACK Flood、HTTP Flood，需要结合入口流量、连接状态和应用指标判断。

### UDP Flood

攻击者发送大量 UDP 包，消耗目标带宽、CPU 或 UDP 服务处理能力。因为 UDP 无连接，源地址也更容易伪造。

常见防护：

1. 限制异常 UDP 流量。
2. 对非业务端口直接丢弃。
3. 对业务 UDP 协议加入 token、cookie 或握手机制。
4. 通过高防、Anycast、运营商清洗扩展入口容量。

### 反射放大攻击

攻击者伪造目标 IP，向开放 DNS、NTP、SSDP、Memcached 等服务发请求，让这些服务把更大的响应打到目标。

防护不仅在受害方，也需要全网治理：

1. 服务提供方关闭开放递归或放大接口。
2. 网络运营方做源地址校验，例如 BCP 38。
3. 受害方接入清洗中心，过滤异常协议和异常响应。

### HTTP Flood / CC 攻击

攻击者模拟正常用户访问高消耗接口，例如登录、搜索、复杂查询、下单试算，使应用线程池、数据库或缓存被打满。

常见防护：

1. CDN/WAF 按 IP、账号、设备指纹、UA、路径限流。
2. 对高成本接口增加验证码、挑战、排队和熔断。
3. 静态内容缓存，动态接口做降级。
4. 识别异常行为序列，而不是只看单个请求。

## 3. 防护体系

DDoS 防护通常是分层的：

1. **网络入口层**：Anycast、高防 IP、运营商清洗、黑洞路由。
2. **四层层面**：SYN Cookie、连接数限制、速率限制、ACL。
3. **七层层面**：CDN、WAF、验证码、行为风控、接口级限流。
4. **应用架构层**：缓存、异步化、熔断、降级、容量隔离。
5. **监控响应层**：流量基线、QPS、连接状态、错误率、来源分布、自动封禁。

单机调参数不能解决大规模 DDoS。带宽被打满时，必须在流量进入机房或云主机之前清洗。

## 4. 真实场景

1. **静态站点**：优先接 CDN，源站隐藏真实 IP，只允许 CDN 回源。
2. **API 服务**：网关层做身份校验、限流、熔断和 WAF，后端按租户隔离容量。
3. **游戏服务**：UDP 协议需要设计连接验证和速率控制，避免被伪造源流量打穿。
4. **登录接口**：应用层 DDoS 常和撞库结合，需要验证码、设备指纹、账号维度限速和风控。

## 5. 易错点

1. DDoS 不只是“很多请求”，也可能是带宽、协议栈或应用依赖被耗尽。
2. HTTPS 不能天然防 DDoS，TLS 握手本身也会消耗 CPU。
3. 只按 IP 限流不够，攻击源可能非常分散，也可能来自代理和移动网络。
4. 应用层攻击看起来像正常请求，需要结合行为、成本和业务语义识别。
5. 源站 IP 暴露后，绕过 CDN 直打源站会让 CDN 防护失效。

## 6. 面试回答模板

DDoS 是分布式拒绝服务攻击，目标是耗尽带宽、连接表、协议栈资源或应用后端能力。它可以分为流量型、协议型和应用层攻击，例如 UDP Flood、SYN Flood、反射放大和 HTTP Flood。防护要分层做：入口用 Anycast、高防和运营商清洗；四层用 SYN Cookie、连接数和速率限制；七层用 CDN、WAF、验证码、行为风控和接口限流；应用内部要有缓存、熔断、降级和容量隔离。大流量攻击必须在上游清洗，不能只靠业务服务器硬抗。
