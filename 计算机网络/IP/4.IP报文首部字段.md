# 4. IP 报文首部字段

面试问“IP 协议头有多长”，通常默认指 IPv4 首部。IPv4 首部最小 20 字节，最大 60 字节；超过 20 字节的部分是 options。IPv6 基础首部固定 40 字节，扩展能力通过扩展首部表达。

## 1. IPv4 首部长度

IPv4 首部里有一个 IHL（Internet Header Length）字段，占 4 bit，单位是 4 字节：

```text
IPv4 header length = IHL * 4 bytes
```

因此：

1. IHL 最小为 5，对应 `5 * 4 = 20` 字节。
2. IHL 最大为 15，对应 `15 * 4 = 60` 字节。
3. 如果没有 IP options，常见 IPv4 首部就是 20 字节。

## 2. IPv4 核心字段

| 字段 | 作用 |
| --- | --- |
| Version | IP 版本，IPv4 为 4 |
| IHL | 首部长度，单位 4 字节 |
| DSCP/ECN | 服务质量和显式拥塞通知 |
| Total Length | IP 数据报总长度，包含 IP 首部和载荷 |
| Identification | 分片重组标识 |
| Flags | 分片控制，例如 DF、MF |
| Fragment Offset | 当前分片在原始数据报中的偏移 |
| TTL | 每经过一跳减 1，防止路由环路 |
| Protocol | 上层协议，例如 TCP=6、UDP=17、ICMP=1 |
| Header Checksum | IPv4 首部校验和 |
| Source Address | 源 IPv4 地址 |
| Destination Address | 目的 IPv4 地址 |
| Options | 可选字段，最多 40 字节 |

`Total Length` 是 16 bit，所以 IPv4 单个数据报理论最大长度是 65535 字节。真实网络中还受 MTU 限制，超过链路 MTU 可能触发分片或被丢弃。

## 3. IP 首部和 TCP/UDP 的关系

IP 是网络层，负责寻址和路由；TCP/UDP 是传输层，负责端到端进程通信。IP 首部通过 `Protocol` 字段告诉接收端应该把载荷交给哪个上层协议：

```text
IPv4 packet
  -> IP header: src ip, dst ip, ttl, protocol
  -> payload: TCP segment / UDP datagram / ICMP message
```

常见以太网 IPv4 + TCP 无 option 场景：

```text
MTU = 1500
IPv4 header = 20
TCP header = 20
TCP MSS = 1460
```

如果 IP 或 TCP 携带 options，可用载荷会变小。

## 4. IPv6 首部对比

IPv6 基础首部固定 40 字节，核心字段包括 Version、Traffic Class、Flow Label、Payload Length、Next Header、Hop Limit、源地址和目的地址。

和 IPv4 的主要差异：

1. IPv6 基础首部不含首部校验和，减少路由器处理成本。
2. IPv6 中间路由器不做分片，路径 MTU 问题由源主机处理。
3. IPv6 用 Next Header 串联 TCP、UDP、ICMPv6 或扩展首部。
4. IPv6 地址是 128 bit，源/目的地址字段明显更大。

## 5. 易错点

1. IPv4 首部最小 20 字节，不是固定 20 字节；有 options 时会变长。
2. IPv4 `Total Length` 包含 IP 首部，UDP Length 包含 UDP 首部和数据，TCP 没有应用消息长度字段。
3. TTL 不是按秒递减，现代网络中主要按路由跳数递减。
4. IPv4 首部校验和只校验 IP 首部，不校验 TCP/UDP 数据。
5. 路由器转发时会修改 TTL，并重新计算 IPv4 首部校验和。

## 6. 面试回答模板

IPv4 首部最小 20 字节，最大 60 字节，长度由 IHL 字段表示，单位是 4 字节。核心字段包括版本、首部长度、总长度、分片标识、DF/MF、分片偏移、TTL、Protocol、首部校验和、源 IP 和目的 IP。`Protocol` 用来区分 TCP、UDP、ICMP 等上层协议。IPv6 基础首部固定 40 字节，中间路由器不分片，也没有 IPv4 那样的首部校验和。回答时要把 IP 首部长度、链路 MTU、TCP MSS 区分开。
