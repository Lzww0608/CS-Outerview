# 3. TTL 与缓存过期

TTL 是 Time To Live 的缩写，在不同场景含义不同。面试里需要先说明上下文：IP 包里的 TTL 是跳数限制，DNS、缓存、Redis 里的 TTL 是时间过期。

## IP TTL

IP 头部中的 TTL 用来防止报文在路由环路中无限转发。每经过一个三层路由器，TTL 减 1；减到 0 时路由器丢弃该包，并通常返回 ICMP Time Exceeded。

```text
源主机 TTL=64
-> 第 1 跳 TTL=63
-> 第 2 跳 TTL=62
...
-> TTL=0 时丢弃
```

`traceroute` 正是利用这个机制：从 TTL=1 开始逐步增大 TTL，让路径上的路由器依次返回 ICMP 超时消息，从而推断路径。

注意：

1. IP TTL 不是按秒扣减，现代网络中主要按跳数递减。
2. 不同操作系统默认初始 TTL 不同，常见如 Linux 64、Windows 128。
3. NAT 通常会改写地址和端口，但不改变 TTL 语义。

## DNS TTL

DNS 记录中的 TTL 表示解析结果可以被缓存多久。TTL 长，缓存命中高、权威 DNS 压力低，但故障切换和域名变更生效慢；TTL 短，切换更快，但递归 DNS 和权威 DNS 压力更大。

工程上常见做法：

1. 业务稳定期使用较长 TTL。
2. 迁移、灰度、故障切换前提前把 TTL 调短。
3. 变更完成并稳定后再把 TTL 调回较长值。
4. 注意部分客户端和递归 DNS 不一定严格遵守很短 TTL。

## 缓存和 Redis TTL

缓存 TTL 表示 key 的过期时间。它用于控制数据新鲜度、释放内存、防止脏数据长期存在。

常见策略：

1. **固定过期**：写入后固定 N 秒过期，简单但可能造成同一批 key 同时失效。
2. **随机抖动**：在基础 TTL 上加随机值，缓解缓存雪崩。
3. **滑动过期**：每次访问后续期，适合会话类数据。
4. **逻辑过期**：key 不直接删除，而是在值里记录过期时间，由后台异步刷新热点数据。

Redis TTL 还要注意：

1. `EXPIRE key seconds` 设置秒级过期，`PEXPIRE` 设置毫秒级过期。
2. `TTL key` 返回剩余秒数，`-1` 表示存在但未设置过期，`-2` 表示 key 不存在。
3. Redis 通过惰性删除和定期删除组合清理过期 key。
4. 大量 key 同时过期可能造成 CPU 抖动和缓存击穿，需要加随机过期或预热。

## 面试回答模板

TTL 要看语境。IP TTL 是跳数限制，每过一个路由器减 1，减到 0 丢弃，用来避免路由环路，traceroute 利用了这个机制。DNS TTL 和缓存 TTL 是时间过期，用来控制缓存结果能保存多久。工程上 TTL 要在命中率、故障切换速度、数据新鲜度和缓存雪崩风险之间权衡。
