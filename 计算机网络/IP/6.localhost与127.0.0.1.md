# 6. localhost 与 127.0.0.1 的区别

`localhost` 和 `127.0.0.1` 都常用于访问本机服务，但它们不是同一个层面的概念。

## 1. 基本定义

`127.0.0.1` 是 IPv4 loopback 地址，属于 `127.0.0.0/8` 回环网段。发往该地址的数据包不会从物理网卡发出，而是在本机网络协议栈内部回环。

`localhost` 是主机名，不是 IP 地址。它需要经过名称解析，通常在 hosts 文件中映射到回环地址：

```text
127.0.0.1       localhost
::1             localhost
```

因此访问 `localhost` 时，系统可能解析到 IPv4 的 `127.0.0.1`，也可能解析到 IPv6 的 `::1`，取决于 hosts 配置、DNS/解析顺序和应用是否优先使用 IPv6。

## 2. 主要区别

| 对比项 | localhost | 127.0.0.1 |
| --- | --- | --- |
| 类型 | 主机名 | IPv4 地址 |
| 是否需要解析 | 需要 hosts/DNS 解析 | 不需要名称解析 |
| 可能结果 | `127.0.0.1` 或 `::1` | 固定 IPv4 loopback |
| 受配置影响 | 受 hosts、解析顺序、IPv6 影响 | 基本不受 hosts 影响 |
| 常见问题 | 服务只监听 IPv4 时，localhost 解析到 `::1` 可能连接失败 | 服务监听在 IPv6 时，用 127.0.0.1 可能连不上 |

## 3. 和 0.0.0.0 的区别

`127.0.0.1` 表示只通过本机回环访问。服务如果只绑定 `127.0.0.1:8080`，通常只有本机能访问。

`0.0.0.0` 用在服务端监听时表示绑定所有 IPv4 网卡地址，包括 `127.0.0.1`、局域网地址和公网地址。它不是一个应该被客户端当目标访问的普通地址。

示例：

```bash
# 只允许本机访问
server --host 127.0.0.1 --port 8080

# 允许其他机器通过本机网卡 IP 访问
server --host 0.0.0.0 --port 8080
```

## 4. 真实排查场景

1. 服务监听 `127.0.0.1:3306`，远程机器无法访问，这是绑定地址限制，不是防火墙一定有问题。
2. 浏览器访问 `localhost:8000` 失败，但 `127.0.0.1:8000` 成功，可能是 `localhost` 优先解析到 `::1`，而服务只监听 IPv4。
3. 容器内访问 `127.0.0.1` 指的是容器自身，不是宿主机；访问宿主机要用宿主机网关地址或 Docker 提供的特殊域名。
4. hosts 文件被错误修改时，`localhost` 可能解析异常；直接访问 `127.0.0.1` 可以绕过主机名解析做对照。
5. 用 `curl -4 localhost` 和 `curl -6 localhost` 可以区分 IPv4/IPv6 解析和监听问题。

## 5. 面试回答模板

`127.0.0.1` 是 IPv4 回环地址，数据包不会经过物理网卡；`localhost` 是主机名，需要经过 hosts 或 DNS 解析，通常映射到 `127.0.0.1` 和 `::1`。所以二者大多数情况下效果相同，但 `localhost` 可能受解析顺序和 IPv6 影响。服务只监听 IPv4 时，`localhost` 如果解析到 `::1` 可能连接失败；服务绑定 `127.0.0.1` 只允许本机访问，绑定 `0.0.0.0` 才表示监听所有 IPv4 网卡。
