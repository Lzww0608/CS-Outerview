# 2. IP 分片与 MTU

IP 分片是网络层在数据报长度超过链路 MTU 时，把一个 IP 数据报拆成多个较小分片传输的机制。面试里通常会把它和 UDP 最大报文长度、TCP MSS、路径 MTU 发现一起考。

## 1. MTU 是什么

MTU（Maximum Transmission Unit）表示某条链路一次能承载的最大网络层数据报长度。以太网常见 MTU 是 1500 字节，表示一个 IP 包最多 1500 字节，不包含以太网帧头尾。

如果应用层写入的数据太大，最终会发生两类切分：

1. **传输层切分**：TCP 会按 MSS 把字节流拆成多个 TCP segment。
2. **网络层分片**：IP 数据报超过下一跳链路 MTU 时被拆成多个 IP fragment。

工程上更希望在传输层或应用层控制报文大小，尽量避免 IP 分片。

## 2. IPv4 分片原理

IPv4 头部里和分片相关的字段包括：

| 字段 | 作用 |
| --- | --- |
| Identification | 同一个原始 IP 数据报的所有分片使用相同 ID |
| DF | Don't Fragment，置 1 表示不允许中间路由器分片 |
| MF | More Fragments，置 1 表示后面还有分片 |
| Fragment Offset | 当前分片在原始数据报中的偏移，单位是 8 字节 |

接收端根据 `src_ip + dst_ip + protocol + identification` 把分片归并起来，再按 offset 重组原始 IP 数据报。除了最后一个分片，其余分片的数据长度通常必须是 8 字节的整数倍。

如果任意一个分片丢失，整个原始数据报都无法重组成功，只能等待超时后丢弃。

## 3. IPv4 和 IPv6 的区别

IPv4 中，中间路由器可以在允许分片时对数据报分片；如果设置 DF 且报文超过 MTU，路由器会丢弃报文并返回 ICMP `Fragmentation Needed`。

IPv6 中，中间路由器不负责分片，只能由源主机分片。路径上如果报文过大，路由器返回 ICMPv6 `Packet Too Big`，源主机根据路径 MTU 重新调整发送大小。

这也是路径 MTU 发现（PMTUD）的核心：发送端逐步发现一条路径上可用的最大报文长度，避免中间设备分片。

## 4. TCP MSS 和 IP 分片的关系

MSS（Maximum Segment Size）是 TCP 单个报文段中应用数据的最大长度，不包含 TCP 头和 IP 头。常见以太网场景下：

```text
MTU = 1500
IPv4 header = 20
TCP header = 20
MSS = 1500 - 20 - 20 = 1460
```

TCP 会在三次握手的 SYN 报文中通过 MSS option 协商对端可接收的最大 segment 大小。协商 MSS 的目的就是让 TCP segment 加上 IP 头后尽量不超过路径 MTU。

注意：应用层调用一次 `send()` 不等于发出一个 TCP 报文。TCP 是字节流协议，内核可能把数据拆成多个 MSS 大小的 segment，也可能合并小写入。

## 5. UDP 和分片

UDP 保留报文边界，但协议本身不会像 TCP 那样按 MSS 做可靠切分。如果一个 UDP datagram 很大，它只能依赖 IP 层分片。

例如无 IP options 的 IPv4 下：

```text
最大 IP 数据报 = 65535 字节
IPv4 header = 20 字节
UDP header = 8 字节
最大 UDP payload = 65535 - 20 - 8 = 65507 字节
```

这个值只是理论上限。真实公网传输中，大 UDP 包一旦分片，任意分片丢失都会导致整个 UDP datagram 丢失，而且很多 NAT、防火墙和负载均衡设备对分片包支持并不好。

QUIC 通常把初始 UDP datagram 控制在 1200 字节左右，就是为了减少路径 MTU 和分片问题。

## 6. 为什么要避免 IP 分片

1. **丢包放大**：一个分片丢失，整个原始数据报都失败。
2. **重组成本高**：接收端需要缓存分片并等待重组，容易被分片攻击消耗内存。
3. **中间设备兼容性差**：NAT、防火墙、负载均衡可能丢弃或错误处理分片。
4. **排障困难**：应用只看到请求超时，很难直接判断是路径 MTU、ICMP 被拦截还是中间设备问题。
5. **安全风险**：历史上存在重叠分片、Tiny Fragment 等绕过安全设备检测的攻击手法。

## 7. 真实场景

1. **TCP 服务**：依赖 MSS、PMTUD 和内核协议栈控制报文大小，业务层通常不需要手动分片。
2. **UDP 服务**：应用层主动限制包大小，必要时自己设计分片、序号、重传和重组。
3. **VPN/隧道**：封装会额外增加头部，真实可用 MTU 会变小，常见问题是隧道内大包黑洞。
4. **云原生网络**：VXLAN、IPIP、GRE 等封装会降低有效 MTU，Kubernetes 跨节点网络要统一规划 MTU。

## 8. 易错点

1. UDP 最大 payload 理论上接近 64KB，但工程上不建议直接发送这么大的 UDP 包。
2. TCP 没有“消息长度”，只有字节流；MSS 是 TCP segment 数据部分上限，不是应用消息上限。
3. MTU 是链路层约束，MSS 是传输层约束，二者不是同一个概念。
4. IPv6 路由器不做中间分片，必须依赖源主机分片和路径 MTU 发现。
5. 禁 ICMP 可能导致 PMTUD 失效，表现为小包正常、大包超时。

## 9. 面试回答模板

IP 分片是当 IP 数据报超过链路 MTU 时，把一个数据报拆成多个 fragment 传输，接收端再根据 Identification、MF 和 Fragment Offset 重组。IPv4 中路由器可以分片，但设置 DF 后会丢包并返回 ICMP；IPv6 中中间路由器不分片，只返回 Packet Too Big，由源主机调整。工程上要尽量避免分片，因为任意分片丢失会导致整个报文失败，重组也有缓存和安全成本。TCP 通过 MSS 和路径 MTU 发现控制 segment 大小；UDP 需要应用层主动控制报文大小，公网通常会把 UDP 包控制在 MTU 以内。
