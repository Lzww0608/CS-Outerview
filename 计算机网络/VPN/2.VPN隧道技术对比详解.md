# VPN 隧道技术对比详解

## 一、隧道技术概述

### 1.1 隧道协议分层

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  OSI 模型与隧道协议：                                      │
│                                                             │
│  ┌───────────────┐                                        │
│  │    应用层     │  TLS VPN (HTTPS)                       │
│  ├───────────────┤                                        │
│  │    传输层     │  OpenVPN (SSL/TLS)                     │
│  ├───────────────┤                                        │
│  │    网络层      │  IPsec, WireGuard                      │
│  ├───────────────┤                                        │
│  │    数据链路层  │  L2TP, PPTP                            │
│  └───────────────┘                                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 二、PPTP

### 2.1 原理

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  PPTP 架构：                                               │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐  │
│  │              GRE (Generic Routing Encapsulation)      │  │
│  │              封装 PPP 帧到 IP 包                       │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
│  PPP 帧可承载：                                            │
│  • PAP/CHAP 认证                                          │
│  • MPPE 加密（40-128位 RC4）                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 缺点与淘汰

| 缺点 | 说明 |
|------|------|
| 安全性低 | MPPE 有已知漏洞 |
| 防火墙难穿透 | 使用 GRE 协议（IP 47） |
| 被墙率高 | 协议特征明显 |
| 仅支持 IPV4 | 无法用于 IPv6 |

---

## 三、L2TP/IPsec

### 3.1 原理

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  L2TP/IPsec 架构：                                        │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐  │
│  │                    IP Header                         │  │
│  ├─────────────────────────────────────────────────────┤  │
│  │                IPsec (ESP) Header                    │  │
│  ├─────────────────────────────────────────────────────┤  │
│  │                    L2TP Header                       │  │
│  ├─────────────────────────────────────────────────────┤  │
│  │                    PPP Frame                         │  │
│  ├─────────────────────────────────────────────────────┤  │
│  │                    Payload                           │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
│  工作流程：                                                │
│  1. L2TP 建立隧道                                        │
│  2. IPsec 加密整个 L2TP 隧道                            │
│  3. 双重封装确保安全                                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 配置示例

```bash
# Linux L2TP/IPsec 配置
# /etc/ipsec.conf
conn %default
    ikelifetime=60m
    keylife=20m
    esp=aes256-sha2_256

conn myvpn
    authby=secret
    auto=add
    keyexchange=ikev2
    type=tunnel
    left=公网IP
    leftsubnet=0.0.0.0/0
    right=VPN服务器IP
    rightsubnet=192.168.1.0/24
```

### 3.3 L2TP/IPsec 优缺点

| 优点 | 缺点 |
|------|------|
| 跨平台支持好 | 配置复杂 |
| 穿透性好（UDP 500/4500） | 需要防火墙打开多个端口 |
| 安全性高（IPsec） | 无法伪装成 HTTPS |
| 原生系统支持 | 性能一般 |

## 四、IPsec

### 4.1 两种模式

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  传输模式（Transport Mode）：                             │
│  ┌─────────────────────────────────────────────────────┐  │
│  │  IP Header  │  AH/ESP  │  TCP  │  Data           │  │
│  └─────────────────────────────────────────────────────┘  │
│  只加密数据，IP 头不变                                      │
│                                                             │
│  隧道模式（Tunnel Mode）：                                 │
│  ┌─────────────────────────────────────────────────────┐  │
│  │ New IP │ ESP │ Original IP │ TCP │ Data │ ESP T/A │  │
│  └─────────────────────────────────────────────────────┘  │
│  整个原始包都加密和认证                                    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 IKEv2 密钥交换

```c
// IKEv2 握手流程

// 阶段 1：建立 IKE SA
Client ──► HDR, SAi1, KEi, Ni ──► Server
Client ◄── HDR, SAr1, KEr, Nr, [CERTREQ] ◄── Server

// 阶段 2：认证
Client ── ► HDR, IDi, CERT, AUTH, SAi2, TSi, TSr ──► Server
Client ◄── HDR, IDr, CERT, AUTH, SAr2, TSi, TSr ◄── Server

// 结果：建立双向 SA
```

### 4.3 IPsec 优缺点

| 优点 | 缺点 |
|------|------|
| 安全性极高（军事级） | 配置复杂 |
| 性能好 | 防火墙穿透需特殊配置 |
| 网络层透明 | 被墙风险中等 |
| 完整性+加密 | 不支持流量混淆 |

## 五、OpenVPN

### 5.1 原理

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  OpenVPN 架构：                                           │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐  │
│  │              OpenVPN 隧道（SSL/TLS）                 │  │
│  │                                                      │  │
│  │  TLS Record: {HMAC | IV | Encrypted | MAC}         │  │
│  │                                                      │  │
│  └─────────────────────────────────────────────────────┘  │
│           │                                                  │
│  ┌────────┴────────┐                                     │
│  │ TCP (443)       │ UDP (1194)                         │
│  │ 稳定、可穿透     │ 高速                                │
│  └─────────────────┘                                     │
│                                                             │
│  使用 TUN/TAP 虚拟网卡                                    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 配置示例

```bash
# OpenVPN 服务端配置
port 1194
proto udp
dev tun

# 证书
ca ca.crt
cert server.crt
key server.key
dh dh.pem

# 网段
server 10.8.0.0 255.255.255.0

# 推送路由
push "route 192.168.1.0 255.255.255.0"

# 加密
cipher AES-256-GCM
auth SHA256

# 持久化
persist-key
persist-tun
status openvpn-status.log
verb 3
```

```bash
# OpenVPN 客户端配置
client
dev tun
proto udp
remote vpn.example.com 1194
resolv-retry infinite
nobind

# 证书
ca ca.crt
cert client.crt
key client.key

# 加密
cipher AES-256-GCM
auth SHA256

# 重连
persist-key
persist-tun
```

### 5.3 OpenVPN 优缺点

| 优点 | 缺点 |
|------|------|
| 跨平台（Win/Mac/Linux/Android/iOS） | 性能一般 |
| SSL 伪装（443 端口） | 配置复杂 |
| 生态成熟 | 单线程性能 |
| 可靠性高 | - |

## 六、WireGuard

### 6.1 原理

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  WireGuard 架构：                                          │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐  │
│  │              WireGuard 协议                         │  │
│  │                                                      │  │
│  │  数据包: {Header | Encrypt | Poly1305}              │  │
│  │                                                      │  │
│  │  Header: {Receiver, Counter, 0}                    │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
│  密钥交换：Curve25519                                      │
│  加密：ChaCha20-Poly1305                                  │
│  哈希：BLAKE2s                                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 配置示例

```bash
# WireGuard 服务端 /etc/wireguard/wg0.conf
[Interface]
PrivateKey = <server_private_key>
Address = 10.0.0.1/24
ListenPort = 51820

# NAT 转发
PostUp = iptables -t nat -A POSTROUTING -s 10.0.0.0/24 -j MASQUERADE
PostDown = iptables -t nat -D POSTROUTING -s 10.0.0.0/24 -j MASQUERADE

[Peer]
PublicKey = <client_public_key>
AllowedIPs = 10.0.0.2/32

# 客户端配置
[Interface]
PrivateKey = <client_private_key>
Address = 10.0.0.2/24

[Peer]
PublicKey = <server_public_key>
Endpoint = vpn.example.com:51820
AllowedIPs = 0.0.0.0/0  # 全流量代理
PersistentKeepalive = 25
```

### 6.3 WireGuard 优缺点

| 优点 | 缺点 |
|------|------|
| 性能极高（内核级） | 生态较新 |
| 代码简洁（~4000 行） | 企业功能较少 |
| 配置极其简单 | 无法伪装成 HTTPS |
| 安全性高 | - |

## 十、面试常见问题

### Q1: 为什么 PPTP 被淘汰？

PPTP 使用 MPPE 加密，存在已知漏洞（如 MS-CHAPv2 容易被破解）；协议特征明显，容易被防火墙识别和阻断。

### Q2: WireGuard 为什么这么快？

1. 内核级实现（减少上下文切换）
2. 现代加密算法（ChaCha20 软件实现高效）
3. 无状态包处理（不需要维护连接状态）
4. 代码简洁（减少开销）

### Q3: TLS VPN 为什么穿透性最好？

TLS VPN 使用标准 HTTPS（443 端口），流量与正常 Web 流量无法区分，防火墙通常放行。

### Q4: 如何选择 VPN 协议？

1. 追求性能 → WireGuard
2. 企业安全 → IPsec
3. 高度审查网络 → TLS VPN
4. 跨平台兼容 → OpenVPN
