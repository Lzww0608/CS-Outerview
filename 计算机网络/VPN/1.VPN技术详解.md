# VPN 技术详解

## 一、VPN 概述

### 1.1 什么是 VPN

VPN（Virtual Private Network，虚拟专用网络）通过公网建立加密隧道，让用户像在私有网络一样安全地访问远程资源。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  VPN 核心原理：                                           │
│                                                             │
│  用户 ──► 加密隧道 ──► VPN 服务器 ──► 目标服务器         │
│           (公网)          │                                │
│                        解密转发                            │
│                                                             │
│  效果：用户感觉像在局域网内访问                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 二、VPN 核心技术

### 2.1 隧道技术

| 隧道协议 | 工作层 | 特点 |
|----------|--------|------|
| PPTP | L2TP | 简单但安全性低，已淘汰 |
| L2TP/IPsec | L2 | 需配合 IPsec |
| IPsec | L3 | 安全性高，配置复杂 |
| OpenVPN | L4 | 跨平台，SSL-based |
| WireGuard | L3 | 现代协议，高性能 |
| TLS VPN | L4 | HTTPS 伪装 |

### 2.2 隧道模式

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  隧道模式对比：                                            │
│                                                             │
│  传输模式（Transport Mode）：                              │
│  ┌─────────────────────────────────────────────────────┐  │
│  │  IP Header │ ESP Header │ Data │ ESP Trailer │ Auth │  │
│  └─────────────────────────────────────────────────────┘  │
│  只加密数据，IP 头不变                                    │
│                                                             │
│  隧道模式（Tunnel Mode）：                                 │
│  ┌─────────────────────────────────────────────────────┐  │
│  │ New IP │ ESP │ IP Header │ Data │ ESP Trailer │ Auth │  │
│  └─────────────────────────────────────────────────────┘  │
│  整个原始 IP 包都加密                                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 三、IPsec 协议

### 3.1 IPsec 架构

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  IPsec 协议栈：                                           │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐  │
│  │                  应用层                              │  │
│  ├─────────────────────────────────────────────────────┤  │
│  │         AH (Authentication Header)                  │  │
│  │         ESP (Encapsulating Security Payload)        │  │
│  ├─────────────────────────────────────────────────────┤  │
│  │               IKE (Internet Key Exchange)          │  │
│  ├─────────────────────────────────────────────────────┤  │
│  │               IP Layer                             │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 AH 与 ESP

| 协议 | 功能 | 加密 | 认证 |
|------|------|------|------|
| AH | 完整性校验 | 否 | 是 |
| ESP | 加密+认证 | 是 | 是 |

```c
// AH 头结构
struct AHHeader {
    uint8_t  next_header;    // 下一个头
    uint8_t  payload_len;    // 负载长度
    uint16_t reserved;       // 保留
    uint32_t spi;            // 安全参数索引
    uint32_t sequence;       // 序列号
    uint8_t  icv[];         // 完整性校验值
};

// ESP 头结构
struct ESPHeader {
    uint32_t spi;            // 安全参数索引
    uint32_t sequence;       // 序列号
    uint8_t  iv[];           // 初始化向量
};
```

### 3.3 IKE 密钥交换

```c
// IKEv2 密钥交换流程

// 1. 初始交换（IKE_SA_INIT）
Client ──► SAi1, KEi, Ni ──► Server
Client ◄── SAr1, KEr, Nr, [CERTREQ] ◄── Server

// 2. 认证交换（IKE_AUTH）
Client ──► {IDi, [CERT], [IDr]} Auth, SAi2, TSi, TSr ──► Server
Client ◄── {IDr, [CERT]} Auth, SAr2, TSi, TSr ◄── Server

// 3. 结果
// - 建立 IKE SA（控制平面）
// - 建立 Child SA（数据平面）
// - 交换加密密钥材料
```

### 4.2 OpenVPN 配置

```bash
# 服务端配置
port 1194
proto udp
dev tun

# 证书和密钥
ca ca.crt
cert server.crt
key server.key
dh dh.pem

# VPN 网段
server 10.8.0.0 255.255.255.0

# 推送路由
push "route 192.168.1.0 255.255.255.0"

# 加密算法
cipher AES-256-GCM
auth SHA256

# 持久化密钥
persist-key
persist-tun
```

```bash
# 客户端配置
client
dev tun
proto udp
remote vpn.example.com 1194

# 证书
ca ca.crt
cert client.crt
key client.key

# 加密
cipher AES-256-GCM
auth SHA256
```

## 五、WireGuard

### 5.1 WireGuard 特点

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  WireGuard 优势：                                          │
│                                                             │
│  1. 现代化设计                                             │
│     • 代码量少（~4000行）                                  │
│     • 审计友好                                             │
│     • 无历史包袱                                          │
│                                                             │
│  2. 高性能                                                │
│     • 基于 ChaCha20-Poly1305                             │
│     • 低延迟                                              │
│     • 内核级实现                                          │
│                                                             │
│  3. 简洁配置                                              │
│     • 类似 SSH 的密钥配置                                 │
│     • 无需复杂 PKI                                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 WireGuard 配置

```bash
# 服务端配置 (/etc/wireguard/wg0.conf)
[Interface]
PrivateKey = <server_private_key>
Address = 10.0.0.1/24
ListenPort = 51820
PostUp = iptables -A FORWARD -i wg0 -j ACCEPT
PostDown = iptables -D FORWARD -i wg0 -j ACCEPT

# 客户端公钥和允许的 IP
[Peer]
PublicKey = <client_public_key>
AllowedIPs = 10.0.0.2/32
```

```bash
# 客户端配置
[Interface]
PrivateKey = <client_private_key>
Address = 10.0.0.2/24
DNS = 8.8.8.8

[Peer]
PublicKey = <server_public_key>
Endpoint = vpn.example.com:51820
AllowedIPs = 0.0.0.0/0  # 流量走 VPN
PersistentKeepalive = 25  # 保持连接
```

### 5.3 WireGuard 加密

```c
// WireGuard 使用的加密算法

// 1. 密钥交换：Curve25519
//    - 椭圆曲线 Diffie-Hellman
//    - 足够安全且高效

// 2. 对称加密：ChaCha20-Poly1305
//    - 流加密 + 认证
//    - 针对移动设备优化

// 3. 哈希：BLAKE2s
//    - 哈希和 HMAC

// 4. HKDF
//    - 从 DH 输出派生会话密钥
```

## 八、面试常见问题

### Q1: VPN 和代理的区别？

VPN 在网络层工作，处理所有流量；代理在应用层，只处理特定应用流量。VPN 提供完整隧道，代理只转发特定请求。

### Q2: WireGuard 为什么比 OpenVPN 快？

WireGuard 使用 ChaCha20-Poly1305（软件实现高效）、内核级集成、无状态包处理、内核模块而非用户空间。

### Q3: 如何穿透防火墙？

1. 使用 443 端口（HTTPS 伪装）
2. TLS VPN（伪装成正常 HTTPS 流量）
3. 协议混淆

### Q4: VPN 的安全性如何保证？

1. 强加密算法（AES-256、ChaCha20）
2. 完美前向保密（PFS）
3. 证书认证
4. 定期密钥轮换

## 九、总结

1. **VPN 核心**：加密隧道、公网建立私有网络
2. **隧道技术**：IPsec、OpenVPN、WireGuard
3. **IPsec**：AH（认证）+ ESP（加密）+ IKE（密钥交换）
4. **WireGuard**：ChaCha20 + Curve25519，现代高性能
5. **选择建议**：企业用 IPsec，个人用 WireGuard，受限网络用 TLS VPN
