### 4.2 HTTP/3 (QUIC)

```c
// QUIC 协议优势（相比 TCP+TLS）

// HTTP/1.1 + TLS
// 握手：TCP 三次握手 + TLS 1.2 握手 = 2-3 RTT

// HTTP/2 + TLS 1.3
// 握手：TCP 三次握手 + TLS 1.3 0-RTT/1-RTT = 1-2 RTT

// HTTP/3 (QUIC)
// 握手：QUIC 0-RTT/1-RTT = 0-1 RTT

// QUIC 优势
// 1. 0-RTT 快速恢复
// 2. 独立流控制（不因单一流阻塞）
// 3. 连接迁移（切换网络 IP 不变）
```

### 4.3 TLS 1.3 优化

## 五、传输层优化

### 5.1 TCP 优化策略

```c
// Linux TCP 优化参数

// 1. 拥塞控制算法选择
sysctl -w net.ipv4.tcp_congestion_control=bbr

// 2. 扩大连接队列
sysctl -w net.core.somaxconn=65535
sysctl -w net.ipv4.tcp_max_syn_backlog=65535

// 3. TCP Fast Open
sysctl -w net.ipv4.tcp_fastopen=3

// 4. 窗口扩大
sysctl -w net.ipv4.tcp_window_scaling=1
sysctl -w net.core.rmem_max=16777216
sysctl -w net.core.wmem_max=16777216
```

### 5.2 BBR 拥塞控制

```c
// BBR vs CUBIC 对比

// BBR 原理
// - 不丢包作为拥塞信号
// - 实时探测带宽和延迟
// - 最大化带宽利用率

// 适用场景
// - 高带宽高延迟网络
// - 长肥管道（LFN）
// - 跨洲际传输

// 启用方法
echo "bbr" > /proc/sys/net/ipv4/tcp_congestion_control
```

## 十一、面试常见问题

### Q1: CDN 的工作原理？

用户请求时，DNS 调度到最近边缘节点；边缘节点检查缓存，有则直接返回，无则回源拉取并缓存。

### Q2: HTTP/2 和 HTTP/3 的区别？

HTTP/2 基于 TCP，有队头阻塞问题；HTTP/3 基于 QUIC（UDP），无队头阻塞，支持 0-RTT。

### Q3: BBR 和 CUBIC 的区别？

CUBIC 以丢包为拥塞信号，适合低延迟网络；BBR 以实时带宽探测为依据，适合高带宽高延迟网络。

### Q4: 预加载和预取的区别？

预加载（preload）强制浏览器下载当前页面必需资源；预取（prefetch）提示浏览器下载可能需要的未来资源。
