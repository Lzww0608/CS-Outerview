# 1. CDN 加速原理

CDN（Content Delivery Network，内容分发网络）是在离用户更近的边缘节点缓存和分发内容的系统。它的核心目标是减少用户到源站的网络距离、降低源站压力，并提升静态资源、大文件、音视频和部分动态接口的访问稳定性。

## 1. CDN 为什么能加速

CDN 加速不是单一技术，而是 DNS 调度、边缘缓存、连接复用、协议优化和回源控制共同作用。

主要原因：

1. **就近访问**：用户请求被调度到距离近、链路质量好的边缘节点，RTT 更低。
2. **缓存命中**：静态资源在边缘节点命中后，不需要回源站读取，减少跨地域传输。
3. **降低源站压力**：大量请求在边缘消化，源站只处理未命中、刷新、动态请求和回源请求。
4. **链路优化**：CDN 厂商通常有更好的跨运营商网络、专线、BGP 调度和拥塞避让能力。
5. **协议层优化**：边缘节点可以复用到源站的长连接，支持 HTTP/2、HTTP/3、TLS 会话复用、Brotli/Gzip 压缩等。

简化流程：

```text
用户访问 www.example.com/static/a.js
  -> DNS/CNAME 调度到 CDN 域名
  -> CDN 根据用户 IP、运营商、节点负载选择边缘节点
  -> 用户连接边缘节点
  -> 边缘命中缓存则直接返回
  -> 未命中则回源拉取，缓存后再返回给用户
```

## 2. DNS 调度和全局负载均衡

业务接入 CDN 后，通常会把业务域名配置成 CNAME：

```text
www.example.com -> www.example.com.cdnvendor.com
```

用户解析域名时，CDN 的 DNS 或全局负载均衡系统会根据用户来源和节点状态返回合适的边缘 IP。

调度因素包括：

1. 用户 Local DNS 或 EDNS Client Subnet 暴露出的地理位置。
2. 用户运营商和网络出口。
3. 边缘节点健康状态、负载、水位和带宽。
4. 缓存命中率、回源链路质量和故障切换策略。
5. 灰度、区域封禁、成本控制等业务规则。

易错点：DNS 调度不是每次 HTTP 请求都重新选择节点。DNS 结果会被 Local DNS、操作系统、浏览器和应用缓存，TTL 太长会降低故障切换速度，TTL 太短会增加解析压力。

## 3. 缓存命中和回源

CDN 的核心收益来自缓存命中。边缘节点通常根据 URL、请求头、查询参数、Cookie 和缓存规则生成 cache key。

常见缓存控制：

1. **HTTP 头**：`Cache-Control`、`Expires`、`ETag`、`Last-Modified`。
2. **强制缓存规则**：按路径、文件后缀、状态码设置 TTL。
3. **忽略参数**：图片资源可能忽略无关 query，提升命中率。
4. **刷新和预热**：发布新资源后主动刷新旧缓存，或提前把热点资源推到边缘。
5. **回源合并**：多个用户同时请求同一个未命中资源时，只让一个请求回源，其余等待结果，避免源站被击穿。

静态资源常用“文件名带 hash + 长 TTL”：

```text
app.4f8a91c2.js
```

内容变化后文件名变化，旧资源可长期缓存，新资源天然不会被旧缓存污染。

## 4. 动态内容能不能走 CDN

CDN 不只服务静态文件。动态内容也可以通过以下方式获益：

1. **动态加速**：不缓存响应体，但优化用户到边缘、边缘到源站的链路。
2. **边缘 TLS 终止**：用户和 CDN 建立就近 TLS，CDN 到源站复用长连接。
3. **边缘计算**：在边缘做鉴权、重写、A/B 分流、图片处理、轻量 API 聚合。
4. **短 TTL 缓存**：对热点但容忍短暂延迟的数据缓存几秒，例如榜单、配置、公开详情页。

动态接口要特别关注权限和个性化内容。带用户身份的响应如果错误地按 URL 缓存，可能造成数据泄露。

## 5. 易错点

1. CDN 命中缓存不代表源站不会被打。缓存穿透、首次冷启动、刷新风暴和热点大文件都可能打满回源。
2. CDN 加速主要降低网络和源站压力，不会让源站慢 SQL 或业务计算本身变快。
3. `Cache-Control: no-store` 通常禁止缓存，`no-cache` 表示使用前要再验证，不是完全不缓存。
4. 带 Cookie、Authorization 或个性化 query 的请求要谨慎缓存。
5. HTTPS 场景要配置证书、SNI、回源协议和 HSTS，边缘解密后到源站是否再加密取决于安全要求。
6. 大文件分发要支持 Range 请求，否则断点续传和拖拽播放体验会很差。

## 6. 真实场景

1. **前端静态资源**：JS/CSS/图片使用 hash 文件名和长 TTL，发布时只更新 HTML 引用。
2. **对象存储下载**：用户下载大文件时走 CDN，源站或对象存储只承担回源流量。
3. **图片服务**：边缘节点根据参数裁剪、压缩、WebP/AVIF 转码，降低客户端流量。
4. **直播和点播**：边缘节点缓存分片，使用多级缓存和回源调度降低卡顿。
5. **API 动态加速**：跨地域用户访问时，边缘到源站走优化链路，并复用连接减少握手成本。

## 7. 面试回答模板

CDN 能加速主要是因为把内容缓存到离用户更近的边缘节点，并通过 DNS/GSLB 把用户调度到合适节点。用户请求静态资源时，如果边缘缓存命中，就不用跨地域访问源站，RTT 更低、源站压力更小；未命中时边缘再回源拉取并缓存。CDN 还会做链路优化、连接复用、TLS 会话复用、压缩和回源合并。实际使用时要注意 cache key、TTL、刷新预热、权限内容缓存、防回源击穿和动态接口的数据安全。
