# BitTorrent 协议详解

## 一、BitTorrent 概述

### 1.1 什么是 BitTorrent

BitTorrent 是 Bram Cohen 于 2001 年设计的 P2P 文件分发协议，通过用户之间互相分享文件片段，实现高效的大文件分发。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  BitTorrent 核心特点：                                     │
│                                                             │
│  1. 去中心化：文件分散存储在所有用户节点                   │
│  2. 高效分发：用户越多，速度越快                          │
│  3. 断点续传：支持分片下载，可随时暂停恢复                │
│  4. 激励分享：上传越多，可下载越快                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 三、工作流程

### 3.1 下载流程

```python
# BitTorrent 下载流程
class BitTorrentClient:
    def download(self, torrent_file):
        # 1. 解析 .torrent 文件
        meta = bencodepy.decode(torrent_file)
        info_hash = self.calc_info_hash(meta['info'])
        
        # 2. 连接 Tracker 获取 peers
        peers = self.tracker.announce(
            info_hash=info_hash,
            peer_id=self.peer_id,
            port=self.port,
            uploaded=0,
            downloaded=0,
            left=self.total_size
        )
        
        # 3. 与 peers 建立连接，开始下载
        self.connect_to_peers(peers)
        
        # 4. 交换 piece 可用性
        for peer in self.active_peers:
            self.send_bitfield(peer)
        
        # 5. 选择并下载 pieces
        while self.has_incomplete_pieces():
            piece = self.select_piece()
            peer = self.select_peer(piece)
            self.download_piece(peer, piece)
```

## 四、Piece 选择算法

### 4.1 稀有优先算法

```python
import collections

class PieceSelector:
    def __init__(self):
        self.availability = collections.Counter()  # 各 piece 可用副本数
    
    def update_availability(self, peer, new_pieces):
        """更新 piece 可用性"""
        for piece_index in new_pieces:
            self.availability[piece_index] += 1
    
    def select_rarest_piece(self, available_pieces, completed_pieces):
        """
        稀有优先策略：
        选择所有 peer 中副本数最少的 piece
        目的是最大化文件存活率
        """
        candidates = set(available_pieces) - set(completed_pieces)
        
        if not candidates:
            return None
        
        # 选择副本数最少的 piece
        rarest = min(candidates, key=lambda p: self.availability[p])
        return rarest
    
    def select_endgame_piece(self, requested_pieces, available_pieces):
        """
        终局策略：
        当只剩少量 pieces 时，
        向所有拥有这些 pieces 的 peer 请求
        """
        remaining = set(requested_pieces) - set(completed_pieces)
        
        if len(remaining) > 10:
            return None
        
        # 返回任意未完成的 piece
        return next(iter(remaining)) if remaining else None
```

### 4.2 Piece 选择策略对比

| 策略 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| 随机 | 随机选择 piece | 简单 | 不均匀 |
| 稀有优先 | 选择副本最少的 | 文件存活率高 | 初期可能慢 |
| 顺序 | 按顺序下载 | 适合预览 | 不均衡 |
| 终局 | 向所有 peer 请求 | 快速完成 | 可能浪费带宽 |

## 五、Piece 下载机制

### 5.1 分片传输

```python
# Piece 下载
class PieceDownloader:
    def __init__(self, piece_index, piece_size, hash_value):
        self.piece_index = piece_index
        self.piece_size = piece_size
        self.hash_value = hash_value
        self.blocks = {}  # {block_offset: data}
    
    def request_block(self, peer, block_size=16384):
        """请求一个 block（piece 的子集）"""
        # Block 大小通常是 16KB
        for offset in range(0, self.piece_size, block_size):
            if offset not in self.blocks:
                # 发送 REQUEST 消息
                peer.send_request(self.piece_index, offset, block_size)
                break
    
    def receive_block(self, offset, data):
        """接收 block 数据"""
        self.blocks[offset] = data
        
        # 检查是否完成
        if len(self.blocks) * len(data) >= self.piece_size:
            return self.verify()
        
        return False
    
    def verify(self):
        """验证 piece 完整性"""
        import hashlib
        piece_data = b''.join(
            self.blocks[k] for k in sorted(self.blocks.keys())
        )
        return hashlib.sha1(piece_data).digest() == self.hash_value
```

### 5.2 Bitfield 交换

```python
# Bitfield 消息格式
class BitfieldMessage:
    @staticmethod
    def encode(completed_pieces, total_pieces):
        """将完成的 pieces 编码为 bitfield"""
        bitfield = bytearray((total_pieces + 7) // 8)
        
        for piece_index in completed_pieces:
            byte_index = piece_index // 8
            bit_index = piece_index % 8
            bitfield[byte_index] |= (1 << (7 - bit_index))
        
        return bytes(bitfield)
    
    @staticmethod
    def decode(bitfield_bytes, total_pieces):
        """解码 bitfield"""
        completed = []
        
        for i in range(total_pieces):
            byte_index = i // 8
            bit_index = i % 8
            
            if bitfield_bytes[byte_index] & (1 << (7 - bit_index)):
                completed.append(i)
        
        return completed
```

## 六、Peer 协议消息

### 6.1 消息类型

| 消息 ID | 名称 | 方向 | 描述 |
|---------|------|------|------|
| 0 | choke | 发送 | 拒绝上传 |
| 1 | unchoke | 发送 | 允许上传 |
| 2 | interested | 发送 | 请求数据 |
| 3 | not interested | 发送 | 不需要数据 |
| 4 | have | 发送 | 拥有某 piece |
| 5 | bitfield | 发送 | 所有 pieces |
| 6 | request | 发送 | 请求 block |
| 7 | piece | 发送 | 发送数据 |
| 8 | cancel | 发送 | 取消请求 |

### 6.2 消息处理

```python
class PeerProtocol:
    def handle_message(self, peer, message_id, payload):
        if message_id == 0:  # choke
            peer.am_choking = True
            
        elif message_id == 1:  # unchoke
            peer.am_choking = False
            
        elif message_id == 4:  # have
            piece_index = struct.unpack('!I', payload)[0]
            peer.available_pieces.add(piece_index)
            
        elif message_id == 6:  # request
            piece_index, begin, length = struct.unpack('!III', payload)
            # 检查是否应该上传
            if not peer.am_interested:
                return
            
            data = self.get_block(piece_index, begin, length)
            peer.send_piece(piece_index, begin, data)
```

## 八、BitTorrent V2

### 8.1 V1 vs V2

| 特性 | V1 | V2 |
|------|----|----|
| 哈希算法 | SHA-1（不安全） | SHA-256 |
| 文件结构 | 单文件/多文件混合 | Merkle 树 |
| piece 大小 | 固定 | 可变 |
| 文件复用 | 无法共享相同内容 | Merkle 树支持去重 |

### 8.2 Merkle 树结构

```python
import hashlib

class MerkleTree:
    @staticmethod
    def build_leaves(file_hashes):
        """构建 Merkle 树叶子"""
        return [sha256(h).digest() for h in file_hashes]
    
    @staticmethod
    def build_tree(hashes):
        """递归构建 Merkle 树"""
        if len(hashes) == 1:
            return hashes[0]
        
        new_level = []
        for i in range(0, len(hashes), 2):
            left = hashes[i]
            right = hashes[i + 1] if i + 1 < len(hashes) else left
            new_level.append(sha256(left + right).digest())
        
        return MerkleTree.build_tree(new_level)
    
    @staticmethod
    def verify_proof(leaf_hash, proof, root, index):
        """验证 Merkle 证明"""
        current = leaf_hash
        
        for i, sibling in enumerate(proof):
            if (index >> i) & 1:
                current = sha256(sibling + current).digest()
            else:
                current = sha256(current + sibling).digest()
        
        return current == root
```

## 九、面试常见问题

### Q1: BitTorrent 的优缺点？

优点：去中心化、用户越多速度越快、支持断点续传、激励分享。缺点：依赖 Tracker、初始源重要性高、小文件效率低、版权问题。

### Q2: 稀有优先策略的目的？

让副本数最少的 piece 被优先下载，确保每个 piece 至少有多个完整副本，提高文件存活率，防止种子下线后部分 piece 丢失。

### Q3: BitTorrent 和 HTTP 下载的区别？

HTTP 是 C/S 模式，所有用户从同一个服务器下载；BitTorrent 是 P2P 模式，用户之间互相分享，服务器压力小，但协议复杂。

### Q4: 什么是 Seed 和 Peer？

Seed（种子）是拥有完整文件且只上传不下载的节点；Peer 是正在下载且可能同时上传的节点。
