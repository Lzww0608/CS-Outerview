# 2.内网穿透原理

内网穿透解决的是“内网主机没有公网可路由地址，公网客户端如何访问它”的问题。花生壳、frp、ngrok、云隧道、远程桌面穿透等产品，本质上都是围绕 NAT、端口映射和中继隧道做工程封装。

## 1. 为什么公网不能直接访问内网

家庭或公司内网主机通常使用私有地址，例如 `192.168.x.x`。这些地址不会在公网路由。内网访问公网时，出口路由器通过 NAT/NAPT 建立临时映射；但公网主动访问内网时，如果 NAT 表里没有映射，网关不知道应该转发给哪台内网机器。

## 2. 常见穿透方式

### 端口映射

在路由器上配置 DNAT：

```text
公网IP:8080 -> 192.168.1.10:80
```

优点是链路直接、性能好；缺点是需要控制路由器，且暴露端口有安全风险。

### UPnP/NAT-PMP

内网应用请求路由器自动创建端口映射。家庭网络常见，但企业网络通常会禁用，因为安全边界不可控。

### 反向隧道

内网客户端主动连接一台有公网 IP 的中转服务器，并保持长连接。公网用户访问中转服务器，中转服务器把流量通过这条反向连接转发回内网客户端。

```text
公网用户 -> 公网中转服务器 -> 内网客户端主动建立的隧道 -> 内网服务
```

花生壳、frp、ngrok 常用这种思路。它不要求内网路由器配置端口映射，只要求内网机器能主动访问公网。

### P2P 打洞

STUN/ICE 让双方探测自己的公网映射地址，再尝试 UDP 打洞直接通信。WebRTC、音视频、游戏常用。打洞失败时会退化到 TURN 中继。

## 3. 花生壳这类工具的大致链路

1. 内网客户端登录穿透平台，和平台公网节点建立长连接。
2. 平台分配域名或公网访问入口。
3. 外部用户访问域名，DNS 解析到平台公网节点。
4. 平台根据域名和账号找到对应内网客户端隧道。
5. 平台把 TCP/HTTP 数据转发到内网客户端。
6. 内网客户端再连接本机或局域网目标服务，把响应沿隧道返回。

如果是 HTTP/HTTPS 穿透，平台还可能做 Host 路由、TLS 终止、证书管理和访问控制；如果是 TCP 穿透，则更接近四层字节流转发。

## 4. 易错点

1. 内网穿透不是让私有 IP 变成公网 IP，而是通过映射、中继或打洞让流量可达。
2. 反向隧道会引入中转延迟，带宽也受平台节点限制。
3. 中转服务器能看到连接元数据，明文协议还可能看到内容，敏感服务要端到端加密。
4. 暴露 SSH、数据库、管理后台时要加认证、白名单和限流，避免把内网服务直接暴露到公网。
5. P2P 打洞受 NAT 类型影响，对称 NAT 下直连成功率低，常需要 TURN 中继。

## 5. 面试回答模板

花生壳这类内网穿透工具通常不是直接打破 NAT，而是让内网客户端主动连到公网中转节点并保持隧道。外部用户访问平台分配的域名或端口，流量先到公网节点，再通过内网客户端已经建立好的反向连接转发到内网服务。其他方式还包括路由器端口映射、UPnP、STUN/ICE 打洞和 TURN 中继。真实使用时要关注中转延迟、带宽、安全认证和暴露面。
