# 1.OSI 七层模型与 TCP/IP 四层模型

网络分层模型用于把复杂的网络通信拆成多个职责清晰的层次。面试里常要求说明 OSI 七层模型和 TCP/IP 四层模型，以及两者的对应关系。

## 1. OSI 七层模型

从上到下：

| 层级 | 名称 | 作用 | 常见协议/概念 |
| --- | --- | --- | --- |
| 7 | 应用层 | 为应用程序提供网络服务 | HTTP、DNS、SMTP、FTP |
| 6 | 表示层 | 数据格式转换、加密、压缩 | TLS、编码、序列化 |
| 5 | 会话层 | 建立、维护、管理会话 | 会话管理、RPC 会话 |
| 4 | 传输层 | 端到端传输、可靠性、端口 | TCP、UDP |
| 3 | 网络层 | 路由寻址、跨网络转发 | IP、ICMP |
| 2 | 数据链路层 | 局域网内帧传输、MAC 地址 | Ethernet、ARP、交换机 |
| 1 | 物理层 | 比特流传输 | 网线、光纤、无线信号 |

OSI 更偏理论模型，层次清晰，但实际互联网协议栈通常按 TCP/IP 模型理解。

## 2. TCP/IP 四层模型

从上到下：

| 层级 | 名称 | 作用 | 常见协议 |
| --- | --- | --- | --- |
| 4 | 应用层 | 应用协议和数据格式 | HTTP、DNS、SMTP、SSH |
| 3 | 传输层 | 端到端通信 | TCP、UDP |
| 2 | 网络层 | IP 寻址和路由 | IP、ICMP |
| 1 | 网络接口层 | 链路传输和物理网络 | Ethernet、Wi-Fi、ARP |

TCP/IP 四层模型更贴近真实互联网协议实现。

## 2.1 TCP/IP 五层模型

很多教材和面试也会使用五层模型，它把 TCP/IP 四层里的“网络接口层”拆成数据链路层和物理层：

| 层级 | 名称 | 作用 | 常见协议/概念 |
| --- | --- | --- | --- |
| 5 | 应用层 | 应用协议和数据格式 | HTTP、DNS、SMTP |
| 4 | 传输层 | 端到端通信、端口、可靠性 | TCP、UDP |
| 3 | 网络层 | IP 寻址和路由 | IP、ICMP |
| 2 | 数据链路层 | 同一链路内帧传输 | Ethernet、Wi-Fi、ARP、MAC |
| 1 | 物理层 | 比特流传输 | 网线、光纤、无线电 |

端口号在传输层指定。TCP/UDP 首部都有源端口和目的端口，用于把同一台主机上的不同应用进程区分开。

## 2.2 TCP/IP 协议族

TCP/IP 不是只包含 TCP 和 IP，而是一组分层协作的协议族：

| 层级 | 常见协议 | 作用 |
| --- | --- | --- |
| 应用层 | HTTP、DNS、SMTP、SSH、FTP、RPC | 定义应用数据格式和交互语义 |
| 传输层 | TCP、UDP、QUIC | 端到端进程通信，端口复用，可靠性或低延迟传输 |
| 网络层 | IP、ICMP、IGMP | 跨网络寻址、路由、错误报告和诊断 |
| 数据链路层 | Ethernet、Wi-Fi、ARP | 局域网内帧传输，IP 到 MAC 的解析 |
| 物理层 | 光纤、双绞线、无线信号 | 比特流传输 |

几个常见关系：

1. HTTP 通常运行在 TCP/TLS 之上，HTTP/3 运行在 QUIC/UDP 之上。
2. DNS 常用 UDP 53，也会在大响应、区域传送、DoT 等场景使用 TCP/TLS。
3. ICMP 和 TCP/UDP 一样封装在 IP 包里，但它属于网络层控制协议，不使用端口。
4. ARP 只在局域网内解析下一跳 MAC，不负责跨网络路由。
5. NAT/NAPT 常改写 IP 地址和 TCP/UDP 端口，属于网关上的地址转换机制。

### 常见应用层协议

应用层协议定义应用数据格式、交互语义和错误处理方式，常见包括：

1. **HTTP/HTTPS**：Web、REST API、网关、微服务调用。
2. **DNS**：域名解析。
3. **SMTP/POP3/IMAP**：邮件发送和收取。
4. **SSH**：安全远程登录和隧道。
5. **FTP/SFTP**：文件传输。
6. **WebSocket/SSE**：实时消息和服务端推送。
7. **RPC/gRPC**：服务间远程调用。
8. **MQTT**：物联网和弱网络消息通信。

应用层协议可以运行在不同传输层之上。例如 HTTP/1.1 和 HTTP/2 常跑在 TCP/TLS 上，HTTP/3 跑在 QUIC/UDP 上。

## 2.3 为什么互联网采用 TCP/IP 而不是 OSI

OSI 七层模型层次清晰，适合教学和分析；但真实互联网最终主要采用 TCP/IP，原因包括：

1. **TCP/IP 先实现、先部署**：TCP/IP 在 ARPANET 和早期 Unix 系统中已经可用，工程生态先跑起来。
2. **实现简单务实**：TCP/IP 分层较少，协议边界更贴近实际系统实现。
3. **开放互联需求强**：IP 提供统一的跨网络寻址和路由能力，能连接不同底层网络。
4. **端到端思想明确**：复杂性更多放在端系统，网络层保持相对简单，利于扩展。
5. **生态和兼容性滚雪球**：应用、设备、操作系统都围绕 TCP/IP 建设后，迁移成本极高。

所以 OSI 更像理论参考模型，TCP/IP 是互联网实际协议栈。面试回答时可以说：用 OSI 解释分层，用 TCP/IP 解释真实落地。

## 3. 对应关系

```text
OSI 应用层
OSI 表示层      -> TCP/IP 应用层
OSI 会话层

OSI 传输层      -> TCP/IP 传输层
OSI 网络层      -> TCP/IP 网络层
OSI 数据链路层  -> TCP/IP 网络接口层
OSI 物理层
```

## 4. 数据封装过程

一次 HTTP 请求从应用发出时，大致会经历：

```text
HTTP 数据
  -> TCP segment，添加源端口、目的端口、序号、确认号
  -> IP packet，添加源 IP、目的 IP
  -> Ethernet frame，添加源 MAC、目的 MAC
  -> 物理介质上的 bit
```

接收端则反向解封装。

更具体一点：

1. 应用层产生 HTTP 报文，例如请求行、请求头、请求体。
2. 传输层把 HTTP 数据切分为 TCP segment，加源端口、目的端口、序号、确认号、窗口、校验和等。
3. 网络层把 TCP segment 封装进 IP packet，加源 IP、目的 IP、TTL、协议号等。
4. 数据链路层把 IP packet 封装成 Ethernet frame，加源 MAC、目的 MAC、类型、FCS 等。
5. 物理层把帧编码成电信号、光信号或无线信号发送出去。

经过路由器时，二层帧头会在每一跳重新封装，源/目的 MAC 会变；三层 IP 的源/目的地址通常保持不变，但 TTL 会递减，NAT 场景下 IP 和端口可能被改写。

## 5. 常见追问

### 端口号属于哪一层？

端口号属于传输层，TCP 和 UDP 都通过端口号区分同一台主机上的不同进程或服务。

### IP 地址属于哪一层？

IP 地址属于网络层，用来做跨网络寻址和路由。

### MAC 地址属于哪一层？

MAC 地址属于数据链路层，用于同一局域网链路内的下一跳转发。

### ARP 属于哪一层？

ARP 用于把 IP 地址解析成 MAC 地址，位置比较特殊，通常认为工作在网络层和数据链路层之间。在 TCP/IP 模型里可归到网络接口层相关协议。

## 6. 面试回答模板

OSI 是七层模型，从上到下是应用层、表示层、会话层、传输层、网络层、数据链路层、物理层。TCP/IP 常用四层模型，分别是应用层、传输层、网络层、网络接口层；也常用五层模型，把网络接口层拆成数据链路层和物理层。TCP/IP 协议族包括 HTTP、DNS、TCP、UDP、IP、ICMP、ARP、Ethernet 等协议，端口号属于传输层，由 TCP/UDP 首部指定，用来区分主机上的不同进程。OSI 更适合做理论分层，TCP/IP 因为先实现、易部署、生态成熟而成为真实互联网协议栈。

实际通信时，应用层 HTTP 数据会先交给 TCP 加端口和序号，再交给 IP 加源/目的 IP，最后交给以太网加 MAC 地址并在物理链路上传输。
