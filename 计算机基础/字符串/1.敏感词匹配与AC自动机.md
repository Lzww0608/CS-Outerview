# 敏感词匹配与 AC 自动机

敏感词匹配是典型的多模式字符串匹配问题：给定一批词典词，在一段文本中找出是否出现任意敏感词，或找出所有命中的词和位置。

## 1. 常见方案

| 方案 | 思路 | 适用场景 |
| --- | --- | --- |
| 逐个词 `find` | 对每个敏感词扫描文本 | 词库很小、离线脚本 |
| 正则合并 | 把敏感词拼成正则或分组 | 词库小、规则复杂 |
| Trie 前缀树 | 从每个文本位置沿 Trie 匹配 | 中等词库、实现简单 |
| AC 自动机 | Trie + fail 指针，一次扫描文本 | 大词库、高吞吐在线服务 |

如果敏感词有几万到几十万，文本又很多，逐个词扫描会变成 `O(词数 * 文本长度)`，通常要用 AC 自动机。

## 2. AC 自动机原理

AC 自动机（Aho-Corasick）可以理解为 KMP 的多模式扩展：

1. 用所有敏感词构建 Trie。
2. 为每个节点建立 `fail` 指针，表示当前路径匹配失败时，应该跳到哪个最长可用后缀节点。
3. 扫描文本时，当前字符如果不能继续匹配，就沿 `fail` 指针回退。
4. 每走到一个节点，检查该节点及其 fail 链上是否有敏感词结束。

构建完成后，扫描复杂度接近：

```text
O(文本长度 + 命中数量)
```

## 3. 简化代码

下面代码适合面试说明核心流程，生产环境还要处理 Unicode、归一化、词库热更新和内存压缩。

```cpp
#include <array>
#include <queue>
#include <string>
#include <utility>
#include <vector>
using namespace std;

class ACAutomaton {
private:
    struct Node {
        array<int, 26> next{};
        int fail = 0;
        vector<int> output;

        Node() {
            next.fill(-1);
        }
    };

    vector<Node> trie_{Node{}};

public:
    void insert(const string& word, int id) {
        int cur = 0;
        for (char ch : word) {
            int c = ch - 'a';
            if (trie_[cur].next[c] == -1) {
                trie_[cur].next[c] = static_cast<int>(trie_.size());
                trie_.push_back(Node{});
            }
            cur = trie_[cur].next[c];
        }
        trie_[cur].output.push_back(id);
    }

    void build() {
        queue<int> q;

        for (int c = 0; c < 26; ++c) {
            int child = trie_[0].next[c];
            if (child == -1) {
                trie_[0].next[c] = 0;
            } else {
                trie_[child].fail = 0;
                q.push(child);
            }
        }

        while (!q.empty()) {
            int u = q.front();
            q.pop();

            for (int c = 0; c < 26; ++c) {
                int v = trie_[u].next[c];
                if (v == -1) {
                    trie_[u].next[c] = trie_[trie_[u].fail].next[c];
                    continue;
                }
                trie_[v].fail = trie_[trie_[u].fail].next[c];
                for (int id : trie_[trie_[v].fail].output) {
                    trie_[v].output.push_back(id);
                }
                q.push(v);
            }
        }
    }

    vector<pair<int, int>> match(const string& text) const {
        vector<pair<int, int>> ans;
        int cur = 0;
        for (int i = 0; i < static_cast<int>(text.size()); ++i) {
            int c = text[i] - 'a';
            cur = trie_[cur].next[c];
            for (int id : trie_[cur].output) {
                ans.push_back({i, id});
            }
        }
        return ans;
    }
};
```

这段代码假设文本和词库都是小写英文字母。真实中文敏感词需要先做 Unicode 分词或按 UTF-8 code point/rune 建边，不能直接按 `char - 'a'` 写死 26 个分支。

## 4. 工程化注意事项

1. **归一化**：大小写、全角半角、繁简体、空格插入、特殊符号、谐音和 Unicode 变体都可能绕过简单匹配。
2. **最长匹配和重叠匹配**：业务要明确返回所有命中、最长命中、最短命中还是命中即停止。
3. **误伤处理**：白名单、上下文判断、词边界和人工审核很重要，不能只靠字符串匹配做最终处罚。
4. **词库更新**：大词库可用双 buffer 构建新自动机，构建完成后原子切换指针，避免在线请求阻塞。
5. **内存优化**：字符集大时不要用固定数组，可以用压缩 Trie、稀疏 map、双数组 Trie 或分层字典。
6. **多级策略**：在线链路先 AC 自动机快速召回，再用规则、模型或人工审核降低误判。

## 5. 面试回答模板

敏感词匹配本质是多模式字符串匹配。词库小可以逐个 `find` 或正则，词库大应该用 AC 自动机。AC 自动机先把所有词建成 Trie，再用 BFS 构建 fail 指针，扫描文本时匹配失败就沿 fail 回退，因此可以一次扫描找出所有敏感词，复杂度接近 `O(文本长度 + 命中数量)`。真实业务还要处理归一化、谐音变体、最长匹配、白名单、词库热更新和误伤审核。
