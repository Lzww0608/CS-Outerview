# 正则表达式

正则表达式用于描述字符串模式，适合做格式校验、字段提取、日志过滤和简单文本替换。面试回答时不要只背语法，还要说明匹配引擎和性能风险。

## 1. 常见语法

| 语法 | 含义 | 示例 |
| --- | --- | --- |
| `.` | 匹配任意单个字符，通常不含换行 | `a.c` |
| `*` | 前一个元素重复 0 次或多次 | `ab*` |
| `+` | 前一个元素重复 1 次或多次 | `ab+` |
| `?` | 前一个元素重复 0 次或 1 次 | `ab?` |
| `{m,n}` | 重复 m 到 n 次 | `a{2,4}` |
| `[]` | 字符集合 | `[0-9]` |
| `[^]` | 排除字符集合 | `[^0-9]` |
| `^` | 行首或字符串开头 | `^GET` |
| `$` | 行尾或字符串结尾 | `200$` |
| `()` | 分组和捕获 | `(ab)+` |
| `|` | 或 | `GET|POST` |
| `\d`、`\w`、`\s` | 数字、单词字符、空白字符 | `\d+` |

贪婪匹配会尽可能多匹配，例如 `.*`；非贪婪匹配会尽可能少匹配，例如 `.*?`。

## 2. 引擎原理

常见正则引擎可以粗略分成两类：

1. **DFA 类引擎**：偏自动机，匹配速度稳定，通常不支持复杂回溯特性。
2. **NFA/回溯类引擎**：功能强，支持捕获组、反向引用、复杂断言，但可能出现灾难性回溯。

灾难性回溯示例：

```text
regex: ^(a+)+$
input: aaaaaaaaaaaaaaaaaab
```

多个嵌套量词会让回溯路径指数增长，导致 CPU 被打满。生产环境处理用户输入时，应避免复杂嵌套量词，或选择 RE2 这类保证线性时间的引擎。

## 3. 日志 IP 提取示例

如果日志每行格式类似：

```text
192.168.1.2 2026-04-25 login ok
```

可以用锚点约束 IP 在行首：

```regex
^(\d{1,3}(?:\.\d{1,3}){3})\s+
```

注意这只能匹配形态，不保证每段都在 `0-255`。严格 IPv4 校验可以写成：

```regex
^(25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)(\.(25[0-5]|2[0-4]\d|1\d\d|[1-9]?\d)){3}$
```

工程里如果要长期处理 IP，通常解析成整数或结构化字段，不建议每次查询都反复跑复杂正则。

## 4. C++ 中的正则

C++ 标准库提供 `std::regex`：

```cpp
#include <iostream>
#include <regex>
#include <string>

int main() {
    std::regex ip(R"(^(\d{1,3}(?:\.\d{1,3}){3})\s+)");
    std::string line = "192.168.1.2 2026-04-25 login ok";
    std::smatch m;

    if (std::regex_search(line, m, ip)) {
        std::cout << m[1] << '\n';
    }
}
```

`std::regex` 在不同标准库实现上的性能差异较大，高吞吐日志处理常选择 RE2、Hyperscan，或直接使用手写解析器。

## 5. 易错点

1. 正则适合模式匹配，不适合解析任意嵌套语法，例如完整 XML/HTML。
2. `.*` 太宽泛，容易跨字段吞掉大量内容，应尽量用明确字符集。
3. 用户可控正则或用户可控输入都要考虑 ReDoS。
4. 日志查询要优先结构化字段和索引，正则作为补充过滤。
5. 匹配 IP、邮箱、URL 等格式时，要区分“形态匹配”和“语义合法”。

## 6. 面试回答模板

正则表达式是描述字符串模式的工具，常用于校验、提取、过滤和替换。基础语法包括字符类、量词、分组、锚点和或运算。底层引擎常见 DFA 和 NFA/回溯两类，回溯引擎功能强但可能出现灾难性回溯。实际工程里处理日志或请求参数时，要避免过宽的 `.*` 和嵌套量词，高吞吐场景可以用结构化解析、RE2 或 Hyperscan。
