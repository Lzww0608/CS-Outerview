# 1.排序下界与线性排序

## 1. 排序算法的时间复杂度下界是什么？

如果讨论的是 **基于比较的排序算法**，时间复杂度下界是：

```text
Ω(n log n)
```

也就是说，归并排序、堆排序、快速排序这类只通过元素之间两两比较来确定顺序的算法，平均或最坏情况下不可能突破 `n log n` 这个量级。

## 2. 为什么比较排序下界是 Ω(n log n)？

可以用决策树解释。

对 `n` 个互不相同的元素排序，最终可能的排列有：

```text
n!
```

基于比较的排序，每次比较只有两种结果：

```text
a < b 或 a >= b
```

所以整个排序过程可以看成一棵二叉决策树。为了区分 `n!` 种排列，决策树至少要有 `n!` 个叶子节点。高度为 `h` 的二叉树最多有 `2^h` 个叶子，因此：

```text
2^h >= n!
h >= log2(n!)
```

根据 Stirling 公式：

```text
log2(n!) = Ω(n log n)
```

所以任何基于比较的排序，最坏情况下都需要至少 `Ω(n log n)` 次比较。

## 3. 有没有比 O(n log n) 更快的排序？

有，但前提是它们不是纯比较排序，而是利用了数据范围、位数、分布等额外条件。

| 算法 | 复杂度 | 适用条件 |
| --- | --- | --- |
| 计数排序 | `O(n + k)` | key 是整数，且范围 `k` 不大 |
| 基数排序 | `O(d(n + k))` | key 可以按位拆分，位数 `d` 有界 |
| 桶排序 | 平均 `O(n + k)` | 数据分布较均匀 |

这些算法能突破 `O(n log n)`，不是因为推翻了比较排序下界，而是因为它们绕开了“只靠比较”这个限制。

## 4. 计数排序

计数排序适合整数范围不大的场景。

```text
1. 统计每个值出现次数
2. 对计数数组做前缀和，得到每个值的最终位置
3. 反向遍历原数组，把元素放入输出数组，保证稳定性
```

复杂度：

```text
时间 O(n + k)
空间 O(n + k)
```

缺点是如果值域很大，例如只有 1 万个数但范围是 0 到 10 亿，就会浪费大量空间。

## 5. 基数排序

基数排序把整数或字符串拆成多位，从低位到高位或从高位到低位排序。

例如对非负整数按十进制低位优先排序：

```text
个位 -> 十位 -> 百位 -> ...
```

每一轮可以用稳定的计数排序。假设有 `d` 位，每位范围是 `k`：

```text
时间 O(d(n + k))
```

当 `d` 和 `k` 可以看作常数时，整体接近线性。

## 6. 面试回答模板

排序复杂度下界要先限定范围。对于基于比较的排序，下界是 `Ω(n log n)`，可以用决策树证明，因为 `n` 个元素有 `n!` 种排列，每次比较最多把可能性分成两类，所以至少需要 `log(n!)` 次比较。

比 `O(n log n)` 更快的排序是存在的，比如计数排序、基数排序、桶排序，但它们依赖额外假设：整数值域不能太大、位数有限、数据分布相对均匀等。因此它们不是通用比较排序。
