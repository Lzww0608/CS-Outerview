# 5. 外部排序与多路归并

外部排序用于处理数据量大于内存的数据。例如 1GB 文件、内存限制 100MB，不能一次性读入内存排序，就要把文件拆成多个有序分片，再做多路归并。

## 1. 基本流程

```text
大文件
-> 按内存预算切块读取
-> 每块内存排序
-> 写出有序临时文件 run
-> k 路归并多个 run
-> 输出最终有序文件
```

如果内存限制是 100MB，不能真的每次读满 100MB。要预留解析对象、排序临时空间、输出缓冲和堆结构空间，实际分块可以控制在 60MB 到 80MB。

## 2. 生成有序分片

步骤：

1. 顺序读取一批记录。
2. 解析成可比较的结构，例如整数、字符串或多字段记录。
3. 在内存中排序。
4. 写入临时文件，保证每个临时文件内部有序。

如果是文本行排序，要注意一行可能很长，不能假设固定长度。读取时可以按行流式解析，超过最大行长要报错或进入特殊处理。

## 3. k 路归并

每个有序分片打开一个输入流，用最小堆保存每个分片当前最小记录：

```text
heap item = (value, run_id)
```

流程：

1. 从每个 run 读一条记录入堆。
2. 弹出堆顶，写入输出文件。
3. 从对应 run 再读下一条记录入堆。
4. 直到堆为空。

复杂度：

```text
生成分片: O(n log m)，m 是每块记录数
归并: O(n log k)，k 是分片数量
空间: O(内存块 + k 个输入缓冲 + 堆)
```

## 4. 工程优化

1. **多路归并的 k 不宜过大**：受文件描述符数量和缓冲区内存限制，必要时分多轮归并。
2. **顺序 I/O**：外部排序尽量顺序读写，减少随机 I/O。
3. **缓冲区**：每个 run 使用读缓冲，输出也使用写缓冲。
4. **临时文件管理**：任务失败要清理临时文件，避免磁盘被打满。
5. **压缩**：磁盘是瓶颈时可以用 LZ4/Snappy 压缩临时 run。
6. **分布式扩展**：TB 级数据交给 Spark、Flink、MapReduce 或数据库/数仓排序。

## 5. 易错点

1. 不能把 1GB 文件映射或读入内存后再排序，否则违反内存限制。
2. 内存预算要考虑对象开销，不只是原始文件大小。
3. 文件描述符有限，不能无限路归并。
4. 临时文件所在磁盘空间可能成为瓶颈。
5. 如果要求稳定排序，要在比较键相同时附带原始序号或分片顺序。

## 6. 面试回答模板

1GB 文件、100MB 内存限制下，我会使用外部归并排序。先按内存预算分块读取，例如每次读 60 到 80MB，内存中排序后写成有序临时 run；所有分片生成后，用最小堆做 k 路归并，每个 run 只在内存中保留当前记录和缓冲区，弹出最小值写到输出，再从对应 run 读下一条。这样不需要全量加载文件，主要成本是顺序磁盘 I/O 和 `O(n log k)` 的归并。如果分片太多，就分多轮归并。
