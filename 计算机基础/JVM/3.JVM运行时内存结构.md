# 3. JVM 运行时内存结构

JVM 运行时内存结构描述的是 Java 程序运行时，虚拟机如何把类元数据、对象、方法调用栈、程序计数器等信息组织起来。面试里常问“哪些区域线程共享，哪些区域线程私有”，本质是在考察并发线程之间能共享什么、各自独占什么，以及 OOM 或栈溢出会发生在哪里。

## 1. 总体分类

JVM 运行时数据区可以按线程共享关系分为两类：

| 区域 | 是否线程共享 | 主要内容 |
| --- | --- | --- |
| 堆 | 共享 | 对象实例、数组、字符串对象等 |
| 方法区 / 元空间 | 共享 | 类元数据、方法信息、字段信息、运行时常量池等 |
| Java 虚拟机栈 | 线程私有 | 栈帧、局部变量表、操作数栈、动态链接、返回地址 |
| 本地方法栈 | 线程私有 | Native 方法调用栈 |
| 程序计数器 | 线程私有 | 当前线程正在执行的字节码位置 |

线程私有区域随线程创建而创建，随线程结束而销毁；共享区域由所有线程共同访问，需要依赖对象锁、volatile、原子类、并发容器等机制保证并发正确性。

## 2. 堆

堆是 Java 对象主要分配区域，也是 GC 管理的核心区域。

```text
Heap
  Young Generation
    Eden
    Survivor 0 / Survivor 1
  Old Generation
```

对象一般先在新生代分配，经历 Minor GC 后仍然存活的对象会逐步晋升到老年代。大对象、长期存活对象或分配担保失败时，可能直接进入老年代，具体行为和 JVM 版本、GC 算法、参数有关。

需要注意：

1. 堆是线程共享的，但 HotSpot 会用 TLAB 为每个线程分配一小块本地分配缓冲区，减少对象分配时的全局竞争。
2. 堆空间不足且 GC 后仍无法分配对象，会抛出 `OutOfMemoryError: Java heap space`。
3. 堆里的对象是否线程安全，取决于访问方式，不是“放在堆上就一定不安全”，也不是“局部变量引用的对象就一定线程私有”。

## 3. 方法区和元空间

方法区是 JVM 规范中的概念，HotSpot 在 Java 8 之后主要用元空间 Metaspace 实现。元空间使用本地内存，保存类加载后的元数据，例如：

1. 类名、父类、接口。
2. 字段和方法描述信息。
3. 字节码、运行时常量池。
4. JIT 编译相关元数据。

Java 8 之前常说永久代 PermGen，Java 8 之后改为 Metaspace。元空间不在 Java 堆里，但仍可能耗尽，例如动态生成大量类、频繁热部署但类加载器无法卸载，可能触发 `OutOfMemoryError: Metaspace`。

面试里不要简单说“静态变量都在方法区”。更准确的说法是：类级元数据与方法区/元空间相关；静态字段的具体存放实现和 JVM 版本有关，业务回答时重点说明它属于类级共享状态，多个线程访问时仍需保证并发安全。

## 4. Java 虚拟机栈

每个 Java 线程都有自己的虚拟机栈。每次方法调用都会创建一个栈帧，方法返回时栈帧出栈。

一个栈帧通常包含：

1. **局部变量表**：方法参数、局部变量、`this` 引用。
2. **操作数栈**：字节码执行过程中的临时计算栈。
3. **动态链接**：指向运行时常量池中当前方法相关符号引用。
4. **方法返回地址**：方法执行完成后回到调用方的位置。

如果递归太深或单个线程栈空间不足，会抛出 `StackOverflowError`；如果系统无法再为新线程分配栈空间，可能出现无法创建本地线程的 OOM。`-Xss` 可以调整单线程栈大小，栈越大，单线程递归深度更高，但同一机器可创建线程数会下降。

## 5. 程序计数器和本地方法栈

程序计数器记录当前线程下一条要执行的字节码指令地址。多线程切换后，线程需要靠自己的程序计数器恢复执行位置，因此它必须是线程私有的。

本地方法栈服务于 JNI / Native 方法。例如 Java 调用 C/C++ 实现的本地库时，相关调用状态会进入本地方法栈。它也属于线程私有区域。

## 6. 直接内存

直接内存不是 JVM 运行时数据区的一部分，但在后端项目里非常重要。`ByteBuffer.allocateDirect`、Netty 的直接缓冲区、零拷贝 I/O 都可能使用堆外内存。

直接内存的优势是减少 Java 堆和 Native 堆之间的数据复制，适合网络 I/O、大文件传输、序列化缓冲区等场景。风险是它不受 Java 堆大小直接限制，释放也依赖 Cleaner 或框架内存池管理，泄漏时容易表现为进程 RSS 不断上涨，但 Java 堆看起来并不大。

## 7. 真实场景

在一个 Web 服务中：

1. 每个请求通常由某个工作线程处理，该线程有自己的程序计数器、Java 栈和本地方法栈。
2. Controller、Service 中的局部变量引用保存在栈帧里，但引用指向的对象通常在堆上。
3. Spring Bean、缓存对象、连接池、业务实体都在堆上被多线程共享访问。
4. 类元数据、代理类、反射信息放在元空间；动态代理、字节码增强过多可能造成元空间压力。
5. Netty、RPC 框架、文件传输模块可能大量使用直接内存，需要单独监控。

## 8. 易错点

1. 栈上保存的是局部变量和对象引用，不代表对象本体一定在栈上。
2. `String` 对象在堆上，字符串常量池的实现也经历过 JVM 版本变化，不要机械背“常量池在永久代”。
3. TLAB 是堆上的线程本地分配缓冲区，不是线程私有堆。
4. 方法区是规范概念，元空间是 HotSpot 的实现方式。
5. 调大 `-Xss` 可以减少栈溢出，但会降低最大线程数，不适合用来掩盖无限递归或线程过多的问题。

## 9. 面试回答模板

JVM 运行时内存可以分为线程共享和线程私有两类。线程共享的主要是堆和方法区/元空间：堆放对象实例和数组，是 GC 的主要区域；方法区或元空间放类元数据、方法信息和运行时常量池等。线程私有的包括程序计数器、Java 虚拟机栈和本地方法栈：每个线程都有自己的栈，方法调用时创建栈帧，栈帧里有局部变量表、操作数栈、动态链接和返回地址。堆 OOM、元空间 OOM、栈溢出和无法创建线程对应的原因不同，排查时要结合 `-Xmx`、`-Xss`、Metaspace、直接内存和线程数一起看。
