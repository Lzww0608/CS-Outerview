# 6. Java 内存溢出与内存泄漏

Java 面试里“内存溢出”和“内存泄漏”经常一起问。二者不是一回事：内存泄漏是对象或资源不再需要却仍被引用，导致无法释放；内存溢出是可用内存不足，JVM 或操作系统无法继续分配。

## 1. 定义区别

| 概念 | 含义 | 结果 |
| --- | --- | --- |
| 内存泄漏 | 无用对象仍被引用，GC 无法回收 | 内存持续增长，最终可能 OOM |
| 内存溢出 | 内存不足，分配失败 | 抛出 `OutOfMemoryError` 或进程被 OOM killer 杀死 |

内存泄漏是原因之一，内存溢出是结果之一。程序也可能没有泄漏，只是一次性加载数据太大、线程太多、堆设置太小、直接内存不足而 OOM。

## 2. 常见 OOM 类型

### Java heap space

堆空间不足，常见原因：

1. 一次性加载大文件、大列表、大 JSON。
2. 缓存无上限，例如 `Map` 长期增长。
3. 对象生命周期过长，老年代无法回收。
4. 查询返回过多数据，分页缺失。

### GC overhead limit exceeded

JVM 大部分时间都在 GC，但回收效果很差。常见于堆接近满、对象仍被强引用。

### Metaspace

元空间不足，常见原因：

1. 动态生成大量类，例如 CGLIB、ByteBuddy、Groovy 脚本。
2. 热部署或插件系统中类加载器无法卸载。
3. `MaxMetaspaceSize` 设置过小。

### Direct buffer memory

直接内存不足，常见于 Netty、NIO、文件传输、大 buffer 池。Java 堆看起来不大，但进程 RSS 很高。

### unable to create native thread

无法创建本地线程，常见原因：

1. 线程池无界增长。
2. `-Xss` 过大导致单线程栈占用过高。
3. OS 线程数、ulimit、容器 pids 或内存限制不足。

## 3. Java 常见内存泄漏场景

1. **静态集合持有对象**：`static Map/List` 不清理，导致对象一直可达。
2. **本地缓存无上限**：缓存没有最大容量、TTL 或淘汰策略。
3. **ThreadLocal 未 remove**：线程池线程长期复用，value 被线程持有。
4. **监听器/回调未注销**：对象注册到全局事件总线后不解除。
5. **定时任务持有引用**：任务闭包捕获大对象，任务未取消。
6. **连接、文件、Socket 未关闭**：不是堆内存泄漏，但属于资源泄漏。
7. **类加载器泄漏**：Web 容器热部署后旧 ClassLoader 仍被线程、ThreadLocal、静态变量引用。
8. **JNI/native 内存泄漏**：C/C++ 侧分配后未释放，Java GC 看不到。

ThreadLocal 示例：

```java
private static final ThreadLocal<byte[]> BUF = new ThreadLocal<>();

void handle() {
    try {
        BUF.set(new byte[1024 * 1024]);
        // business
    } finally {
        BUF.remove();
    }
}
```

线程池场景中，`remove()` 很重要，否则 value 可能跟随工作线程长期存活。

## 4. 如何排查

基本步骤：

1. 看现象：是 Java 堆上涨、RSS 上涨、线程数上涨，还是 Metaspace 上涨。
2. 打开 GC 日志：观察 Full GC、老年代、Humongous、晋升失败等。
3. 抓堆转储：`jmap -dump` 或 OOM 时 `-XX:+HeapDumpOnOutOfMemoryError`。
4. 分析 dump：用 MAT、JProfiler、VisualVM 看 dominator tree、GC roots、retained size。
5. 看线程：`jstack`、Arthas、JFR 判断是否线程泄漏。
6. 看 native memory：NMT、`pmap`、`smaps`、Netty leak detector。

常用参数：

```bash
-XX:+HeapDumpOnOutOfMemoryError
-XX:HeapDumpPath=/path/to/dump.hprof
-Xlog:gc*:file=gc.log:time,level,tags
-XX:NativeMemoryTracking=summary
```

## 5. 如何解决

1. 大数据处理改成分页、流式、游标、分批。
2. 缓存加容量上限、TTL、淘汰策略和监控。
3. ThreadLocal 用完 `remove()`。
4. 监听器、定时任务、回调注册要有注销路径。
5. 线程池设置核心数、最大数、队列容量和拒绝策略。
6. Netty/直接内存使用池化并开启泄漏检测。
7. 动态类生成要控制 ClassLoader 生命周期。
8. JNI 资源按所有权释放，并用 native 工具定位。

## 6. 面试回答模板

内存泄漏是对象或资源不再需要但仍被引用，GC 无法回收；内存溢出是内存不够导致分配失败。Java 常见 OOM 有 `Java heap space`、`GC overhead limit exceeded`、`Metaspace`、`Direct buffer memory` 和无法创建 native thread。泄漏场景包括静态集合、本地缓存无上限、ThreadLocal 未 remove、监听器未注销、定时任务持有引用、类加载器泄漏和 JNI native 内存泄漏。排查时先区分 Java 堆、元空间、直接内存、线程数和 RSS，再用 GC 日志、heap dump、MAT、JFR、jstack、NMT 等工具定位，修复上控制对象生命周期、缓存容量、线程池规模和 native 资源释放。
