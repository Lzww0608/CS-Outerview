# 9. GC 整体流程详解

面试里问"详细介绍垃圾回收整体流程"，核心考察是否理解对象从分配、晋升到被回收的完整生命周期，以及不同 GC 算法在何时、何处、如何发挥作用。

## 1. 对象生命周期总览

从分配角度，一个 Java 对象的 GC 相关路径是：

```text
new 对象
  -> 栈上分配（逃逸分析，标量替换，不进入堆）
  -> TLAB 分配（线程本地分配缓冲区，避免争用）
  -> Eden 区域分配

Eden 满 -> Minor GC / Young GC
  -> 存活对象移入 Survivor（age++）
  -> 到达晋升阈值 -> 移入 Old Gen

Old Gen 满 -> Major GC / Full GC
  -> 标记存活对象 -> 回收死亡对象 -> 可选压缩
```

不是所有对象都走完整路径。大部分小对象死在 Eden，少数进入 Survivor，能熬到老年代的更少。

## 2. 分配阶段

### 2.1 栈上分配

JVM 通过逃逸分析判断对象是否被外部方法或线程引用。如果对象不逃逸方法范围，JVM 会把对象拆成标量字段（标量替换），直接在栈帧局部变量表分配，不进入堆。

```java
void foo() {
    Point p = new Point(1, 2);  // p 不逃逸 foo
    int sum = p.x + p.y;
}
```

栈上分配的对象随方法返回自动销毁，不参与 GC，减少堆压力和 GC 停顿。

### 2.2 TLAB 分配

如果对象需要在堆上分配，JVM 会优先使用线程本地分配缓冲区。每个线程在 Eden 有一小块私有缓冲区，避免多线程分配时的 CAS 争用。

TLAB 大小动态调整。如果线程分配量大，JVM 会适当增大 TLAB；如果对象大于 TLAB 剩余空间，直接在 Eden 公共区域分配。

### 2.3 Eden 分配

大多数新对象直接分配在 Eden 区。Eden 区设计为大块连续空间，分配时只需要指针碰撞（bump-the-pointer），效率极高。

## 3. 新生代 GC（Minor GC / Young GC）

Eden 区满时触发 Minor GC。这是最频繁的 GC 事件。

### 3.1 根枚举

GC 从 GC Roots 出发，标记所有存活对象。GC Roots 包括：

1. **栈帧引用**：虚拟机栈和本地方法栈中引用的对象。
2. **静态引用**：方法区中类静态属性引用的对象。
3. **常量引用**：运行时常量池中引用的对象，例如字符串常量。
4. **JNI 引用**：Native 方法持有的全局引用。
5. **同步锁持有**：被加锁对象。
6. **JVM 内部引用**：类加载器、基本类型 Class 对象、常驻异常对象等。

### 3.2 标记-复制

新生代使用复制算法：

1. 把 Eden + From Survivor 中的存活对象复制到 To Survivor。
2. 对象年龄（age）加 1。
3. 清空 Eden 和 From Survivor。
4. 交换 From / To Survivor 角色。

复制算法在新生代的优点：大部分对象已死，只需复制少数存活对象，效率高；复制后内存连续无碎片。

### 3.3 晋升

当对象 age 达到阈值（默认 15，可通过 `-XX:MaxTenuringThreshold` 调整），或 Survivor 区无法容纳全部存活对象时，对象晋升到老年代。

动态年龄判定：如果所有年龄的对象总大小超过 Survivor 的 50%，那么年龄较大的对象会直接晋升，不一定要等到 15 岁。

## 4. 老年代 GC（Major GC / Full GC）

老年代触发 GC 的典型原因：

1. **Major GC**：老年代空间不足。
2. **Full GC**：老年代空间不足、元空间不足、System.gc() 显式触发、CMS 并发模式失败或晋升失败（Promotion Failed）。

### 4.1 标记-清除

CMS 和 G1 的初始标记、并发标记、最终标记和并发清除四个阶段，核心思路都是先标记存活对象，再回收死亡对象。

标记-清除的问题是内存碎片。大量小对象被回收后，可用空间可能分散成多个小块，无法分配连续大对象。

### 4.2 标记-压缩

Full GC 通常伴随压缩（Compact）。GC 把存活对象向堆一端移动，剩余空间成为一整块连续区域。后续分配可以直接使用指针碰撞。

## 5. 完整 GC 流程示意

```text
线程分配对象 -> [栈上分配] -> [TLAB] -> [Eden]

Eden 满:
  Minor GC:
    标记 Eden + From Survivor 存活对象
    复制到 To Survivor (age++)
    交换 From/To
    ---
    如果对象 age 达阈值 -> 晋升到 Old Gen
    如果 Survivor 溢出 -> 提前晋升到 Old Gen

Old Gen 满:
  Full GC / Major GC:
    CMS: 初始标记 -> 并发标记 -> 重新标记 -> 并发清除
    G1:  初始标记 -> 并发标记 -> 最终标记 -> 筛选回收
    Serial/Parallel: 标记 -> 清理 -> 压缩（可选）
```

## 6. 不同 GC 实现的流程差异

### 6.1 Serial / Parallel Scavenge + Parallel Old

最传统的分代流程。Minor GC 用复制算法，Full GC 用标记-压缩。全程 STW，Parallel 版本多线程执行标记和压缩。

### 6.2 CMS

CMS 追求低停顿，只做老年代回收，不与新生代 GC 同时执行。

- 初始标记（STW 短）：标记 GC Roots 直接引用的对象。
- 并发标记：从初始标记对象出发，递归遍历存活对象。用户线程仍在运行。
- 重新标记（STW 短）：修正并发标记期间用户线程修改的引用。
- 并发清除：回收死亡对象空间（不压缩）。

CMS 碎片问题可以通过 `-XX:CMSFullGCsBeforeCompaction` 在若干次 CMS 后触发一次压缩 Full GC 解决。

### 6.3 G1

G1 把堆切分成多个 Region，不严格分代连续。Region 是分配和回收的基本单位。

- 初始标记（STW 短）：标记 GC Roots 直接引用的对象。
- 并发标记：从根对象开始标记整个堆。
- 最终标记（STW 短）：处理 SATB 队列中的剩余引用。
- 筛选回收（STW）：根据 Region 的回收价值和停顿预测模型，选择一批 Region 回收（实质是复制存活对象到空闲 Region，回收后 Region 恢复空闲）。

G1 的标记-复制把存活对象整理到目标 Region，不产生碎片。

### 6.4 ZGC

ZGC 以 Region 为单位，但染色指针和读屏障让它能在并发阶段完成几乎所有操作。

- 并发标记：从 GC Roots 出发标记存活对象。
- 并发预备重分配：确定哪些 Region 要回收，创建转发表。
- 并发重分配：使用读屏障在访问时修复引用，把存活对象复制到新 Region。
- 并发重映射：修正旧引用到新地址。

ZGC 几乎不停顿，停顿时间基本不随堆大小变化。

## 7. 面试延伸

面试官问完"GC 整体流程"，常会追问几个方向：

1. **对象一定在堆上分配吗**：栈上分配（逃逸分析 + 标量替换）可以避免堆分配和 GC。
2. **大对象直接进老年代**：`-XX:PretenureSizeThreshold` 控制，避免大对象在新生代频繁复制。
3. **Concurrent Mode Failure**：CMS 并发回收阶段老年代被用户线程填满，CMS 退化为 Serial Old Full GC，停顿大幅增加。
4. **Promotion Failed**：Minor GC 后晋升对象太大，老年代无法容纳，触发 Full GC。
5. **跨代引用**：新生代 GC 需要知道老年代哪些对象引用了新生代。卡表（Card Table）把老年代分区，标记脏卡，Minor GC 只扫描脏卡避免全堆扫描。

## 8. 总结

GC 整体流程可以概括为：对象优先分配在 Eden，Eden 满触发 Minor GC 并通过复制算法回收大部分对象，少数存活对象经多次 Survivor 周转后晋升到老年代；老年代满触发 Major/Full GC，使用标记-清除或标记-压缩回收空间。不同 GC 实现在并发能力、停顿时间和碎片处理上有差异，选择取决于业务延迟要求和堆大小。
