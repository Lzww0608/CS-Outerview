# 8. JVM 引用类型详解

Java 从 JDK 1.2 开始引入了引用类型的概念，将引用分为强引用、软引用、弱引用和虚引用四种。这四种引用强度依次递减，适用于不同的内存管理和缓存场景。

## 1. 四种引用类型概述

| 引用类型 | 类名 | 回收时机 | 典型用途 |
| --- | --- | --- | --- |
| 强引用 | 普通对象引用 | 永不回收 | 普通对象引用 |
| 软引用 | `SoftReference<T>` | JVM 内存不足时回收 | 内存敏感缓存 |
| 弱引用 | `WeakReference<T>` | 下次 GC 时回收 | 规范化映射、缓存 |
| 虚引用 | `PhantomReference<T>` | 任何时候都可能回收 | 对象追踪、清理 |

```java
// 强引用（最常见）
Object obj = new Object();

// 软引用
SoftReference<Object> softRef = new SoftReference<>(new Object());

// 弱引用
WeakReference<Object> weakRef = new WeakReference<>(new Object());

// 虚引用（必须和 ReferenceQueue 一起使用）
ReferenceQueue<Object> queue = new ReferenceQueue<>();
PhantomReference<Object> phantomRef = new PhantomReference<>(new Object(), queue);
```

## 2. 强引用（Strong Reference）

### 定义

强引用是最普通的对象引用方式，只要强引用存在，垃圾收集器就永远不会回收被引用的对象。

```java
Object strongRef = new Object();  // 强引用
strongRef = null;                 // 解除强引用，对象变为可回收
```

### 特点

1. **永不回收**：只要强引用存在，即使 `OOME` 也不会回收
2. **内存泄漏风险**：大量强引用可能导致 `OutOfMemoryError`
3. **默认方式**：Java 中默认的引用类型

### 真实场景

```java
// 常见强引用导致的内存问题
public class Cache {
    private Map<String, Object> cache = new HashMap<>();  // 强引用
    
    public void put(String key, Object value) {
        cache.put(key, value);  // 永不释放，除非手动 remove
    }
}

// 改进：使用 WeakHashMap
public class ImprovedCache {
    private Map<String, Object> cache = new WeakHashMap<>();  // 弱引用
}
```

## 3. 软引用（Soft Reference）

### 定义

软引用描述还有用但非必需的对象。在 JVM 内存不足时，这些对象会被回收。适用于实现内存敏感的缓存。

### 回收时机

软引用对象在 JVM 抛出 `OutOfMemoryError` 前会被回收。是否回收取决于：
1. 堆内存是否接近上限
2. 软引用对象的存活时间
3. 垃圾收集器的具体实现

### 源码解析

```java
public class SoftReference<T> extends Reference<T> {
    
    // 每次 GC 后，ReferenceHandler 线程会检查软引用
    // 如果堆内存接近上限，清理软引用
    
    private static long clock;  // 最近一次 GC 的时间戳
    private long timestamp;     // 本次软引用创建时的时间戳
    
    public T get() {
        T o = super.get();
        if (o != null && this.timestamp != clock) {
            this.timestamp = clock;  // 更新访问时间
        }
        return o;
    }
}
```

### 使用示例

```java
import java.lang.ref.SoftReference;
import java.util.HashMap;
import java.util.Map;

public class SoftReferenceCache<K, V> {
    
    private final Map<K, SoftReference<V>> cache = new HashMap<>();
    
    public V get(K key) {
        SoftReference<V> ref = cache.get(key);
        if (ref == null) {
            return null;
        }
        V value = ref.get();
        if (value == null) {
            // 已被回收，移除
            cache.remove(key);
        }
        return value;
    }
    
    public void put(K key, V value) {
        cache.put(key, new SoftReference<>(value));
    }
}
```

### 真实场景

1. **图片缓存**：Android/JavaFX 等平台常用软引用缓存图片
2. **大对象缓存**：如文档、报表等内存敏感数据
3. **浏览器缓存**：页面资源缓存

```java
// 经典图片缓存实现
public class ImageCache {
    private final Map<String, SoftReference<Bitmap>> cache = new HashMap<>();
    
    public Bitmap getImage(String url) {
        SoftReference<Bitmap> ref = cache.get(url);
        if (ref != null) {
            Bitmap bitmap = ref.get();
            if (bitmap != null) {
                return bitmap;
            }
        }
        
        // 加载并缓存
        Bitmap bitmap = loadBitmap(url);
        cache.put(url, new SoftReference<>(bitmap));
        return bitmap;
    }
}
```

## 4. 弱引用（Weak Reference）

### 定义

弱引用比软引用更弱。无论内存是否充足，只要发生垃圾收集，被弱引用关联的对象都会被回收。

### 回收时机

弱引用对象在 **下一次 GC 时必定被回收**，与内存是否充足无关。

### 使用示例

```java
import java.lang.ref.WeakReference;

public class WeakReferenceExample {
    public static void main(String[] args) {
        WeakReference<Object> weakRef = new WeakReference<>(new Object());
        
        System.out.println("Before GC: " + weakRef.get());  // 有值
        
        System.gc();  // 建议 JVM 进行 GC
        
        System.out.println("After GC: " + weakRef.get());   // null
    }
}
```

### 真实场景

#### 4.1 WeakHashMap

`WeakHashMap` 是弱引用最典型的应用，Map 中的 Entry 在没有外部强引用时会自动被回收。

```java
import java.util.WeakHashMap;

public class WeakHashMapExample {
    public static void main(String[] args) {
        WeakHashMap<String, String> map = new WeakHashMap<>();
        
        String key = new String("key");  // 局部变量，强引用
        map.put(key, "value");
        
        System.out.println("Before: " + map.get("key"));  // value
        
        key = null;  // 解除强引用
        
        System.gc();  // key 没有强引用，会被回收
        
        // map 中的 entry 也会被自动移除
        // 注意：依赖 GC 时机
    }
}
```

#### 4.2 防止内存泄漏

```java
public class ListenerHolder {
    // 如果用普通 List，监听器对象永远不会被回收
    // private List<Listener> listeners = new ArrayList<>();
    
    // 使用弱引用，监听器没有外部引用时可以回收
    private List<WeakReference<Listener>> listeners = new CopyOnWriteArrayList<>();
    
    public void addListener(Listener listener) {
        listeners.add(new WeakReference<>(listener));
    }
    
    public void notifyListeners() {
        for (WeakReference<Listener> ref : listeners) {
            Listener listener = ref.get();
            if (listener != null) {
                listener.onEvent();
            } else {
                // 监听器已被回收，移除引用
                listeners.remove(ref);
            }
        }
    }
}
```

#### 4.3 ThreadLocal 内存泄漏预防

ThreadLocal 的 key（ThreadLocal 对象）使用弱引用，value 使用强引用：

```java
// ThreadLocal.ThreadLocalMap Entry 结构
static class Entry extends WeakReference<ThreadLocal<?>> {
    Object value;
    
    Entry(ThreadLocal<?> k, Object v) {
        super(k);
        value = v;
    }
}
```

**为什么 key 用弱引用**：
- 线程存活期间，ThreadLocal 对象可能被遗忘导致内存泄漏
- 使用弱引用后，ThreadLocal 对象没有外部引用时可以回收
- 下次 get/set 时会清理 key 为 null 的 Entry

**为什么 value 用强引用**：
- 防止 value 在使用过程中被意外回收
- 需要主动调用 `remove()` 清理

## 5. 虚引用（Phantom Reference）

### 定义

虚引用是最弱的引用类型。一个对象是否有虚引用的存在，完全不影响其生命周期。虚引用主要用于对象被回收时的追踪。

### 特点

1. **无法获取对象**：调用 `get()` 永远返回 `null`
2. **必须配合 ReferenceQueue**：用于追踪对象回收
3. **回收时通知**：在对象被回收前收到通知

### 使用示例

```java
import java.lang.ref.PhantomReference;
import java.lang.ref.ReferenceQueue;

public class PhantomReferenceExample {
    public static void main(String[] args) {
        ReferenceQueue<Object> queue = new ReferenceQueue<>();
        
        Object obj = new Object();
        PhantomReference<Object> phantomRef = new PhantomReference<>(obj, queue);
        
        System.out.println("Phantom get: " + phantomRef.get());  // 永远是 null
        
        obj = null;  // 解除强引用
        
        System.gc();  // 对象被回收后，phantomRef 会被加入 queue
        
        // 阻塞等待或轮询
        new Thread(() -> {
            while (true) {
                try {
                    Thread.sleep(1000);
                } catch (InterruptedException e) {}
                
                // 检查是否有虚引用被加入队列
                while (queue.poll() != null) {
                    System.out.println("Object was collected!");
                    // 执行清理逻辑
                }
            }
        }).start();
    }
}
```

### 真实场景

#### 5.1 直接内存（DirectByteBuffer）回收

`DirectByteBuffer` 使用虚引用追踪，当 DirectByteBuffer 被回收前，会主动释放堆外内存。

```java
// DirectByteBuffer 构造时
DirectByteBuffer(long addr, int cap, FileDescriptor fd, 
                 long cleanupInterval) {
    // ...
    // 创建虚引用，关联 Cleaner
    cleaner = Cleaner.create(this, new Deallocator(addr, cap, fd));
}

public void clean() {
    if (cleaner != null) {
        cleaner.clean();  // 释放堆外内存
    }
}
```

#### 5.2 对象生命周期追踪

```java
public class ResourceTracker {
    private final ReferenceQueue<Object> queue = new ReferenceQueue<>();
    private final Map<PhantomReference<Object>, Resource> tracked = new HashMap<>();
    
    public void track(Object obj, Resource resource) {
        PhantomReference<Object> ref = new PhantomReference<>(obj, queue);
        tracked.put(ref, resource);
    }
    
    public void processCollected() {
        PhantomReference<?> ref;
        while ((ref = queue.poll()) != null) {
            Resource resource = tracked.remove(ref);
            if (resource != null) {
                resource.close();  // 执行清理
                System.out.println("Resource cleaned");
            }
        }
    }
}
```

## 6. 为什么 JVM 需要这几种引用

### 6.1 内存管理精细化

不同场景需要不同的回收策略：

```text
强引用：普通业务对象，必须确保存在
软引用：内存敏感缓存，内存不足时释放
弱引用：规范化映射，随时可能回收
虚引用：资源清理追踪，仅用于通知
```

### 6.2 缓存设计模式

引用类型是实现各种缓存策略的基础：

```java
// 多级缓存：强引用 + 软引用 + 弱引用
public class MultiLevelCache<K, V> {
    
    // L1: 强引用缓存（永久）
    private final Map<K, V> l1Cache = new ConcurrentHashMap<>();
    
    // L2: 软引用缓存（内存敏感）
    private final Map<K, SoftReference<V>> l2Cache = new ConcurrentHashMap<>();
    
    // L3: 弱引用缓存（随时可回收）
    private final Map<K, WeakReference<V>> l3Cache = new ConcurrentHashMap<>();
}
```

### 6.3 避免内存泄漏

```java
// 场景：监听器模式
public class EventSource {
    // 错误：监听器永远不会被回收
    private final List<Listener> listeners = new ArrayList<>();
    
    // 正确：使用弱引用
    private final List<WeakReference<Listener>> listeners = new ArrayList<>();
}

// 场景：ThreadLocal
// ThreadLocalMap 用弱引用保存 ThreadLocal key
// 防止开发者忘记 remove() 时内存泄漏
```

### 6.4 资源清理

```java
// 场景：文件句柄、数据库连接等资源
public class DatabaseConnection {
    private static final ReferenceQueue<DatabaseConnection> queue = 
        new ReferenceQueue<>();
    
    // 使用虚引用追踪回收
    private static void track(PhantomReference<DatabaseConnection> ref) {
        // 在对象回收前执行清理
    }
}
```

## 7. 四种引用对比

| 特性 | 强引用 | 软引用 | 弱引用 | 虚引用 |
| --- | --- | --- | --- | --- |
| `get()` 返回值 | 对象本身 | 对象或 null | 对象或 null | 永远 null |
| GC 回收时机 | 不回收 | 内存不足时 | 下次 GC | 任何时候 |
| 是否必须配合 Queue | 否 | 否 | 否 | 是 |
| 实现类 | 无 | `SoftReference` | `WeakReference` | `PhantomReference` |
| 典型用途 | 普通对象 | 内存缓存 | 规范化映射 | 资源清理 |

## 8. 面试易错点

1. **软引用不是一定会被回收**：只有在内存不足时才回收
2. **弱引用不能"保护"对象**：它只是提供一种弱关联
3. **虚引用无法获取对象**：唯一作用是追踪回收
4. **ThreadLocal 使用弱引用是设计选择**：不是技术限制
5. **引用队列的使用**：软/弱/虚引用都可以配合 ReferenceQueue
6. **内存泄漏场景**：如果持有大量强引用，即使 OOM 也不会回收

## 9. 面试回答模板

JVM 提供了四种引用类型，从强到弱依次是强引用、软引用、弱引用和虚引用。

强引用是普通对象引用，永远不会被回收。软引用适合做内存敏感缓存，在 OOM 前会被回收。弱引用在每次 GC 时都会被回收，常用于 WeakHashMap、ThreadLocal 等场景。虚引用最弱，`get()` 永远返回 null，必须配合 ReferenceQueue 使用，主要用于对象追踪和资源清理。

设计这几种引用是为了满足不同的内存管理需求：强引用保业务对象，软引用做缓存降级，弱引用防止内存泄漏，虚引用做资源清理通知。
