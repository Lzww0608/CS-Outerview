# 5. JNI 与 Native 方法

Java 中的 `native` 方法表示方法声明在 Java 里，但具体实现由本地代码完成，常见是 C/C++ 动态库。JVM 通过 JNI（Java Native Interface）在 Java 世界和本地代码之间建立调用边界。

## 1. native 方法怎么运行

一个典型流程：

```text
Java 声明 native 方法
-> 编译生成 class
-> 加载本地动态库 .so/.dll/.dylib
-> JVM 按符号名或 RegisterNatives 绑定本地函数
-> Java 调用 native 方法
-> JVM 切换到本地调用约定，执行 C/C++ 函数
-> 本地函数通过 JNIEnv 访问 Java 对象或抛异常
-> 返回 JVM 继续执行 Java 字节码
```

示例：

```java
public class NativeDemo {
    static {
        System.loadLibrary("native_demo");
    }

    public native int add(int a, int b);
}
```

C/C++ 侧函数签名一般包含 `JNIEnv*` 和调用对象：

```cpp
#include <jni.h>

extern "C"
JNIEXPORT jint JNICALL
Java_NativeDemo_add(JNIEnv* env, jobject self, jint a, jint b) {
    return a + b;
}
```

`JNIEnv*` 是 JNI 函数表入口，用来创建字符串、访问字段、调用 Java 方法、抛异常、管理局部引用等。

## 2. 为什么需要 JNI

常见场景：

1. 复用已有 C/C++ 库，例如压缩、加密、音视频、图像处理。
2. 调用操作系统或硬件相关能力。
3. 对性能敏感的热点算法使用本地实现。
4. Java 程序嵌入已有 native SDK。
5. 大数据、AI 推理中调用底层 BLAS、CUDA、推理引擎等库。

## 3. JNI 的代价

JNI 不是普通 Java 方法调用，跨边界有额外成本：

1. Java 参数和 native 参数需要转换或 pin 住对象。
2. JVM 要处理线程状态切换、 safepoint、异常语义。
3. 本地代码不受 JVM 内存安全保护，越界、UAF、double free 会直接导致进程崩溃。
4. 本地内存不在 Java 堆里，泄漏时 Java heap 可能正常，但进程 RSS 持续上涨。
5. 频繁小粒度 JNI 调用会让边界成本超过计算收益。

因此 JNI 适合粗粒度调用：一次传入较大 buffer 或批量任务，而不是在循环里逐元素调用 native 方法。

## 4. 对象和内存注意事项

JNI 访问 Java 对象时要注意引用生命周期：

1. **局部引用**：native 方法返回后自动释放，但循环创建大量局部引用时要手动 `DeleteLocalRef`。
2. **全局引用**：跨 native 调用保存 Java 对象必须用 `NewGlobalRef`，不用时 `DeleteGlobalRef`。
3. **字符串和数组**：`GetStringUTFChars`、`GetByteArrayElements` 等获取的资源必须按对应 API 释放。
4. **线程附着**：native 线程要调用 Java，必须先 `AttachCurrentThread`，结束时 `DetachCurrentThread`。
5. **异常处理**：native 侧调用 Java 后要检查异常，异常存在时继续调用 JNI API 可能出错。

## 5. 和 JVM 内存区域的关系

`native` 方法执行时，Java 线程仍然存在，但调用栈会进入本地方法栈。本地代码申请的内存通常属于 native memory，不受 Java 堆 GC 直接管理。直接内存、JNI 分配、线程栈、类元数据等都会体现在进程 RSS 中。

排查 native 问题常用：

1. `-XX:NativeMemoryTracking=summary/detail` + `jcmd VM.native_memory`。
2. core dump + gdb 查看 native 栈。
3. ASan/Valgrind/LSan 检查 C/C++ 内存错误。
4. `pmap`、`/proc/<pid>/smaps`、容器 cgroup 指标查看 RSS。
5. JVM 崩溃日志 `hs_err_pid*.log` 分析 problematic frame。

## 6. 易错点

1. `native` 代码崩溃会让整个 JVM 进程崩溃，不只是抛 Java 异常。
2. JNI 频繁调用不一定提速，边界成本可能很高。
3. Java GC 不会自动释放 C/C++ `malloc/new` 出来的内存。
4. 保存 Java 对象到 native 全局结构时必须使用全局引用，并明确释放。
5. 本地库版本、ABI、编译器、架构不匹配会导致加载失败或运行时崩溃。

## 7. 面试回答模板

Java 的 `native` 方法通过 JNI 调用 C/C++ 动态库。Java 里声明 `native` 方法并加载本地库，JVM 通过符号名或 `RegisterNatives` 把 Java 方法绑定到 C/C++ 函数；调用时 JVM 进入本地方法栈，C/C++ 侧通过 `JNIEnv*` 访问 Java 对象、数组、字符串或抛异常。JNI 常用于复用底层库、硬件 SDK、音视频和高性能计算，但跨边界有参数转换、线程状态切换和内存安全风险。native 内存不受 Java GC 直接管理，泄漏或越界可能导致 RSS 上涨、OOM 或 JVM 崩溃。
