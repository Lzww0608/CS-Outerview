# 1. 类加载机制

Java 类加载机制是 JVM 把 `.class` 字节码加载到内存，并转换成可执行运行时数据结构的过程。一个类从被使用到可执行，通常经历：加载、验证、准备、解析、初始化、使用、卸载。

## 类加载过程

1. **加载**：
   - 通过类的全限定名获取二进制字节流。
   - 把字节流转换成方法区中的运行时数据结构。
   - 在堆中生成一个 `java.lang.Class` 对象作为访问入口。
2. **验证**：
   - 校验字节码格式、元数据、继承关系、操作数栈等是否合法。
   - 目的是保证字节码不会破坏 JVM 安全。
3. **准备**：
   - 为类变量分配内存并设置默认初始值。
   - 例如 `static int x = 10` 在准备阶段先是 `0`，不是 `10`。
4. **解析**：
   - 把常量池中的符号引用转换成直接引用。
   - 例如把类、字段、方法引用解析为实际内存地址或句柄。
5. **初始化**：
   - 执行类构造器 `<clinit>()`，包括静态变量显式赋值和静态代码块。
   - 初始化是类加载过程中真正执行业务代码的阶段。

## 什么时候触发初始化

常见主动使用场景：

1. `new` 一个对象。
2. 读取或设置类的静态字段（编译期常量除外）。
3. 调用类的静态方法。
4. 使用反射调用类。
5. 初始化子类时，父类会先初始化。
6. JVM 启动时包含 `main` 方法的主类会先初始化。

## 双亲委派模型

类加载器收到加载请求后，先把请求交给父加载器处理，父加载器无法加载时，子加载器才尝试加载。

常见类加载器：

1. **Bootstrap ClassLoader**：加载核心类库，例如 `java.lang.*`。
2. **Extension / Platform ClassLoader**：加载扩展或平台类库。
3. **Application ClassLoader**：加载应用 classpath 下的类。
4. **自定义 ClassLoader**：用于插件化、隔离加载、热部署等场景。

双亲委派的好处：

1. 避免核心类被用户自定义类覆盖，例如自定义 `java.lang.String` 不应该生效。
2. 保证同一个类在加载器层级中有稳定来源。
3. 提升安全性和类库一致性。

## 易错点

1. 准备阶段给静态变量赋默认值，初始化阶段才执行显式赋值。
2. 类的唯一性由“类全限定名 + 类加载器”共同决定，同名类被不同加载器加载后不是同一个类。
3. 双亲委派可以被破坏，例如 SPI、Tomcat、OSGi、热部署框架会使用不同的加载策略。
4. 静态常量如果是编译期常量，访问它通常不会触发定义该常量的类初始化。
5. 类加载是线程安全的，同一个类的 `<clinit>()` 在多线程下只会被 JVM 保证执行一次。

## 真实场景

1. **插件系统**：每个插件使用独立 ClassLoader，避免依赖冲突。
2. **Web 容器**：Tomcat 为不同 Web 应用提供隔离的类加载器，防止应用之间类冲突。
3. **热部署**：通过丢弃旧 ClassLoader 并创建新 ClassLoader 加载新类。
4. **排查冲突**：遇到 `ClassCastException` 但类名相同时，要检查是否由不同 ClassLoader 加载。
