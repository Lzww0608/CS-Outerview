# 信号量和互斥锁的区别

信号量和互斥锁都是并发控制工具，但语义不同。互斥锁解决“同一时间只有一个线程进入临界区”，信号量解决“最多允许 N 个线程同时占用某类资源”。

## 1. 互斥锁

互斥锁的核心是所有权和排他访问：

1. 初始状态通常是未加锁。
2. 一个线程 `lock` 成功后拥有锁。
3. 其他线程再 `lock` 会阻塞或失败。
4. 持有锁的线程负责 `unlock`。

适用场景：

1. 保护共享变量、容器、状态机。
2. 保护一组数据不变量，例如 map 和 size 必须一致。
3. 临界区内部只能有一个执行者。

## 2. 信号量

信号量内部是计数器：

1. `P/wait/acquire` 让计数器减 1，计数器为 0 时阻塞。
2. `V/post/release` 让计数器加 1，唤醒等待者。
3. 初始值为 N 时，表示最多 N 个并发许可。

适用场景：

1. 连接池最多允许 N 个连接被借出。
2. 限制同时访问某个下游服务的并发数。
3. 生产者消费者里表示“已有多少个可消费元素”或“还有多少个空槽”。
4. 操作系统中用于资源计数和线程同步。

## 3. 对比

| 维度 | 互斥锁 | 信号量 |
| --- | --- | --- |
| 核心语义 | 排他访问 | 资源计数/并发许可 |
| 允许并发数 | 通常 1 个 | 可以是 N 个 |
| 所有权 | 通常要求持有者解锁 | 不一定强调同一线程 release |
| 保护对象 | 共享数据不变量 | 有限数量资源 |
| 常见风险 | 忘记解锁、死锁、锁粒度过大 | release 次数错误、许可泄漏、计数失衡 |

二值信号量初始值为 1，看起来像互斥锁，但仍然不完全等价。互斥锁通常有明确所有权、可配合 RAII 和调试检查；信号量更偏“许可证数量”，release 次数多一次就可能把并发上限放大。

## 4. 示例

互斥锁保护共享 map：

```cpp
std::mutex m;
std::unordered_map<int, int> mp;

void update(int k, int v) {
    std::lock_guard<std::mutex> lk(m);
    mp[k] = v;
}
```

信号量限制最多 10 个并发请求：

```cpp
#include <semaphore>

std::counting_semaphore<10> sem(10);

void call_downstream() {
    sem.acquire();
    try {
        // call rpc
    } catch (...) {
        sem.release();
        throw;
    }
    sem.release();
}
```

真实代码中 release 应该用 RAII guard 包起来，避免异常路径漏释放。

## 5. 面试回答模板

互斥锁强调排他访问，适合保护共享数据和临界区，同一时刻通常只有一个线程持有；信号量强调计数，适合控制有限资源或限制并发，初始值为 N 就最多允许 N 个线程通过。二值信号量可以模拟互斥，但不完全等价，因为 mutex 通常有所有权语义，要求持有者释放，而 semaphore 更像许可证计数，release 次数错误会破坏并发上限。
