# Google tcmalloc 设计与实现详解

## 1. 概述

tcmalloc（Thread-Caching Malloc）是 Google 开发的高性能内存分配器，旨在替代 glibc 的 malloc，解决多线程环境下的锁竞争问题。tcmalloc 是 Go runtime 垃圾回收器（首次 GC 版本）和许多 Google 内部服务的基础。

## 2. 核心设计思想

tcmalloc 的核心思想是**分层缓存 + 无锁分配**：

```
┌─────────────────────────────────────────────────────────────┐
│                         Thread Cache                         │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐          │
│  │Thread 1 │ │Thread 2 │ │Thread 3 │ │Thread N │          │
│  │Cache    │ │Cache    │ │Cache    │ │Cache    │          │
│  └────┬────┘ └────┬────┘ └────┬────┘ └────┬────┘          │
└───────┼────────────┼───────────┼───────────┼───────────────┘
        │            │           │           │
        ▼            ▼           ▼           ▼
┌─────────────────────────────────────────────────────────────┐
│                     Central Cache                            │
│  每个 Size Class 一个 free list，支持批量转移                │
└───────┬─────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────────┐
│                       Page Heap                              │
│  连续页面组成 span，按大小组织成树或链表                     │
└───────┬─────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────────┐
│                    Operating System                          │
│  mmap/brk 系统调用                                          │
└─────────────────────────────────────────────────────────────┘
```

### 2.1 分配层级

| 层级 | 组件 | 分配单位 | 锁类型 | 延迟 |
| --- | --- | --- | --- | --- |
| L1 | Thread Cache | 对象 | 无锁 | ~10ns |
| L2 | Central Cache | 对象 | Per-class 锁 | ~100ns |
| L3 | Page Heap | 页面/span | 全局锁 | ~1μs |
| L4 | OS | 大块内存 | 系统调用 | ~μs-ms |

### 2.2 Size Class 设计

tcmalloc 将内存请求映射到预定义的 size class：

```cpp
// 简化示例
SizeClass[] = {
    8, 16, 24, 32, 40, 48, 56, 64,       // 8字节递增
    80, 96, 112, 128,                     // 16字节递增
    192, 256, 320, 384, 448, 512,         // 64字节递增
    768, 1024, 1536, 2048,                // 512字节递增
    3072, 4096,                           // 1KB 递增
    // ...更大尺寸
};

// 请求大小 → Size Class 映射
size_t GetSizeClass(size_t size) {
    if (size <= 1024) {
        return ((size + 7) / 8) * 8;  // 8字节对齐
    } else if (size <= 8192) {
        return ((size + 127) / 128) * 128;  // 128字节对齐
    }
    // ...更多映射规则
}
```

**内部碎片控制**：每个 size class 的对象大小固定，碎片率 = `(class_size - avg_request) / class_size`

## 3. Thread Cache 详解

### 3.1 核心结构

每个线程有自己的 Thread Cache（ThreadLocal Storage）：

```cpp
struct ThreadCache {
    // 每个 size class 对应一个 free list
    FreeList* list_[kNumClasses];
    
    // 快速路径：缓存最后一个使用的 size class
    int last_size_class_;
    
    // 增长阈值：超过此值归还对象到 Central
    size_t max_size_;
};

// 分配核心逻辑
void* ThreadCache::Allocate(size_t size) {
    size_t cl = SizeClass(size);
    
    // 快速路径：直接弹出
    if (!list_[cl].Empty()) {
        return list_[cl].Pop();
    }
    
    // 慢速路径：从 Central 批量获取
    return FetchFromCentralCache(cl);
}
```

### 3.2 Free List 实现

```cpp
class FreeList {
 private:
    void* head_;  // 链表头
    size_t length_;  // 长度
    size_t max_length_;  // 最大长度（超过则归还）
    
 public:
    void* Pop() {
        // O(1) 操作，无需锁
        void* result = head_;
        head_ = *(void**)head_;  // next 指针存在对象自身
        length_--;
        return result;
    }
    
    void Push(void* ptr) {
        // O(1) 操作，无需锁
        *(void**)ptr = head_;  // next 指针存在对象自身
        head_ = ptr;
        length_++;
    }
};
```

### 3.3 无锁设计的关键

- **每个线程独立缓存**：不同线程从不操作彼此的 cache
- **对象内存储 next 指针**：利用已分配空间，无额外元数据
- **批量操作**：一次从 Central 获取多个对象，分摊同步开销

### 3.4 动态调整

```cpp
// tcmalloc 会根据使用情况动态调整每个线程的 cache 大小
void ThreadCache::Scavenge() {
    if (total_size_ > max_size_) {
        // 归还一半对象到 Central
        for (int i = 0; i < kNumClasses; i++) {
            while (list_[i].Length() > 1 && total_size_ > max_size_ / 2) {
                void* obj = list_[i].Pop();
                CentralFreeList[i].Push(obj);
                total_size_ -= ClassSize(i);
            }
        }
    }
}
```

## 4. Central Cache 详解

### 4.1 核心结构

Central Cache 是所有线程共享的，每个 size class 有一个 CentralFreeList：

```cpp
class CentralFreeList {
 private:
    pthread_mutex_t lock_;  // 每个 size class 独立锁
    void* head_;  // 非空 span 的 object 链表头
    Span* empty_;  // 空的 span 链表
    Span* nonempty_;  // 非空的 span 链表
    
 public:
    // 从 span 获取对象（可能需要从 Page Heap 获取新 span）
    void* FetchFromHeap(size_t cl);
    
    // 批量归还对象到 span
    void ReleaseToHeap(void* batch, size_t n);
};
```

### 4.2 Span 管理

Span 是连续内存页的抽象：

```cpp
struct Span {
    uintptr_t start;      // 起始页面号
    uintptr_t length;     // 页面数量
    void* objects;        // 可用对象链表头
    
    CentralFreeList* owner;  // 所属 Central Cache
    
    // 交叉引用：object → span
    Span* next;  // 链表链接
    Span* prev;
};
```

### 4.3 Object-Span 映射

```cpp
// 页面号 → Span 查找（使用数组或树）
Span* PageHeap::GetSpan(uintptr_t page) {
    return page_to_span_[page];  // O(1) 查找
}

// Object 地址 → Span
Span* GetSpanFromObject(void* obj) {
    uintptr_t page = reinterpret_cast<uintptr_t>(obj) >> kPageShift;
    return GetSpanByPage(page);
}
```

### 4.4 批量转移机制

```cpp
// Central → ThreadCache 批量转移
const int kBatchSize = 32;

void* CentralFreeList::FetchBatch(int size_class, void** batch, int n) {
    pthread_mutex_lock(&lock_);
    
    if (list_[size_class].Empty()) {
        // 从 Page Heap 获取新 span
        FetchFromPageHeap(size_class);
    }
    
    // 批量弹出 n 个对象
    for (int i = 0; i < n && !list_[size_class].Empty(); i++) {
        batch[i] = list_[size_class].Pop();
    }
    
    pthread_mutex_unlock(&lock_);
    return batch;
}
```

## 5. Page Heap 详解

### 5.1 核心结构

Page Heap 管理大块内存，按 span 大小组织：

```cpp
class PageHeap {
 private:
    // 按 span 大小分类的链表
    Span free_[kMaxPages];  // free_[n] = n 页面 span 的链表
    Span large_;  // > kMaxPages 页面的大 span 链表
    
    // 页面到 span 的映射
    std::map<uintptr_t, Span*> pagemap_;
    
 public:
    // 分配 n 页的 span
    Span* AllocateSpan(size_t n);
    
    // 释放 span
    void FreeSpan(Span* span);
};
```

### 5.2 最佳适应分配

```cpp
Span* PageHeap::AllocateSpan(size_t n) {
    // 1. 首先找恰好 n 页的 span（最佳适应）
    if (!free_[n].Empty()) {
        return free_[n].Pop();
    }
    
    // 2. 找更大的 span，分割
    for (size_t i = n + 1; i < kMaxPages; i++) {
        if (!free_[i].Empty()) {
            Span* big = free_[i].Pop();
            // 分割成 n 页 + (i-n) 页
            Span* rest = SplitSpan(big, n);
            free_[i - n].Push(rest);  // 剩余部分放回
            return big;  // 返回 n 页部分
        }
    }
    
    // 3. 向 OS 申请新内存
    return RequestFromOS(n);
}
```

### 5.3 Span 合并（伙伴系统简化版）

释放 span 时，尝试与相邻空闲 span 合并：

```cpp
void PageHeap::FreeSpan(Span* span) {
    // 尝试向前合并
    while (span->start > 0) {
        Span* buddy = GetSpanByPage(span->start - 1);
        if (buddy->free && buddy->length == span->length) {
            // 合并
            RemoveSpan(buddy);
            span = MergeSpans(buddy, span);
        } else {
            break;
        }
    }
    
    // 放回对应链表
    free_[span->length].Push(span);
}
```

## 6. 内存申请/释放流程

### 6.1 分配流程（小对象 ≤ 32KB）

```
malloc(100B)
    │
    ▼
ThreadCache.Allocate(100)
    │
    ├── SizeClass(100) = 8  // 实际分配 104B
    │
    ├── FreeList[8].Pop() ──→ 命中 ──→ 返回对象
    │
    └── 命中失败 ──→ FetchFromCentral(8, batch=32)
                        │
                        ├── Central.Lock()
                        │
                        ├── FreeList[8].PopBatch(32)
                        │
                        │   └── 如果空 ──→ PageHeap.AllocateSpan(1)
                        │                   │
                        │                   └── OS: mmap()
                        │
                        ├── Central.Unlock()
                        │
                        └── 返回对象 + 缓存 31 个
```

### 6.2 释放流程

```
free(ptr)
    │
    ▼
ThreadCache::Release(ptr)
    │
    ├── SizeClass = GetSizeClass(ptr)
    │
    ├── FreeList[cl].Push(ptr)
    │
    ├── Length > MaxLength?
    │       │
    │       └── 是 ──→ ReturnToCentral(cl, batch=32)
    │                   │
    │                   ├── Central.Lock()
    │                   │
    │                   ├── Central.FreeList[cl].PushBatch(batch)
    │                   │
    │                   └── Central.Unlock()
    │
    └── 返回
```

### 6.3 大对象分配（> 32KB）

```
malloc(100KB)
    │
    ▼
直接进入 PageHeap
    │
    ├── PageHeap.Allocate(25 pages)
    │
    ├── 按 best-fit 找空闲 span
    │
    ├── 找不到 ──→ mmap() 申请
    │
    └── 返回 span 起始地址
```

## 7. 性能优化技巧

### 7.1 减少锁竞争

| 优化 | 原理 | 效果 |
| --- | --- | --- |
| Per-thread cache | 线程本地分配 | 95%+ 分配无锁 |
| Per-class 锁 | Central 锁细分 | 减少锁粒度 |
| 批量操作 | 一次获取多个对象 | 分摊同步成本 |
| 无锁链表 | 对象内存储 next | 无额外元数据 |

### 7.2 缓存局部性

```cpp
// 批量获取时优先取靠近的对象
void* FetchFromCentral(int cl) {
    // Central 可能返回不同 span 的对象
    // 这些对象可能在内存上不连续
    
    // 优化：尽可能从同一个 span 分配
    Span* span = GetSpanFromObject(top);
    // ... 保证 span 内局部性
}
```

### 7.3 内存碎片控制

```
内部碎片：
- Size class 粒度控制（8B/16B/32B 递增）
- 最大碎片率通常 < 10%

外部碎片：
- Span 合并机制
- Span 分割机制
- 大对象直接走 PageHeap
```

## 8. 与 jemalloc 对比

| 特性 | tcmalloc | jemalloc |
| --- | --- | --- |
| 分层 | ThreadCache → Central → PageHeap | Per-thread Arena → Central → Base |
| 锁策略 | Per-class Central 锁 | Per-arena 锁 |
| Size Class | ~90 个 | ~220 个 |
| 碎片控制 | Span 合并 | Region + Bin |
| 适用场景 | Google 内部服务 | Firefox、Redis、Rust |

## 9. 面试高频问题

### Q1: tcmalloc 如何减少锁竞争？

**回答要点**：
- 每个线程有独立的 Thread Cache，95%+ 小对象分配无锁
- Central Cache 按 size class 分锁，锁粒度细
- 批量操作分摊同步开销
- 大对象直接走 PageHeap，避免 Central 瓶颈

### Q2: tcmalloc 的三级缓存结构是什么？

**回答要点**：
- L1 Thread Cache：线程本地，O(1) 无锁分配
- L2 Central Cache：全局共享，按 size class 组织，批量转移
- L3 Page Heap：管理页面/span，按大小组织

### Q3: 为什么 Thread Cache 要有最大大小限制？

**回答要点**：
- 避免一个线程占用过多内存
- 内存紧张时，scavenge 线程会回收部分对象
- 动态调整：使用多的线程获得更大 cache
- 归还机制：超过 max_length 时归还一半到 Central

### Q4: Span 的作用是什么？

**回答要点**：
- Span 是连续内存页的抽象
- 支持跨页管理，便于合并
- Object-Span 映射实现 O(1) 查找对象所属 span
- 支持 span 分割和合并

### Q5: tcmalloc 如何处理大对象？

**回答要点**：
- 大于 32KB 直接走 PageHeap
- 按 best-fit 找空闲 span
- 找不到时向 OS 申请（mmap）
- 释放直接归还 PageHeap

## 10. 总结

tcmalloc 是教科书级别的高性能内存分配器：

1. **分层缓存**：ThreadCache → CentralCache → PageHeap → OS
2. **无锁分配**：线程本地缓存，95%+ 操作无锁
3. **批量转移**：减少同步次数，分摊开销
4. **Size Class**：固定大小分配，减少碎片
5. **Span 管理**：连续页面抽象，支持合并和分割

tcmalloc 的核心洞察：**多线程程序的内存分配模式通常是"每个线程倾向于分配相似大小的对象"**，利用这一特点，通过线程本地缓存实现了极致的分配性能。
