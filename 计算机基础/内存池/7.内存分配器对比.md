# 内存分配器对比：tcmalloc vs jemalloc vs glibc malloc

## 1. 概述

本文对主流内存分配器进行深度对比，包括 Google tcmalloc、Facebook jemalloc 和 glibc malloc（ptmalloc）。理解它们的差异有助于在实际项目中做出合理选择。

## 2. 基础概念回顾

### 2.1 内存分配器的基本职责

```
┌─────────────────────────────────────────────────────────────────┐
│                      应用程序                                    │
│   malloc() ─── free() ─── realloc()                            │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                      内存分配器                                  │
│   ┌──────────┐  ┌──────────┐  ┌──────────┐                    │
│   │ tcmalloc │  │ jemalloc │  │ ptmalloc │                    │
│   └──────────┘  └──────────┘  └──────────┘                    │
└─────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────┐
│                      操作系统                                    │
│   brk() ──── mmap() ──── munmap()                            │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 核心性能指标

| 指标 | 说明 |
| --- | --- |
| **吞吐量** | 单位时间内完成的分配/释放次数 |
| **延迟** | 单次分配/释放的耗时 |
| **内存利用率** | 实际使用 vs 分配的比例 |
| **可伸缩性** | 多线程下的性能衰减程度 |
| **碎片率** | 内部碎片 + 外部碎片的综合指标 |

## 3. 架构对比

### 3.1 ptmalloc（glibc malloc）

glibc 默认分配器，采用**边界标签（Boundary Tags）**技术：

```
┌─────────────────────────────────────────────────────────────────┐
│                         Arena 0                                 │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │  Chunk 0  │  Chunk 1  │  Chunk 2  │  Chunk 3  │ ...  │   │
│   │  [size|prev|next|fd|bk]                                 │   │
│   └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │                    Fastbins (小对象)                      │   │
│   │  单链表，LIFO，只合并，不分割                             │   │
│   └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │                    Unsortedbin                          │   │
│   │  刚释放的 chunk 最近使用优先                             │   │
│   └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │                    Smallbins                             │   │
│   │  固定大小，双链表，精确匹配                              │   │
│   └─────────────────────────────────────────────────────────┘   │
│                                                                 │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │                    Largebins                             │   │
│   │  按大小排序，双链表，支持最佳匹配                        │   │
│   └─────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────┘
```

**特点**：
- 单一全局堆，所有线程共享
- Arena 数量固定 = 2 * CPU 核心数 + 1
- 主线程 arena 永不释放
- 使用边界标签合并空闲块

### 3.2 tcmalloc（Google）

三级缓存 + PageHeap：

```
┌─────────────────────────────────────────────────────────────────┐
│                         Thread Cache                            │
│   ┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐           │
│   │ T0     │  │ T1     │  │ T2     │  │ Tn     │           │
│   │ ├─SC0  │  │ ├─SC0  │  │ ├─SC0  │  │ ├─SC0  │           │
│   │ ├─SC1  │  │ ├─SC1  │  │ ├─SC1  │  │ ├─SC1  │           │
│   │ └─...  │  │ └─...  │  │ └─...  │  │ └─...  │           │
│   └────────┘  └────────┘  └────────┘  └────────┘           │
└───────────────────────────┬─────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│                       Central Cache                             │
│   ┌────────┐  ┌────────┐  ┌────────┐                         │
│   │ SC0    │  │ SC1    │  │ SC2    │  ...                    │
│   │ (lock) │  │ (lock) │  │ (lock) │                         │
│   └────────┘  └────────┘  └────────┘                         │
└───────────────────────────┬─────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│                       Page Heap                                 │
│   ┌──────────┬──────────┬──────────┬──────────┬──────────┐    │
│   │Span 1page│Span 2page│Span 4page│Span 8page│   ...   │    │
│   └──────────┴──────────┴──────────┴──────────┴──────────┘    │
└─────────────────────────────────────────────────────────────────┘
```

**特点**：
- 每个线程独立 Thread Cache
- Central Cache 按 Size Class 分锁
- Span 概念管理连续页面
- ~90 个 Size Class

### 3.3 jemalloc（Facebook）

多 Arena + Extent 架构：

```
┌─────────────────────────────────────────────────────────────────┐
│                      Thread Cache (TCache)                       │
│   ┌────────┐  ┌────────┐  ┌────────┐  ┌────────┐           │
│   │ T0     │  │ T1     │  │ T2     │  │ Tn     │           │
│   │ ├─bin0 │  │ ├─bin0 │  │ ├─bin0 │  │ ├─bin0 │           │
│   │ ├─bin1 │  │ ├─bin1 │  │ ├─bin1 │  │ ├─bin1 │           │
│   │ └─...  │  │ └─...  │  │ └─...  │  │ └─...  │           │
│   └────────┘  └────────┘  └────────┘  └────────┘           │
└───────────────────────────┬─────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│                      Arena 0     Arena 1     Arena 2         │
│   ┌────────────────┐  ┌────────────────┐  ┌────────────────┐ │
│   │ bins[NBINS]   │  │ bins[NBINS]   │  │ bins[NBINS]   │ │
│   │ ├─run(32B)   │  │ ├─run(32B)   │  │ ├─run(32B)   │ │
│   │ ├─run(64B)   │  │ ├─run(64B)   │  │ ├─run(64B)   │ │
│   │ └─...        │  │ └─...        │  │ └─...        │ │
│   ├─dirty_ep     │  ├─dirty_ep     │  ├─dirty_ep     │ │
│   ├─reserve_ep   │  ├─reserve_ep   │  ├─reserve_ep   │ │
│   └────────────────┘  └────────────────┘  └────────────────┘ │
└───────────────────────────┬─────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│                       Base (Basealloc)                          │
│   ┌─────────────────────────────────────────────────────────┐   │
│   │              Huge Extent Tree                            │   │
│   │              (独立 mmap/unmap)                          │   │
│   └─────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────┘
```

**特点**：
- 多个 Arena，线程绑定
- ~220 个 Size Class（更精细）
- Chunk = 4MB 基本单元
- Decay 机制定期 purge dirty extent

## 4. 核心机制对比

### 4.1 线程本地缓存

| 特性 | ptmalloc | tcmalloc | jemalloc |
| --- | --- | --- | --- |
| **线程本地** | Per-thread heap (sub-heap) | Thread Cache | TCache |
| **缓存大小** | 受 arena 限制 | 动态增长，最大 2MB | 动态调整 |
| **无锁程度** | 部分无锁 | 95%+ 无锁 | 90%+ 无锁 |
| **回收机制** | 合并后归还 heap | Scavenge 线程 | TCache flush |

### 4.2 Size Class 设计

```cpp
// ptmalloc: 约 30 个 size class
Smallbin: 16, 32, 48, 64, 80, 96, 112, 128, 144, 160...
Largebin: 512, 1024, 1536, 2048...

// tcmalloc: ~90 个 size class
8, 16, 24, 32, 40, 48, 56, 64, 80, 96, 112, 128...
增长规律：8B → 16B → 32B → 64B 递增

// jemalloc: ~220 个 size class
8, 16, 24, 32, 40, 48, 56, 64, 72, 80, 88, 96, 104...
增长规律：越细分越好
```

**内部碎片率对比**：

```
ptmalloc:   最大 ~12%
tcmalloc:   最大 ~10%
jemalloc:   最大 ~8% (更精细)
```

### 4.3 锁策略

```
ptmalloc:
┌─────────────┐
│  Arena 0   │ ◄── 所有绑定线程共享
│  T0, T1, T2│
└─────────────┘
┌─────────────┐
│  Arena 1   │
│  T3, T4, T5│
└─────────────┘
问题：同一 arena 内线程仍竞争

tcmalloc:
┌─────────────────────────────────────────────┐
│  Thread Cache (T0)  ──────────────────── 无锁
│  Thread Cache (T1)  ──────────────────── 无锁
│  ...
└─────────────────────────────────────────────┘
┌────────┬────────┬────────┐
│Central │Central │Central │
│ SC0.Lock│ SC1.Lock│ SC2.Lock│ ◄── Per-class 锁
└────────┴────────┴────────┘

jemalloc:
┌─────────┬─────────┬─────────┐
│ Arena 0 │ Arena 1 │ Arena 2 │
│ (CPU 0) │ (CPU 1) │ (CPU 2) │
│ Bin.Lock│ Bin.Lock│ Bin.Lock│ ◄── Per-bin 锁
└─────────┴─────────┴─────────┘
优势：线程绑定到 CPU，减少跨 NUMA 访问
```

### 4.4 内存管理粒度

| 特性 | ptmalloc | tcmalloc | jemalloc |
| --- | --- | --- | --- |
| **基本单元** | Chunk（最小 4KB+） | Page（4KB） | Chunk（4MB） |
| **大对象阈值** | >128KB | >32KB | >Smax（~14KB） |
| **管理结构** | 边界标签 | Span 树 | Extent + Region |
| **合并机制** | 边界标签合并 | Span 合并 | Extent 合并 |

### 4.5 系统调用策略

```cpp
// ptmalloc: 保守策略
if (需要更多空间) {
    if (top chunk 够用) {
        split(top);           // 分割 top chunk
    } else {
        brk()/mmap();         // 向 OS 申请
    }
}

// tcmalloc: 批量预取
void* AllocateSpan(size_t n) {
    if (free_[n].非空) return pop;  // 精确匹配
    
    // 找更大的分割
    for (i = n+1; i < MAX; i++) {
        if (free_[i].非空) {
            big = pop(i);
            rest = split(big, n);    // 分割
            push(free_[i-n], rest);  // 剩余放回
            return big;
        }
    }
    mmap();  // 最后手段
}

// jemalloc: 多层复用
void* chunk_alloc(size_t size) {
    // 1. Dirty extent 复用（最优先）
    ep = extent_alloc(dirty_ep, size);
    if (ep) return ep;
    
    // 2. Reserve extent
    ep = extent_alloc(reserve_ep, size);
    if (ep) return ep;
    
    // 3. Base (mmap)
    return base_chunk_alloc();
}
```

## 6. 碎片控制对比

### 6.1 内部碎片控制

```
ptmalloc:
- Size class 粗粒度
- 16B 递增（>64B 后更大）
- 最大碎片: (16-8)/16 = 50% ❌

tcmalloc:
- Size class 较细
- 8B 递增（前期）
- 最大碎片: <10% ✅

jemalloc:
- Size class 极细（~220 个）
- 8B/16B/32B 混合递增
- 最大碎片: <8% ✅✅
```

### 6.2 外部碎片控制

```
ptmalloc:
- 使用边界标签合并
- 合并后放回对应 bin
- 缺点：合并成本高，可能产生新的外部碎片

tcmalloc:
- Span 合并机制
- 大对象独立 span
- 缺点：Span 合并可能不充分

jemalloc:
- Extent 合并机制
- Dirty extent 优先复用（减少碎片产生）
- Decay 机制定期清理
- 优点：主动管理碎片 ✅
```

### 6.3 Decay vs Scavenge

```cpp
// tcmalloc Scavenge（被动）
void ThreadCache::Scavenge() {
    // 只在线程缓存超过阈值时触发
    if (total_size_ > max_size_) {
        // 归还一半到 Central
        ReturnToCentral();
    }
}

// jemalloc Decay（主动）
void arena_decay() {
    // 定期检查并清理 dirty extent
    // 避免 dirty extent 积累
    while (dirty_count > dirty_target) {
        extent_purge(arena, purge_size);
    }
}
```

## 8. 常见问题

### Q1: 为什么 Redis 使用 jemalloc 而不是 tcmalloc？

**回答要点**：
- Redis 是长期运行服务，碎片控制关键
- jemalloc 的 Decay 机制主动管理内存
- Redis 多线程模型（6.0+）适合 jemalloc 的 Arena
- jemalloc 的统计工具更丰富

### Q2: tcmalloc 和 jemalloc 哪个更快？

**回答要点**：
- 小对象（<1KB）：tcmalloc 稍快（Thread Cache 更精简）
- 大对象（>32KB）：jemalloc 更快（Huge 直接 mmap）
- 多线程扩展性：两者相近
- 内存利用率：jemalloc 更好

### Q3: 如何判断内存碎片问题？

**回答要点**：
- 观察 RSS vs VSS 比例
- jemalloc 提供 `mallctl` 统计
- tcmalloc 提供 Heap Profile
- 长期监控内存增长趋势

### Q4: 可以混用分配器吗？

**回答要点**：
- 同一进程内强烈不建议
- LD_PRELOAD 只能替换整个 malloc
- 不同分配器管理不同内存区域会有问题
- 特殊情况：某些库静态链接自己的分配器

### Q5: Go/Rust 的内存分配和这些有什么关系？

**回答要点**：
- Go 使用 tcmalloc 风格的 mcache（goroutine 本地）
- Rust 默认使用 jemalloc
- GC 语言 vs 手动管理：设计哲学不同
- 但核心思想（分层缓存）是一致的

## 9. 面试高频问题

### Q1: 内存分配器的核心性能指标有哪些？

**回答要点**：
- 吞吐量：单位时间分配次数
- 延迟：单次分配耗时
- 可伸缩性：多线程下性能保持
- 内存利用率：碎片率
- 内存增长：长期运行内存增长情况

### Q2: tcmalloc 和 jemalloc 的核心区别是什么？

**回答要点**：
- Thread Cache vs Arena：架构不同
- Central Cache vs Per-bin：Arena 更分散
- ~90 vs ~220 Size Class：jemalloc 更精细
- Decay vs Scavenge：jemalloc 主动管理
- Chunk 大小：4MB vs 4KB

### Q3: 为什么 ptmalloc 在多线程下性能差？

**回答要点**：
- 单一全局堆结构
- 所有线程竞争同一个 arena 锁
- Sub-heap 合并成本高
- 没有 Thread Cache

### Q4: 如何选择内存分配器？

**回答要点**：
- 长期运行服务 → jemalloc
- 高吞吐量服务 → tcmalloc
- 简单场景 → 系统默认
- 内存敏感 → jemalloc
- 性能敏感 → tcmalloc

### 10.1 选择建议

| 场景 | 推荐 | 备选 |

### 10.2 核心对比

| 特性 | ptmalloc | tcmalloc | jemalloc |

### 10.3 最终建议

1. **大多数场景**：直接使用系统默认分配器
2. **高并发服务**：考虑 tcmalloc 或 jemalloc
3. **长期运行**：优先选择 jemalloc
4. **性能敏感**：通过压测选择
5. **不要过早优化**：除非明确是分配器瓶颈
