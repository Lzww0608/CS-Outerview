# Facebook jemalloc 设计与实现详解

## 1. 概述

jemalloc（Jason Evans Malloc）最初由 Jason Evans 为 FreeBSD 开发，后被 Facebook 采纳并大规模优化，是 Redis、Rust 等项目的默认内存分配器。jemalloc 以其出色的内存碎片控制和良好的多核可伸缩性著称。

## 2. 核心设计思想

jemalloc 的核心设计理念是**分离请求（Allocation Sizes）与管理粒度（Allocation Units）**，通过多层级 arenas 和精致的 size class 设计实现高效分配。

```
┌─────────────────────────────────────────────────────────────────────────┐
│                           Thread 1                                       │
│  thread.tcache[bin0] ─┐                                                 │
│  thread.tcache[bin1] ─┼──→ 每个线程有 thread cache                     │
│  thread.tcache[bin2] ─┘     (类似 tcmalloc，但更轻量)                   │
└─────────────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                           Arena 0 (CPU 0)                               │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐                              │
│  │  Extent   │  │  Extent   │  │  Extent   │  ← 由 extent 组成的 chunk │
│  │  (run)    │  │  (run)    │  │  (run)    │                            │
│  └─────┬─────┘  └─────┬─────┘  └─────┬─────┘                            │
│        │               │               │                                 │
│        ▼               ▼               ▼                                 │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐                              │
│  │  Bin 0   │  │  Bin 1   │  │  Bin 2   │  ← 每个 extent 被划分为       │
│  │ (32B×n) │  │ (64B×n) │  │ (128B×n)│     多个 region                 │
│  └──────────┘  └──────────┘  └──────────┘                              │
└─────────────────────────────────────────────────────────────────────────┘
                              │
                              ▼
┌─────────────────────────────────────────────────────────────────────────┐
│                           Central (Base)                                 │
│  所有 arenas 共享的元数据管理                                           │
└─────────────────────────────────────────────────────────────────────────┘
```

### 2.1 关键概念

| 概念 | 说明 |
| --- | --- |
| **Chunk** | 4MB（或可配置）连续内存块，jemalloc 的基本分配单元 |
| **Extent** | 连续内存区域，可能是整个 chunk 或其子集 |
| **Region** | 从 extent 分割出来的小块内存，最终分配给用户 |
| **Run** | Extent 被划分为多个 run，run 包含同尺寸的 region |
| **Bin** | 管理同尺寸 run 的结构 |

### 2.2 Size Class 设计

jemalloc 有 ~220 个 size class，比 tcmalloc 更精细：

```cpp
// 简化示意
SizeClass[] = {
    // 小尺寸：8 字节递增
    8, 16, 24, 32, 40, 48, 56, 64, 72, 80, 88, 96, 104, 112, 120, 128,
    
    // 中小尺寸：16 字节递增
    144, 160, 176, 192, 208, 224, 240, 256,
    
    // 中等尺寸：32 字节递增
    288, 320, 352, 384, 416, 448, 480, 512,
    
    // 中大尺寸：64 字节递增
    576, 640, 704, 768, 832, 896, 960, 1024,
    
    // 大尺寸：128 字节递增
    1152, 1280, 1408, 1536, 1664, 1792, 1920, 2048,
    
    // 更大尺寸：256/512/1024 字节递增
    ...
    
    // Huge: 直接 mmap
    8MB, 16MB, 32MB, ...
};
```

**分组策略**：
- **Small**: ≤ Smax (通常 14KB)，走 bin + run 路径
- **Large**: > Smax 但 < Huge，直接分配 extent
- **Huge**: > 某个阈值，直接 mmap，独立管理

## 3. Arena 详解

### 3.1 为什么需要 Arena？

Arena 是 jemalloc 并发性能的关键：

```
传统 malloc:                     jemalloc:
┌─────────────────────┐          ┌──────────┬──────────┬──────────┐
│     malloc          │          │ Arena 0  │ Arena 1  │ Arena 2  │
│     lock ───┐       │          │ ┌──────┐│ ┌──────┐│ ┌──────┐│
│     allocate│       │          │ │T0,T3 ││ │T1,T4 ││ │T2,T5 ││
│     unlock └───────┘          │ └──────┘│ └──────┘│ └──────┘│
└─────────────────────┘          └──────────┴──────────┴──────────┘
        ↑                              ↑           ↑           ↑
   所有线程竞争                       CPU 0       CPU 1       CPU 2
```

**线程绑定策略**：
- 线程首次 malloc 时绑定到某个 arena（轮询或 CPU 亲和）
- 同一 arena 的线程共享锁，但锁被分散到多个 arena
- 理论上 N 个 arena 能将锁竞争降低 N 倍

### 3.2 Arena 结构

```cpp
struct arena_s {
    // 基础锁，保护 arena 核心结构
    malloc_mutex_t        lock;
    
    // 所有分配的 chunk 列表
    rb_tree_t             chunk_tree;
    
    // 每个 size class 对应一个 bin
    bin_t                 bins[NBINS];
    
    // 可用的 dirty extent 列表
    extent_list_t         dirty_ep;
    
    // 保留 extent 列表
    extent_list_t         reserve_ep;
    
    // 统计数据
    arena_stats_t         stats;
};
```

### 3.3 多 Arena 配置

```bash
# 设置 arena 数量 = CPU 核心数 * 2（经验值）
export MALLOC_CONF="narenas:tpN"
```

经验公式：`narenas = CPU * 2` 或 `narenas = CPU * 4`

## 4. Chunk 管理

### 4.1 Chunk 是分配单元

```cpp
// Chunk 大小通常为 4MB
#define CHUNK_SIZE      (4U << 20)  // 4MB
#define CHUNK_MASK      (~(CHUNK_SIZE - 1))
```

```
┌─────────────────────────────────────────────────────────────────┐
│                         4MB Chunk                               │
├─────────────┬─────────────┬─────────────┬─────────────┬─────────┤
│  Run 0      │  Run 1      │  Run 2      │  Extent     │  ...    │
│  (32B×n)    │  (64B×n)    │  (128B×n)   │  (large)    │         │
└─────────────┴─────────────┴─────────────┴─────────────┴─────────┘
```

### 4.2 Chunk 分配流程

```cpp
void* chunk_alloc(size_t size) {
    // 1. 尝试从 dirty extent 分配
    extent_t* ep = extent_alloc(arena->dirty_ep, size);
    if (ep != NULL) {
        return extent_addr_get(ep);
    }
    
    // 2. 尝试从 reserve extent 分配
    ep = extent_alloc(arena->reserve_ep, size);
    if (ep != NULL) {
        return extent_addr_get(ep);
    }
    
    // 3. 向 base（mmap）申请新 chunk
    ep = base_chunk_alloc();
    if (ep == NULL) {
        return NULL;
    }
    
    // 4. 注册到 chunk 树
    chunk_register(ep);
    return extent_addr_get(ep);
}
```

### 4.3 Extent 与 DSS

jemalloc 使用 **DSS（Dynamic Spatial Subdivision）** 管理 extent：

```
可用内存来源（按优先级）：
1. dirty extent（已释放的 chunk，还有未使用的 region）
2. reserve extent（预保留的 extent）
3. base（通过 mmap 向 OS 申请）

优势：
- 优先复用 dirty extent，减少向 OS 的系统调用
- 避免过早归零内存（性能优化）
- 延迟归零：只在实际使用时归零
```

## 5. Bin 与 Run 详解

### 5.1 Bin 结构

Bin 管理同尺寸的所有 run：

```cpp
struct bin_s {
    malloc_mutex_t        lock;           // 每个 bin 有独立锁
    extent_t*             current;        // 当前可用 run
    extent_list_t         slabs_full;     // 已满的 run
    extent_list_t         slabs_nonfull;  // 未满的 run
    
    // Run 状态
    size_t                reg_size;       // region 大小
    size_t                reg0_offset;    // 第一个 region 偏移
};
```

### 5.2 Run 结构

Run 是 extent 的子集，包含同尺寸的 region：

```
┌─────────────────────────────────────────────────────────────────┐
│                          4MB Run                                 │
├─────────┬─────────┬─────────┬─────────┬─────────┬─────────┬──────┤
│ Region  │ Region  │ Region  │ Region  │ Region  │ Region  │ ...  │
│ 0       │ 1       │ 2       │ 3       │ 4       │ 5       │      │
├─────────┴─────────┴─────────┴─────────┴─────────┴─────────┴──────┤
│ Bitmap: 1=已分配, 0=可用                                          │
└─────────────────────────────────────────────────────────────────┘
```

### 5.3 Region 分配

```cpp
void* region_alloc(extent_t* run, size_t size) {
    // 1. 在 run 的 bitmap 中找空闲位
    int bit = bitmap_find_zero(run->bitmap, run->nregs);
    if (bit < 0) {
        return NULL;  // run 已满
    }
    
    // 2. 标记为已分配
    bitmap_set(run->bitmap, bit);
    
    // 3. 计算 region 地址
    void* ptr = (char*)extent_addr_get(run) + run->reg0_offset + 
                bit * run->reg_size;
    
    // 4. 更新统计
    run->nfree--;
    
    return ptr;
}
```

## 6. Thread Cache（TCache）

### 6.1 TCache 结构

jemalloc 的 TCache 比 tcmalloc 更轻量：

```cpp
struct tcache_s {
    // 每组 size class 对应一个 tbins 条目
    tcache_bin_t*          tbins[NTBINS];
    
    // 大尺寸的独立缓存
    tcache_bin_t           large_tbins[NTLABINS];
    
    // GC 计数
    uint64_t               gc_ewait;
    
    // 关联的 arena
    arena_t*               arena;
};
```

### 6.2 分配流程

```
malloc(100B)
    │
    ▼
┌─────────────────────────────────────┐
│ 1. 计算 size class                  │
│    sc = sz_index(100) → 128B       │
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│ 2. TCache 快速路径                  │
│    if (tcache.tbins[sc].ncached > 0)│
│       return tcache.tbins[sc].pop()│
└─────────────────────────────────────┘
    │
    ▼
┌─────────────────────────────────────┐
│ 3. Central → TCache 批量填充        │
│    tcache_fill(sc, batch=20)       │
└─────────────────────────────────────┘
```

### 6.3 TCache 刷新

```cpp
void tcache_flush(tcache_t* tcache) {
    // 定期将缓存归还到 arena
    for (int i = 0; i < NTBINS; i++) {
        tcache_bin_t* tbin = &tcache->tbins[i];
        while (tbin->ncached > 0) {
            void* ptr = tbin->pop();
            // 归还很复杂，需要找到对象大小
            extent_t* run = ptr_to_run(ptr);
            arena_bin_dalloc(tcache->arena, run, ptr);
        }
    }
}
```

## 7. Large 和 Huge 分配

### 7.1 Large 分配（> Smax 但 < Huge）

Large 对象直接从 extent 分配：

```
┌─────────────────────────────────────────────────────────────────┐
│                      4MB Chunk                                  │
├─────────────────────────────────────────────────────────────────┤
│ ┌─────────────────────────────────────────────────────────────┐ │
│ │                     Large Extent                            │ │
│ │                     Size = 200KB                            │ │
│ └─────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

### 7.2 Huge 分配（> Huge 阈值）

Huge 对象走独立的 huge extent 树：

```cpp
// Huge extent 独立管理，释放时立即返回 OS
void huge_alloc(size_t size) {
    // 直接 mmap
    void* ptr = mmap(NULL, size, PROT_READ|PROT_WRITE,
                     MAP_PRIVATE|MAP_ANONYMOUS, -1, 0);
    
    // 注册到 huge extent 树
    huge_extent_t* hep = huge_extent_insert(ptr, size);
    return ptr;
}

void huge_dalloc(void* ptr) {
    // 从 huge extent 树移除
    huge_extent_t* hep = huge_extent_remove(ptr);
    
    // 立即 munmap
    munmap(ptr, hep->size);
}
```

## 8. 内存碎片控制

### 8.1 内部碎片

jemalloc 通过精细的 size class 控制内部碎片：

```
Size Class 粒度：
- 8B~128B: 每 8B 一个 class
- 128B~512B: 每 16B 一个 class  
- 512B~4KB: 每 32B 一个 class
- ...

最大内部碎片率 ≈ (class_size - avg_request) / class_size
通常 < 10%
```

### 8.2 外部碎片控制

jemalloc 的外部碎片控制策略：

| 策略 | 说明 |
| --- | --- |
| **Extent 合并** | 相邻空闲 extent 合并 |
| **Dirty Extent 复用** | 优先从 dirty 分配，减少碎片 |
| **Large 对象专用** | 大对象分配后不碎片化 |
| **定期 Purge** | 定期归零和释放 dirty extent |

### 8.3 Decay 机制

```cpp
// jemalloc 使用 decay 机制控制 dirty extent
void arena_decay() {
    // 计算应该 purge 的空间
    size_t npages = arena_dirty_count(arena);
    
    // 线性衰减：每次释放后衰减一点
    if (arena->purging || npages > arena->dirty_max) {
        // 开始 purge
        size_t to_purge = npages - arena->dirty_target;
        extent_purge(arena, to_purge);
    }
}
```

## 9. 与 tcmalloc 对比

| 特性 | jemalloc | tcmalloc |
| --- | --- | --- |
| **Arena 数量** | 多个 arena，线程绑定 | 单一 Central Cache |
| **锁粒度** | Per-bin + Per-arena 锁 | Per-class Central 锁 |
| **Size Class** | ~220 个，更精细 | ~90 个 |
| **TCache** | 轻量级，每个 size class 一个计数 | 每个 size class 独立 free list |
| **Chunk 大小** | 4MB，可配置 | 4KB（页大小） |
| **碎片控制** | Decay + Extent 合并 | Span 合并 |
| **适用场景** | Redis, Rust, Firefox | Google 内部服务 |
| **Huge 对象** | 独立 huge extent 树，释放即 munmap | PageHeap 管理 |

## 10. 面试高频问题

### Q1: jemalloc 的 Arena 机制是什么？

**回答要点**：
- Arena 是内存管理的基本单元
- 每个 arena 独立管理 chunk、bin、extent
- 线程绑定到 arena，减少锁竞争
- 通常配置 arena 数量 = CPU * 2 或 * 4

### Q2: jemalloc 如何控制内存碎片？

**回答要点**：
- 精细 size class 控制内部碎片（~220 个 class）
- Extent 合并减少外部碎片
- Dirty extent 优先复用
- Decay 机制定期 purge

### Q3: jemalloc 和 tcmalloc 的核心区别？

**回答要点**：
- Arena vs Central Cache：jemalloc 多 arena，tcmalloc 单一 Central
- 锁策略：jemalloc per-bin 锁，tcmalloc per-class 锁
- Size class 数量：jemalloc ~220，tcmalloc ~90
- Huge 处理：jemalloc 独立 huge tree，tcmalloc PageHeap

### Q4: TCache 在 jemalloc 中如何工作？

**回答要点**：
- 每个线程有自己的 TCache
- 小对象优先从 TCache 分配
- 缓存满时批量归还到 arena
- 比 tcmalloc 更轻量

### Q5: jemalloc 的 chunk 和 extent 是什么关系？

**回答要点**：
- Chunk 是 4MB 基本分配单元
- Chunk 可划分为多个 extent
- Extent 可以是整个 chunk 或其子集
- Large 对象可能独占一个 extent

## 11. 总结

jemalloc 是 Facebook 级别的高性能内存分配器：

1. **多 Arena 架构**：线程绑定，减少锁竞争
2. **精细 Size Class**：~220 个 class，减少内部碎片
3. **Extent 管理**：灵活的内存粒度管理
4. **TCache 轻量化**：每个线程独立的轻量缓存
5. **Decay 机制**：定期 purge dirty extent
6. **Huge 独立**：大对象走独立 mmap 路径

jemalloc 的核心洞察：**内存碎片是长期运行服务的主要敌人**，通过 Arena 隔离、Extent 合并、Decay 机制等组合拳，实现了长期稳定、低碎片运行。
