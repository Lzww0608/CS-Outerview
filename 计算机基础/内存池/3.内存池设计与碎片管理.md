# 内存池设计与碎片管理

设计内存池时，要先明确目标：是固定大小对象的高速分配，还是支持任意大小申请释放；是单线程使用，还是高并发服务；是请求级生命周期一次性释放，还是长期运行并需要控制碎片。

## 1. 基本接口

最小接口通常是：

```cpp
class MemoryPool {
public:
    void* allocate(size_t size);
    void deallocate(void* ptr, size_t size);
};
```

生产实现还需要：

1. 对齐，例如 8/16 字节对齐。
2. 记录块大小，避免调用方传错 size。
3. 扩容策略，池不够时向 OS 申请新 span/page。
4. 线程安全策略，单线程无锁、多线程加锁或线程本地缓存。
5. 调试能力，例如 double free、越界写、泄漏统计。

## 2. 固定大小对象池

固定大小对象池最简单，适合频繁创建相同类型对象。

核心结构是 free list：

```text
pool memory:
+-------+-------+-------+-------+
| block | block | block | block |
+-------+-------+-------+-------+

free_list -> block3 -> block1 -> block0
```

分配时从 free list 头部弹出一个块；释放时把块插回 free list。

优点：

1. 分配和释放都是 `O(1)`。
2. 块大小固定，外部碎片很低。
3. 元数据可以复用空闲块本身存储 `next` 指针。

缺点：

1. 只能服务固定大小或固定类型对象。
2. 请求大小远小于块大小时有内部碎片。
3. 多线程共享同一个 free list 时需要锁或无锁栈。

## 3. 可变大小内存池

可变大小申请常用 size class：

```text
8B, 16B, 32B, 64B, 128B, 256B, ...
```

请求 `size` 时向上取整到某个 size class，从对应 free list 分配。释放时根据块头记录的 size class 放回对应链表。

```cpp
struct BlockHeader {
    uint32_t sizeClass;
    uint32_t flags;
};
```

这种设计类似 slab、tcmalloc、jemalloc 的基本思想：小对象走分级缓存，大对象直接向 OS 申请整页或多页。

## 4. 碎片管理

### 4.1 内部碎片

内部碎片来自“分配块大于请求大小”。控制方式：

1. 设计合理 size class，避免跨度过大。
2. 小对象按 8/16 字节粒度增长，大对象按页粒度增长。
3. 对超大对象直接 `mmap`，不用小块池承接。

### 4.2 外部碎片

外部碎片来自空闲块分散，无法满足大块连续申请。控制方式：

1. **伙伴系统**：按 2 的幂管理块，释放时和相邻 buddy 合并。
2. **边界标记**：在块头/块尾记录大小和空闲状态，释放时合并相邻空闲块。
3. **按页/span 管理**：整页只服务某个 size class，空闲页达到阈值后归还中央池或 OS。
4. **生命周期分区**：请求级短生命周期对象使用 region pool，一次性释放。

## 5. 并发优化

高并发内存池通常避免所有线程抢同一把锁：

1. 每个线程维护 thread cache，小对象本地分配无锁。
2. thread cache 不够时向 central cache 批量申请。
3. central cache 再向 page heap 申请 span。
4. 跨线程释放可以进入远程释放队列，延迟归还到所属线程或中央池。

这也是 tcmalloc、jemalloc 这类通用分配器能提升多线程服务性能的关键。

## 6. 易错点

1. 内存池不是一定更省内存，size class 设计不好会增加内部碎片。
2. 固定对象池不能直接拿来处理任意大小申请。
3. 释放接口必须能找到块大小，否则无法放回正确 free list。
4. 多线程下 free list 要考虑 ABA、锁竞争和 false sharing。
5. 内存池绕过通用分配器后，调试工具可能更难定位越界和泄漏，需要额外埋点。

## 7. 面试回答模板

我会先确认内存池服务的对象大小和并发模型。固定大小对象可以用 free list，分配时弹出空闲块，释放时插回链表，`O(1)` 且外部碎片低。可变大小申请可以按 size class 分级，每个尺寸维护 free list，小对象从池里取，大对象直接走 `mmap`。碎片方面，内部碎片靠合理尺寸等级控制，外部碎片靠伙伴系统、边界标记合并、按页/span 管理和生命周期分区控制。高并发下再加 thread cache 和 central cache，减少全局锁竞争。
