# 常见数据结构总览

面试里问“有哪些数据结构”时，不适合只背名字。更好的回答方式是按线性结构、哈希结构、树、堆、图和概率数据结构分类，并说明核心操作复杂度、适用场景和取舍。

## 线性结构

| 数据结构 | 核心特点 | 常见复杂度 | 适用场景 |
| --- | --- | --- | --- |
| 数组 | 连续内存，随机访问快 | 按下标访问 `O(1)`，中间插删 `O(n)` | 顺序存储、缓存友好、二分查找 |
| 动态数组 | 容量不足时扩容搬迁 | 尾插摊还 `O(1)` | C++ `vector`、Java `ArrayList` |
| 链表 | 节点离散，通过指针连接 | 已知节点插删 `O(1)`，查找 `O(n)` | LRU、频繁插删、队列节点 |
| 栈 | 后进先出 | 入栈/出栈 `O(1)` | 函数调用栈、括号匹配、单调栈 |
| 队列 | 先进先出 | 入队/出队 `O(1)` | BFS、生产消费队列 |
| 双端队列 | 两端都可插删 | 两端操作 `O(1)` | 滑动窗口、任务调度 |

## 链表首尾插入和双链表

单链表节点通常只保存 `next` 指针。它的优势是已知前驱节点时插入、删除只改指针，缺点是不能反向遍历，也无法在 `O(1)` 内找到某个节点的前驱。

### 1. 单链表首尾插入

头插：

```cpp
node->next = head;
head = node;
```

头插只需要改新节点的 `next` 和 `head`，无论链表多长都是 `O(1)`。

尾插要分情况：

1. **没有 tail 指针**：需要从 `head` 遍历到尾节点，时间 `O(n)`。
2. **维护 tail 指针**：直接 `tail->next = node; tail = node;`，时间 `O(1)`。
3. **空链表**：插入第一个节点时，`head` 和 `tail` 都要指向新节点。

易错点是只说“链表插入是 `O(1)`”。更准确地说：**已知插入位置的前驱节点时是 `O(1)`；如果还要先查找位置，查找成本是 `O(n)`**。

### 2. 双链表

双链表节点保存 `prev` 和 `next`，可以双向移动。插入节点时要同时维护前后两个方向的指针：

```cpp
node->prev = cur;
node->next = cur->next;
if (cur->next != nullptr) {
    cur->next->prev = node;
}
cur->next = node;
```

双链表的优势：

1. 已知节点时，可以 `O(1)` 删除该节点，不必先找前驱。
2. 支持从尾部向前遍历。
3. 适合 LRU、双端队列、缓存淘汰链表、内核等待队列等场景。

代价是每个节点多一个指针，插入删除要维护更多关系，错误更新可能造成断链或环。工程里常用 dummy head/tail 哨兵节点减少空链表、头尾节点的特殊分支。

## 哈希结构

哈希表用 hash 函数把 key 映射到桶，平均查找、插入、删除接近 `O(1)`。

典型应用：

1. 缓存索引：`key -> node`。
2. 去重和计数。
3. 数据分片和路由。
4. 字典、集合、对象属性表。

需要关注：

1. 哈希冲突解决方式。
2. 装载因子和扩容。
3. 哈希函数质量。
4. 并发访问时的锁粒度或无锁设计。

## 常见 C++ 容器查找复杂度

面试问“几种容器查找数据的时间复杂度”时，要区分按下标访问、按 key 查找和按 value 扫描。

| 容器 | 底层结构 | 按下标/队首访问 | 按值或 key 查找 | 适用场景 |
| --- | --- | --- | --- | --- |
| `vector` | 连续动态数组 | 下标访问 `O(1)` | 未排序按值查找 `O(n)`；排序后二分 `O(log n)` | 随机访问多、尾部追加多 |
| `array` | 固定连续数组 | 下标访问 `O(1)` | 未排序 `O(n)`；排序后二分 `O(log n)` | 固定大小、栈上对象 |
| `deque` | 分段连续数组 | 下标访问 `O(1)`，两端操作 `O(1)` | 按值查找 `O(n)` | 双端队列、滑动窗口 |
| `list` | 双向链表 | 不支持随机访问 | `O(n)` | 已知位置频繁插删 |
| `forward_list` | 单向链表 | 不支持随机访问 | `O(n)` | 极简链表、只向前遍历 |
| `map/set` | 红黑树 | 不支持下标随机访问 | 按 key 查找 `O(log n)` | 有序遍历、范围查询 |
| `unordered_map/unordered_set` | 哈希表 | 不支持有序下标访问 | 平均 `O(1)`，最坏 `O(n)` | 高频等值查询、去重、计数 |
| `priority_queue` | 堆 | 取堆顶 `O(1)` | 查任意元素 `O(n)` | Top K、定时器、优先调度 |

易错点：

1. `vector` 的下标访问是 `O(1)`，但按值查找不是 `O(1)`。
2. `map` 查询是 `O(log n)`，因为通常基于红黑树；`unordered_map` 平均 `O(1)`，但哈希冲突严重时可能退化。
3. `priority_queue` 只能高效访问堆顶，不能高效查找任意元素。
4. 排序后的 `vector` 可以二分查找，但插入维护有序性需要移动元素，成本是 `O(n)`。

## 如何突破基于比较的 `O(log n)` 查找

有序数组或平衡搜索树的查找，本质上基于比较模型，通常下界是 `O(log n)`。如果想突破这个限制，需要利用额外约束或换模型：

1. **哈希表**：平均 `O(1)` 查找，但依赖哈希函数质量，最坏情况可能退化。
2. **直接寻址表**：key 范围很小且稠密时，直接用 key 当下标，严格 `O(1)`，空间成本可能很高。
3. **Bitmap**：适合整数集合存在性判断，`O(1)` 判断是否出现，不能直接存复杂对象。
4. **Trie**：字符串查找复杂度是 `O(L)`，`L` 是字符串长度，不直接依赖集合规模 `n`。
5. **布隆过滤器**：空间更小，判断“不存在”准确，判断“存在”可能误判。

因此“能不能比 `logn` 更快”不能只回答能或不能，要说明是否仍在比较模型内。如果仍然只能比较大小，平衡树和二分查找就是 `O(log n)` 级别；如果可以使用哈希、下标、位图或字符路径，就可以在特定场景下降到平均或严格 `O(1)`、`O(L)`。

## 树结构

| 数据结构 | 特点 | 适用场景 |
| --- | --- | --- |
| 二叉搜索树 | 左小右大，退化时可能成链 | 教学基础 |
| AVL 树 | 严格平衡，查询稳定 | 读多、需要更严格平衡 |
| 红黑树 | 近似平衡，插删旋转较少 | `map/set`、内核调度结构 |
| B/B+ 树 | 多路平衡树，节点适配页大小 | 数据库索引、文件系统 |
| Trie | 按字符路径组织 | 前缀匹配、词典、自动补全 |
| 线段树/树状数组 | 维护区间信息 | 区间查询、单点/区间更新 |

面试易错点：`map` 通常是红黑树，`unordered_map` 是哈希表；数据库索引常用 B+ 树，不是普通二叉搜索树，因为 B+ 树更适合磁盘页和范围扫描。

## 树遍历复杂度

树遍历通常会访问每个节点一次，所以时间复杂度一般是 `O(n)`，`n` 是节点数。

| 遍历方式 | 时间复杂度 | 额外空间复杂度 |
| --- | --- | --- |
| 前序/中序/后序 DFS | `O(n)` | 递归栈 `O(h)`，最坏 `O(n)` |
| 层序遍历 BFS | `O(n)` | 队列 `O(w)`，`w` 是最大层宽 |
| Morris 中序遍历 | `O(n)` | `O(1)`，会临时改动树指针 |

注意：

1. 平衡二叉树高度 `h = O(log n)`，递归栈通常是 `O(log n)`。
2. 退化成链表的二叉树高度 `h = O(n)`，递归栈可能达到 `O(n)`。
3. 二叉搜索树查找、插入、删除复杂度是 `O(h)`，平衡时 `O(log n)`，退化时 `O(n)`。
4. “遍历一棵树”的复杂度不要回答成 `O(log n)`，`O(log n)` 通常是平衡搜索树单次查找的复杂度。

## 堆

堆是一棵满足堆序性质的完全二叉树，常用数组实现。

1. 最大堆：父节点大于等于子节点。
2. 最小堆：父节点小于等于子节点。

复杂度：

1. 取堆顶 `O(1)`。
2. 插入 `O(log n)`。
3. 删除堆顶 `O(log n)`。
4. 建堆 `O(n)`。

常见应用：

1. Top K。
2. 优先队列。
3. 定时器。
4. 多路归并。

## 图

图用于描述对象之间的关系。

常见表示：

1. 邻接矩阵：适合稠密图，查边 `O(1)`，空间 `O(V^2)`。
2. 邻接表：适合稀疏图，空间 `O(V+E)`。

常见算法：

1. BFS/DFS：连通性、层序、拓扑基础。
2. Dijkstra：非负权最短路。
3. Floyd：多源最短路，适合点少的稠密图。
4. Kruskal/Prim：最小生成树。
5. 拓扑排序：依赖调度、编译顺序。

## 概率和工程数据结构

1. **布隆过滤器**：空间小，可能误判存在，不会误判不存在。
2. **跳表**：多级索引链表，平均 `O(log n)`，实现比平衡树简单。
3. **LRU/LFU**：缓存淘汰结构，通常组合哈希表、链表、堆或多级链表。
4. **位图 Bitmap**：适合稠密整数集合、状态标记和快速去重。
5. **并查集**：维护动态连通性，路径压缩后接近 `O(1)`。

## 面试回答模板

常见数据结构可以按类别说：线性结构有数组、链表、栈、队列、双端队列；哈希结构有哈希表和集合；树结构有 BST、AVL、红黑树、B/B+ 树、Trie、线段树、树状数组；堆常用于优先队列和 Top K；图用邻接表或邻接矩阵表示；工程里还有布隆过滤器、跳表、Bitmap、LRU/LFU、并查集等。回答时要结合复杂度和场景，例如数组随机访问快但中间插删慢，链表插删快但缓存局部性差，哈希表平均 `O(1)` 但有冲突和扩容，B+ 树适合数据库范围查询。
