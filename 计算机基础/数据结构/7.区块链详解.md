# 区块链详解：从原理到应用

## 一、区块链概述

### 1.1 什么是区块链

区块链（Blockchain）是一种分布式账本技术，通过密码学方法将数据打包成区块，并通过哈希指针将区块串联成链，形成一个不可篡改、可追溯的账本。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  区块链核心特性：                                            │
│                                                             │
│  1. 去中心化：没有单一机构控制，数据存储在多个节点            │
│  2. 不可篡改：历史数据无法修改，只能追加                    │
│  3. 可追溯：所有交易记录完整保存                          │
│  4. 共识机制：通过共识算法保证数据一致性                   │
│  5. 智能合约：可自动执行的程序                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 三、密码学基础

### 3.1 哈希函数

```c
// 区块链使用的哈希函数：SHA-256
#include <openssl/sha.h>

uint8_t hash[SHA256_DIGEST_LENGTH];

SHA256((uint8_t*)data, strlen(data), hash);

// 特性：
// 1. 确定性：相同输入产生相同输出
// 2. 快速计算：计算速度快
// 3. 单向性：无法从输出反推输入
// 4. 抗碰撞：找不到两个不同输入产生相同输出
// 5. 雪崩效应：输入微小变化导致输出大幅变化
```

### 3.2 数字签名

```c
// 公钥加密，私钥签名
struct KeyPair {
    uint8_t public_key[32];   // 公钥
    uint8_t private_key[64];  // 私钥
};

// 签名
uint8_t sign(uint8_t* message, KeyPair* keys) {
    // 1. 计算消息哈希
    uint8_t hash[SHA256_DIGEST_LENGTH];
    SHA256(message, strlen(message), hash);
    
    // 2. 使用私钥签名
    return ecdsa_sign(hash, keys->private_key);
}

// 验证
bool verify(uint8_t* message, uint8_t* signature, uint8_t* public_key) {
    // 1. 计算消息哈希
    uint8_t hash[SHA256_DIGEST_LENGTH];
    SHA256(message, strlen(message), hash);
    
    // 2. 使用公钥验证签名
    return ecdsa_verify(hash, signature, public_key);
}
```

## 四、共识机制

### 4.1 工作量证明（PoW）

```c
// PoW 原理：找到满足条件的 nonce
struct Block {
    uint8_t prev_hash[32];
    Transaction* txs;
    uint32_t timestamp;
    uint32_t difficulty;
    uint32_t nonce;
};

bool is_valid_proof(Block* block) {
    uint8_t hash[32];
    SHA256(block, sizeof(Block), hash);
    
    // 检查哈希前 N 位是否都是 0
    // N 由 difficulty 决定
    for (int i = 0; i < block->difficulty / 8; i++) {
        if (hash[i] != 0) return false;
    }
    return true;
}

// 挖矿过程
uint32_t mine(Block* block) {
    while (!is_valid_proof(block)) {
        block->nonce++;
    }
    return block->nonce;
}
```

### 4.2 权益证明（PoS）

```c
// PoS 原理：根据持有的代币和币龄选择验证者
struct Validator {
    uint64_t stake;       // 质押数量
    uint64_t coin_age;   // 币龄（持有时间 × 数量）
    uint64_t last_block; // 最后验证的区块
};

// 选择验证者
Validator* select_validator(Validator* validators[], int count) {
    // 币龄越大，被选中的概率越高
    uint64_t total_weight = 0;
    for (int i = 0; i < count; i++) {
        validators[i]->weight = validators[i]->stake * validators[i]->coin_age;
        total_weight += validators[i]->weight;
    }
    
    uint64_t rand = random(total_weight);
    uint64_t cumulative = 0;
    for (int i = 0; i < count; i++) {
        cumulative += validators[i]->weight;
        if (cumulative >= rand) {
            return validators[i];
        }
    }
    return NULL;
}
```

### 5.2 Layer 1 vs Layer 2

```text
Layer 1（主链）：
┌─────────────────────────────────────────────────────────────┐
│  - 主链本身                                             │
│  - 例如：Bitcoin, Ethereum                               │
│  - 所有交易都在主链结算                                  │
└─────────────────────────────────────────────────────────────┘

Layer 2（扩容方案）：
┌─────────────────────────────────────────────────────────────┐
│  - 在主链之上构建                                         │
│  - 例如：Lightning Network, Rollup                        │
│  - 大部分交易在 Layer 2 处理，主链只结算最终状态           │
└─────────────────────────────────────────────────────────────┘
```

## 七、智能合约

### 7.1 以太坊智能合约

```solidity
// Solidity 智能合约示例：代币合约
pragma solidity ^0.8.0;

contract Token {
    mapping(address => uint256) public balanceOf;
    mapping(address => mapping(address => uint256)) public allowance;
    
    event Transfer(address indexed from, address indexed to, uint256 value);
    
    function transfer(address to, uint256 value) public returns (bool) {
        require(balanceOf[msg.sender] >= value, "Insufficient balance");
        balanceOf[msg.sender] -= value;
        balanceOf[to] += value;
        emit Transfer(msg.sender, to, value);
        return true;
    }
    
    function approve(address spender, uint256 value) public returns (bool) {
        allowance[msg.sender][spender] = value;
        return true;
    }
    
    function transferFrom(address from, address to, uint256 value) public returns (bool) {
        require(balanceOf[from] >= value, "Insufficient balance");
        require(allowance[from][msg.sender] >= value, "Not approved");
        balanceOf[from] -= value;
        balanceOf[to] += value;
        allowance[from][msg.sender] -= value;
        emit Transfer(from, to, value);
        return true;
    }
}
```

## 八、面试常见问题

### Q1: 区块链为什么是不可篡改的？

因为每个区块都包含前一个区块的哈希值，如果修改历史区块，该区块的哈希会变化，导致后续所有区块的哈希都不匹配。要篡改，需要重新计算所有后续区块的工作量证明，成本极高。

### Q2: PoW 和 PoS 的区别？

PoW 通过计算难题消耗算力来竞争记账权，资源消耗大但安全性高；PoS 根据持有代币数量和币龄选择验证者，资源消耗小但存在富者愈富的问题。

### Q3: 区块链的"不可能三角"是什么？

"不可能三角"指去中心化、安全性、可扩展性三者不可兼得：
- 公链选择去中心化+安全性 → 牺牲可扩展性（Bitcoin, Ethereum）
- 联盟链选择去中心化+可扩展性 → 牺牲安全性
- 中心化+可扩展性+安全性 → 传统数据库

### Q4: 智能合约有什么风险？

1. 代码漏洞风险（DAO 攻击）
2. 预言机风险（外部数据不可信）
3. 升级风险（合约不可修改）
4. 治理风险（社区分裂）

## 九、总结

1. **区块链定义**：分布式账本，通过哈希链串联区块
2. **核心特性**：去中心化、不可篡改、可追溯、共识机制、智能合约
3. **共识机制**：PoW（工作量证明）、PoS（权益证明）
4. **应用场景**：金融支付、供应链、版权保护、电子政务、医疗健康
5. **智能合约**：自动执行的程序，运行在区块链上
