# MEV 概念与应用及 Sandwich Attack 原理

## 1. 问题背景

MEV（Miner Extractable Value / Maximal Extractable Value）是区块链领域的重要概念，指通过操纵交易排序可提取的最大价值。Sandwich Attack 是最常见的 MEV 攻击形式，严重损害普通用户利益。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  MEV 时空：                                                │
│                                                             │
│  用户交易 ──► Pending Pool ──► 区块打包                   │
│                   │                                         │
│                   ▼                                         │
│            矿工/验证者选择排序                             │
│                   │                                         │
│                   ▼                                         │
│         MEV 提取机会出现！                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 |
|------|------|
| 用户交易滑点增加 | 被夹在两笔交易中间 |
| gas 费用异常 | 攻击者抬高 gas 抢夺资源 |
| DEX 价格操纵 | 价格被临时拉高或压低 |
| 套利机会消失快 | 攻击者抢先执行 |

---

## 3. 影响范围

- DEX 用户（Uniswap, SushiSwap 等）
- DeFi 协议交互者
- NFT  mint 操作
- 跨DEX套利者

### 4.3 Sandwich Attack 完整原理

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Sandwich Attack 流程：                                    │
│                                                             │
│  时间线：                                                  │
│  T0: 受害者发起大额 Swap（100 ETH → Token A）            │
│                                                             │
│  T1: 攻击者检测到这笔交易                                 │
│      → 抢先用更高 gas 发起买入                             │
│      → 推高 Token A 价格                                   │
│                                                             │
│  T2: 受害者的交易执行                                      │
│      → 受害者以更高价格买入（差价为攻击者所得）           │
│                                                             │
│  T3: 攻击者立即卖出 Token A                               │
│      → 赚取利润 = 受害者损失                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.4 数学建模

```solidity
// Sandwich Attack 数学分析

// 假设：
// - 受害者买入前，池子状态：x_token0, y_token0
// - 受害者意图买入 Δy
// - 受害者设置滑点 s (例如 1%)

// 无攻击时的执行价格
function getExecutionPrice(uint256 x, uint256 y, uint256 deltaY) 
    pure 
    returns (uint256) 
{
    // x * y = k
    uint256 newX = (x * y) / (y - deltaY);
    return (newX - x) / deltaY;  // 价格 = deltaX / deltaY
}

// 攻击者利润计算
contract SandwichAttack {
    // 受害者大额交易
    uint256 victimDeltaY = 1000 ether;
    uint256 victimSlippage = 0.01;  // 1%
    
    // 攻击者买入量（通常小于受害者）
    uint256 attackerAmount = 10 ether;
    
    function calculateProfit(
        uint256 poolX,
        uint256 poolY,
        uint256 victimDeltaY,
        uint256 attackerDeltaY
    ) public pure returns (uint256 profit) {
        // 步骤1：攻击者买入（推高价格）
        uint256 x1 = poolX + attackerDeltaY;
        uint256 y1 = (poolX * poolY) / x1;
        uint256 attackerBuyPrice = attackerDeltaY / (poolY - y1);
        
        // 步骤2：受害者买入（以更高价格）
        uint256 x2 = x1;
        uint256 y2 = y1 - victimDeltaY;
        uint256 victimBuyPrice = (x2 - x1) / victimDeltaY;
        
        // 步骤3：攻击者卖出
        uint256 x3 = (x2 * y2) / y1;  // 回到原始状态
        uint256 attackerSellPrice = (x2 - x3) / attackerDeltaY;
        
        // 攻击者利润
        profit = (attackerSellPrice - attackerBuyPrice) * attackerDeltaY;
    }
}
```

### 5.2 Flashbots Protect

```javascript
const { FlashbotsBundleProvider } = require('@flashbots/ethers-provider-bundle');

async function sendPrivateTransaction(signer, tx) {
    const flashbots = await FlashbotsBundleProvider.create(
        signer.provider,
        authSigner
    );
    
    const bundle = await flashbots.signBundle([
        {
            signer: signer,
            transaction: tx
        }
    ]);
    
    // 发送到 Flashbots 而非公共 Mempool
    return await flashbots.sendBundle(bundle);
}
```

### 5.3 DEX 协议层防护

```solidity
// 方案1：TWAP（时间加权平均价格）

contract TWAPExchange {
    uint256 public constant PERIOD = 1 hours;
    
    struct Observation {
        uint256 timestamp;
        uint256 price0Cumulative;
        uint256 price1Cumulative;
    }
    
    Observation[] public observations;
    
    function update() internal {
        Observation memory obs = observations[observations.length - 1];
        uint256 timeElapsed = block.timestamp - obs.timestamp;
        
        if (timeElapsed >= PERIOD) {
            observations.push(Observation({
                timestamp: block.timestamp,
                price0Cumulative: obs.price0Cumulative + (currentPrice0 * timeElapsed),
                price1Cumulative: obs.price1Cumulative + (currentPrice1 * timeElapsed)
            }));
        }
    }
    
    function getTwap(uint256 lookback) public view returns (uint256) {
        Observation memory first = observations[observations.length - lookback];
        Observation memory last = observations[observations.length - 1];
        
        return (last.price0Cumulative - first.price0Cumulative) / 
               (last.timestamp - first.timestamp);
    }
}
```

### 5.4 CEX-DEX 混合方案

```solidity
// 方案2：订单价格保护

contract ProtectedExchange {
    // 使用链下签名价格 + 链上验证
    mapping(bytes32 => bool) public usedSignatures;
    
    struct SignedOrder {
        address user;
        uint256 tokenIn;
        uint256 tokenOut;
        uint256 amountIn;
        uint256 minAmountOut;  // 最小输出（包含滑点保护）
        uint256 validUntil;
        bytes signature;
    }
    
    function executeProtectedSwap(SignedOrder calldata order) external {
        // 验证签名未被使用
        bytes32 orderHash = keccak256(abi.encode(order));
        require(!usedSignatures[orderHash], "Order already used");
        usedSignatures[orderHash] = true;
        
        // 验证价格
        uint256 currentRate = getCurrentRate(order.tokenIn, order.tokenOut);
        require(currentRate >= order.minAmountOut, "Slippage exceeded");
        
        // 执行交易
        _executeSwap(order.user, order.tokenIn, order.tokenOut, order.amountIn);
    }
}
```

## 11. 总结

1. **MEV 本质**：通过交易排序操纵提取的价值
2. **Sandwich Attack**：抢先买入 → 受害者交易 → 攻击者卖出
3. **防护核心**：隐藏交易意图、限制滑点、使用 TWAP
4. **用户方案**：Flashbots RPC + 小滑点 + 分批成交
5. **协议方案**：TWAM + 价格预言机 + 签名验证
