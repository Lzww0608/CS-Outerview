# Uniswap V2 与 V3 区别及集中流动性原理

## 1. 问题背景

Uniswap 是以太坊上最流行的去中心化交易所（DEX）。V2 采用恒定乘积做市商模型，而 V3 引入了集中流动性（Concentrated Liquidity）机制，大幅提升了资本效率。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Uniswap V2:                                              │
│  x * y = k                                               │
│  流动性均匀分布在整个价格区间 [0, ∞)                    │
│                                                             │
│  Uniswap V3:                                              │
│  流动性集中在指定价格区间 [Pa, Pb]                       │
│  资本效率提升 4000+ 倍（理论上）                         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | V2 | V3 |
|------|----|----|
| 价格范围 | 全区间 [0, ∞) | 可选区间 [Pa, Pb] |
| 资金利用率 | 低（大部分闲置） | 高（仅需少量资金覆盖价格） |
| LP 手续费 | 固定 0.3% | 可选 0.01%, 0.05%, 0.3%, 1% |
| Tick 概念 | 无 | 核心概念，价格粒度化 |

---

## 3. 影响范围

- DeFi 流动性提供者
- DEX 聚合器
- 量化交易策略
- 跨DEX套利

## 4. 原因分析

### 4.1 恒定乘积模型 (V2)

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  x * y = k                                                  │
│                                                             │
│  其中：                                                     │
│  x = Token0 数量                                           │
│  y = Token1 数量                                           │
│  k = 恒定乘积（交易前后不变）                              │
│                                                             │
│  价格公式：p = y / x                                        │
│                                                             │
│  特点：                                                     │
│  • 流动性无限（价格可到无穷）                              │
│  • 无滑点上限                                              │
│  • 所有流动性等价                                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 集中流动性模型 (V3)

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Tick 概念：                                                │
│  • 价格被离散化为一个个 "Tick"（刻度）                    │
│  • Tick 间隔 = 1.0001（价格变化 0.01%）                  │
│  • 每个 Tick 有唯一的 index i                               │
│  • 价格 p(i) = 1.0001^i                                    │
│                                                             │
│  流动性聚集：                                               │
│  • LP 可以选择价格区间 [sqrt(Pa), sqrt(Pb)]               │
│  • 只在该区间内提供流动性                                  │
│  • 区间外的价格由其他 LP 覆盖                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.3 Tick 与价格关系

```solidity
// Tick 计算公式

struct TickInfo {
    int24 index;              // Tick 索引
    uint128 liquidityGross;    // 该 Tick 的总流动性
    int128 liquidityNet;      // 该 Tick 的净流动性
}

// 价格与 Tick 互转
function getSqrtPriceAtTick(int24 tick) public pure returns (uint160) {
    return TickMath.getSqrtRatioAtTick(tick);
}

function getTickAtSqrtPrice(uint160 sqrtPrice) public pure returns (int24) {
    return TickMath.getTickAtSqrtRatio(sqrtPrice);
}

// 示例
// Tick 0: 价格 = 1.0001^0 = 1
// Tick 1: 价格 = 1.0001^1 = 1.0001
// Tick 100: 价格 = 1.0001^100 ≈ 1.01
```

### 4.4 集中流动性数学

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  V3 单个区间的 AMM：                                       │
│                                                             │
│  (x + Δx) * (y + Δy) = L²                                  │
│                                                             │
│  其中 L = 虚拟流动性总量（类似 V2 的 √k）                │
│                                                             │
│  价格范围：                                                 │
│  Pa ≤ p ≤ Pb                                               │
│                                                             │
│  需要的流动性：                                             │
│  L = Δy / (sqrt(Pb) - sqrt(Pa))  // 全额 Token1          │
│  或                                                         │
│  L = Δx * sqrt(Pa) * sqrt(Pb) / (sqrt(Pb) - sqrt(Pa))    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 5. 解决方案

### 5.1 V3 流动性提供策略

```solidity
// 策略1：全区间做市（类似 V2）
// 在 [MIN_TICK, MAX_TICK] 提供流动性

// 策略2：集中做市
// 在 [currentPrice - 10%, currentPrice + 10%] 提供流动性

// 策略3：范围订单
// 在特定价格附近狭窄区间做市（类似限价单）

contract LiquidityManager {
    int24 public baseTick = -887272;  // MIN_TICK
    int24 public rangeWidth = 100;    // ±100 ticks
    
    function provideConcentratedLiquidity(
        address pool,
        uint256 amount0,
        uint256 amount1
    ) external {
        int24 tickLower = getCurrentTick() - rangeWidth;
        int24 tickUpper = getCurrentTick() + rangeWidth;
        
        INonfungiblePositionManager.MintParams memory params = 
            INonfungiblePositionManager.MintParams({
                token0: IUniswapV3Pool(pool).token0(),
                token1: IUniswapV3Pool(pool).token1(),
                fee: 3000,
                tickLower: tickLower,
                tickUpper: tickUpper,
                amount0Desired: amount0,
                amount1Desired: amount1,
                amount0Min: 0,
                amount1Min: 0,
                recipient: address(this),
                deadline: block.timestamp
            });
        
        positionManager.mint(params);
    }
}
```

### 5.2 多头仓位管理

```solidity
// V3 NFT 仓位示例

contract PositionManager {
    // 每个仓位是一个 NFT
    struct Position {
        uint96 nonce;
        address operator;
        address token0;
        address token1;
        uint24 fee;
        int24 tickLower;
        int24 tickUpper;
        uint128 liquidity;
        uint256 feeGrowthInside0LastX128;
        uint256 feeGrowthInside1LastX128;
        uint128 tokensOwed0;
        uint128 tokensOwed1;
    }
    
    // 主动做市策略
    function rebalancePosition(
        int24 newTickLower,
        int24 newTickUpper
    ) external {
        // 1. 移除当前仓位
        uint128 oldLiquidity = positions[currentNft].liquidity;
        if (oldLiquidity > 0) {
            positionManager.decreaseLiquidity(
                INonfungiblePositionManager.DecreaseLiquidityParams({
                    tokenId: currentNft,
                    liquidity: oldLiquidity,
                    amount0Min: 0,
                    amount1Min: 0,
                    deadline: block.timestamp
                })
            );
        }
        
        // 2. 添加新仓位
        positionManager.increaseLiquidity(
            INonfungiblePositionManager.IncreaseLiquidityParams({
                tokenId: currentNft,
                amount0Desired: token0Balance,
                amount1Desired: token1Balance,
                amount0Min: 0,
                amount1Min: 0,
                deadline: block.timestamp
            })
        );
    }
}
```

## 6. 可选方案对比

| 特性 | V2 恒定乘积 | V3 集中流动性 |
|------|-------------|---------------|
| 流动性分布 | 均匀分布全区间 | 可集中在任意区间 |
| 资本效率 | 低 | 高（可达 4000x） |
| LP 策略灵活性 | 无 | 多样化 |
| 手续费率 | 固定 0.3% | 可选 0.01%~1% |
| 实现复杂度 | 简单 | 复杂（Tick 机制） |
|gas费用|较低|较高（状态更新多）|

## 7. 推荐方案

### 7.1 散户 LP

```text
推荐使用宽区间策略：
- 范围：[currentPrice * 0.5, currentPrice * 2]
- 手续费率：0.3%
- 优点：无需频繁调整
- 缺点：资本效率较低
```

### 7.2 专业 LP

```text
推荐使用窄区间策略：
- 范围：[currentPrice * 0.99, currentPrice * 1.01]
- 手续费率：0.3% 或 1%
- 配合主动管理策略
- 优点：资本效率极高
- 缺点：需监控和调仓
```

## 8. 实施步骤

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  V3 LP 操作流程：                                          │
│                                                             │
│  1. 授权 Token 到 NonfungiblePositionManager              │
│  2. 调用 mint() 创建仓位（获得 NFT）                     │
│  3. 监控仓位状态和手续费累积                              │
│  4. 可选：主动 rebalance（增减流动性）                 │
│  5. 调用 decreaseLiquidity() 移除流动性                 │
│  6. 调用 collect() 提取手续费和本金                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 9. 风险与注意事项

| 风险 | 说明 | 缓解措施 |
|------|------|----------|
| 无常损失放大 | 区间越窄无常损失越大 | 适当扩大范围 |
| 主动管理成本 | rebalance 有 gas 费用 | 计算手续费覆盖成本 |
| 仓位清理 | 价格出区间后流动性失效 | 及时调整区间 |
| Tick 边界 | 价格在 Tick 边界波动大 | 选择合适 Tick 间距 |

## 11. 总结

1. **V2 vs V3 本质区别**：V2 流动性均匀分布，V3 可集中在特定价格区间
2. **Tick 概念**：价格离散化的刻度，Tick 间距为 1.0001
3. **集中流动性**：允许 LP 用更少资金覆盖更大交易量，资本效率提升
4. **数学本质**：V3 单区间仍是 x*y=L²，但多区间叠加形成复杂曲线
5. **选型建议**：根据资金量、风险偏好、管理能力选择策略
