# 2. BST、AVL 树和红黑树

二叉搜索树、AVL 树和红黑树都属于搜索树，核心目标是在动态集合中支持查找、插入、删除和有序遍历。面试里要说明它们的有序性、平衡策略、复杂度和工程取舍。

## 二叉搜索树 BST

二叉搜索树满足：

1. 任意节点的左子树所有 key 小于当前节点。
2. 任意节点的右子树所有 key 大于当前节点。
3. 中序遍历可以得到有序序列。

查找过程类似二分：

```text
key < node.key  -> 去左子树
key > node.key  -> 去右子树
key == node.key -> 找到
```

复杂度取决于树高 `h`：

1. 查找、插入、删除都是 `O(h)`。
2. 树平衡时 `h = O(log n)`。
3. 如果按有序数据连续插入，BST 可能退化成链表，复杂度变成 `O(n)`。

## AVL 树

AVL 树是严格平衡的二叉搜索树。它要求任意节点左右子树高度差不超过 1，通常通过记录节点高度或平衡因子来维护。

核心操作：

1. 插入或删除后沿祖先链更新高度。
2. 如果平衡因子失衡，通过旋转恢复平衡。
3. 常见旋转有 LL、RR、LR、RL 四类。

### AVL 树左旋和右旋

AVL 旋转的目标不是改变二叉搜索树的有序性，而是在保持“左小右大”的前提下降低局部子树高度。旋转完成后要从低到高重新计算相关节点高度。

**右旋**用于 LL 型失衡，也就是节点 `z` 的左子树过高，且新增或删除导致的高度变化落在 `z.left` 的左侧：

```text
        z                 y
       / \               / \
      y   T4   ->       x   z
     / \               / \ / \
    x   T3            T1 T2 T3 T4
   / \
  T1 T2
```

**左旋**用于 RR 型失衡，也就是节点 `z` 的右子树过高，且高度变化落在 `z.right` 的右侧：

```text
    z                     y
   / \                   / \
  T1  y       ->         z   x
     / \               / \ / \
    T2  x             T1 T2 T3 T4
       / \
      T3 T4
```

双旋本质上是先把“折线”变成“直线”，再做单旋：

1. **LR 型**：先对左孩子做左旋，再对当前节点做右旋。
2. **RL 型**：先对右孩子做右旋，再对当前节点做左旋。

实现时要注意三点：

1. 旋转只影响局部 2 到 3 个节点和若干子树，不会破坏中序遍历结果。
2. 高度更新顺序通常是先更新下沉的旧根，再更新上升的新根。
3. 插入导致的失衡通常一次旋转即可恢复；删除可能沿祖先链继续向上修复。

特点：

1. 查询路径更短，查找性能稳定。
2. 插入删除后可能需要更多旋转和高度维护。
3. 适合读多写少、对查询延迟更敏感的内存索引。

## 红黑树

红黑树是近似平衡的二叉搜索树，通过颜色和黑高约束控制树高。典型性质包括：

1. 每个节点是红色或黑色。
2. 根节点通常是黑色。
3. 叶子 NIL 节点视为黑色。
4. 红色节点不能有红色子节点。
5. 从任意节点到其所有后代 NIL 节点的路径上，黑色节点数量相同。

这些性质保证最长路径不会超过最短路径的 2 倍，因此树高仍是 `O(log n)`。

红黑树的工程特点：

1. 平衡约束比 AVL 宽松，插入删除旋转次数通常更少。
2. 查找略逊于 AVL，但更新更友好。
3. 适合查找、插入、删除都频繁的场景。
4. C++ `std::map/std::set`、Linux CFS 运行队列、Nginx 定时器等常用红黑树或类似有序树结构。

### 红黑树性质的面试追问

根节点通常要求是黑色。即使某次插入修复过程中临时把根染红，修复结束也会把根重新染黑。把根设为黑色不会破坏二叉搜索树有序性，也更方便统一黑高定义。

红黑树不允许连续两个红节点。也就是说，红色节点的父节点和子节点都必须是黑色。这个约束的作用是限制红节点连续堆叠，配合“任意节点到后代 NIL 的黑高相同”，可以推出最长路径不会超过最短路径的 2 倍。

插入新节点时通常先染红，原因是：

1. 插入红节点不会立刻改变路径黑高。
2. 如果父节点是黑色，直接结束。
3. 如果父节点也是红色，出现连续红节点，再通过叔叔节点染色、左旋、右旋修复。

删除更复杂，因为删除黑色节点可能破坏黑高，需要通过兄弟节点颜色、侄子节点颜色和旋转重新平衡。

## 三者对比

| 对比项 | 普通 BST | AVL 树 | 红黑树 |
| --- | --- | --- | --- |
| 是否自平衡 | 否 | 是，严格平衡 | 是，近似平衡 |
| 最坏树高 | `O(n)` | `O(log n)` | `O(log n)` |
| 查找性能 | 取决于树形 | 最稳定，路径较短 | 稳定，路径略长于 AVL |
| 插入删除成本 | 简单但可能退化 | 旋转和高度维护较多 | 旋转较少，更新更友好 |
| 有序遍历 | 支持 | 支持 | 支持 |
| 适用场景 | 教学、小规模、输入随机 | 读多写少 | 读写都频繁、标准库有序容器 |

## 易错点

1. “平衡二叉树”在面试里经常默认指 AVL，但广义上红黑树也是自平衡二叉搜索树。
2. 红黑树不是绝对平衡，它保证的是黑高约束下的近似平衡。
3. BST 的中序遍历有序，但这不代表它一定高效；如果树退化，单次查找是 `O(n)`。
4. `std::map` 标准没有强制必须用红黑树，但要求有序和 `O(log n)` 复杂度，主流实现采用红黑树。
5. 数据库索引更常用 B+ 树，不是红黑树，因为 B+ 树扇出高、树高低，更适合磁盘页和范围扫描。

## 真实场景

1. 内存中的有序字典、范围查询、定时器管理可以使用红黑树。
2. 查询远多于修改的内存索引可以考虑 AVL 或只读排序数组。
3. 如果只需要等值查询且不要求有序，哈希表通常比树更合适。
4. 如果数据存放在磁盘或 SSD 上，优先考虑 B/B+ 树或 LSM Tree，而不是二叉搜索树。

## 红黑树节点和实现要点

红黑树节点通常至少包含 key、value、颜色、父指针、左右孩子指针：

```cpp
enum class Color { Red, Black };

template <typename K, typename V>
struct RBNode {
    K key;
    V value;
    Color color = Color::Red;
    RBNode* parent = nullptr;
    RBNode* left = nullptr;
    RBNode* right = nullptr;
};
```

很多实现还会使用一个全局黑色 `nil` 哨兵节点，让空孩子统一表示为黑色，减少空指针判断。

插入流程：

1. 先按普通 BST 规则找到插入位置。
2. 新节点染红，避免直接破坏黑高。
3. 如果父节点是黑色，结束。
4. 如果父节点是红色，根据叔叔节点颜色处理：
   - 叔叔为红：父和叔染黑，祖父染红，继续向上修复。
   - 叔叔为黑：通过左旋/右旋把局部结构转成直线，再重新染色和旋转。
5. 最后根节点染黑。

删除比插入复杂，因为删除黑节点会破坏黑高。工程中通常用成熟库，面试手写时先把旋转、插入修复讲清楚，再说明删除需要处理兄弟节点和侄子节点颜色。

## 红黑树和定时器

定时器可以用红黑树按过期时间排序：

```text
key = expire_time
value = timer callback
```

执行流程：

1. 新定时器按过期时间插入红黑树，复杂度 `O(log n)`。
2. 事件循环每次取最左节点，即最早过期定时器。
3. 如果最早过期时间还没到，把它作为 `epoll_wait` 的 timeout。
4. 如果已经过期，删除节点并执行回调。

红黑树适合大量定时器的动态插入、删除和查找最早过期任务。Nginx 定时器、Linux CFS 运行队列都体现了“按 key 排序并快速取最小值”的思路。若定时器数量极大且精度固定，也可以考虑时间轮，牺牲部分精度换取接近 `O(1)` 的插入删除。

## 红黑树反转的注意点

如果“反转红黑树”指把每个节点左右孩子交换，颜色和黑高性质在结构上仍可能保持，但它会破坏二叉搜索树的有序性：原来左小右大，镜像后变成左大右小。

因此要先问清楚题意：

1. 如果只是像普通二叉树一样镜像输出，可以递归交换左右孩子。
2. 如果反转后仍要作为同一个比较器下的红黑树使用，不能简单镜像，需要重新按 key 建树。
3. 如果同时把比较器从 `<` 改为 `>`，镜像结构才可能与新的顺序语义一致。

## 面试回答模板

BST 通过“左小右大”维护有序性，中序遍历有序，查找插入删除复杂度是 `O(h)`，但普通 BST 可能退化成链表。AVL 是严格平衡二叉搜索树，左右子树高度差不超过 1，查找路径短但插入删除维护成本高。红黑树通过颜色和黑高约束保持近似平衡，最长路径不超过最短路径 2 倍，查找、插入、删除都是 `O(log n)`，更新成本比 AVL 低，所以 `std::map/std::set` 等工程结构更常用红黑树。
