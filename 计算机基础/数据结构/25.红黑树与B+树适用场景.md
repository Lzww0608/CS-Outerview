# 25. 红黑树与 B+ 树适用场景

红黑树和 B+ 树都能支持有序查找，但它们面向的存储层级不同。红黑树是内存中的二叉搜索树，重点是动态有序集合；B+ 树是多路平衡树，重点是磁盘页、缓存页和范围扫描。

## 1. 红黑树适合什么场景

红黑树是近似平衡的二叉搜索树，通过颜色和黑高约束把树高控制在 `O(log n)`。

适合场景：

1. 内存中的有序映射和集合，例如 `std::map`、`std::set`。
2. 需要频繁插入、删除、查找，同时要求 key 有序。
3. 需要快速找到最小值、最大值、前驱、后继或做范围遍历。
4. 定时器、调度队列、内存索引等节点对象已经在内存中的结构。

红黑树的优势是更新成本稳定，旋转次数通常少于 AVL；缺点是每个节点至少有左右孩子、父指针和颜色，指针跳转多，缓存局部性不如数组和 B+ 树页。

## 2. B+ 树适合什么场景

B+ 树是多路平衡搜索树，非叶子节点只保存 key 和孩子指针，叶子节点保存数据或数据指针，且叶子节点有序相连。

适合场景：

1. 数据库存储引擎索引，例如 InnoDB 聚簇索引和二级索引。
2. 磁盘或 SSD 上的大规模数据检索。
3. 范围查询、排序扫描、分页查询、前缀查询。
4. 需要让单个节点对齐磁盘页或缓存页，降低 I/O 次数。

B+ 树的核心优势是扇出高。一个 16KB 页可以放很多 key 和指针，树高通常只有 3 到 4 层；范围查询时只要定位到第一个叶子页，后续沿叶子链表顺序扫描即可。

## 3. 为什么数据库不用红黑树做主索引

红黑树是二叉树，树高相对 B+ 树更高。即使同样是 `O(log n)`，在数据库里一次节点访问往往意味着一次页访问或缓存 miss，常数差异很大。

对比：

| 对比项 | 红黑树 | B+ 树 |
| --- | --- | --- |
| 节点分支数 | 2 | 多路，通常几十到几百 |
| 树高 | 相对更高 | 扇出高，树高低 |
| 缓存局部性 | 指针分散，cache miss 多 | 页内连续存放，局部性更好 |
| 范围查询 | 中序遍历，需要大量指针跳转 | 叶子链表顺序扫描 |
| 典型位置 | 内存数据结构 | 数据库索引、文件系统索引 |

因此数据库索引选择 B+ 树，不是因为红黑树复杂度不对，而是因为 B+ 树更符合页式存储、磁盘 I/O 和范围扫描。

## 4. 面试易错点

1. 不能只说“B+ 树比红黑树快”。要说明快在哪里：树高、I/O 次数、缓存局部性和范围扫描。
2. 红黑树不是严格平衡树，它是近似平衡；AVL 更严格，查询路径更短但更新成本更高。
3. B+ 树也不是只适合磁盘，内存数据库也可能用 B+ 树或 B-link Tree，因为页式布局和范围扫描仍然有价值。
4. 哈希表等值查询平均 `O(1)`，但不支持有序范围查询，所以不能完全替代 B+ 树索引。
5. LSM-Tree 更偏写入吞吐和顺序写，B+ 树更偏低读放大和范围查询，不能把所有数据库索引都归为 B+ 树。

## 5. 真实场景

1. C++ 服务里维护在线用户按过期时间排序，可以用红黑树、跳表或堆。
2. Nginx 定时器、Linux CFS 运行队列这类内存调度结构，适合红黑树思路。
3. MySQL InnoDB 主键索引和二级索引适合 B+ 树，因为数据量远超内存，查询要以页为单位。
4. 范围查询 `where uid between 100 and 200`、按时间分页、联合索引前缀扫描，B+ 树叶子链表能直接顺序访问。

面试回答可以总结为：红黑树适合内存里的动态有序集合，读写都频繁、需要前驱后继和有序遍历；B+ 树适合数据库和文件系统索引，因为多路高扇出降低树高，节点按页组织，范围查询沿叶子链表顺序扫描，能显著减少随机 I/O 和 cache miss。
