# 23. 链上数据索引与 The Graph 协议

## 1. 问题背景

链上数据索引是 Web3 应用开发的核心基础设施。直接在链上查询数据效率极低（需要遍历所有历史区块），The Graph 等索引协议通过预索引提供高效的查询能力。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  链上数据查询的挑战：                                       │
│                                                             │
│  直接查询：                                                │
│  ┌─────────────────────────────────────────────────────┐  │
│  │ 查询 "Uniswap V3 所有 ETH/USDC 交易"              │  │
│  │ → 需扫描数百万个区块                               │  │
│  │ → 耗时数小时                                       │  │
│  │ → 不可行！                                        │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
│  使用索引协议：                                            │
│  ┌─────────────────────────────────────────────────────┐  │
│  │ 查询 "Uniswap V3 所有 ETH/USDC 交易"              │  │
│  │ → 预索引数据存储在 Postgres/ClickHouse             │  │
│  │ → 毫秒级响应                                      │  │
│  │ → 可行！                                          │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 |
|------|------|
| 查询延迟高 | 直接读取链上数据耗时过长 |
| 索引延迟 | subgraph 同步滞后 |
| 跨链困难 | 多链数据聚合复杂 |
| 存储成本 | 全量数据存储昂贵 |

---

## 3. 影响范围

- DeFi 协议（历史交易查询）
- NFT 市场（交易记录、稀有度）
- 链上分析平台
- 治理投票系统
- 跨链桥接应用

## 4. 原因分析

### 4.1 直接链上查询的局限性

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  以太坊数据结构：                                           │
│                                                             │
│  Block #1 ──► Block #2 ──► Block #3 ──► ... ──► Block #M │
│      │            │            │                   │        │
│      ▼            ▼            ▼                   ▼        │
│   Txs[]        Txs[]        Txs[]              Txs[]      │
```

```typescript
  const swap = new Swap(event.transaction.hash.toHex() + '-' + event.logIndex.toString());
  
  swap.transaction = event.transaction.hash;
  swap.timestamp = event.block.timestamp;
  swap.pool = event.address;
  
  swap.sender = event.params.sender;
  swap.recipient = event.params.recipient;
  
  swap.amount0 = event.params.amount0;
  swap.amount1 = event.params.amount1;
  
  swap.sqrtPriceX96 = event.params.sqrtPriceX96;
  swap.tick = event.params.tick;
  
  swap.logIndex = event.params.liquidity;
  
  swap.save();
}
```

## 5. 解决方案

### 5.1 中心化索引方案（自建）

```typescript
// 自建索引服务

class ChainIndexer {
    private provider: ethers.JsonRpcProvider;
    private db: PostgresDB;
    private blocks: Map<number, Block>;
    
    async indexBlocks(fromBlock: number, toBlock: number): Promise<void> {
        for (let blockNum = fromBlock; blockNum <= toBlock; blockNum++) {
            const block = await this.provider.getBlock(blockNum, true);
            
            for (const tx of block.transactions) {
                const receipt = await this.provider.getTransactionReceipt(tx.hash);
                
                for (const log of receipt.logs) {
                    // 解析特定合约的日志
                    if (this.isTargetContract(log.address)) {
                        const parsed = this.parseLog(log);
                        await this.db.insert(parsed);
                    }
                }
            }
            
            await this.updateProgress(blockNum);
        }
    }
    
    async query(sql: string, params: any[]): Promise<any[]> {
        return await this.db.query(sql, params);
    }
}

// 使用
const indexer = new ChainIndexer();
await indexer.indexBlocks(15000000, 15001000);

// GraphQL 查询
app.get('/graphql', async (req, res) => {
    const result = await indexer.query(`
        SELECT * FROM swaps 
        WHERE pool = $1 
        ORDER BY timestamp DESC 
        LIMIT 100
    `, [poolAddress]);
    
    res.json(result);
});
```

### 5.2 分布式索引方案（Covalent）

```typescript
// Covalent API

class CovalentIndexer {
    private apiKey: string;
    
    // 获取 ERC-20 代币转账
    async getTokenTransfers(address: string): Promise<Transfer[]> {
        const response = await fetch(
            `https://api.covalenthq.com/v1/1/address/${address}/transactions/` +
            `?quote-currency=USD&format=JSON&page-number=0&page-size=100`,
            {
                headers: {

                }
            }
        );
        
        const data = await response.json();
        return data.data.items;
    }
    
    // 获取 DEX 交易
    async getDexSwaps(address: string): Promise<Swap[]> {
        const response = await fetch(
            `https://api.covalenthq.com/v1/1/address/${address}/transactions/` +
            `?quote-currency=USD&format=JSON&page-number=0&page-size=100&key=txntype=DEX`
        );
        
        return (await response.json()).data.items;
    }
}
```

### 5.3 实时索引方案（Dune Analytics 风格）

```typescript
// 实时索引 + 事件驱动

class RealTimeIndexer {
    private provider: ethers.providers.WebSocketProvider;
    private redis: Redis;
    private db: ClickHouse;
    
    constructor() {
        this.provider = new ethers.providers.WebSocketProvider(WS_RPC);
    }
    
    async start(targetContracts: string[]): Promise<void> {
        for (const contract of targetContracts) {
            // 订阅新区块
            this.provider.on('block', async (blockNumber) => {
                await this.processBlock(blockNumber, contract);
            });
            
            // 订阅特定事件
            this.provider.on(contract, 'Swap', async (...args) => {
                const event = args[args.length - 1];
                await this.processSwapEvent(event);
            });
        }
    }
    
    private async processSwapEvent(event: ethers.Event): Promise<void> {
        const swapData = {
            txHash: event.transactionHash,
            blockNumber: event.blockNumber,
            timestamp: (await event.getBlock()).timestamp,
            
            sender: event.args.sender,
            recipient: event.args.recipient,
            
            amount0: event.args.amount0.toString(),
            amount1: event.args.amount1.toString(),
            
            sqrtPriceX96: event.args.sqrtPriceX96.toString(),
            tick: event.args.tick.toString()
        };
        
        // 写入 ClickHouse
        await this.db.insert('swaps', [swapData]);
        
        // 写入 Redis（实时查询）
        await this.redis.lpush(`pool:${event.address}:recent_swaps`, JSON.stringify(swapData));
        await this.redis.ltrim(`pool:${event.address}:recent_swaps`, 0, 99);
    }
}
```

## 6. 可选方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| The Graph | 去中心化、索引完善 | 同步慢、费用高 | 公开 API |
| 自建索引 | 完全可控 | 维护成本高 | 企业内部 |
| Covalent | 简单易用 | 中心化、有限免费 | 快速原型 |
| Dune | 查询方便 | 无法自建 | 公开分析 |
| 自建 + Kafka | 实时性好 | 复杂度高 | 高性能需求 |

## 11. 总结

1. **The Graph**：去中心化索引协议， subgraph 定义事件到实体的映射
2. **局限性**：同步慢、实时性差、跨链支持有限
3. **替代方案**：自建索引、Covalent、Dune、自建 + Kafka
4. **选型建议**：小型项目用 The Graph，大型项目自建
5. **核心原则**：索引延迟和存储成本是核心权衡点
