# 4. 撤销与重做的数据结构

`Ctrl+Z` 和 `Ctrl+Y` 对应撤销和重做。最常见的数据结构是两个栈：一个 undo 栈保存已执行操作，一个 redo 栈保存被撤销但还可以恢复的操作。

## 1. 核心模型

```text
执行新操作:
  apply(op)
  undo.push(op)
  redo.clear()

撤销 Ctrl+Z:
  op = undo.pop()
  revert(op)
  redo.push(op)

重做 Ctrl+Y:
  op = redo.pop()
  apply(op)
  undo.push(op)
```

为什么要清空 redo 栈：撤销几步后，如果用户执行了一个新操作，历史分支已经改变，原来的 redo 路径不再是当前文档状态的合法未来。

## 2. 操作怎么表示

操作记录可以有两种方式：

1. **命令模式**：每个操作对象提供 `apply()` 和 `undo()`，例如插入文本、删除文本、移动图形。
2. **快照/差量**：保存操作前后的状态快照，或只保存变化的差量。

示例：

```text
Insert(pos=5, text="abc")
Delete(pos=8, oldText="xyz")
Replace(pos=3, oldText="foo", newText="bar")
```

撤销删除时需要知道被删除的旧内容，因此操作记录不能只保存“删除位置”，还要保存足够恢复状态的信息。

## 3. 快照和命令的取舍

| 方案 | 优点 | 缺点 | 适用场景 |
| --- | --- | --- | --- |
| 全量快照 | 实现简单，恢复直接 | 内存大，复制成本高 | 小对象、低频编辑 |
| 差量快照 | 内存较小，恢复准确 | 需要设计 diff 和合并 | 文本、文档编辑 |
| 命令模式 | 表达业务语义，易合并 | 每类命令都要写反操作 | 编辑器、绘图、IDE |
| 事件日志 | 可回放、可审计 | 回放成本和压缩复杂 | 协同编辑、业务状态机 |

真实编辑器通常会合并连续小操作，例如连续输入字符可以合并成一次“插入字符串”操作，避免用户按一次撤销只删一个字符。

## 4. 易错点

1. 执行新操作后要清空 redo 栈。
2. 撤销操作本身不要再被记录成普通新操作，否则会污染 undo 栈。
3. 操作记录必须包含足够恢复状态的信息。
4. 对外部副作用要谨慎，例如发送消息、扣款、删除远程文件不一定能简单撤销。
5. 多人协同编辑不能只靠本地双栈，需要 OT、CRDT 或服务端操作日志。

## 5. 面试回答模板

撤销和重做通常用两个栈实现。执行新操作时，把操作应用到当前状态并压入 undo 栈，同时清空 redo 栈；按 `Ctrl+Z` 时从 undo 栈弹出操作，执行反操作并压入 redo 栈；按 `Ctrl+Y` 时从 redo 栈弹出操作重新执行，再压回 undo 栈。操作对象要保存足够的反向信息，例如删除文本时保存被删除内容。工程上还要合并连续输入、限制历史栈大小，并注意外部副作用不一定能撤销。
