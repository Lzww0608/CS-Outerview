# 以太坊原理详解

## 一、以太坊概述

### 1.1 什么是以太坊

以太坊（Ethereum）是 Vitalik Buterin 于 2015 年发布的开源区块链平台，支持图灵完备的智能合约，是 DeFi、NFT、DAO 等应用的基础设施。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  以太坊核心特性：                                           │
│                                                             │
│  1. 图灵完备：支持任意复杂度的计算                          │
│  2. 智能合约：可编程的区块链                                │
│  3. EVM：以太坊虚拟机，执行智能合约                        │
│  4. 账户模型：EOA（外部账户）+ CA（合约账户）              │
│  5. GAS 机制：防止资源滥用                                 │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 四、共识机制

### 4.1 Ethash（PoW）

```go
// Ethash 算法核心概念

// 1. DAG（有向无环图）
// 每 30000 区块（约 5 天）生成新 DAG
// 完整 DAG 约 4GB（2023 年）

// 2. 挖矿过程
type Ethash struct {
    caches   []*cache // 伪随机缓存
    datasets []*dataset // 完整数据集
}

func (ethash *Ethash) hashimoto(headerHash []byte, nonce uint64) ([]byte, []byte) {
    // 计算 mix
    mix := ethash.computeMix(headerHash, nonce)
    
    // 计算哈希
    hash := ethash.computeHash(headerHash, mix)
    
    return hash, mix
}
```

### 4.2 Beacon Chain（PoS）

```go
// 以太坊 2.0 信标链

// 验证者结构
type Validator struct {
    Pubkey          []byte  // 公钥
    WithdrawalCreds []byte  // 取款凭证
    Balance         uint64  // 质押余额
    EffectiveBalance uint64 // 有效余额
    Slashed         bool    // 是否被惩罚
}

// 区块提议
func proposeBlock(block *BeaconBlock, validator *Validator) error {
    // 1. 检查验证者角色
    if !isProposer(validator, block.Slot) {
        return ErrNotProposer
    }
    
    // 2. Randao 揭示
    if !revealRandao(block) {
        return ErrInvalidRandao
    }
    
    // 3. 收集 attestations
    attestations := collectAttestations(block)
    
    // 4. 生成区块
    block.Attestations = attestations
    block.ParentRoot = block.ParentBlockHash
    
    return nil
}
```

```solidity
contract GasExample {
    // 基本操作：21000 Gas（交易）
    function basicTransaction() public payable {
        // 转账操作
    }
    
    // 存储操作：200 Gas（冷访问）
    uint public storedValue;

        storedValue = 100;  // 写入：20000 Gas
        storedValue = 200;   // 修改：2900 Gas（热访问）
        storedValue = 0;     // 删除：-15000 Gas（退款）
    }
    
    // 计算操作
    function compute() public pure returns (uint) {
        uint sum = 0;
        for (uint i = 0; i < 100; i++) {
            sum += i;  // 加法：3 Gas
        }
        return sum;
    }
}
```

### 7.1 ERC-20 代币标准

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

interface IERC20 {
    function totalSupply() external view returns (uint256);
    function balanceOf(address account) external view returns (uint256);
    function transfer(address to, uint256 amount) external returns (bool);
    function allowance(address owner, address spender) external view returns (uint256);
    function approve(address spender, uint256 amount) external returns (bool);
    function transferFrom(address from, address to, uint256 amount) external returns (bool);
}

contract ERC20 is IERC20 {
    mapping(address => uint256) private _balances;
    mapping(address => mapping(address => uint256)) private _allowances;
    uint256 private _totalSupply;
    
    function totalSupply() public view override returns (uint256) {
        return _totalSupply;
    }
    
    function balanceOf(address account) public view override returns (uint256) {
        return _balances[account];
    }
    
    function transfer(address to, uint256 amount) public override returns (bool) {
        _transfer(msg.sender, to, amount);
        return true;
    }
    
    function _transfer(address from, address to, uint256 amount) internal {
        require(_balances[from] >= amount, "Insufficient balance");
        _balances[from] -= amount;
        _balances[to] += amount;
    }
    
    // ... 其他函数实现
}
```

### 7.2 ERC-721 NFT 标准

```solidity
// NFT 合约
contract ERC721 {
    using Address for address;
    
    event Transfer(address indexed from, address indexed to, uint256 indexed tokenId);
    event Approval(address indexed owner, address indexed approved, uint256 indexed tokenId);
    
    mapping(uint256 => address) private _owners;
    mapping(address => uint256) private _balances;
    mapping(uint256 => address) private _tokenApprovals;
    
    function mint(address to, uint256 tokenId) public {
        _mint(to, tokenId);
    }
    
    function _mint(address to, uint256 tokenId) internal {
        require(to != address(0), "Invalid address");
        require(_owners[tokenId] == address(0), "Token already exists");
        
        _owners[tokenId] = to;
        _balances[to]++;
        
        emit Transfer(address(0), to, tokenId);
    }
    
    function ownerOf(uint256 tokenId) public view returns (address) {
        address owner = _owners[tokenId];
        require(owner != address(0), "Token does not exist");
        return owner;
    }
}
```

## 九、面试常见问题

### Q1: EVM 和传统 VM 的区别？

- EVM 是栈式虚拟机，256 位字长，专为区块链设计
- 支持 Gas 计费，防止无限循环
- 确定性执行，确保全网一致
- 隔离执行，每个合约独立运行环境

### Q2: 以太坊如何实现图灵完备？

通过 Gas 机制限制计算步骤，避免无限循环；结合存储和计算能力限制，实现实际意义的图灵完备。

### Q3: 什么是叔块（Uncle Block）？

由于出块时间短（12 秒），区块链分叉频繁；叔块是被主链"收养"的孤立区块，矿工仍可获得部分奖励，提高网络安全性和去中心化。

### Q4: The Merge 的意义？

- 减少约 99.95% 的能源消耗
- ETH 年发行量从约 5% 降至约 0.5%
- 为未来分片升级奠定基础

### Q5: ERC-20 和 ERC-721 的区别？

| 对比 | ERC-20 | ERC-721 |
|------|--------|---------|
| 类型 | 同质化代币 | 非同质化代币 |
| 最小单位 | 可分割 | 不可分割 |
| 用途 | 货币、积分 | 艺术品、游戏道具 |
| 唯一性 | 每枚等价 | 每枚唯一 |
