# 4. 状态机

状态机用于描述对象在不同状态之间如何迁移。它由状态、事件、迁移条件和动作组成，适合处理生命周期明确、分支复杂、状态组合容易出错的业务逻辑。

## 状态机是什么

一个有限状态机可以抽象为：

```text
当前状态 + 事件 + 条件 -> 下一个状态 + 动作
```

例如订单系统可以有 `INIT`、`WAIT_PAY`、`PAID`、`CANCELLED`、`FINISHED` 等状态；游戏角色可以有 `IDLE`、`RUNNING`、`ATTACKING`、`DEAD` 等状态；客户端页面也可以有 `LOADING`、`READY`、`ERROR` 等状态。

## 为什么需要状态机

状态机的价值在于把隐式分支变成显式规则：

1. **约束合法迁移**：例如未支付订单不能直接进入已完成。
2. **集中处理副作用**：状态迁移时统一发送消息、写日志、触发动画或回调。
3. **便于测试**：可以按状态和事件枚举测试用例。
4. **便于排查问题**：日志记录 `from_state`、`event`、`to_state` 后，线上问题更容易还原。
5. **降低 if-else 膨胀**：复杂流程不用散落在多个函数和回调中。

## 常见实现方式

### 1. enum + switch

适合状态数量少、迁移规则简单的场景：

```cpp
enum class State {
    Loading,
    Ready,
    Error
};

enum class Event {
    LoadOk,
    LoadFailed,
    Retry
};

State transfer(State state, Event event) {
    switch (state) {
    case State::Loading:
        if (event == Event::LoadOk) return State::Ready;
        if (event == Event::LoadFailed) return State::Error;
        break;
    case State::Error:
        if (event == Event::Retry) return State::Loading;
        break;
    default:
        break;
    }
    return state;
}
```

### 2. 表驱动

适合状态和事件组合较多、需要配置化或可视化的场景：

```text
from       event        to         action
INIT       submit       WAIT_PAY   create_order
WAIT_PAY   pay_ok       PAID       freeze_inventory
WAIT_PAY   timeout      CANCELLED  release_inventory
PAID       deliver_ok   FINISHED   notify_user
```

表驱动实现时可以把 `(from, event)` 作为 key，value 保存目标状态、条件函数和动作函数。

### 3. 状态模式

把不同状态的行为封装为不同类，适合每个状态都有复杂行为的对象：

```text
Context 持有 State 接口
不同 ConcreteState 实现 handle(event)
handle 内部决定是否切换到另一个状态对象
```

这种方式扩展状态方便，但类数量会增加，状态迁移关系不如表驱动直观。

## 易错点

1. 状态机不是简单枚举，关键是定义清楚事件、迁移条件和副作用。
2. 状态迁移要保证幂等，重复事件不能把对象推到错误状态。
3. 迁移动作失败时要明确回滚、重试或进入失败状态。
4. 多线程或分布式场景下，状态更新要用锁、CAS、数据库条件更新或事务保护。
5. 不要让状态散落在多个布尔字段里，例如 `is_paid`、`is_cancelled`、`is_finished` 容易组合出非法状态。

## 真实场景

1. **客户端开发**：页面加载、网络请求、动画播放和角色行为都适合用状态机管理。
2. **服务端订单**：订单创建、支付、取消、发货、退款可以用状态机约束流程。
3. **网络协议解析**：HTTP 请求行、请求头、body 解析常用状态机处理半包和粘包。
4. **游戏技能系统**：技能前摇、释放、后摇、冷却和打断都可以建模为状态迁移。
5. **任务调度系统**：任务从待执行、运行中、成功、失败、重试中迁移，便于恢复和补偿。

## 面试回答模板

状态机是用状态、事件、迁移条件和动作描述对象生命周期的模型。它能把复杂 if-else 变成明确的迁移规则，避免非法状态和重复事件导致的问题。实现上可以用 enum + switch、表驱动或状态模式；工程上要关注幂等、并发更新、失败回滚和状态迁移日志。
