# 2. 常见设计模式

设计模式是对常见软件设计问题的可复用解决方案。面试里回答“了解哪些设计模式”时，不要只背名字，最好能说出适用场景和取舍。

## 创建型模式

1. **单例模式**：保证全局只有一个实例，适合配置中心、日志器等共享对象。注意线程安全、生命周期和全局状态耦合。
2. **工厂方法**：把对象创建延迟到子类或工厂函数，调用方依赖抽象而不是具体类。
3. **抽象工厂**：创建一族相关对象，例如不同平台 UI 组件族。
4. **建造者模式**：分步骤构造复杂对象，适合参数多、构造过程复杂的对象。
5. **原型模式**：通过复制已有对象创建新对象，适合创建成本高或运行时类型动态的场景。

## 结构型模式

1. **适配器模式**：把一个接口转换成调用方期望的接口，常用于兼容旧系统或第三方 SDK。
2. **装饰器模式**：不改变原对象结构，动态叠加功能，例如 IO 流、缓存、鉴权包装。
3. **代理模式**：通过代理对象控制访问，可做远程代理、虚拟代理、保护代理、缓存代理。
4. **外观模式**：给复杂子系统提供简单入口，降低调用方使用成本。
5. **组合模式**：把树形结构中的叶子和容器用统一接口处理，例如文件系统、UI 组件树。

## 行为型模式

1. **策略模式**：多种算法选一种，例如价格计算、路由策略、压缩算法。
2. **责任链模式**：多个处理器顺序处理并可中断，例如过滤器、拦截器、下单校验。
3. **命令模式**：把请求封装成对象，便于排队、撤销、重试和日志记录。
4. **观察者模式**：被观察者状态变化后通知多个观察者，例如事件总线、发布订阅。
5. **模板方法模式**：父类定义流程骨架，子类实现可变步骤。
6. **状态模式**：把不同状态下的行为封装到状态对象中，例如订单状态机。

## 工程注意事项

1. 设计模式不是越多越好，模式应该服务于扩展点和复杂度。
2. C++ 中 RAII 本身就是重要设计思想，常和代理、装饰器、策略等模式结合。
3. 如果需求变化不明确，过早抽象会增加理解成本。
4. 面试回答可以用“定义 + 适用场景 + 项目例子 + 缺点”组织，而不是只列清单。
