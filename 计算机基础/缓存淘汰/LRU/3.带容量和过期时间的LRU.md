# 3. 带容量和过期时间的 LRU

LRU（Least Recently Used）按最近访问时间淘汰数据：最近访问过的数据保留，最久未访问的数据优先淘汰。实际缓存通常还要同时支持**容量上限**和**过期时间 TTL**。

## 核心数据结构

高效实现一般使用：

1. **哈希表**：`key -> 链表节点`，保证 O(1) 查找。
2. **双向链表**：链表头表示最近访问，链表尾表示最久未访问，保证 O(1) 移动和淘汰。
3. **过期时间字段**：每个节点保存 `expire_at`，读取时判断是否过期。

```text
map[key] -> node

head <-> recent ... old <-> tail
```

## get 流程

1. 哈希表找不到 key，返回 miss。
2. 找到节点但 `expire_at <= now`，删除节点并返回 miss。
3. 未过期则把节点移动到链表头，返回 value。

## put 流程

1. 如果 key 已存在，先删除旧节点。
2. 插入新节点到链表头，并设置 `expire_at = now + ttl`。
3. 如果超过容量，从链表尾部开始淘汰节点。
4. 可以顺便清理尾部已过期节点，但不能只依赖尾部，因为过期节点可能在链表中间。

## 简化 C++ 写法

```cpp
class LRUCache {
    struct Node {
        int key;
        int value;
        int64_t expire_at;
    };

    int capacity_;
    std::list<Node> lru_;
    std::unordered_map<int, std::list<Node>::iterator> index_;

public:
    explicit LRUCache(int capacity) : capacity_(capacity) {}

    std::optional<int> get(int key, int64_t now) {
        auto it = index_.find(key);
        if (it == index_.end()) return std::nullopt;

        auto node = it->second;
        if (node->expire_at <= now) {
            lru_.erase(node);
            index_.erase(it);
            return std::nullopt;
        }

        lru_.splice(lru_.begin(), lru_, node);
        return lru_.begin()->value;
    }

    void put(int key, int value, int ttl, int64_t now) {
        auto it = index_.find(key);
        if (it != index_.end()) {
            lru_.erase(it->second);
            index_.erase(it);
        }

        lru_.push_front(Node{key, value, now + ttl});
        index_[key] = lru_.begin();

        while (static_cast<int>(index_.size()) > capacity_) {
            auto last = std::prev(lru_.end());
            index_.erase(last->key);
            lru_.erase(last);
        }
    }
};
```

## 过期策略

1. **懒删除**：访问 key 时发现过期再删。实现简单，但冷门过期 key 可能长期占内存。
2. **定期扫描**：后台周期性抽样或批量删除过期 key，适合控制内存。
3. **最小堆**：按过期时间建堆，堆顶就是最早过期 key；删除时要处理堆中旧版本节点。
4. **时间轮**：大量 TTL 接近的场景可用时间轮分桶，降低定时任务成本。

## 易错点

1. LRU 顺序和过期时间是两套规则：容量淘汰看最近访问，TTL 淘汰看时间。
2. TTL 可以设计成写入后固定过期，也可以设计成访问后续期，后者叫 sliding expiration。
3. 多线程缓存要保护哈希表和链表的一致性，通常需要锁、分段锁或无锁近似算法。
4. 系统时间回拨会影响 TTL 判断，工程上更适合使用单调时钟。
5. 缓存中 value 如果很大，还要按内存大小淘汰，而不只是按 key 数量淘汰。
