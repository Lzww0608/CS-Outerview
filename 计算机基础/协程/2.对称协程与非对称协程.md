# 对称协程与非对称协程

## 1. 基本概念

### 1.1 什么是对称协程和非对称协程

协程根据转移控制权的方式可以分为**对称协程（Symmetric Coroutine）**和**非对称协程（Asymmetric Coroutine）**。这一区分最早由 Marvin Conway 在 1963 年的论文中提出，后来被学术文献广泛讨论。

- **对称协程**：任何一个协程都可以将控制权转移给任意其他协程，所有协程地位平等。
- **非对称协程**：协程之间存在调用-返回关系，类似函数调用栈，有一个明确的"主人"关系。

```text
对称协程：                                    非对称协程：
┌─────┐        ┌─────┐                       ┌─────┐ 
│ A   │ ──────>│ B   │                       │ A   │ ─────>─┐
└─────┘        └─────┘                       └──┬──┘        │
      ↑              ↑                           │           ▼
      └──────────────┘                           │     ┌─────┐ 
      (任意转移)                                 │     │ B   │
                                                 │     └─────┘
                                                 │           │
                                                 └───────────┘
                                               (调用-返回关系)
```

### 1.2 历史发展

| 时间 | 里程碑 |
| --- | --- |
| 1963 | Marvin Conway 在论文《Design of a Separable Transition-Diagram Compiler》中首次提出协程概念，区分了对称和非对称形式 |
| 1970s | Simula 语言引入了类协程机制，用于离散事件仿真 |
| 1980s | Icon、Python 早期版本探索了协程实现 |
| 2000s | Lua、Go 等现代语言将协程带入主流开发 |
| 2010s | async/await 模式普及，本质是语法糖化的非对称协程 |

## 2. 非对称协程

### 2.1 核心特征

非对称协程要求协程之间保持明确的调用关系：
- `resume(coroutine)` 恢复协程执行
- `yield()` 将控制权返回给调用者
- 协程只能将控制权返还给自己的"调用者"，不能随意跳转

这与普通函数的调用-返回模式非常相似，只是多了挂起-恢复的能力。

### 2.2 Python Generator 实现

Python 的 generator 是典型的非对称协程前身：

```python
def caller():
    # 主协程逻辑
    value = yield from sub()  # 调用子协程
    print(f"收到返回值: {value}")

def sub():
    # 子协程
    yield 1
    yield 2
    return 3  # 返回值会传给 caller

# 使用
c = caller()
print(next(c))  # 输出: 1
print(next(c))  # 输出: 2
print(next(c))  # 输出: 收到返回值: 3
```

### 2.3 Lua 协程示例

Lua 是最早广泛使用非对称协程的主流语言之一：

```lua
-- Lua 非对称协程
local co = coroutine.create(function(a)
    print("协程开始, 参数:", a)
    local b = coroutine.yield(a + 1)  -- 挂起，返回 a+1
    print("恢复时参数:", b)
    return a + b
end)

local ok, val = coroutine.resume(co, 10)  -- 启动协程
print("yield 返回值:", val)  -- 输出: 11

ok, val = coroutine.resume(co, 20)  -- 恢复协程
print("协程返回值:", val)  -- 输出: 30
```

特点：
- `coroutine.create()` 创建协程，返回协程对象
- `coroutine.resume()` 恢复协程执行
- `coroutine.yield()` 挂起并返回控制权
- 协程只能 yield 给恢复它的 resume，不能随意跳转

### 2.4 Python asyncio（现代非对称协程）

Python 3.4+ 的 asyncio 是现代非对称协程的典型实现：

```python
import asyncio

async def task1():
    print("task1 开始")
    await asyncio.sleep(1)
    print("task1 完成")
    return "result1"

async def task2():
    print("task2 开始")
    await asyncio.sleep(0.5)
    print("task2 完成")
    return "result2"

async def main():
    # 显式的调用-返回关系
    results = await asyncio.gather(task1(), task2())
    print(f"所有任务完成: {results}")

asyncio.run(main())
```

关键点：
- `await` 本质上是挂起当前协程，返回控制权给事件循环
- 事件循环（调度器）决定下一步恢复哪个协程
- 协程之间不是平等的，是被调度器管理的

## 3. 对称协程

### 3.1 核心特征

对称协程中所有协程地位平等，任何协程都可以将控制权转移到任意其他协程：

```c
// 伪代码示意
coroutine_a {
    // 做某些事...
    transfer_to(coroutine_b);  // 可以转移到任何协程
    // 可能会从任意协程恢复
}
```

### 3.2 C 语言 ucontext 实现对称协程

Linux/Unix 提供了 `ucontext` 系统，可以实现对称协程：

```c
#define _GNU_SOURCE
#include <ucontext.h>
#include <stdio.h>
#include <stdlib.h>

static ucontext_t ctx[3];
static char stacks[3][8192];

// 协程函数
void coro_func(int id) {
    for (int i = 0; i < 3; i++) {
        printf("协程 %d: 第 %d 次执行\n", id, i);
        // 对称转移：可以转移到任意其他协程
        int next = (id + 1) % 3;
        swapcontext(&ctx[id], &ctx[next]);
    }
}

int main() {
    // 初始化 3 个协程
    for (int i = 0; i < 3; i++) {
        getcontext(&ctx[i]);
        ctx[i].uc_stack.ss_sp = stacks[i];
        ctx[i].uc_stack.ss_size = sizeof(stacks[i]);
        ctx[i].uc_link = NULL;  // 无返回链接，对称协程特征
        
        // 注意：这里是简化的伪代码逻辑演示
        // 实际需要用 makecontext 配合
    }
    
    // 对称协程可以自由跳转，不需要调用者
}
```

### 3.3 Go goroutine 的对称特性

Go 的 goroutine 实际上结合了对称和非对称特征：

```go
package main

import (
    "fmt"
    "runtime"
)

func main() {
    // goroutine 可以自由创建和调度
    // runtime 负责在 M(线程) 和 P(处理器) 之间分配
    
    done := make(chan bool)
    
    go func() {  // 可以随时创建新协程
        fmt.Println("goroutine 执行")
        done <- true
    }()
    
    // 不需要"返回"，只需要发送信号
    <-done
}
```

关键理解：
- Go 的调度器是运行时的一部分
- goroutine 本身是对称的（可以自由创建）
- 但调度行为由运行时统一控制，更像非对称模式

### 3.4 状态机模式（对称协程的高级形式）

对称协程本质上是一个状态机：

```python
from enum import Enum, auto
from typing import Callable, Dict
from dataclasses import dataclass

class State(Enum):
    A = auto()
    B = auto()
    C = auto()

@dataclass
class SymmetricCoroutine:
    current_state: State
    handlers: Dict[State, Callable[['SymmetricCoroutine'], None]]
    
    def run(self):
        while self.current_state is not None:
            handler = self.handlers.get(self.current_state)
            if handler:
                handler(self)
            else:
                break
    
    def transfer_to(self, state: State):
        """对称转移：可以转移到任意状态"""
        self.current_state = state

# 使用示例
def state_a(coro: SymmetricCoroutine):
    print("状态 A")
    coro.transfer_to(State.B)

def state_b(coro: SymmetricCoroutine):
    print("状态 B")
    coro.transfer_to(State.C)

def state_c(coro: SymmetricCoroutine):
    print("状态 C")
    coro.transfer_to(None)  # 结束

coro = SymmetricCoroutine(
    current_state=State.A,
    handlers={State.A: state_a, State.B: state_b, State.C: state_c}
)
coro.run()
```

## 4. 对称 vs 非对称对比

### 4.1 核心区别

| 特征 | 非对称协程 | 对称协程 |
| --- | --- | --- |
| 控制权转移 | 调用-返回模式 | 任意转移 |
| 协程关系 | 有主从/调用关系 | 完全平等 |
| 实现复杂度 | 较简单 | 较复杂 |
| 灵活性 | 受限 | 更高 |
| 典型代表 | Python async/await, Lua 协程 | ucontext, 状态机 |
| 调度器依赖 | 必须有调度器 | 可无调度器 |

### 4.2 优缺点分析

#### 非对称协程优点

1. **结构清晰**：调用-返回关系符合直觉，调试友好
2. **实现简单**：复用函数调用栈的思维模型
3. **易于分析**：控制流是树形结构，可预测性强
4. **调度器天然存在**：必须配合调度器（如事件循环）

#### 非对称协程缺点

1. **灵活性受限**：不能随意跳转到任意协程
2. **复杂流程需要回调**：需要额外机制处理多路等待

#### 对称协程优点

1. **灵活性极高**：可以实现任意复杂的控制流
2. **适合状态机**：仿真、博弈、自动机场景天然匹配
3. **无需预设调度关系**：协程之间可以自由协作

#### 对称协程缺点

1. **控制流复杂**：难以追踪和调试
2. **实现难度大**：需要处理循环引用、死锁检测
3. **难以优化**：编译器优化空间有限

### 4.3 实际选择

| 场景 | 推荐类型 |
| --- | --- |
| 网络 I/O、异步编程 | 非对称（async/await） |
| 离散事件仿真 | 对称协程 |
| 游戏 AI、状态机 | 对称协程 |
| 简单异步任务 | 非对称（更易用） |
| 高性能调度框架 | 视情况选择 |

## 5. 现代语言的协程模型

### 5.1 语言实现对比

| 语言 | 协程模型 | 类型 |
| --- | --- | --- |
| Python | async/await | 非对称 |
| JavaScript | async/await | 非对称 |
| C# | async/await | 非对称 |
| Go | goroutine | 混合（对称创建，非对称调度） |
| Rust | async/await | 非对称 |
| Lua | 协程库 | 非对称 |
| Kotlin | 协程 | 非对称 |
| Swift | async/await | 非对称 |

### 5.2 为什么现代语言倾向非对称协程

现代编程语言几乎都选择了非对称协程，原因：

1. **可组合性**：非对称协程的 await 可以组合成复杂的异步流程
2. **调试友好**：调用栈可追踪，控制流清晰
3. **编译器优化**：状态机转换易于优化
4. **语言一致性**：与异常、错误处理的语义统一

### 5.3 对称协程的复兴

但对称协程的概念在某些场景重新受到关注：

```python
# Trio 库的对称转移尝试
# 引入 "门票" 机制保持对称性

import trio

async def worker(name, write_stream):
    for i in range(5):
        await write_stream.send(f"{name}: {i}")
        await trio.sleep(0.1)

async def main():
    async with trio.open_nursery() as nursery:
        # Trio 实际上是非对称的，但尝试提供
        # 更高层次的"对称"调度能力
        nursery.start_soon(worker, "A", nursery)
        nursery.start_soon(worker, "B", nursery)
```

## 6. 面试高频问题

### Q1: 什么是对称协程和非对称协程？有什么区别？

**回答要点**：
- 对称协程：任意协程可以将控制权转移到任意其他协程，地位平等
- 非对称协程：协程之间是调用-返回关系，有明确的主从关系
- 现代语言（Python、JS、Rust）基本都采用非对称模型
- 对称协程更适合状态机、仿真等复杂控制流场景

### Q2: 为什么 async/await 是非对称的？

**回答要点**：
- `await` 只能挂起当前协程，返回给调用者（调度器）
- 不能在协程内部跳转到任意其他协程
- 这种设计简化了控制流，配合事件循环实现
- 适合 I/O 密集型的高并发场景

### Q3: Go goroutine 是对称还是非对称？

**回答要点**：
- goroutine 的创建是对称的（可以自由创建）
- 但调度行为由 runtime 的 GMP 模型统一控制
- goroutine 只能被调度器恢复，本质上是非对称调度
- 可以理解为"对称创建 + 非对称调度"的混合模式

### Q4: 什么时候应该用对称协程？

**回答要点**：
- 离散事件仿真（DES）：实体之间自由通信
- 游戏开发：AI 状态机、行为树
- 网络协议实现：需要复杂的握手状态机
- 需要任意跳转的高性能场景（但需要自行处理死锁）

## 7. 总结

对称和非对称协程是协程理论的基础分类：

- **非对称协程**采用调用-返回模式，现代语言主流选择，适合高并发 I/O
- **对称协程**允许任意转移，灵活性高但实现复杂，适合状态机场景
- 理解这一区分有助于理解 async/await 的本质和协程的调度原理
