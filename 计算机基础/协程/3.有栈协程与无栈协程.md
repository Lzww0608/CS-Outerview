# 有栈协程与无栈协程

## 1. 基本概念

### 1.1 什么是有栈协程和无栈协程

协程根据实现方式可分为**有栈协程（Stackful Coroutine）**和**无栈协程（Stackless Coroutine）**：

- **有栈协程**：每个协程有独立的调用栈，可以在任意嵌套调用层级中挂起和恢复
- **无栈协程**：协程状态编译成状态机，只能在顶层函数位置挂起

有栈协程在深层嵌套函数中挂起时，能够保留完整的调用栈；无栈协程通过编译器将控制流转换为状态机实现，挂起点必须是协程函数的入口位置。

## 2. 历史发展

| 时间 | 里程碑 |
| --- | --- |
| 1963 | Marvin Conway 提出协程概念，早期实现均为有栈形式 |
| 1980s | Stackless Python 项目探索无栈协程 |
| 2000s | Lua、Go 普及有栈协程 |
| 2012 | Lua 5.2 引入无栈协程扩展（yield across C boundaries） |

| 2020s | Rust async/await、JavaScript async/await 全面普及 |

## 3. 有栈协程

### 3.1 核心特征

有栈协程为每个协程分配独立的栈空间，切换时保存完整的寄存器、栈指针和程序计数器。这使得协程可以在深层嵌套中挂起，恢复时仍能访问完整的调用栈。

### 3.2 Go goroutine（有栈协程典范）

```go
package main

import (
    "fmt"
    "sync"
)

func main() {
    var wg sync.WaitGroup
    
    // goroutine 是有栈协程
    for i := 0; i < 3; i++ {
        wg.Add(1)
        go func(id int) {
            defer wg.Done()
            
            // 可以在嵌套函数中挂起
            doWork(id)
        }(i)
    }
    
    wg.Wait()
}

func doWork(id int) {
    // 深层嵌套
    innerWork := func() {
        fmt.Printf("goroutine %d: 深层嵌套执行\n", id)
    }
    
    innerWork()
}
```

Go goroutine 关键特性：
- 初始栈 2KB，可动态增长（最大 1GB）
- 栈增长通过复制实现（栈分裂）
- 调度器 GMP 模型管理协程到线程的映射

### 3.3 libco（有栈协程实现示例）

微信开源的 libco 是 C++ 有栈协程的经典实现：

```cpp
#include "coctx.h"
#include <stdio.h>
#include <string.h>

// 协程上下文切换核心
// 基于 ucontext_t 或汇编实现

struct coctx_t {
    void* regs[14];  // 保存寄存器
    char* ss_sp;     // 栈底
    int ss_size;     // 栈大小
};

// 协程创建
coctx_t* coctx_new(void (*fn)(void*), void* arg, int stack_size) {
    coctx_t* ctx = new coctx_t();
    ctx->ss_sp = new char[stack_size];
    ctx->ss_size = stack_size;
    
    // 设置初始状态，函数从这里开始执行
    make_coctx(ctx, fn, arg);
    return ctx;
}

// 协程切换
void coctx_swap(coctx_t* from, coctx_t* to) {
    // 保存当前上下文到 from
    // 恢复到 to 上下文
    // ...
}

// 协程函数示例
void coro_func(void* arg) {
    int* counter = (int*)arg;
    printf("协程开始: %d\n", (*counter)++);
    
    // 主动让出，切换到其他协程
    co_yield();
    
    printf("协程恢复: %d\n", (*counter)++);
}
```

## 4. 无栈协程

### 4.1 核心特征

无栈协程不分配独立栈，而是将协程函数编译成状态机。挂起点通过保存局部变量到堆/栈上的协程帧实现，恢复时从状态机的下一个状态继续执行。

### 4.2 C++20 协程（无栈协程标准实现）

```cpp
#include <experimental/coroutine>
#include <iostream>
#include <future>

// promise_type 定义协程行为
struct Task {
    struct promise_type {
        Task get_return_object() {
            return Task{std::experimental::coroutine_handle<promise_type>::from_promise(*this)};
        }
        
        std::experimental::suspend_never initial_suspend() { return {}; }
        std::experimental::suspend_always final_suspend() { return {}; }
        
        void return_void() {}
        void unhandled_exception() {}
    };
    
    std::experimental::coroutine_handle<promise_type> coro;
    Task(std::experimental::coroutine_handle<promise_type> c) : coro(c) {}
    ~Task() { if (coro) coro.destroy(); }
};

// async 函数示例
Task fetchData(int id) {
    std::cout << "协程 " << id << " 开始\n";
    
    // co_await 挂起点
    co_await std::experimental::suspend_always{};
    
    std::cout << "协程 " << id << " 恢复\n";
    co_return;
}

int main() {
    auto task = fetchData(1);
    task.coro.resume();  // 恢复执行
    
    return 0;
}
```

### 4.3 Rust async/await（无栈协程）

```rust
use std::future::Future;
use std::pin::Pin;
use std::task::{Context, Poll};

// 自定义 Future 实现
struct CountDown(u8);

impl Future for CountDown {
    type Output = ();
    
    fn poll(mut self: Pin<&mut Self>, cx: &mut Context) -> Poll<Self::Output> {
        if self.0 == 0 {
            Poll::Ready(())
        } else {
            println!("count: {}", self.0);
            self.0 -= 1;
            // 需要手动 wake 来恢复
            cx.waker().wake_by_ref();
            Poll::Pending
        }
    }
}

// async 函数编译后的状态机
async fn async_example() {
    let countdown = CountDown(5);
    countdown.await;
    println!("完成");
}

// 等价的状态机实现（编译器生成形式）
enum AsyncExampleFuture {
    Start,
    Waiting {
        countdown: CountDown,
    },
    Done,
}

impl Future for AsyncExampleFuture {
    fn poll(self: Pin<&mut Self>, cx: &mut Context) -> Poll<Self::Output> {
        let this = self.get_mut();
        loop {
            match this {
                AsyncExampleFuture::Start => {
                    *this = AsyncExampleFuture::Waiting {
                        countdown: CountDown(5),
                    };
                }
                AsyncExampleFuture::Waiting { countdown } => {
                    let pinned = Pin::new(countdown);
                    if let Poll::Ready(_) = pinned.poll(cx) {
                        *this = AsyncExampleFuture::Done;
                        return Poll::Ready(());
                    }
                }
                AsyncExampleFuture::Done => return Poll::Ready(()),
            }
        }
    }
}
```

### 4.4 Python async/await（无栈协程）

```python
import asyncio

async def async_task():
    """async 函数会被编译成协程对象"""
    print("step 1")
    await asyncio.sleep(0)  # 挂起点
    
    print("step 2")
    await asyncio.sleep(0)  # 挂起点
    
    print("step 3")
    return "done"

# 等价的生成器实现（Python 3.4 之前）
from functools import wraps

def async_task_generator():
    """yield from 实现同样的效果"""
    print("step 1")
    yield asyncio.sleep(0)
    
    print("step 2")
    yield asyncio.sleep(0)
    
    print("step 3")
    return "done"

# 协程对象本质
async def inspectCoroutine():
    coro = async_task()
    print(type(coro))  # <class 'coroutine'>
    print(dir(coro))   # 有 send, throw, close 方法
    await coro
```

### 4.5 JavaScript async/await

```javascript
// async 函数是无栈协程
async function fetchData(id) {
    console.log(`请求 ${id}`);
    const response = await fetch(`/api/${id}`);
    const data = await response.json();
    return data;
}

// 编译后的状态机（简化模型）
function fetchData_generator(id, resumePoint = 0) {
    switch(resumePoint) {
        case 0:
            console.log(`请求 ${id}`);
            return fetch(`/api/${id}`).then(data => {
                return fetchData_generator(id, 1);  // 恢复点 1
            });
        case 1:
            return response.json().then(data => {
                return fetchData_generator(id, 2);  // 恢复点 2
            });
        case 2:
            return data;  // 完成
    }
}
```

## 5. 对比分析

### 5.1 核心区别

| 特征 | 有栈协程 | 无栈协程 |
| --- | --- | --- |
| 栈管理 | 每个协程独立栈 | 无独立栈，编译成状态机 |
| 挂起位置 | 任意嵌套层级 | 仅协程顶层函数 |
| 内存布局 | 栈 + 堆协程控制块 | 仅协程帧（堆） |
| 切换成本 | 较高（需切换栈） | 较低（状态转换） |
| 实现方式 | 运行时/汇编 | 编译器转换 |
| 栈大小 | 固定或可增长 | 无栈，无需管理 |

### 5.2 优缺点对比

#### 有栈协程优点

1. **自然的执行模型**：支持深层嵌套挂起，与普通函数调用无异
2. **调试友好**：调用栈完整，可直接查看
3. **无需修改函数签名**：可以在任意函数中使用

#### 有栈协程缺点

1. **内存开销**：每个协程需要独立栈（Go 最小 2KB）
2. **栈切换成本**：切换时需要复制栈指针和寄存器
3. **栈大小问题**：太小容易溢出，太大浪费内存
4. **实现复杂**：需要处理栈增长、栈分裂等

#### 无栈协程优点

1. **内存效率高**：协程帧按需分配，无栈空间浪费
2. **切换成本低**：纯状态转换，无栈数据复制
3. **编译器优化**：状态机易于内联和优化
4. **适合高性能**：C++ async、Rust async 设计初衷

#### 无栈协程缺点

1. **不能嵌套挂起**：await 只能在协程函数顶层使用
2. **调用栈不完整**：调试时无法看到完整调用链
3. **异步传播**：函数签名必须包含 Future/Task 返回值
4. **Pin 语义**：Rust 需要处理自引用结构

## 7. Java 虚拟线程（有趣的例外）

Java 21 引入的虚拟线程是有栈协程的 JVM 实现：

```java
import java.util.concurrent.*;

public class VirtualThreads {
    public static void main(String[] args) throws Exception {
        try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
            IntStream.range(0, 10_000).forEach(i -> {
                executor.submit(() -> {
                    // 深层嵌套挂起
                    deepNestedCall(i);
                    return null;
                });
            });
        }
    }
    
    static void deepNestedCall(int i) {
        nested1(i);
    }
    
    static void nested1(int i) {
        nested2(i);
    }
    
    static void nested2(int i) {
        // 模拟 I/O
        try { Thread.sleep(1000); } catch (InterruptedException e) {}
        System.out.println(i);
    }
}
```

虚拟线程特点：
- 每个虚拟线程有独立栈（初始 ~1MB，可增长）
- 由 JVM 调度，不阻塞 OS 线程
- 兼容现有 Thread API
- 适合高并发 I/O 场景

## 8. 面试高频问题

### Q1: 有栈协程和无栈协程的核心区别是什么？

**回答要点**：
- 有栈协程每个协程有独立栈，可以嵌套挂起
- 无栈协程编译成状态机，只能在顶层函数挂起
- 有栈协程内存开销更大，切换需要复制栈
- 无栈协程切换成本低，但调用链不完整

### Q2: 为什么 Go 选择有栈协程？

**回答要点**：
- Go 的设计哲学是"简单"，让并发编程像写同步代码
- 有栈协程支持在任意深层函数中挂起，不需要改函数签名
- 调试时可以查看完整调用栈
- 栈增长机制解决了固定栈的大小问题

### Q3: C++20 为什么选择无栈协程？

**回答要点**：
- C++ 追求零成本抽象，无栈协程开销更小
- 状态机形式便于编译器优化
- 不需要运行时调度，更轻量
- 与现有 C++ 库生态更好集成

### Q4: 什么时候选择有栈 vs 无栈？

**回答要点**：
- 需要深层嵌套挂起：选择有栈（Go、Java 虚拟线程）
- 追求极致性能：选择无栈（C++20、Rust async）
- 团队习惯同步写法：选择有栈
- 需要编译器状态机优化：选择无栈

## 9. 总结

有栈和无栈协程是协程的两种实现范式：

- **有栈协程**：提供完整调用栈体验，适合 Go 这类追求简单性的语言
- **无栈协程**：内存效率高、切换成本低，是现代语言（Rust、C++20、Python async）的主流选择

理解这两种实现的差异，有助于根据场景选择合适的协程方案。
