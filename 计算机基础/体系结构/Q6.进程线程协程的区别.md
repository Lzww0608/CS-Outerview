# Q6. 进程、线程、协程的区别

## 1. 问题背景

进程、线程、协程是操作系统和并发编程中的三个核心概念，它们都用于实现程序并发执行，但设计目标、资源开销和适用场景各不相同。

**假设条件**：本文档以 Linux/Unix 系统为主，线程特指内核线程（Native Thread），协程指用户态协程（User-level Coroutine）。

## 2. 问题现象

在实际开发中，选择不当会导致以下问题：

1. **性能瓶颈**：使用进程处理高并发 I/O，资源开销过大
2. **响应迟钝**：线程数量过多，上下文切换开销显著
3. **代码复杂**：回调地狱、状态管理混乱
4. **资源耗尽**：进程/线程创建过多，导致系统崩溃

## 3. 影响范围

| 维度 | 进程 | 线程 | 协程 |
| --- | --- | --- | --- |
| 系统资源占用 | 高 | 中 | 低 |
| 切换开销 | 最高 | 高 | 低 |
| 并发能力 | 低 | 中 | 高 |
| 适用场景 | 进程隔离 | CPU 并行 | I/O 高并发 |
| 通信复杂度 | 高 | 中 | 低 |

## 4. 原因分析

### 4.1 进程（Process）

进程是操作系统资源分配的最小单位，每个进程有独立的：
- 虚拟地址空间
- 文件描述符表
- 信号处理机制
- PID 和 PPID

```c
// 进程的创建
pid_t pid = fork();
if (pid == 0) {
    // 子进程
} else {
    // 父进程
}
```

**进程间通信方式**：
- 管道（Pipe）
- 消息队列（Message Queue）
- 共享内存（Shared Memory）
- 信号量（Semaphore）
- Socket

### 4.2 线程（Thread）

线程是 CPU 调度的最小单位，同一进程内的线程共享：
- 堆内存
- 全局/静态变量
- 文件描述符
- 信号处理

```c
// POSIX 线程创建
pthread_t tid;
pthread_create(&tid, NULL, thread_func, arg);
```

**线程同步机制**：
- mutex（互斥锁）
- semophore（信号量）
- condition variable（条件变量）
- barrier（屏障）

### 4.3 协程（Coroutine）

协程是用户态的"轻量级线程"，由运行时/库调度，不涉及内核切换：

```go
// Go 协程
go func() {
    // 并发执行
}()
```

```python
# Python 协程
async def fetch():
    await asyncio.sleep(1)
```

### 4.4 三者核心对比

```
┌─────────────────────────────────────────────────────────────┐
│                        进程                                 │
│  ┌─────────────────────────────────────────────────────┐   │
│  │                     线程 1                           │   │
│  │  ┌─────────┐  ┌─────────┐  ┌─────────┐             │   │
│  │  │ 协程 A  │  │ 协程 B  │  │ 协程 C  │             │   │
│  │  └─────────┘  └─────────┘  └─────────┘             │   │
│  └─────────────────────────────────────────────────────┘   │
│  ┌─────────────────────────────────────────────────────┐   │
│  │                     线程 2                           │   │
│  │  ┌─────────┐  ┌─────────┐                          │   │
│  │  │ 协程 D  │  │ 协程 E  │                          │   │
│  │  └─────────┘  └─────────┘                          │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

| 特性 | 进程 | 线程 | 协程 |
| --- | --- | --- | --- |
| 资源占用 | 独立地址空间 | 共享进程资源 | 极小（协程帧） |
| 创建开销 | fork/execve | pthread_create | 栈分配或状态机 |
| 切换成本 | 最高（完整上下文） | 较高（内核切换） | 低（用户态） |
| 通信方式 | IPC | 共享内存+锁 | Channel/Await |
| 隔离性 | 强 | 弱 | 极弱 |
| 并行能力 | 受限（多进程可多核） | 可多核并行 | 依赖绑定线程 |

### 4.5 上下文切换详解

**进程切换**：
```
1. 保存当前进程上下文（寄存器、页表、文件描述符等）
2. 更新进程控制块 PCB
3. 切换内核栈
4. 切换页表（TLB 失效）
5. 恢复目标进程上下文
```

**线程切换**：
```
1. 保存线程上下文（寄存器、栈指针）
2. 切换用户态栈
3. 内核调度器选择新线程
4. 恢复新线程上下文
```

**协程切换**：
```c
// libco 协程切换核心
void coctx_swap(coctx_t* from, coctx_t* to) {
    // 仅保存/恢复：RIP, RSP, RBX, RBP, R12-R15
    // 不切换页表，不进入内核
}
```

## 5. 解决方案

### 5.1 选择决策树

```
开始
  │
  ├─ 是否需要进程隔离？
  │    │
  │    ├─ 是 ──> 选择进程（多进程）
  │    │
  │    └─ 否 ──> 下一步
  │
  ├─ 是否需要 CPU 多核并行？
  │    │
  │    ├─ 是 ──> 选择多线程
  │    │
  │    └─ 否 ──> 下一步
  │
  ├─ 是否是 I/O 密集型？
  │    │
  │    ├─ 是 ──> 选择协程
  │    │
  │    └─ 否 ──> 选择多线程
```

### 5.2 场景化方案

#### 高并发 I/O 场景（如网关、爬虫）
```go
// Go: 协程 + Channel
for _, url := range urls {
    go fetch(url)  // 10万协程轻松支持
}
```

#### CPU 密集计算（如图像处理）
```c
// C++: 线程池 + SIMD
ThreadPool pool(8);  // 8 核
pool.map(process_image, images);
```

#### 高可靠服务（如数据库、消息队列）
```python
# Python: 多进程 + Supervisor
from multiprocessing import Process
p = Process(target=run_service)
p.start()
```

## 6. 可选方案对比

| 方案 | 优势 | 劣势 | 典型应用 |
| --- | --- | --- | --- |
| 多进程 | 隔离强、稳定 | 开销大、通信复杂 | Nginx、PostgreSQL |
| 多线程 | 可并行、共享资源 | 同步复杂、调试难 | Java Web 服务 |
| 协程 | 高并发、低开销 | 不能并行、调度复杂 | Goroutine、Go Web |
| 混合模型 | 兼顾各种需求 | 复杂度高 | Go Runtime (GMP) |

## 8. 实施步骤

### 8.1 评估阶段
1. 分析任务类型（CPU 密集 / I/O 密集）
2. 确定并发规模
3. 评估同步复杂度

### 8.2 选型阶段
| 并发量 | CPU型 | I/O型 | 推荐 |
| --- | --- | --- | --- |
| < 100 | 线程池 | 线程池 | 多线程 |
| 100-10000 | 协程 | 协程 | 协程 |
| > 10000 | 多进程+协程 | 多进程+协程 | 混合模型 |

### 8.3 实现阶段
1. 选择语言/框架
2. 实现基础模型
3. 添加监控
4. 压力测试调优

## 9. 风险与注意事项

### 9.1 进程风险
- 进程间通信开销大
- 数据共享困难
- 进程创建成本高

### 9.2 线程风险
- 竞态条件
- 死锁风险
- 线程数量控制

### 9.3 协程风险
- 阻塞调用会卡住线程
- 调试困难
- 不适合 CPU 密集

## 11. 总结

| 维度 | 进程 | 线程 | 协程 |
| --- | --- | --- | --- |
| 本质 | 资源分配单位 | CPU 调度单位 | 用户态执行单元 |
| 开销 | 最大 | 中等 | 最小 |
| 隔离性 | 完全隔离 | 共享地址空间 | 极弱 |
| 适用 | 进程隔离需求 | CPU 并行 | I/O 高并发 |

**面试回答模板**：

进程是资源分配的基本单位，拥有独立地址空间；线程是 CPU 调度的最小单位，同进程内共享堆和全局变量；协程是用户态轻量级执行单元，由运行时调度，切换成本最低。

进程隔离性最强但开销最大，适合需要强隔离的场景；线程可以多核并行，适合 CPU 密集任务；协程适合高并发 I/O，能用同步写法写异步逻辑。实际系统通常组合使用，如 Go 的 GMP 模型就是线程+协程的混合实现。
