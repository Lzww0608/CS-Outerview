# 1. 空间复杂度与运行内存

算法题里问“运行内存耗费多少”，通常要分清两个概念：空间复杂度描述随输入规模增长的额外内存量级；真实运行内存是程序在操作系统中实际占用的内存，包括输入、输出、辅助结构、调用栈、对象布局和运行时开销。

## 1. 空间复杂度是什么

空间复杂度衡量算法额外使用的存储空间如何随输入规模 `n` 增长。常见写法有：

1. `O(1)`：只使用常数个变量，例如双指针反转数组。
2. `O(log n)`：递归深度或分治栈为对数级，例如平衡分治。
3. `O(n)`：使用哈希表、队列、栈或 DP 数组保存线性规模数据。
4. `O(n * m)`：二维 DP、矩阵、图邻接矩阵等。

面试里默认“额外空间”通常不计算输入本身，也不计算必须返回的输出；但如果题目问系统容量、内存限制或工程实现，就要把输入、输出和容器开销都算进去。

## 2. 真实运行内存包含什么

真实进程内存通常包括：

1. 输入数据本身，例如数组、字符串、树节点。
2. 算法辅助结构，例如哈希表、堆、队列、DP 表。
3. 递归调用栈，每层函数栈帧包含参数、局部变量、返回地址和保存寄存器。
4. 容器元数据，例如 `vector` 的容量、`unordered_map` 的桶数组和节点指针。
5. 对象头、对齐填充、分配器元数据和碎片。
6. 语言运行时开销，例如 JVM 对象头、GC 元数据、线程栈、类元数据。

因此 `O(n)` 只说明增长量级，不说明具体字节数。两个同为 `O(n)` 的方案，常数可能差很多：`int[]` 通常比链表或哈希表省得多。

## 3. 常见场景估算

### 数组和 DP

如果 `int` 是 4 字节，`n = 1e7` 的一维 `int` 数组大约是：

```text
1e7 * 4B = 40MB
```

二维 `int dp[n][m]`：

```text
n * m * 4B
```

如果 `n = m = 10000`，就是 100,000,000 个 int，大约 400MB，还不算其他开销。很多背包 DP 可以从二维压缩到一维，把 `O(n * cap)` 空间降到 `O(cap)`。

### 递归

递归空间主要看最大递归深度：

1. 平衡二叉树 DFS：栈深 `O(log n)`。
2. 链状树 DFS：栈深 `O(n)`，节点很多时可能栈溢出。
3. 快排平均递归栈 `O(log n)`，最坏 `O(n)`，工程实现通常递归短区间、循环处理长区间来控制栈深。

### 哈希表

哈希表的空间不只是键和值：

1. 桶数组需要额外指针或索引。
2. 链地址法每个节点有 next 指针和分配器开销。
3. 为降低冲突，负载因子通常小于 1，会预留空桶。

所以同样保存 `n` 个整数，哈希表常数开销明显高于数组。内存紧张时可以考虑排序、位图、布隆过滤器、压缩编码或外部存储。

## 4. 面试易错点

1. 只说大 O 不够，遇到内存限制要估算字节数。
2. 递归不是“没有额外空间”，调用栈也算空间。
3. 原地算法通常指额外空间 `O(1)`，不代表完全不占内存，输入数组本身仍然存在。
4. `vector` 的 `size` 和 `capacity` 不一定相同，扩容会预留空间。
5. Java、Go、Python 的对象和容器常数开销更大，不能按 C 数组简单估算。

## 5. 真实场景

工程里做内存评估通常按“数据规模 * 单条记录大小 * 副本数 * 索引/元数据系数”估算，再用压测和 profile 校准。例如本地缓存保存 100 万个用户配置，如果每条配置序列化后 200B，纯 value 就约 200MB；再加 key、哈希表桶、对象头和分配器碎片，实际可能到 400MB 以上。

如果算法服务要处理大输入，常见优化包括：

1. 流式处理，避免一次性加载全部数据。
2. 滚动数组或状态压缩，降低 DP 空间。
3. 位图、Roaring Bitmap、布隆过滤器等压缩结构。
4. 对象复用和内存池，减少频繁分配。
5. 外部排序、分块处理和多路归并，把内存压力转移为顺序 I/O。

## 6. 面试回答模板

算法的空间复杂度描述额外辅助空间随输入规模增长的量级，比如双指针是 `O(1)`，哈希表是 `O(n)`，二维 DP 是 `O(n*m)`，递归还要算调用栈。真实运行内存不能只看大 O，还要算输入、输出、容器元数据、对象头、对齐、分配器碎片和线程栈。面试中如果有内存限制，我会按元素个数乘单元素字节数先估算，再考虑哈希表、对象和运行时的常数开销；如果超限，就考虑状态压缩、位图、流式处理或外部排序。
