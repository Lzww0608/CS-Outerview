# MPMC 多生产者多消费者队列

MPMC（Multi-Producer Multi-Consumer）队列允许多个生产者线程同时入队、多个消费者线程同时出队。面试里要先说明：它可以用互斥锁和条件变量实现，也可以用无锁算法实现；无锁版本的难点远高于 SPSC 队列，不能只用两个原子下标简单 `load/store`，否则多个生产者或消费者会抢到同一个槽位。

## 1. 互斥锁版本怎么设计

如果没有极致低延迟要求，生产环境最稳妥的是有界队列 + `mutex` + `condition_variable`：

```cpp
template <class T>
class BlockingQueue {
public:
    explicit BlockingQueue(size_t cap) : cap_(cap) {}

    void push(T value) {
        std::unique_lock<std::mutex> lk(mu_);
        not_full_.wait(lk, [&] { return q_.size() < cap_ || closed_; });
        if (closed_) return;
        q_.push_back(std::move(value));
        not_empty_.notify_one();
    }

    bool pop(T& out) {
        std::unique_lock<std::mutex> lk(mu_);
        not_empty_.wait(lk, [&] { return !q_.empty() || closed_; });
        if (q_.empty()) return false;
        out = std::move(q_.front());
        q_.pop_front();
        not_full_.notify_one();
        return true;
    }

    void close() {
        std::lock_guard<std::mutex> lk(mu_);
        closed_ = true;
        not_empty_.notify_all();
        not_full_.notify_all();
    }

private:
    size_t cap_;
    std::deque<T> q_;
    bool closed_ = false;
    std::mutex mu_;
    std::condition_variable not_empty_;
    std::condition_variable not_full_;
};
```

优点是正确性容易验证，支持阻塞等待、关闭语义和背压。缺点是高竞争下有锁竞争、上下文切换和唤醒成本。

## 2. 无锁 MPMC 的核心问题

无锁 MPMC 队列通常依赖：

1. **原子 head/tail**：用 CAS 抢占入队或出队序号。
2. **槽位序列号**：每个 ring buffer 槽位保存一个 `sequence`，判断这个槽当前属于哪个生产/消费轮次。
3. **内存序**：生产者写完数据后用 release 发布，消费者用 acquire 看到数据。
4. **有界容量**：常见无锁 MPMC 用固定大小环形数组，避免动态分配和节点回收问题。
5. **缓存行隔离**：head、tail 和热点槽位要减少 false sharing。

只写下面这种伪逻辑是不够的：

```cpp
tail.store(tail + 1);
buffer[tail] = value;
```

多个生产者可能同时读到同一个 `tail`，从而覆盖同一个槽位。正确做法是用 CAS 抢占一个唯一位置，并用槽位序列号判断队列满/空。

## 3. 有界无锁 MPMC 示例

下面是 Dmitry Vyukov bounded MPMC queue 思路的简化版。容量必须大于 0，内部会上调到 2 的幂，便于用掩码取模。

```cpp
#include <atomic>
#include <cstddef>
#include <new>
#include <type_traits>
#include <utility>
#include <vector>

template <class T>
class MPMCQueue {
public:
    explicit MPMCQueue(size_t capacity)
        : mask_(roundUpPowerOfTwo(capacity) - 1),
          buffer_(mask_ + 1) {
        for (size_t i = 0; i < buffer_.size(); ++i) {
            buffer_[i].sequence.store(i, std::memory_order_relaxed);
        }
    }

    bool enqueue(const T& value) {
        Cell* cell;
        size_t pos = enqueue_pos_.load(std::memory_order_relaxed);

        for (;;) {
            cell = &buffer_[pos & mask_];
            size_t seq = cell->sequence.load(std::memory_order_acquire);
            intptr_t diff = static_cast<intptr_t>(seq) - static_cast<intptr_t>(pos);

            if (diff == 0) {
                if (enqueue_pos_.compare_exchange_weak(
                        pos, pos + 1,
                        std::memory_order_relaxed,
                        std::memory_order_relaxed)) {
                    break;
                }
            } else if (diff < 0) {
                return false; // 队列满
            } else {
                pos = enqueue_pos_.load(std::memory_order_relaxed);
            }
        }

        new (&cell->storage) T(value);
        cell->sequence.store(pos + 1, std::memory_order_release);
        return true;
    }

    bool dequeue(T& out) {
        Cell* cell;
        size_t pos = dequeue_pos_.load(std::memory_order_relaxed);

        for (;;) {
            cell = &buffer_[pos & mask_];
            size_t seq = cell->sequence.load(std::memory_order_acquire);
            intptr_t diff = static_cast<intptr_t>(seq) - static_cast<intptr_t>(pos + 1);

            if (diff == 0) {
                if (dequeue_pos_.compare_exchange_weak(
                        pos, pos + 1,
                        std::memory_order_relaxed,
                        std::memory_order_relaxed)) {
                    break;
                }
            } else if (diff < 0) {
                return false; // 队列空
            } else {
                pos = dequeue_pos_.load(std::memory_order_relaxed);
            }
        }

        T* ptr = reinterpret_cast<T*>(&cell->storage);
        out = std::move(*ptr);
        ptr->~T();
        cell->sequence.store(pos + mask_ + 1, std::memory_order_release);
        return true;
    }

private:
    struct Cell {
        std::atomic<size_t> sequence;
        typename std::aligned_storage<sizeof(T), alignof(T)>::type storage;
    };

    static size_t roundUpPowerOfTwo(size_t n) {
        size_t p = 1;
        while (p < n) p <<= 1;
        return p;
    }

    size_t mask_;
    std::vector<Cell> buffer_;
    alignas(64) std::atomic<size_t> enqueue_pos_{0};
    alignas(64) std::atomic<size_t> dequeue_pos_{0};
};
```

这个实现的核心语义：

1. `enqueue_pos_` 只负责给生产者分配唯一入队序号。
2. `dequeue_pos_` 只负责给消费者分配唯一出队序号。
3. 每个 `Cell::sequence` 表示该槽位当前处于哪个轮次，防止环形数组绕回后误判。
4. 生产者构造完元素后，`sequence.store(pos + 1, release)` 发布数据。
5. 消费者看到 `sequence == pos + 1` 后才能读取元素，读完后把槽位序列号推进到下一轮。

## 4. 内存序怎么理解

生产者路径：

```text
构造 T 对象
-> release 写 sequence
```

消费者路径：

```text
acquire 读 sequence
-> 看到对应轮次
-> 读取 T 对象
```

`release/acquire` 保证消费者看到槽位就绪时，也能看到生产者对元素内容的写入。`enqueue_pos_` 和 `dequeue_pos_` 的 CAS 可以使用 relaxed，因为它们只分配唯一序号，不负责发布元素内容；真正的数据可见性由槽位 `sequence` 负责。

## 5. 工程注意事项

1. **阻塞策略**：无锁队列通常 `enqueue/dequeue` 失败就返回，调用方决定自旋、yield、sleep、丢弃还是降级。
2. **容量规划**：有界队列必须处理满队列，不能无限堆积；满队列往往是下游处理能力不足的信号。
3. **异常安全**：如果 `T` 的构造、移动或赋值可能抛异常，队列实现要额外处理槽位状态恢复；低延迟队列常要求 `T` 可移动且不抛异常。
4. **对象生命周期**：环形数组保存的是未初始化存储，入队 placement new，出队显式析构。
5. **ABA 和内存回收**：数组槽位用递增 sequence 避免绕回误判；链表式无锁队列还要考虑 hazard pointer、epoch reclamation 等安全回收。
6. **性能验证**：无锁不一定更快。高竞争下 CAS 失败、自旋和缓存行抖动可能比有锁队列更差。

## 6. 面试回答模板

多生产者多消费者队列我会先明确是否需要阻塞和强背压。如果追求易维护，可以用 `mutex + condition_variable + 有界队列`，支持满队列等待和关闭语义。如果追求低延迟，可以用有界无锁 MPMC 环形队列：全局原子 head/tail 通过 CAS 分配唯一位置，每个槽位带 sequence 判断满/空和轮次，生产者写完元素后 release 发布，消费者 acquire 看到就绪后读取并释放槽位。工程上还要处理容量、失败退避、false sharing、异常安全和对象生命周期；不能简单用两个原子下标 `load/store`，那不是正确的 MPMC。
