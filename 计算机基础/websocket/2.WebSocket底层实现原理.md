# 2. WebSocket 底层实现原理

## 1. 问题背景

WebSocket 是一种基于 TCP 的全双工通信协议，允许客户端和服务器在单个 TCP 连接上进行双向通信。与传统 HTTP 请求-响应模式不同，WebSocket 可以让服务器主动向客户端推送数据。

假设条件：本文档基于 RFC 6455（WebSocket 协议标准），分析 Firefox、Chrome 等主流浏览器和常见服务端的实现。

## 2. 问题现象

1. WebSocket 如何实现全双工通信
2. 握手过程中 Sec-WebSocket-Key 的作用是什么
3. 数据帧的结构是怎样的
4. 为什么客户端发送的帧需要掩码
5. 如何处理大消息的分片传输

## 3. 影响范围

| 维度 | 影响 |
| --- | --- |
| 实时性 | 延迟从秒级降低到毫秒级 |
| 资源消耗 | 相比 HTTP 长轮询，服务器资源消耗大幅降低 |
| 开发复杂度 | 需要处理连接管理、心跳、断线重连等逻辑 |
| 兼容性 | 需要处理代理服务器、WebSocket 兼容性问题 |

## 4. 原因分析

### 4.1 WebSocket 协议栈位置

```
OSI 模型：
┌──────────────────────┐
│      应用层           │  WebSocket
├──────────────────────┤
│      表示层           │
├──────────────────────┤
│      会话层           │
├──────────────────────┤
│      传输层           │  TCP
├──────────────────────┤
│      网络层           │  IP
└──────────────────────┘
```

WebSocket 协议位于 OSI 应用层，基于 TCP 传输协议实现。

### 4.2 协议握手详解

#### 4.2.1 客户端握手请求

```http
GET /ws HTTP/1.1
Host: server.example.com
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Key: dGhlIHNhbXBsZSBub25jZQ==
Sec-WebSocket-Version: 13
Origin: http://example.com
```

关键头部说明：

| 头部 | 说明 |
| --- | --- |
| `Upgrade: websocket` | 协议升级标识 |
| `Connection: Upgrade` | HTTP/1.1 协议转换标识 |
| `Sec-WebSocket-Key` | 16 字节随机 Base64 编码，用于防止缓存代理误解 |
| `Sec-WebSocket-Version` | 协议版本，RFC 6455 规定为 13 |

#### 4.2.2 服务端握手响应

```http
HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: s3pPLMBiTxaQ9kYG3hZbKOAxFI=
```

**Sec-WebSocket-Accept 计算过程**：

```python
import hashlib
import base64

client_key = "dGhlIHNhbXBsZSBub25jZQ=="
magic_string = "258EAFA5-E914-47DA-95CA-C5AB0DC85B11"

# 1. 拼接
combined = client_key + magic_string
# 2. SHA-1 哈希
sha1_hash = hashlib.sha1(combined.encode()).digest()
# 3. Base64 编码
accept = base64.b64encode(sha1_hash).decode()
# 结果：s3pPLMBiTxaQ9kYG3hZbKOAxFI=
```

#### 4.2.3 握手安全性分析

握手设计的目的：
1. 确保服务器支持 WebSocket 协议（非普通 HTTP 服务器）
2. 防止代理服务器缓存 WebSocket 握手响应
3. 防止 WebSocket 被用作 HTTP 缓存攻击向量

### 4.3 数据帧结构

RFC 6455 定义的数据帧格式：

```
┌─────────────┬─────────────┬─────────────┬─────────────┬─────────────┐
│     FIN     │    RSV1     │    RSV2     │    RSV3     │     OPCODE │
│     1位      │     1位      │     1位      │     1位      │     4位     │
├─────────────┼─────────────┼─────────────┼─────────────┼─────────────┤
│               MASK（掩码标志）│          PAYLOAD LEN（负载长度）          │
│                 1 位         │              7 位 / 7+64 位             │
├─────────────┴─────────────┴─────────────────────────────────────────┤
│                         MASKING-KEY（掩码密钥）                        │
│                              0 或 32 位                               │
├─────────────────────────────────────────────────────────────────────┤
│                              PAYLOAD DATA                             │
│                           扩展数据 + 应用数据                         │
└─────────────────────────────────────────────────────────────────────┘
```

#### 帧首字节：

| 位 | 说明 |
| --- | --- |
| FIN (1位) | 1=消息最后一帧，0=消息未完 |
| RSV1-3 (3位) | 扩展用，必须为 0，除非协商了扩展 |
| OPCODE (4位) | 0x0=继续帧，0x1=文本帧，0x2=二进制帧，0x8=关闭帧，0x9=Ping，0xA=Pong |

#### 帧长度：

| 长度值 | 实际长度 |
| --- | --- |
| 0-125 | 直接表示 |
| 126 | 后续 2 字节无符号整数 |
| 127 | 后续 8 字节无符号整数 |

#### 客户端掩码：

客户端发送的帧必须掩码，掩码密钥为 4 字节。掩码算法：

```python
def mask_payload(masking_key, payload):
    """XOR 掩码"""
    masked = bytearray()
    for i, byte in enumerate(payload):
        masked.append(byte ^ masking_key[i % 4])
    return bytes(masked)
```

### 4.4 帧分片机制

大消息可以通过多个帧传输：

```
帧 1: FIN=0, OPCODE=1, DATA="Hello "
帧 2: FIN=0, OPCODE=0, DATA="World "
帧 3: FIN=1, OPCODE=0, DATA="!"
```

规则：
1. 第一个帧的 OPCODE 非 0
2. 中间帧的 OPCODE 必须为 0
3. 最后帧的 FIN 必须为 1

### 4.5 控制帧

**关闭帧 (OPCODE=0x8)**：

```
┌───────┬─────────┬───────────┬─────────────┐
│ FIN=1 │ OPCODE=8│  Length   │ Close Code │
│       │         │   +      │   + Reason │
└───────┴─────────┴───────────┴─────────────┘
```

常见关闭码：

| 代码 | 说明 |
| --- | --- |
| 1000 | 正常关闭 |
| 1001 | 服务器即将关闭 |
| 1002 | 协议错误 |
| 1003 | 不支持的数据类型 |
| 1006 | 异常关闭（禁止发送） |
| 1009 | 消息太大 |
| 1010 | 必需扩展缺失 |

**Ping/Pong 帧 (OPCODE=0x9/0xA)**：

用于心跳检测，连接保活。

### 4.6 连接生命周期

```
建立连接
    ↓
HTTP 握手
    ↓
全双工通信 ←→ (Ping/Pong 心跳)
    ↓
发送/接收关闭帧
    ↓
TCP 断开
```

## 5. 解决方案

### 5.1 服务端实现

```python
import asyncio
import websockets
import hashlib
import base64
import os

# 简单 WebSocket 服务端
async def echo(websocket, path):
    async for message in websocket:
        await websocket.send(message)

asyncio.run(websockets.serve(echo, "localhost", 8765))
```

### 5.2 客户端实现

```javascript
const ws = new WebSocket('ws://localhost:8765');

ws.onopen = () => {
    console.log('Connection opened');
    ws.send('Hello Server');
};

ws.onmessage = (event) => {
    console.log('Received:', event.data);
};

ws.onclose = () => {
    console.log('Connection closed');
};

// 心跳保活

    if (ws.readyState === WebSocket.OPEN) {
        ws.send(JSON.stringify({type: 'ping'}));
    }
}, 30000);
```

### 5.3 手动实现握手（底层理解）

```python
import socket
import hashlib
import base64
import os

MAGIC_STRING = "258EAFA5-E914-47DA-95CA-C5AB0DC85B11"

def generate_handshake_request():
    key = base64.b64encode(os.urandom(16)).decode()
    request = (
        f"GET / HTTP/1.1\r\n"
        f"Host: localhost:8765\r\n"
        f"Upgrade: websocket\r\n"
        f"Connection: Upgrade\r\n"
        f"Sec-WebSocket-Key: {key}\r\n"
        f"Sec-WebSocket-Version: 13\r\n"
        f"\r\n"
    )
    return request, key

def verify_handshake_response(response, client_key):
    # 解析响应头
    lines = response.split("\r\n")
    if not lines[0].startswith("HTTP/1.1 101"):
        raise Exception("Handshake failed")
    
    # 验证 Sec-WebSocket-Accept
    accept_header = [l for l in lines if l.startswith("Sec-WebSocket-Accept:")]
    if not accept_header:
        raise Exception("No Sec-WebSocket-Accept header")
    
    server_accept = accept_header[0].split(": ")[1]
    expected_accept = base64.b64encode(
        hashlib.sha1((client_key + MAGIC_STRING).encode()).digest()
    ).decode()
    
    if server_accept != expected_accept:
        raise Exception("Invalid Sec-WebSocket-Accept")

def recv_frame(sock):
    data = sock.recv(2)
    if len(data) < 2:
        return None
    
    first_byte, second_byte = data
    fin = (first_byte >> 7) & 1
    opcode = first_byte & 0x0F
    masked = (second_byte >> 7) & 1
    length = second_byte & 0x7F
    
    # 扩展长度
    if length == 126:
        ext = sock.recv(2)
        length = int.from_bytes(ext, 'big')
    elif length == 127:
        ext = sock.recv(8)
        length = int.from_bytes(ext, 'big')
    
    # 掩码密钥
    masking_key = b""
    if masked:
        masking_key = sock.recv(4)
    
    # 负载数据
    payload = b""
    if length > 0:
        payload = sock.recv(length)
    
    # 解掩码
    if masked and masking_key:
        payload = bytes(b ^ masking_key[i % 4] for i, b in enumerate(payload))
    
    return payload

def send_frame(sock, data, opcode=0x01):
    # 文本帧
    length = len(data)
    first_byte = 0x80 | opcode  # FIN=1, OPCODE
    
    if length < 126:
        frame = bytes([first_byte, length]) + data
    elif length < 65536:
        frame = bytes([first_byte, 126]) + length.to_bytes(2, 'big') + data
    else:
        frame = bytes([first_byte, 127]) + length.to_bytes(8, 'big') + data
    
    sock.sendall(frame)
```

## 9. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |

## 11. 总结

### 核心原理

1. **协议升级**：通过 HTTP 101 状态码从 HTTP 升级到 WebSocket
2. **全双工**：握手后基于 TCP 实现真正的双向通信
3. **轻量帧**：数据帧头部仅 2-14 字节，开销极小
4. **掩码机制**：客户端帧必须掩码，防止代理缓存攻击

### 面试回答模板

WebSocket 底层是基于 TCP 的全双工通信协议，通过 HTTP 握手升级实现。客户端发送带有 `Sec-WebSocket-Key` 的升级请求，服务器计算 `Sec-WebSocket-Accept`（Key + 魔法字符串 SHA1 Base64）返回 101 响应后，连接升级为 WebSocket。

数据帧由 2-14 字节头部和负载组成，帧头包含 FIN（是否最后一帧）、OPCODE（数据类型）、掩码位和长度。客户端发送的帧必须掩码，通过 XOR 算法防止代理误解。

相比 HTTP 长轮询，WebSocket 只需一次握手，后续通信开销极小（2-14 字节帧头），服务器可主动推送，真正实现低延迟全双工通信。
