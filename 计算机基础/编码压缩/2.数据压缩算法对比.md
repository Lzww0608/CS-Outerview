## 二、LZ4 算法

### 2.1 算法原理

LZ4 是一种极速的无损压缩算法，属于 LZ77 家族，核心是**匹配字典 + 字节写入**。

```c
// LZ4 简化原理
void compress_lz4(const uint8_t* input, size_t len, uint8_t* output, size_t* out_len) {
    const uint8_t* ip = input;       // 输入指针
    const uint8_t* anchor = input;  // 匹配起始点
    const uint8_t* ip_limit = input + len - 12;
    
    while (ip < ip_limit) {
        // 1. 查找最长匹配
        int match_len = 0;
        int match_offset = 0;
        
        const uint8_t* best_match = find_longest_match(ip, ip + 65535, &match_len, &match_offset);
        
        if (match_len >= 4) {
            // 2. 输出匹配
            emit_token(output, MATCH, match_offset, match_len);
            ip += match_len;
        } else {
            // 3. 输出字面量
            emit_token(output, LITERAL, 0, 1);
            *output++ = *ip++;
        }
    }
}
```

### 2.2 优缺点

| 优点 | 缺点 |
|------|------|
| 极快的压缩/解压速度 | 压缩比相对较低 |
| 内存占用低 | 不适合高重复数据 |
| 适合实时压缩 | - |

## 三、ZSTD 算法

### 3.1 算法原理

ZSTD（Zstandard）是 Facebook 开源的高压缩比算法，采用**字典编码 + 熵编码 + 上下文模型**。

```text
ZSTD 压缩流程：
┌─────────────────────────────────────────────────────────────┐
│  输入数据                                                 │
│     │                                                      │
│     ▼                                                      │
│  ┌─────────────────┐                                       │
│  │  LZ77 压缩     │  匹配字典 + 字面量                    │
│  └────────┬────────┘                                       │
│           │                                                  │
│           ▼                                                  │
│  ┌─────────────────┐                                       │
│  │  FSE/Huffman   │  熵编码                              │
│  └────────┬────────┘                                       │
│           │                                                  │
│           ▼                                                  │
│  ┌─────────────────┐                                       │
│  │   压缩数据     │                                       │
│  └─────────────────┘                                       │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 优缺点

| 优点 | 缺点 |
|------|------|
| 高压缩比（可调） | 压缩速度中等 |
| 压缩级别可调 | 解压速度比 LZ4 慢 |
| 支持字典训练 | - |

## 四、Delta 编码

### 4.1 算法原理

Delta 编码存储数据之间的**差值**，适合有序递增的数据。

```c
// Delta 编码示例
// 输入：100, 102, 105, 108, 110
// 存储：100, 2, 3, 3, 2  (第一个值 + 差值)

// 压缩
int32_t previous = input[0];
output[0] = previous;

for (int i = 1; i < len; i++) {
    output[i] = input[i] - previous;  // 存储差值
    previous = input[i];
}

// 解压
int32_t current = output[0];
result[0] = current;

for (int i = 1; i < len; i++) {
    current += output[i];  // 累加恢复
    result[i] = current;
}
```

### 4.2 优缺点

| 优点 | 缺点 |
|------|------|
| 极简单，压缩快 | 只适合有序/递增数据 |
| 增量小则压缩比高 | 数据无规律时无效 |

## 五、Gorilla 编码

### 5.1 算法原理

Gorilla 是 Facebook 开源的**时序数据压缩算法**，基于 XOR 和 位移编码。

```c
// Gorilla 压缩原理
void compress_gorilla(int64_t* values, int count, uint8_t* output) {
    int64_t prev = 0;
    int64_t prev_xor = 0;
    int out_pos = 0;
    
    // 写入第一个值（完整）
    write_bits(output, &out_pos, values[0], 64);
    
    for (int i = 1; i < count; i++) {
        int64_t current = values[i];
        int64_t xor = prev ^ current;  // XOR 计算
        
        if (xor == 0) {
            // 情况1：值不变
            write_bits(output, &out_pos, 0, 1);  // 标志位 0
        } else {
            int leading = count_leading_zeros(xor);
            int trailing = count_trailing_zeros(xor);
            int value_bits = 64 - leading - trailing;
            
            if (leading >= prev_xor >> 57) {
                // 情况2：XOR 值在有效位内
                write_bits(output, &out_pos, 2, 2);  // 标志位 10
                write_bits(output, &out_pos, leading, 6);
                write_bits(output, &out_pos, xor >> (64 - leading - value_bits), value_bits);
            } else {
                // 情况3：XOR 值超出有效位
                write_bits(output, &out_pos, 3, 2);  // 标志位 11
                write_bits(output, &out_pos, current, 64);
            }
        }
        prev = current;
        prev_xor = xor >> (64 - leading - trailing);
    }
}
```

### 5.2 优缺点

| 优点 | 缺点 |
|------|------|
| 时序数据超高压缩比 | 只适合浮点/整数时序 |
| 适合 IoT、监控场景 | 数据无规律时无效 |
| 解压速度快 | - |

## 六、对比总结

### 6.1 性能对比

| 算法 | 压缩速度 | 解压速度 | 压缩比 | 适用场景 |
|------|----------|----------|---------|----------|
| LZ4 | 极快 | 极快 | 中等 | 实时压缩、数据库 |
| ZSTD | 可调(快-慢) | 快 | 高 | 通用压缩、传输 |
| Delta | 极快 | 极快 | 高(有序数据) | 时序数据、数值数组 |
| Gorilla | 快 | 快 | 极高(时序) | 时序监控、IoT |

### 6.2 选型指南

```text
数据特点                推荐算法
─────────────────────────────────
通用文件压缩            → ZSTD
实时通信压缩            → LZ4
时序监控数据            → Gorilla
有序数值数组            → Delta + LZ4
混合数据               → ZSTD
```

## 七、面试常见问题

### Q1: LZ4 和 ZSTD 的区别？

LZ4 追求极致速度，ZSTD 追求高压缩比。ZSTD 可以调节压缩级别（1-22），速度可牺牲换取更高压缩比。

### Q2: Gorilla 适合什么场景？

Gorilla 专为时序数据设计，适合 IoT 传感器、监控系统、股票价格等有序时序数据，压缩比可达 10x 以上。

### Q3: Delta 编码的原理？

存储相邻数据的差值，有序递增数据差值小，压缩效果好。

---

## 八、总结

1. **LZ4**：极速压缩，适合实时场景
2. **ZSTD**：高压缩比可调，通用场景
3. **Delta**：有序数值数组专用
4. **Gorilla**：时序数据压缩之王
