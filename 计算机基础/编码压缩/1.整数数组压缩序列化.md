# 1. 整数数组压缩序列化

题目类似“序列化数组 `[1,100,1000...]`，如何尽可能节省空间并且快速序列化、反序列化”。核心不是只说 Protobuf，而是要根据整数分布选择编码方式，并在空间、速度和随机访问之间取舍。

## 1. 基础方案

最简单方案是固定宽度二进制编码：

```text
int32: 每个整数 4 字节
int64: 每个整数 8 字节
```

优点：

1. 编码和解码快。
2. 支持 O(1) 随机访问。
3. 实现简单。

缺点：

1. 小整数浪费空间。
2. 数据分布差异大时压缩率低。
3. 跨语言时要约定大小端、符号和版本。

如果数组都是小正整数，固定 32 位通常不是最省空间。

## 2. Varint 变长整数

Varint 用 1 到多个字节表示一个整数，小数占更少字节。每个字节用 7 bit 存数据，最高 bit 表示是否还有后续字节。

适合：

1. 大多数数值较小。
2. 数组需要顺序扫描。
3. 希望实现简单且跨语言。

例如：

```text
1      -> 1 字节
100    -> 1 字节
1000   -> 2 字节
100000 -> 3 字节左右
```

缺点是随机访问困难，因为第 `i` 个数的位置要从前面扫描才能知道。

## 3. Delta 编码

如果数组单调递增或相邻值差距小，可以存差值：

```text
原数组: [1, 100, 1000, 1010]
delta: [1, 99, 900, 10]
```

再对 delta 使用 varint，通常能显著变小。

适合：

1. ID 列表。
2. 时间戳序列。
3. 倒排索引 doc_id。
4. 有序主键或日志 offset。

如果差值可能为负，可以用 ZigZag 编码把有符号整数映射成无符号整数：

```text
0 -> 0
-1 -> 1
1 -> 2
-2 -> 3
2 -> 4
```

这样小的负数也能用较少字节表示。

## 4. Bit Packing

如果一批整数的最大值较小，可以用固定 bit 宽打包。

例如一组 delta 最大值小于 1024，只需要 10 bit：

```text
32 个 int32 原本 128 字节
32 个 10-bit 数约 40 字节
```

常见做法是分块：

```text
block header: count, bit_width, base
block data: packed integers
```

适合：

1. 大批量整数。
2. 列式存储。
3. 搜索引擎倒排索引。
4. OLAP 中的整数列压缩。

缺点是实现比 varint 复杂，解码需要位运算，随机访问通常以 block 为粒度。

## 5. Frame 格式怎么设计

一个可扩展的序列化格式至少要包含：

```text
magic/version
encoding_type
count
flags
payload_length
payload
checksum 可选
```

例如：

```text
version = 1
encoding = delta_varint
count = 100000
payload = ...
```

这样后续可以从 `delta_varint` 升级到 `bitpack`、`zstd`、`patched frame-of-reference`，旧版本仍可解析。

## 6. 怎么兼顾快和省

常见组合：

1. **小规模数组**：固定宽度或 varint，减少复杂度。
2. **递增 ID 数组**：delta + varint。
3. **大规模有序整数**：分块 delta + bit packing。
4. **包含异常大值**：Frame-of-Reference + exception list。
5. **追求极限压缩**：先整数编码，再用 zstd/lz4 二次压缩。
6. **追求极限速度**：固定宽度、SIMD-BP128、StreamVByte、Roaring Bitmap。

如果是集合而不是普通数组，还可以考虑 Roaring Bitmap。它对稀疏和稠密整数集合都比较友好，并支持交并差操作。

## 7. 易错点

1. JSON 文本序列化可读性好，但空间和解析速度都差。
2. Varint 省空间但随机访问弱。
3. Delta 编码要求解码时保留前一个值，数据损坏会影响后续。
4. 压缩率要看数据分布，不能脱离样本拍脑袋选方案。
5. 跨机器传输必须定义大小端、符号、版本和校验。
6. 如果需要频繁随机访问，要设计 block index 或固定宽度块。

## 8. 面试回答模板

我会先看数组的数据分布。如果是普通整数且追求速度，可以用固定宽度二进制编码；如果大多数值较小，用 varint；如果数组有序或相邻差值小，用 delta + varint；如果是大批量整数列，可以按 block 做 delta、base 和 bit packing；如果是整数集合并且要做交并差，可以考虑 Roaring Bitmap。格式上要有 version、encoding、count、payload length 和 checksum，方便演进和校验。最终方案要用真实数据评估压缩率、序列化/反序列化速度、随机访问能力和实现复杂度。
