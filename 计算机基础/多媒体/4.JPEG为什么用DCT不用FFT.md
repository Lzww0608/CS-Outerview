# JPEG 为什么用 DCT 不用 FFT

JPEG 的核心变换是 DCT（Discrete Cosine Transform，离散余弦变换），而不是 FFT（Fast Fourier Transform，快速傅里叶变换）。关键原因是图像块压缩更需要实数、能量集中、边界友好和易量化的变换。

## JPEG 编码简化流程

1. RGB 转 YCbCr。
2. 可选色度降采样，例如 4:2:0。
3. 分成 8x8 图像块。
4. 对每个块做 2D DCT。
5. 对 DCT 系数量化，高频系数更容易被量化为 0。
6. Zigzag 扫描，把低频到高频排成序列。
7. RLE + Huffman/算术编码。

## DCT 的特点

DCT 可以看成对实数信号做偶对称扩展后的余弦基分解。对自然图像的小块来说，大部分能量集中在左上角低频系数，高频系数通常较小，适合量化压缩。

优点：

1. 输入输出都是实数，适合图像像素块。
2. 能量集中能力强，自然图像低频成分占主导。
3. 边界延拓相对平滑，块边界不连续影响比直接周期延拓更小。
4. 计算复杂度低，硬件和 SIMD 优化成熟。
5. 量化表可以按人眼对高频不敏感的特点设计。

## 为什么不用 FFT

FFT 是 DFT 的快速算法。DFT 使用复指数基，天然假设信号周期延拓。对 8x8 图像块直接使用 DFT/FFT 会有几个问题：

1. **复数输出**：需要处理实部/虚部或幅度/相位，编码复杂度更高。
2. **周期边界假设**：块左右、上下边界被当作周期相接，不连续会引入更多高频能量。
3. **能量集中不如 DCT 适合图像块**：DCT 的偶对称边界对自然图像块更友好。
4. **JPEG 量化和视觉模型更适配 DCT 系数**。

注意：FFT 是算法，DFT 是变换。严格说“为什么不用 FFT”更准确地问法是“为什么不用 DFT/傅里叶变换”。FFT 可以加速傅里叶变换，但它不改变傅里叶基的这些特性。

## 易错点

1. JPEG 不是因为 DCT 无损才用 DCT，损失主要来自量化。
2. DCT 本身是可逆或近似可逆的线性变换，量化才是 JPEG 有损压缩的核心。
3. FFT 不是压缩算法，而是计算 DFT 的快速算法。
4. DCT 用 8x8 块会带来块效应，高压缩率下更明显。

## 面试回答模板

JPEG 用 DCT，是因为自然图像在小块上能量主要集中在低频 DCT 系数，后续可以对高频强量化来压缩；DCT 输入输出实数，边界相当于偶对称扩展，比 DFT 的周期延拓更适合 8x8 图像块，复数处理也更少。FFT 是计算傅里叶变换的快速算法，不是压缩本身；傅里叶变换对块边界不连续更容易产生高频能量，不如 DCT 适合 JPEG 的量化和视觉模型。
