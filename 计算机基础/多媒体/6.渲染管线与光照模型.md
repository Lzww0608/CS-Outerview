# 6. 渲染管线与光照模型

渲染管线描述的是一组 3D 数据如何被转换成屏幕上的像素。面试里问“渲染管线”和“光照模型”，重点不是背 API 名字，而是说明顶点、三角形、片元、深度和光照计算之间的关系。

## 1. 渲染管线整体流程

典型实时渲染管线：

```text
应用阶段
-> 顶点处理
-> 图元装配
-> 裁剪与透视除法
-> 光栅化
-> 片元/像素着色
-> 深度/模板测试
-> 混合
-> 帧缓冲输出
```

## 2. 应用阶段

应用阶段运行在 CPU 侧，主要负责：

1. 加载模型、贴图、材质和动画。
2. 做场景管理、可见性裁剪、LOD、批处理。
3. 准备 draw call、常量缓冲、纹理和渲染状态。
4. 把顶点缓冲和索引缓冲提交给 GPU。

性能瓶颈可能出现在 draw call 太多、状态切换频繁、CPU/GPU 同步等待、资源上传过多等地方。

## 3. 顶点处理和坐标空间

顶点着色器通常把模型局部坐标转换到裁剪空间：

```text
model space
-> world space
-> view/camera space
-> clip space
-> NDC
-> screen space
```

常见矩阵：

1. `Model`：模型到世界。
2. `View`：世界到相机。
3. `Projection`：相机到裁剪空间。
4. `MVP = Projection * View * Model`。

顶点阶段还会传递法线、UV、颜色、切线等插值数据给后续片元阶段。

## 4. 图元装配、裁剪和光栅化

GPU 通常以三角形为基本图元：

1. **图元装配**：根据索引缓冲把顶点组装成点、线或三角形。
2. **裁剪**：裁掉视锥外或近远平面外的部分。
3. **透视除法**：用 `w` 分量把裁剪空间转换到 NDC。
4. **光栅化**：确定三角形覆盖哪些屏幕像素，生成片元，并对顶点属性做插值。

这里的片元还不是最终像素，后面可能被深度测试、模板测试或混合阶段丢弃。

## 5. 片元着色和输出合并

片元着色器通常计算最终颜色：

1. 采样纹理。
2. 计算法线、光照、阴影和材质。
3. 输出颜色、深度或多个 G-Buffer。

之后进入输出合并阶段：

1. **深度测试**：解决遮挡关系。
2. **模板测试**：用于描边、镜面、遮罩等效果。
3. **混合**：处理透明、粒子、UI 等需要和已有颜色混合的对象。

透明物体通常需要从远到近排序；不透明物体则常配合深度测试和 early-z 减少 overdraw。

## 6. 常见光照模型

### 6.1 环境光

环境光用一个常量近似间接光：

```text
ambient = ka * Ia
```

它简单但不真实，常用于避免背光面全黑。

### 6.2 Lambert 漫反射

Lambert 漫反射和法线、光线方向夹角有关：

```text
diffuse = kd * Id * max(dot(N, L), 0)
```

物理直觉是表面越正对光源，单位面积接收到的光越多。

### 6.3 Phong 和 Blinn-Phong

Phong 模型由环境光、漫反射、高光组成：

```text
color = ambient + diffuse + specular
```

Phong 高光使用反射方向 `R` 和观察方向 `V`：

```text
specular = ks * Is * pow(max(dot(R, V), 0), shininess)
```

Blinn-Phong 使用半程向量 `H = normalize(L + V)`：

```text
specular = ks * Is * pow(max(dot(N, H), 0), shininess)
```

Blinn-Phong 通常计算更稳定，也更常用于实时渲染入门模型。

### 6.4 PBR

PBR（Physically Based Rendering）更接近真实材质，常用参数包括：

1. `baseColor`：基础颜色。
2. `metallic`：金属度。
3. `roughness`：粗糙度。
4. `normal`：法线贴图。
5. `ambient occlusion`：环境遮蔽。

PBR 通常基于微表面 BRDF，配合 IBL、环境贴图、预积分 BRDF LUT 等技术，能让材质在不同光照环境下更一致。

## 7. 易错点

1. 顶点着色器处理的是顶点，片元着色器处理的是光栅化后的片元，不是直接处理“模型”。
2. 法线不能简单用 Model 矩阵变换，非均匀缩放下要用逆转置矩阵。
3. 深度冲突（z-fighting）常来自近平面太近、远近平面比例过大或两个面几乎重合。
4. 透明物体通常不能只依赖深度写入，需要排序和混合策略。
5. 颜色空间要区分线性空间和 sRGB，错误的 gamma 处理会让光照不真实。
6. PBR 不等于“更高级贴图”，核心是能量守恒和基于物理的材质参数。

## 8. 真实场景应用

1. **游戏渲染**：实时管线关注帧率、draw call、overdraw、材质数量和 GPU 带宽。
2. **客户端 UI/特效**：透明混合、模板测试、批处理非常常见。
3. **视觉仿真**：需要更准确的光照、阴影和相机模型。
4. **离线渲染**：更关注全局光照、路径追踪和真实感，实时性要求较低。

## 9. 面试回答模板

渲染管线可以从 CPU 应用阶段讲到 GPU 输出：应用层准备模型、材质、纹理和 draw call；顶点着色器把顶点从模型空间变换到裁剪空间；图元装配后裁剪、透视除法并光栅化成片元；片元着色器计算纹理和光照；最后经过深度、模板和混合写入帧缓冲。常见光照模型有 Lambert 漫反射、Phong/Blinn-Phong 高光，以及更现代的 PBR。工程上要注意法线变换、深度冲突、透明排序、gamma/线性空间、draw call 和 overdraw。
