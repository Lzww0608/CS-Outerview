**指针碰撞**（Bump Pointer 或 Pointer Bumping）是一种**极其高效的内存分配算法**。

简单来说，它就像是在一张白纸上写字，写完一个字，笔尖直接往后移，接着写下一个字，不需要满纸去找空白处。

以下是关于它的详细解析，包括原理、优缺点以及它在多线程环境下的优化。

------

### 1. 核心原理

假设内存是一块**绝对规整**的连续空间：

- 一边是**已使用的内存**。
- 一边是**空闲的内存**。
- 中间有一个**分界点指针**（即 Bump Pointer）。

当程序需要分配 $N$ 字节的内存时，分配器只需要做两步简单的操作：

1. **检查**：当前指针位置 + $N$ 是否超过了内存总上限？
2. **移动**：如果没有超过，将指针向空闲方向移动 $N$ 个距离，并将原来的指针位置返回给程序作为新对象的地址。

> 图解：
>
> [已用内存] <指针> [-----------空闲内存-----------]
>
> ↓ 分配对象 A (大小 10)
>
> [已用内存 + A] <指针+10> [-------空闲内存-------]

### 2. 前提条件：内存必须规整

这是指针碰撞最大的限制。**内存必须是整理过的，不能有碎片（空洞）。**

- 如果内存中 deleted 的对象留下了很多空洞（碎片），你就不能简单地往下移动指针，因为你可能会跳过可用的空洞，或者覆盖了后面还存活的对象。
- 因此，指针碰撞通常配合**带有内存整理（Compacting）或复制（Copying）功能的垃圾回收器**使用。
  - **Java (JVM)**：Java 的新生代（Eden区）使用的是复制算法，内存极其规整，所以默认使用指针碰撞分配，速度极快。
  - **Go (Golang)**：Go 的 GC 是**不移动对象**的（Non-moving GC），内存中会有碎片，所以 Go 的堆内存分配主要使用的是**空闲链表（Free List）**结合位图的机制（基于 tcmalloc），而不是单纯的指针碰撞。

### 3. 优缺点分析

| **特性**               | **说明**                                                     |
| ---------------------- | ------------------------------------------------------------ |
| **优点：速度极快**     | 仅仅是几次 CPU 指令（读取指针、加法运算、比较），几乎等同于栈分配的速度。 |
| **优点：缓存友好**     | 分配出来的对象在物理内存上是连续的（Spatial Locality），这非常利于 CPU 缓存（Cache Line）的命中，提高程序性能。 |
| **缺点：无法处理碎片** | 如果内存像“瑞士奶酪”一样全是洞，就无法使用此方法。必须配合复杂的 GC 算法（如复制算法）来整理内存。 |
| **缺点：并发瓶颈**     | 在多线程环境下，所有线程都去抢这一个指针，必须加锁（或使用 CAS），这会成为性能瓶颈。 |

### 4. 并发优化：TLAB

为了解决上述的“多线程竞争同一个指针”的问题，现代运行时（如 JVM）引入了 **TLAB (Thread Local Allocation Buffer)**。

**原理：**

1. 每个线程在初始化时，先向堆内存“批发”申请一块较大的私有内存块（例如 1% 的 Eden 区）。
2. 在这个**私有的**内存块内部，线程使用**指针碰撞**来分配对象。
3. 因为这块内存是线程私有的，所以**不需要加锁**。
4. 只有当 TLAB 用完了，需要申请新的 TLAB 时，才需要去竞争全局锁。

### 总结

- **指针碰撞** = 也就是“追加写”模式。
- **场景**：适用于内存规整（通常是 Copying GC）的场景，如 Java 的新生代。
- **对比**：与之相对的是 **空闲链表 (Free List)**，适用于内存不规整（有碎片）的场景，需要查表找空位，速度相对较慢（Go 语言主要使用类 Free List 机制）。
