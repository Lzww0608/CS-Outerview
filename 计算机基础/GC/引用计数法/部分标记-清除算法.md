**部分标记-清除算法（Partial Mark-and-Sweep）** 是一种专门为了配合 **引用计数法（Reference Counting）** 而设计的辅助算法。

它的核心目的是：**解决引用计数法无法回收“循环引用”的缺陷，同时避免像全量 GC 那样扫描整个堆。**

简单来说，它不是去检查“所有的对象”，而是只去检查那些**“看起来很像垃圾的嫌疑对象”**。

------

### 1. 为什么需要它？（背景：循环引用的噩梦）

在引用计数法中，如果对象 A 和对象 B 互相引用（A 指向 B，B 指向 A），但外界没有任何指针指向它们：

- 它们的引用计数都是 1。
- 因为计数不是 0，标准的引用计数器永远不会回收它们。
- 这就是**内存泄漏**。

**部分标记-清除**就是为了抓出这种“互相抱团但其实已经没人要”的垃圾团伙。

### 2. 核心思想：只查“嫌疑人”

全量的标记-清除（Mark-Sweep）会扫描整个内存堆，这太慢了。

部分标记-清除认为：只有那些引用计数减少了，但没有减到 0 的对象，才可能是循环引用的根源。

- 如果计数减到 0：直接回收了，没问题。
- 如果计数没变：说明关系很稳定，大概率不是刚刚产生的垃圾。
- **如果计数减少了（比如从 2 变成 1）：** 这就很可疑了！它可能刚刚断开了外部链接，只剩下一个内部循环链接。

### 3. 算法流程（四色标记法）

为了直观理解，研究者（如 David Bacon）通常用颜色来标记对象的状态。

#### 第一步：筛选嫌疑人（Generate Candidates） -> **紫色 (Purple)**

当程序运行（Mutator）修改指针，导致某个对象的引用计数减少（`decref`），但结果仍然 **> 0** 时：

- 这个对象被标记为 **紫色**。
- 它被加入到一个**“候选缓冲区”（Candidate Buffer）**中。
- **含义**：它可能是循环垃圾的一部分，待审。

#### 第二步：模拟试探（Mark / Gray） -> **灰色 (Grey)**

当候选区满了，GC 线程启动。它遍历候选对象，进行一次**“模拟遍历”**：

- 沿着引用链往下走，把沿途对象的计数器**“临时减 1”**（只在逻辑上减，不改写真实的计数器）。
- **含义**：如果你这个圈子是封闭的（循环引用），那么我把你们内部互相指的线都剪断后，你们的计数器应该都会变成 0。

#### 第三步：确认死活（Scan / Black or White）

再次遍历这些对象，检查它们“临时减 1”后的结果：

- **情况 A（变成了 0） -> 白色 (White)**：说明它的引用全来自于圈子内部。你是垃圾！标记为白色。
- **情况 B（仍然 > 0） -> 黑色 (Black)**：说明还有圈子**外部**的指针指着它。你不是垃圾！把刚才减掉的计数加回去，恢复原状，标记为黑色。

#### 第四步：回收（Collect）

- 遍历白色的对象，释放内存。

### 4. 举个栗子

假设有一个循环：A -> B -> A。

外部有一个指针 ptr -> A。此时 A(2), B(1)。

1. **断开外部引用**：用户执行 `ptr = null`。
2. **降级**：A 的计数从 2 变成 1。
3. **入列**：A 没有变成 0，所以 A 被列为**“紫色嫌疑人”**。
4. **部分 GC 介入**：
   - 从 A 开始跑。
   - **模拟减**：GC 假装断开 A 对 B 的引用（B 变成 0），再假装断开 B 对 A 的引用（A 变成 0）。
   - **结果**：在这个封闭圈子里，它们计数都归零了。
5. **判定**：这是一个隔离的环，回收 A 和 B。

### 5. 总结

**部分标记-清除（Partial Mark-and-Sweep）** 是引用计数法的“补丁”。

- **全量 GC** 像是一个负责任的警察，挨家挨户查户口（扫描全堆），绝对精准但效率低。
- **部分 GC** 像是一个侦探，只盯着那些**最近有变动且行迹可疑**的人（候选队列），通过逻辑推理（模拟减法）来断案。



通常“1位计数器”不配合部分标记-清除算法。因为 1 位计数器连具体的数字都没有（只有 0 和 1），无法进行精细的“模拟减法”操作。1 位计数器通常直接配合全量的 Tracing GC（如普通的标记-清除）来兜底。
