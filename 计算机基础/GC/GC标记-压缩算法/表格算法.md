**表格算法（Table-Based Algorithm）**，通常是指在垃圾回收（GC）的**标记-整理（Mark-Compact）**阶段中使用的一种特定技术，全称往往被称为**Break Table（断点表）算法**或者**Table-Based Compaction**。

它是**标记-整理算法**的一种实现流派。

**表格算法**的设计初衷，是为了在**保持对象顺序（保序）**的前提下，尽量减少对堆的遍历次数，或者适用于某些不支持在对象头存储转发地址的特殊硬件/环境。

下面我从**核心思想、Break Table 的工作机制、优缺点**三个方面来详细解释。

---

### 1. 核心思想

表格算法的核心逻辑是：**不把新地址写在对象头里，而是把“空闲区域（垃圾）”的信息记录在一个独立的表格中。**

想象一下，如果把堆看作一条长长的纸带，存活对象是实心的，垃圾是空心的。
*   如果我们知道每一个“空心段（垃圾块）”有多长。
*   那么，对于任意一个存活对象，我们只要算出“它前面总共有多少垃圾”，就能算出它应该向左移动多少距离。

**公式**：
`对象的新地址 = 对象的旧地址 - 对象前方所有垃圾的总大小`

---

### 2. Break Table 的工作机制

这个算法最著名的实现是 **Haddon-Waite 算法**。它主要维护一个 **Break Table（断点表）**。

#### 步骤一：标记与构建表
1.  **标记**：正常的标记阶段，找出所有存活对象。
2.  **扫描并建表**：从头到尾扫描堆。
    *   每当遇到一个“存活对象”和“垃圾区域”的交界处（断点），就在 Break Table 中记录一条信息。
    *   **记录内容**：`{地址, 累计垃圾大小}`。
    *   也就是记录：在这个地址之前，已经发现了多少字节的垃圾。

#### 步骤二：移动对象 (Slide)
再次从头扫描堆，遇到存活对象时：
1.  查 Break Table（通常使用二分查找或哈希），找到该对象前面累计了多少垃圾（`total_garbage`）。
2.  计算新地址：`new_addr = old_addr - total_garbage`。
3.  执行 `memmove`。

#### 步骤三：修正引用 (Remap)
再次扫描堆，修正所有指针。
1.  对于每个指针指向的旧地址 `ptr`。
2.  查 Break Table，算出 `ptr` 前面的累计垃圾量。
3.  更新指针：`*ref = ptr - total_garbage`。

---

### 3. 优缺点深度分析

#### 优点
1.  **不需要修改对象头**：
    *   Lisp2 算法必须在对象头里硬塞一个 `forwarding address`。如果对象太小（比如只有 8 字节），可能根本塞不下，或者会破坏原有数据。
    *   表格算法把元数据存在堆外的表格里，**对对象本身是无侵入的**。
2.  **保序（Order Preserving）**：
    *   整理后的对象顺序与原来一致，缓存友好。

#### 缺点
1.  **额外的内存开销**：
    *   Break Table 本身需要占用内存。如果堆里的碎片非常多（垃圾块极其细碎），这个表格会变得非常大，甚至可能导致 OOM。
    *   *注：为了解决这个问题，通常会限制表格的大小，如果表满了，就只整理堆的一部分，或者放弃整理。*
2.  **查找开销**：
    *   在修正指针时，需要频繁查询 Break Table。虽然可以用二分查找，但相比 Lisp2 直接读对象头（O(1)），表格查询（O(logN)）还是慢了不少。

---

### 4. 总结

**表格算法**是标记-整理算法家族中的一个“异类”。

*   **Lisp2** 是把地图（新地址）画在对象脸上。
*   **表格算法** 是把地图（垃圾统计）画在手里的小本本上。

**适用场景**：
它主要用于那些**对象头无法被修改**，或者**对象极小且紧凑**的特殊系统环境中。在通用的现代 JVM（如 HotSpot）中，由于对象头本身就有设计好的 Mark Word 结构，Lisp2 风格的算法（Serial Old / Parallel Old）因为速度更快（O(1) 寻址），所以比表格算法更常用。
