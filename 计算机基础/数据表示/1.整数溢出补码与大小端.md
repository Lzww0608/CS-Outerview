# 整数溢出、补码与大小端

整数表示是 C/C++ 面试中的高频底层题。核心要分清：有符号整数范围、补码表示、溢出行为、无符号回绕，以及多字节数据在内存中的字节序。

## 1. int 范围和补码表示

常见平台上 `int` 是 32 位，范围通常是：

```text
INT_MIN = -2147483648 = -2^31
INT_MAX =  2147483647 =  2^31 - 1
```

C++ 标准不强制所有平台的 `int` 都是 32 位，工程代码应使用 `<limits>`：

```cpp
#include <limits>

auto lo = std::numeric_limits<int>::min();
auto hi = std::numeric_limits<int>::max();
```

现代机器几乎都使用补码表示有符号整数。32 位补码中，最高位是符号位：

```text
0x00000000 -> 0
0x00000001 -> 1
0x7fffffff -> 2147483647
0xffffffff -> -1
0x80000000 -> -2147483648
```

补码的好处是加减法可以统一用同一套二进制加法电路处理。注意 `INT_MIN` 的绝对值比 `INT_MAX` 大 1，所以 `abs(INT_MIN)` 会溢出。

## 2. 字符串转 int 如何判断溢出

不要等乘 10 加当前数字之后再判断，因为那一步可能已经溢出。应在更新前判断：

```cpp
#include <climits>
#include <string>

bool parseInt(const std::string& s, int& out) {
    int i = 0;
    int n = static_cast<int>(s.size());
    while (i < n && s[i] == ' ') {
        ++i;
    }

    int sign = 1;
    if (i < n && (s[i] == '+' || s[i] == '-')) {
        sign = (s[i] == '-') ? -1 : 1;
        ++i;
    }

    long long value = 0;
    bool hasDigit = false;
    long long limit = (sign == 1) ? INT_MAX : -(long long)INT_MIN;

    while (i < n && s[i] >= '0' && s[i] <= '9') {
        hasDigit = true;
        int digit = s[i] - '0';
        if (value > (limit - digit) / 10) {
            return false; // 溢出，可按题意改成截断到 INT_MAX/INT_MIN
        }
        value = value * 10 + digit;
        ++i;
    }

    if (!hasDigit) {
        return false;
    }
    out = static_cast<int>(sign == 1 ? value : -value);
    return true;
}
```

处理策略取决于题目：

1. 返回失败：如上面的 `bool` 接口。
2. 截断：类似 LeetCode `atoi`，超过范围返回 `INT_MAX` 或 `INT_MIN`。
3. 抛异常：类似 `std::stoi`，非法或越界抛异常。
4. 使用更大类型：中间过程用 `long long`，但仍要在最终转回 `int` 前检查范围。

## 3. 两个无符号数相加如何判断溢出

无符号整数溢出在 C/C++ 中是定义良好的，会按模 `2^N` 回绕。判断方式很简单：

```cpp
#include <cstdint>

bool addOverflow(uint32_t a, uint32_t b, uint32_t& sum) {
    sum = a + b;
    return sum < a; // 或 sum < b
}
```

因为如果发生回绕，结果一定小于至少一个加数。

也可以在加之前判断：

```cpp
#include <limits>

bool overflow = a > std::numeric_limits<uint32_t>::max() - b;
```

注意：无符号溢出是回绕；有符号整数溢出是未定义行为，不能用“结果变小”这种方式可靠判断有符号溢出。

## 4. 浮点数转整数会发生什么

面试里如果问：

```cpp
double x = 100.1;
long long y = x;
```

结果通常是 `100`。C++ 的浮点到整数转换会直接截断小数部分，也就是向 0 取整，不是四舍五入。

常见例子：

```cpp
double a = 100.9;
double b = -100.9;

long long x = static_cast<long long>(a); // 100
long long y = static_cast<long long>(b); // -100
```

需要特别注意范围问题：如果浮点数的值无法用目标整数类型表示，例如超过 `long long` 范围，或者是 NaN/Infinity，这种转换在 C++ 中会产生未定义行为或不可移植行为，不能依赖运行结果。

工程中更稳妥的做法是先检查范围和有限性：

```cpp
#include <cmath>
#include <limits>

bool toLongLong(double x, long long& out) {
    if (!std::isfinite(x)) {
        return false;
    }
    if (x < static_cast<double>(std::numeric_limits<long long>::min()) ||
        x > static_cast<double>(std::numeric_limits<long long>::max())) {
        return false;
    }
    out = static_cast<long long>(x); // 向 0 截断
    return true;
}
```

如果业务需要四舍五入，应显式使用 `std::round`、`std::llround` 等函数；如果需要向下或向上取整，应使用 `std::floor`、`std::ceil`。不要把隐式转换当成业务取整规则。

## 5. 判断当前机器是大端还是小端

字节序描述多字节整数在内存中的排列顺序：

1. **小端**：低有效字节放在低地址，例如 x86/x86-64。
2. **大端**：高有效字节放在低地址，网络字节序就是大端。

运行时判断：

```cpp
#include <cstdint>

bool isLittleEndian() {
    uint32_t x = 0x01020304;
    unsigned char* p = reinterpret_cast<unsigned char*>(&x);
    return p[0] == 0x04;
}
```

C++20 可以用标准库：

```cpp
#include <bit>

bool little = (std::endian::native == std::endian::little);
```

真实场景：

1. 网络协议字段要用 `htonl/htons/ntohl/ntohs` 转换。
2. 文件格式和序列化协议要明确字节序，避免跨平台解析错误。
3. 直接把结构体内存写到网络或文件里通常不可靠，还会受对齐、填充、版本影响。

## 6. 面试回答模板

常见 32 位 `int` 范围是 `[-2^31, 2^31-1]`，现代机器通常用补码表示，`INT_MIN` 比 `INT_MAX` 的绝对值大 1。字符串转 int 判断溢出要在 `value * 10 + digit` 之前判断，例如 `value > (limit - digit) / 10`。无符号加法溢出是定义好的回绕，可以用 `sum < a` 或 `a > max - b` 判断。浮点转整数会向 0 截断，例如 `100.1` 转 `long long` 得到 `100`，但超出目标范围时不能依赖结果。大小端看多字节整数的低地址保存高位还是低位，网络字节序是大端，跨机器通信和序列化必须显式约定字节序。
