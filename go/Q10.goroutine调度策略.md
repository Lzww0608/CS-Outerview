# Q10. goroutine调度策略

`Golang` 的调度器采用 M:N 调度模型，把大量 goroutine 调度到少量 OS 线程上运行。更准确地说，Go 运行时使用 G-M-P 模型：

1. **G**：goroutine，表示待执行的用户态任务。
2. **M**：machine，表示 OS 线程。
3. **P**：processor，表示调度器的执行资源，维护本地运行队列，数量通常由 `GOMAXPROCS` 决定。

只有拿到 P 的 M 才能执行 Go 代码。goroutine 不是固定占用某个 CPU，它会被调度到持有 P 的不同 OS 线程上运行，而 OS 线程再由内核调度到不同 CPU 核心。

`Go`调度器使用了三种队列来管理`goroutine`

1. **全局队列(Global Queue)**：此队列中包含了所有刚创建的`goroutine`。
2. **本地队列(Local Queue)**：每个P(Processor，处理器)都有一个本地队列，P会有限从本地队列中取出`goroutine`来执行。
3. **网络轮循器(Netpoller)**：此队列中包含了所有在等待网络时间(如IO操作)的`goroutine`。当网络事件就绪时，对应的`goroutine`会被放入到全局队列中，等待被P取出。



`Go`的调度器采用了工作窃取(Work Stealing)和手动抢占(Preemption)的策略

+ **工作窃取**：当一个P的本地队列中没有`goroutine`时，它会尝试从全局队列或其他P的本地队列中窃取`goroutine`来执行。
+ **手动抢占**：为了防止一个`goroutine`长时间占用P而导致其他`goroutine`饿死，`Go`的调度器会定期地进行抢占操作。在`Go 1.14`之前，`Go`的调度器只在函数调用时才会进行抢占，从`Go 1.14`开始引入了异步抢占，即允许在任何安全点进行抢占。

这种调度模型和策略使得`Go`语言可以有效地利用硬件资源，处理大量的并发任务，同时也为复杂的并发编程提供了简介的语言级别的支持。

## Goroutine 什么时候切换

常见切换点：

1. goroutine 阻塞在 channel、mutex、select、timer 上。
2. 网络 I/O 进入 runtime netpoller，等待 epoll/kqueue/IOCP 事件。
3. 系统调用阻塞时，M 可能和 P 分离，P 交给其他 M 继续执行 Go 代码。
4. 运行时间过长时，调度器通过抢占让其他 goroutine 获得执行机会。
5. goroutine 主动调用 `runtime.Gosched()`。

## 系统调用阻塞时调度器怎么处理

当 goroutine 执行可能阻塞的系统调用时，运行时会把当前 M 标记为 syscall 状态，并把 P 从这个 M 上解绑出来：

1. G 继续跟着原来的 M 进入内核系统调用。
2. P 会交给空闲 M，或新建一个 M，继续执行其他可运行的 goroutine。
3. 系统调用返回后，原 M 会尝试重新获取一个 P。
4. 如果拿不到 P，返回的 G 会进入全局运行队列，M 进入休眠或被复用。

这样可以避免一个阻塞系统调用把整个 P 的执行能力卡住。但如果大量 goroutine 同时做长时间阻塞 syscall，仍然可能导致 OS 线程数量膨胀、上下文切换增加和内存占用上升。

优化思路：

1. 网络 I/O 尽量走 Go runtime netpoller，不要用不可被 runtime 接管的阻塞调用。
2. 对文件、外部命令、cgo、DNS、慢磁盘 I/O 做并发数限制。
3. 使用超时和 context 取消，避免 goroutine 长期卡在外部依赖上。
4. 高 QPS 服务要观察线程数、goroutine 数、syscall 时间和调度延迟。

面试回答模板：Go 的 goroutine 由运行时调度器管理，采用 G-M-P 模型。G 是 goroutine，M 是 OS 线程，P 是执行 Go 代码所需的调度资源，`GOMAXPROCS` 决定最多有多少个 P 同时运行 Go 代码。goroutine 会在阻塞、网络 I/O、系统调用、抢占等时机切换；系统调用阻塞时 M 和 P 会分离，P 交给其他 M 继续跑 Go 代码。它不绑定某个 CPU，也不能被外部安全 kill，应该用 context 或 channel 做协作式取消。
