# Q49. interface 接口与可比较性

Go 的 `interface` 表示一组方法集合。一个具体类型只要实现了接口要求的所有方法，就隐式实现了该接口，不需要像 Java 那样显式 `implements`。

## 1. interface 的底层理解

接口值可以理解为两部分：

```text
interface value = (dynamic type, dynamic value)
```

例如：

```go
type Reader interface {
    Read([]byte) (int, error)
}

var f *os.File = nil
var r Reader = f
```

此时 `r` 的动态类型是 `*os.File`，动态值是 `nil`，所以 `r != nil`。只有动态类型和动态值都为 nil 时，接口值才等于 nil。

## 2. 空接口和非空接口

1. `interface{}` 或 `any`：方法集合为空，任何类型都实现它。
2. 非空接口：要求实现特定方法集合。

空接口适合承载未知类型，但会失去静态类型信息，使用时通常需要类型断言或 type switch：

```go
func printValue(v any) {
    switch x := v.(type) {
    case string:
        fmt.Println("string:", x)
    case int:
        fmt.Println("int:", x)
    default:
        fmt.Println("unknown")
    }
}
```

## 3. 两个 interface 能比较吗

接口值可以用 `==` 比较，但必须满足运行时动态值可比较。

比较规则：

1. 两个接口都是 nil，则相等。
2. 动态类型不同，则不相等。
3. 动态类型相同且动态值可比较，则比较动态值。
4. 动态类型相同但动态值不可比较，例如 slice、map、func，则运行时 panic。

示例：

```go
var a any = 1
var b any = 1
fmt.Println(a == b) // true

var x any = []int{1}
var y any = []int{1}
fmt.Println(x == y) // panic: comparing uncomparable type []int
```

接口能不能比较，和接口本身是否“看起来一样”无关，关键看动态类型和值。

## 4. 真实场景

1. 函数参数用小接口表达能力，例如 `io.Reader`、`io.Writer`，比传具体类型更灵活。
2. 依赖注入和单元测试中，用接口替换真实实现。
3. 错误处理里 `error` 是接口，要注意 typed nil 问题。
4. map 的 key 如果是 `interface{}`，要确保放入的动态值都可比较。

## 5. 易错点

1. 接口是隐式实现，方法接收者是值还是指针会影响类型是否实现接口。
2. `var err error = (*MyError)(nil)` 时 `err != nil`。
3. 空接口不是泛型，它只是装箱动态类型和值。
4. 接口比较可能 panic，尤其是动态值为 slice、map、func 时。
5. 过度抽象接口会让代码难以理解，Go 里更推荐在使用方定义小接口。

## 6. 面试回答模板

Go 的 interface 是方法集合，具体类型只要实现这些方法就隐式满足接口。接口值底层可以理解为动态类型和动态值两部分，因此 typed nil 放进接口后接口本身不等于 nil。两个接口可以比较，但要求动态类型相同且动态值可比较；如果动态值是 slice、map、func 这类不可比较类型，比较会 panic。工程上常用小接口做解耦和测试替身，同时要注意 nil 接口和接口比较的坑。
