# Q53. Delve 调试与性能排查

Delve 是 Go 官方生态里最常用的源码级调试器，命令行工具通常叫 `dlv`。它可以调试普通程序、测试用例、正在运行的进程，也可以查看 goroutine、栈帧、变量和断点状态。

## 1. Delve 解决什么问题

`pprof` 更适合回答“时间和内存花在哪里”，Delve 更适合回答“程序此刻为什么走到这里、变量是什么、哪个 goroutine 卡住了”。

常见场景：

1. 本地复现 bug，逐行查看执行路径。
2. 调试单元测试或某个失败 case。
3. 查看并发程序中 goroutine 的阻塞点和调用栈。
4. attach 到线上或预发进程进行短时间诊断。
5. 调试 panic 前后的变量状态。

## 2. 常用命令

```bash
dlv debug ./cmd/server
dlv test ./pkg/foo
dlv attach <pid>
```

进入交互界面后常用命令：

```text
break main.go:42       # 设置断点
continue               # 继续运行
next                   # 单步，不进入函数
step                   # 单步，进入函数
print variable         # 打印变量
locals                 # 查看局部变量
args                   # 查看函数参数
goroutines             # 查看所有 goroutine
goroutine 12 stack     # 查看指定 goroutine 栈
stack                  # 当前栈
```

## 3. 调试 Go 程序的注意事项

1. 调试构建最好关闭优化和内联，避免源码行和变量被优化掉：

```bash
go build -gcflags="all=-N -l" ./cmd/server
```

2. 线上 attach 要谨慎，断点会暂停线程或进程执行，可能影响请求延迟。
3. 对高并发问题，Delve 只能看到某一刻的状态，通常要结合日志、指标、trace、pprof 一起判断。
4. goroutine 泄漏更适合先用 goroutine profile 找大量相同栈，再用 Delve 做局部复现。
5. race 问题不能只靠单步调试，应优先使用 `go test -race`、压测和最小复现。

## 4. 和 pprof、trace 的区别

| 工具 | 主要用途 | 典型问题 |
| --- | --- | --- |
| Delve | 交互式源码调试 | 变量值、分支路径、栈帧、断点 |
| pprof | 采样剖析 | CPU 热点、内存分配、goroutine 堆栈、锁竞争 |
| trace | 运行时事件时间线 | 调度延迟、网络阻塞、GC 暂停、goroutine 生命周期 |
| race detector | 数据竞争检测 | 未加锁的共享变量读写 |

## 5. 面试回答模板

DLV/Delve 是 Go 的源码级调试器，可以 `debug`、`test`、`attach`，常用来打断点、看变量、看调用栈和 goroutine 状态。它适合定位控制流和变量状态；如果是性能问题，我会先用 pprof/trace 找热点或阻塞点，再用 Delve 在本地复现细节。调试构建通常加 `-gcflags="all=-N -l"` 关闭优化和内联，线上 attach 要控制影响范围。
