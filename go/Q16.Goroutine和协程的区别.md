# Q16. Goroutine和协程的区别

### Goroutine 和协程的区别

1. **调度方式**：
   - **Goroutine**：由 Go 运行时自动调度，采用抢占式调度。
   - **协程**：通常是非抢占式的，由用户代码控制，切换点需要显式指定。
2. **并行性**：
   - **Goroutine**：可以并行运行，Go 运行时会将 Goroutine 映射到多个操作系统线程上，充分利用多核 CPU。
   - **协程**：通常运行在单线程中，不能真正实现并行，只是并发。
3. **启动和管理**：
   - **Goroutine**：启动简单，只需在函数或方法前加上 `go` 关键字，Goroutine 的生命周期和调度完全由 Go 运行时管理。
   - **协程**：需要显式管理切换，程序代码负责暂停和恢复协程。
4. **内存模型**：
   - **Goroutine**：可以共享内存，但 Go 提倡使用通道（Channel）进行通信，避免直接共享数据。
   - **协程**：一般通过共享内存或传递参数来交换数据，可能需要同步机制来避免数据竞争。
5. **性能和资源使用**：
   - **Goroutine**：非常轻量级，每个 Goroutine 初始栈很小，可以动态扩展，Go 运行时的调度器非常高效。
   - **协程**：也轻量，但需要开发者管理其切换逻辑，资源使用视具体实现而定。

### 协程和线程的区别

线程是操作系统调度的执行单元，协程通常是用户态调度的轻量执行单元。可以从这些角度回答：

1. **调度位置**：线程由内核调度，切换需要进入内核；协程由语言运行时或用户态调度器调度，切换成本更低。
2. **资源占用**：线程有较大的栈和内核调度元数据；协程栈通常更小，可以按需增长或由运行时管理。
3. **并行能力**：多个线程可以真正跑在多个 CPU 核上；协程是否能并行取决于它是否映射到多个线程，例如 Go 的 G-M-P 模型可以让 goroutine 并行。
4. **阻塞影响**：线程阻塞通常只阻塞当前线程；用户态协程如果直接调用阻塞系统调用，可能阻塞整个调度线程，所以运行时需要网络轮询器或异步 I/O 配合。
5. **编程模型**：线程需要关注锁、条件变量和共享内存竞争；协程更适合用 channel、async/await、事件循环等方式表达高并发 I/O。

易错点是不要把“协程一定不能并行”说死。普通用户态协程在单线程事件循环里不能并行，但 Go goroutine、Kotlin coroutine 配合线程池、C++20 coroutine 配合调度器时，都可以通过多个线程获得并行执行能力。

真实场景中，网络服务和爬虫这类 I/O 密集任务适合协程模型，用较少线程承载大量连接；CPU 密集任务仍然要控制并行度，最终依赖线程或进程利用多核。
