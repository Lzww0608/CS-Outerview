`reflect.DeepEqual()` 是 Go 语言中一个非常强大但也相对复杂的函数，它用于“深度”比较两个值是否相等。

与常规的 `==` 运算符不同，`==` 只能比较基本类型或指针地址（以及少数支持的复合类型），而 `DeepEqual` 会递归地深入到数据结构的内部进行比较。

它的底层逻辑可以概括为：**一个类型驱动的、递归的、逐元素的值比较过程。**

下面是 `DeepEqual` 的核心比较逻辑和规则的分解：



### 1. 核心比较原则



`DeepEqual` 的比较过程由一个内部函数 `deepValueEqual` 驱动，它会递归地比较两个 `reflect.Value`。

1. **类型检查：**
   - 如果两个值的类型（Type）**不同**，它们在绝大多数情况下**不相等**（`false`）。例如，`int(5)` 和 `int32(5)` 是不相等的。
2. **有效性（Nil）检查：**
   - 在检查类型之后，它会检查值的 "validity"。
   - 如果两个值都是 `nil`（例如两个 `nil` 指针，两个 `nil` 接口，或一个 `nil` 接口和一个 `nil` 指针），它们相等（`true`）。
   - 如果一个有效（non-nil）而另一个无效（nil），它们不相等（`false`）。
3. **循环引用检测（Cycle Detection）：**
   - `DeepEqual` 在比较指针时，会维护一个“已访问”的指针（地址）对的集合。
   - 如果在递归过程中遇到了一对之前已经开始比较的指针，它会**直接返回 true**，假定它们相等，以此来避免无限循环。



### 2. 按类型的详细比较规则



`DeepEqual` 根据值的 `Kind`（种类）来执行不同的比较逻辑：



#### 🔹 基本类型 (Basic Types)



- **布尔值 (Bool):** 比较 `true` 或 `false`。
- **整数 (Int, Uint):** 比较数值。
- **浮点数 (Float):** 比较数值。
  - **特殊规则 (NaN):** `DeepEqual` **会**认为两个 `NaN` (Not a Number) 值是相等的，这与 `==` 的行为不同（`NaN == NaN` 为 `false`）。
- **复数 (Complex):** 比较实部和虚部。
- **字符串 (String):** 比较字符串内容。



#### 🔹 复合类型 (Composite Types)



- **数组 (Array):**
  1. 检查长度是否相等（类型相同时长度必然相等）。
  2. 递归地对数组中的**每一个元素**调用 `DeepEqual`。
- **结构体 (Struct):**
  1. 遍历结构体的所有**导出的字段 (Exported Fields)**。
  2. 递归地对**每一个导出的字段**调用 `DeepEqual`。
  3. **注意：** 未导出的字段（小写字母开头）**会被忽略**，不参与比较。
- **接口 (Interface):**
  1. 获取接口内部存储的**具体值 (Concrete Value)**。
  2. 递归地对这两个具体值调用 `DeepEqual`。
- **指针 (Pointer):**
  1. （经过 `nil` 和循环引用检查后）
  2. 获取指针指向的**底层元素**。
  3. 递归地对这两个底层元素调用 `DeepEqual`。
- **切片 (Slice):**
  1. 首先检查 `nil`。一个 `nil` 切片只等于另一个 `nil` 切片。
  2. **关键点：** `var s1 []int` (`nil`) **不等于** `s2 := make([]int, 0)`（非 `nil` 但为空）。
  3. 如果两个切片都非 `nil`，检查它们的**长度 (Length)** 是否相等。
  4. 如果长度相等，递归地对**每一个元素**调用 `DeepEqual`。
- **映射 (Map):**
  1. 首先检查 `nil`。一个 `nil` map 只等于另一个 `nil` map。
  2. **关键点：** `var m1 map[string]int` (`nil`) **不等于** `m2 := make(map[string]int)`（非 `nil` 但为空）。
  3. 如果两个 map 都非 `nil`，检查它们的**长度 (Length)** 是否相等。
  4. 如果长度相等，遍历其中一个 map（例如 `m1`）的所有 `(key, value)` 对。
  5. 对于 `m1` 中的每一个 `key`，检查 `m2` 中是否存在这个 `key`。
  6. 如果 `key` 存在，递归地对 `m1[key]` 和 `m2[key]` 的**值 (Value)** 调用 `DeepEqual`。
  7. 只要有任何一个 `key` 不存在或 `value` 不相等，就返回 `false`。



#### 🔹 特殊类型 (Special Types)

- **函数 (Func):**
  - 函数类型的值**只有在两者都为 nil 时**才相等。
  - 任何非 `nil` 的函数值（即使是同一个函数）都不等于任何其他值。
- **通道 (Channel):**
  - 通道类型的值只有在**它们指向同一个通道实例**（即内存地址相同）或**两者都为 nil 时**才相等。

------



### 3. 总结：关键点与“陷阱”

`reflect.DeepEqual` 的底层逻辑非常严谨，但也因此产生了一些常见的“陷阱”：

1. **nil vs. 空 (Empty):**
   - `DeepEqual( ([]int)(nil), make([]int, 0) )` 返回 `false`。
   - `DeepEqual( (map[int]int)(nil), make(map[int]int) )` 返回 `false`。
2. **未导出字段 (Unexported Fields):**
   - 结构体中未导出的字段（私有字段）**不参与**比较。两个结构体即使私有字段不同，只要导出字段相同，`DeepEqual` 也会返回 `true`。
3. **函数 (Functions):**
   - `DeepEqual` 几乎从不认为两个函数相等（除非都是 `nil`）。如果你在结构体中包含了函数字段，这几乎总会导致 `DeepEqual` 返回 `false`。
4. **NaN:**
   - `DeepEqual` 认为 `NaN == NaN`，这在数学上或标准 `==` 中是不成立的。

总而言之，`DeepEqual` 是通过 `reflect` 包，对两个值进行类型和 `Kind` 的识别，然后递归地“剥开”复合类型，直到最底层的基本类型，最后对基本类型进行值比较。
