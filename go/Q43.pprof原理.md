`pprof` 获取信息的核心原理是：**它严重依赖 Go 语言的运行时（Runtime）来进行数据采集，pprof 工具本身更多是作为这些数据的“收集器”和“分析器”。**

Go 的运行时被设计为“可观测的”（Observable），它在内部维护了各种性能统计数据。`pprof` 只是通过标准接口（`runtime/pprof` 或 `net/http/pprof`）去“请求”运行时把这些数据“快照”并导出来。

不同类型的 Profile（剖析）数据，其底层的采集原理各不相同。

------



### 1. CPU Profile (CPU 剖析)

**核心原理：基于操作系统的信号（Signal）进行“采样” (Sampling)。**

当你启动 CPU 剖析时（例如，访问 `/debug/pprof/profile?seconds=30`），会发生以下情况：

1. **设置定时器：** Go 运行时会向操作系统内核请求，要求**以 100Hz 的频率**（默认每秒 100 次，即每 10 毫秒一次）向当前进程发送 **SIGPROF** 信号。
2. **信号处理器：** Go 运行时为 `SIGPROF` 信号注册了一个“信号处理器”（Signal Handler）。
3. **中断与采样：**
   - 每当 `SIGPROF` 信号到达时，操作系统会**暂停**（中断）当前正在某个 CPU 核心上运行的 Goroutine。
   - Go 的信号处理器被触发，它会**记录下这个被中断的 Goroutine 的当前函数调用堆栈（Stack Trace）**。
   - 记录完成后，Goroutine 恢复执行。
4. **数据汇总：**
   - 这个过程在剖析期间（例如 30 秒）内会发生 `30 * 100 = 3000` 次。
   - `pprof` 会收集所有这 3000 个堆栈样本。
5. **分析：**
   - `go tool pprof` 工具在分析时会统计这些样本。
   - **如果函数 A() 出现在了 1500 个样本中**（即 50% 的时间），`pprof` 就会报告函数 `A()` 占用了 50% 的 CPU 时间。
   - 这就是为什么 `pprof` CPU 剖析是“采样”而不是“精确”的——它通过高频快照来*估算* CPU 的消耗。



### 2. Memory Profile (Heap - 堆内存剖析)

**核心原理：在内存分配器（Allocator）中进行“采样”。**

`pprof` 的内存剖析**不是**对*整个堆*进行快照，而是对**分配内存的代码行为**进行采样。

1. **采样率 (Rate)：**
   - Go 运行时有一个 `runtime.MemProfileRate` 参数（默认 512KB）。
   - 它的意思是：**“平均每分配 512KB 内存，就采集一次样本。”**
   - （注意：这是一个平均值，实现上使用了随机数，以避免采样偏差）。
2. **采样时机：**
   - 当你的代码执行内存分配（例如 `make()`、`new()` 或 `append()` 导致扩容）时，Go 的内存分配器会检查是否应该进行采样。
3. **记录堆栈：**
   - 如果决定采样，内存分配器就会**记录当前 Goroutine 的函数调用堆栈**，并将这个堆栈与“分配了 XXX 字节”这个信息关联起来。
4. **分析（inuse_space vs alloc_space）：**
   - `alloc_space`：报告**自程序启动以来**所有被采样到的*累计*内存分配。
   - `inuse_space`：这是最常用的（用于查内存泄漏）。Go 运行时会在**垃圾回收（GC）时，更新 pprof 的样本数据。如果一个被采样的内存块被 GC 回收了，运行时就会从 inuse 样本中将其减去。因此，inuse_space 显示的是当前仍然存活**（未被回收）的内存是*由哪些代码*分配的。



### 3. Goroutine Profile (Goroutine 剖析)

**核心原理：一次完整的“全局快照” (Stop The World)。**

这个最简单粗暴：

1. **STW：** 当你请求 `goroutine` 剖析时，Go 运行时会触发一个**短暂的“Stop The World” (STW)**，暂停所有 Goroutine 的执行。
2. **遍历：** 运行时会**遍历全局的 Goroutine 列表**（`allgs`）。
3. **记录：** 对**每一个** Goroutine，记录其：
   - **当前状态**（`running`, `runnable`, `syscall`, `chan send`, `chan recv`, `select`, `mutex wait` 等）。
   - **当前的函数调用堆栈**。
4. **恢复：** 遍历完成后，STW 结束，程序恢复运行。
5. **分析：** `pprof` 工具会聚合这些信息。如果你看到 5000 个 Goroutine 都卡在同一个 `<-ch` 上，你就找到了泄露点。



### 4. Block Profile (阻塞剖析) / Mutex Profile (锁竞争剖析)

**核心原理：在 Go 调度器中“埋点”并设置“阈值”。**



#### Block Profile

1. **设置阈值：** 你必须手动调用 `runtime.SetBlockProfileRate(nanoseconds)` 来开启。这个阈值（例如 100 毫秒）的意思是：“只关心那些阻塞时间*超过* 100 毫秒的操作。”
2. **埋点：** Go 运行时在会导致 Goroutine 阻塞的地方（如 `select`、`chan send/recv`）都埋了点。
3. **记录：** 当一个 Goroutine 在这些点上被阻塞，调度器会记录一个开始时间。当它*最终*被唤醒时，调度器会计算总阻塞时间。
4. **采样：** 如果总阻塞时间**超过了你设置的阈值**，运行时就会记录这个 Goroutine 的堆栈和阻塞时间。



#### Mutex Profile

- 与 Block 类似，但专注于 `sync.Mutex` 和 `sync.RWMutex`。
- 它只记录**发生锁竞争**（Contention）的等待。如果一个锁没有竞争，`Lock()` 立即成功，`pprof` 不会记录它。
- 你可以通过 `runtime.SetMutexProfileFraction` 来设置采样率，决定记录*百分之几*的锁竞争事件。

------



### 总结：数据是怎么流向 `pprof` 工具的？

1. **数据源 (Data Source)：** **Go 运行时（Runtime）**是所有 `pprof` 数据的真正来源。它通过信号、内存分配器、调度器和 GC 紧密协作，在内部维护着这些性能统计数据。
2. **采集接口 (Interface)：**
   - `net/http/pprof`：当你 `import _ "net/http/pprof"` 时，它会注册几个 HTTP 接口（如 `/debug/pprof/heap`）。
   - 当你访问这个 URL 时，HTTP 处理器会调用 `runtime/pprof` 包中的函数（例如 `pprof.WriteHeapProfile`）。
   - 这些函数会向 Go 运行时“索要”当前的快照数据。
3. **原始数据 (Raw Data)：**
   - 运行时将数据（主要是大量的“堆栈样本”和“计数值”）打包成一种标准格式（Protocol Buffers，`.pb.gz` 文件）。
4. **分析工具 (Analyzer)：**
   - `go tool pprof` 是一个**分析工具**。它读取 `.pb.gz` 原始数据。
   - **关键一步：** 它还需要你的**可执行二进制文件**。
   - 它使用二进制文件中的**符号表（Symbol Table）**，将原始数据中的*内存地址*（如 `0x10a2b4c`）**翻译**（Symbolize）成人类可读的*函数名和代码行号*（如 `main.go:50` 的 `main.databaseQuery` 函数）。
   - 最后，它以火焰图、Top 列表、Graphviz 图等形式将分析结果呈现给你。

| **Profile 类型**  | **采集原理**                | **采集时机**                          |
| ----------------- | --------------------------- | ------------------------------------- |
| **CPU**           | OS 信号 (`SIGPROF`) 采样    | 高频定时器（默认 100Hz）              |
| **Heap (Memory)** | 内存分配器 (Allocator) 采样 | `make()` / `new()` 时（默认每 512KB） |
| **Goroutine**     | 全局 Goroutine 列表快照     | STW 期间，遍历所有 Goroutine          |
| **Block**         | 调度器 (Scheduler) 埋点     | Goroutine 阻塞时间超过阈值时          |
| **Mutex**         | 调度器 (Scheduler) 埋点     | 发生锁竞争时（按比例采样）            |
