# Q55. Go GC 演进与三色标记

Go GC 的核心目标不是追求最高吞吐，而是让服务端程序在较低延迟下稳定运行。它选择了并发标记清除、非分代、非移动的路线，配合写屏障和 GC pacing 控制 STW 时间。

## 1. Go GC 的演进脉络

粗略可以按目标理解：

1. **早期版本**：STW 时间较长，主要目标是正确回收。
2. **Go 1.5 左右**：引入并发三色标记，显著降低长暂停。
3. **Go 1.8 以后**：混合写屏障、并发标记和 pacing 更成熟，STW 常见为毫秒级甚至更低。
4. **后续版本**：持续优化 pacer、栈扫描、页分配器、内存归还和 `GOMEMLIMIT`，更适合容器环境。

面试里不要把 Go GC 说成“没有 STW”。Go 仍然有 STW，例如开始标记、结束标记、栈扫描协调等阶段，只是时间被压得很短。

## 2. 三色标记过程

三色是一种抽象：

1. **白色**：尚未确认可达，标记结束后仍为白色的对象会被回收。
2. **灰色**：对象本身已确认可达，但它引用的对象还没有全部扫描。
3. **黑色**：对象可达，并且它直接引用的对象都已扫描。

并发标记大致过程：

1. 从根对象开始，例如全局变量、goroutine 栈、寄存器、runtime 结构。
2. 把根直接可达对象标记为灰色。
3. 不断取灰色对象，扫描它的指针字段，把引用到的白色对象变灰。
4. 灰色对象扫描完成后变黑。
5. 灰色队列为空后，仍为白色的对象不可达，可以清扫。

核心不变量是：不能出现“黑色对象直接指向白色对象且没有任何灰色路径能再发现它”。否则用户程序并发写指针时，GC 可能误回收仍然可达的对象。

## 3. 写屏障解决什么问题

并发标记期间，用户 goroutine 还在运行，可能把一个白色对象挂到黑色对象下面。写屏障就是在指针写入时插入一小段 runtime 逻辑，维护三色标记的不变量。

Go 使用过插入写屏障、删除写屏障，后来采用混合写屏障。可以简化理解为：

1. 指针写入时，确保新指向的对象不会被漏标。
2. 指针覆盖旧值时，确保旧引用链不会在标记期间突然丢失。
3. 尽量减少重新扫描栈和 STW 成本。

写屏障会增加指针写入成本，因此大量指针对象、频繁修改指针关系的程序会给 GC 带来更大压力。

## 4. 和 Java G1、ZGC 的设计权衡

| 对比项 | Go GC | Java G1 | Java ZGC |
| --- | --- | --- | --- |
| 主要目标 | 简单、低延迟、服务端稳定 | 可预测停顿、兼顾吞吐 | 超低停顿、大堆 |
| 是否分代 | 传统上不分代 | 分代/Region 化 | 新版本支持分代 ZGC |
| 是否移动对象 | 通常不移动 | Evacuation 会移动对象 | 会并发搬迁对象 |
| 内存整理 | 不压缩，依赖分配器管理碎片 | Region 复制整理 | 读屏障/染色指针支持并发整理 |
| 代价 | 指针扫描和堆增长会带来 GC CPU | 机制复杂，调参较多 | 实现复杂，对平台和屏障要求高 |

Go 不移动对象的好处是实现简单、和 C 交互、指针语义、runtime 成本更可控；代价是不能像压缩 GC 一样彻底整理碎片。Java 的 G1/ZGC 在大堆和复杂内存整理方面能力更强，但运行时机制和调优维度也更复杂。

## 5. 潜在瓶颈与优化方向

常见瓶颈：

1. 堆对象分配过多，GC 触发频繁。
2. 指针密集对象多，标记扫描成本高。
3. 长生命周期对象持有短生命周期大对象，导致内存无法及时释放。
4. 大量 goroutine 栈需要扫描。
5. 写屏障在指针更新热点上带来额外开销。

优化方向：

1. 用 `go test -benchmem`、pprof heap、逃逸分析定位分配热点。
2. 预分配 slice/map，复用 buffer，减少临时对象。
3. 能用值类型或无指针结构时，减少不必要的指针图。
4. 避免全局缓存、闭包、goroutine 长期持有大对象。
5. 在容器里设置合理的 `GOMEMLIMIT`，再结合 `GOGC` 调整吞吐和内存。

## 6. 面试回答模板

Go GC 走的是并发三色标记清除路线，目标是把 STW 压低，适合服务端低延迟场景。三色标记把对象分成白、灰、黑，从根对象出发扫描引用，灰色队列清空后仍为白色的对象就可以回收。并发标记时用户程序会修改指针，所以 Go 通过写屏障维护“不漏标”的不变量。和 Java G1/ZGC 相比，Go GC 更简单，通常不分代也不移动对象，停顿低但不做压缩整理；G1/ZGC 更适合大堆和复杂内存整理，但机制和调参更复杂。优化 Go GC 的关键是减少堆分配、降低指针扫描量和控制对象生命周期。
