# Q45.error和panic

Go 里 `error` 和 `panic` 都能表达“出错”，但定位完全不同。

## 1. error 是什么？

`error` 是普通的返回值，表示函数执行过程中出现了预期内、可处理的错误。

```go
type error interface {
	Error() string
}
```

典型场景：

1. 文件不存在。
2. 网络请求失败。
3. 数据库查询没有结果。
4. 参数校验失败。
5. 下游服务超时。

Go 鼓励显式返回和处理 error：

```go
resp, err := http.Get(url)
if err != nil {
	return err
}
defer resp.Body.Close()
```

## 2. panic 是什么？

`panic` 表示程序遇到了无法正常继续执行的严重问题，会中断当前函数的正常流程，并开始栈展开。在栈展开过程中，已经注册的 `defer` 会按后进先出的顺序执行。

典型场景：

1. 数组越界。
2. 空指针解引用。
3. 向已关闭的 channel 写数据。
4. 类型断言失败且没有使用 `ok`。
5. 程序内部不变量被破坏。

业务代码里不应该把普通错误都写成 panic。panic 更适合表示程序员错误、不可恢复错误或启动阶段的致命配置错误。

## 3. error 和 panic 的区别

| 对比项 | error | panic |
| --- | --- | --- |
| 本质 | 普通返回值 | 运行时异常流程 |
| 是否可预期 | 通常可预期 | 通常不可预期或不可恢复 |
| 处理方式 | 调用方判断 `err != nil` | `defer` + `recover` 捕获 |
| 控制流 | 不打断栈 | 触发栈展开 |
| 使用场景 | 业务错误、IO 错误、下游错误 | 程序 bug、严重不变量破坏 |

## 4. panic 怎么捕获？

使用 `recover` 捕获 panic，但 `recover` 必须在 deferred 函数中直接或间接执行，才会生效。

```go
func safeRun(fn func()) (err error) {
	defer func() {
		if r := recover(); r != nil {
			err = fmt.Errorf("panic recovered: %v", r)
		}
	}()

	fn()
	return nil
}
```

注意：`recover` 只能捕获当前 goroutine 的 panic，不能跨 goroutine 捕获。

错误示例：

```go
func main() {
	defer func() {
		if r := recover(); r != nil {
			fmt.Println("recover:", r)
		}
	}()

	go func() {
		panic("panic in another goroutine")
	}()

	time.Sleep(time.Second)
}
```

上面的 `defer recover` 在 main goroutine 中，无法捕获子 goroutine 的 panic。每个 goroutine 如果需要兜底，都要在自己的入口处加 `defer recover`。

## 5. Web 服务里怎么用？

Web 服务通常在 middleware 层统一 recover，避免单个请求 panic 导致整个进程退出。

```go
func Recovery(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if v := recover(); v != nil {
				// 记录堆栈和请求上下文
				http.Error(w, "internal server error", http.StatusInternalServerError)
			}
		}()

		next.ServeHTTP(w, r)
	})
}
```

但 recover 后要记录堆栈、请求参数、trace id 等上下文，否则问题会被吞掉，后续很难排查。

## 6. 面试回答模板

`error` 是 Go 推荐的显式错误处理方式，它是普通返回值，适合文件、网络、数据库、参数校验这类可预期错误。`panic` 是异常控制流，表示程序遇到了无法继续执行的问题，会触发当前 goroutine 的栈展开，并执行已经注册的 defer。

panic 可以用 `defer` 里的 `recover` 捕获，但只能捕获当前 goroutine 的 panic。实际项目里，一般在 goroutine 入口或 Web middleware 层做统一 recover，记录堆栈并返回 500；普通业务错误不应该用 panic，而应该返回 error。
