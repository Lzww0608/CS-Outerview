# Q46.零值

Go 中变量声明后即使没有显式初始化，也会被自动初始化为该类型的零值。零值让很多类型可以“声明即用”，但也有一些类型的零值只能读不能写，面试里容易被追问。

## 1. 常见类型的零值

| 类型 | 零值 |
| --- | --- |
| `bool` | `false` |
| 整数类型 | `0` |
| 浮点类型 | `0` |
| `string` | `""` |
| 指针 | `nil` |
| slice | `nil` |
| map | `nil` |
| channel | `nil` |
| function | `nil` |
| interface | `nil` |
| struct | 每个字段都是对应类型零值 |

## 2. nil slice 和 nil map

nil slice 可以安全读、遍历和 append：

```go
var s []int
fmt.Println(len(s)) // 0
s = append(s, 1)
```

nil map 可以读，但不能写：

```go
var m map[string]int
fmt.Println(m["a"]) // 0
m["a"] = 1          // panic: assignment to entry in nil map
```

写 map 前必须 `make`：

```go
m := make(map[string]int)
m["a"] = 1
```

## 3. nil channel

nil channel 的收发都会永久阻塞：

```go
var ch chan int
ch <- 1   // 阻塞
<-ch      // 阻塞
```

在 `select` 中，可以把 channel 置为 nil 来禁用某个 case：

```go
var ch chan int

select {
case v := <-ch:
	fmt.Println(v)
default:
	fmt.Println("disabled")
}
```

## 4. struct 的零值可用性

Go 标准库里很多类型的零值是可用的：

```go
var mu sync.Mutex
mu.Lock()
mu.Unlock()

var buf bytes.Buffer
buf.WriteString("hello")
```

这是 Go 的一个重要设计习惯：让类型的零值尽量处于可用状态。

## 5. interface 的 nil 易错点

接口值由动态类型和动态值两部分组成。只有两者都为 nil，接口才等于 nil。

```go
var p *MyError = nil
var err error = p

fmt.Println(err == nil) // false
```

这里 `err` 的动态类型是 `*MyError`，动态值是 nil，所以整个接口不为 nil。

## 6. 面试回答模板

Go 的零值是变量未显式初始化时的默认值，比如数字是 0，bool 是 false，string 是空串，指针、slice、map、channel、func、interface 是 nil，struct 的零值是每个字段的零值。

需要注意 nil slice 和 nil map 不一样：nil slice 可以 `len`、`range`、`append`，但 nil map 只能读不能写，写会 panic。nil channel 收发都会阻塞。还有接口 nil 的坑，接口只有动态类型和动态值都为 nil 时才等于 nil。
