# Q54. Go 性能优化与 GC 调优

Go 程序性能问题通常不是单点原因，而是 CPU、内存分配、GC、调度、锁竞争、I/O、序列化和外部依赖共同作用的结果。面试里被问“怎么优化 Go 性能”，应该先讲定位方法，再讲具体优化手段。

## 1. 常见性能影响因素

1. **频繁堆分配**：短生命周期对象大量逃逸到堆上，会增加分配成本和 GC 扫描压力。
2. **GC 压力**：堆太大、指针太多、对象存活时间太长，会增加标记成本和 STW 辅助成本。
3. **锁竞争**：全局 mutex、热点 map、共享连接池会让 goroutine 阻塞。
4. **goroutine 泄漏**：goroutine 数不断上涨，会增加内存、调度和 FD 压力。
5. **channel 阻塞**：无缓冲 channel、缓冲过小、消费者不足会导致生产者堆积。
6. **反射和序列化**：JSON、反射、interface 装箱在高 QPS 链路中可能成为热点。
7. **系统调用和网络 I/O**：频繁小包、无批量、无连接复用会放大开销。
8. **cgo**：跨 Go/C 边界有调用成本，也会影响调度和栈管理。

## 2. 优化前先定位

不要凭感觉优化。常用流程：

1. 通过业务指标确认问题：P99 延迟、QPS、错误率、CPU、RSS、GC pause、goroutine 数。
2. 用 `pprof` 看 CPU、heap、goroutine、mutex、block profile。
3. 用 `go test -bench` 做基准测试，用 `benchstat` 比较优化前后。
4. 用 `go test -run=^$ -bench=. -benchmem` 看每次操作分配次数和分配字节数。
5. 用 `go build -gcflags="-m"` 看逃逸分析，确认对象为什么进堆。
6. 复杂调度问题再用 `go tool trace` 看 goroutine、网络阻塞和 GC 时间线。

## 3. 减少分配和 GC 压力

1. **预分配容器**：能估算大小时使用 `make([]T, 0, n)`、`make(map[K]V, n)`。
2. **复用缓冲区**：热点路径可用 `bytes.Buffer`、对象池或 `sync.Pool`，但不要把池当缓存。
3. **减少指针密度**：能用值类型就不要把大量小对象都做成指针，降低 GC 扫描成本。
4. **避免无意义装箱**：频繁把具体类型转成 `interface{}` 会带来逃逸和动态分派成本。
5. **优化字符串拼接**：多段拼接用 `strings.Builder` 或预估容量，避免反复分配。
6. **控制对象生命周期**：不要把大对象放到全局缓存、闭包或 goroutine 中长期持有。

## 4. GC 参数怎么调

Go GC 默认由堆增长比例触发。`GOGC` 表示下一轮 GC 触发目标与上次存活堆的比例关系，默认通常是 `100`。

1. 降低 `GOGC`：更频繁 GC，降低堆占用，但 CPU 消耗可能上升。
2. 提高 `GOGC`：减少 GC 频率，降低 GC CPU，但堆和 RSS 可能上升。
3. 设置 `GOMEMLIMIT`：给 Go 运行时一个软内存上限，适合容器环境，避免只看宿主机内存导致 OOM。
4. 调参前要先看 `runtime/metrics`、`gctrace`、heap profile 和容器内存限制。

示例：

```bash
GODEBUG=gctrace=1 ./server
GOGC=200 ./server
GOMEMLIMIT=2GiB ./server
```

## 5. 并发和 I/O 优化

1. 热点共享 map 可以按 key 分片加锁，或在读多写少场景评估 `sync.Map`。
2. 数据库、RPC、HTTP 调用要设置超时和连接池，不要无限创建连接。
3. 批量写、批量读、合并请求可以减少系统调用和网络往返。
4. 日志要避免同步阻塞热点路径，高频日志要限流或异步化。
5. goroutine 池只适合限制并发和资源，不是越多越快。

## 6. 面试回答模板

Go 性能优化我会先定位再动手：看监控确认瓶颈，用 pprof 看 CPU、heap、goroutine、mutex/block，用 benchmark 和 benchmem 量化分配。GC 优化的核心是减少堆分配、降低指针扫描量、控制对象生命周期，必要时用 `GOGC` 和 `GOMEMLIMIT` 调整运行时策略。具体手段包括容器预分配、复用 buffer、减少 interface 和反射、避免 goroutine 泄漏、降低锁竞争、批量化 I/O，并用压测验证 P99 和资源占用是否真的改善。
