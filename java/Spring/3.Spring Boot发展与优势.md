# 3. Spring Boot 发展与优势

Spring Boot 是 Spring 生态中最成功的项目之一，它的设计目标是用约定俗成的配置和自动装配机制，让开发者能够快速创建独立的、生产级别的 Spring 应用。

## 1. Spring Boot 的发展历史

### 1.1 前置背景：Spring 框架的复杂度

在 Spring Boot 出现之前，使用 Spring 框架开发需要大量的配置：

```java
// 传统 Spring 配置示例
public class AppConfig {
    
    @Bean
    public DataSource dataSource() {
        DriverManagerDataSource ds = new DriverManagerDataSource();
        ds.setDriverClassName("com.mysql.jdbc.Driver");
        ds.setUrl("jdbc:mysql://localhost:3306/test");
        ds.setUsername("root");
        ds.setPassword("password");
        return ds;
    }
    
    @Bean
    public SqlSessionFactory sqlSessionFactory() throws Exception {
        SqlSessionFactoryBean factory = new SqlSessionFactoryBean();
        factory.setDataSource(dataSource());
        factory.setTypeAliasesPackage("com.example.model");
        return factory.getObject();
    }
    
    @Bean
    public PlatformTransactionManager transactionManager() {
        return new DataSourceTransactionManager(dataSource());
    }
}
```

问题：
1. 每个项目都要重复配置
2. 依赖版本管理复杂
3. 配置文件冗长
4. 部署和运维成本高

## 2. Spring Boot 的核心优势

### 2.1 自动配置（Auto Configuration）

Spring Boot 最核心的特性，能够根据类路径中的依赖自动配置 Spring 应用。

```java
// Spring Boot 自动配置原理
// 当 spring-boot-autoconfigure 在类路径中时

// 条件配置示例
@Configuration
@ConditionalOnClass({DataSource.class, JdbcTemplate.class})
@ConditionalOnProperty(name = "spring.datasource.enabled", matchIfMissing = true)
public class DataSourceAutoConfiguration {
    
    @Bean
    @ConditionalOnMissingBean
    public DataSource dataSource() {
        // 自动创建 DataSource
        return new HikariDataSource();
    }
}
```

**工作原理**：
1. `@SpringBootApplication` 包含 `@EnableAutoConfiguration`
2. Spring Boot 从 `META-INF/spring.factories` 读取自动配置类
3. 通过 `@Conditional*` 注解判断条件是否满足
4. 满足条件时自动注册 Bean

### 2.2 Starter 依赖（Starters）

Starter 是一组便捷的依赖描述符，包含了一组依赖的版本兼容组合。

```xml
<!-- Web 开发只需添加一个依赖 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>

<!-- 包含的传递依赖 -->
<!-- spring-web, spring-webmvc, tomcat, jackson, validation 等 -->
```

**常见 Starter**：

| Starter | 用途 |
| --- | --- |
| `spring-boot-starter-web` | RESTful API 开发 |
| `spring-boot-starter-data-jpa` | JPA 数据访问 |
| `spring-boot-starter-data-redis` | Redis 缓存 |
| `spring-boot-starter-security` | 安全认证 |
| `spring-boot-starter-actuator` | 应用监控 |
| `spring-boot-starter-test` | 单元测试 |

### 2.3 嵌入式服务器

Spring Boot 打包的应用可以直接运行，无需额外部署服务器：

```bash
# 传统方式
1. 打包 WAR
2. 部署到 Tomcat
3. 配置 Tomcat
4. 启动

# Spring Boot 方式
java -jar application.jar
```

Spring Boot 默认支持：
- Tomcat（默认）
- Jetty
- Undertow

```yaml
# application.yml
server:
  port: 8080
  tomcat:
    threads:
      max: 200
      min-spare: 10
```

### 2.4 生产就绪特性

Spring Boot 提供开箱即用的生产监控能力：

```java
// 引入 actuator 依赖后，自动提供
// /actuator/health     - 健康检查
// /actuator/info        - 应用信息
// /actuator/metrics     - 指标数据
// /actuator/env         - 环境属性
// /actuator/beans       - Bean 列表

// 自定义健康检查
@Component
public class DatabaseHealthIndicator implements HealthIndicator {
    @Override
    public Health health() {
        try {
            jdbcTemplate.execute("SELECT 1");
            return Health.up().build();
        } catch (Exception e) {
            return Health.down().withException(e).build();
        }
    }
}
```

### 2.5 外部化配置

Spring Boot 支持多种配置源，配置优先级清晰：

```yaml
# application.yml
# 或 application.properties
# 或 --spring.config.location 外部配置

spring:
  datasource:
    url: jdbc:mysql://localhost:3306/db
    username: root
    password: ${DB_PASSWORD}  # 环境变量
```

**配置优先级**（从高到低）：
1. 命令行参数
2. OS 环境变量
3. application-{profile}.yml
4. application.yml
5. 打包在 JAR 中的默认配置

## 3. Spring Boot vs 传统 Spring

| 对比项 | 传统 Spring | Spring Boot |
| --- | --- | --- |
| 配置方式 | XML 或 Java Config | 注解 + 自动配置 |
| 依赖管理 | 手动管理版本 | Starter 自动管理 |
| 服务器 | 需要外部部署 | 嵌入式服务器 |
| 启动速度 | 较慢 | 较快 |
| 微服务支持 | 需要额外配置 | 原生支持 |
| 监控运维 | 需要集成 | Actuator 开箱即用 |

## 4. Spring Boot 自动配置原理深度解析

### 4.1 @SpringBootApplication 分析

```java
@SpringBootApplication
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
```

`@SpringBootApplication` 是一个组合注解：

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Documented
@Configuration        // 标记为配置类
@EnableAutoConfiguration  // 启用自动配置
@ComponentScan        // 组件扫描
public @interface SpringBootApplication {}

// 细粒度拆分（Spring 5+）
@SpringBootConfiguration
@EnableAutoConfiguration
@ComponentScan
public @interface SpringBootApplication {}
```

### 4.2 @EnableAutoConfiguration

```java
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Import(AutoConfigurationImportSelector.class)
public @interface EnableAutoConfiguration {
    String ENABLED_OVERRIDE_PROPERTY = "spring.boot.enableautoconfiguration";
}
```

`AutoConfigurationImportSelector` 加载流程：

```text
1. getAutoConfigurationEntry()
2. -> getCandidateConfigurations()  // 获取候选配置
3. -> SpringFactoriesLoader.loadFactoryNames()
4. -> META-INF/spring.factories 中读取
5. -> 返回 @Configuration 类列表
6. -> 按 @Conditional 过滤
7. -> 注册为 Bean
```

### 4.3 条件注解

Spring Boot 使用条件注解控制配置是否生效：

```java
// 类级别条件
@ConditionalOnClass(DataSource.class)      // 类路径存在
@ConditionalOnMissingBean(DataSource.class)  // 不存在该 Bean
@ConditionalOnProperty(prefix = "xxx", name = "enabled")  // 配置项存在

// 方法级别条件
@ConditionalOnBean                          // 存在特定 Bean
@ConditionalOnClass                           // 类路径存在
@ConditionalOnMissingClass                   // 类路径不存在
@ConditionalOnJava(JavaVersion.ELEVEN)       // JDK 版本

// Web 相关条件
@ConditionalOnWebApplication                 // 是 Web 应用
@ConditionalOnNotWebApplication              // 非 Web 应用
```

### 4.4 自定义 Starter

企业可以创建自己的 Starter：

```text
mycompany-starter/
├── pom.xml
└── src/main/resources/
    └── META-INF/
        └── spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
```

```java
// 自动配置类
@Configuration
@ConditionalOnClass(MyService.class)
@EnableConfigurationProperties(MyProperties.class)
public class MyServiceAutoConfiguration {
    
    @Bean
    @ConditionalOnMissingBean
    public MyService myService(MyProperties properties) {
        return new MyService(properties);
    }
}

// 配置属性
@ConfigurationProperties(prefix = "mycompany")
public class MyProperties {
    private String name = "default";
    private int timeout = 3000;
}
```

```xml
<!-- spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports -->
com.mycompany.autoconfigure.MyServiceAutoConfiguration
```

### 5.3 常见问题

#### Q: 为什么 Spring Boot 打出的 JAR 可以直接运行？

```bash
# JAR 结构
myapp.jar
├── BOOT-INF/
│   ├── classes/           # 应用类
│   └── lib/               # 依赖 JAR
└── org/springframework/boot/loader/
    └── SpringBootLoader   # 启动器
```

Spring Boot 的 `META-INF/MANIFEST.MF`：

```properties
Main-Class: org.springframework.boot.loader.JarLauncher
Start-Class: com.example.demo.DemoApplication
```

#### Q: 自动配置不生效怎么办？

1. 检查 `@SpringBootApplication` 是否扫描到配置类
2. 检查 `@Conditional*` 条件是否满足
3. 排除自动配置类：

```java
@SpringBootApplication(exclude = {DataSourceAutoConfiguration.class})
```

4. 开启 debug 模式查看：

```yaml
debug: true
# 或
--debug
```

## 6. 面试回答模板

Spring Boot 的核心优势是"约定优于配置"，通过自动配置和 Starter 依赖，让开发者能快速搭建 Spring 应用。

它的设计初衷是解决传统 Spring 配置复杂的问题。传统 Spring 需要手动配置 DataSource、TransactionManager、视图解析器等，而 Spring Boot 通过 `@EnableAutoConfiguration` 和 `spring-boot-autoconfigure` 里的条件注解，根据类路径依赖自动注册这些 Bean。

比如 `spring-boot-starter-web` 会自动引入 Tomcat、Spring MVC、JSON 处理，配置好就能直接运行 REST 接口。嵌入式服务器让部署变成 `java -jar` 一行命令搞定。Actuator 提供开箱即用的健康检查和监控。外部化配置支持多环境切换。

本质上是把 Spring 生态里"最佳实践"的配置抽成自动配置类，再用 `@Conditional*` 按需加载，既保留了 Spring 的灵活性，又极大降低了使用门槛。
