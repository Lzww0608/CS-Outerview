# 2. Spring IOC 与 AOP

Spring IoC 和 AOP 是 Spring 框架的两条主线。IoC 负责对象创建、依赖注入和生命周期管理，AOP 负责把事务、日志、权限、缓存等横切逻辑织入业务方法。

## 1. IOC 是什么

IoC 是 Inversion of Control，控制反转。它的核心思想是：对象不再自己 `new` 依赖对象，而是把对象创建和依赖管理交给 Spring 容器。

普通写法：

```java
class OrderService {
    private final UserService userService = new UserService();
}
```

IoC 写法：

```java
@Service
class OrderService {
    private final UserService userService;

    OrderService(UserService userService) {
        this.userService = userService;
    }
}
```

这样做的好处：

1. 业务类只依赖接口或抽象，不关心依赖对象如何创建。
2. 依赖关系集中交给容器管理，便于替换实现、测试和配置。
3. 容器可以统一处理生命周期、代理、条件装配和扩展点。

## 2. DI 和 IOC 的关系

DI 是 Dependency Injection，依赖注入，是实现 IoC 的主要方式。IoC 是思想，DI 是手段。

常见注入方式：

1. **构造器注入**：依赖不可变，适合必需依赖，推荐优先使用。
2. **Setter 注入**：适合可选依赖或运行期可变配置。
3. **字段注入**：写起来简单，但不利于单元测试和显式表达依赖，不推荐作为核心业务默认方式。

面试中可以强调：构造器注入能让依赖在对象创建时就完整可用，也能避免循环依赖被隐藏。

## 3. Bean 创建流程

Spring 创建单例 Bean 的简化流程：

```text
扫描配置和注解
-> 生成 BeanDefinition
-> 实例化对象
-> 填充属性和依赖注入
-> 执行 Aware 回调
-> BeanPostProcessor 前置处理
-> 初始化方法
-> BeanPostProcessor 后置处理
-> 放入单例池
```

关键扩展点：

1. `BeanFactoryPostProcessor`：在 Bean 实例化前修改 BeanDefinition。
2. `BeanPostProcessor`：在 Bean 初始化前后增强对象，AOP 代理通常在这里创建。
3. `InitializingBean`、`@PostConstruct`：执行初始化逻辑。
4. `DisposableBean`、`@PreDestroy`：执行销毁逻辑。

注意不要在初始化阶段做耗时远程调用，否则会拖慢应用启动；复杂资源初始化最好有超时、失败降级和健康检查。

## 4. AOP 是什么

AOP 是 Aspect Oriented Programming，面向切面编程。它把日志、事务、权限、监控等横切逻辑从业务代码中抽离出来，在方法调用前后统一增强。

核心概念：

1. **Join Point**：可被增强的位置，Spring AOP 中通常是方法调用。
2. **Pointcut**：切点，定义哪些方法要被增强。
3. **Advice**：通知，定义增强逻辑，例如前置、后置、环绕、异常通知。
4. **Aspect**：切面，Pointcut 和 Advice 的组合。
5. **Weaving**：织入，把增强逻辑应用到目标对象的过程。

示例：

```java
@Aspect
@Component
public class LogAspect {
    @Around("@annotation(AuditLog)")
    public Object around(ProceedingJoinPoint pjp) throws Throwable {
        long start = System.currentTimeMillis();
        try {
            return pjp.proceed();
        } finally {
            long cost = System.currentTimeMillis() - start;
            // 记录方法名、耗时和 traceId
        }
    }
}
```

## 5. Spring AOP 的实现原理

Spring AOP 主要基于代理：

1. 如果目标类实现了接口，默认可以使用 JDK 动态代理，代理对象实现同一组接口。
2. 如果目标类没有接口，可以使用 CGLIB 创建目标类的子类代理。
3. 调用方必须调用代理对象，增强逻辑才会生效。

`@Transactional` 就是典型 AOP 场景：

```text
调用代理对象方法
-> TransactionInterceptor 开启事务
-> 调用目标方法
-> 正常返回提交
-> 抛出符合规则的异常回滚
```

Spring AOP 不是完整 AspectJ 编译期织入，它主要增强 Spring 容器里的 Bean 方法调用，因此对构造函数、字段访问、同类自调用等场景能力有限。

## 6. AOP 常见应用场景

1. **事务管理**：`@Transactional` 统一开启、提交和回滚事务。
2. **日志审计**：记录操作人、请求参数摘要、结果、耗时和 traceId。
3. **权限校验**：在进入业务方法前检查用户角色、租户和数据权限。
4. **缓存**：`@Cacheable`、`@CacheEvict` 统一处理缓存读写。
5. **限流和防重**：基于注解做接口级限流、幂等校验和重复提交拦截。
6. **监控埋点**：统一采集方法耗时、异常率和调用次数。

AOP 适合处理和业务主流程正交的通用逻辑。如果增强逻辑需要深度参与领域决策，放进显式业务代码通常更清晰。

## 7. 易错点

1. **同类自调用不生效**：`this.inner()` 没有经过代理，`inner()` 上的 AOP 注解不会触发。
2. **private/final 方法不适合代理增强**：CGLIB 不能覆盖 final 方法，private 方法也不是正常代理入口。
3. **异常被吞掉会影响事务回滚**：代理看不到异常，事务可能提交。
4. **切面顺序要明确**：事务、权限、日志、幂等同时存在时，要用 `@Order` 或配置明确顺序。
5. **切点不要过宽**：过宽会让无关方法被增强，带来性能、日志噪声和隐藏副作用。
6. **代理类型影响注入和类型判断**：JDK 动态代理注入实现类可能失败，最好面向接口编程。

## 8. 和真实项目的关系

真实后端项目里，IoC 让服务、Repository、消息生产者、客户端 SDK 等组件由容器统一管理；AOP 则把事务、审计、限流、缓存、监控等通用能力做成注解或切面，减少重复样板代码。

但不能把所有逻辑都塞进 AOP。比如订单状态流转、库存扣减、风控决策是业务核心，应该显式写在领域服务里；AOP 更适合做边界增强和基础设施能力。

## 9. 面试回答模板

IoC 是控制反转，把对象创建、依赖注入和生命周期交给 Spring 容器，常见实现方式是 DI，推荐构造器注入。Spring 会先扫描配置生成 BeanDefinition，再实例化、注入依赖、执行初始化和 BeanPostProcessor，AOP 代理也通常在后置处理阶段生成。AOP 是面向切面编程，用代理把事务、日志、权限、缓存、监控等横切逻辑织入方法调用。Spring AOP 主要基于 JDK 动态代理或 CGLIB，调用必须经过代理对象才生效，所以同类自调用、private/final 方法、异常被吞掉、切面顺序和切点过宽都是常见坑。
