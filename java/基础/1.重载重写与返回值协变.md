# 1. 重载、重写与返回值协变

Java 面试里问“方法重载和方法重写的区别”“重写时返回值能不能不同”，核心考察的是编译期绑定、运行期多态和方法签名规则。

## 1. 方法重载是什么

方法重载（Overload）是同一个类中方法名相同，但参数列表不同。它发生在编译期，编译器根据参数个数、参数类型和参数顺序选择具体调用哪个方法。

```java
class Printer {
    void print(String text) {}

    void print(int number) {}

    void print(String text, int copies) {}
}
```

判断重载只看方法名和参数列表，不看返回值。

下面这种写法不能构成重载：

```java
class BadExample {
    int value() {
        return 1;
    }

    // 编译失败：只有返回值不同，方法签名没有变化
    // long value() {
    //     return 1L;
    // }
}
```

## 2. 方法重写是什么

方法重写（Override）是子类重新实现父类或接口中的实例方法。它发生在运行期，调用哪个实现由对象的实际类型决定，这就是多态。

```java
class Animal {
    String sound() {
        return "unknown";
    }
}

class Dog extends Animal {
    @Override
    String sound() {
        return "wang";
    }
}

Animal animal = new Dog();
System.out.println(animal.sound()); // wang
```

重写要求：

1. 方法名相同。
2. 参数列表相同。
3. 返回值相同，或返回父类返回值的子类型。
4. 访问权限不能更严格，例如父类是 `protected`，子类不能改成 `private`。
5. 抛出的受检异常不能比父类更宽。
6. `private`、`static`、`final` 方法不能被正常重写。

## 3. 重写时返回值可以不同吗

可以，但只能是协变返回值。也就是说，子类重写方法的返回类型可以是父类方法返回类型的子类。

```java
class Fruit {}

class Apple extends Fruit {}

class FruitFactory {
    Fruit create() {
        return new Fruit();
    }
}

class AppleFactory extends FruitFactory {
    @Override
    Apple create() {
        return new Apple();
    }
}
```

这种设计让调用方仍然可以把结果当作 `Fruit` 使用，同时子类可以暴露更具体的返回类型。

不能这样写：

```java
class Parent {
    Number get() {
        return 1;
    }
}

class Child extends Parent {
    // 编译失败：String 不是 Number 的子类
    // @Override
    // String get() {
    //     return "1";
    // }
}
```

如果返回类型完全无关，就不是合法重写；如果只改变返回值、不改变参数列表，也不能构成重载。

## 4. 重载和重写的区别

| 对比项 | 重载 Overload | 重写 Override |
| --- | --- | --- |
| 发生位置 | 同一个类或继承体系中 | 子类和父类 / 接口之间 |
| 方法名 | 相同 | 相同 |
| 参数列表 | 必须不同 | 必须相同 |
| 返回值 | 不能只靠返回值区分 | 相同或协变返回 |
| 绑定时机 | 编译期决定 | 运行期动态分派 |
| 目的 | 提供同名不同参数的便捷 API | 实现多态和行为扩展 |

## 5. 易错点

1. **只改返回值不是重载**：Java 方法签名不包含返回值。
2. **`static` 方法不是重写**：静态方法属于类，子类同名静态方法是隐藏，不是多态重写。
3. **`private` 方法不能被重写**：父类 private 方法对子类不可见，子类同名方法是新方法。
4. **访问权限不能缩小**：否则父类引用调用子类对象时会破坏可替换性。
5. **受检异常不能扩大**：子类不能让调用父类方法的代码被迫处理更多受检异常。
6. **建议加 `@Override`**：让编译器帮忙检查是否真的重写，避免参数写错变成重载。

## 6. 真实场景

重载常用于构造便捷 API，例如 `List.of()`、日志方法、工具类方法和构造函数。重写常用于模板方法、策略模式、Spring Bean 扩展点、接口实现和框架回调。

例如 Spring MVC 中不同 Controller 方法不是靠重载分发 HTTP 请求，而是靠 `@RequestMapping` 的路径、HTTP 方法和参数条件匹配；但业务服务实现接口时，子类或实现类对接口方法的实现就是重写。

## 7. 面试回答模板

重载是同名方法参数列表不同，属于编译期多态，返回值不同不能构成重载。重写是子类实现父类或接口的同签名实例方法，属于运行期多态，调用哪个方法由对象真实类型决定。重写时返回值可以不同，但必须是协变返回，也就是返回父类返回类型的子类型；访问权限不能缩小，受检异常不能扩大，`private/static/final` 方法不能被正常重写。
