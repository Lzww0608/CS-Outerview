# Java volatile 关键字

Java 的 `volatile` 是 Java 内存模型中的轻量级同步机制，主要解决共享变量的**可见性**和一定程度的**有序性**问题，但不保证复合操作的原子性。

## 1. 可见性

普通共享变量可能被线程缓存到工作内存或寄存器中，一个线程写入后，另一个线程不一定立刻看到。`volatile` 变量的写入会对后续读取建立可见性关系：

```java
class Worker {
    private volatile boolean stopped = false;

    void stop() {
        stopped = true;
    }

    void run() {
        while (!stopped) {
            doWork();
        }
    }
}
```

这里 `stopped` 适合作为停止标志，因为写线程把它改成 `true` 后，读线程能及时观察到。

## 2. 有序性和 happens-before

Java 内存模型规定：

1. 对一个 `volatile` 变量的写，happens-before 后续任意线程对这个变量的读。
2. `volatile` 写之前的普通写，对读到这个 `volatile` 值的线程也可见。
3. 编译器和 CPU 不能把普通读写随意重排到 `volatile` 屏障两侧。

典型场景是双重检查单例：

```java
class Singleton {
    private static volatile Singleton instance;

    static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

`volatile` 防止对象引用赋值和构造过程被重排，避免其他线程看到“引用非空但对象尚未初始化完成”的状态。

## 2.1 底层如何保证

从 Java 内存模型角度看，`volatile` 不是简单地“每次都从主内存读”。它通过编译器约束和内存屏障建立跨线程的可见性与有序性：

1. `volatile` 写之前的普通写，不能被重排到 `volatile` 写之后。
2. `volatile` 读之后的普通读写，不能被重排到 `volatile` 读之前。
3. 线程 A 对 `volatile` 变量的写，会把写之前的共享变量修改一并发布出去；线程 B 读到这个 `volatile` 值后，也能看到这些修改。
4. 在具体 CPU 上，JVM 会结合内存屏障、缓存一致性协议和平台指令实现这些语义，屏障种类和强弱会因架构而不同。

可以用一个发布配置的例子理解：

```java
class ConfigHolder {
    private Map<String, String> config;
    private volatile boolean ready;

    void load() {
        Map<String, String> tmp = loadFromFile();
        config = tmp;       // 普通写
        ready = true;       // volatile 写，发布前面的普通写
    }

    String get(String key) {
        if (!ready) {       // volatile 读，读到 true 后能看到 config
            return null;
        }
        return config.get(key);
    }
}
```

这里 `ready` 只负责发布和观察状态，不负责保护 `config` 之后的并发修改。如果 `config` 还会被多个线程更新，仍然需要锁、不可变对象或并发容器。

## 3. 不保证原子性

`volatile int count` 的 `count++` 仍然不安全，因为它包含读、加、写多个步骤：

```java
volatile int count = 0;

void inc() {
    count++; // 非原子
}
```

多线程计数应使用：

1. `AtomicInteger` / `LongAdder`。
2. `synchronized` 或 `ReentrantLock`。
3. 数据分片后汇总，降低热点竞争。

## 4. 和 C++ volatile 的区别

Java `volatile` 有明确的线程可见性和内存屏障语义；C/C++ `volatile` 主要约束编译器优化，常用于内存映射 I/O、信号处理等场景，不能替代 `std::atomic` 或锁。面试时不要把二者混在一起回答。

## 5. 适用场景

适合：

1. 状态标志，例如停止标记、配置版本号。
2. 单写多读且写入是简单赋值的场景。
3. 配合锁实现双重检查。

不适合：

1. 计数器自增。
2. 多个变量需要保持一致的不变式。
3. 读-改-写复合逻辑。

## 6. 面试回答模板

Java `volatile` 保证变量在线程间的可见性，并通过编译器约束和内存屏障限制重排序。对 volatile 变量的写 happens-before 后续读，因此写 volatile 前的普通写也会对读到该 volatile 值的线程可见，常用于停止标志、配置发布和双重检查单例。但 volatile 不保证 `i++` 这类复合操作的原子性，也不能维护多个变量之间的一致性；这些场景要用原子类、锁或更高层并发工具。
