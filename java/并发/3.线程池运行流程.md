简单版可以这样理解：

## Java 线程池运行流程

### 1. 先创建线程池

比如用 `ThreadPoolExecutor` 或 `Executors` 创建。
线程池里会提前定义好：

- 核心线程数
- 最大线程数
- 任务队列
- 拒绝策略

------

### 2. 提交任务

你调用：

```java
executor.execute(task);
```

或者

```java
executor.submit(task);
```

把任务交给线程池。

------

### 3. 线程池先看当前线程数量

收到任务后，线程池不是马上新建线程，而是按规则判断：

#### 情况一：当前线程数 < 核心线程数

直接创建新线程来执行这个任务。

#### 情况二：当前线程数 >= 核心线程数

先不急着建新线程，而是尝试把任务放进任务队列。

------

### 4. 任务队列满了怎么办

如果队列已经放不下新任务了，线程池会继续判断：

#### 如果当前线程数 < 最大线程数

再创建新线程处理任务。

#### 如果当前线程数已经达到最大线程数

就触发**拒绝策略**。

------

### 5. 拒绝策略生效

常见几种：

- 直接报错
- 让提交任务的线程自己执行
- 丢掉当前任务
- 丢掉队列里最老的任务再尝试加入

------

### 6. 线程执行完任务后怎么办

线程不会立刻销毁。

- 核心线程通常会保留，等下一个任务
- 非核心线程如果空闲时间太久，可能会被回收

------

## 一句话总结流程

可以记成这句：

> **先开核心线程，再进队列，队列满了再开非核心线程，真的满了就拒绝。**

------

## 一个很简化的流程图思路

```text
提交任务
   ↓
核心线程没满？
   ├─ 是 → 创建核心线程执行
   └─ 否 → 放入队列
              ↓
          队列满了？
              ├─ 否 → 等待空闲线程执行
              └─ 是 → 最大线程没满？
                        ├─ 是 → 创建非核心线程执行
                        └─ 否 → 拒绝策略
```

------

## 你可以把它想成饭店

- 核心线程：固定员工
- 队列：排队区
- 最大线程：高峰期临时加的人
- 拒绝策略：实在接待不了时的处理方式

来一个顾客（任务）时：

1. 固定员工有空就直接接待
2. 固定员工满了，就去排队
3. 排队区满了，就叫临时工
4. 临时工也满了，就不接了或者换种处理方式

------

## 补一句 execute 和 submit 的区别

- `execute()`：只执行任务，没有返回值
- `submit()`：可以拿到 `Future`，以后能看结果、异常、是否完成
