# 6. DCL 单例与静态方法调用

## 1. 问题背景

在 Java 面试中，DCL（Double-Checked Locking，双重检查锁）单例是高频考点，通常会连续考察：

1. 如何写一个线程安全的懒加载单例；
2. 为什么实例变量必须加 `volatile`；
3. 外部如何拿到这个单例；
4. `getInstance()` 为什么通常写成 `static`；
5. 静态方法能不能调用非静态成员；
6. 静态成员、实例成员在 JVM 中的关系。

这些问题看似是设计模式，实际考察的是 **对象创建过程、类加载、静态成员、实例成员、JMM 可见性、有序性和 synchronized 锁语义**。

**假设条件：**

- 使用 Java 8+；
- 单例对象需要懒加载，即第一次使用时才创建；
- 单例对象在多线程环境下被并发访问；
- 目标是解释面试中常见的 DCL 单例、外部访问方式和静态方法调用规则。

## 2. 问题现象

常见错误写法如下：

```java
public class Singleton {
    private Singleton instance;

    private Singleton() {}

    public Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

这段代码的问题包括：

1. `instance` 不是 `static`，每个对象都有一份，无法表达全局唯一；
2. `getInstance()` 不是 `static`，外部想调用它必须先 `new Singleton()`，但构造方法又是 private，外部根本无法 new；
3. `instance` 没有 `volatile`，可能发生指令重排序，导致其他线程拿到未初始化完成的对象；
4. `synchronized` 锁对象虽然写了 `Singleton.class`，但整体语义仍不完整；
5. 如果在静态方法中直接访问非静态成员，会编译报错。

## 3. 影响范围

| 影响点 | 具体表现 |
|--------|---------|
| 线程安全 | 多线程下可能创建多个实例，或读取到半初始化对象 |
| 可用性 | `getInstance()` 非静态时，外部无法在不创建对象的情况下获取单例 |
| 代码正确性 | 静态方法直接访问非静态成员会编译失败 |
| 面试表现 | 容易暴露 Java 基础、JMM、类加载理解不扎实 |
| 维护性 | 错误单例可能导致全局状态混乱，排查困难 |

## 4. 原因分析

### 4.1 外部怎么拿到单例

单例模式的核心目标是：**全局只有一个对象，并且外部只能通过统一入口获取它**。

因此通常需要：

1. 构造方法私有化，禁止外部 `new`；
2. 单例实例用 `private static` 保存，保证属于类而不是属于某个对象；
3. 对外提供 `public static getInstance()`，外部通过类名直接调用。

正确访问方式：

```java
Singleton singleton = Singleton.getInstance();
```

如果 `getInstance()` 不是静态方法，外部调用方式会变成：

```java
Singleton singleton = new Singleton().getInstance();
```

这与单例模式矛盾，因为外部必须先创建一个对象才能拿到单例。

### 4.2 静态方法为什么不能直接调用非静态成员

静态方法属于类，类加载后即可通过类名调用；非静态成员属于对象，必须先创建对象才存在。

例如：

```java
public class Demo {
    private int count = 1;

    public static void test() {
        System.out.println(count); // 编译错误
    }
}
```

原因是：执行 `Demo.test()` 时，可能根本没有任何 `Demo` 对象存在，因此 JVM 不知道应该访问哪个对象的 `count`。

正确方式有两种：

```java
public class Demo {
    private int count = 1;

    public static void test() {
        Demo demo = new Demo();
        System.out.println(demo.count);
    }
}
```

或将成员也声明为静态：

```java
public class Demo {
    private static int count = 1;

    public static void test() {
        System.out.println(count);
    }
}
```

### 4.3 DCL 为什么需要 volatile

`new Singleton()` 并不是一个原子操作，底层大致分三步：

```text
1. 分配内存空间
2. 调用构造方法初始化对象
3. 将对象引用赋值给 instance
```

如果没有 `volatile`，JVM 和 CPU 可能发生指令重排序：

```text
1. 分配内存空间
2. 将对象引用赋值给 instance
3. 调用构造方法初始化对象
```

此时线程 A 执行到第 2 步，`instance != null`，但对象还没初始化完成。线程 B 进入 `getInstance()`，发现 `instance != null`，直接返回，就可能拿到半初始化对象。

`volatile` 的作用：

1. 保证可见性：一个线程写入 `instance` 后，其他线程立即可见；
2. 禁止指令重排序：避免引用赋值发生在构造方法完成之前。

## 5. 解决方案

### 5.1 标准 DCL 单例写法

```java
public class Singleton {

    private static volatile Singleton instance;

    private Singleton() {
        // 防止反射破坏单例，可按需补充保护逻辑
    }

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

关键点：

1. `private static volatile Singleton instance`：
   - `private`：外部不能直接访问；
   - `static`：属于类，全局一份；
   - `volatile`：保证可见性并禁止指令重排序。
2. `private Singleton()`：构造方法私有化，禁止外部 new。
3. `public static Singleton getInstance()`：外部通过类名获取单例。
4. 第一层 `if (instance == null)`：避免每次调用都加锁，提高性能。
5. `synchronized (Singleton.class)`：保证并发创建时只有一个线程进入临界区。
6. 第二层 `if (instance == null)`：防止多个线程排队进入锁后重复创建对象。

### 5.2 外部调用方式

```java
public class Main {
    public static void main(String[] args) {
        Singleton singleton = Singleton.getInstance();
    }
}
```

外部不需要、也不能 `new Singleton()`。因为构造方法是 `private`，唯一入口就是 `Singleton.getInstance()`。

### 5.3 静态方法调用非静态成员的正确理解

| 场景 | 是否允许 | 原因 |
|------|---------|------|
| 静态方法直接访问非静态变量 | 不允许 | 非静态变量属于对象，静态方法属于类 |
| 静态方法通过对象访问非静态变量 | 允许 | 已经明确访问的是哪个对象 |
| 非静态方法访问静态变量 | 允许 | 对象方法可以访问类级别成员 |
| 非静态方法访问非静态变量 | 允许 | 都属于对象 |
| 静态方法访问静态变量 | 允许 | 都属于类 |

示例：

```java
public class Demo {
    private int instanceValue = 1;
    private static int staticValue = 2;

    public static void staticMethod() {
        // System.out.println(instanceValue); // 编译错误
        Demo demo = new Demo();
        System.out.println(demo.instanceValue); // 正确
        System.out.println(staticValue);        // 正确
    }

    public void instanceMethod() {
        System.out.println(instanceValue); // 正确
        System.out.println(staticValue);   // 正确
    }
}
```

## 6. 可选方案对比

| 方案 | 是否懒加载 | 线程安全 | 实现复杂度 | 推荐程度 | 说明 |
|------|------------|----------|------------|---------|------|
| 饿汉式 | 否 | 是 | 低 | ★★★ | 类加载时创建，简单但不能懒加载 |
| 懒汉式（方法加 synchronized） | 是 | 是 | 低 | ★★ | 每次获取都加锁，性能较差 |
| DCL 双重检查锁 | 是 | 是（需 volatile） | 中 | ★★★★ | 面试高频，生产可用但代码较复杂 |
| 静态内部类 | 是 | 是 | 低 | ★★★★★ | 推荐写法，利用类加载机制保证线程安全 |
| 枚举单例 | 否 | 是 | 低 | ★★★★★ | 防反射、防序列化破坏，最安全 |

### 6.1 饿汉式

```java
public class Singleton {
    private static final Singleton INSTANCE = new Singleton();

    private Singleton() {}

    public static Singleton getInstance() {
        return INSTANCE;
    }
}
```

### 6.2 synchronized 懒汉式

```java
public class Singleton {
    private static Singleton instance;

    private Singleton() {}

    public static synchronized Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
```

### 6.3 静态内部类

```java
public class Singleton {
    private Singleton() {}

    private static class Holder {
        private static final Singleton INSTANCE = new Singleton();
    }

    public static Singleton getInstance() {
        return Holder.INSTANCE;
    }
}
```

静态内部类利用 JVM 类加载机制：`Holder` 只有在第一次调用 `getInstance()` 时才会被加载，类加载过程天然线程安全。

### 6.4 枚举单例

```java
public enum Singleton {
    INSTANCE;

    public void doSomething() {
        // business logic
    }
}
```

枚举单例能天然防止反射和反序列化破坏，是《Effective Java》推荐方式。

## 7. 推荐方案

如果是面试题，推荐先写 **DCL 单例**，因为它能体现对 `volatile`、`synchronized`、静态成员和对象创建过程的理解。

面试回答建议：

1. 先写标准 DCL 代码；
2. 说明外部通过 `Singleton.getInstance()` 获取对象；
3. 强调 `getInstance()` 必须是 `static`，否则外部拿不到单例；
4. 说明 `instance` 必须是 `static`，否则不是类级别唯一；
5. 说明 `instance` 必须是 `volatile`，防止指令重排序导致半初始化对象；
6. 补充静态方法不能直接访问非静态成员，因为非静态成员属于具体对象。

如果是实际工程代码，优先推荐：

1. **无参数、无复杂初始化**：枚举单例；
2. **需要懒加载**：静态内部类；
3. **需要展示并发控制原理**：DCL 单例。

## 8. 实施步骤

### 8.1 面试中写 DCL 单例的步骤

1. 定义类 `Singleton`；
2. 声明 `private static volatile Singleton instance;`；
3. 私有化构造方法 `private Singleton() {}`；
4. 编写 `public static Singleton getInstance()`；
5. 第一层判断 `if (instance == null)`；
6. 使用 `synchronized (Singleton.class)` 加锁；
7. 第二层判断 `if (instance == null)`；
8. 创建对象 `instance = new Singleton();`；
9. 返回 `instance`；
10. 解释 `volatile`、`static`、双重检查和锁对象。

### 8.2 标准代码

```java
public class Singleton {
    private static volatile Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

### 8.3 面试追问回答模板

**问：外部怎么拿到这个单例？**

答：通过类名调用静态方法：

```java
Singleton singleton = Singleton.getInstance();
```

因为构造方法是 `private`，外部不能 `new`，所以必须提供 `public static getInstance()` 作为唯一入口。

**问：为什么 `getInstance()` 要是 static？**

答：因为如果不是静态方法，外部必须先创建对象才能调用它，这和单例禁止外部创建对象矛盾。`static` 方法属于类，可以通过 `Singleton.getInstance()` 直接调用。

**问：静态方法能调用非静态成员吗？**

答：不能直接调用。静态方法属于类，非静态成员属于对象；调用静态方法时对象可能还不存在，所以不能直接访问非静态成员。但如果在静态方法中先创建对象，再通过对象引用访问非静态成员，是可以的。

**问：非静态方法能调用静态成员吗？**

答：可以。因为静态成员属于类，类加载后就存在，对象方法当然可以访问类级别成员。

## 9. 风险与注意事项

| 风险 | 说明 | 解决方式 |
|------|------|---------|
| 忘记 `volatile` | 可能因指令重排序返回半初始化对象 | `instance` 必须加 `volatile` |
| 忘记 `static` | 单例实例变成对象级别，不再全局唯一 | `instance` 和 `getInstance()` 都要 static |
| 构造方法不是 private | 外部可以随意 new，破坏单例 | 构造方法私有化 |
| 只写一层 if | 多线程排队进入锁后可能重复创建 | 必须双重检查 |
| 锁对象写错 | 锁不住所有线程 | 推荐 `synchronized (Singleton.class)` |
| 反射破坏单例 | 反射可调用私有构造方法 | 可在构造方法中检查 instance，或使用枚举单例 |
| 序列化破坏单例 | 反序列化生成新对象 | 实现 `readResolve()` 或使用枚举单例 |
| 过度使用单例 | 全局状态难测试、难替换 | 依赖注入优先，单例仅用于真正全局唯一对象 |

## 10. 验证方式

### 10.1 编译验证

验证静态方法不能直接访问非静态成员：

```java
public class Demo {
    private int value = 1;

    public static void test() {
        System.out.println(value);
    }
}
```

编译会报错：

```text
non-static variable value cannot be referenced from a static context
```

### 10.2 多线程验证单例唯一性

```java
import java.util.Set;
import java.util.concurrent.*;
import java.util.concurrent.ConcurrentHashMap;

public class SingletonTest {
    public static void main(String[] args) throws Exception {
        ExecutorService executor = Executors.newFixedThreadPool(100);
        Set<Singleton> set = ConcurrentHashMap.newKeySet();
        CountDownLatch latch = new CountDownLatch(1000);

        for (int i = 0; i < 1000; i++) {
            executor.submit(() -> {
                set.add(Singleton.getInstance());
                latch.countDown();
            });
        }

        latch.await();
        executor.shutdown();

        System.out.println(set.size()); // 应输出 1
    }
}
```

### 10.3 重点验证点

1. 1000 个并发任务获取到的对象引用是否只有一个；
2. `getInstance()` 是否可以通过类名直接调用；
3. 构造方法是否无法被外部直接调用；
4. 删除 `static` 后能否解释为什么编译或语义错误；
5. 删除 `volatile` 后能否说明潜在重排序风险。

## 11. 总结

DCL 单例的标准写法是：

```java
public class Singleton {
    private static volatile Singleton instance;

    private Singleton() {}

    public static Singleton getInstance() {
        if (instance == null) {
            synchronized (Singleton.class) {
                if (instance == null) {
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

核心结论：

1. 外部通过 `Singleton.getInstance()` 获取单例；
2. `getInstance()` 必须是 `static`，否则外部无法在不创建对象的情况下调用；
3. `instance` 必须是 `static`，否则不是全局唯一实例；
4. `instance` 必须是 `volatile`，防止指令重排序导致半初始化对象；
5. 静态方法不能直接调用非静态成员，因为静态方法属于类，非静态成员属于对象；
6. 静态方法可以通过对象引用访问非静态成员，但 DCL 单例场景下不应该这样设计；
7. 工程中更推荐静态内部类或枚举单例，面试中 DCL 更能体现并发基础。
