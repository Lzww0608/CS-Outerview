# 2. Dockerfile 编写

Dockerfile 是镜像构建脚本，用一组声明式指令描述基础镜像、依赖安装、文件复制、构建步骤、运行用户和启动命令。面试里不要只背指令名，要能说明镜像分层、缓存、安全和体积控制。

## 1. 常见指令

| 指令 | 作用 | 注意点 |
| --- | --- | --- |
| `FROM` | 指定基础镜像 | 尽量固定版本，不要随意用 `latest` |
| `WORKDIR` | 设置工作目录 | 比 `RUN cd ...` 更稳定 |
| `COPY` | 复制本地文件到镜像 | 优先于 `ADD`，语义更清晰 |
| `RUN` | 构建时执行命令 | 每条 `RUN` 会形成镜像层 |
| `ENV` | 设置环境变量 | 不要写入密码、token 等秘密 |
| `EXPOSE` | 声明服务端口 | 只是元数据，不会自动发布端口 |
| `USER` | 指定运行用户 | 生产镜像应避免 root 运行 |
| `CMD` | 容器默认启动命令 | 可被 `docker run` 参数覆盖 |
| `ENTRYPOINT` | 固定入口程序 | 常配合 `CMD` 传默认参数 |

## 2. Python 服务示例

```dockerfile
FROM python:3.12-slim AS runtime

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1

WORKDIR /app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

RUN useradd -r -u 10001 appuser
USER appuser

EXPOSE 8000
CMD ["uvicorn", "main:app", "--host", "0.0.0.0", "--port", "8000"]
```

这个 Dockerfile 的关键点：

1. 先复制 `requirements.txt` 再安装依赖，可以复用 Docker build cache。
2. `--no-cache-dir` 减少 pip 缓存体积。
3. 用非 root 用户运行，降低容器逃逸或误操作风险。
4. `PYTHONUNBUFFERED=1` 让日志及时输出到 stdout，方便容器平台采集。

## 3. 多阶段构建

编译型语言常用多阶段构建：第一阶段编译，第二阶段只保留运行产物。

```dockerfile
FROM golang:1.22 AS builder

WORKDIR /src
COPY go.mod go.sum ./
RUN go mod download
COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -o /out/server ./cmd/server

FROM alpine:3.20

WORKDIR /app
COPY --from=builder /out/server /app/server
RUN adduser -D -u 10001 appuser
USER appuser

EXPOSE 8080
ENTRYPOINT ["/app/server"]
```

多阶段构建的价值是让最终镜像不包含编译器、源码和构建缓存，体积更小，攻击面也更低。

## 4. 镜像分层和缓存

Dockerfile 每条指令通常会生成一层。构建时如果某一层输入没有变化，就可以复用缓存；一旦某层变化，后续层都要重新构建。

常见优化：

1. 把变化少的依赖描述文件放在前面，例如 `go.mod`、`package-lock.json`、`requirements.txt`。
2. 把业务源码 `COPY . .` 放在依赖安装之后。
3. 用 `.dockerignore` 排除 `.git`、日志、测试输出、本地虚拟环境和临时文件。
4. 合并相关 `RUN`，并在同一层删除包管理器缓存。
5. 基础镜像固定版本，生产镜像定期重建以获取安全补丁。

示例 `.dockerignore`：

```text
.git
__pycache__
.venv
node_modules
dist
*.log
```

## 5. 易错点

1. `CMD` 和 `ENTRYPOINT` 容易混淆：`ENTRYPOINT` 更像固定入口，`CMD` 更像默认参数或默认命令。
2. `EXPOSE` 不等于发布端口，真正映射端口要用 `docker run -p` 或 Kubernetes Service。
3. 不要把密钥写进 Dockerfile、镜像层或环境变量，构建历史可能泄漏。
4. 不要在生产镜像里默认 root 运行，除非确实需要特权。
5. 基础镜像越小不一定越好，`scratch`、`alpine` 可能带来调试困难、glibc/musl 兼容问题和证书缺失。
6. 容器里只跑一个主进程时，要让它以前台方式运行，并正确处理 SIGTERM，方便优雅下线。

## 6. 面试回答模板

Dockerfile 用来描述镜像怎么构建，常见指令有 `FROM`、`WORKDIR`、`COPY`、`RUN`、`ENV`、`EXPOSE`、`USER`、`CMD`、`ENTRYPOINT`。我会先选固定版本基础镜像，按依赖文件优先复制来利用构建缓存，再复制源码；编译型语言用多阶段构建，只把最终二进制放进运行镜像。生产上还要用 `.dockerignore` 控制上下文体积，避免 root 运行，不把密钥写进镜像，关注镜像大小、安全补丁、日志输出和优雅退出。
