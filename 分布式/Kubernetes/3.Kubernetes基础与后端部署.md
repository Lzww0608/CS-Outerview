# 3. Kubernetes 基础与后端部署

Kubernetes 是容器编排系统，核心目标是把“我要运行什么服务、需要多少副本、如何暴露、如何更新、如何自愈”描述成期望状态，再由控制器持续把实际状态拉回期望状态。

面试里被问“了解 K8s 吗”，不要只回答会写 YAML，可以按资源对象、控制面、发布运维和排障四层展开。

## 1. 核心对象

常见对象：

1. **Pod**：最小调度单元，一组共享网络命名空间和存储卷的容器。
2. **Deployment**：声明无状态服务的副本数、镜像版本和滚动更新策略。
3. **ReplicaSet**：保证 Pod 副本数，通常由 Deployment 自动管理。
4. **Service**：给一组 Pod 提供稳定访问入口，屏蔽 Pod IP 变化。
5. **Ingress**：七层入口规则，常用于域名、路径路由和 TLS 终止。
6. **ConfigMap/Secret**：配置和敏感信息注入，Secret 还要配合权限、加密和轮转。
7. **Job/CronJob**：一次性任务和定时任务。
8. **StatefulSet**：有状态服务，提供稳定网络标识和有序发布。
9. **HPA**：基于 CPU、内存或自定义指标自动扩缩容。

后端服务最常见组合是：

```text
Deployment -> Pod
Service -> 稳定服务入口
Ingress/Gateway -> 对外流量入口
ConfigMap/Secret -> 配置和密钥
HPA -> 自动扩缩容
```

## 2. 控制面和节点组件

控制面组件：

1. **API Server**：所有资源读写入口，负责认证、鉴权、准入和资源校验。
2. **etcd**：保存集群状态。
3. **Scheduler**：给未绑定节点的 Pod 选择 Node。
4. **Controller Manager**：运行各种控制器，让实际状态接近期望状态。

节点组件：

1. **kubelet**：节点代理，负责拉起 Pod、探针检查、上报状态。
2. **container runtime**：如 containerd，通过 CRI 创建容器。
3. **kube-proxy 或替代组件**：实现 Service 转发规则。
4. **CNI 插件**：负责 Pod 网络，例如 Flannel、Calico、Cilium。
5. **CSI 插件**：负责存储卷挂载和生命周期。

K8s 的核心思想是声明式控制：

```text
用户提交期望状态
  -> API Server 写入 etcd
  -> 控制器 watch 变化
  -> 创建/删除/更新资源
  -> kubelet 在节点上执行
  -> 状态回写 API Server
```

## 3. 后端服务怎么部署

一个基础 Deployment 示例：

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: order-service
spec:
  replicas: 3
  selector:
    matchLabels:
      app: order-service
  template:
    metadata:
      labels:
        app: order-service
    spec:
      containers:
        - name: order-service
          image: registry.example.com/order-service:20260523
          ports:
            - containerPort: 8080
          resources:
            requests:
              cpu: "500m"
              memory: "512Mi"
            limits:
              cpu: "1"
              memory: "1Gi"
          readinessProbe:
            httpGet:
              path: /health/ready
              port: 8080
          livenessProbe:
            httpGet:
              path: /health/live
              port: 8080
```

配套 Service：

```yaml
apiVersion: v1
kind: Service
metadata:
  name: order-service
spec:
  selector:
    app: order-service
  ports:
    - port: 80
      targetPort: 8080
```

生产环境要重点关注：

1. **readinessProbe**：未就绪实例不进入流量后端。
2. **livenessProbe**：进程死锁或不可恢复时自动重启。
3. **resources**：设置 requests/limits，避免调度不准或资源互相挤压。
4. **rollingUpdate**：控制发布期间最大不可用和最大新增副本。
5. **terminationGracePeriodSeconds**：给服务优雅停机时间。
6. **日志与指标**：标准输出日志、Prometheus 指标、trace id 串联请求。
7. **配置和密钥**：配置外置，密钥避免写入镜像和 Git。

## 4. 中间件和外部依赖怎么处理

后端服务常依赖 MySQL、Redis、MQ、对象存储和下游 RPC。K8s 只负责运行服务，不会自动保证业务一致性。

常见做法：

1. **数据库**：生产 MySQL 通常使用云数据库或专门运维的集群，应用通过 Secret 注入连接信息。
2. **Redis/MQ**：可以用云服务、Operator 或独立集群，应用侧要有超时、重试、熔断和连接池限制。
3. **服务发现**：集群内服务通过 Service DNS 访问，例如 `order-service.default.svc.cluster.local`。
4. **配置发布**：ConfigMap 更新后应用不一定自动重载，需要热加载逻辑或滚动重启。
5. **批处理任务**：用 Job/CronJob，但要处理幂等、失败重试和并发策略。

不要把 K8s 当成数据库事务或分布式锁。Pod 重启、迁移、扩缩容都可能发生，应用本身要处理幂等、超时、重试和优雅退出。

## 5. 常见排障思路

Pod 异常可以按状态排查：

1. **Pending**：资源不足、调度约束过强、污点未容忍、PVC 未绑定。
2. **ImagePullBackOff**：镜像地址、tag、仓库权限、网络或镜像不存在。
3. **CrashLoopBackOff**：进程启动失败、配置错误、依赖不可用、探针过严。
4. **Running 但无流量**：readiness 未通过、Service selector 不匹配、端口配置错误。
5. **访问超时**：网关、Service、NetworkPolicy、DNS、Pod 监听地址或下游依赖问题。

常用命令：

```bash
kubectl get pod -o wide
kubectl describe pod <pod>
kubectl logs <pod> -c <container>
kubectl get events --sort-by=.lastTimestamp
kubectl exec -it <pod> -- sh
kubectl rollout status deployment/<name>
kubectl rollout undo deployment/<name>
```

排障时先看 `describe` 事件，再看容器日志和探针结果；如果是网络问题，再查 Service selector、EndpointSlice、DNS、NetworkPolicy 和 Ingress/Gateway。

## 6. 易错点

1. Pod 是易失的，不能把本地磁盘当长期存储，除非明确使用 PVC。
2. Running 不等于 Ready，只有 readiness 通过才应该接流量。
3. ConfigMap/Secret 变更不一定让应用自动感知。
4. replicas 不是高可用的全部，还要看节点分布、反亲和、PDB 和外部依赖。
5. HPA 扩容不能解决所有问题，下游数据库、Redis、MQ 可能先被打爆。
6. 强制删除 Pod 可能跳过优雅停机，导致请求中断或外部资源未清理。

## 7. 面试回答模板

Kubernetes 我会按声明式编排理解。用户把 Deployment、Service、Ingress、ConfigMap 等期望状态提交给 API Server，API Server 鉴权校验后写入 etcd；控制器和调度器 watch 状态变化，创建 Pod、选择节点，节点上的 kubelet 再通过 CNI、CSI 和容器运行时把容器拉起来。后端服务部署时要配置 requests/limits、readiness/liveness probe、滚动更新、优雅停机、日志指标和 Secret。排障时按 Pending、ImagePull、CrashLoop、Ready、Service/Ingress 链路逐层看事件、日志、探针和网络配置。
