# 1.Pod 创建与删除流程

Kubernetes 面试里问“一个 Pod 是怎么创建出来、怎么删除的”，本质是在考你是否理解控制面、调度、节点代理和容器运行时之间的协作。

## 1. Pod 创建流程

以创建 Deployment 为例，Pod 通常不是直接由用户手工创建，而是由控制器根据期望状态生成。

完整链路可以按下面顺序回答：

1. **提交资源**：用户通过 `kubectl apply` 或 API 调用把 Deployment/Pod YAML 提交给 API Server。
2. **认证鉴权与准入**：API Server 执行认证、RBAC 鉴权、Admission Webhook、默认值填充和资源校验。
3. **写入 etcd**：合法资源被持久化到 etcd，成为集群的期望状态。
4. **控制器创建 Pod**：Deployment Controller 创建 ReplicaSet，ReplicaSet Controller 创建具体 Pod 对象。
5. **调度器绑定节点**：Scheduler watch 到未绑定节点的 Pod，经过过滤和打分，选择合适 Node，并写入 binding。
6. **kubelet 拉取任务**：目标节点上的 kubelet watch 到分配给自己的 Pod。
7. **准备运行环境**：kubelet 调用 CNI 配置网络，调用 CSI 或本地插件挂载卷，处理 Secret/ConfigMap。
8. **创建容器**：kubelet 通过 CRI 调用 containerd/CRI-O，拉镜像并创建 sandbox 与业务容器。
9. **探针与就绪**：容器启动后执行 startup/readiness/liveness probe；readiness 通过后，EndpointSlice 控制器把 Pod 加入服务后端。

## 2. 调度阶段看什么

Scheduler 通常分成过滤和打分：

1. **过滤**：节点资源是否足够，端口是否冲突，NodeSelector、NodeAffinity、Taint/Toleration、PVC 拓扑是否满足。
2. **打分**：资源利用率、亲和/反亲和、镜像本地性、拓扑分布、负载均衡等。
3. **绑定**：选出节点后写回 API Server，后续由节点 kubelet 接管。

如果 Pod 一直 Pending，排查方向通常是资源不足、节点污点未容忍、镜像拉取失败、PVC 无法绑定或调度约束过强。

## 3. Pod 删除流程

删除不是立刻杀进程，而是一个优雅终止流程：

1. 用户删除 Pod，API Server 给对象设置 `deletionTimestamp`，并保留一段 `terminationGracePeriodSeconds`。
2. EndpointSlice 很快把该 Pod 从 Service 后端摘除，避免新流量继续打过来。
3. kubelet watch 到删除状态后，先执行容器的 `preStop` hook。
4. kubelet 向容器主进程发送 `SIGTERM`，应用应停止接新请求并尽快完成正在处理的请求。
5. 宽限期内进程正常退出，kubelet 清理容器、网络和卷。
6. 超过宽限期仍未退出，kubelet 发送 `SIGKILL` 强制结束。
7. 资源清理完成后，Pod 对象从 API Server 中消失；关联资源可能由 ownerReference 和 GC 回收。

## 4. Finalizer 与强制删除

Finalizer 用于阻止资源在外部清理完成前被真正删除，例如云盘解绑、负载均衡摘除、外部注册中心注销。对象带有 finalizer 时，即使有 `deletionTimestamp`，也会等控制器移除 finalizer 后才完成删除。

强制删除会跳过部分优雅流程：

```bash
kubectl delete pod demo --grace-period=0 --force
```

这适合处理节点失联或对象卡死，但可能导致业务请求中断、外部资源未清理或存储状态不一致，生产环境要谨慎使用。

## 5. 易错点

1. Deployment 创建 Pod 不是 kubelet 主动扫描出来的，而是控制器把期望状态写入 API Server，再由各组件 watch。
2. Pod Running 不代表可以接流量，只有 readiness 通过后才应进入 Service 后端。
3. 删除 Pod 时 Service 摘除和进程退出存在时间窗口，应用本身也要处理优雅停机。
4. `preStop` 执行时间算在 termination grace period 内，不是额外赠送时间。
5. 镜像拉取、CNI、CSI、探针失败都会让 Pod 看起来“创建失败”，排查要看 `describe pod`、kubelet 日志和事件。

## 6. 面试回答模板

Pod 创建时，API Server 先做认证、鉴权、准入和校验，然后把期望状态写入 etcd。控制器根据 Deployment/ReplicaSet 创建 Pod，Scheduler 给未调度 Pod 选择节点并写入绑定结果。节点上的 kubelet watch 到自己负责的 Pod 后，通过 CNI 准备网络、挂载卷、拉镜像，并通过 CRI 调用 containerd 创建容器。容器启动后 readiness probe 通过，才会被加入 Service 后端。

删除时，API Server 先给 Pod 设置删除时间戳，EndpointSlice 把它从服务后端摘掉，kubelet 执行 `preStop` 并发送 `SIGTERM`，应用在宽限期内优雅退出；超时则 `SIGKILL`。如果有 finalizer，还要等外部清理完成后才真正删除。
