# 1. GFS 与分布式文件系统

分布式文件系统把大文件切成块，分散存储到多台机器上，通过元数据服务管理文件名、块位置、副本和租约。它解决的是单机磁盘容量、吞吐和可靠性不足的问题。

## 1. GFS 核心思想

GFS（Google File System）的典型设计包括：

1. **Master**：保存元数据，例如目录树、文件到 chunk 的映射、chunk 副本位置、租约。
2. **Chunkserver**：保存真实数据块，块通常较大，适合顺序读写和追加。
3. **Client**：先向 Master 查询元数据，再直接和 Chunkserver 传输数据。

读流程：

```text
client -> master 查询 chunk 位置
client -> 最近或合适的 chunkserver 读取数据
```

写流程：

```text
client -> master 获取 primary 和 replicas
client -> 多个 chunkserver 传数据
client -> primary 排序写请求
primary -> replicas 同步写入
```

## 2. 为什么适合大文件

1. 大块减少元数据数量，降低 Master 压力。
2. 客户端直接读写 Chunkserver，Master 不在数据路径上。
3. 多副本提高容错和读吞吐。
4. 适合日志、图片视频、离线数据、对象存储底层等顺序读写场景。

不适合大量小文件和强 POSIX 语义，因为元数据压力、随机写和一致性成本会很高。

## 3. 容错和一致性

1. 每个 chunk 多副本存储，副本分布在不同机器或机架。
2. Master 通过心跳发现 Chunkserver 故障。
3. 副本不足时自动复制补足。
4. 写入由 primary 排序，保证多个副本按相同顺序执行。
5. Master 自身需要操作日志、checkpoint 和备份，避免单点故障。

## 4. 和 HDFS、对象存储的关系

| 系统 | 特点 | 适合场景 |
| --- | --- | --- |
| GFS | 大文件、追加写、Master 管元数据 | Google 内部大规模数据处理 |
| HDFS | 受 GFS 启发，NameNode + DataNode | Hadoop/Spark 离线计算 |
| Ceph | 去中心化、RADOS、强扩展 | 云存储、块/对象/文件统一存储 |
| S3/对象存储 | HTTP API、桶和对象、弱化文件系统语义 | 图片视频、备份、归档、静态资源 |

## 5. 面试回答模板

分布式文件系统通常把文件切成多个 chunk/block，元数据服务负责文件到块、块到副本位置的映射，数据节点负责实际存储。GFS 的 Master 不走数据路径，客户端先问 Master 拿 chunk 位置，再直接读写 Chunkserver；写入时通过 primary 给并发写排序，并复制到多个副本。它适合大文件、顺序读写、日志和离线数据，不适合大量小文件和强 POSIX 随机写。工程上要关注副本放置、故障检测、自动补副本、元数据高可用和热点块治理。
