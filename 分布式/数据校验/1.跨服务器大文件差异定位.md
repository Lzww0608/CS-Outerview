# 跨服务器大文件差异定位

两个异地服务器上有同名文件，内容 99.99% 相同，只想尽快找出不同的几行，核心目标不是“把文件传回来 diff”，而是减少跨地域传输量和比较次数。

## 1. 基本思路

如果文件不大，最直接的方法是在两端分别计算每一行的 hash，再交换 `行号 -> hash` 结果，hash 不同的行就是候选差异行。

如果文件很大，推荐分层比较：

1. 两端按固定大小或固定行数切 chunk。
2. 每个 chunk 计算强 hash，例如 SHA-256、BLAKE3。
3. 先交换 chunk hash，找出不同 chunk。
4. 只对不同 chunk 继续按更小粒度二分或按行 hash。
5. 最后只传输候选行附近的少量内容，确认真实差异。

这样跨地域网络只传 hash 元数据和少量差异内容，避免传完整文件。

## 2. Merkle Tree 方案

Merkle Tree 是分布式文件校验中常用的结构。叶子节点是数据块 hash，父节点是子节点 hash 的 hash。

比较流程：

```text
比较 root hash
  -> root 相同：文件一致
  -> root 不同：比较左右子树 hash
  -> 递归下钻到不同叶子块
  -> 对不同块做行级 hash 或直接传小块 diff
```

优点：

1. 差异很少时，比较次数接近 `O(k log n)`，`k` 是差异块数量。
2. 适合大文件、对象存储、备份校验、跨机房数据一致性检查。
3. 可以缓存中间节点 hash，下次只增量更新变更路径。

注意事项：

1. chunk 边界要稳定，否则插入一行会导致后续所有固定偏移块 hash 变化。
2. 如果文件可能插入、删除行，更适合按“行号范围”或内容定义 chunk，而不是只按字节偏移。
3. hash 可能碰撞，最终确认差异时仍建议拉取原文片段比较。

## 3. rsync 滚动校验方案

如果两份文件有插入、删除，固定块边界会整体错位，此时可以借鉴 rsync 算法：

1. 接收端按块计算弱滚动校验和强 hash，把签名发给发送端。
2. 发送端用滚动窗口扫本地文件，弱校验快速过滤，强 hash 确认匹配块。
3. 找不到匹配的窗口就是差异数据。

rsync 的优势是能处理“中间插入几行导致后续偏移变化”的情况，不会因为固定块错位而认为后面全不同。

常见工具：

```bash
rsync -avzc --dry-run src user@host:/path/
```

其中 `-c` 会按 checksum 判断内容差异，适合修改时间不可信的场景；真正要定位到“哪几行不同”，还需要在差异块上继续做行级比较。

## 4. 行级差异定位示例

如果文件是文本日志、配置或 CSV，且行数基本一致，可以在两端运行：

```bash
awk '{print NR, $0}' file | sha256sum
```

工程实现时不要对整行文本直接跨网传输，可以只传：

```text
line_no, hash(line_content)
```

发现某个行号 hash 不同后，再拉取该行原文确认。如果担心插入/删除导致行号整体错位，可以先用 chunk/Merkle 找到小范围，再在小范围内用 LCS、Myers diff 或普通 `diff -u`。

## 5. 面试回答模板

我不会直接把北京或上海的完整文件传到另一端再 diff。更快的做法是在两端本地计算摘要，先按 chunk 或行号生成 hash，只交换摘要；如果 root 或 chunk hash 相同就跳过，不同的 chunk 再递归细分，最后只传少量候选行确认。文件只有少量行不同且没有插入删除时，行号 hash 就足够；如果有插入删除导致偏移变化，要用 Merkle Tree 配合行级 diff，或者借鉴 rsync 的 rolling checksum 处理块错位。真实系统还要统一编码、换行符、排序规则和 hash 算法，并考虑 hash 碰撞和跨地域 RTT。
