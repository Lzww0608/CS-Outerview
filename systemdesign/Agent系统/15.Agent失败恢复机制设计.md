# Agent 系统失败恢复机制设计

## 1. 问题背景

Agent 系统在执行复杂任务时可能遭遇各种失败：工具调用超时、API 错误、环境异常等。设计有效的失败恢复机制是保障系统可靠性的关键。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Agent 失败场景：                                         │
│                                                             │
│  1. 工具调用失败                                         │
│     • 网络超时                                            │
│     • 服务不可用                                          │
│     • 权限错误                                            │
│                                                             │
│  2. 规划失败                                              │
│     • 找不到有效路径                                      │
│     • 陷入死循环                                          │
│                                                             │
│  3. 执行异常                                              │
│     • 状态不一致                                          │
│     • 资源耗尽                                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 |
|------|------|
| 任务中断 | 执行过程中突然失败 |
| 不可恢复 | 失败后无法继续 |
| 重复失败 | 同样的失败反复发生 |
| 状态损坏 | 部分执行导致数据不一致 |

---

## 3. 影响范围

- 多步骤任务执行
- 长时间运行系统
- 用户体验

## 4. 原因分析

### 4.1 失败分类

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  失败类型分析：                                            │
│                                                             │
│  1. 可重试失败（Transient）                               │
│     • 网络抖动                                            │
│     • 临时过载                                            │
│     • 特点：短时间后可恢复                              │
│                                                             │
│  2. 永久失败（Permanent）                                 │
│     • 权限不足                                            │
│     • 资源不存在                                          │
│     • 特点：无法通过重试解决                              │
│                                                             │
│  3. 超时失败（Timeout）                                   │
│     • 外部服务响应慢                                      │
│     • 死锁                                                │
│     • 特点：需要中断或延长等待                            │
│                                                             │
│  4. 状态失败（State）                                     │
│     • 部分执行导致不一致                                  │
│     • 幂等性问题                                          │
│     • 特点：需要回滚或补偿                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 恢复机制缺失的后果

```python
# 缺乏恢复机制的问题

# 问题 1：任务直接失败
task.execute()  # 失败
# 没有重试，没有恢复，直接返回错误

# 问题 2：无限重试
while True:
    try:
        task.execute()
        break
    except:
        continue  # 可能永远失败

# 问题 3：状态不一致
# 步骤1成功 → 步骤2失败 → 步骤3未执行
# 系统处于不一致状态
```

## 5. 解决方案

### 5.1 分层恢复策略

```python
class LayeredRecoveryStrategy:
    """
    分层恢复策略
    """
    
    def __init__(self):
        self.strategies = [
            RetryStrategy(),           # 第1层：重试
            FallbackStrategy(),        # 第2层：降级
            RollbackStrategy(),        # 第3层：回滚
            EscalationStrategy()       # 第4层：升级
        ]
    
    def recover(self, failure):
        """
        逐层尝试恢复
        """
        for strategy in self.strategies:
            if strategy.can_handle(failure):
                result = strategy.execute(failure)
                if result.success:
                    return result
        return FailureResult(status="unrecoverable")
```

### 5.2 重试策略

```python
class ExponentialBackoffRetry:
    """
    指数退避重试策略
    """
    
    def __init__(self, 
                 max_retries=3,
                 base_delay=1,
                 max_delay=60,
                 exponential_base=2):
        self.max_retries = max_retries
        self.base_delay = base_delay
        self.max_delay = max_delay
        self.exponential_base = exponential_base
    
    def execute(self, operation, *args, **kwargs):
        """
        执行带重试的操作
        """
        last_exception = None
        
        for attempt in range(self.max_retries + 1):
            try:
                return operation(*args, **kwargs)
            
            except TransientError as e:
                last_exception = e
                
                if attempt < self.max_retries:
                    delay = self._calculate_delay(attempt)
                    print(f"Attempt {attempt + 1} failed: {e}. Retrying in {delay}s...")
                    time.sleep(delay)
                else:
                    break
            
            except PermanentError as e:
                # 永久错误，不重试
                raise
        
        raise last_exception
    
    def _calculate_delay(self, attempt):
        """计算退避延迟"""
        delay = self.base_delay * (self.exponential_base ** attempt)
        return min(delay, self.max_delay)
```

### 5.3 状态保存与恢复

```python
class CheckpointManager:
    """
    检查点管理器：支持任务恢复
    """
    
    def __init__(self, storage):
        self.storage = storage
        self.checkpoint_interval = 10  # 每N步保存检查点
    
    def save_checkpoint(self, task_id, state):
        """
        保存检查点
        """
        checkpoint = {
            "task_id": task_id,
            "state": state,
            "timestamp": time.time(),
            "step": state.get("current_step", 0)
        }
        self.storage.save(f"checkpoint_{task_id}", checkpoint)
    
    def load_checkpoint(self, task_id):
        """
        加载检查点
        """
        return self.storage.load(f"checkpoint_{task_id}")
    
    def has_checkpoint(self, task_id):
        """检查是否存在检查点"""
        return self.storage.exists(f"checkpoint_{task_id}")
```

### 5.4 任务执行器

```python
class ResilientTaskExecutor:
    """
    带恢复机制的任务执行器
    """
    
    def __init__(self, config):
        self.config = config
        self.retry_strategy = ExponentialBackoffRetry(**config.retry)
        self.checkpoint_manager = CheckpointManager(config.storage)
        self.circuit_breaker = CircuitBreaker(**config.circuit_breaker)
    
    async def execute(self, task):
        """
        执行任务，带完整恢复机制
        """
        task_id = task.id
        
        # 1. 检查是否有检查点
        if self.checkpoint_manager.has_checkpoint(task_id):
            state = self.checkpoint_manager.load_checkpoint(task_id)
            task.restore(state)
            print(f"Resuming task {task_id} from checkpoint...")
        else:
            task.initialize()
        
        # 2. 执行任务
        while not task.is_completed():
            try:
                # 检查熔断器
                if not self.circuit_breaker.can_execute():
                    await self.circuit_breaker.wait()
                
                # 执行当前步骤
                step_result = await self.execute_step(task)
                
                # 保存检查点
                if task.current_step % self.checkpoint_manager.checkpoint_interval == 0:
                    self.checkpoint_manager.save_checkpoint(task_id, task.get_state())
                
                # 更新步骤
                task.advance(step_result)
            
            except TransientError as e:
                # 可重试错误：重试
                await self.handle_retry(task, e)
            
            except PermanentError as e:
                # 永久错误：降级或放弃
                return await self.handle_permanent_failure(task, e)
            
            except TimeoutError as e:
                # 超时错误：中断或延长
                return await self.handle_timeout(task, e)
        
        return task.get_result()
    
    async def handle_retry(self, task, error):
        """处理可重试错误"""
        max_retries = self.config.retry.get("max_retries", 3)
        
        if task.retry_count < max_retries:
            delay = self._calculate_delay(task.retry_count)
            task.retry_count += 1
            await asyncio.sleep(delay)
        else:
            raise PermanentError(f"Max retries exceeded: {error}")
    
    async def handle_permanent_failure(self, task, error):
        """处理永久失败"""
        # 尝试降级策略
        if task.has_fallback():
            return await task.execute_fallback()
        
        # 记录失败
        task.mark_failed(str(error))
        return None
```

### 5.5 熔断器模式

```python
class CircuitBreaker:
    """
    熔断器：防止级联失败
    """
    
    def __init__(self, 
                 failure_threshold=5,
                 recovery_timeout=60,
                 half_open_max_calls=3):
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.half_open_max_calls = half_open_max_calls
        
        self.state = "closed"  # closed, open, half_open
        self.failure_count = 0
        self.last_failure_time = None
        self.half_open_calls = 0
    
    def can_execute(self):
        """判断是否可以执行"""
        if self.state == "closed":
            return True
        
        if self.state == "open":
            if self._should_attempt_reset():
                self._transition_to_half_open()
                return True
            return False
        
        if self.state == "half_open":
            return self.half_open_calls < self.half_open_max_calls
        
        return False
    
    async def wait(self):
        """等待恢复"""
        if self.state == "open":
            wait_time = self.recovery_timeout - (time.time() - self.last_failure_time)
            if wait_time > 0:
                await asyncio.sleep(wait_time)
    
    def record_success(self):
        """记录成功"""
        if self.state == "half_open":
            self.half_open_calls += 1
            if self.half_open_calls >= self.half_open_max_calls:
                self._transition_to_closed()
        else:
            self.failure_count = 0
    
    def record_failure(self):
        """记录失败"""
        self.failure_count += 1
        self.last_failure_time = time.time()
        
        if self.failure_count >= self.failure_threshold:
            self._transition_to_open()
    
    def _transition_to_open(self):
        """转换到熔断状态"""
        self.state = "open"
        print("Circuit breaker: CLOSED -> OPEN")
    
    def _transition_to_half_open(self):
        """转换到半开状态"""
        self.state = "half_open"
        self.half_open_calls = 0
        print("Circuit breaker: OPEN -> HALF_OPEN")
    
    def _transition_to_closed(self):
        """转换到关闭状态"""
        self.state = "closed"
        self.failure_count = 0
        self.half_open_calls = 0
        print("Circuit breaker: HALF_OPEN -> CLOSED")
```

### 5.6 完整恢复流程

```python
class AgentRecoveryOrchestrator:
    """
    Agent 恢复协调器
    """
    
    def __init__(self):
        self.executor = ResilientTaskExecutor()
        self.saga = SagaManager()
        self.monitor = RecoveryMonitor()
    
    async def run_with_recovery(self, agent, task):
        """
        带完整恢复的执行流程
        """
        try:
            # 1. 开启监控
            self.monitor.start(task.id)
            
            # 2. 执行（带检查点）
            result = await self.executor.execute(task)
            
            # 3. 成功：清理检查点
            self.checkpoint_manager.delete(task.id)
            self.monitor.record_success(task.id)
            
            return result
        
        except RecoverableError as e:
            # 4a. 可恢复错误：尝试恢复
            recovery_plan = self._plan_recovery(e)
            
            if recovery_plan:
                result = await self._execute_recovery(recovery_plan)
                if result:
                    return result
            
            # 恢复失败：回滚
            await self.saga.rollback(task.id)
            self.monitor.record_failure(task.id, "recovery_failed")
            raise
        
        except UnrecoverableError as e:
            # 4b. 不可恢复错误：直接回滚
            await self.saga.rollback(task.id)
            self.monitor.record_failure(task.id, "unrecoverable")
            raise
    
    def _plan_recovery(self, error):
        """规划恢复方案"""
        recovery_strategies = {
            "timeout": [RetryStrategy(), TimeoutExtensionStrategy()],
            "network": [RetryStrategy(), FallbackStrategy()],
            "resource": [RetryStrategy(), ResourceCleanupStrategy()]
        }
        
        strategies = recovery_strategies.get(error.type, [])
        for strategy in strategies:
            if strategy.can_handle(error):
                return strategy.create_plan(error)
        
        return None
```

## 11. 总结

1. **失败分类**：可重试（瞬时）、永久、超时、状态失败
2. **分层策略**：重试 → 降级 → 回滚 → 升级
3. **核心组件**：指数退避重试、检查点管理、熔断器、Saga
4. **实施要点**：失败分类 → 恢复规划 → 执行验证
5. **最佳实践**：幂等性设计、状态检查点、监控告警
