# 强约束工作流中的 LLM 集成策略

## 1. 问题背景

某些 LLM 擅长生成创意内容，但在严格遵循流程方面表现不佳。如何在需要强流程约束的场景中有效利用这类 LLM 是关键挑战。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  问题本质：                                                 │
│                                                             │
│  LLM 能力矩阵：                                          │
│  • 强项：创意生成、文本丰富、上下文理解                  │
│  • 弱项：精确流程遵循、一致性输出、边界控制              │
│                                                             │
│  工作流要求：                                             │
│  • 强约束：每步必须执行特定操作                          │
│  • 可审计：操作可追溯                                    │
│  • 确定性：相同输入产生相同输出                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 |
|------|------|
| 跳过步骤 | LLM 跳过某些流程 |
| 输出不一致 | 相同输入不同输出 |
| 格式漂移 | 偏离预定格式 |
| 创意过度 | 生成过多无关内容 |

---

## 3. 影响范围

- 流程自动化系统
- 合规要求高的场景
- 需要可审计的决策系统

---

## 4. 原因分析

### 4.1 LLM 生成 vs 流程遵循的矛盾

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  矛盾分析：                                                 │
│                                                             │
│  生成模式：                                                 │
│  • 鼓励发散、创造性                                       │
│  • 模糊的指令可能产生意外好结果                          │
│  • 随机性是优点                                           │
│                                                             │
│  流程遵循：                                               │
│  • 要求确定性、精确性                                     │
│  • 明确的边界和约束                                       │
│  • 零容忍的偏差                                           │
│                                                             │
│  根本冲突：生成式训练的奖励函数 vs 流程约束的目标      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 约束失效的原因

```python
# LLM 违反流程的典型场景

# 场景 1：跳过验证步骤
# 要求：先验证输入，再处理
# LLM：直接处理，跳过验证

# 场景 2：擅自增加步骤
# 要求：5步流程
# LLM：增加第6步"创意润色"

# 场景 3：输出格式漂移
# 要求：JSON格式 {"status": "ok", "data": ...}
# LLM：输出 Markdown 或自由文本
```

## 5. 解决方案

### 5.1 方案一：外部流程引擎控制

```python
class ExternalWorkflowEngine:
    """
    外部流程引擎：LLM 只负责单步生成
    """
    
    def __init__(self, llm, workflow_definition):
        self.llm = llm
        self.workflow = workflow_definition
        self.executor = WorkflowExecutor()
    
    def execute(self, initial_input):
        """
        外部引擎控制流程，LLM 只负责单步任务
        """
        context = {"input": initial_input, "steps": []}
        
        for step in self.workflow.steps:
            # 外部引擎决定当前步骤
            if step.type == "llm_generation":
                # 调用 LLM 执行单步
                prompt = self._build_step_prompt(step, context)
                output = self.llm.generate(prompt)
                context["steps"].append({
                    "name": step.name,
                    "input": context.get("previous_output"),
                    "output": output
                })
                context["previous_output"] = output
            
            elif step.type == "validation":
                # 验证步骤（确定性代码）
                is_valid = self._validate(context["previous_output"], step.rules)
                if not is_valid:
                    return {"status": "error", "step": step.name}
            
            elif step.type == "transformation":
                # 数据转换（确定性代码）
                context["previous_output"] = self._transform(
                    context["previous_output"], 
                    step.rules
                )
        
        return {"status": "success", "output": context["previous_output"]}
    
    def _build_step_prompt(self, step, context):
        """构建单步 prompt"""
        return f"""
        任务：{step.description}
        
        要求：
        {step.constraints}
        
        输出格式：
        {step.output_format}
        
        上下文：
        {context.get('previous_output')}
        """
```

### 5.2 方案二：结构化输出 + 验证循环

```python
class ConstrainedLLMWrapper:
    """
    带约束的 LLM 包装器
    """
    
    def __init__(self, llm, output_schema, max_retries=3):
        self.llm = llm
        self.output_schema = output_schema
        self.max_retries = max_retries
        self.validator = SchemaValidator(output_schema)
    
    def generate(self, prompt):
        """
        带验证的生成，确保输出符合约束
        """
        for attempt in range(self.max_retries):
            # 1. 生成
            raw_output = self.llm.generate(prompt)
            
            # 2. 解析
            parsed = self._parse_output(raw_output)
            
            # 3. 验证
            is_valid, errors = self.validator.validate(parsed)
            
            if is_valid:
                return parsed
            
            # 4. 反馈修正
            prompt = self._build_correction_prompt(
                raw_output, errors, attempt
            )
        
        # 超过最大尝试次数，使用降级策略
        return self._fallback(parsed)
    
    def _build_correction_prompt(self, raw_output, errors, attempt):
        """构建修正 prompt"""
        return f"""
        上一轮输出存在问题：
        
        原始输出：
        {raw_output}
        
        验证错误：
        {errors}
        
        这是第 {attempt + 1} 次修正。
        请严格按照以下 schema 输出，不要偏离：
        {self.output_schema}
        
        再次生成：
        """
```

### 5.3 方案三：LLM 作为裁判而非执行者

```python
class JudgePattern:
    """
    裁判模式：LLM 负责判断，确定性代码负责执行
    """
    
    def __init__(self, llm, workflow_steps):
        self.llm = llm
        self.steps = workflow_steps
    
    def execute(self, input_data):
        """
        LLM 作为裁判，决定下一步；确定性代码执行
        """
        context = {"data": input_data, "history": []}
        current_step = 0
        
        while current_step < len(self.steps):
            step = self.steps[current_step]
            
            if step.judge_by == "llm":
                # LLM 判断是否执行此步骤
                decision = self._llm_judge(step, context)
                
                if decision["action"] == "execute":
                    context = self._execute_step(step, context)
                    current_step += 1
                elif decision["action"] == "skip":
                    current_step += 1
                elif decision["action"] == "retry":
                    # 重新执行当前步骤
                    pass
            
            else:
                # 确定性判断
                should_execute = self._code_judge(step, context)
                if should_execute:
                    context = self._execute_step(step, context)
                current_step += 1
        
        return context["result"]
    
    def _llm_judge(self, step, context):
        """LLM 判断是否执行步骤"""
        prompt = f"""
        当前任务：{step.name}
        
        上下文：
        {context}
        
        请判断：
        1. 是否应该执行此步骤？
        2. 如果执行，是否需要修改输入？
        
        输出格式（严格 JSON）：
        {{"action": "execute|skip|retry", "reasoning": "...", "modified_input": ...}}
        """
        
        response = self.llm.generate(prompt)
        return self._parse_json(response)
```

### 5.4 方案四：工具化 + 强制调用

```python
class ToolConstrainedLLM:
    """
    工具化 LLM：强制调用指定工具
    """
    
    def __init__(self, llm, allowed_tools, required_sequence):
        self.llm = llm
        self.tools = {t.name: t for t in allowed_tools}
        self.required_sequence = required_sequence
    
    def execute_workflow(self, initial_input):
        """
        按顺序强制调用工具
        """
        context = {"input": initial_input, "tool_results": {}}
        tool_index = 0
        
        while tool_index < len(self.required_sequence):
            required_tool = self.required_sequence[tool_index]
            
            # 1. 强制调用指定工具
            tool = self.tools[required_tool]
            result = tool.execute(context)
            context["tool_results"][required_tool] = result
            
            # 2. LLM 决定下一步（但必须在剩余工具中选择）
            remaining_tools = self.required_sequence[tool_index + 1:]
            next_tool = self._llm_choose_next(result, remaining_tools)
            
            if next_tool == required_tool:
                # 同一工具再执行一次
                tool_index += 0
            else:
                tool_index = self.required_sequence.index(next_tool)
        
        return context
    
    def _llm_choose_next(self, current_result, allowed_tools):
        """LLM 在允许的工具中选择下一个"""
        prompt = f"""
        当前工具执行结果：
        {current_result}
        
        允许的下一个工具：
        {allowed_tools}
        
        请选择下一个应该调用的工具（只能选一个）：
        """
        
        response = self.llm.generate(prompt)
        return self._parse_tool_name(response)
```

## 11. 总结

1. **问题本质**：生成式 LLM 的随机性 vs 流程约束的确定性
2. **核心思路**：不让 LLM 控制流程，只让它负责单步生成
3. **四大方案**：外部引擎控制、结构化+验证、裁判模式、工具化
4. **推荐实践**：外部流程引擎 + 强验证 + 单步 LLM 调用
5. **实施要点**：明确约束边界、多层验证、降级策略
