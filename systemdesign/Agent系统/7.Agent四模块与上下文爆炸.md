# Agent 四基础模块与上下文爆炸问题

## 1. 问题背景

Agent（智能体）是当前大模型应用的核心形态。理解 Agent 的基础模块以及常见问题（如上下文爆炸）是开发可靠 AI 应用的关键。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Agent 四大基础模块：                                       │
│                                                             │
│  1. 感知（Perception）                                    │
│     → 接收用户输入，理解环境信息                           │
│                                                             │
│  2. 规划（Planning）                                       │
│     → 分析任务，制定执行计划                               │
│                                                             │
│  3. 记忆（Memory）                                         │
│     → 存储历史信息，支持上下文连贯                         │
│                                                             │
│  4. 行动（Action）                                         │
│     → 调用工具，执行具体操作                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 |
|------|------|
| 上下文越来越长 | 对话历史无限增长 |
| 响应越来越慢 | Token 数量爆炸 |
| 回答质量下降 | 模型上下文太长性能退化 |
| 成本急剧上升 | Token 计费持续增长 |
| 模型拒绝输入 | 超出上下文窗口限制 |

---

## 3. 影响范围

- 多轮对话系统
- 复杂任务执行
- 长期记忆需求场景
- 资源受限部署环境

### 5.1 记忆管理系统

```python
class HierarchicalMemory:
    """
    分层记忆管理：解决上下文爆炸
    """
    
    def __init__(self, config):
        self.sensory_memory = []      # 感官记忆（原始输入）
        self.working_memory = []      # 工作记忆（最近 N 轮）
        self.long_term_memory = VectorDB()  # 长期记忆（向量化）
        self.summary_threshold = 10   # 摘要触发阈值
    
    def add_interaction(self, user_input, assistant_output, metadata=None):
        """添加交互到记忆"""
        # 1. 加入感官记忆
        self.sensory_memory.append({
            'user': user_input,
            'assistant': assistant_output,
            'timestamp': time.time(),
            'metadata': metadata
        })
        
        # 2. 加入工作记忆
        self.working_memory.append({
            'user': user_input,
            'assistant': assistant_output
        })
        
        # 3. 超过阈值则摘要并存入长期记忆
        if len(self.working_memory) > self.summary_threshold:
            self.compress_memory()
    
    def compress_memory(self):
        """压缩记忆"""
        # 1. 生成摘要
        summary = self.summarize_recent()
        
        # 2. 存入长期记忆
        self.long_term_memory.add(summary)
        
        # 3. 清空工作记忆，保留摘要
        self.working_memory = [{'type': 'summary', 'content': summary}]
    
    def get_context(self, current_task: str) -> str:
        """
        获取当前上下文
        
        策略：
        1. 从长期记忆检索相关记忆
        2. 拼接工作记忆
        3. 控制在 token 限制内
        """
        # 检索相关长期记忆
        relevant_memories = self.long_term_memory.search(
            query=current_task,
            top_k=3
        )
        
        # 构建上下文
        context_parts = []
        context_parts.append("=== 相关历史记忆 ===")
        context_parts.extend(relevant_memories)
        
        context_parts.append("=== 当前对话 ===")
        context_parts.extend(self.working_memory[-5:])  # 最近 5 轮
        
        return self.truncate_to_limit("\n".join(context_parts))
    
    def summarize_recent(self) -> str:
        """摘要最近对话"""
        recent = "\n".join([
            f"用户: {m['user']}\n助手: {m['assistant']}"
            for m in self.working_memory
        ])
        
        prompt = f"请简洁摘要以下对话的核心内容：\n{recent}"
        summary = llm.generate(prompt)
        
        return summary
```

### 5.2 上下文窗口管理

```python
class ContextWindowManager:
    """
    上下文窗口管理器
    """
    
    def __init__(self, max_tokens: int = 128000):
        self.max_tokens = max_tokens
        self.reserved_tokens = 2000  # 保留空间给回复
        self.available_tokens = max_tokens - self.reserved_tokens
    
    def fit_context(self, components: dict) -> dict:
        """
        智能适配上下文组件
        
        components = {
            'system_prompt': '...',
            'long_term_memory': '...',
            'recent_history': '...',
            'current_task': '...',
            'retrieved_docs': '...'
        }
        
        返回调整后的组件，确保总 token 不超过限制
        """
        # 1. 计算各组件 token 数
        token_counts = {
            k: self.count_tokens(v) for k, v in components.items()
        }
        
        total = sum(token_counts.values())
        
        # 2. 如果超限，按优先级裁剪
        if total > self.available_tokens:
            components = self.smart_truncate(components, token_counts)
        
        return components
    
    def smart_truncate(self, components: dict, token_counts: dict) -> dict:
        """
        智能裁剪策略
        """
        # 优先级：system_prompt > current_task > recent_history > retrieved_docs > long_term_memory
        
        priorities = ['system_prompt', 'current_task', 'recent_history', 
                      'retrieved_docs', 'long_term_memory']
        
        for key in priorities[:-1]:  # 最后一个不裁剪
            if token_counts[key] > 0:
                # 裁剪到当前的一半
                components[key] = self.truncate_tokens(
                    components[key], 
                    token_counts[key] // 2
                )
                token_counts[key] //= 2
                
                if sum(token_counts.values()) <= self.available_tokens:
                    break
        
        return components
    
    def count_tokens(self, text: str) -> int:
        """计算 token 数量"""
        # 简单估算：中文 ~1.5 tokens/字，英文 ~4 chars/token
        return len(text) // 2  # 保守估计
```

### 5.3 主动遗忘机制

```python
class ProactiveForgetting:
    """
    主动遗忘机制
    """
    
    def __init__(self):
        self.importance_scorer = ImportanceScorer()
        self.forgetting_threshold = 0.3
    
    def should_forget(self, memory: MemoryItem) -> bool:
        """
        判断是否应该遗忘
        """
        # 1. 时间衰减
        age_hours = (time.time() - memory.timestamp) / 3600
        time_decay = math.exp(-age_hours / 24)  # 24小时半衰期
        
        # 2. 重要性评分
        importance = self.importance_scorer.score(memory)
        
        # 3. 访问频率
        access_decay = math.exp(-memory.access_count / 10)
        
        # 4. 综合得分
        score = time_decay * importance * (0.5 + 0.5 * access_decay)
        
        return score < self.forgetting_threshold
    
    def forget_unimportant(self, memories: list) -> list:
        """遗忘不重要的记忆"""
        return [m for m in memories if not self.should_forget(m)]
```

### 5.4 连续多工具调用导致 token 越来越多怎么办

多工具 Agent 的上下文增长通常来自三类内容：工具 schema、工具参数和工具结果。连续查日志、搜代码、分页查数据时，如果把所有原始结果都塞回模型，很快会超过上下文窗口，也会让模型被旧结果干扰。

治理思路是把“完整轨迹”和“模型上下文”分开：

```text
Trace Store: 保存完整工具调用、原始结果、日志、分页数据
Context: 只保留当前决策需要的摘要、关键字段、引用 ID
```

具体策略：

1. **工具结果摘要化**：长日志只保留错误码、关键堆栈、时间范围和统计；完整日志放对象存储或 trace store。
2. **资源引用代替全文**：返回 `artifact_id/path/url`，需要时再读局部内容，不把大文件一次塞入 prompt。
3. **分页和字段裁剪**：列表工具必须支持 `limit/cursor/fields`，默认只返回摘要字段。
4. **Observation 去重**：同一工具、同一参数、同一结果 hash 不重复注入上下文。
5. **滚动任务状态**：把多轮工具调用压缩成 `current_facts/open_questions/next_action`，而不是保留每一步原文。
6. **按优先级裁剪**：用户硬性约束、当前目标、最新工具证据优先；旧的中间推理和失败尝试可以摘要或移出。
7. **设置预算**：限制最大工具次数、单工具最大返回 token、总运行 token 和最大 wall time。
8. **错误语义结构化**：工具失败时只注入错误码、是否可重试、trace id 和下一步建议，不粘贴整段异常日志。

一个可落地的上下文结构可以是：

```json
{
  "task_state": {
    "goal": "定位配置热更新失败原因",
    "current_step": "检查 watcher 是否收到 rename 事件",
    "open_questions": ["是否读到了半写入文件"]
  },
  "facts": [
    {"source": "tool:read_log:tr_1", "summary": "15:03 reload failed: YAML parse error"},
    {"source": "tool:read_file:tr_2", "summary": "配置发布使用直接覆盖写入，不是 temp + rename"}
  ],
  "artifacts": [
    {"id": "log_123", "type": "raw_log", "path": "/tmp/reload.log"}
  ]
}
```

面试里可以概括：连续工具调用时，完整 trace 留给系统审计和回放，模型上下文只保留摘要事实和引用；通过分页、裁剪、去重、滚动摘要和预算控制，把 token 增长从线性累积变成受控窗口。

## 6. 可选方案对比

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| 固定窗口 | 只保留最近 N 轮 | 简单 | 可能丢失重要历史 |
| 摘要压缩 | LLM 生成摘要 | 保留核心信息 | 有信息损失 |
| 语义检索 | 只检索相关内容 | 精准 | 实现复杂 |
| 分层记忆 | 多级存储和检索 | 平衡 | 架构复杂 |
| 主动遗忘 | 重要性评分过滤 | 智能 | 评分可能不准 |

## 11. 总结

1. **Agent 四模块**：感知（理解输入）、规划（制定策略）、记忆（存储信息）、行动（执行操作）
2. **上下文爆炸**：记忆无限累积、任务链式扩展、RAG 结果叠加导致 token 爆炸
3. **解决方案**：分层记忆（感官/工作/长期）+ 上下文窗口管理 + 主动遗忘机制
4. **推荐架构**：工作记忆窗口 + 向量化长期记忆 + 智能上下文裁剪
5. **核心原则**：在有限上下文中保留最相关的信息，平衡历史信息和响应质量
