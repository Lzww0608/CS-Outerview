# 19. DeFi Agent 幻觉风险控制与安全机制

## 1. 问题背景

LLM 幻觉（Hallucination）是生成式 AI 的固有特性，可能导致 DeFi Agent 做出错误的链上操作决策，如错误的代币地址、错误的合约参数、错误的价格判断，造成不可逆的资金损失。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  LLM 幻觉在 DeFi 中的危害：                                 │
│                                                             │
│  正常情况：                                                 │
│  Agent: "检测到 Uniswap ETH/USDC 套利机会"                │
│  实际操作: swap(ETH → USDC) → swap(USDC → ETH)           │
│  结果: 盈利                                                │
│                                                             │
│  幻觉情况：                                                 │
│  Agent: "检测到套利机会"                                   │
│  幻觉: 将 WETH 地址识别为 USDT                             │
│  实际操作: swap(ETH → 错误代币)                            │
│  结果: 资金损失！                                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 |
|------|------|
| 地址幻觉 | 合约地址错误 |
| 参数幻觉 | 金额、滑点、gas 错误 |
| 逻辑幻觉 | 交易逻辑错误 |
| 价格幻觉 | 价格数据过时或错误 |

---

## 3. 影响范围

- DeFi 套利 Agent
- 流动性管理 Agent
- 自动理财 Agent
- 量化交易 Bot

## 4. 原因分析

### 4.1 幻觉类型分析

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  LLM 幻觉来源：                                            │
│                                                             │
│  1. 训练数据过时                                          │
│     • 模型知识截止日期后的事件                            │
│     • 新合约地址、新的协议                                │
│                                                             │
│  2. 上下文窗口限制                                        │
│     • 无法感知完整的市场状态                              │
│     • 可能遗忘关键信息                                    │
│                                                             │
│  3. 概率生成特性                                          │
│     • 高温采样可能生成错误内容                            │
│     • 低置信度答案被自信输出                              │
│                                                             │
│  4. 外部数据依赖                                          │
│     • 错误的价格预言机数据                                │
│     • 过时的知识库信息                                    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 5.3 模拟执行验证

```typescript
// Layer 2: 模拟执行验证

class SimulationValidator {
    private bundler: FlashbotsBundler;
    
    async validate(tx: Transaction): Promise<SimulationResult> {
        try {
            // 1. 模拟执行
            const simulation = await this.bundler.simulate(tx);
            
            // 2. 检查模拟是否成功
            if (!simulation.success) {
                return {
                    valid: false,
                    reason: `Simulation failed: ${simulation.error}`,
                    gasUsed: 0
                };
            }
            
            // 3. 验证结果合理性
            const expectedOutput = await this.calculateExpectedOutput(tx);
            const actualOutput = simulation.output;
            
            if (!this.isWithinTolerance(expectedOutput, actualOutput)) {
                return {
                    valid: false,
                    reason: "Output mismatch - possible slippage or price change",
                    expected: expectedOutput,
                    actual: actualOutput
                };
            }
            
            return {
                valid: true,
                gasUsed: simulation.gasUsed,
                output: simulation.output
            };
            
        } catch (error) {
            return {
                valid: false,
                reason: `Simulation error: ${error.message}`
            };
        }
    }
    
    private isWithinTolerance(expected: bigint, actual: bigint, tolerance: number = 0.01): boolean {
        const diff = expected > actual 
            ? expected - actual 
            : actual - expected;
        const ratio = Number(diff) / Number(expected);
        return ratio <= tolerance;
    }
}
```

### 5.4 小额试单机制

```typescript
// Layer 3: 小额试单

class TrialExecutor {
    private readonly TRIAL_AMOUNT_RATIO = 0.01;  // 1%
    private readonly MIN_TRIAL_GAS = 0.001;       // ETH
    
    async executeWithTrial(
        agentDecision: AgentDecision,
        walletBalance: bigint
    ): Promise<ExecutionResult> {
        
        const trialAmount = this.calculateTrialAmount(walletBalance);
        
        // 1. 执行小额试单
        const trialTx = {
            ...agentDecision.tx,
            value: trialAmount
        };
        
        const trialResult = await this.blockchain.sendTransaction(trialTx);
        
        // 2. 验证试单结果
        if (!trialResult.success) {
            return {
                success: false,
                reason: "Trial transaction failed",
                error: trialResult.error
            };
        }
        
        // 3. 等待确认
        await trialResult.wait(1);
        
        // 4. 检查结果符合预期
        const resultCheck = await this.verifyTrialResult(trialResult, trialAmount);
        
        if (!resultCheck.valid) {
            return {
                success: false,
                reason: "Trial result validation failed",
                details: resultCheck.reason
            };
        }
        
        // 5. 执行正式交易
        return await this.executeFullTransaction(agentDecision);
    }
    
    private async verifyTrialResult(
        result: TransactionReceipt,
        expectedAmount: bigint
    ): Promise<ValidationResult> {
        
        // 检查实际收到的代币数量
        const actualReceived = await this.getReceivedAmount(result);
        
        // 考虑滑点后的最低期望
        const minExpected = expectedAmount * 0.95n;  // 5% 容差
        
        if (actualReceived < minExpected) {
            return {
                valid: false,
                reason: `Received ${actualReceived}, expected at least ${minExpected}`
            };
        }
        
        return { valid: true };
    }
}
```

### 5.5 实时价格验证

```typescript
// 价格验证中间层

class PriceValidator {
    private priceOracles: PriceOracle[];
    private readonly MAX_PRICE_DEVIATION = 0.02;  // 2%
    
    async validatePrice(
        tokenIn: string,
        tokenOut: string,
        amountIn: bigint,
        expectedAmountOut: bigint
    ): Promise<PriceValidationResult> {
        
        // 1. 获取多个预言机价格
        const prices = await Promise.all(
            this.priceOracles.map(o => o.getPrice(tokenIn, tokenOut))
        );
        
        // 2. 计算共识价格（去除极端值）
        const consensusPrice = this.calculateConsensusPrice(prices);
        
        // 3. 计算预期输出
        const expectedOutput = this.calculateExpectedOutput(
            amountIn,
            consensusPrice
        );
        
        // 4. 检查偏差
        const deviation = Math.abs(
            Number(expectedAmountOut - expectedOutput) / Number(expectedOutput)
        );
        
        if (deviation > this.MAX_PRICE_DEVIATION) {
            return {
                valid: false,
                reason: `Price deviation ${deviation} exceeds limit ${this.MAX_PRICE_DEVIATION}`,
                consensusPrice,
                providedPrice: expectedAmountOut
            };
        }
        
        return {
            valid: true,
            consensusPrice,
            deviation
        };
    }
    
    private calculateConsensusPrice(prices: number[]): number {
        // 去除最高和最低
        const sorted = [...prices].sort();
        const trimmed = sorted.slice(1, -1);
        
        // 取平均值
        return trimmed.reduce((a, b) => a + b, 0) / trimmed.length;
    }
}
```

## 6. 可选方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| 白名单验证 | 简单有效 | 维护成本高 | 代币地址 |
| 模拟执行 | 准确验证 | 增加延迟 | 所有交易 |
| 小额试单 | 实战验证 | 额外 gas | 大额交易 |
| 多预言机 | 防预言机攻击 | 复杂度高 | 价格敏感 |
| 规则引擎 | 快速拦截 | 需人工规则 | 异常检测 |

### 8.2 核心修改逻辑

```typescript
// 核心修改逻辑：

// 1. Agent 决策后添加验证层
class SecureDeFiAgent {
    async executeDecision(decision: AgentDecision): Promise<Result> {
        // 风险分级
        const riskLevel = this.classifyRisk(decision);
        
        // 根据风险等级选择验证
        if (riskLevel === 'LOW') {
            return await this.fastPath(decision);
        } else if (riskLevel === 'MEDIUM') {
            return await this.moderatePath(decision);
        } else {
            return await this.securePath(decision);
        }
    }
    
    // 低风险：白名单 + 直接执行
    private async fastPath(decision: AgentDecision): Promise<Result> {
        await this.addressValidator.validate(decision.target);
        return await this.blockchain.sendTransaction(decision.tx);
    }
    
    // 中风险：添加模拟
    private async moderatePath(decision: AgentDecision): Promise<Result> {
        await this.addressValidator.validate(decision.target);
        await this.priceValidator.validate(...);
        await this.simulationValidator.validate(decision.tx);
        return await this.blockchain.sendTransaction(decision.tx);
    }
    
    // 高风险：人工审批
    private async securePath(decision: AgentDecision): Promise<Result> {
        await this.requireApproval(decision);
        return await this.executeWithTrial(decision);
    }
}
```

## 11. 总结

1. **幻觉来源**：训练数据过时、上下文限制、概率生成特性
2. **防护核心**：多层验证 + 渐进式执行 + 实时监控
3. **分级策略**：基于金额的风险分级，不同级别不同验证
4. **关键措施**：地址白名单、模拟执行、小额试单、价格验证
5. **最佳实践**：宁可错杀不可放过，安全性优先于效率
