# Agent 多源上下文优先级处理

## 1. 问题背景

Agent 在回答用户问题时，可能需要整合多种信息源：知识库（KB）、外部 API 调用、用户历史偏好。如何合理处理这三类上下文的优先级直接影响回答质量。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Agent 多源上下文：                                        │
│                                                             │
│  用户问题 ─┬─► 知识库（KB）                             │
│            ├─► 外部 API                                  │
│            └─► 用户偏好（History）                       │
│                                                             │
│  核心问题：这三类信息如何组织优先级？                    │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 |
|------|------|
| 上下文冲突 | KB 说 A，API 说 B，用户偏好说 C |
| Token 爆炸 | 所有信息塞入上下文超限 |
| 响应延迟 | API 调用阻塞生成 |
| 回答不一致 | 三类信息相互矛盾 |

---

## 3. 影响范围

- 智能客服系统
- 个人助手应用
- 企业知识管理系统

## 5. 解决方案

### 5.1 方案一：规则驱动的优先级

```python
class RuleBasedPrioritizer:
    """
    基于规则的优先级处理
    """
    
    def __init__(self):
        # 优先级配置：数字越小优先级越高
        self.priority_rules = {
            # 价格相关：API > 知识库 > 用户偏好
            "price": {"external_api": 1, "knowledge_base": 2, "user_preference": 3},
            
            # 事实性问答：知识库 > API > 用户偏好
            "fact": {"knowledge_base": 1, "external_api": 2, "user_preference": 3},
            
            # 个性化推荐：用户偏好 > API > 知识库
            "personalized": {"user_preference": 1, "external_api": 2, "knowledge_base": 3},
        }
    
    def determine_priority(self, question_type):
        """根据问题类型确定优先级"""
        return self.priority_rules.get(question_type, {
            "knowledge_base": 1,
            "external_api": 2,
            "user_preference": 3
        })
    
    def merge_contexts(self, question, contexts, question_type):
        """
        合并多源上下文
        
        Args:
            question: 用户问题
            contexts: {"kb": [], "api": [], "history": []}
            question_type: 问题类型
        """
        priority = self.determine_priority(question_type)
        
        # 按优先级排序
        sorted_sources = sorted(priority.items(), key=lambda x: x[1])
        
        merged_context = {
            "facts": [],        # 事实信息
            "preferences": [],  # 用户偏好
            "metadata": {}       # 元信息
        }
        
        for source, _ in sorted_sources:
            if source == "knowledge_base":
                merged_context["facts"].extend(contexts.get("kb", []))
            elif source == "external_api":
                merged_context["facts"].extend(contexts.get("api", []))
            elif source == "user_preference":
                merged_context["preferences"].extend(contexts.get("history", []))
        
        return merged_context
```

### 5.2 方案二：置信度加权融合

```python
class ConfidenceWeightedFusion:
    """
    基于置信度的加权融合
    """
    
    def __init__(self):
        self.source_weights = {
            "knowledge_base": 0.3,
            "external_api": 0.4,
            "user_preference": 0.3
        }
    
    def fuse(self, contexts):
        """
        加权融合多源信息
        """
        fused_result = {}
        
        # 1. 为每个信息计算综合置信度
        for source, items in contexts.items():
            weight = self.source_weights.get(source, 0.33)
            
            for item in items:
                item_id = item.get("id")
                if item_id not in fused_result:
                    fused_result[item_id] = {
                        "content": item.get("content"),
                        "confidence": 0,
                        "sources": []
                    }
                
                # 更新置信度
                item_conf = item.get("confidence", 1.0)
                fused_result[item_id]["confidence"] += weight * item_conf
                fused_result[item_id]["sources"].append(source)
        
        # 2. 归一化
        for item_id, result in fused_result.items():
            result["confidence"] /= len(result["sources"])
        
        # 3. 按置信度排序
        sorted_results = sorted(
            fused_result.items(),
            key=lambda x: x[1]["confidence"],
            reverse=True
        )
        
        return [item for _, item in sorted_results]
```

### 5.3 方案三：分层处理架构

```python
class HierarchicalContextProcessor:
    """
    分层处理架构
    """
    
    def __init__(self, llm):
        self.llm = llm
        self.kb_retriever = KnowledgeBaseRetriever()
        self.api_caller = APIClient()
        self.history_manager = HistoryManager()
    
    async def process(self, question, user_id):
        """
        分层处理用户问题
        """
        # Layer 1: 快速获取用户偏好（并行）
        user_preference_task = self.history_manager.get_preference(user_id)
        
        # Layer 2: 根据问题类型决定是否调用 API（串行）
        need_api = self.classify_needs_api(question)
        api_result = None
        if need_api:
            api_result = await self.api_caller.call(question)
        
        # Layer 3: 检索知识库（可并行）
        kb_results = await self.kb_retriever.search(question)
        
        # Layer 4: 等待用户偏好并合并
        user_pref = await user_preference_task
        
        # Layer 5: 构建最终上下文
        final_context = self.build_context(question, {
            "kb": kb_results,
            "api": api_result,
            "history": user_pref
        })
        
        return final_context
    
    def classify_needs_api(self, question):
        """判断是否需要调用 API"""
        api_keywords = ["价格", "库存", "实时", "当前", "现在"]
        return any(kw in question for kw in api_keywords)
    
    def build_context(self, question, contexts):
        """构建最终上下文"""
        # 1. 根据问题类型确定结构
        context_template = self.llm.generate(f"""
        根据问题确定上下文结构：
        问题：{question}
        """)
        
        # 2. 按模板填充信息
        context = {
            "question_summary": self.summarize(question),
            "factual_info": self.merge_facts(contexts),
            "personalization": contexts.get("history", []),
            "metadata": {
                "sources": list(contexts.keys()),
                "freshness": self.get_freshness(contexts)
            }
        }
        
        return context
```

### 5.4 方案四：LLM 智能编排

```python
class LLMOrchestratedContext:
    """
    LLM 驱动的上下文编排
    """
    
    SYSTEM_PROMPT = """
    你是一个上下文编排专家。用户会提供来自不同来源的信息，
    请根据问题的核心意图，智能地编排这些信息。
    
    编排原则：
    1. 优先使用最相关的信息
    2. 冲突时以时效性高的为准
    3. 尊重用户偏好但不违背事实
    4. 上下文过长时进行摘要
    """
    
    def __init__(self, llm):
        self.llm = llm
    
    def orchestrate(self, question, contexts):
        """
        LLM 智能编排上下文
        """
        # 1. 构造编排指令
        instruction = self.construct_instruction(question, contexts)
        
        # 2. 调用 LLM 编排
        orchestration = self.llm.generate(instruction)
        
        # 3. 解析编排结果
        return self.parse_orchestration(orchestration)
    
    def construct_instruction(self, question, contexts):
        """构造编排指令"""
        kb_text = "\n".join([
            f"- [知识库] {item['content']}" 
            for item in contexts.get("kb", [])
        ])
        
        api_text = "\n".join([
            f"- [API] {item['content']}"
            for item in contexts.get("api", [])
        ])
        
        history_text = "\n".join([
            f"- [用户偏好] {item['content']}"
            for item in contexts.get("history", [])
        ])
        
        return f"""
        问题：{question}
        
        可用信息：
        知识库信息：
        {kb_text or "（无）"}
        
        API 信息：
        {api_text or "（无）"}
        
        用户历史偏好：
        {history_text or "（无）"}
        
        请按以下格式输出编排后的上下文：
        - 优先级顺序
        - 每条信息的来源和置信度
        - 最终采用的答案要点
        """
```

## 11. 总结

1. **核心挑战**：三类信息（KB/API/History）如何合理组合
2. **优先级策略**：规则驱动（简单）、置信度加权（量化）、分层处理（解耦）、LLM 编排（智能）
3. **推荐方案**：规则驱动 + 置信度加权组合使用
4. **关键设计**：问题分类 → 并行获取 → 置信度融合 → 上下文构建
5. **优化方向**：异步并行、动态 Token 分配、透明来源说明
