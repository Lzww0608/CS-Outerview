# 1. 亿级实时推荐系统

推荐系统后端要解决的是：在海量用户、物品和行为数据下，以低延迟返回个性化候选，并持续根据用户反馈更新排序效果。面试里要先把链路拆成召回、粗排、精排、重排、反馈闭环和特征平台。

## 1. 核心链路

```text
请求进入
  -> 用户画像 / 上下文特征
  -> 多路召回
  -> 去重和过滤
  -> 粗排
  -> 精排
  -> 重排和业务规则
  -> 返回结果
  -> 曝光/点击/停留/转化反馈
```

常见组件：

1. **特征存储**：用户长期兴趣、短期行为、物品画像、上下文特征。
2. **召回服务**：协同过滤、向量 ANN、标签召回、热门召回、社交召回。
3. **排序服务**：模型推理，按点击率、转化率、时长、收益等目标打分。
4. **规则服务**：去重、频控、黑名单、内容安全、多样性。
5. **实时反馈链路**：日志 -> MQ/Kafka -> 实时计算 -> 特征更新。

## 2. 冷启动怎么解决

冷启动分用户冷启动和物品冷启动。

用户冷启动：

1. 注册时收集少量兴趣选择或地域、设备、入口场景。
2. 使用热门内容、编辑精选、同城同年龄段趋势做兜底。
3. 前几次交互提高探索比例，快速收集点击、停留、跳过等反馈。
4. 利用相似人群画像做迁移，例如新用户落入某个 cohort。

物品冷启动：

1. 用内容理解生成初始标签、embedding 和质量分。
2. 给新物品小流量探索，观察点击率、完播率、负反馈。
3. 按作者、主题、类目或相似物品做关联召回。
4. 设置探索预算和安全阈值，避免低质新内容大规模曝光。

## 3. 探索与利用

利用（exploitation）是把当前模型认为最优的内容推给用户，保证短期效果；探索（exploration）是给不确定内容一定曝光，收集反馈，避免系统陷入局部最优。

常见方法：

1. **ε-greedy**：大部分流量走最优结果，小比例随机探索。
2. **UCB**：根据均值和置信区间选择不确定但潜力高的内容。
3. **Thompson Sampling**：从后验分布采样，天然平衡探索和利用。
4. **多样性重排**：在最终列表里控制类目、作者、主题分布。

真实系统会给探索设置边界：内容安全、质量阈值、人群隔离、频控和最大流量比例。

## 4. 如何保证实时性

1. 行为日志实时写入 Kafka。
2. Flink/Spark Streaming 更新短期兴趣、计数、热门榜、负反馈特征。
3. 特征写入 Redis/HBase/在线特征库，排序服务毫秒级读取。
4. 模型可以离线训练、近线增量、在线校准组合使用。
5. 热门和召回索引用增量构建，避免全量重建造成延迟。

实时性也要分层：用户刚点过的内容应立即去重；短期兴趣可以秒级更新；复杂模型参数可以分钟级或小时级更新。

## 5. 架构取舍

1. **低延迟**：召回和排序要有超时预算，慢召回可降级。
2. **高可用**：每路召回独立失败不影响整体，保底热门兜底。
3. **可解释和可控**：推荐结果要能追踪来源、特征和规则命中。
4. **反作弊和内容安全**：刷量、低质内容、敏感内容要在召回前后都能过滤。
5. **实验平台**：A/B 实验是推荐迭代的核心，指标要看短期点击和长期留存。

## 6. 面试回答模板

亿级推荐后端我会拆成多路召回、粗排、精排、重排和反馈闭环。用户画像、物品画像和实时行为进入特征平台；召回阶段用热门、标签、协同过滤、向量 ANN 等多路拿候选；排序阶段用模型打分，再做去重、频控、多样性和安全过滤。冷启动靠热门兜底、内容标签、相似人群和小流量探索；探索与利用可以用 ε-greedy、UCB 或 Thompson Sampling；实时性靠 Kafka/Flink 更新短期特征和热门索引，关键反馈秒级生效，模型参数则按成本做分钟级或小时级更新。
