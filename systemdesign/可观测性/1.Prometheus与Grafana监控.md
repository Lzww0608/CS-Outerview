# 1. Prometheus 与 Grafana 监控

Prometheus 是时序指标采集和查询系统，Grafana 是可视化展示和告警看板工具。二者常用于服务监控、基础设施监控、SLO 看板和故障定位。

## 1. Prometheus 基本模型

Prometheus 以指标为中心：

```text
http_requests_total{service="api", method="GET", code="200"} 1024
```

核心组件：

1. **Exporter / Instrumentation**：暴露 `/metrics` 指标接口。
2. **Prometheus Server**：按配置周期性抓取指标并存储时序数据。
3. **PromQL**：查询和聚合时序数据。
4. **Alertmanager**：接收告警规则触发结果，做分组、抑制和通知。
5. **Grafana**：连接 Prometheus 数据源，展示仪表盘。

## 2. 拉模式和推模式

Prometheus 主要采用 pull 模式，也支持通过 Pushgateway 间接接收短生命周期任务的指标。

| 模式 | 方式 | 优点 | 缺点 | 适用场景 |
| --- | --- | --- | --- | --- |
| Pull | Prometheus 主动抓 `/metrics` | 易发现目标、可判断目标是否存活、统一控制采集频率 | 目标需要能被 Prometheus 访问 | 常驻服务、K8s Pod、节点监控 |
| Pushgateway | 任务把指标推到 Pushgateway，Prometheus 再抓它 | 适合短任务退出前上报 | 不适合常驻服务，指标生命周期容易残留 | cron、batch job |
| remote_write | Prometheus 把数据推到远端存储 | 扩展长期存储和集中查询 | 不是服务主动推指标给 Prometheus | Thanos、Mimir、VictoriaMetrics |

公司内部常驻服务一般优先选 pull：Prometheus 可以结合服务发现自动发现实例，并且“抓不到”本身就是实例异常信号。push 更适合短生命周期任务、跨网络隔离或无法被访问的场景。

## 3. 常见指标设计

面试里可以按 RED/USE 思路讲：

1. **请求类 RED**：Rate、Errors、Duration，例如 QPS、错误率、P95/P99。
2. **资源类 USE**：Utilization、Saturation、Errors，例如 CPU、内存、磁盘、网络、fd。
3. **依赖类指标**：数据库慢查询、Redis 命中率、MQ 堆积、RPC 超时率。
4. **业务指标**：登录成功率、下单量、支付成功率、库存扣减失败数。

指标类型：

1. Counter：只增不减，例如请求总数。
2. Gauge：可增可减，例如当前连接数。
3. Histogram：桶统计，适合延迟分布和分位数估算。
4. Summary：客户端计算分位数，跨实例聚合不如 Histogram 方便。

## 4. Grafana 怎么用

Grafana 负责把 PromQL 查询结果组织成面板：

1. 服务概览：QPS、错误率、P99、实例数。
2. 资源面板：CPU、内存、GC、goroutine 数、fd 数。
3. 依赖面板：下游 RPC、数据库、缓存、MQ。
4. 告警面板：按服务、等级、影响范围展示。

真实排障时通常从“错误率和延迟是否升高”开始，再下钻到实例、接口、下游依赖和资源指标，最后结合日志与 trace 定位代码路径。

## 5. 易错点

1. label 不能放用户 ID、订单 ID 这类高基数字段，否则会打爆时序库。
2. Counter 要用 `rate()` 或 `increase()` 看增长率，不能直接看绝对值。
3. Histogram 分桶要按业务延迟设计，桶太粗看不出尾延迟，桶太细会增加时序数量。
4. Pushgateway 不适合替代常驻服务的 pull 采集。
5. 监控要同时看现象指标和原因指标，只看 CPU 或只看 QPS 都不够。

## 6. 面试回答模板

Prometheus 负责采集和存储时序指标，Grafana 负责可视化。服务通过 `/metrics` 暴露 Counter、Gauge、Histogram 等指标，Prometheus 按服务发现结果周期性 pull，Grafana 用 PromQL 展示 QPS、错误率、P99、资源和依赖状态。Prometheus 默认推荐 pull，因为能统一控制采集并判断实例是否存活；push 通常通过 Pushgateway 处理短生命周期任务。线上设计要避免高基数 label，并围绕 RED/USE、业务指标、告警和日志 trace 联动排查。
