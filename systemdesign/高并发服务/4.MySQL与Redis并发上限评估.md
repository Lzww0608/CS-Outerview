# 4. MySQL 与 Redis 并发上限评估

面试问“MySQL 和 Redis 并发上限是多少”，不要直接报一个固定数字。并发上限取决于机器规格、数据模型、请求类型、连接数、网络、慢查询、持久化配置和可接受延迟。更合理的回答是说明如何评估、瓶颈在哪里、怎么扩展。

## 1. 先区分指标

常见指标：

1. **QPS/TPS**：每秒请求数或事务数。
2. **并发连接数**：同时保持的客户端连接数量。
3. **P95/P99 延迟**：高并发下是否仍满足响应时间。
4. **CPU 使用率**：用户态、内核态、软中断。
5. **内存和命中率**：Buffer Pool 命中率、Redis 内存使用率。
6. **I/O**：磁盘 await、iops、redo/binlog fsync、AOF fsync。
7. **锁等待**：InnoDB 行锁、元数据锁、Redis 热 key 阻塞。

并发上限不是“能连多少连接”，而是在错误率和 P99 延迟可接受时能稳定处理多少业务请求。

## 2. MySQL 的上限受什么影响

MySQL 更容易受这些因素限制：

1. SQL 是否走索引，扫描行数是否可控。
2. 单行热点更新，例如库存、计数、余额。
3. 事务大小和锁持有时间。
4. Buffer Pool 命中率和磁盘随机 I/O。
5. redo log、binlog 刷盘策略。
6. 连接数过高导致线程调度和内存开销增加。
7. 排序、临时表、回表和大分页。

扩展方式：

1. 建联合索引、覆盖索引，减少扫描和回表。
2. 缩短事务，避免事务内远程调用。
3. 热点行拆分，例如库存分桶、计数分片。
4. 读写分离，把只读流量分摊到从库。
5. 分库分表，降低单库单表容量和写入压力。
6. 用缓存、异步化、批量写削减数据库峰值。

## 3. Redis 的上限受什么影响

Redis 单实例命令执行通常在主线程，吞吐很高，但不是无限：

1. 命令复杂度：`GET/SET/INCR` 和大 `ZRANGE/HGETALL/KEYS` 成本不同。
2. value 大小：大 key 会拉高网络和序列化开销。
3. 热 key：单个 key 被集中访问会形成 CPU 或网络热点。
4. 持久化：AOF/RDB、fork、fsync 会影响延迟。
5. 网络带宽和包量：小包 QPS 高时可能受 PPS 和软中断限制。
6. Lua 脚本：脚本执行期间会阻塞其他命令，不能写长脚本。
7. 集群跨 slot：多 key 命令、事务和 Lua 会受限制。

扩展方式：

1. Cluster 分片，把不同 key 分散到多个主节点。
2. 热 key 拆分或本地缓存。
3. 大 key 拆分，避免一次读写过大对象。
4. 使用 pipeline 或批量接口降低 RTT 成本。
5. 读多场景可用副本读，但要接受复制延迟。
6. 对关键写路径保留数据库或强一致服务兜底。

## 4. MySQL 和 Redis 的关系

Redis 抗不住时，不能简单让所有请求回源 MySQL，否则缓存故障会放大成数据库故障。高并发系统要做：

1. Redis 调用短超时和熔断。
2. 本地缓存保存热点只读数据和降级值。
3. 限流保护 MySQL。
4. 核心写链路 fail closed，避免超卖和重复处理。
5. 用 MQ 异步削峰，让 MySQL 处理可控流量。

Redis Cluster 只解决容量和部分吞吐问题，不会自动消除缓存穿透、击穿、雪崩、热 key 和数据一致性问题。穿透仍要靠布隆过滤器、空值缓存、参数校验和风控；击穿仍要靠互斥重建、singleflight、逻辑过期和限流。

## 5. 如何压测

压测要模拟真实链路，而不是只跑裸 `redis-benchmark` 或简单 `sysbench`。

步骤：

1. 明确目标：峰值 QPS、P99、错误率、库存正确性或下单成功率。
2. 构造真实数据规模和热点分布。
3. 分别压测单组件和完整链路。
4. 观察 CPU、内存、网络、磁盘、慢 SQL、Redis latency、连接池、线程池。
5. 找到瓶颈后只改一个变量，再复测对比。

## 6. 面试回答模板

我不会直接说 MySQL 或 Redis 固定能抗多少并发，因为它取决于请求类型、数据规模、机器规格和延迟目标。MySQL 的瓶颈通常在索引、锁、事务、Buffer Pool、redo/binlog 刷盘和热点行；Redis 的瓶颈通常在单线程命令执行、大 key、热 key、Lua、网络和持久化。评估时要用真实数据和热点分布压测，看 QPS、P99、CPU、内存、I/O、慢 SQL 和 Redis latency。扩展上，MySQL 做索引优化、缩短事务、读写分离、分库分表；Redis 做 Cluster 分片、热 key 拆分、本地缓存和 pipeline。但 Redis 集群不解决穿透、击穿和一致性问题，这些仍要靠业务设计兜底。
