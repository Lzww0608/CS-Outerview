# 单点登录（SSO）原理与实现详解

## 1. 问题背景

单点登录（Single Sign-On，SSO）是一种身份认证机制，用户只需登录一次，即可在多个相互信任的应用系统间访问，无需重复输入凭证。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  SSO 核心价值：                                            │
│                                                             │
│  • 用户体验：一次登录，多系统访问                          │
│  • 安全提升：减少密码暴露风险                              │
│  • 效率提升：IT 运维管理简化                              │
│  • 成本降低：减少密码重置请求                              │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 | 影响 |
|------|------|------|
| 多系统需多次登录 | 每个系统独立登录 | 用户体验差 |
| 密码管理混乱 | 用户设置相同密码或记在备忘录 | 安全隐患 |
| 账号难以统一管理 | 各系统独立维护用户 | 运维成本高 |
| 权限无法同步 | 用户权限变更需逐系统修改 | 数据不一致 |

## 4. 原因分析

### 4.1 技术原因

- 各系统独立维护会话，无跨域信任机制
- 缺少统一身份提供者（Identity Provider）
- 会话 Cookie 无法跨域共享

### 4.2 架构原因


## 5. 解决方案

### 5.1 SSO 核心组件

| 组件 | 作用 |
|------|------|
| IdP (Identity Provider) | 身份提供者，负责用户认证 |
| SP (Service Provider) | 服务提供者，依赖 IdP 验证身份 |
| 浏览器 | 充当 IdP 和 SP 之间的通信桥梁 |
| Token/JWT | 身份凭证，跨域传递用户信息 |

### 5.2 认证流程

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  SSO 认证流程：                                           │
│                                                             │
│  1. 用户访问系统 A，未登录                                │
│  2. 系统 A 重定向到 IdP                                  │
│  3. IdP 显示登录页面                                    │
│  4. 用户输入凭证，IdP 验证通过                          │
│  5. IdP 生成 Ticket，重定向回系统 A                     │
│  6. 系统 A 验证 Ticket，建立会话                          │
│  7. 用户再访问系统 B                                     │
│  8. 系统 B 发现未登录，重定向到 IdP                      │
│  9. IdP 发现已登录，直接生成 Ticket                      │
│  10. 系统 B 验证 Ticket，建立会话                         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 5.3 CAS 协议实现

```python
# CAS (Central Authentication Service) 协议实现

class CASServer:
    """CAS 服务端"""
    
    def __init__(self):
        self.tickets = {}  # ticket -> user_info
        self.ticket_prefix = "ST-"
    
    def authenticate(self, username, password):
        """用户认证"""
        # 验证用户凭证
        if self.verify_credentials(username, password):
            return self.create_ticket(username)
        return None
    
    def create_ticket(self, username):
        """创建 Ticket"""
        import uuid
        ticket = f"{self.ticket_prefix}{uuid.uuid4().hex}"
        self.tickets[ticket] = {
            'username': username,
            'created_at': time.time()
        }
        return ticket
    
    def validate_ticket(self, ticket, service):
        """验证 Ticket"""
        if ticket not in self.tickets:
            return None
        
        ticket_info = self.tickets[ticket]
        
        # 检查 Ticket 是否过期（默认 10 分钟）
        if time.time() - ticket_info['created_at'] > 600:
            del self.tickets[ticket]
            return None
        
        # 销毁 Ticket（一次性使用）
        del self.tickets[ticket]
        
        return ticket_info['username']


class CASClient:
    """CAS 客户端（集成到各业务系统）"""
    
    def __init__(self, cas_server_url, service_id):
        self.cas_url = cas_server_url
        self.service_id = service_id
    
    def login_required(self, func):
        """登录装饰器"""
        @wraps(func)
        def wrapper(request, *args, **kwargs):
            ticket = request.GET.get('ticket')
            
            if not ticket:
                # 重定向到 CAS 登录
                return redirect(self.get_login_url())
            
            # 验证 Ticket
            username = self.validate_ticket(ticket)
            if not username:
                return redirect(self.get_login_url())
            
            # 建立会话
            request.session['user'] = username
            return func(request, *args, **kwargs)
        
        return wrapper
    
    def get_login_url(self):
        """获取 CAS 登录 URL"""
        import urllib.parse
        params = urllib.parse.urlencode({
            'service': self.service_id
        })
        return f"{self.cas_url}/login?{params}"
    
    def validate_ticket(self, ticket):
        """验证 Ticket"""
        import requests
        params = {'ticket': ticket, 'service': self.service_id}
        response = requests.get(
            f"{self.cas_url}/validate",
            params=params
        )
        if response.text.startswith('yes'):
            return response.text.split('\n')[1]
        return None
```

## 6. 可选方案对比

### 6.1 主流 SSO 协议

| 协议 | 特点 | 适用场景 |
|------|------|----------|
| CAS | 简单成熟 | 企业内部 |
| OAuth 2.0 | 授权为主 | 第三方应用 |
| OIDC | 基于 OAuth，携带身份 | 现代 Web |
| SAML 2.0 | XML 标准 | 企业 SSO |
| LDAP + CAS | 目录服务集成 | 企业统一认证 |

### 6.2 方案对比

| 方案 | 复杂度 | 安全性 | 生态 | 推荐度 |
|------|--------|--------|------|--------|
| CAS | 低 | 高 | 一般 | ⭐⭐⭐ |
| OAuth 2.0 + OIDC | 中 | 高 | 好 | ⭐⭐⭐⭐⭐ |
| SAML 2.0 | 高 | 高 | 好 | ⭐⭐⭐ |
| 自研 Token 方案 | 中 | 中 | 差 | ⭐⭐ |

## 7. 推荐方案

### 7.1 企业内部推荐：CAS

- 成熟稳定，实施简单
- 支持多种语言客户端

### 7.2 现代应用推荐：OIDC


## 9. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| SSO 服务单点故障 | 所有系统无法登录 | SSO 服务高可用部署 |
| Ticket 被窃取 | 身份冒充 | HTTPS + 短期 Ticket |
| 跨域 Cookie | 安全风险 | HttpOnly + Secure |
| 权限同步延迟 | 权限变更不及时 | 实时同步机制 |

```python
def test_sso_flow():
    """测试完整 SSO 流程"""
    # 1. 用户在系统 A 登录

        'username': 'user1',
        'password': 'password'
    })
    assert response.status_code == 200
    ticket = response.json()['ticket']

    response = client.get(f'/cas/validate?ticket={ticket}&service=app-a')

    response = client.get(f'/cas/validate?ticket={ticket}&service=app-b')
```

## 11. 总结

1. **SSO 定义**：一次登录，多系统访问
2. **核心原理**：IdP 统一认证，SP 信任 IdP
3. **主流协议**：CAS（简单）、OIDC（现代）、SAML（企业）
4. **推荐方案**：企业内部用 CAS，现代应用用 OIDC
5. **注意事项**：高可用、安全传输、权限同步
