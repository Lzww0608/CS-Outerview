# Canal 监听 binlog 延迟问题分析与解决

## 1. 问题背景

Canal 是阿里巴巴开源的 MySQL binlog 增量订阅与同步组件，常用于缓存更新、搜索引擎索引同步、异构数据库同步等场景。当 binlog 产生速度快于 Canal 消费速度时，会产生延迟。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  问题设定：                                                │
│                                                             │
│  Canal 工作原理：                                          │
│  MySQL Master ──► binlog ──► Canal ──► MQ/下游         │
│                                                             │
│  延迟原因：binlog 产生速度 > Canal 消费速度               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 | 影响 |
|------|------|------|
| 位点差距大 | Canal 位点落后 MySQL 位点 | 数据延迟 |
| 消费积压 | MQ 消息堆积 | 延迟扩大 |
| 同步超时 | 缓存/索引数据过期 | 用户看到旧数据 |

## 5. 解决方案

### 5.1 源头优化：减少大事务

```sql
-- 方案1：分批提交大事务

-- 原语句（延迟风险）
UPDATE orders SET status = 'completed' WHERE create_time < '2024-01-01';

-- 优化：分批处理
DELIMITER //
CREATE PROCEDURE batch_update()
BEGIN
    DECLARE i INT DEFAULT 0;
    DECLARE batch_size INT DEFAULT 1000;
    
    WHILE i < 10000000 DO
        UPDATE orders 
        SET status = 'completed' 
        WHERE create_time < '2024-01-01'
        LIMIT batch_size;
        
        SET i = i + batch_size;
        DO SLEEP(0.1);  -- 避免锁竞争
    END WHILE;
END //
DELIMITER ;
```

### 5.4 下游消费优化

```python
# 下游消费优化

class BatchConsumer:
    def __init__(self, batch_size=100, batch_timeout=1.0):
        self.batch_size = batch_size
        self.batch_timeout = batch_timeout
        self.buffer = []
        self.last_flush = time.time()
    
    def consume(self, message):
        """批量消费消息"""
        self.buffer.append(message)
        
        # 批量写入
        if (len(self.buffer) >= self.batch_size or 
            time.time() - self.last_flush >= self.batch_timeout):
            self.flush()
    
    def flush(self):
        """批量写入 Redis/ES"""
        if not self.buffer:
            return
        
        # 批量操作
        pipeline = redis.pipeline()
        for msg in self.buffer:
            pipeline.set(msg.key, msg.value)
        pipeline.execute()
        
        self.buffer = []
        self.last_flush = time.time()
```

## 11. 总结

1. **延迟原因**：大事务、DDL、解析慢、消费慢
2. **优化层面**：源头、Canal、MQ、下游
3. **推荐方案**：分批事务 + 并行解析 + 分区扩容 + 批量消费
4. **监控指标**：位点差距、消费 Lag、TPS
5. **核心原则**：源头控制 + 消费优化 + 监控告警
