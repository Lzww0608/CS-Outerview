# CRDT 详解：原理、类型与应用

## 一、CRDT 概述

### 1.1 什么是 CRDT

CRDT（Conflict-free Replicated Data Type，无冲突复制数据类型）是一种能够在分布式系统中无需协调即可并行更新、且最终一致的数据结构。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  CRDT 的核心特性：                                         │
│                                                             │
│  1. 无冲突：多个副本可以独立更新，不需要锁                  │
│  2. 无协调：副本之间不需要同步协商                          │
│  3. 最终一致：所有副本最终会收敛到相同状态                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 CRDT vs OT（操作转换）

```text
OT（Operational Transformation）：
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  用户A ──► 删除[0] ──► 服务器 ──► 转发给B              │
│  用户B ──► 插入[x]@0 ──► 服务器 ──► 转发给A              │
│                                                             │
│  问题：需要服务器协调，复杂                                  │
│  解决：OT 算法转换操作                                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘

CRDT：
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  用户A ──► 删除[0] ──┐                                    │
│                             ├──► 各自独立应用 ──► 最终一致   │
│  用户B ──► 插入[x]@0 ──┘                                 │
│                                                             │
│  特点：不需要服务器协调                                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 二、CRDT 数学原理

### 2.1 理论基础：半格（Semilattice）

CRDT 的数学基础是**半格**——一种满足交换性、结合性、幂等性的偏序集合。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  半格定义：                                                │
│                                                             │
│  设 (S, ≤) 是偏序集，join 是上确界运算                    │
│  若对任意 a, b ∈ S，a ∨ b（最小上界）存在               │
│  则 (S, ∨) 是半格                                       │
│                                                             │
│  半格性质：                                                │
│  ┌─────────────────────────────────────────────────────┐  │
│  │ 交换律：a ∨ b = b ∨ a                              │  │
│  │ 结合律：(a ∨ b) ∨ c = a ∨ (b ∨ c)                │  │
│  │ 幂等律：a ∨ a = a                                 │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 CvRDT 与 CmRDT

CRDT 有两种类型：

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  ┌─────────────────────────────────────────────────────┐  │
│  │ CvRDT（Convergent Replicated Data Type）           │  │
│  │ 基于状态的复制数据类型                               │  │
│  │ - 传输状态合并                                       │  │
│  │ - 需要知道完整状态                                   │  │
│  │ - 例：G-Counter、LWW-Register                      │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐  │
│  │ CmRDT（Commutative Replicated Data Type）           │  │
│  │ 基于操作的复制数据类型                               │  │
│  │ - 传输操作合并                                       │  │
│  │ - 操作必须可交换                                     │  │
│  │ - 例：Add-Wins Set、RWW-Set                        │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 三、CRDT 数据类型

### 3.1 计数器（Counter）

```c
// G-Counter（只增计数器）
struct GCounter {
    int node_id;       // 节点ID
    long count;         // 当前计数器值
};

// 合并操作：取最大值
GCounter merge(GCounter a, GCounter b) {
    return GCounter { count = max(a.count, b.count) };
}

// 示例：
// 节点A: count=5
// 节点B: count=3
// 合并后: count=max(5,3)=5 ✓

// PN-Counter（可增可减计数器）
struct PNCounter {
    GCounter positive;  // 增计数器
    GCounter negative;  // 减计数器
};

PNCounter merge(PNCounter a, PNCounter b) {
    return PNCounter {
        merge(a.positive, b.positive),  // max
        merge(a.negative, b.negative)    // max
    };
}

long value(PNCounter c) {
    return c.positive.count - c.negative.count;
}
```

### 3.2 寄存器（Register）

```c
// LWW-Register（最后写入胜出）
struct LWWRegister {
    int64_t timestamp;   // 时间戳
    int node_id;         // 节点ID
    void* value;         // 值
};

// 合并规则：时间戳大者胜出，时间戳相同则节点ID大者胜出
LWWRegister merge(LWWRegister a, LWWRegister b) {
    if (a.timestamp > b.timestamp) return a;
    if (a.timestamp < b.timestamp) return b;
    return (a.node_id > b.node_id) ? a : b;
}

// 示例：
// A: timestamp=100, value="hello"
// B: timestamp=200, value="world"
// 合并后: timestamp=200, value="world"
```

### 3.3 集合（Set）

```c
// G-Set（只增集合）
struct GSet {
    std::set<void*> elements;  // 元素集合
};

GSet add(GSet s, void* e) {
    s.elements.insert(e);  // 插入元素
    return s;
}

GSet merge(GSet a, GSet b) {
    GSet result = a;
    result.elements.insert(b.elements.begin(), b.elements.end());
    return result;  // 并集
}

// 特点：只能添加，不能删除

// 2P-Set（两阶段集合）
struct TwoPSet {
    GSet added;     // 添加集合
    GSet removed;   // 删除集合
};

TwoPSet add(TwoPSet s, void* e) {
    if (!s.removed.elements.count(e)) {
        s.added.add(e);
    }
    return s;
}

TwoPSet remove(TwoPSet s, void* e) {
    if (s.added.elements.count(e)) {
        s.removed.add(e);
    }
    return s;
}

TwoPSet merge(TwoPSet a, TwoPSet b) {
    return TwoPSet {
        merge(a.added, b.added),
        merge(a.removed, b.removed)
    };
}

bool contains(TwoPSet s, void* e) {
    return s.added.elements.count(e) && !s.removed.elements.count(e);
}

// Add-Wins Set（AWW-Set，更常用的集合）
struct AWSet {
    GSet add_set;       // 添加标记
    GSet remove_set;     // 删除标记
    std::map<void*, int> add_timestamps;  // 添加时间戳
    std::map<void*, int> remove_timestamps; // 删除时间戳
};

bool contains(AWSet s, void* e) {
    auto add_ts = s.add_timestamps.get(e, 0);
    auto remove_ts = s.remove_timestamps.get(e, 0);
    return add_ts > remove_ts;
}
```

### 3.4 地图（Map）

```c
// LWW-Map（最后写入胜出地图）
struct LWWMap {
    std::map<std::string, LWWRegister> entries;
};

LWWMap put(LWWMap m, std::string key, void* value, int64_t ts) {
    m.entries[key] = LWWRegister { timestamp=ts, value };
    return m;
}

LWWMap erase(LWWMap m, std::string key, int64_t ts) {
    m.entries[key] = LWWRegister { timestamp=ts, value=NULL };
    return m;
}

LWWMap merge(LWWMap a, LWWMap b) {
    LWWMap result = a;
    for (auto& kv : b.entries) {
        if (!result.entries.count(kv.first) ||
            result.entries[kv.first].timestamp < kv.second.timestamp) {
            result.entries[kv.first] = kv.second;
        }
    }
    return result;
}
```

## 四、CRDT 在协同编辑的应用

### 4.1 Yjs 库

Yjs 是最流行的 CRDT 协同编辑库：

```javascript
// Yjs 示例
import * as Y from 'yjs'

// 创建文档
const ydoc = new Y.Doc()

// 创建协同文本
const ytext = ydoc.getText('prosemirror')

// 监听变化
ytext.observe((event) => {
    console.log('Changed:', event.delta)
})

// 本地修改
ytext.insert(0, 'Hello')
ytext.delete(5, 1)

// 与远程同步（通过 WebSocket 等）
const provider = new WebsocketProvider('ws://server', 'room', ydoc)
```

### 4.2 文本 CRDT

协同编辑的核心是**序列 CRDT（Sequence CRDT）**：

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  RGA（Replicated Growable Array）算法：                     │
│                                                             │
│  每个字符都有唯一ID和左邻居ID                               │
│  ┌─────────────────────────────────────────────────────┐  │
│  │ 字符 | ID          | 左邻居ID                       │  │
│  │  H   | (A,0)     | null                          │  │
│  │  e   | (A,1)     | (A,0)                        │  │
│  │  l   | (A,2)     | (A,1)                        │  │
│  │  l   | (A,3)     | (A,2)                        │  │
│  │  o   | (A,4)     | (A,3)                        │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
│  插入操作：                                                │
│  - 客户端生成 (client_id, clock) 唯一ID                   │
│  - 找到左邻居，在其后插入                                  │
│  - 删除操作：标记删除，但不真正删除                        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 六、CRDT 的局限性

### 6.1 内存占用

```text
问题：
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  文本 CRDT 的 Tombstone 问题：                             │
│                                                             │
│  "Hello World" 的删除历史：                               │
│  H e l l o   W o r l d                                  │
│  ────────────────────────                                 │
│  删除后保留 Tombstone（墓碑）：                           │
│  H e l l o   W o r l d   [deleted markers]              │
│                                                             │
│  问题：长期编辑后，Tombstone 可能比实际内容还多           │
│                                                             │
│  解决：定期 GC，但需要协调                                │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 6.2 性能问题

| 问题 | 说明 |
|------|------|
| 合并复杂度 | O(n²) 复杂度的合并操作 |
| ID 生成 | 需要保证全局唯一性 |
| 内存占用 | Tombstone 导致内存膨胀 |
| 语义限制 | 不是所有操作都能转为 CRDT |

## 七、面试常见问题

### Q1: 什么是 CRDT？

CRDT（Conflict-free Replicated Data Type）是无冲突复制数据类型，能够在分布式系统中无需协调即可并行更新，最终自动收敛到一致状态。

### Q2: CRDT 和 OT 的区别？

OT 需要服务器转换和协调操作，复杂且需要中心化；CRDT 无需协调，每个副本可以独立合并，但内存占用可能较高。

### Q3: CRDT 的数学基础是什么？

CRDT 基于半格（Semilattice）理论，利用交换性、结合性、幂等性保证最终一致性。

### Q4: CRDT 有哪些局限性？

内存占用大（tombstone 问题）、合并复杂度高、不是所有操作都能转为 CRDT。

### Q5: CRDT 的应用场景？

协同编辑（Google Docs、Figma）、分布式数据库（Riak）、消息系统（已读状态同步、收藏同步）。

## 八、总结

1. **CRDT 定义**：无冲突复制数据类型，无需协调即可最终一致
2. **数学原理**：基于半格，满足交换性、结合性、幂等性
3. **数据类型**：Counter、Register、Set、Map
4. **应用场景**：协同编辑、分布式数据库、消息同步
5. **局限性**：内存占用、合并复杂度
