# LWW（Last-Writer-Wins）详解

## 一、LWW 概述

### 1.1 什么是 LWW

LWW（Last-Writer-Wins，最后写入者胜出）是一种冲突解决策略，当多个副本对同一数据产生冲突时，时间戳最近的操作胜出。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  LWW 核心思想：                                             │
│                                                             │
│  冲突解决规则：                                             │
│  ┌─────────────────────────────────────────────────────┐  │
│  │ 操作A: value="hello", timestamp=100                   │  │
│  │ 操作B: value="world", timestamp=200                   │  │
│  │                                                      │  │
│  │ timestamp(B)=200 > timestamp(A)=100                    │  │
│  │ → 最终值: "world"                                   │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
│  LWW 特点：                                                │
│  - 简单高效，无需复杂合并逻辑                              │
│  - 需要可靠的逻辑时钟                                      │
│  - 可能丢失中间更新                                      │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 二、LWW 的问题

### 2.1 丢失中间更新

这是 LWW 最严重的问题之一。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  场景：计数器增量操作                                        │
│                                                             │
│  初始值：counter = 0                                       │
│                                                             │
│  节点A：                                                    │
│  T=100: counter = 1  (+1操作)                             │
│  T=300: counter = 2  (+1操作)  ──► 丢失！                 │
│                                                             │
│  节点B：                                                    │
│  T=200: counter = 99 (+99操作)                             │
│                                                             │
│  LWW 合并后：                                              │
│  最终值 = max(timestamp) = 99                               │
│  期望值 = 100 (0 + 1 + 99)                                │
│                                                             │
│  问题：A 的两次更新都丢失了！                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 三、LWW 的改进方案

### 3.1 使用向量时钟替代物理时钟

```c
// 向量时钟
struct VectorClock {
    std::map<int, int64_t> clock;  // node_id -> timestamp
};

// 向量时钟比较
bool happens_before(VectorClock a, VectorClock b) {
    for (auto& kv : a.clock) {
        int node = kv.first;
        int64_t a_ts = kv.second;
        int64_t b_ts = b.clock.get(node, 0);
        if (a_ts > b_ts) return false;
    }
    return true;
}

// 定义偏序关系
enum Relation {
    BEFORE,      // a happens-before b
    AFTER,      // a happens-after b
    CONCURRENT  // 并发
};

Relation compare(VectorClock a, VectorClock b) {
    bool a_before_b = happens_before(a, b);
    bool b_before_a = happens_before(b, a);
    
    if (a_before_b) return AFTER;   // a 在 b 之后
    if (b_before_a) return BEFORE;  // a 在 b 之前
    return CONCURRENT;                // 并发
}
```

### 3.2 使用多值 CRDT（Multi-Value CRDT）

```c
// MV-Register：保留所有并发值
struct MVRegister {
    std::map<VectorClock, void*> values;  // 时钟 -> 值
};

MVRegister merge(MVRegister a, MVRegister b) {
    MVRegister result;
    
    // 收集所有值
    for (auto& kv : a.values) {
        result.values[kv.first] = kv.second;
    }
    for (auto& kv : b.values) {
        result.values[kv.first] = kv.second;
    }
    
    // 删除被支配的值
    for (auto it = result.values.begin(); it != result.values.end();) {
        bool dominated = false;
        for (auto other = result.values.begin(); 
             other != result.values.end(); ++other) {
            if (it != other && happens_before(it->first, other->first)) {
                dominated = true;
                break;
            }
        }
        if (dominated) {
            it = result.values.erase(it);
        } else {
            ++it;
        }
    }
    
    return result;
}

// 用户展示：告诉用户有冲突
void display(MVRegister reg) {
    if (reg.values.size() == 1) {
        // 没有冲突
        show_value(reg.values.begin()->second);
    } else {
        // 有冲突，显示所有并发值
        show_conflict_dialog(reg.values);
    }
}
```

### 3.3 使用操作日志代替状态合并

```c
// 操作日志（Operation Log）
struct Operation {
    int64_t timestamp;
    int node_id;
    std::string operation;  // "set", "inc", "delete"
    void* value;
};

struct OpLog {
    std::vector<Operation> log;
};

// 合并：追加所有操作
OpLog merge(OpLog a, OpLog b) {
    OpLog result = a;
    // 追加 b 中独有的操作
    for (auto& op : b.log) {
        bool exists = false;
        for (auto& existing : result.log) {
            if (op.timestamp == existing.timestamp && 
                op.node_id == existing.node_id) {
                exists = true;
                break;
            }
        }
        if (!exists) {
            result.log.push_back(op);
        }
    }
    // 按时间戳排序
    sort(result.log.begin(), result.log.end(),
         [](auto& a, auto& b) { return a.timestamp < b.timestamp; });
    return result;
}

// 计算最终值：重放所有操作
void* apply(OpLog log) {
    void* state = NULL;
    for (auto& op : log) {
        state = apply_operation(state, op);
    }
    return state;
}
```

### 3.4 使用专门的数据类型

```c
// PN-Counter：解决计数器问题
struct PNCounter {
    GCounter positive;  // 增操作
    GCounter negative;  // 减操作
};

PNCounter increment(PNCounter c, int node_id) {
    c.positive[node_id]++;
    return c;
}

PNCounter decrement(PNCounter c, int node_id) {
    c.negative[node_id]++;
    return c;
}

long value(PNCounter c) {
    return c.positive.value() - c.negative.value();
}

// G-Counter 合并：取最大值
GCounter merge(GCounter a, GCounter b) {
    GCounter result;
    for (auto& kv : a.counts) {
        result.counts[kv.first] = kv.second;
    }
    for (auto& kv : b.counts) {
        int node_id = kv.first;
        long cnt = kv.second;
        result.counts[node_id] = max(result.counts[node_id], cnt);
    }
    return result;
}
```

## 五、LWW 实践指南

### 5.1 LWW 寄存器实现

```c
// LWW-Register
struct LWWRegister {
    int node_id;
    int64_t timestamp;
    void* value;
};

LWWRegister set(LWWRegister reg, void* new_value, int64_t ts) {
    return LWWRegister {
        .node_id = reg.node_id,
        .timestamp = ts,
        .value = new_value
    };
}

LWWRegister merge(LWWRegister a, LWWRegister b) {
    if (a.timestamp > b.timestamp) return a;
    if (a.timestamp < b.timestamp) return b;
    // 时间戳相同，节点ID大的胜出
    if (a.node_id > b.node_id) return a;
    return b;
}
```

### 5.2 LWW 地图实现

```c
// LWW-Map
struct LWWMap {
    std::map<std::string, LWWRegister> entries;
};

LWWMap put(LWWMap m, std::string key, void* value, int64_t ts) {
    m.entries[key] = set(m.entries[key], value, ts);
    return m;
}

LWWMap erase(LWWMap m, std::string key, int64_t ts) {
    // 删除 = 写入 NULL 值
    return put(m, key, NULL, ts);
}

LWWMap merge(LWWMap a, LWWMap b) {
    LWWMap result = a;
    for (auto& kv : b.entries) {
        if (!result.entries.count(kv.first)) {
            result.entries[kv.first] = kv.second;
        } else {
            result.entries[kv.first] = merge(result.entries[kv.first], kv.second);
        }
    }
    return result;
}
```

### 5.3 时钟生成策略

```c
// 混合逻辑时钟（Hybrid Logical Clock）
struct HLC {
    int64_t wall_time;     // 物理时间
    int64_t logical;        // 逻辑计数器
    int node_id;
};

HLC now(int node_id) {
    int64_t wall = current_time_millis();
    return HLC { wall, 0, node_id };
}

HLC tick(HLC c) {
    return HLC { c.wall_time, c.logical + 1, c.node_id };
}

HLC merge(HLC a, HLC b) {
    int64_t wall = max(a.wall_time, b.wall_time);
    int64_t logical = 0;
    
    if (a.wall_time == wall && b.wall_time == wall) {
        logical = max(a.logical, b.logical) + 1;
    } else if (a.wall_time == wall) {
        logical = a.logical + 1;
    } else {
        logical = b.logical + 1;
    }
    
    return HLC { wall, logical, a.node_id };
}

bool happens_before(HLC a, HLC b) {
    if (a.wall_time < b.wall_time) return true;
    if (a.wall_time > b.wall_time) return false;
    if (a.logical < b.logical) return true;
    if (a.logical > b.logical) return false;
    return a.node_id < b.node_id;  // tie-breaker
}
```

## 六、面试常见问题

### Q1: LWW 的问题是什么？

LWW 的主要问题是丢失中间更新。当两个节点并发写入时，时间戳较晚的操作会直接覆盖较早的操作，导致中间的状态变更被静默丢弃。例如：计数器增量操作可能被覆盖。

### Q2: 如何改进 LWW？

1. 使用向量时钟替代物理时钟
2. 使用多值 CRDT（MV-Register）保留所有并发值
3. 使用操作日志（OpLog）代替状态合并
4. 使用专门的数据类型（如 PN-Counter）代替简单 LWW

### Q3: LWW 适合什么场景？

LWW 适合配置管理、用户偏好设置、在线状态同步等**最终状态覆盖**的场景，不适合计数器、协同编辑、任务清单等**累积操作**的场景。

### Q4: 向量时钟解决了什么问题？

向量时钟解决了物理时钟不可靠的问题。通过记录每个节点的逻辑时间戳，可以准确判断两个操作是因果关系还是并发关系。

## 七、总结

1. **LWW 定义**：最后写入者胜出的冲突解决策略
2. **LWW 问题**：丢失中间更新、时钟同步问题、并发写入丢失
3. **改进方案**：向量时钟、MV-CRDT、操作日志、专门数据类型
4. **应用场景**：配置管理、用户偏好、在线状态（适合）；计数器、协同编辑、任务清单（不适合）
