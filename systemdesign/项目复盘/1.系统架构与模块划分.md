# 1.项目系统架构与模块划分

面试里让你“讲讲项目架构”，重点不是把所有类和接口背一遍，而是说明这个系统解决什么问题、核心链路怎么走、模块为什么这样拆。

## 1. 回答顺序

可以按这个顺序讲：

1. **业务目标**：系统服务谁，解决什么问题。
2. **规模指标**：QPS、数据量、用户量、延迟要求、可用性要求。
3. **整体架构**：接入层、业务层、存储层、异步链路、观测治理。
4. **核心链路**：一条请求从入口到返回经过哪些模块。
5. **模块划分**：每个模块负责什么，模块之间如何交互。
6. **关键技术点**：缓存、消息队列、数据库、限流、降级、一致性、幂等。
7. **取舍**：为什么这样设计，有哪些替代方案，当前方案解决了什么问题。

## 2. 通用架构表达

可以把大多数后端项目抽象成下面几层：

```text
Client
  -> Gateway / API Server
      -> Auth / RateLimit / Router
      -> Business Service
          -> Cache
          -> Database
          -> MQ / Async Worker
          -> External Service
      -> Metrics / Log / Trace
```

面试时不要只说“用了 Redis、MySQL、MQ”，要把它们放到链路里：

1. Redis 是做热点缓存、分布式锁、限流还是 Bitmap 统计。
2. MQ 是削峰、异步解耦、延迟任务还是最终一致性。
3. MySQL 是核心事务数据、关系查询还是索引检索。
4. 定时任务或 worker 负责什么补偿逻辑。

## 3. 模块划分原则

模块划分可以从这些角度解释：

1. **按业务能力拆**：用户、订单、支付、内容、搜索、通知等。
2. **按读写链路拆**：写链路保证一致性，读链路关注低延迟和高吞吐。
3. **按同步/异步拆**：必须立即返回的走同步链路，可延迟处理的放到 MQ 或任务队列。
4. **按数据归属拆**：每个模块明确自己负责哪些表、缓存 key 和数据更新规则。
5. **按稳定性边界拆**：外部依赖、慢任务、非核心功能独立出来，便于降级和隔离。

## 4. 面试回答模板

我的项目可以分成接入层、业务服务层、异步任务层、数据存储层和观测治理层。接入层负责鉴权、参数校验、路由和限流；业务层承载核心流程；数据层主要包括 MySQL 和 Redis，MySQL 保存核心状态，Redis 用于缓存和高频状态判断；异步层通过 MQ 或任务队列处理耗时操作、补偿任务和通知；观测层负责日志、指标和链路追踪。

核心请求进来后，先经过接入层做校验和限流，再进入业务服务。业务服务会先读缓存，缓存未命中再查数据库；涉及耗时或非强一致的操作会写入 MQ，由 worker 异步处理。模块划分上，我主要按业务能力和数据归属拆分，同时把高频读、慢任务和外部依赖隔离出来，避免一个模块的问题影响整条主链路。

## 5. 常见追问

### 为什么这样拆模块？

回答重点是边界清晰和故障隔离。每个模块负责稳定的数据和业务能力，模块之间通过接口、消息或明确的数据契约交互，减少互相直接访问内部状态。

### 请求量上来后哪里会成为瓶颈？

可以从接入层连接数、业务线程池、数据库慢查询、热点缓存 key、MQ 堆积、外部接口超时几个方向分析。

### 怎么保证可观测？

至少要有结构化日志、核心指标和链路追踪。日志用于定位具体请求，指标用于发现趋势和报警，trace 用于定位跨模块耗时。
