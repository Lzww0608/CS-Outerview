# CI/CD 容器化部署详解

## 1. 问题背景

CI/CD（持续集成/持续部署）是现代软件工程的核心实践，容器化部署则通过 Docker 等技术实现应用的标准化打包和交付。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  CI/CD 容器化部署全景：                                   │
│                                                             │
│  Code → Build → Test → Push → Deploy                      │
│            ↓         ↓       ↓      ↓                     │
│          镜像      镜像    镜像   容器                    │
│                                                             │
│  核心价值：                                               │
│  • 环境一致性：Build Once, Run Anywhere                   │
│  • 快速迭代：自动化流程，加速交付                        │
│  • 可靠性：标准化、可重复的部署                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 |
|------|------|
| 环境不一致 | 本地正常，线上报错 |
| 部署慢 | 手动打包上传耗时 |
| 难以回滚 | 出问题只能重装 |
| 扩展困难 | 无法快速扩缩容 |

---

## 3. 影响范围

- 开发团队交付效率
- 运维自动化程度
- 系统稳定性和可扩展性

## 5. 解决方案

### 5.1 Dockerfile 示例

```dockerfile
# 多阶段构建示例
FROM golang:1.21-alpine AS builder

WORKDIR /app
COPY go.mod go.sum ./
RUN go mod download

COPY . .
RUN CGO_ENABLED=0 GOOS=linux go build -o main .

# 运行镜像
FROM alpine:latest
RUN apk --no-cache add ca-certificates tzdata

WORKDIR /root/
COPY --from=builder /app/main .

EXPOSE 8080
CMD ["./main"]
```

### 5.2 Docker Compose 本地开发

```yaml
# docker-compose.yml
version: '3.8'

services:
  app:
    build: .
    ports:
      - "8080:8080"
    environment:
      - DB_HOST=postgres
      - REDIS_HOST=redis
    depends_on:
      - postgres
      - redis
  
  postgres:
    image: postgres:15-alpine
    environment:
      POSTGRES_DB: myapp
      POSTGRES_USER: user
      POSTGRES_PASSWORD: pass
  
  redis:
    image: redis:7-alpine
```

### 5.3 CI Pipeline 示例

```yaml
# .github/workflows/ci.yml
name: CI/CD Pipeline

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    
    steps:
      - uses: actions/checkout@v4
      
      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v3
      
      - name: Build image
        run: docker build -t myapp:${{ github.sha }} .
      
      - name: Run tests
        run: |
          docker run myapp:${{ github.sha }} pytest
      
      - name: Push to registry
        if: github.ref == 'refs/heads/main'
        run: |
          echo ${{ secrets.DOCKER_TOKEN }} | docker login -u ${{ secrets.DOCKER_USER }} --password-stdin
          docker push myapp:${{ github.sha }}
```

### 5.4 Kubernetes 部署

```yaml
# k8s-deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  replicas: 3
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec:
      containers:
        - name: myapp
          image: myapp:latest
          ports:
            - containerPort: 8080
          resources:
            limits:
              memory: "512Mi"
              cpu: "500m"
          readinessProbe:
            httpGet:
              path: /health
              port: 8080
          livenessProbe:
            httpGet:
              path: /health
              port: 8080
---
apiVersion: v1
kind: Service
metadata:
  name: myapp-svc
spec:
  selector:
    app: myapp
  ports:
    - port: 80
      targetPort: 8080
  type: ClusterIP
```

## 7. 推荐方案

### 7.1 生产架构

```yaml
# 推荐生产架构

architecture:
  # CI/CD 平台
  cicd:
    provider: "github_actions"  # 或 jenkins, gitlab ci
    registry: "harbor"  # 或 docker hub, ecr
  
  # 容器编排
  orchestration:
    k8s: true
    ingress: "nginx"
    monitoring: "prometheus"
  
  # 部署策略
  deployment:
    strategy: "rolling"  # 滚动更新
    max_surge: 1
    max_unavailable: 0
```

## 9. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 镜像体积过大 | 拉取慢、占用存储 | 多阶段构建、优化层 |
| 依赖漏洞 | 安全风险 | 定期扫描、定期更新基础镜像 |
| 配置泄露 | 安全风险 | 使用 K8s Secret、Vault |
| 回滚失败 | 服务中断 | 蓝绿部署、金丝雀发布 |

## 10. 验证方式

```bash
# 1. 本地验证 Dockerfile
docker build -t myapp:test .
docker run -p 8080:8080 myapp:test

# 2. 检查镜像
docker images | grep myapp
docker history myapp:test

# 3. Kubernetes 验证
kubectl apply -f k8s-deployment.yaml
kubectl get pods -l app=myapp
kubectl describe deployment myapp
kubectl logs -l app=myapp

# 4. 健康检查
curl http://localhost:8080/health
```

## 11. 总结

1. **CI/CD 核心**：代码 → 构建 → 测试 → 部署 全流程自动化
2. **容器化优势**：环境一致、快速启动、版本管理、资源隔离
3. **实施要点**：Dockerfile 多阶段构建 + CI Pipeline + K8s 编排
4. **生产建议**：Harbor 镜像仓库 + K8s 滚动部署 + 监控告警
5. **安全考虑**：镜像扫描、密钥管理、最小权限、安全基线
