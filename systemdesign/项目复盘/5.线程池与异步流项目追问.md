# 5.线程池与异步流项目追问

面试里问“项目里的线程池怎么设计”“异步流是什么”，通常不是只想听代码实现，而是想确认你是否理解任务从提交、排队、执行、回调、失败处理到关闭的完整链路。

## 1. 线程池怎么讲

线程池的定义：预先创建一组 worker 线程，复用它们执行任务，避免每个任务都创建和销毁线程。

项目里介绍线程池可以按下面顺序：

1. **为什么需要线程池**：隔离耗时任务，避免事件循环或主线程被阻塞。
2. **线程数量**：CPU 密集型接近 CPU 核数，I/O 密集型可以适当更多，但要压测决定。
3. **任务队列**：有界队列更安全，可以防止突发流量打爆内存。
4. **同步机制**：互斥锁保护队列，条件变量唤醒 worker。
5. **返回结果**：可以用 `future/promise`、回调、事件投递或消息队列。
6. **关闭语义**：停止接收新任务，处理完存量任务，唤醒所有线程并 `join`。

## 2. 线程池关键取舍

| 问题 | 常见方案 | 取舍 |
| --- | --- | --- |
| 队列是否有界 | 固定容量任务队列 | 防止内存膨胀，但需要拒绝策略 |
| 队列满怎么办 | 拒绝、阻塞提交、调用方执行、丢弃低优先级任务 | 取决于业务是否允许降级 |
| 任务异常怎么办 | worker 捕获异常并记录日志 | 避免一个任务导致线程退出 |
| 任务是否有优先级 | 优先队列或多队列 | 提升关键任务响应，但可能饿死低优先级 |
| 如何监控 | 队列长度、活跃线程数、任务耗时、拒绝次数 | 便于发现堆积和容量不足 |

面试里要强调：任务执行不能持有队列锁，否则线程池会退化为串行执行。

## 3. 异步流是什么

项目里的“异步流”可以理解为一条由事件、队列、回调或协程串起来的异步处理流水线。它把请求拆成多个阶段，每个阶段完成后把结果投递给下一个阶段，而不是在一个线程里同步阻塞到底。

典型链路：

```text
请求进入
-> 参数校验
-> 投递到线程池或 MQ
-> worker 执行业务/IO
-> 结果回调到事件循环
-> 写响应或触发后续任务
```

异步流的核心价值：

1. **解耦**：上游不直接等待下游慢操作。
2. **削峰**：队列吸收短时间流量突刺。
3. **隔离**：慢任务不阻塞主线程或事件循环。
4. **可恢复**：持久化队列或任务状态机可以支持失败重试。
5. **可观测**：每个阶段都能记录耗时和失败原因。

## 3.1 异步有什么好处

异步的好处可以从性能和架构两个角度讲：

1. **降低同步等待时间**：主链路不必等待邮件、通知、日志、发奖、报表等慢任务完成。
2. **削峰填谷**：突发流量先进入队列，后端 worker 按可控速率消费。
3. **解耦上下游**：调用方只依赖消息或任务结果，不直接感知下游实现和临时故障。
4. **隔离故障**：下游慢或失败时，不直接拖死入口线程池。
5. **提升吞吐**：I/O 等待型任务可以让出线程或协程，系统同时处理更多请求。
6. **支持重试和补偿**：失败任务可以持久化后重试，避免用户请求一直阻塞。

但异步也有代价：

1. 用户不能立即拿到最终结果，需要轮询、回调、SSE 或状态查询。
2. 数据通常从强一致变成最终一致，需要幂等和补偿。
3. 队列堆积会造成延迟上升，必须有监控和背压。
4. 排查问题更依赖 trace id、任务状态和结构化日志。

所以面试里不能只说“异步提高性能”，还要说明异步把同步延迟变成了队列延迟和一致性问题，需要配套状态机、幂等、重试、死信和监控。

## 4. 背压和可靠性

异步不是无限排队。真正可用的异步流必须考虑背压：

1. 队列长度达到阈值时拒绝或降级。
2. 消费速度低于生产速度时扩容 worker 或限流入口。
3. 任务设置超时时间，避免一直占用资源。
4. 失败任务带重试次数和退避策略。
5. 写操作要有幂等 key，避免重试造成重复副作用。
6. 关键任务状态落库，worker 重启后能恢复。

## 5. 和事件循环的配合

在 WebServer 或 RPC 项目中，常见做法是：

1. Reactor 线程只做非阻塞 I/O、协议解析和事件分发。
2. CPU 计算、磁盘 I/O、数据库访问交给线程池。
3. worker 完成后不要直接跨线程操作连接 fd，而是把回调投递回连接所属的 EventLoop。
4. EventLoop 再把结果写入输出缓冲区，打开 `EPOLLOUT`。

这样可以避免多个线程同时读写同一个连接对象，也能保持连接生命周期清晰。

## 6. 易错点

1. 异步流不是“开个线程就完了”，要有队列、状态、错误处理和背压。
2. 线程池大小不是越大越好，线程过多会增加上下文切换和锁竞争。
3. 无界队列在压测中可能看起来吞吐高，但线上突刺会堆爆内存。
4. 回调跨线程执行时要明确对象生命周期，避免悬垂引用。
5. 异步任务失败后必须有重试、补偿或明确丢弃策略。

## 7. 面试回答模板

我的项目里线程池主要用来隔离耗时任务，避免事件循环线程被阻塞。线程池由固定 worker、有界任务队列、互斥锁、条件变量和停止标志组成；提交任务时入队并唤醒 worker，worker 取任务后释放锁再执行。队列满时根据业务做拒绝或降级，任务异常会捕获并记录，关闭时先停止接收新任务，再处理完存量任务并 join。

异步流可以理解为请求处理流水线：入口线程完成轻量校验后把任务投递到队列，worker 执行业务或 I/O，完成后把结果投递回事件循环写响应。它的价值是解耦、削峰和隔离慢操作，但必须配套背压、超时、重试、幂等和监控，否则只是把同步阻塞变成队列堆积。
