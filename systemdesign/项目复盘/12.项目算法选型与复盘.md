# 12. 项目算法选型与复盘

项目面试里经常会问“这些算法都是你自己实现的吗”“为什么不用库”“项目里学到了什么”。这类问题不是考背算法，而是考你是否理解算法在项目中的位置、边界和风险。

## 1. 算法是自研还是复用

回答时可以按分层说明：

1. **成熟基础能力优先复用**：排序、哈希、编解码、网络库、矩阵计算等，优先使用标准库、FFmpeg、OpenCV、Eigen、成熟中间件。
2. **业务相关策略可以自研**：规则组合、评分函数、调度策略、过滤逻辑、项目特定的数据结构。
3. **学习项目可以手写核心算法**：为了掌握原理可以自己实现，但要说明和生产库的差距。
4. **生产场景要有验证**：自研算法必须有单测、边界测试、性能基准和回滚方案。

面试时不要把“全部自己写”当作优点。真正的工程能力是知道哪些该复用，哪些必须定制。

## 2. 怎么解释算法选型

可以用下面结构：

```text
业务目标
-> 数据规模
-> 延迟/吞吐/内存约束
-> 可维护性和风险
-> 选择方案
-> 验证结果
```

示例：

1. 数据规模小、实时性不高：选择简单实现，降低维护成本。
2. 数据规模大、内存有限：使用分桶、外部排序、流式处理或近似算法。
3. 延迟敏感：优先预计算、缓存、索引或降低算法复杂度。
4. 精度可让渡：考虑 Bloom Filter、HyperLogLog、采样等近似方案。
5. 依赖第三方库：说明版本、参数、异常处理和降级策略。

## 3. 怎么证明算法正确

1. **单元测试**：空输入、单元素、重复元素、极值、非法输入。
2. **对拍**：小数据用暴力算法和优化算法输出对比。
3. **不变量**：例如堆的父子关系、排序后的有序性、链表前后指针一致性。
4. **复杂度验证**：压测不同规模输入，观察耗时是否符合预期曲线。
5. **线上指标**：错误率、延迟、资源占用、召回率或业务转化。

## 4. 项目里学到了什么

技术回答要落到具体能力：

1. 把算法从 demo 落到工程时，要处理异常输入、边界条件和资源释放。
2. 算法复杂度只是起点，真实性能还受缓存局部性、内存分配、I/O 和并发影响。
3. 复用成熟库时，要理解关键参数和失败路径，不能只会调用 API。
4. 多人协作中，算法模块需要清晰接口、测试数据和性能基线。
5. 线上问题要能用日志、指标、trace 和回放数据定位。

## 5. 项目里用到了哪些数据结构

面试官问“项目里用了哪些数据结构”，不要只罗列 `vector/map/queue`，要把数据结构和业务链路、复杂度、并发方式联系起来。

可以按下面结构回答：

```text
业务场景
-> 数据规模和访问模式
-> 选择的数据结构
-> 复杂度和取舍
-> 线上如何验证
```

常见回答方向：

1. **哈希表**：用于 ID 到对象、连接、会话、缓存条目的快速定位。平均 `O(1)`，但要关注哈希冲突、扩容抖动、内存占用和并发安全。
2. **有序结构**：红黑树、跳表、堆适合 TopK、排行榜、定时器、范围查询。要说明为什么需要有序性，而不是只用哈希表。
3. **队列**：任务队列、消息缓冲、日志异步落盘。普通业务可以用阻塞队列；低延迟单生产单消费链路可以考虑环形队列。
4. **位图和布隆过滤器**：适合大规模存在性判断、签到、去重、黑名单预过滤。要说明误判率、空间成本和删除限制。
5. **前缀树/AC 自动机**：适合前缀搜索、敏感词匹配、路由匹配。要关注内存膨胀和字符集规模。
6. **LRU/LFU 缓存结构**：哈希表配合链表或频次桶，实现快速查询和淘汰。要结合热点 key、容量、TTL 和一致性说明。
7. **并发数据结构**：分段锁、读写锁、Copy-on-Write、RCU、无锁队列。重点说明读写比例、冲突程度和正确性边界。

示例回答：

> 项目里核心映射关系用哈希表，因为请求链路需要按 ID 快速定位上下文；定时任务用小顶堆维护最近触发时间，插入和删除是 `O(log n)`；异步日志链路用有界队列削峰，队列满时按等级丢弃低价值日志；本地缓存用 LRU，哈希表保证查询，双向链表维护访问顺序。选择这些结构主要是根据访问模式定的：点查用哈希，有序调度用堆，削峰用队列，容量受限缓存用 LRU。

易错点：

1. 不要说“用了很多 STL 容器”就结束，要说明容器背后的访问模式。
2. 数据结构的理论复杂度不等于真实性能，缓存局部性、内存分配和锁竞争也会影响延迟。
3. 并发场景下不要默认 `unordered_map` 安全，多线程读写必须加锁、分片或使用并发容器。
4. 能用成熟库就不要轻易自研复杂结构；自研时必须有单测、压测和边界验证。

## 6. 面试回答模板

项目里的通用基础算法和编解码能力我会优先复用成熟库，例如标准库、OpenCV 或 FFmpeg，因为它们经过大量测试和优化。项目特定的策略，比如业务规则、调度逻辑、数据过滤和参数选择，会根据数据规模和性能目标自己实现。自研部分我会用单测、边界样例、对拍和压测验证；复用库也会说明关键参数、异常处理和降级方案。这样既能保证交付质量，也能体现我理解核心原理，而不是只会调用接口。
