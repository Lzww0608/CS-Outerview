# 8. PC 客户端开发理解

PC 客户端开发不只是“写界面”。它通常同时涉及 UI 架构、事件循环、线程模型、本地资源管理、网络通信、崩溃定位、安装升级和跨平台兼容。

## 1. PC 客户端的核心模块

常见模块可以拆成：

```text
UI 层
  -> 状态管理 / ViewModel / Controller
      -> 业务服务
          -> 网络通信
          -> 本地缓存 / 配置 / 文件
          -> 设备 / 系统 API
      -> 日志 / 崩溃上报 / 指标
      -> 自动更新 / 插件 / 安装包
```

面试里可以按职责说明：

1. **UI 层**：窗口、控件、绘制、用户输入。
2. **状态层**：页面状态、选中项、加载状态、错误状态。
3. **业务层**：领域逻辑、命令处理、权限和流程控制。
4. **通信层**：HTTP、WebSocket、自定义 TCP、RPC。
5. **本地存储**：配置、缓存、SQLite、日志、临时文件。
6. **工程能力**：崩溃 dump、自动更新、灰度、性能监控。

## 2. UI 线程和后台线程

PC 客户端通常有一个 UI 主线程负责消息循环和界面刷新。耗时任务不能直接在 UI 线程执行，否则会卡顿或无响应。

常见做法：

1. UI 线程只处理绘制、输入和轻量状态更新。
2. 网络、磁盘、解码、压缩、模型推理放到后台线程或任务队列。
3. 后台线程完成后通过消息队列、事件、signal/slot 或 dispatcher 切回 UI 线程更新界面。
4. UI 状态更新要保证线程安全，不要从后台线程直接改控件。

示意流程：

```text
button click
  -> UI thread dispatch command
  -> worker thread request/compute
  -> post result to UI thread
  -> UI thread update view
```

## 3. MVC/MVVM 在客户端中的价值

客户端项目容易出现所有逻辑都写在窗口类里的问题。MVC 或 MVVM 的价值是拆职责：

1. View 只负责展示和输入。
2. Controller/ViewModel 负责事件转换和状态组织。
3. Model/Service 负责业务数据和业务规则。

这样做的收益：

1. UI 修改不容易影响业务逻辑。
2. 核心业务可以脱离界面做单元测试。
3. 多端复用更容易，例如桌面端和命令行工具复用同一业务层。
4. 页面复杂后状态流转更清晰。

## 4. 性能和体验关注点

PC 客户端常见指标：

1. 启动时间。
2. 页面首次渲染时间。
3. 输入响应延迟。
4. CPU 和内存占用。
5. 磁盘读写量。
6. 网络弱网体验。
7. 崩溃率和卡死率。

优化方向：

1. 延迟加载非首屏模块。
2. 大文件和大量列表做分页、虚拟列表或懒加载。
3. 图片、视频、渲染资源做缓存和异步解码。
4. 日志和埋点异步写入，避免阻塞 UI。
5. 渲染循环中减少分配、锁和跨线程同步。

## 5. 图形渲染和游戏引擎开源库怎么回答

如果被问是否看过游戏引擎或图形渲染开源库，可以从“理解哪些模块”回答，而不是只报项目名。

常见关注点：

1. **渲染循环**：主循环、帧率控制、输入、更新、渲染。
2. **资源管理**：纹理、模型、shader、音频的加载、缓存和释放。
3. **场景组织**：Entity Component System、Scene Graph、组件系统。
4. **多线程**：渲染线程、资源加载线程、任务系统。
5. **图形 API**：OpenGL、DirectX、Vulkan、Metal 的抽象层。
6. **工具链**：编辑器、资源导入、热重载、调试可视化。

可以提到的开源方向包括 Qt、Chromium、Electron、Godot、Ogre、bgfx、Dear ImGui、SDL 等。重点是结合岗位说明自己关注过 UI 框架、消息循环、渲染管线、资源管理还是跨平台抽象。

## 6. 易错点

1. 不要把 PC 客户端等同于“写页面”，它还包括线程、资源、网络、升级和诊断。
2. 后台线程不要直接操作 UI 控件。
3. 客户端日志要注意隐私和磁盘占用。
4. 自动更新要有回滚和完整性校验。
5. 本地缓存要考虑版本、失效、清理和损坏恢复。

## 7. 面试回答模板

我理解 PC 客户端开发主要包括 UI 架构、事件循环、线程模型、本地资源、网络通信和工程诊断。UI 主线程负责消息循环和界面刷新，耗时的网络、磁盘、解码和计算任务要放到后台线程，完成后再切回 UI 线程更新状态。架构上可以用 MVC 或 MVVM，把 View、状态和业务逻辑拆开，避免窗口类膨胀。工程上还要关注启动速度、输入响应、CPU/内存、崩溃 dump、日志、自动更新和跨平台兼容。如果涉及图形或游戏引擎，我会重点看渲染循环、资源管理、场景组织、多线程和图形 API 抽象。
