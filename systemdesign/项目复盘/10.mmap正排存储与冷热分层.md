# 10.mmap 正排存储与冷热分层

面试里问“正排索引用 mmap 怎么做”“热冷分层怎么设计”，通常不是只想听 `mmap` API，而是想确认你是否理解内存映射文件、页缓存、数据布局、更新策略和长尾延迟。

## 1. 正排存储是什么

正排存储是按对象 id 直接取对象完整属性的结构。搜索、广告、推荐系统里常见两类索引：

1. **倒排索引**：从词、标签、类目查到一批对象 id。
2. **正排索引**：从对象 id 查到对象的属性、特征、状态、价格、质量分等。

召回阶段通常先用倒排或向量索引拿到候选 id，再用正排快速补齐候选特征，供过滤、打分和排序使用。

## 2. 为什么用 mmap

`mmap` 把文件映射到进程虚拟地址空间，应用可以像访问内存一样读取文件内容。真正的数据页由内核按需从磁盘加载到 page cache。

优点：

1. 少一次显式 `read` 到用户缓冲区的拷贝，访问路径更短。
2. 数据由内核 page cache 统一管理，多进程可共享只读页。
3. 大文件不必一次性读入内存，按页懒加载。
4. 正排如果是只读快照，访问代码可以非常简单。

代价：

1. 首次访问缺页会触发磁盘 I/O，可能造成长尾延迟。
2. 随机访问大文件会污染 page cache。
3. 文件更新、版本切换和并发读一致性要单独设计。
4. 映射区指针不能跨进程或跨版本长期保存，只能保存偏移。

## 3. 数据布局怎么设计

正排 mmap 的关键是让 `id -> offset` 尽量快：

```text
header
  magic / version / record_count / checksum

offset table
  item_id -> record_offset

record area
  record_length + encoded fields
```

常见设计：

1. **定长记录**：`offset = base + id * record_size`，查询最快，但浪费空间，不适合字段差异大的对象。
2. **偏移表 + 变长记录**：先查 offset table，再到 record area 解析，空间利用率高。
3. **分块压缩**：多个 record 组成 block，block 内压缩，减少磁盘和 page cache 占用，但增加解压成本。
4. **冷热字段拆分**：热字段单独定长或轻压缩，冷字段放变长区或远程存储。

正排文件通常用离线构建、在线只读加载。发布新版本时使用新文件映射，验证成功后原子切换指针，旧版本等请求自然结束后再释放。

## 4. 热冷分层怎么做

热冷分层的目标是：让高频访问数据留在内存和 page cache，低频数据不挤占热数据。

常见方案：

1. **热数据常驻内存**：Top 热门对象的关键字段放进本地内存 hash table 或数组。
2. **温数据 mmap**：多数可查询对象放 mmap 正排，依赖 page cache。
3. **冷数据远端存储**：极低频对象走 Redis、KV、对象存储或数据库兜底。
4. **热字段拆分**：点击率、价格、库存、状态等高频字段和大文本、图片、历史特征拆开。
5. **预热机制**：服务启动或版本切换后，对热门 id 顺序访问，提前把页加载进 page cache。
6. **淘汰策略**：本地热缓存按 LFU/LRU/TinyLFU 维护，定期根据访问日志重算热度。

## 5. 更新和一致性

mmap 正排适合读多写少。更新方式通常有两类：

1. **全量快照切换**：离线构建新文件，校验后原子替换，适合日级或小时级更新。
2. **增量 delta 层**：主文件只读，增量更新写入内存表、Redis 或小文件，查询时先查 delta，再查主文件。

需要注意：

1. 不要直接原地改 mmap 大文件中的变长记录，容易破坏并发读一致性。
2. 版本切换使用 `shared_ptr`、RCU 或引用计数保护旧映射生命周期。
3. 文件头保存版本、长度、校验和，防止读到半文件或错误版本。
4. 线上回滚要保留最近几个快照版本。

## 6. 易错点

1. `mmap` 不等于所有数据都在内存里，缺页仍然可能触发磁盘 I/O。
2. 访问 mmap 地址时可能收到 `SIGBUS`，例如映射后文件被截断。
3. 指针不能写入文件持久化，重启后地址会变，应该存 offset。
4. 大量随机访问会导致 page cache 抖动，必要时要预热、冷热拆分或加本地缓存。
5. 多线程读取只读 mmap 通常安全，但版本切换和资源释放必须同步。

## 7. 真实场景应用

广告召回系统中，mmap 正排适合存候选广告的静态或准静态特征：

1. 广告 id、主类目、投放状态、预算状态、质量分。
2. 模型需要的离散特征编码。
3. 召回后快速过滤不可投放广告。
4. 热门广告常驻内存，长尾广告走 mmap 或远端 KV。

这样能把在线路径从“每个候选都查数据库/Redis”变成“本地内存或本地文件页访问”，显著降低延迟和远程依赖压力。

## 8. 面试回答模板

mmap 正排适合读多写少的大规模本地索引。文件里一般有 header、offset table 和 record area，查询时根据 id 找 offset，再解析对应 record。它的优势是利用 page cache、减少显式拷贝、支持大文件按需加载；风险是缺页长尾、page cache 抖动和版本切换一致性。工程上会做冷热分层：热字段和热点对象放本地内存，温数据放 mmap，冷数据走远端 KV；更新采用离线构建新快照后原子切换，必要时叠加增量 delta 层。
