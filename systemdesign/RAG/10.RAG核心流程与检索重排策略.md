# RAG 核心流程与检索策略详解

## 1. 问题背景

RAG（Retrieval-Augmented Generation）是当前大模型应用的主流架构，通过检索外部知识库增强生成质量。用户提问涉及 RAG 完整流程、文档处理后续步骤、检索策略以及重排机制。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  RAG 核心流程全景：                                         │
│                                                             │
│  文档加载 → 文本分割 → 向量化 → 索引存储                   │
│      ↓                                                    │
│  查询处理 → 检索召回 → 重排 → 生成回答                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 |
|------|------|
| 检索结果不相关 | 召回的文档与问题关联度低 |
| 上下文过长 | 切分不合理导致关键信息被切断 |
| 回答幻觉 | 检索质量差导致模型生成错误内容 |
| 延迟高 | 检索+生成链路耗时长 |

---

## 3. 影响范围

- 客服机器人、知识库问答、文档检索系统

## 5. 解决方案

### 5.1 混合检索实现

```python
class HybridRetriever:
    """
    混合检索器：结合关键词检索和语义检索
    """
    def __init__(self, vector_db, bm25_index):
        self.vector_db = vector_db
        self.bm25_index = bm25_index
    
    def retrieve(self, query: str, top_k: int = 10) -> list:
        # 1. 语义检索
        semantic_results = self.vector_db.search(
            query_embedding=self.embed(query),
            top_k=top_k
        )
        
        # 2. 关键词检索
        bm25_results = self.bm25_index.search(query, top_k)
        
        # 3. 融合结果
        # RRF (Reciprocal Rank Fusion)
        fused_scores = {}
        k = 60  # RRF 参数
        
        for rank, doc in enumerate(semantic_results):
            doc_id = doc['id']
            fused_scores[doc_id] = fused_scores.get(doc_id, 0) + 1 / (k + rank + 1)
        
        for rank, doc in enumerate(bm25_results):
            doc_id = doc['id']
            fused_scores[doc_id] = fused_scores.get(doc_id, 0) + 1 / (k + rank + 1)
        
        # 按分数排序
        sorted_docs = sorted(fused_scores.items(), key=lambda x: x[1], reverse=True)
        return sorted_docs[:top_k]
```

### 5.2 重排机制详解

```python
class Reranker:
    """
    Cross-Encoder 重排
    """
    def __init__(self, model_name="cross-encoder/ms-marco-MiniLM-L-12-v2"):
        from sentence_transformers import CrossEncoder
        self.model = CrossEncoder(model_name)
    
    def rerank(self, query: str, documents: list[str], top_k: int = 5):
        """
        使用 Cross-Encoder 对文档进行精细化排序
        
        与 Bi-Encoder 双塔模型的区别：
        - 双塔：query 和 doc 分别编码，在向量空间计算相似度
        - Cross-Encoder：query 和 doc 一起输入 encoder，输出相关性分数
        """
        # 构建 query-doc 对
        pairs = [(query, doc) for doc in documents]
        
        # 批量预测相关性分数
        scores = self.model.predict(pairs)
        
        # 按分数排序
        ranked_indices = sorted(range(len(scores)), key=lambda i: scores[i], reverse=True)
        
        return [documents[i] for i in ranked_indices[:top_k]]
```

## 6. 可选方案对比

| 方案 | 适用场景 | 优点 | 缺点 |
|------|----------|------|------|
| 纯向量检索 | 语义相似场景 | 语义理解强 | 专有名词召回差 |
| BM25 | 精确匹配场景 | 精确匹配 | 无语义理解 |
| 混合检索+RRF | 通用场景 | 综合两者优势 | 权重调优复杂 |
| 混合检索+重排 | 高精度场景 | 精度最高 | 延迟增加 |

---

## 7. 推荐方案

生产环境推荐：**混合检索 + Cross-Encoder 重排**

```yaml
# RAG 配置推荐
retrieval:
  # 混合检索
  hybrid:
    semantic_weight: 0.7
    keyword_weight: 0.3
    fusion: rrf  # Reciprocal Rank Fusion
  
  # 重排
  rerank:
    enabled: true
    model: cross-encoder/ms-marco-MiniLM-L-12-v2
    top_k: 5  # 重排后保留数量
  
  # 生成
  generation:
    context_limit: 4096  # token 上限
    prompt_template: "请根据以下参考文档回答问题..."
```

    base_retriever=ensemble_retriever,

)

## 9. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 向量检索质量差 | 召回不相关 | 优化 embedding 模型 |
| BM25 专有名词误召回 | 精确匹配反而差 | 混合检索权重调优 |
| 重排延迟高 | 响应慢 | 限制重排候选数量 |
| 上下文超限 | 关键信息丢失 | 动态上下文压缩 |

## 11. 总结

1. **RAG 核心流程**：文档加载 → 文本分割 → 向量化 → 索引存储 → 查询向量化 → 检索召回 → 重排 → 生成
2. **检索策略**：关键词检索（BM25）、语义检索（向量）、混合检索（RRF 融合）
3. **重排机制**：Cross-Encoder 相比双塔模型精度更高，但延迟更大
4. **推荐方案**：混合检索 + Cross-Encoder 重排
5. **核心优化**：根据场景调优混合权重、重排候选数量、上下文限制
