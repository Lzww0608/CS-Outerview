# 1. 恶意网址识别

恶意网址识别是安全风控问题，不只是字符串匹配。目标是在用户访问、内容发布、消息传播或广告投放前，判断 URL 是否涉黄、诈骗、钓鱼、木马、恶意跳转或违规内容，并给出拦截、审核或放行决策。

## 1. 识别流程

典型流程：

```text
URL 输入
-> 规范化
-> 黑白名单和规则匹配
-> 域名/IP/证书/WHOIS 特征
-> 页面抓取和跳转链分析
-> 内容识别和模型打分
-> 风险决策
-> 人工审核与反馈闭环
```

规范化是第一步，否则攻击者可以通过大小写、编码、短链、跳转、默认端口、路径混淆绕过检测。

常见规范化包括：

1. 转小写域名，处理 punycode 和国际化域名。
2. URL decode，处理 `%2f`、多重编码、空白字符。
3. 去掉默认端口，例如 `:80`、`:443`。
4. 解析短链和多级 302 跳转。
5. 抽取主域、子域、路径、query 参数和 fragment。

## 2. 规则和名单

规则适合高确定性、低延迟判断：

1. **黑名单**：已知恶意域名、URL、IP、证书指纹、短链落地页。
2. **白名单**：可信大站、内部域名、已审核合作方。
3. **关键词规则**：涉黄、诈骗、博彩、仿冒品牌词。
4. **URL 结构规则**：超长域名、异常子域、混淆字符、可疑 TLD、IP 直连。
5. **跳转规则**：短时间多级跳转、跳转到高风险域名、Referer 绕过。

名单查询可以使用 HashSet、布隆过滤器、Trie、前缀树或本地缓存。大规模黑名单可以放在 Redis/本地内存，更新通过消息或配置中心推送。

## 3. 特征工程和模型

只靠名单会漏掉新域名。更完整的方案会做特征打分：

1. **域名特征**：注册时长、注册商、WHOIS 隐私保护、TTL、解析变更频率。
2. **IP 特征**：ASN、机房、历史恶意 IP、同 IP 站点风险。
3. **证书特征**：证书颁发机构、SAN 数量、证书年龄、证书复用情况。
4. **URL 文本特征**：长度、数字比例、特殊字符比例、品牌词编辑距离。
5. **页面内容特征**：标题、正文、表单、二维码、图片 OCR、JS 混淆、下载链接。
6. **行为特征**：用户举报、传播速度、点击来源、账号画像、历史封禁关系。

模型可以从轻到重：

1. 规则 + 逻辑回归/GBDT：解释性好，工程成本低。
2. 文本分类模型：识别标题、正文、URL token 中的风险语义。
3. 图模型：分析域名、IP、证书、账号、设备之间的关联团伙。
4. 多模态模型：结合截图、OCR、页面文本和 URL 特征。

## 4. 实时和离线结合

实时链路要快，离线链路要准：

1. **实时拦截**：名单、规则、轻量模型，本地缓存优先，毫秒级返回。
2. **异步深度检测**：爬虫抓取页面、执行 JS、分析跳转链、截图 OCR。
3. **人工审核**：对模型低置信度或高影响 URL 进入审核队列。
4. **反馈闭环**：举报、误杀申诉、审核结果回流训练集和黑白名单。

对于高风险但不确定的 URL，可以先做“灰度处置”：展示安全提示、禁止自动跳转、限制传播范围，而不是直接永久封禁。

## 5. 易错点

1. URL 不规范化就匹配，容易被编码、大小写、短链和跳转绕过。
2. 只看域名不够，同一域名下不同路径可能风险不同。
3. 只靠页面文本会漏掉图片二维码、截图式诈骗页和 JS 动态渲染内容。
4. 黑名单有滞后性，必须配合新域名和行为特征识别。
5. 风控系统要关注误杀率，不能只追求召回率。

## 6. 面试回答模板

我会把恶意网址识别设计成“规范化 + 名单规则 + 特征模型 + 异步审核”的体系。请求进来先做 URL decode、域名归一化、短链展开和跳转链解析；再查黑白名单、布隆过滤器和规则；命中不了时抽取域名、IP、证书、URL 文本、页面内容、传播行为等特征做模型打分。实时链路用轻量规则和模型保证低延迟，深度爬取、OCR、多跳跳转和人工审核放到异步链路。最终要有误杀申诉和审核反馈闭环，把新样本回流到名单和模型中。
