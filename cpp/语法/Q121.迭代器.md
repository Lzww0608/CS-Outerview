# Q121.迭代器

C++ 标准库定义了 5 种**迭代器类别 (Iterator Categories)**。这些类别根据迭代器支持的操作（移动、读、写能力）进行了划分，它们形成了一个**能力递增**的层次结构。算法会根据它们需要的最低迭代器能力来指定可以接受的迭代器类别。

这 5 种迭代器类别分别是：

1. **输入迭代器 (Input Iterator):**

   - **能力:** 只能向前移动 (`++`)，只能读取 (`*`，只读) 一次。它提供对序列的**单趟 (Single-pass)** 顺序只读访问。一旦递增，之前的值可能就无法访问了。
   - **支持操作:** `*` (读取), `->`, `++` (前置和后置), `==`, `!=`。
   - **典型例子:** 从输入流读取数据 (`std::istream_iterator`)，用于只需要遍历一次读取数据的算法（如 `std::find`, `std::accumulate`）。

2. **输出迭代器 (Output Iterator):**

   - **能力:** 只能向前移动 (`++`)，只能写入 (`* = value`) 一次。它提供对序列的**单趟 (Single-pass)** 顺序只写访问。
   - **支持操作:** `*it = value` (写入), `++` (前置和后置)。注意：对输出迭代器解引用 (`*it`) 后立即赋值，且通常不期望能读回刚写入的值。`==`, `!=` 的支持是有限的（通常只用于判断是否到达末尾）。
   - **典型例子:** 向输出流写入数据 (`std::ostream_iterator`), 插入迭代器 (`std::back_inserter`, `std::front_inserter`, `std::inserter`)，用于只需要遍历一次写入数据的算法（如 `std::copy` 的输出）。

3. **前向迭代器 (Forward Iterator):**

   - **能力:** 可以向前移动 (`++`)，可以多次读取 (`*`) 或写入 (`* = value`, 如果不是 const 迭代器)。它提供对序列的**多趟 (Multi-pass)** 顺序读写访问。你可以保存一个前向迭代器的副本，稍后用它从相同位置重新开始遍历。
   - **支持操作:** 包含所有输入迭代器的操作（`*` 读, `->`, `++`, `==`, `!=`），并且如果可写，则支持输出迭代器的写操作 (`* = value`)。关键在于**可以多次解引用同一个迭代器位置获取相同的值**（只要序列未改变）。
   - **典型例子:** `std::forward_list`, `std::unordered_set`, `std::unordered_map` 的迭代器，大部分不需要反向遍历的算法（如 `std::replace`）的最低要求。

4. **双向迭代器 (Bidirectional Iterator):**

   - **能力:** 具备前向迭代器的所有能力，并且增加了**向后移动 (--)** 的能力。
   - **支持操作:** 包含所有前向迭代器的操作，并增加了 `--` (前置和后置) 操作。
   - **典型例子:** `std::list`, `std::set`, `std::map` 的迭代器。用于需要双向遍历的算法（如 `std::reverse`）。

5. **随机访问迭代器 (Random Access Iterator):**

   - **能力:** 具备双向迭代器的所有能力，并且增加了**常数时间内的任意步长移动**和**访问**的能力（像指针一样）。

   - 支持操作:

     包含所有双向迭代器的操作，并增加了：

     - 算术运算：`it + n`, `n + it`, `it - n`
     - 复合赋值：`it += n`, `it -= n`
     - 下标访问：`it[n]` (等价于 `*(it + n)`)
     - 比较：`<`, `>`, `<=`, `>=`
     - 两个迭代器相减得到距离：`it2 - it1`

   - **典型例子:** `std::vector`, `std::deque`, `std::array`, `std::string` 的迭代器，以及原始的 C 风格指针。用于需要高效随机访问的算法（如 `std::sort`, `std::binary_search`）。

## STL 容器迭代器表现

面试里除了问迭代器类别，还常追问不同容器在插入、删除、扩容后的迭代器表现。核心原则是：连续内存容器容易因为搬迁导致迭代器失效，节点式容器通常只让被删除节点的迭代器失效，哈希容器还要额外考虑 rehash。

| 容器 | 典型迭代器类别 | 查找复杂度 | 插入/删除后的迭代器表现 |
| --- | --- | --- | --- |
| `vector` | 随机访问迭代器 | 未排序 `O(n)`，排序后二分 `O(log n)` | 扩容会导致所有迭代器、指针、引用失效；未扩容时，插入点及其后的迭代器失效；`erase` 位置及其后的迭代器失效 |
| `string` | 随机访问迭代器 | 子串查找通常和模式长度、文本长度相关 | 规则类似 `vector`，容量变化后原迭代器失效 |
| `array` | 随机访问迭代器 | 未排序 `O(n)`，排序后二分 `O(log n)` | 固定容量，不存在扩容；元素替换不影响迭代器 |
| `deque` | 随机访问迭代器 | 按值查找 `O(n)`，按下标访问 `O(1)` | 中间插删通常会使迭代器失效；两端插入对引用影响较小，但迭代器失效规则比 `vector` 更复杂，面试中不要承诺完全稳定 |
| `list` | 双向迭代器 | `O(n)` | 插入不影响其他迭代器；删除只使被删元素的迭代器失效 |
| `forward_list` | 前向迭代器 | `O(n)` | 插入不影响其他迭代器；删除只使被删元素的迭代器失效，常用 `erase_after` |
| `map/set` | 双向迭代器 | `O(log n)` | 红黑树节点式结构，插入不影响已有迭代器；删除只使被删元素的迭代器失效 |
| `unordered_map/unordered_set` | 前向迭代器 | 平均 `O(1)`，最坏 `O(n)` | 插入如果触发 rehash，会使所有迭代器失效；删除只使被删元素迭代器失效；引用和指针通常仍指向节点，除非节点被删除 |
| `stack/queue/priority_queue` | 不提供普通迭代器 | 只能通过适配器接口访问 | 容器适配器不暴露遍历迭代器，不能按普通容器方式循环访问 |

循环删除时要使用删除函数返回的新迭代器：

```cpp
for (auto it = v.begin(); it != v.end(); ) {
    if (needErase(*it)) {
        it = v.erase(it);
    } else {
        ++it;
    }
}
```

对于 `map`、`set`、`unordered_map` 等容器，C++11 以后 `erase(iterator)` 也会返回下一个迭代器，可以使用同样写法。不要在 `erase(it)` 之后继续对旧的 `it` 做 `++it`，旧迭代器已经失效。

## 如何设计一个迭代器

设计迭代器的核心是让容器的遍历方式和算法解耦。算法不需要知道底层是数组、链表还是树，只要迭代器满足相应类别的操作约定即可。

以 `vector` 为例，迭代器可以直接使用原始指针：

```cpp
template <class T>
class SimpleVector {
public:
    using iterator = T*;
    using const_iterator = const T*;

    iterator begin() { return data_; }
    iterator end() { return data_ + size_; }
    const_iterator begin() const { return data_; }
    const_iterator end() const { return data_ + size_; }

private:
    T* data_ = nullptr;
    size_t size_ = 0;
};
```

如果要手写一个封装迭代器，至少要定义解引用、移动、比较和必要的 traits：

```cpp
template <class T>
class VectorIterator {
public:
    using iterator_category = std::random_access_iterator_tag;
    using value_type = T;
    using difference_type = std::ptrdiff_t;
    using pointer = T*;
    using reference = T&;

    explicit VectorIterator(T* p = nullptr) : p_(p) {}

    reference operator*() const { return *p_; }
    pointer operator->() const { return p_; }

    VectorIterator& operator++() {
        ++p_;
        return *this;
    }

    VectorIterator operator++(int) {
        VectorIterator old(*this);
        ++(*this);
        return old;
    }

    VectorIterator& operator--() {
        --p_;
        return *this;
    }

    VectorIterator operator+(difference_type n) const {
        return VectorIterator(p_ + n);
    }

    difference_type operator-(const VectorIterator& other) const {
        return p_ - other.p_;
    }

    bool operator==(const VectorIterator& other) const {
        return p_ == other.p_;
    }

    bool operator!=(const VectorIterator& other) const {
        return !(*this == other);
    }

private:
    T* p_;
};
```

前置 `++it` 返回自增后的自身引用；后置 `it++` 的 `int` 参数只是区分签名的哑元参数，需要先保存旧值，再自增，最后返回旧值。因此迭代器循环里通常推荐 `++it`，语义更直接，也避免不必要的旧值拷贝。

不同容器的迭代器设计重点不同：

1. `vector/string/array`：连续内存，迭代器可近似指针，支持随机访问。
2. `list`：迭代器保存节点指针，`++` 走 `next`，`--` 走 `prev`，不支持 `it + n`。
3. `map/set`：迭代器保存树节点指针，`++` 找中序后继，`--` 找中序前驱。
4. `unordered_map`：迭代器要能在 bucket 和链表/节点之间移动，rehash 后迭代器会失效。

易错点：

1. `end()` 是尾后位置，不能解引用。
2. `const_iterator` 表示不能通过迭代器修改元素，不等于迭代器对象本身不能自增。
3. 迭代器失效规则由容器结构决定，不能跨容器套用。
4. 自定义迭代器要保证 `iterator_traits` 能提取类型，否则很多标准算法无法正确选择实现。

## 为什么 STL 算法既能接收迭代器也能接收指针

STL 算法通常写成函数模板，只要求参数满足某类迭代器操作，而不是要求参数必须来自某个容器。原始指针天然支持 `*p`、`++p`、`p + n`、`p2 - p1`、比较等操作，所以它可以满足随机访问迭代器的要求。

```cpp
int a[] = {3, 1, 2};
std::sort(a, a + 3);              // 原始指针

std::vector<int> v = {3, 1, 2};
std::sort(v.begin(), v.end());    // 容器迭代器
```

背后的机制主要有三点：

1. **模板泛型编程**：算法只在编译期检查表达式是否可用，满足接口约定即可工作。
2. **`iterator_traits`**：标准库通过 traits 提取 `value_type`、`difference_type`、`iterator_category` 等信息，并对原始指针提供了特化。
3. **静态多态**：不同迭代器类型在编译期生成对应代码，没有虚函数调用开销。

这也是为什么同一份算法代码能处理 `vector<int>::iterator`、`deque<int>::iterator` 和 `int*`。但算法仍然有能力要求，例如 `std::sort` 需要随机访问迭代器，所以 `list` 的迭代器不能直接传给 `std::sort`，应使用 `list::sort()`。

**总结:**

这个分类形成了一个层次结构：

- 随机访问迭代器 **包含** 双向迭代器的所有能力。
- 双向迭代器 **包含** 前向迭代器的所有能力。
- 前向迭代器 **包含** 输入迭代器的所有能力（并且是多趟的，如果可写也支持输出迭代器的写）。
- 输入迭代器和输出迭代器是基础，主要特点是单趟性。

了解这些类别有助于理解 C++ 标准库算法对容器的要求，以及为什么某些算法不能用于某些容器（例如，`std::sort` 要求随机访问迭代器，所以不能直接用于 `std::list`）。
