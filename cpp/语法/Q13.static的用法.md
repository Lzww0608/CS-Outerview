# Static关键字用法

1. 用于函数内部修饰变量，使得该变量的生存期长于函数，使得函数具有一定的“状态”。使用静态变量的函数一般是不可重入的，也不是线程安全的。

2. 用于文件级别（函数体之外），修饰变量或函数。该变量或函数只能在本文件可见，其他文件看不到也无法访问（internal linkage)。
3. 修饰class的数据成员，即所谓“静态成员”。生存期大于class的对象，即将变量的所有权从对象转移为类，每个类只有一份。只能通过类访问，不能通过实例化的对象访问。
4. 修饰class的成员函数，即所谓“静态成员函数”。这种成员函数只能访问静态成员或者其他静态程序函数，不能访问普通成员变量和普通成员函数。

## static 变量存储在哪里

`static` 变量具有**静态存储期**，生命周期从程序开始到程序结束。它不是放在栈上，也不是每次调用函数时重新创建。

常见位置：

1. **已初始化的 static/global 变量**：放在数据段 `.data`。
2. **未初始化或初始化为 0 的 static/global 变量**：放在 `.bss`，程序加载时由系统清零。
3. **字符串字面量、部分只读常量**：通常放在只读数据段 `.rodata`。
4. **函数内 static 局部变量**：作用域在函数内部，但存储期仍然是静态存储期；C++11 起局部静态变量初始化是线程安全的。
5. **类 static 数据成员**：属于类而不是对象，本质上也是静态存储期对象，需要有定义；C++17 后 `inline static` 成员可以在类内定义。

需要区分：

1. `static` 成员函数本身不对应一个“变量存储位置”，它只是没有 `this` 指针的类成员函数，代码仍在代码段。
2. `thread_local static` 是线程局部静态存储期，每个线程一份，通常位于 TLS 区域。
3. 局部 static 的初始化时机是第一次执行到定义处，而不是程序启动时一定初始化；但它的存储空间属于静态存储。

## 函数内局部 static 在任何 C++ 版本都线程安全吗

不是。C++11 起标准保证函数内局部静态变量的初始化是线程安全的，也就是多个线程第一次同时进入函数时，只会有一个线程完成初始化，其他线程等待初始化结束。

```cpp
class Singleton {
public:
    static Singleton& instance() {
        static Singleton obj; // C++11 起初始化线程安全
        return obj;
    }
};
```

需要区分几个边界：

1. C++03 标准没有保证这个初始化过程线程安全，不同编译器可能用扩展实现。
2. C++11 只保证“初始化过程”线程安全，不保证对象成员函数的后续并发访问安全。
3. 如果使用特殊编译选项关闭线程安全静态初始化，例如 GCC/Clang 的 `-fno-threadsafe-statics`，标准保证会被破坏。
4. 如果初始化过程中递归进入同一个局部静态变量的初始化，行为不应依赖，设计上要避免。

## 不同位置的 static 有什么区别

| 位置 | 含义 | 作用域 | 生命周期 | 链接属性 |
| --- | --- | --- | --- | --- |
| 函数内 `static` 局部变量 | 局部可见，静态存储期 | 函数块内 | 程序运行期 | 无链接 |
| 文件作用域 `static` 变量 | 当前翻译单元私有全局变量 | 当前 `.cpp` 文件 | 程序运行期 | internal linkage |
| 文件作用域 `static` 函数 | 当前翻译单元私有函数 | 当前 `.cpp` 文件 | 程序运行期 | internal linkage |
| 类内 `static` 数据成员 | 属于类，不属于对象 | 类作用域 | 程序运行期 | 取决于定义 |
| 类内 `static` 成员函数 | 没有 `this` 指针 | 类作用域 | 程序运行期 | 取决于定义 |

## static 一般什么时候用

1. **函数内缓存状态**：例如计数器、单例对象、懒加载缓存。要注意线程安全和可重入性。
2. **限制符号可见性**：文件作用域 `static` 可以把辅助函数或变量限制在当前 `.cpp`，减少命名冲突。
3. **类级共享数据**：例如对象计数、全局配置、工厂注册表。
4. **静态成员函数作为工具函数**：函数不依赖具体对象状态时可以设为 `static`。
5. **Meyers Singleton**：C++11 起函数内局部静态变量初始化线程安全。

示例：

```cpp
class IdGenerator {
public:
    static int next() {
        return ++counter_;
    }

private:
    inline static int counter_ = 0; // C++17
};
```

## 静态成员函数如何访问非静态成员

`static` 成员函数没有隐藏的 `this` 指针，因此不能直接访问某个对象的非静态成员变量，也不能直接调用依赖对象状态的非静态成员函数。它想访问对象状态，必须先拿到一个明确的对象。

常见方式：

1. **显式传入对象引用或指针**：把对象作为普通参数传给静态成员函数。

```cpp
class Session {
public:
    static void reset(Session& s) {
        s.seq_ = 0;
        s.close();
    }

private:
    void close() {}
    int seq_ = 0;
};
```

2. **静态工厂或注册表中保存对象句柄**：静态函数先根据 id 找到对象，再调用对象方法。真实业务中常见于连接管理器、对象池和回调分发。

```cpp
class ConnectionManager {
public:
    static void onReadable(int fd) {
        auto it = conns_.find(fd);
        if (it != conns_.end()) {
            it->second->handleRead();
        }
    }

private:
    void handleRead() {}

    inline static std::unordered_map<int, ConnectionManager*> conns_;
};
```

3. **作为 C API 回调的 trampoline**：很多 C 风格库只接受普通函数指针，无法直接传非静态成员函数。常用做法是把 `this` 放进 `void* userdata`，静态回调中转回对象指针。

```cpp
class Timer {
public:
    void start() {
        register_timer(&Timer::onTimeout, this);
    }

private:
    static void onTimeout(void* userdata) {
        auto* self = static_cast<Timer*>(userdata);
        self->handleTimeout();
    }

    void handleTimeout() {}
};
```

如果函数天然依赖某个对象的状态，优先考虑把它设计为普通成员函数；如果它只做工具计算或类级管理，才适合设计为 `static` 成员函数。

注意点：

1. 静态函数中保存裸指针要特别注意对象生命周期，避免对象已经析构后仍被回调访问。
2. 多线程场景下，静态注册表、全局对象池等共享结构需要加锁或使用无锁结构。
3. `static` 成员函数不能实现虚函数多态，因为它没有 `this` 指针，也不会通过虚表动态分派。

## static 在编译器和链接器层面的实现

1. **静态存储期变量**：编译器把它们放入 `.data`、`.bss`、`.rodata` 或 TLS 段，程序加载时由 loader 建立映射。
2. **文件作用域 static**：符号表中通常标记为 local symbol，只在当前目标文件参与链接，不向其他翻译单元暴露。
3. **类 static 数据成员**：本质是一个带类作用域名字的全局对象。C++17 前通常需要在类外提供一次定义；`inline static` 可以在头文件类内定义。
4. **函数内 static 局部变量**：编译器生成静态存储对象，并生成 guard variable 控制“第一次执行到这里时初始化”。C++11 要求初始化线程安全，常见实现会用 guard acquire/release 或锁。
5. **static 成员函数**：没有隐藏的 `this` 参数，调用约定接近普通函数，只是名字经过 C++ name mangling 后带有类作用域信息。

## 函数内 static 容器的并发问题

C++11 只保证函数内 `static` 局部变量的**初始化过程**是线程安全的，不保证这个对象后续的读写操作天然线程安全。

例如：

```cpp
void someFunction() {
    static std::vector<int> params{111, 222, 333};

    if (FLAGS_add_exp_param) {
        params.emplace_back(444);
    }

    for (int x : params) {
        LOG(INFO) << x;
    }
}
```

这段代码的风险在于：

1. `params` 是函数级共享对象，所有线程、所有类实例调用这个函数时都会访问同一个 `vector`。
2. 一个线程 `emplace_back` 时可能触发扩容，移动底层数组；另一个线程正在遍历旧数组，会产生 data race、迭代器失效甚至崩溃。
3. 即使没有扩容，`vector` 的 `size` 和元素写入也不是并发安全的。
4. 把 `static` 去掉可以让每次调用都有局部副本，从而避免共享写，但会带来重复构造、重复拷贝和状态无法跨调用复用的问题。

常见改法：

1. **不可变初始化**：如果参数集合固定，初始化后不再修改，把它设计成 `const static` 或只读表。
2. **互斥锁保护**：如果必须修改，用同一把静态锁保护 `vector` 的读写，锁要和共享数据具有同样的共享范围。
3. **读写锁**：读多写少时读路径用共享锁，写路径用独占锁。
4. **Copy-On-Write 快照**：构造新 `vector` 后原子替换 `shared_ptr<const vector<int>>`，读路径只读快照。
5. **线程局部副本**：如果每个线程可以独立维护状态，用 `thread_local static`，但要接受线程间状态不共享。

示例：

```cpp
#include <mutex>
#include <vector>

void someFunction() {
    static std::vector<int> params{111, 222, 333};
    static std::mutex mu;

    std::lock_guard<std::mutex> lock(mu);
    if (FLAGS_add_exp_param) {
        params.emplace_back(444);
    }

    for (int x : params) {
        LOG(INFO) << x;
    }
}
```

如果遍历耗时较长，可以在锁内复制快照，锁外遍历，减少锁持有时间：

```cpp
std::vector<int> snapshot;
{
    std::lock_guard<std::mutex> lock(mu);
    snapshot = params;
}
for (int x : snapshot) {
    LOG(INFO) << x;
}
```

## 头文件里加 static 和不加 static 的区别

头文件会被预处理器复制到每一个包含它的 `.cpp` 文件中，所以在 `.h` 里写文件作用域变量或函数时，核心问题不是“语法能不能过”，而是**每个翻译单元到底得到同一个实体，还是各自得到一份实体**。

示例：

```cpp
// config.h
static int counter = 0;
static void helper() {}
```

每个包含 `config.h` 的 `.cpp` 都会得到自己私有的 `counter` 和 `helper`，它们是 internal linkage，不参与跨翻译单元合并。这可以避免链接期多重定义，但也会带来“看起来是全局变量，实际每个 `.cpp` 一份”的问题。

如果不加 `static`：

```cpp
// config.h
int counter = 0;     // 错误用法：多个 .cpp 包含后通常会多重定义
void helper() {}     // 错误用法：非 inline 函数定义放头文件也会多重定义
```

多个翻译单元会各自生成一个 external linkage 的定义，链接时容易报 `multiple definition`。正确写法通常是头文件声明、源文件定义：

```cpp
// config.h
extern int counter;
void helper();

// config.cpp
int counter = 0;
void helper() {}
```

C++17 以后，如果确实希望把变量定义放到头文件并在所有翻译单元中表示同一个实体，可以使用 `inline` 变量：

```cpp
// config.h
inline int counter = 0;
inline void helper() {}
```

面试里可以这样区分：

1. `.h` 中的文件作用域 `static`：每个包含者各有一份，避免链接冲突，但状态不共享。
2. `.h` 中的非 `static` 定义：多个翻译单元包含后容易违反 ODR，产生多重定义。
3. `.h` 中的 `extern` 声明：只声明不定义，真实定义放一个 `.cpp`。
4. `.h` 中的 `inline` 函数或 `inline` 变量：允许多个翻译单元看到定义，由链接器按 ODR 合并为同一个实体。

## 易错点

1. 函数内 `static` 局部变量不是每次调用重新初始化。
2. 文件作用域 `static` 和类内 `static` 不是一个概念：前者控制链接可见性，后者表示类级成员。
3. `static` 成员函数不能直接访问非静态成员，因为没有 `this` 指针。
4. 头文件里定义非 `inline` 的 static 数据成员容易引发多重定义或每个翻译单元一份的问题，要区分 internal linkage 和 ODR。
5. 头文件中的文件作用域 `static` 虽然不报多重定义，但每个 `.cpp` 一份状态，做全局计数器、注册表或配置时很容易得到错误结果。
6. 函数内 `static` 对象初始化线程安全，不等于对象后续操作线程安全；`static vector` 被多线程读写仍然要加锁、快照化或避免共享修改。
