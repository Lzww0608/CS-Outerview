# Q163. C++模板基础与实例化

C++ 模板是泛型编程的基础。它允许把类型、常量或模板本身作为参数，让同一份代码在编译期生成适配不同类型的具体实现。

## 1. 函数模板

函数模板用于描述一类函数：

```cpp
template <typename T>
T maxValue(const T& a, const T& b) {
    return a < b ? b : a;
}
```

调用时编译器会根据实参类型做模板参数推导：

```cpp
int a = maxValue(1, 2);          // T = int
double b = maxValue(1.0, 2.0);   // T = double
```

模板参数推导通常不考虑返回值，只看函数实参、显式模板参数和上下文约束。

## 2. 类模板

类模板用于生成一族类型：

```cpp
template <typename T>
class Box {
public:
    explicit Box(T value) : value_(value) {}
    const T& value() const { return value_; }

private:
    T value_;
};

Box<int> a(1);
Box<std::string> b("hello");
```

`Box<int>` 和 `Box<std::string>` 是两个不同类型。模板本身不是类型，模板实例化之后才形成具体类型。

## 3. 非类型模板参数

模板参数不只能是类型，也可以是编译期常量：

```cpp
template <typename T, std::size_t N>
class Array {
public:
    T data[N];
};

Array<int, 16> arr;
```

常见场景包括固定大小数组、对齐值、哈希桶数量、矩阵维度等。非类型模板参数必须能在编译期确定。

## 4. 模板实例化

模板实例化分为隐式实例化和显式实例化：

1. **隐式实例化**：使用某个模板实参时，编译器自动生成对应代码。
2. **显式实例化**：手动要求编译器生成某个实例，例如 `template class Box<int>;`。
3. **显式特化**：为某个类型提供专门实现，例如 `template <> class Box<bool> { ... };`。

模板通常要把定义放在头文件里。原因是编译器在实例化时需要看到完整定义；如果只有声明，其他翻译单元无法生成对应类型的代码，容易产生链接错误。

## 5. 模板和多态

模板常用于静态多态，虚函数常用于动态多态：

| 对比项 | 模板/静态多态 | 虚函数/动态多态 |
| --- | --- | --- |
| 决定时机 | 编译期 | 运行期 |
| 调用开销 | 通常可内联，无虚调用 | 需要 vptr/vtable 间接调用 |
| 代码体积 | 不同类型会生成多份实例 | 一份接口，多态派发 |
| 适合场景 | 容器、算法、数值库、策略可在编译期确定 | 插件、运行时对象集合、接口稳定扩展 |

示例：策略通过模板参数传入：

```cpp
template <typename Compare>
void sortWithPolicy(std::vector<int>& nums, Compare comp) {
    std::sort(nums.begin(), nums.end(), comp);
}
```

## 6. SFINAE、Concepts 和约束

模板错误信息可能很复杂，因为模板会在实例化时才检查具体表达式。常见约束方式：

1. **SFINAE**：替换失败不是错误，可让不满足条件的重载从候选集中移除。
2. **`std::enable_if` / type traits**：按类型性质选择模板。
3. **C++20 Concepts**：直接声明模板参数要满足的语义约束，可读性更好。

```cpp
#include <concepts>

template <std::integral T>
T addOne(T x) {
    return x + 1;
}
```

## 7. 易错点

1. 模板定义通常放头文件，不只是声明放头文件。
2. 模板不是运行期反射，它是在编译期生成代码。
3. 模板参数推导不看返回值。
4. 模板过度使用可能导致编译慢、错误信息长、二进制体积膨胀。
5. 静态多态不能替代所有动态多态，运行期才知道对象类型时仍需要虚函数、类型擦除或 `std::variant` 等方案。

## 8. 真实场景

1. STL 容器和算法大量使用模板，例如 `std::vector<T>`、`std::sort`。
2. 序列化、RPC、数学库常用模板消除运行期开销。
3. `std::function`、`std::any`、`std::variant` 等库设施在内部结合模板和类型擦除。
4. 高性能服务中，编译期策略可用模板注入，例如哈希函数、比较器、分配器。

## 9. 面试回答模板

C++ 模板是编译期泛型机制，可以写函数模板、类模板，也可以使用非类型模板参数。模板在使用具体类型时实例化，生成对应代码，所以定义通常要放在头文件里。模板支持静态多态，调用可内联、没有虚函数开销，但可能导致代码膨胀和编译变慢；虚函数是运行期多态，适合对象类型运行时才确定的场景。复杂模板可以用 SFINAE、type traits 或 C++20 Concepts 做约束。
