# Q161. C++对象构造顺序与纯虚调用

面试里围绕“子类构造时父类怎么构造”“虚表指针什么时候写入”“构造函数里调用虚函数运行谁的实现”“运行时报纯虚函数调用可能是什么原因”连续追问，本质是在考 C++ 对象生命周期和动态类型边界。

## 1. 派生类对象构造顺序

构造一个派生类对象时，顺序是固定的：

1. 分配整块对象存储空间。
2. 构造虚基类子对象，如果有虚继承。
3. 构造直接基类子对象，按基类声明顺序。
4. 构造当前类成员变量，按成员声明顺序。
5. 执行当前类构造函数体。

示例：

```cpp
struct Base {
    Base();
};

struct Derived : Base {
    int a;
    int b;
    Derived() : b(2), a(1) {}
};
```

即使初始化列表写成 `b(2), a(1)`，成员仍按声明顺序 `a` 再 `b` 初始化。初始化列表的书写顺序不决定真实初始化顺序。

## 2. 初始化列表和构造函数体的区别

初始化列表发生在对象成员真正构造阶段；构造函数体发生在成员都已经构造完成之后。

```cpp
class Foo {
public:
    Foo(int x) : value_(x) { // 初始化
        value_ = x + 1;      // 赋值
    }

private:
    int value_;
};
```

区别：

1. `const` 成员、引用成员、没有默认构造函数的成员必须在初始化列表中初始化。
2. 类类型成员如果在函数体里赋值，会先默认构造再赋值，可能多一次成本。
3. 初始化顺序按声明顺序，不按初始化列表书写顺序。
4. 构造函数体执行时，`this` 已经指向当前对象存储，并且当前构造层级的成员已经初始化。

## 3. vptr 什么时候设置

虚表通常是编译期生成的只读数据，运行时对象里保存的是虚表指针 `vptr`。

构造过程中，`vptr` 会随着构造层级变化：

1. 进入 `Base` 构造时，`vptr` 指向 `Base` 的虚表。
2. `Base` 构造完成后，进入 `Derived` 构造前或构造开始阶段，`vptr` 被调整为 `Derived` 的虚表。
3. 析构时顺序相反，先执行 `Derived` 析构，随后进入 `Base` 析构时 `vptr` 退回 `Base` 虚表。

具体指令由编译器按 ABI 生成，不建议回答成“先于所有成员绝对固定”。更稳的说法是：在某个类自己的构造函数体执行期间，虚调用会按当前构造层级的类型解析，不会派发到尚未构造完成的更派生类。

## 4. 构造函数能否是虚函数

构造函数不能是虚函数。原因不是语法限制这么简单，而是对象构造和虚派发的前提矛盾：

1. **虚调用依赖对象已经具有动态类型**：普通虚函数通过对象中的 `vptr` 找到虚表，再按真实动态类型分派。
2. **构造函数负责建立对象本身**：调用构造函数之前，对象还没有完整构造完成，派生类部分也不存在，谈不上按“最终派生类”虚派发。
3. **构造函数名字不继承**：构造函数用于初始化某个具体类，不像普通成员函数那样被派生类覆盖。
4. **创建对象需要先知道具体类型和大小**：`new Derived()` 在编译期或工厂逻辑中已经确定了要分配多少空间、调用哪个构造函数，不能靠尚未存在的对象虚表来决定。

如果业务想要“按类型动态创建对象”，常用的是工厂模式、注册表或虚 `clone()`：

```cpp
struct Base {
    virtual ~Base() = default;
    virtual Base* clone() const = 0;
};

struct Derived : Base {
    Derived* clone() const override {
        return new Derived(*this);
    }
};
```

析构函数则经常需要是虚函数，因为通过基类指针删除派生类对象时，对象已经存在，虚派发可以确保先调用派生类析构，再调用基类析构。

## 5. 构造函数中调用虚函数运行谁

```cpp
#include <iostream>

struct Base {
    Base() { f(); }
    virtual void f() { std::cout << "Base\n"; }
};

struct Derived : Base {
    void f() override { std::cout << "Derived\n"; }
};
```

构造 `Derived` 时，`Base()` 构造函数里调用 `f()`，运行的是 `Base::f()`，不是 `Derived::f()`。因为此时派生类部分还没有构造完成，动态类型被限制在当前基类构造阶段。

析构函数中同理。进入基类析构时，派生类部分已经析构完，虚调用不会派发到派生类版本。

## 6. 运行时报纯虚函数调用的可能原因

常见原因：

1. **基类构造函数调用纯虚函数**：当前阶段只能看到基类版本，而基类版本是纯虚。
2. **基类析构函数调用纯虚函数**：派生类已经析构，调用退回基类纯虚槽位。
3. **对象生命周期已结束**：悬空指针调用虚函数，`vptr` 已被破坏或退回基类状态。
4. **构造失败期间调用虚函数**：异常导致部分对象析构，回调触发纯虚调用。
5. **内存越界破坏 vptr**：对象头部被写坏，虚表跳转异常。
6. **在构造/析构间接调用**：构造函数调用普通函数，普通函数内部再调用虚函数，本质仍发生在构造阶段。

## 7. 对象内存布局

单继承多态对象常见布局：

```text
Derived object
  [vptr]
  [Base data members]
  [Derived data members]
  [padding]
```

多继承或虚继承更复杂：

1. 可能有多个基类子对象。
2. 每个多态基类子对象可能有自己的 `vptr`。
3. 通过不同基类指针看同一个完整对象时，指针值可能不同。
4. 编译器可能生成 this 调整 thunk。

标准不规定具体布局，具体由 ABI 决定；面试回答应抓住“虚表是类级别只读数据，vptr 是对象内的隐藏指针”。

## 8. 易错点

1. 初始化列表顺序不决定成员初始化顺序，声明顺序才决定。
2. 构造函数体执行前，基类和成员已经构造完成。
3. 构造/析构期间虚调用不会派发到更派生类。
4. 不要在构造/析构函数中调用纯虚函数。
5. `vptr` 不是虚表本身，虚表通常不在对象内。
6. 多继承下对象可能有多个 `vptr`，不要把单继承结论泛化。

## 9. 面试回答模板

派生类构造时先分配整块对象存储，再构造虚基类、直接基类、成员变量，最后执行派生类构造函数体；成员初始化顺序按声明顺序，不按初始化列表书写顺序。虚表是编译器生成的类级别只读数据，对象里保存 `vptr`。构造过程中 `vptr` 会按当前构造层级设置，基类构造阶段指向基类虚表，派生类构造阶段再指向派生类虚表。因此构造函数或析构函数里调用虚函数，不会派发到更派生类版本。运行时报纯虚函数调用，常见原因是基类构造/析构中直接或间接调用纯虚函数，或者对象生命周期结束、内存越界破坏了 `vptr`。
