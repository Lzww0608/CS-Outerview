## 默认成员函数

### 1.八大类

> 默认构造函数
>
> 默认拷贝构造函数
>
> 默认析构函数
>
> 默认重载赋值运算符函数
>
> 默认重载取地址运算符函数
>
> 默认重载取地址运算符const函数
>
> 默认移动构造函数
>
> 默认重载移动赋值操作符函数

```c++
class MyClass
{
public:
    MyClass();  // 默认构造函数 
    MyClass(const MyClass &);  // 默认拷贝构造函数
    ~MyClass();  // 默认析构函数
    MyClass& operator =(const MyClass &);  // 默认重载赋值运算符函数
    MyClass* operator &();  // 默认重载取址运算符函数
    MyClass const * operator &() const;  // 默认重载取址运算符const函数
    MyClass(MyClass &&);  // 默认移动构造函数
    MyClass& operator=(MyClass &&);  // 默认重载移动赋值操作符函数
};
```

1. **默认构造函数**

   C++ 默认构造函数是对类中的参数提供默认值的构造函数。如果用户没有定义构造函数，那么编译器会给类提供一个默认的构造函数，但是只要用户自定义了任意一个构造函数，那么编译器就不会提供默认的构造函数。在C++11中可通过=default显式指定采用默认构造函数。

2. **默认拷贝构造函数**

   当类中没有定义拷贝构造函数时，编译器会默认提供一个拷贝构造函数，进行成员变量之间的拷贝。具体来说，编译器会直接使用"="进行值拷贝。一般类型中，"="的行为是值拷贝，而成员中有指针类型时，则会指复制指针，不复制指针指向的内容，产生浅拷贝。进一步，当类中某些成员的赋值运算符函数"="被delete掉（如unique_ptr、std::atomic等，或其他自定义类型），无法调用时，编译器将无法提供默认拷贝构造函数。例子见后文。

3. **默认析构函数**

4. **默认重载赋值运算符函数**

   当程序没有显式地提供一个以本类或本类的引用为参数的赋值运算符重载函数时，编译器会自动生成这样一个赋值运算符重载函数。默认重载赋值运算符函数与默认拷贝构造函数的行为类似，编译器会直接使用"="进行值拷贝，当类中某些成员的赋值运算符函数"="被delete掉时，编译器将无法提供默认的重载赋值运算符函数。

5. **默认重载取地址运算符函数**

   如果没有显式定义，编译器会自动生成默认的重载取址运算符函数，函数内部直接return this，一般使用默认即可。

6. **默认重载取地址运算符const函数**

   与重载取址运算符函数类似，取地址后返回const类型

7. **默认移动构造函数（C++11）**

   满足以下条件时，编译器将生成默认的移动构造函数：

   1）没有用户声明的复制构造函数
   2）没有用户声明的复制赋值运算符,
   3）没有用户声明的移动赋值运算符,
   4）没有用户声明的析构函数
   5）移动构造函数不会被隐式定义为已删除.

   当类中某些成员的赋值运算符函数"="被delete掉（如unique_ptr，std::atomic等，或其他自定义类型），无法调用时，编译器将无法提供默认移动构造函数

8. **默认重载移动赋值运算符操作函数**（C++11)

   默认重载移动赋值操作符函数的行为与默认移动构造函数的行为类似，不再赘述。

### 2.默认拷贝构造函数

```c++
#include <cstdlib>
#include <iostream>
#include <string>
#include<vector>
#include<atomic>
using namespace std;
class A
{
public:
	A() = default;
	A(const A& a) {
		cout << "A& called" << endl;
	}
	A(A&& a) {
		cout << "A&& called" << endl;
	}
};
class B
{
public:
	B() = default;
	B(const B& a) {
		cout << "B& called" << endl;
	}
	B(B&& a) {
		cout << "B&& called" << endl;
	}
};
class C
{
public:
	A a;
	B b;
	string str;
	vector<int> vec;
	//atomic<int>x; 报这个错误的主要原因是原子变量不能使用拷贝构造。这个限制只在原子变量初始时生效，初始之后时可以使用赋值操作符的。
};
int main()
{
	C q;
	q.str = "123456";
	q.vec.resize(100);
	C w(q);
	system("pause");
	return 0;
}
```

### 2.默认移动构造函数

```c++
int main()
{
	C q;
	q.str = "123456";
	q.vec.resize(100);
	C w(std::move(q));
	system("pause");
	return 0;
}
```

### 3. 不写拷贝构造函数时编译器一定会生成吗

不一定。更准确地说，编译器会先尝试**隐式声明**拷贝构造函数；只有当成员和基类都能被拷贝时，它才会形成一个可用的、隐式定义的拷贝构造函数。如果某些成员或基类不可拷贝，这个拷贝构造函数会被定义为 deleted，调用时编译失败。

常见规则：

1. 如果没有用户声明的拷贝构造函数，编译器会隐式声明一个拷贝构造函数。
2. 如果类成员或基类的拷贝构造不可访问、被删除或不存在，则该隐式拷贝构造会被定义为 deleted。
3. 如果类包含 `std::unique_ptr`、`std::mutex`、`std::atomic<T>` 等不可拷贝成员，默认拷贝构造通常不可用。
4. 用户声明了移动构造或移动赋值后，拷贝构造/拷贝赋值的隐式生成规则会受影响，容易出现拷贝能力被删除的情况。
5. 有裸指针成员时，默认拷贝构造即使可用，也只是浅拷贝，不会自动深拷贝指针指向的资源。

示例：

```cpp
#include <memory>

struct A {
    int x;
};

struct B {
    std::unique_ptr<int> p;
};

int main() {
    A a1;
    A a2 = a1; // 可以，默认成员拷贝

    B b1;
    // B b2 = b1; // 编译失败：unique_ptr 不可拷贝，B 的拷贝构造被删除
}
```

面试回答可以这样组织：编译器不是“无条件生成一个可调用的拷贝构造”。没有手写时，它会根据成员和基类情况隐式声明并按成员逐个拷贝；如果某个子对象不可拷贝，这个函数会被删除。对于拥有资源的类，应该遵守 Rule of Three/Five/Zero：要么自己定义拷贝、赋值、析构实现深拷贝，要么删除拷贝只允许移动，要么把资源交给 RAII 成员让编译器默认生成正确行为。

### 3.1 什么时候需要重载拷贝构造函数

默认拷贝构造是逐成员拷贝。只有当“逐成员拷贝”不能表达正确所有权或不变量时，才需要自己定义拷贝构造函数。

常见需要手写的情况：

1. **类直接管理资源**：成员里有裸指针、文件描述符、socket、GPU buffer、OpenCV 外部句柄等，需要定义如何复制资源。
2. **需要深拷贝**：两个对象不能共享同一块堆内存，否则会重复释放或互相修改。
3. **需要维护不变量**：拷贝后缓存、索引、引用计数、统计字段、互斥锁状态不能简单照抄。
4. **需要禁止拷贝**：独占资源应删除拷贝构造和拷贝赋值，只允许移动。
5. **多态拷贝**：通过基类接口复制派生对象时，通常使用虚函数 `clone()`，避免对象切片。

示例：

```cpp
class ImageBuffer {
public:
    ImageBuffer(std::size_t n) : size_(n), data_(new unsigned char[n]) {}

    ImageBuffer(const ImageBuffer& other)
        : size_(other.size_), data_(new unsigned char[other.size_]) {
        std::copy(other.data_, other.data_ + size_, data_);
    }

    ImageBuffer& operator=(const ImageBuffer& other) {
        if (this == &other) {
            return *this;
        }
        ImageBuffer tmp(other);
        swap(tmp);
        return *this;
    }

    ~ImageBuffer() {
        delete[] data_;
    }

    void swap(ImageBuffer& other) noexcept {
        std::swap(size_, other.size_);
        std::swap(data_, other.data_);
    }

private:
    std::size_t size_ = 0;
    unsigned char* data_ = nullptr;
};
```

现代 C++ 更推荐 Rule of Zero：把资源放进 `std::vector`、`std::string`、`std::unique_ptr` 等 RAII 成员，让默认特殊成员函数自然正确。只有在封装底层资源、性能敏感 buffer 或跨 C API 资源时，才手写拷贝/移动/析构。

## 4. 深拷贝和浅拷贝

浅拷贝是只复制对象中的成员值。如果成员里有裸指针，浅拷贝只会复制指针地址，不会复制指针指向的资源。

```cpp
struct BadBuffer {
    char* data;
    std::size_t size;
};
```

`BadBuffer b = a;` 后，`a.data` 和 `b.data` 指向同一块内存。如果两个对象析构时都 `delete[] data`，就会重复释放；如果一个对象修改内容，另一个对象也会看到变化。

深拷贝是为新对象分配独立资源，并复制资源内容：

```cpp
#include <algorithm>
#include <cstring>

class Buffer {
public:
    Buffer(const char* s) : size_(std::strlen(s)), data_(new char[size_ + 1]) {
        std::copy(s, s + size_ + 1, data_);
    }

    Buffer(const Buffer& other)
        : size_(other.size_), data_(new char[other.size_ + 1]) {
        std::copy(other.data_, other.data_ + size_ + 1, data_);
    }

    Buffer& operator=(const Buffer& other) {
        if (this == &other) {
            return *this;
        }
        char* newData = new char[other.size_ + 1];
        std::copy(other.data_, other.data_ + other.size_ + 1, newData);
        delete[] data_;
        data_ = newData;
        size_ = other.size_;
        return *this;
    }

    ~Buffer() {
        delete[] data_;
    }

private:
    std::size_t size_ = 0;
    char* data_ = nullptr;
};
```

工程中更推荐 Rule of Zero：把资源交给 `std::string`、`std::vector`、`std::unique_ptr` 等 RAII 成员，让默认拷贝或移动语义自然正确。

易错点：

1. 有裸指针成员时，默认拷贝通常是浅拷贝。
2. 深拷贝要处理自赋值和异常安全，先分配新资源再释放旧资源更稳。
3. 独占资源对象不一定要支持深拷贝，可以删除拷贝、只允许移动，例如 `unique_ptr`。
4. `shared_ptr` 的拷贝不是深拷贝对象，而是共享同一对象并增加引用计数。

面试回答可以说：浅拷贝复制指针值，多个对象共享同一资源，容易导致重复释放和状态互相影响；深拷贝复制资源内容，新对象拥有独立资源。现代 C++ 尽量用 RAII 类型表达所有权，避免手写裸指针拷贝。

## 5. 空类会生成哪些成员

一个空类看起来没有成员，但编译器仍会隐式声明一组特殊成员函数。C++11 后常说的特殊成员包括：

1. 默认构造函数。
2. 析构函数。
3. 拷贝构造函数。
4. 拷贝赋值运算符。
5. 移动构造函数。
6. 移动赋值运算符。

传统资料还会提到取地址运算符和 const 取地址运算符，但现代面试更常按 Rule of Five/Zero 讨论上面六类特殊成员。

```cpp
class Empty {};

int main() {
    Empty a;
    Empty b(a);
    Empty c(std::move(a));
    b = c;
    c = std::move(b);
}
```

需要注意：

1. “隐式声明”不代表一定能被成功使用；如果成员或基类不可拷贝，对应函数可能被定义为 deleted。
2. 空类对象大小通常不是 0，而是 1 字节，目的是让不同对象有不同地址。
3. 空基类作为基类子对象时可能触发空基类优化，不占额外空间。
4. 一旦用户声明了某些特殊成员，其他特殊成员的隐式生成规则会受到影响。

面试回答模板：空类会由编译器隐式声明默认构造、析构、拷贝构造、拷贝赋值，以及 C++11 后的移动构造和移动赋值。空类对象大小通常是 1 字节，因为对象必须有唯一地址；但作为基类时可能被空基类优化掉。是否真的生成可调用函数，还要看成员和基类是否支持对应操作。
