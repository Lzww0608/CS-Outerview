## 面试展开回答

如果面试官问“C++11 以上新特性用过哪些”，不要只背特性列表，可以按工程价值回答：

1. **资源管理**：`unique_ptr`、`shared_ptr`、`weak_ptr` 用 RAII 管理堆对象、文件句柄、socket 等资源，减少手写 `new/delete` 带来的泄漏、重复释放和异常安全问题。
2. **移动语义**：右值引用、移动构造、移动赋值、`std::move` 可以把资源所有权转移出去，避免大对象拷贝，常用于容器扩容、返回临时对象、转移 `unique_ptr`。
3. **泛型与类型推导**：`auto`、`decltype`、模板别名、可变参数模板能减少重复类型书写，配合完美转发实现通用工厂函数。
4. **并发库**：`std::thread`、`std::mutex`、`std::condition_variable`、`std::atomic` 把跨平台线程、锁、条件变量和原子操作纳入标准库。
5. **函数式能力**：lambda、`std::function`、`std::bind` 让回调、异步任务、排序比较器更容易表达。
6. **类型安全增强**：`nullptr` 替代 `NULL`，`enum class` 避免枚举污染作用域，`override/final` 提前暴露虚函数覆盖错误。

C++14/17/20 也可以补充：

1. **C++14**：泛型 lambda、`std::make_unique`、变量模板。
2. **C++17**：结构化绑定、`if constexpr`、`std::optional`、`std::variant`、`std::string_view`、并行算法。
3. **C++20**：concepts、coroutine、ranges、`std::span`、`std::jthread`。

真实项目里更重要的是说清楚使用边界。例如 `shared_ptr` 适合共享所有权，但有引用计数和原子操作开销；`unique_ptr` 适合独占所有权，默认和裸指针一样大小；`string_view` 避免拷贝但不拥有内存，必须保证底层字符串生命周期。

## C++20 重点特性

如果面试官继续追问 C++20，可以优先讲 Modules、Coroutines、Ranges 和 Concepts，因为它们不只是语法糖，而是改变代码组织、异步编程、泛型约束和集合处理方式。

### 1. Concepts

Concepts 用来给模板参数增加约束，让错误在模板实例化早期暴露，并让接口表达更清楚。

```cpp
#include <concepts>

template <std::integral T>
T add(T a, T b) {
    return a + b;
}
```

没有 Concepts 时，模板错误常常出现在很深的实例化栈里；有了 Concepts，编译器可以直接提示“传入类型不满足 integral 约束”。真实项目里，它适合约束序列容器、可哈希类型、可比较类型、序列化接口等泛型组件。

易错点是不要把 Concepts 当运行时类型检查。它是编译期约束，不会带来虚函数那类运行时分发。

### 2. Modules

Modules 试图替代传统头文件的文本包含模型，减少重复解析、宏污染和头文件顺序问题。

```cpp
export module math;

export int add(int a, int b) {
    return a + b;
}
```

使用方：

```cpp
import math;

int x = add(1, 2);
```

Modules 的优势：

1. 编译器可以把模块接口编译成中间表示，减少重复解析头文件。
2. 模块只导出显式 `export` 的实体，接口边界更清晰。
3. 宏默认不会像 `#include` 一样跨模块大范围污染。

注意事项：

1. Modules 不等于完全取消头文件，和旧代码、第三方库、构建系统的兼容仍然是工程难点。
2. 宏、条件编译、平台相关头文件仍可能存在。
3. 不同编译器和构建工具对 Modules 的支持程度会影响落地成本。

### 3. Ranges

Ranges 把“范围”和“算法”结合起来，支持更自然的管道式组合，减少手写迭代器边界。

```cpp
#include <ranges>
#include <vector>

std::vector<int> nums{1, 2, 3, 4, 5};

auto even_square = nums
    | std::views::filter([](int x) { return x % 2 == 0; })
    | std::views::transform([](int x) { return x * x; });
```

这里 `filter` 和 `transform` 返回的是 view，通常是惰性求值，不会立刻生成新容器。真实项目里适合对集合做过滤、映射、截断、拼接等只读流水线处理。

易错点：

1. view 很多时候不拥有数据，底层容器生命周期必须覆盖 view 的使用周期。
2. 惰性求值意味着每次遍历可能重新计算，不要误以为一定缓存结果。
3. 复杂管道可读性可能变差，性能敏感路径要结合编译结果和压测判断。

### 4. Coroutines

C++20 协程提供 `co_await`、`co_yield`、`co_return` 三个关键字，编译器会把协程函数转换成状态机，并把局部状态保存到协程帧中。

```cpp
Task fetch() {
    auto data = co_await async_read();
    co_return data;
}
```

协程的核心价值是把异步回调写成接近同步的代码结构，适合网络 I/O、定时器、异步 RPC、游戏脚本等场景。

需要特别说明：C++20 只提供语言机制，不自带完整调度器、事件循环和标准 `Task` 类型。实际项目通常需要配合框架，例如 asio、folly、cppcoro 或业务自研 runtime。

### 5. 其他常用补充

1. `std::span`：非拥有的连续内存视图，适合函数参数传数组或 vector 片段，但要注意生命周期。
2. `std::jthread`：析构时自动 join，并支持 `stop_token` 协作取消，比裸 `std::thread` 更安全。
3. `std::format`：类型安全的格式化输出，替代部分 `sprintf` 场景。
4. `std::latch`、`std::barrier`、`std::counting_semaphore`：补齐并发同步工具。

面试可以总结为：C++20 的 Concepts 改善模板约束，Modules 改善编译和接口隔离，Ranges 改善集合处理表达，Coroutines 改善异步流程表达；但这些特性都有工程落地成本，不能只背语法，要说明生命周期、编译器支持和运行时框架边界。
