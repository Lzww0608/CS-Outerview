# 虚函数表与虚函数表指针

虚函数表与虚函数表是用来实现**多态**的，每一个类只有一个虚函数表

**静态多态**：函数重载（编译期确定）

**动态多态**：虚函数（运行期确定）





### 虚函数表的创建时机：

+ 生成时间：
  + 编译期生成，识别到`virtual`关键字修饰的函数，**虚函数地址的数组**
  + `.bss`: 未初始化的或者自动初始化为0的全局、静态变量
  + `.data`: 已经初始化的全局、静态变量
  + `.rodata`: 只读数据段，虚函数表，常量数据
+ 存放在哪里： 可执行程序（磁盘，只读数据段`.rodata`）， 运行状态（内存）



### 虚函数指针：

+ 存放位置：
  + 一般在类的最开始位置，4字节(32位)， 8字节(64位)
  + 堆区，指向虚函数表的地址
  + 类的不同对象虚函数表指针不一样
+ 创建时间：
  + 类对象构造的时候，初始化`vptr`
  + 如果对象是派生类，在`vptr`随着构造函数逐层向下进行构造，每个类指向自己的虚函数表；即构造函数先分配堆或者栈的内存，然后初始化`vptr`，然后初始化其他成员并执行构造函数体
  + **注：`vptr`在构造期间可能多次更新。当基类构造函数运行时，`vptr`指向基类虚函数表。而当派生类构造函数执行时，`vptr`会更新为指向派生类的虚函数表。这保证了构造期间，任何函数的调用都将解析到当前构造阶段的正确版本。**
+ 对象析构：
  + 同理，在析构期间，从子类析构到父类，`vptr`将依次被设置会每个级别的基类。
  + 这里也引出了另外一个问题，在继承结构中析构函数最好为虚函数，这样当指向派生类的基类指针这种结构出现的时候，我们进行析构，通过虚函数指针的作用可以先执行子类的析构，再执行父类的析构，防止析构子类之后找不到父类的析构函数了（这是另外一个较大的问题，这里太小写得简略一下，可以自行搜索一下）。

## 构造函数可不可以是虚函数

构造函数不能是虚函数。

原因：

1. 虚函数调用依赖对象里的 `vptr`。
2. 构造函数的职责之一就是初始化对象，包括初始化当前构造阶段对应的 `vptr`。
3. 构造开始前，对象还没有形成完整的动态类型，无法通过虚表做动态派发。
4. 构造函数没有普通成员函数那样的继承重写语义，派生类构造必须显式或隐式先构造基类。

如果想根据类型创建对象，可以用工厂函数：

```cpp
class Base {
public:
    virtual ~Base() = default;
};

std::unique_ptr<Base> createByType(int type);
```

## 析构函数可不可以是虚函数

析构函数可以是虚函数，而且如果一个类要通过基类指针删除派生类对象，基类析构函数必须是虚函数。

错误示例：

```cpp
struct Base {
    ~Base() {}
};

struct Derived : Base {
    ~Derived() {}
};

Base* p = new Derived();
delete p; // 未定义行为，可能只调用 Base::~Base()
```

正确写法：

```cpp
struct Base {
    virtual ~Base() = default;
};
```

如果类不打算作为多态基类，可以不写虚析构，避免每个对象增加 vptr 成本。

## 构造和析构期间虚函数调用

构造和析构期间调用虚函数，不会动态派发到“更外层”的派生类版本。

1. 基类构造阶段，对象还只是基类部分，`vptr` 指向基类虚表。
2. 派生类构造阶段，`vptr` 再更新为派生类虚表。
3. 析构时顺序相反，派生类析构后进入基类析构，`vptr` 会退回基类虚表。

因此不要依赖构造函数或析构函数中的虚函数调用实现多态行为。

## 面试回答模板

虚函数表通常由编译器生成并放在只读数据段，虚表指针 `vptr` 在对象构造过程中由构造函数写入。构造函数不能是虚函数，因为虚调用依赖已经初始化好的 `vptr` 和完整对象动态类型，而构造函数正是在建立对象。析构函数可以是虚函数，多态基类应当有 virtual 析构，否则通过基类指针删除派生类对象会产生未定义行为。构造和析构期间调用虚函数只会绑定到当前构造/析构阶段的类。
