# C++ 未定义行为与内存越界

未定义行为（Undefined Behavior, UB）是指 C++ 标准没有规定程序行为的情况。一旦触发 UB，编译器可以基于“这种情况不会发生”的假设优化代码，程序可能表现为正常、崩溃、数据损坏或被优化成完全意外的结果。

## `delete` 和 `delete[]` 的未定义行为

`new` / `delete` 必须配对，`new[]` / `delete[]` 必须配对：

```cpp
int* a = new int(1);
delete a;      // 正确

int* b = new int[10];
delete[] b;    // 正确
```

错误示例：

```cpp
int* p = new int[10];
delete p; // 未定义行为
```

原因：

1. 数组对象可能需要记录元素个数，用于逐个调用析构函数。
2. `delete` 和 `delete[]` 可能走不同的运行时释放逻辑。
3. 对非平凡析构类型，错误释放可能导致部分元素析构缺失、堆元数据损坏或崩溃。

同理，`malloc/free` 不能和 `new/delete` 混用，因为构造/析构语义和分配器元数据都不同。

## 重复 delete 会发生什么

对同一个指针重复 `delete` 不是编译期错误，而是运行期未定义行为：

```cpp
int* p = new int(1);
delete p;
delete p; // 未定义行为，可能崩溃、可能破坏堆，也可能暂时看不出问题
```

它通常不会被编译器稳定诊断，因为编译器很难在一般情况下证明两个指针一定指向同一块动态内存。运行时结果取决于分配器实现和当前堆状态：

1. 调试分配器、ASan、glibc 等可能报 `double free`、`invalid pointer` 或直接 abort。
2. 普通构建下可能破坏 malloc/free 的 chunk 元数据，后续在别的分配或释放点才崩溃。
3. 如果释放后的内存被重新分配给别的对象，第二次 `delete` 可能误释放别人的对象，造成更隐蔽的数据损坏。

释放裸指针后把指针置为 `nullptr` 可以降低“同一变量再次释放”的风险，因为 `delete nullptr` 是安全的；但如果还有其他别名指针指向同一对象，置空一个变量并不能解决所有权问题。工程上更推荐用 RAII、`std::unique_ptr`、`std::shared_ptr` 和容器表达所有权，减少手动 `delete`。

## 虚析构和多态删除

如果通过基类指针删除派生类对象，基类析构函数必须是虚函数：

```cpp
struct Base {
    virtual ~Base() = default;
};

struct Derived : Base {
    ~Derived() override = default;
};

Base* p = new Derived();
delete p; // 正确，先 Derived 后 Base
```

如果 `Base::~Base()` 不是虚函数，`delete p` 是未定义行为，常见结果是只调用基类析构，派生类资源泄漏，甚至破坏堆。

## 内存越界为什么危险

数组越界、写野指针、Use-After-Free 都属于未定义行为。它们可能覆盖：

1. 同一对象里的相邻成员。
2. 栈帧中的其他局部变量。
3. 堆分配器元数据。
4. 虚表指针、函数指针、返回地址等控制数据。
5. 其他对象或线程正在使用的数据。

但不能把“越界能改到某个变量”当成稳定机制。局部变量布局受编译器、优化等级、ABI、栈保护、对齐、寄存器分配影响，任何示例都只是特定环境下的偶然表现。

## 如何通过越界影响其他作用域变量

面试里如果被问到这个问题，重点应答是：这依赖未定义行为和具体内存布局，不能在正确程序中依赖。理论上，如果两个对象在栈或堆上相邻，越界写可能覆盖相邻对象的存储；如果一个作用域中的指针仍指向已经结束生命周期的栈对象，继续写入也可能破坏后续复用同一栈区域的变量。

防御角度要关注：

1. 栈保护：`-fstack-protector` 在返回地址附近放 canary，检测栈溢出。
2. ASan：`-fsanitize=address` 在对象周围放 redzone，检测越界和 UAF。
3. UBSan：检测部分未定义行为。
4. `_FORTIFY_SOURCE`：对部分 libc 调用增加边界检查。
5. 使用 `std::array::at()`、`std::vector::at()`、span 边界检查和静态分析减少越界。
6. RAII 和智能指针减少手动释放错误。

## 常见 C++ UB

1. 数组越界读写。
2. 解引用空指针、野指针、悬垂指针。
3. `new/delete`、`new[]/delete[]`、`malloc/free` 混用。
4. 对同一块动态内存重复 `delete/free`。
5. 有符号整数溢出。
6. 修改字符串字面量。
7. 访问已经结束生命周期的对象。
8. 数据竞争：多个线程无同步读写同一变量且至少一个写。
9. 通过非虚析构基类指针删除派生类对象。

## 面试回答模板

C++ 未定义行为是标准不规定结果的行为，编译器会假设它不会发生并据此优化。`new` 要配 `delete`，`new[]` 要配 `delete[]`，重复释放同一块动态内存也是 UB；多态基类要有虚析构，否则通过基类指针删除派生类对象是 UB。内存越界理论上可能覆盖相邻变量、堆元数据、vptr 或返回地址，但这完全依赖编译器和运行时布局，不能作为正确代码依赖。工程上用 ASan/UBSan、栈保护、边界检查容器、RAII 和代码审查来发现和避免这类问题。
