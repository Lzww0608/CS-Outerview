# Q174.C++限制对象创建位置

C++ 对象创建可以分成两件事：先获得一块原始存储，再在存储上开始对象生命周期。普通栈对象由编译器自动分配存储并调用构造/析构；普通 `new` 表达式会调用 `operator new` 分配原始内存，再调用构造函数。面试里问“如何不显式调用 `malloc/new` 分配”或“如何禁止栈上分配”，本质是在考对象生命周期和访问控制。

## 1. 不显式调用 malloc 和 new 如何分配对象

最常见做法是把对象创建封装到工厂函数里，让调用方不直接写 `new`：

```cpp
#include <memory>

class Session {
public:
    static std::unique_ptr<Session> Create(int fd) {
        return std::unique_ptr<Session>(new Session(fd));
    }

    Session(const Session&) = delete;
    Session& operator=(const Session&) = delete;

private:
    explicit Session(int fd) : fd_(fd) {}

    int fd_;
};

auto s = Session::Create(10);
```

这里调用方没有显式写 `new`，但工厂内部仍然可以使用 `new`。更现代的写法通常优先用 `std::make_unique`，但如果构造函数是 private，`make_unique` 默认无法访问 private 构造函数，需要把工厂作为类成员，或提供可访问的构造令牌。

如果希望对象来自内存池，可以重载类作用域 `operator new/delete`：

```cpp
#include <cstddef>
#include <new>

class Node {
public:
    static Node* Create(int value) {
        return new Node(value);
    }

    static void Destroy(Node* p) {
        delete p;
    }

    static void* operator new(std::size_t n) {
        if (void* p = pool_alloc(n)) {
            return p;
        }
        throw std::bad_alloc();
    }

    static void operator delete(void* p) noexcept {
        pool_free(p);
    }

private:
    explicit Node(int value) : value_(value) {}

    int value_;
};
```

这样 `new Node` 的原始内存来源可以是内存池、共享内存、mmap 区或调试分配器，不要求底层一定调用 `malloc`。

## 2. 如何禁止栈上分配

栈上对象离开作用域时必须能自动调用析构函数。如果把析构函数设为 `private` 或 `protected`，外部代码就不能定义自动对象，因为作用域结束时无法访问析构函数。

```cpp
class HeapOnly {
public:
    static HeapOnly* Create() {
        return new HeapOnly();
    }

    static void Destroy(HeapOnly* p) {
        delete p;
    }

    HeapOnly(const HeapOnly&) = delete;
    HeapOnly& operator=(const HeapOnly&) = delete;

private:
    HeapOnly() = default;
    ~HeapOnly() = default;
};

// HeapOnly x;              // 编译失败：析构函数不可访问
auto* p = HeapOnly::Create();
HeapOnly::Destroy(p);
```

如果希望用智能指针管理，可以提供自定义 deleter，因为默认 `std::default_delete` 也访问不到 private 析构函数：

```cpp
#include <memory>

class HeapOnly {
public:
    struct Deleter {
        void operator()(HeapOnly* p) const {
            delete p;
        }
    };

    using Ptr = std::unique_ptr<HeapOnly, Deleter>;

    static Ptr Create() {
        return Ptr(new HeapOnly());
    }

    HeapOnly(const HeapOnly&) = delete;
    HeapOnly& operator=(const HeapOnly&) = delete;

private:
    HeapOnly() = default;
    ~HeapOnly() = default;

    friend struct Deleter;
};
```

这个模式适合必须由框架统一管理生命周期的对象，例如连接对象、线程对象、引用计数对象、只能通过句柄释放的资源对象。

## 3. 如何禁止堆上分配

相反，如果希望对象只能在栈上、成员里或静态区创建，可以删除类作用域 `operator new`：

```cpp
#include <cstddef>

class StackOnly {
public:
    StackOnly() = default;

    static void* operator new(std::size_t) = delete;
    static void operator delete(void*) = delete;
};

StackOnly x;               // 可以
// auto* p = new StackOnly; // 编译失败
```

注意这并不能完全阻止所有“非栈”生命周期：对象仍然可以作为另一个堆对象的成员，也可以通过 placement new 在调用方提供的 buffer 上构造。C++ 很难用一种写法绝对禁止所有存储位置，访问控制主要约束常规创建路径。

## 4. 构造函数私有、析构函数私有和 operator new 私有的区别

| 手段 | 限制效果 | 常见用途 |
| --- | --- | --- |
| private 构造函数 | 外部不能直接构造对象 | 单例、工厂创建、强制校验参数 |
| private/protected 析构函数 | 外部不能创建自动对象，也不能直接 delete | 禁止栈上分配、引用计数对象 |
| deleted `operator new` | 禁止常规 `new T` | 希望对象不被单独堆分配 |
| 类作用域重载 `operator new` | 改变堆分配来源 | 内存池、对象池、调试分配 |
| 工厂函数 | 统一创建和返回所有权 | 返回 `unique_ptr/shared_ptr/句柄` |

如果只把 `operator new` 设为 private，并不能禁止栈上创建；它限制的是常规堆分配。要禁止栈上创建，关键通常是让外部不能访问析构函数。

## 5. 易错点

1. `new` 表达式不等于 `malloc`，它包含原始内存分配和构造函数调用。
2. `operator new` 只负责分配原始内存，不负责构造对象；`operator delete` 只释放原始内存，不负责析构对象。
3. 析构函数 private 后，普通 `std::unique_ptr<T>` 默认删除器不能用，需要自定义 deleter 或暴露销毁函数。
4. 删除 `operator new` 不能阻止 placement new，也不能阻止对象作为其他对象成员间接出现在堆上。
5. 工程中不要为了“禁止 new”牺牲 RAII；优先让工厂返回智能指针或明确的句柄。
6. `malloc/free` 不能管理 C++ 对象生命周期，除非配合 placement new 和显式析构，且要保证对齐和异常安全。

## 6. 面试回答模板

不让调用方显式写 `malloc/new`，可以把构造函数设为 private，然后提供静态工厂函数，返回 `unique_ptr`、`shared_ptr` 或业务句柄；如果还要控制内存来源，可以重载类作用域 `operator new/delete`，让对象从内存池分配。禁止栈上分配通常把析构函数设为 private 或 protected，因为栈对象离开作用域时需要调用析构函数，外部不可访问就会编译失败，再提供 `Destroy` 或自定义智能指针 deleter 统一释放。禁止堆上分配则可以删除 `operator new`，但要注意 placement new 和成员对象这些路径并不一定被完全禁止。
