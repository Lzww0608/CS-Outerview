# Q160. 检测类型是否有某个方法

在 C++ 模板代码里，经常需要判断一个类型是否支持某个成员函数或表达式。例如判断 `T` 是否有 `serialize()`、`begin()`、`size()`。常见方式包括 SFINAE、`void_t` detection idiom、`if constexpr` 和 C++20 concepts。

## 1. C++11/14：SFINAE

SFINAE 的核心是：模板替换失败不是硬错误，而是把这个重载从候选集中移除。

```cpp
#include <type_traits>
#include <utility>

template <class T>
class has_size {
private:
    template <class U>
    static auto test(int) -> decltype(std::declval<U>().size(), std::true_type{});

    template <class>
    static auto test(...) -> std::false_type;

public:
    static constexpr bool value = decltype(test<T>(0))::value;
};
```

解释：

1. `std::declval<U>()` 只用于 unevaluated context，不会真的构造对象。
2. `decltype(expr, std::true_type{})` 用逗号表达式检测 `expr` 是否合法。
3. 如果 `U().size()` 不合法，第一个 `test` 替换失败，选择 `...` 版本。

## 2. C++17：void_t detection idiom

C++17 提供 `std::void_t` 后，写法更清晰。

```cpp
#include <type_traits>
#include <utility>

template <class, class = void>
struct has_serialize : std::false_type {};

template <class T>
struct has_serialize<
    T,
    std::void_t<decltype(std::declval<T&>().serialize())>
> : std::true_type {};

template <class T>
inline constexpr bool has_serialize_v = has_serialize<T>::value;
```

如果要检查返回类型：

```cpp
template <class, class = void>
struct has_int_size : std::false_type {};

template <class T>
struct has_int_size<
    T,
    std::enable_if_t<
        std::is_same_v<decltype(std::declval<T&>().size()), int>
    >
> : std::true_type {};
```

真实项目里通常不建议强制返回值必须完全相同，可以用 `std::is_convertible_v` 放宽。

## 3. C++17：if constexpr 分支

检测到能力后，可以用 `if constexpr` 在编译期选择实现。

```cpp
template <class T>
void dump(T& obj) {
    if constexpr (has_serialize_v<T>) {
        obj.serialize();
    } else {
        // fallback
    }
}
```

`if constexpr` 的未选中分支不会实例化，因此可以写只对某些类型合法的代码。

## 4. C++20：concepts

C++20 concepts 可以把约束写得更接近接口语义。

```cpp
#include <concepts>

template <class T>
concept Serializable = requires(T t) {
    { t.serialize() };
};

template <Serializable T>
void save(T& obj) {
    obj.serialize();
}
```

检查返回类型：

```cpp
template <class T>
concept Sized = requires(T t) {
    { t.size() } -> std::convertible_to<std::size_t>;
};
```

concepts 的好处是错误信息更友好，接口约束更明确，也能参与重载选择。

## 5. 还可以怎么做

其他方式：

1. **继承接口基类**：运行时多态，要求类型显式继承接口。
2. **traits 手工特化**：对外部类型或特殊类型手动声明能力。
3. **tag dispatch**：根据 traits 结果选择不同标签重载。
4. **反射**：标准 C++ 目前没有完整静态反射，不能像动态语言一样随意按名字查询方法。

## 6. 易错点

1. 检测表达式要放在模板替换的直接上下文中，否则可能变成硬错误。
2. `std::declval` 不能在运行期求值。
3. 检测“有同名方法”不够，还要考虑参数、`const`、引用限定符和返回类型。
4. 私有成员访问可能不是 SFINAE 友好的简单 false，要注意访问控制。
5. concepts 只是编译期约束，不会让类型自动拥有某个方法。

## 7. 面试回答模板

判断一个类型有没有某个方法，C++11 可以用 SFINAE 和 `decltype(std::declval<T>().method())`，替换失败时选择 fallback；C++17 可以用 `std::void_t` 写 detection idiom，再配合 `if constexpr` 做编译期分支；C++20 可以用 concepts 和 `requires` 表达接口约束。检测时要把参数、`const`、返回类型和访问权限讲清楚，不能只检测一个名字。运行时方案则可以用虚基类接口或 traits 手工注册，但那不是自动反射。
