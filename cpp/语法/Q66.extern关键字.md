# Q66. `extern`关键字的作用

###  1. 声明一个全局变量，但不定义它

当使用 `extern` 声明一个变量时，它告诉编译器变量的定义在别的地方，这就意味着不在当前位置创建变量的存储空间。这样的声明不分配内存，仅仅是向编译器承诺该变量在别的地方定义。例如：

```
cppCopy code
// File: main.cpp
#include <iostream>

extern int globalVar;  // 声明，不是定义

int main() {
    std::cout << globalVar << std::endl;  // 使用外部定义的变量
    return 0;
}

// File: support.cpp
int globalVar = 42;  // 定义及初始化
```

在这个例子中，`globalVar` 在 `support.cpp` 文件中定义和初始化，而在 `main.cpp` 中通过 `extern` 关键字声明了它的存在，但没有重新分配内存或改变其值。

#### `extern int c` 的含义

`extern int c;` 表示声明一个具有外部链接属性的 `int` 变量 `c`，它的定义在其他翻译单元中。这个声明本身不分配存储空间，编译器只据此通过类型检查，链接器会在其他目标文件或库中寻找 `c` 的唯一定义。

```cpp
// a.cpp
extern int c;  // 声明，不定义

int readC() {
    return c;
}

// b.cpp
int c = 10;    // 定义，分配存储
```

容易混淆的是：

1. `extern int c;` 是声明。
2. `int c;` 在命名空间作用域通常是定义。
3. `extern int c = 10;` 带初始化，是定义，不只是声明。
4. 如果全项目找不到 `int c` 的定义，编译可能通过，但链接会报 `undefined reference`。

### 2. 在多个文件中共享函数声明

对于函数，`extern` 用来在一个文件中声明一个函数，而定义在另一个文件中，这样可以在多个文件中使用同一个函数。这在分模块编程中特别有用。例如：

```
cppCopy code
// File: math_functions.h
#ifndef MATH_FUNCTIONS_H
#define MATH_FUNCTIONS_H

extern int add(int, int);  // 函数声明

#endif

// File: math_functions.cpp
#include "math_functions.h"

int add(int x, int y) {  // 函数定义
    return x + y;
}

// File: main.cpp
#include <iostream>
#include "math_functions.h"

int main() {
    std::cout << add(10, 20) << std::endl;  // 调用外部定义的函数
    return 0;
}
```

在这个例子中，函数 `add` 被声明为 `extern`（虽然对于函数来说，如果没有 `static` 或者函数体，`extern` 是隐式的），并在另一个文件中定义。

### 3. 防止多重定义

在多文件项目中，`extern` 可以避免头文件的内容被多次包含时导致的重定义错误。例如，使用 `extern` 声明的全局变量，确保变量在所有引用点都是同一个变量。

正确组织方式：

```cpp
// global.h
#pragma once

extern int g_count;     // 声明，不分配存储
extern const int g_max; // const 全局变量如果要跨文件共享，也要 extern

// global.cpp
#include "global.h"

int g_count = 0;        // 唯一定义
extern const int g_max = 1024;
```

需要注意：命名空间作用域的 `const` 变量在 C++ 中默认具有 internal linkage，如果希望多个 `.cpp` 共享同一个 `const` 对象，要在声明和定义处都处理好 `extern`。

### 4. `extern` 和链接属性

`extern` 的本质是影响声明和链接查找，常见结论如下：

1. `extern int x;` 是声明，不是定义，不会分配存储空间。
2. `int x;` 在命名空间作用域通常是定义，会分配存储空间。
3. 普通函数声明天然具有 external linkage，`extern int f();` 里的 `extern` 通常可以省略。
4. 文件作用域 `static` 与 `extern` 语义相反：`static` 把符号限制在当前翻译单元，`extern` 表示这个符号可由其他翻译单元提供或引用。
5. `extern` 不能“修复”一个已经在头文件里写出来的变量定义；头文件应放 `extern` 声明，源文件放唯一定义。

### 5. `extern "C"`

`extern "C"` 解决的是 C++ 名字改编问题，不是普通变量跨文件共享问题。

C++ 支持函数重载，编译器会把函数名、命名空间、参数类型编码到符号名里；C 语言没有这个机制。如果 C++ 代码要调用 C 库，或者 C 代码要调用 C++ 导出的函数，需要用 `extern "C"` 暴露 C ABI。

```cpp
// api.h
#ifdef __cplusplus
extern "C" {
#endif

int add(int a, int b);

#ifdef __cplusplus
}
#endif
```

这样生成的符号名接近 C 风格的 `add`，避免 C 代码链接不到被 C++ name mangling 改写后的符号。

### 6. Linux 下用 `nm` 验证符号

`extern` 最终会落到链接阶段的符号解析上。Linux 下可以用 `nm` 查看目标文件、静态库或可执行文件中的符号表，判断一个符号是“已定义”还是“未定义引用”。

示例：

```cpp
// a.cpp
extern int g;
int readG() {
    return g;
}

// b.cpp
int g = 10;
```

分别编译后查看：

```bash
g++ -c a.cpp -o a.o
g++ -c b.cpp -o b.o
nm a.o
nm b.o
```

常见输出含义：

| 标记 | 含义 |
| --- | --- |
| `U` | undefined，当前文件只引用该符号，需要链接器从其他目标文件或库中找到定义 |
| `T/t` | 符号定义在代码段，通常是函数；大写表示全局可见，小写表示本翻译单元可见 |
| `D/d` | 符号定义在已初始化数据段，例如已初始化的全局变量 |
| `B/b` | 符号定义在 BSS 段，例如未显式初始化或零初始化的全局变量 |
| `R/r` | 符号定义在只读数据段，例如部分常量对象 |
| `W` | weak symbol，弱符号，可被强符号覆盖 |

如果 `a.o` 中看到 `U g`，说明 `extern int g;` 只是声明，`a.o` 依赖外部定义；如果 `b.o` 中看到 `D g` 或 `B g`，说明 `g` 的存储空间由 `b.o` 提供。

C++ 函数名会经过 name mangling，`nm` 输出可能是 `_Z3addii` 这类名字。排查链接问题时可以配合：

```bash
nm main.o | c++filt
```

把 C++ 符号还原成更可读的函数签名。若 C 代码要链接 C++ 导出的函数，则要使用 `extern "C"` 关闭 C++ 名字改编。

## 易错点

1. `extern` 声明变量不分配内存，但带初始化的 `extern int x = 1;` 是定义。
2. 头文件中不要写普通全局变量定义，否则多个 `.cpp` 包含后会多重定义。
3. `extern "C"` 只改变链接名和 ABI 约定，不会让 C 语言理解 C++ 类、模板、异常等复杂语义。
4. `extern` 声明必须和真实定义的类型完全一致，否则可能链接失败或产生未定义行为。

### 总结

`extern` 关键字主要用途是：

- 提供全局变量的声明，不在当前文件中定义它。
- 允许在多个文件之间共享单一的全局变量或函数。
- 帮助管理大型项目中的变量和函数定义，避免重复定义及冲突。
- `extern "C"` 用于跨 C/C++ 边界暴露稳定的 C ABI。
