## 一.直接拷贝(eagor copy)

类似于std::vector的三指针结构：

```c++
class string {
    public:
	const_pointer data() const { return start; }
	iterator begin() { return start; }
	iterator end() { return finish; }
	size_type size() const { return finish - start; }
	size_type capacity() const { return end_of_storage - start; }
private:
	char* start;
	char* finish;
	char* end_of_storage;
};
```

## 三.短字符串优化(SSO)

string对象比前两个都大，因为有缓冲区

```c++

    size_t size;
    
    static const int kLocalSize = 15;
    
    union {
        char buffer[kLocalSize+1];
        size_t capacity;
    }data;
};
```

## 四、如何实现 `operator=`

面试里问“如何对 string 的 `operator=` 进行重载”，重点不是背标准库实现，而是说明赋值运算符要处理自赋值、异常安全、深拷贝、旧资源释放和链式赋值。

一个教学版字符串可以这样写：

```cpp
#include <algorithm>
#include <cstring>

class MyString {
public:
    MyString() : data_(new char[1]{'\0'}), size_(0) {}

    explicit MyString(const char* s) {
        if (s == nullptr) {
            data_ = new char[1]{'\0'};
            size_ = 0;
            return;
        }
        size_ = std::strlen(s);
        data_ = new char[size_ + 1];
        std::memcpy(data_, s, size_ + 1);
    }

    MyString(const MyString& other)
        : data_(new char[other.size_ + 1]), size_(other.size_) {
        std::memcpy(data_, other.data_, size_ + 1);
    }

    MyString(MyString&& other) noexcept
        : data_(other.data_), size_(other.size_) {
        other.data_ = new char[1]{'\0'};
        other.size_ = 0;
    }

    MyString& operator=(MyString other) noexcept {
        swap(other);
        return *this;
    }

    ~MyString() {
        delete[] data_;
    }

    void swap(MyString& other) noexcept {
        std::swap(data_, other.data_);
        std::swap(size_, other.size_);
    }

private:
    char* data_ = nullptr;
    std::size_t size_ = 0;
};
```

这里用的是 copy-and-swap 写法：参数按值传入，调用方传左值时先拷贝，传右值时可以移动；进入函数后和当前对象交换资源，旧资源随临时对象析构释放。它的优点是天然处理自赋值，并且如果拷贝阶段抛异常，当前对象不会被破坏。

如果不用 copy-and-swap，手写赋值时也要先分配新内存并拷贝成功，再释放旧内存，避免“先 delete 后 new 失败”导致对象进入无效状态。

## 五、深拷贝和 C 字符串拷贝的风险

深拷贝是指目标对象拥有一份独立资源，而不是和源对象共享同一块可变内存。对于字符串类，深拷贝通常需要重新分配 `size + 1` 字节，并复制结尾的 `'\0'`。

常见拷贝工具：

1. `std::memcpy(dst, src, n)`：复制指定字节数，要求源和目标不重叠。
2. `std::memmove(dst, src, n)`：允许源和目标内存重叠。
3. `std::copy(first, last, out)`：C++ 泛型拷贝，适合对象序列。
4. `strcpy(dst, src)`：复制 C 字符串直到 `'\0'`，但不知道目标缓冲区大小。

`strcpy` 的核心问题是没有容量参数：

```cpp
char buf[8];
strcpy(buf, "this is too long"); // 缓冲区溢出
```

可能造成：

1. 覆盖相邻栈变量、返回地址或对象字段。
2. 破坏堆分配器元数据。
3. 触发崩溃、数据错误或安全漏洞。
4. 源字符串没有 `'\0'` 时继续越界读取。

更安全的做法：

1. C++ 业务代码优先使用 `std::string`、`std::vector<char>`、`std::array<char, N>`。
2. 必须用 C 风格缓冲区时，显式传入容量并检查长度。
3. 使用 `snprintf` 这类带目标缓冲区大小的接口。
4. 自己封装接口时同时传 `char* data` 和 `size_t capacity`，不要只传裸指针。

```cpp
bool copy_cstr(char* dst, std::size_t cap, const char* src) {
    if (dst == nullptr || src == nullptr || cap == 0) {
        return false;
    }
    std::size_t n = std::strlen(src);
    if (n + 1 > cap) {
        return false;
    }
    std::memcpy(dst, src, n + 1);
    return true;
}
```

## 六、手写 `strcpy`

面试里如果要求“用 C 语言实现 `strcpy`”，标准函数语义通常是：把 `src` 指向的 C 字符串复制到 `dst`，包括结尾的 `'\0'`，并返回 `dst`。

```c
char* my_strcpy(char* dst, const char* src) {
    char* ret = dst;

    while ((*dst++ = *src++) != '\0') {
        ;
    }

    return ret;
}
```

这个版本和标准 `strcpy` 一样，不检查目标缓冲区容量，也不处理空指针。工程里更推荐封装带容量的接口：

```c
#include <stddef.h>

int my_strcpy_s(char* dst, size_t cap, const char* src) {
    if (dst == 0 || src == 0 || cap == 0) {
        return -1;
    }

    size_t i = 0;
    while (src[i] != '\0') {
        if (i + 1 >= cap) {
            dst[0] = '\0';
            return -1;
        }
        dst[i] = src[i];
        ++i;
    }
    dst[i] = '\0';
    return 0;
}
```

易错点：

1. 必须复制结尾的 `'\0'`，否则目标不是合法 C 字符串。
2. 返回值应当是原始 `dst`，不能返回已经移动到末尾的指针。
3. `strcpy` 不适用于源和目标内存重叠；重叠拷贝应使用 `memmove`。
4. 标准 `strcpy` 无容量参数，调用方必须保证目标空间足够。

面试回答可以总结为：实现赋值运算符要做深拷贝或资源转移，处理自赋值和异常安全；`strcpy` 的危险在于不知道目标容量，容易写越界，现代 C++ 应优先使用 `std::string` 或带长度的拷贝接口。
