

## 1.基本原理（C++17)

The class template std::optional manages an optional contained value, i.e. a value that may or may not be present.

A common use case for optional is the return value of a function that may fail. As opposed to other approaches, such as std::pair<T, bool>, optional handles expensive-to-construct objects well and is more readable, as the intent is expressed explicitly.


## 2.使用场景

optional用于存储单个元素，相比于单个元素多了一个nullopt值，当值为nullopt的时候，表示当前值无效、未初始化、或者缺失。optional常见应用场景是用作函数返回值表示返回值是否有效、用作函数参数表示参数是否缺失，但用作函数参数时需要注意，标准要求optional数据必须存储在对象内，因此在对optional执行赋值操作的时候，会发生一次对象拷贝。

## 3.创建与基础使用方式

```c++
//直接创建或者用nullopt赋值
std::optional<int> empty;
std::optional<int> opt = std::nullopt; 

//使用对象初始化
std::optional<int> opt = 1;

struct Some
{
  int some_i_ = 0;
  std::string some_str_;
};
Some s;
std::optional<Some> opt = s;

//使用 std::make_optional构造,类似std::make_shared可以传递参数原地构造optional包含的对象
struct Some
{
  Some(int i, std::string str):
          some_i_(i),
          some_str_(std::move(str)) {}

  int some_i_ = 0;
  std::string some_str_;
};
using namespace std;
optional<Some> opt = make_optional<Some>(1, "1");
auto opt = make_optional(1); // optional<int>
optional<Some> opt {in_place, 1, "1"}; //使用std::in_place构造

```

##  4.optional基本操作总结

### std::optional方法

| Function  | Instruction                                                  |
| --------- | ------------------------------------------------------------ |
| value     | return the contained value                                   |
| emplace   | construct the contained value in-place                       |
| reset     | destroy contained object                                     |
| swap      | exchanges the contents                                       |
| has_value | check if object has a value                                  |
| value_or  | returns the contained value if available, another value otherwise |

## 5. optional 的底层存储

`std::optional<T>` 的核心可以理解为：

```cpp
template <typename T>
class Optional {
    bool engaged_;
    alignas(T) unsigned char storage_[sizeof(T)];
};
```

当 `engaged_ == false` 时，`storage_` 只是一块原始内存；当 `emplace` 或构造有值时，使用 placement new 在这块内存中原地构造 `T`；当 `reset` 或析构时，如果有值就显式调用 `T` 的析构函数。

这带来几个特点：

1. `optional<T>` 不需要为 `T` 单独堆分配，值通常直接存放在 `optional` 对象内部。
2. `optional<T>` 的大小大约是 `sizeof(T) + 状态位 + 对齐填充`。
3. 访问空的 `optional` 调用 `value()` 会抛 `std::bad_optional_access`，用 `*opt` 或 `opt->` 前要确认有值。
4. `optional<T&>` 不是 C++17 标准库类型，想表达可空引用通常用指针或 `std::reference_wrapper`。

## 6. variant 如何让 union 类型安全

`std::variant<Ts...>` 可以理解为“带类型标签的 union”。它内部有一块足够容纳最大备选类型的对齐存储，再用一个 index 记录当前保存的是第几个类型。

```text
storage: max(sizeof(Ts...)) bytes
index: 当前激活类型下标，或 valueless 状态
```

相比裸 `union`，`variant` 做了这些事情：

1. 构造新类型前会析构旧的激活成员。
2. 访问时通过 `std::get<T>`、`std::get_if<T>` 或 `std::visit` 检查类型。
3. 拷贝、移动、析构会根据当前 index 调用正确类型的操作。
4. 当移动/拷贝构造过程中抛异常时，可能进入 `valueless_by_exception()` 状态。

示例：

```cpp
#include <iostream>
#include <string>
#include <variant>

std::variant<int, std::string> v = "hello";

std::visit([](const auto& x) {
    std::cout << x << '\n';
}, v);
```

`variant` 适合表达“一个值只可能是有限几种类型之一”，比如 AST 节点、协议字段、状态机事件。它比继承体系少一次虚调用和堆分配，但类型集合必须在编译期确定；如果需要运行期插件扩展，虚函数或类型擦除更合适。

## 7. 易错点

1. `optional` 表示“值可能不存在”，不是“指针可能为空”的同义词，它通常直接内嵌对象。
2. `optional` 有值时赋值会调用 `T` 的赋值；无值时赋值会构造新 `T`。
3. `variant` 当前激活类型错误时，`std::get<T>` 会抛 `std::bad_variant_access`。
4. `variant` 的备选类型不能重复依赖 `std::get<T>` 区分；重复类型要用下标访问。
5. `optional/variant` 都是值语义工具，不负责共享所有权；大对象是否拷贝要看 `T` 的拷贝/移动行为。
