# Q166. 访问类的私有成员

`private` 的作用是限制类外代码直接访问成员，让类可以维护自己的不变量。面试问“如何拿到类中私有成员变量的值”，通常不是鼓励绕过封装，而是考察访问控制、友元、对象布局和工程边界。

## 1. 正常方式

最推荐的方式是让类自己提供受控接口：

```cpp
class User {
public:
    int id() const {
        return id_;
    }

private:
    int id_ = 0;
};
```

常见方式：

1. `public` getter：读取必要状态，仍由类控制不变量。
2. 成员函数：把访问逻辑封装成业务行为，而不是直接暴露字段。
3. `friend`：给特定函数或类访问权限，适合运算符重载、序列化、单元测试辅助工具。
4. 调试器：线上排障时用 gdb/lldb 查看对象内存，不改变代码语义。

## 2. friend 的适用边界

`friend` 不是继承关系，也不是让外部全部绕过封装；它只是把访问权限授予被声明的函数或类。

```cpp
class Point {
    friend double distance(const Point& a, const Point& b);

private:
    int x_ = 0;
    int y_ = 0;
};
```

使用 `friend` 的场景：

1. 两个对象之间需要对称访问，例如 `operator==`、`operator<`。
2. 序列化框架需要读写内部字段。
3. 测试代码需要检查内部状态，但不希望给生产接口增加调试方法。

易错点：`friend` 会增加耦合，不能滥用成“万能后门”。如果很多外部代码都需要访问私有成员，通常说明类的边界或接口设计有问题。

## 3. 指针偏移和强转为什么不推荐

有些写法试图通过对象地址加偏移、`reinterpret_cast`、`offsetof` 或宏替换访问私有成员：

```cpp
// 不推荐：依赖对象布局，且容易触发未定义行为
auto raw = reinterpret_cast<char*>(&obj);
auto value = *reinterpret_cast<int*>(raw + offset);
```

这些方式的问题是：

1. C++ 访问控制在编译期生效，类外代码不能合法形成私有成员指针。
2. 非标准布局类型的成员偏移不稳定，继承、虚函数、对齐、编译器 ABI 都会影响布局。
3. 违反严格别名、对齐或对象生命周期规则时可能产生未定义行为。
4. `#define private public` 这类测试技巧会污染头文件语义，容易破坏 ODR 和构建隔离。

工程上只有在调试、逆向、特定框架代码生成等极少数场景才会接触这类技巧，并且要把它们隔离在工具层，而不是业务代码里。

## 4. 面试回答模板

类的私有成员应该通过类提供的公共接口、成员函数或受控的 `friend` 访问。`private` 是封装边界，目的是保护对象不变量，不建议用指针偏移、强转、宏把 `private` 改成 `public` 等方式绕过。那些技巧依赖对象布局和 ABI，容易触发未定义行为，只能作为调试或测试里的隔离手段。生产代码里如果经常需要读私有字段，应该重新设计类接口。
