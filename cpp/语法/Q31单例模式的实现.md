# 单例模式的实现

## 1. 常规实现

```c++
#include <iostream>
#include <mutex>

class Singleton {
private:
    // 私有的静态实例
    static Singleton* instance;
    
    // 私有的构造函数，防止外部创建类的多个实例
    Singleton() {}

    // 防止拷贝构造和赋值
    Singleton(const Singleton&) = delete;
    Singleton& operator=(const Singleton&) = delete;

    // 用于线程安全的互斥锁
    static std::mutex mutex;

public:
    // 获取单例实例的静态方法 Double Check
    static Singleton* getInstance() {
        if (instance == nullptr) {
            std::lock_guard<std::mutex> lock(mutex);
            if (instance == nullptr) {
                instance = new Singleton();
            }
        }
        return instance;
    }

    // 示例方法
    void show() {
        std::cout << "Singleton instance: " << this << std::endl;
    }
};

// 初始化静态成员
Singleton* Singleton::instance = nullptr;
std::mutex Singleton::mutex;

int main() {
    // 获取单例对象
    Singleton* singleton = Singleton::getInstance();
    singleton->show();

    return 0;
}
```

上面的双重检查锁写法在面试中能说明思路，但生产代码不推荐这样手写裸指针版本：对象释放时机不清楚，异常安全差；在旧标准或错误实现中，指针写入和对象构造还可能发生重排序问题。

## 2. 推荐写法：Meyers Singleton

C++11 以后，函数内局部静态变量初始化由语言保证线程安全，最简单可靠的单例是：

```cpp
class Logger {
public:
    static Logger& instance() {
        static Logger inst;
        return inst;
    }

    Logger(const Logger&) = delete;
    Logger& operator=(const Logger&) = delete;
    Logger(Logger&&) = delete;
    Logger& operator=(Logger&&) = delete;

    void log(const char* msg) {
        // write log
    }

private:
    Logger() = default;
    ~Logger() = default;
};
```

特点：

1. 第一次调用 `instance()` 时懒加载。
2. 初始化过程线程安全。
3. 不需要手写锁和裸指针。
4. 拷贝、赋值、移动都删除，保证唯一实例。

## 3. 使用 call_once

如果对象需要动态创建，或者初始化逻辑需要显式控制，可以使用 `std::call_once`：

```cpp
#include <memory>
#include <mutex>

class Config {
public:
    static Config& instance() {
        std::call_once(flag_, [] {
            inst_.reset(new Config);
        });
        return *inst_;
    }

    Config(const Config&) = delete;
    Config& operator=(const Config&) = delete;

private:
    Config() = default;

    inline static std::once_flag flag_;
    inline static std::unique_ptr<Config> inst_;
};
```

`call_once` 保证初始化函数只执行一次，适合初始化步骤较复杂、需要捕获错误或需要在测试中更明确控制生命周期的场景。

## 4. 单例的真实问题

单例不是无脑使用的全局变量。它的主要风险是：

1. **全局状态**：测试之间容易互相污染。
2. **隐藏依赖**：函数签名看不出依赖了哪些全局对象。
3. **析构顺序**：多个静态对象退出时析构顺序不确定。
4. **并发安全**：初始化线程安全不代表对象方法天然线程安全。
5. **生命周期控制差**：日志、线程池、连接池这类对象可能需要显式 shutdown。

工程上，如果对象需要在不同测试或不同实例中替换，优先考虑依赖注入；如果确实是进程级唯一资源，例如全局配置、日志入口、指标注册表，可以用单例，但要明确线程安全和关闭顺序。

## 5. 面试回答模板

单例模式保证一个类在进程内只有一个实例，并提供全局访问点。C++11 后我优先写 Meyers Singleton：在 `instance()` 里定义局部静态对象，语言保证初始化线程安全，同时删除拷贝、赋值和移动。复杂初始化可以用 `std::call_once`。不推荐手写裸指针双重检查锁，因为生命周期、异常安全和重排序都容易出问题。还要补充：单例会引入全局状态，初始化线程安全不等于方法线程安全，日志、线程池这类单例通常要设计明确的 shutdown。
