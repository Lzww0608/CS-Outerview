## 怎么避免内存泄漏

避免内存泄漏的核心不是“记得 delete”，而是让资源的生命周期被类型系统和作用域自动管理。

1. **明确所有权**：独占资源用 `std::unique_ptr`，确实共享时才用 `std::shared_ptr`，只观察不拥有时用裸指针、引用或 `std::weak_ptr`。
2. **优先使用 RAII**：文件描述符、socket、锁、连接句柄、内存 buffer 都封装成对象，在构造时获取资源，在析构时释放资源。
3. **减少手写 `new/delete`**：业务代码优先使用标准容器、智能指针和工厂函数，让异常、提前 `return`、多分支路径也能自动释放。
4. **打断循环引用**：父子节点、观察者、回调、定时器、异步任务中如果相互持有 `shared_ptr`，需要把非 owning 的一侧改成 `weak_ptr`。
5. **限制长生命周期容器**：缓存、对象池、任务队列、日志队列要有容量上限、TTL、淘汰策略和监控指标，否则看起来像内存泄漏。
6. **把所有权写进接口**：函数返回 `unique_ptr<T>` 表示转移所有权，参数使用 `T&`/`T*` 表示借用，避免调用方不清楚谁负责释放。
7. **用工具前置发现问题**：在单测、集成测试和压测阶段开启 ASan/LSan，CI 中保留内存泄漏检查，代码评审重点看异常路径和回调生命周期。

示例：如果一个连接对象把回调注册到事件循环中，事件循环又通过 `shared_ptr` 持有连接对象，就可能导致连接关闭后对象仍无法释放。常见做法是事件循环只保存 `weak_ptr<Connection>`，触发回调时先 `lock()`，对象已销毁则直接跳过。

## 工程排查流程

排查 C++ 内存泄漏时，先确认现象，再定位分配栈，最后修复所有权。

1. **确认是否持续增长**：观察 RSS、PSS、heap、fd 数、线程数是否随请求结束回落。
2. **区分泄漏和缓存**：缓存没有上限也会表现为内存上涨，但它可能仍被程序引用，不一定是传统意义的“丢失指针”。
3. **压测复现**：用固定请求持续压测，观察内存是否近似线性增长。
4. **缩小范围**：按接口、模块、开关、请求类型定位是哪条路径导致增长。
5. **抓分配栈**：用 ASan/LSan、Valgrind、heaptrack、gperftools、jemalloc/tcmalloc profile 或 eBPF memleak。
6. **修复所有权**：用 RAII、智能指针、容器和析构封装替代裸 `new/delete`、`malloc/free`。

## 常用工具

| 工具 | 适用阶段 | 特点 |
| --- | --- | --- |
| AddressSanitizer/LeakSanitizer | 单测、集成测试 | 速度较快，能定位泄漏、越界、use-after-free |
| Valgrind Memcheck | 线下复现 | 检查细，但运行慢 |
| heaptrack | 线下压测 | 分析堆分配热点和增长来源 |
| gperftools heap profiler | 服务压测 | 可输出 heap profile 做对比 |
| jemalloc/tcmalloc profiling | 线上低开销采样 | 适合长生命周期服务 |
| eBPF/bcc memleak | 线上定位 | 不改代码，能采样分配栈 |
| `/proc/<pid>/smaps` | 线上观察 | 区分 heap、mmap、栈、匿名页、文件映射 |

## 常见泄漏原因

1. `new/delete`、`new[]/delete[]`、`malloc/free` 不匹配。
2. 异常路径、提前 `return`、错误分支忘记释放资源。
3. `shared_ptr` 循环引用，回调或定时器持有对象导致生命周期延长。
4. 容器中保存裸指针，清理容器时没有释放对象。
5. fd、socket、线程、锁、GPU buffer、数据库连接等非内存资源没有释放。
6. 对象池、缓存、日志队列没有上限或淘汰策略。
7. `unique_ptr::release()` 后没有把裸指针交给新的 owner。

## 修复原则

1. 用 `std::unique_ptr` 表达独占所有权。
2. 确实共享时才使用 `std::shared_ptr`，环形关系用 `std::weak_ptr` 打断。
3. 文件描述符、socket、锁、连接池句柄封装成 RAII 类型。
4. 构造函数获取资源，析构函数释放资源。
5. 所有权跨函数传递时写进函数签名，例如返回 `unique_ptr` 或接收 `unique_ptr`。
6. 对长期缓存设置容量、TTL、淘汰策略和监控指标。

## 面试回答模板

我会先看进程 RSS、heap、fd 数和线程数是否持续上涨，确认是内存泄漏、资源泄漏还是缓存无上限。线下用 ASan/LSan、Valgrind 或 heaptrack 复现并拿到分配栈；线上可以用 jemalloc/tcmalloc profile、`/proc/<pid>/smaps` 或 eBPF 采样。修复上核心是 RAII：堆对象用 `unique_ptr/shared_ptr/weak_ptr` 表达所有权，文件描述符和 socket 用析构自动关闭的 wrapper，异常路径也能释放资源。还要检查循环引用、回调持有对象、容器裸指针和无界缓存。
