# C语言实现多态

C 语言没有类、继承、虚函数这些语法，但可以通过**结构体 + 函数指针 + 约定好的接口表**模拟运行时多态。它的本质是把 C++ 编译器自动生成的虚表和虚表指针手动写出来，让调用方只依赖统一接口，不关心真实对象类型。

## 核心思想

常见做法是：

1. 定义一个公共基类结构体，里面放一张操作表指针。
2. 不同具体类型把公共基类结构体作为第一个成员。
3. 每个具体类型提供一组函数实现，并把这些函数放进操作表。
4. 调用方通过公共接口调用函数指针，实现运行时分派。

这种模式在 Linux 内核、驱动框架、网络协议栈、GUI 框架和插件系统中很常见。例如 Linux 的 `file_operations`、设备驱动的 `net_device_ops` 都是典型的 C 风格多态。

## 示例：Shape 接口

```c
#include <stdlib.h>

typedef struct Shape Shape;

typedef struct ShapeOps {
    double (*area)(const Shape* self);
    void (*destroy)(Shape* self);
} ShapeOps;

struct Shape {
    const ShapeOps* ops;
};

typedef struct Circle {
    Shape base;
    double radius;
} Circle;

static double circle_area(const Shape* self) {
    const Circle* c = (const Circle*)self;
    const double pi = 3.141592653589793;
    return pi * c->radius * c->radius;
}

static void circle_destroy(Shape* self) {
    free(self);
}

static const ShapeOps CIRCLE_OPS = {
    circle_area,
    circle_destroy
};

Shape* circle_create(double radius) {
    Circle* c = (Circle*)malloc(sizeof(*c));
    if (c == NULL) {
        return NULL;
    }
    c->base.ops = &CIRCLE_OPS;
    c->radius = radius;
    return &c->base;
}

double shape_area(const Shape* s) {
    return s->ops->area(s);
}

void shape_destroy(Shape* s) {
    if (s != NULL) {
        s->ops->destroy(s);
    }
}
```

调用方只看到 `Shape*`：

```c
Shape* s = circle_create(3.0);
double a = shape_area(s);
shape_destroy(s);
```

如果后续新增 `Rectangle`，只需要实现 `rectangle_area`、`rectangle_destroy` 和对应的 `ShapeOps`，调用方代码不需要关心真实类型。

## 和 C++ 虚函数的关系

C++ 虚函数通常由编译器在对象中放入虚表指针 `vptr`，不同动态类型的 `vptr` 指向不同虚表，调用虚函数时通过虚表找到真实函数地址。

C 语言模拟多态时：

1. `ShapeOps` 相当于手写的虚表。
2. `Shape.ops` 相当于手写的虚表指针。
3. `Circle` 的第一个成员 `Shape base` 相当于“基类子对象”。
4. `shape_area(s)` 通过 `s->ops->area(s)` 实现动态分派。

区别是 C 没有构造函数、析构函数、访问控制、类型安全和自动向上转型，这些都需要程序员用约定和代码规范保证。

## 易错点

1. 如果依赖 `Shape*` 和 `Circle*` 之间的转换，公共基类结构体通常要放在具体类型的第一个成员位置。
2. 对象创建后必须先初始化 `ops` 指针，否则第一次调用函数指针就可能崩溃。
3. `destroy` 要和创建方式匹配：`malloc` 对应 `free`，自定义内存池要回收到对应池中。
4. C 的强制转换缺少运行时类型检查，错误地把 `Rectangle*` 当成 `Circle*` 访问会产生未定义行为。
5. 多线程场景下，如果操作表是只读全局常量通常安全；如果对象状态会被多个线程修改，需要额外同步。
6. 回调函数中不要保存已经释放的对象指针，事件循环、异步 I/O、定时器中尤其容易出现悬空指针。

## 真实场景应用

1. **驱动和内核对象**：不同设备实现同一组读写、打开、关闭接口，内核通过操作表调用。
2. **协议栈**：TCP、UDP、不同应用协议可以通过统一 handler 接口接入事件循环。
3. **插件系统**：插件导出一张函数表，主程序按统一 ABI 调用插件能力。
4. **C 项目中的面向对象设计**：用 opaque pointer 隐藏结构体定义，对外只暴露 `create/destroy/do_something` 等接口，降低模块耦合。

## 面试回答模板

C 语言本身没有虚函数，但可以用结构体和函数指针模拟多态。通常会定义一个公共结构体，里面放一张函数指针表；具体类型把公共结构体作为第一个成员，并把函数表指向自己的实现。调用方只拿公共指针，通过 `obj->ops->method(obj)` 调用，运行时会根据对象里保存的函数表执行不同实现。这个模型和 C++ 虚函数很像，只是 C++ 的虚表、虚表指针、构造析构和类型检查由编译器处理，而 C 语言需要程序员手动维护生命周期、类型转换和线程安全。
