# Q147. STL 容器增长、删除与迭代器失效

## 1. vector 怎么增长

`std::vector` 是连续内存容器，内部通常维护三个指针或等价状态：

```text
begin: 已用空间起点
end: 已用空间终点
cap: 已分配空间终点
```

当 `push_back` 时：

1. 如果 `size() < capacity()`，直接在尾部构造新元素。
2. 如果 `size() == capacity()`，需要重新申请一块更大的连续内存。
3. 把旧元素移动或拷贝到新内存。
4. 析构旧元素并释放旧内存。
5. 在新内存尾部构造新元素。

增长倍率由标准库实现决定，常见是约 1.5 倍或 2 倍。标准只要求摊还 `O(1)` 的 `push_back`，不规定具体倍率。

## 2. vector push_back 后迭代器会怎样

`vector` 的迭代器本质上可以理解为指向连续数组元素的指针。

1. **未扩容**：已有元素地址不变，原有迭代器、指针、引用通常仍有效；但 `end()` 会失效，因为尾后位置变了。
2. **发生扩容**：旧内存被释放，所有迭代器、指针、引用全部失效。
3. **中间插入或删除**：插入点或删除点之后的迭代器、指针、引用会失效，因为元素需要搬移。

工程上如果要长期保存位置，优先保存下标而不是保存迭代器；如果能预估大小，先 `reserve()` 可以减少扩容次数。

## 3. map 的底层数据结构

`std::map` 通常用红黑树实现，满足：

1. key 有序，迭代器按 key 从小到大遍历。
2. 查找、插入、删除复杂度都是 `O(log n)`。
3. 节点式存储，每个元素单独分配节点，插入删除不会像 `vector` 那样整体搬移元素。
4. 迭代器通常比较稳定：插入不会使已有迭代器失效；删除只会使被删除元素的迭代器失效。

标准没有强制规定必须是红黑树，但要求有序关联容器满足对应复杂度和迭代顺序，红黑树是主流实现。

## 4. 红黑树和平衡二叉树的区别

面试里“平衡二叉树”通常指 AVL 树。

| 对比项 | AVL 树 | 红黑树 |
| --- | --- | --- |
| 平衡要求 | 更严格，左右子树高度差不超过 1 | 相对宽松，通过颜色和黑高约束保持近似平衡 |
| 树高 | 更低，查找路径更短 | 略高，但仍是 `O(log n)` |
| 插入删除 | 旋转和维护成本更高 | 旋转次数通常更少，更新更友好 |
| 适合场景 | 查找远多于修改 | 插入、删除、查找都频繁 |
| 典型应用 | 一些内存索引、查询密集结构 | `std::map`、`std::set`、Linux CFS 运行队列等 |

红黑树不是绝对平衡，而是用“最长路径不超过最短路径 2 倍”的性质换取更低的更新成本。因此标准库有序容器更常选红黑树。

## 5. map 怎么循环删除满足条件的元素

删除时不要在 `erase` 后继续使用已经失效的迭代器。

C++11 以后推荐：

```cpp
#include <map>
#include <string>

void eraseByCondition(std::map<int, std::string>& m) {
    for (auto it = m.begin(); it != m.end(); ) {
        if (it->first % 2 == 0) {
            it = m.erase(it);
        } else {
            ++it;
        }
    }
}
```

`erase(it)` 会删除当前节点，并返回下一个有效迭代器。

C++20 可以用：

```cpp
#include <map>
#include <string>

std::erase_if(m, [](const auto& kv) {
    return kv.first % 2 == 0;
});
```

## 6. list 插入元素后迭代器会怎样

`std::list` 是双向链表，插入或删除一个节点不会移动其他节点。

1. 插入元素：已有迭代器、指针、引用仍有效。
2. 删除元素：只有被删除元素的迭代器、指针、引用失效。
3. 访问不支持随机下标，查找第 `n` 个元素需要 `O(n)`。

因此 `list` 适合已经定位到节点后频繁插入删除的场景，不适合随机访问和缓存友好的顺序扫描。

## 7. 面试回答模板

`vector` 是连续内存，容量不够时会重新分配更大的空间并移动元素，所以扩容会导致所有迭代器、指针、引用失效；未扩容时 `push_back` 只会让 `end()` 失效。`map` 通常是红黑树，查找、插入、删除都是 `O(log n)`，插入不影响已有迭代器，删除只影响被删节点。循环删除 `map` 时要写 `it = m.erase(it)`，不能删除后再对旧迭代器自增。`list` 是链表，插入不影响已有迭代器，删除只影响被删除节点。
