# override overload overwrite

override 一般被翻译为重写或覆盖，overload 一般被翻译为重载，overwrite/name hiding 一般指隐藏。面试里要先把这三个概念分开，否则很容易把“同名函数”都混在一起。

1. override：派生类覆盖基类虚函数，必须拥有兼容的函数签名和返回类型。
2. overload：同一作用域内有多个同名函数，但参数列表不同；返回值类型不参与重载区分。
3. overwrite/name hiding：派生类声明了和基类同名的函数，可能把基类同名函数隐藏掉，即使参数不同也不会自动形成跨作用域重载。

| 概念 | 发生位置 | 条件 | 是否依赖 virtual | 典型目的 |
| --- | --- | --- | --- | --- |
| 重载 overload | 同一作用域 | 函数名相同，参数列表不同 | 否 | 同一语义支持不同参数 |
| 重写 override | 派生类对基类 | 基类函数是虚函数，派生类签名匹配 | 是 | 运行时多态 |
| 隐藏 name hiding | 派生类对基类 | 派生类声明同名函数 | 否 | 名字查找遮蔽基类函数 |

示例：

```cpp
struct Base {
    void f(int);
    virtual void g(int) const;
};

struct Derived : Base {
    void f(double);          // 隐藏 Base::f(int)，不是重载
    void g(int) const override; // 重写 Base::g(int) const
    void h(int);
    void h(double);          // h(int) 和 h(double) 是重载
};
```

如果希望在派生类里保留基类同名函数参与重载，可以显式引入：

```cpp
struct Derived2 : Base {
    using Base::f;
    void f(double); // 此时 Base::f(int) 也参与名字查找
};
```

## 函数重载的实现原理

函数重载发生在编译期。编译器会根据函数名和参数列表做 overload resolution，选择最匹配的候选函数；返回值类型不参与重载区分，因为调用点通常不能只靠返回值唯一确定目标函数。

```cpp
void log(int);
void log(double);
void log(const char*);

log(1);      // 选择 log(int)
log(1.2);    // 选择 log(double)
log("abc");  // 选择 log(const char*)
```

为了让链接器区分这些同名函数，C++ 编译器会做 name mangling，把命名空间、类名、函数名、参数类型等信息编码进符号名。例如 GCC/Clang 下 `void f(int, double)` 可能被编码成类似 `_Z1fid` 的符号。链接器看到的是不同符号，所以能同时存在多个重载版本。

易错点：

1. 返回值不同、参数列表相同不能构成重载。
2. 默认参数可能造成调用二义性。
3. 派生类同名函数会隐藏基类同名函数，不会自动形成跨作用域重载，需要 `using Base::f`。
4. `extern "C"` 会关闭 C++ name mangling，因此同一个 C linkage 名字不能暴露多个重载函数。

## 默认参数和重载的二义性

默认参数必须从右往左连续提供。也就是说，一旦某个形参有默认值，它右边的普通形参也必须有默认值：

```cpp
void f(int a, int b = 0, int c = 0); // 正确
// void g(int a = 0, int b);         // 错误：b 没有默认值
```

默认参数不是函数签名的一部分，函数重载仍然只看函数名和参数类型列表。调用时如果实参个数不足，编译器会把默认参数补上，然后再做重载决议。

典型陷阱：

```cpp
void log(int x);
void log(int x, int level = 0);

log(10); // 错误：调用二义性
```

`log(10)` 同时可以匹配 `log(int)`，也可以匹配 `log(int, int = 0)`。二者第一个参数都是精确匹配，编译器无法判断你想调用哪个，因此报二义性错误。

工程建议：

1. 同一组重载里不要让“多出来的参数”全靠默认值补齐。
2. 默认参数适合给单个稳定接口补可选配置，不适合和相近重载混用。
3. 对外 API 如果参数越来越多，优先考虑配置结构体，避免重载和默认参数组合爆炸。
4. 虚函数的默认参数按静态类型绑定，动态派发只决定函数体，不决定默认实参，因此多态接口中也要谨慎使用默认参数。

## 有函数重载的 C++ 代码放到 C 里会怎样

C 语言没有函数重载、类、模板、引用、异常和 C++ name mangling 规则。把含函数重载的 C++ 源码直接交给 C 编译器，通常会在语法或重复定义阶段失败：

```cpp
// C++ 可以
int add(int a, int b);
double add(double a, double b);

// C 语言里同名函数只能有一个全局符号 add
```

如果是“C 代码调用 C++ 实现”，正确做法是用一层 C ABI wrapper 暴露不同名字：

```cpp
// add_api.h
#ifdef __cplusplus
extern "C" {
#endif

int add_int(int a, int b);
double add_double(double a, double b);

#ifdef __cplusplus
}
#endif
```

```cpp
// add_api.cpp
int add(int a, int b) { return a + b; }
double add(double a, double b) { return a + b; }

extern "C" int add_int(int a, int b) {
    return add(a, b);
}

extern "C" double add_double(double a, double b) {
    return add(a, b);
}
```

这样 C 侧看到的是稳定的 `add_int`、`add_double` 两个符号，而 C++ 内部仍可以使用重载。

## `override` 关键字的作用

`override` 是 C++11 引入的说明符，用在派生类虚函数声明末尾，告诉编译器：这个函数必须覆盖基类中的某个虚函数。如果签名不匹配，编译器直接报错。

```cpp
struct Base {
    virtual void handle(int);
};

struct Derived : Base {
    void handle(int) override;    // 正确：覆盖 Base::handle(int)
    // void handle(long) override; // 错误：签名不同，没有覆盖任何基类虚函数
};
```

它解决的问题是“本来想重写，结果写成隐藏或新函数”：

```cpp
struct Base {
    virtual void f() const;
};

struct Derived : Base {
    void f(); // 没有 const，不是重写，而是隐藏；没有 override 时编译器不一定提醒
};
```

工程建议：

1. 派生类重写虚函数时统一写 `override`，提高可读性并让编译器检查签名。
2. `override` 只能用于虚函数，普通成员函数不能使用。
3. `override` 不改变运行时派发机制，只提供编译期校验。
4. `final` 可以和 `override` 配合，表示当前函数覆盖基类虚函数，且禁止更深层派生类继续覆盖。

```cpp
struct Derived : Base {
    void handle(int) override final;
};
```

## `final` 和防止类被继承

`final` 既可以修饰虚函数，也可以修饰类：

```cpp
struct NoDerive final {
    void run();
};

// struct Child : NoDerive {}; // 编译错误：NoDerive 不能被继承

struct Base2 {
    virtual void f();
};

struct Derived3 : Base2 {
    void f() override final; // Derived3::f 不能再被更深层派生类覆盖
};
```

面试里常见误区是把“私有构造函数”“继承 no-copy 类”和“防止继承”混在一起：

1. 私有构造函数主要限制外部直接构造对象，常用于单例或工厂，并不等价于禁止继承；派生类是否能构造还取决于它是否能访问基类构造函数。
2. 继承 no-copy 类通常用于禁止拷贝构造和拷贝赋值，解决的是对象拷贝问题，不是继承问题。
3. C++11 之后，如果语义就是“不允许再派生”，优先使用 `final`，表达最直接，也能让编译器给出清晰错误。
4. 如果只是不希望某个虚函数继续被覆盖，用 `override final` 修饰函数即可，不需要把整个类标成 `final`。

## 面试回答模板

`override` 用来声明派生类函数确实是在覆盖基类虚函数，核心价值是让编译器检查函数名、参数列表、`const`、引用限定符等签名是否一致。没有 `override` 时，派生类很容易因为少写 `const` 或参数类型不同，把重写写成隐藏，导致运行时多态不生效。`override` 本身不改变虚函数表机制，只是编译期安全检查，工程上建议所有重写虚函数都加。`final` 可以禁止类继续被继承，也可以禁止某个虚函数继续被覆盖；C++11 之后防止继承应优先用 `class X final`，而不是依赖私有构造或 no-copy 这类间接技巧。
