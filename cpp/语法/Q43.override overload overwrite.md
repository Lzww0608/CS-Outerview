# override overload overwrite

override 一般被翻译为重写或覆盖，overload 一般被翻译为重载，overwrite/name hiding 一般指隐藏。面试里要先把这三个概念分开，否则很容易把“同名函数”都混在一起。

1. override：派生类覆盖基类虚函数，必须拥有兼容的函数签名和返回类型。
2. overload：同一作用域内有多个同名函数，但参数列表不同；返回值类型不参与重载区分。
3. overwrite/name hiding：派生类声明了和基类同名的函数，可能把基类同名函数隐藏掉，即使参数不同也不会自动形成跨作用域重载。

| 概念 | 发生位置 | 条件 | 是否依赖 virtual | 典型目的 |
| --- | --- | --- | --- | --- |
| 重载 overload | 同一作用域 | 函数名相同，参数列表不同 | 否 | 同一语义支持不同参数 |
| 重写 override | 派生类对基类 | 基类函数是虚函数，派生类签名匹配 | 是 | 运行时多态 |
| 隐藏 name hiding | 派生类对基类 | 派生类声明同名函数 | 否 | 名字查找遮蔽基类函数 |

示例：

```cpp
struct Base {
    void f(int);
    virtual void g(int) const;
};

struct Derived : Base {
    void f(double);          // 隐藏 Base::f(int)，不是重载
    void g(int) const override; // 重写 Base::g(int) const
    void h(int);
    void h(double);          // h(int) 和 h(double) 是重载
};
```

如果希望在派生类里保留基类同名函数参与重载，可以显式引入：

```cpp
struct Derived2 : Base {
    using Base::f;
    void f(double); // 此时 Base::f(int) 也参与名字查找
};
```

## `override` 关键字的作用

`override` 是 C++11 引入的说明符，用在派生类虚函数声明末尾，告诉编译器：这个函数必须覆盖基类中的某个虚函数。如果签名不匹配，编译器直接报错。

```cpp
struct Base {
    virtual void handle(int);
};

struct Derived : Base {
    void handle(int) override;    // 正确：覆盖 Base::handle(int)
    // void handle(long) override; // 错误：签名不同，没有覆盖任何基类虚函数
};
```

它解决的问题是“本来想重写，结果写成隐藏或新函数”：

```cpp
struct Base {
    virtual void f() const;
};

struct Derived : Base {
    void f(); // 没有 const，不是重写，而是隐藏；没有 override 时编译器不一定提醒
};
```

工程建议：

1. 派生类重写虚函数时统一写 `override`，提高可读性并让编译器检查签名。
2. `override` 只能用于虚函数，普通成员函数不能使用。
3. `override` 不改变运行时派发机制，只提供编译期校验。
4. `final` 可以和 `override` 配合，表示当前函数覆盖基类虚函数，且禁止更深层派生类继续覆盖。

```cpp
struct Derived : Base {
    void handle(int) override final;
};
```

## 面试回答模板

`override` 用来声明派生类函数确实是在覆盖基类虚函数，核心价值是让编译器检查函数名、参数列表、`const`、引用限定符等签名是否一致。没有 `override` 时，派生类很容易因为少写 `const` 或参数类型不同，把重写写成隐藏，导致运行时多态不生效。`override` 本身不改变虚函数表机制，只是编译期安全检查，工程上建议所有重写虚函数都加。
