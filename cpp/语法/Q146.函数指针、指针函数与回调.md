# Q146.函数指针、指针函数与回调

## 1. 函数指针

函数指针是指向函数的指针。它保存函数入口地址，可以通过它间接调用函数。

```cpp
int add(int a, int b) {
    return a + b;
}

int (*fp)(int, int) = add;
int ans = fp(1, 2);
```

这里 `fp` 是函数指针，类型是：

```text
int (*)(int, int)
```

含义是：指向一个函数，这个函数接收两个 `int`，返回 `int`。

## 2. 指针函数

指针函数是返回指针的函数。

```cpp
int* find(int* arr, int n, int target) {
    for (int i = 0; i < n; ++i) {
        if (arr[i] == target) {
            return &arr[i];
        }
    }
    return nullptr;
}
```

判断方式：

```text
int (*fp)(int)  // 函数指针
int* f(int)    // 指针函数
```

括号优先级很关键。`*` 和函数名结合，通常是函数指针；返回类型里带 `*`，通常是指针函数。

## 3. C++ 回调

回调是把一段可执行逻辑传给另一个模块，由对方在合适时机调用。

常见形式：

1. 函数指针。
2. 函数对象。
3. lambda。
4. `std::function`。
5. 成员函数指针 + 对象指针。

### 函数指针回调

```cpp
#include <iostream>

void run(int x, void (*callback)(int)) {
    callback(x);
}

void print(int x) {
    std::cout << x << std::endl;
}

int main() {
    run(10, print);
}
```

函数指针轻量，但只能保存普通函数或无捕获 lambda，不能直接保存有状态闭包。

### std::function 回调

```cpp
#include <functional>
#include <iostream>

void run(int x, const std::function<void(int)>& callback) {
    callback(x);
}

int main() {
    int base = 5;
    run(10, [base](int x) {
        std::cout << x + base << std::endl;
    });
}
```

`std::function` 可以类型擦除，统一保存函数指针、lambda、函数对象，但可能有分配和间接调用开销。

### 模板回调

性能敏感场景可以用模板避免 `std::function` 的类型擦除成本：

```cpp
template <typename Callback>
void runFast(int x, Callback&& callback) {
    callback(x);
}
```

## 4. 真实应用

1. 异步 I/O 完成后调用回调处理结果。
2. 定时器到期后调用回调。
3. 事件循环中注册事件处理函数。
4. 排序函数传入比较器。
5. RPC 框架收到响应后触发业务回调。

## 5. 回调里的对象释放和资源管理

回调最容易出问题的是生命周期：注册回调时对象还活着，真正触发时对象可能已经释放，或者回调内部释放对象导致当前调用链继续访问悬空指针。

常见做法：

1. **同步回调**：调用方保证回调执行期间对象仍然活着，可以传引用或裸指针，但不要把它保存到异步环境。
2. **异步回调延长生命周期**：如果回调必须保证对象活到执行结束，可以捕获 `shared_ptr`。
3. **异步回调不强行续命**：如果对象销毁后回调应自动失效，捕获 `weak_ptr`，执行时 `lock()`，失败则直接返回。
4. **注册句柄 RAII**：事件系统返回一个 `Registration`/`ScopedConnection`，析构时自动取消回调。
5. **取消和关闭协议**：对象析构前先标记 closing，取消 timer/fd/event，再等待正在执行的回调退出。

推荐模式：

```cpp
class Session : public std::enable_shared_from_this<Session> {
public:
    void start() {
        std::weak_ptr<Session> weak = shared_from_this();
        loop_.runLater([weak] {
            auto self = weak.lock();
            if (!self) {
                return;
            }
            self->onEvent();
        });
    }

private:
    void onEvent();
    EventLoop& loop_;
};
```

如果回调里需要释放某个对象，不建议直接 `delete this` 或在对象方法执行中销毁自身。更稳的做法是把释放动作交给拥有者，或者通过 `shared_ptr`/`weak_ptr`、引用计数、事件循环延迟销毁来保证当前调用栈不会继续访问已释放对象。

易错点：

1. lambda 捕获 `this` 后异步执行，对象已析构会 UAF。
2. 回调持有 `shared_ptr`，对象又持有回调，可能形成循环引用，要用 `weak_ptr` 打断。
3. 在持锁状态执行用户回调，回调反过来调用原对象方法，容易死锁或重入。
4. 取消回调不等于正在执行的回调立刻结束，要处理 in-flight 回调。

## 6. 易错点

1. 回调对象捕获引用时，要保证被引用对象生命周期长于回调执行时间。
2. 跨线程回调要关注线程安全和执行线程，不能默认在注册线程执行。
3. `std::function` 可能有额外开销，热路径可以用模板或函数指针。
4. 成员函数指针不能当普通函数指针用，必须绑定对象。
5. 回调中不要在持锁状态调用未知用户逻辑，容易引发死锁或重入问题。

## 7. 面试回答模板

函数指针是指向函数入口的指针，例如 `int (*fp)(int,int)`；指针函数是返回指针的函数，例如 `int* f(int)`。回调就是把可执行逻辑交给其他模块稍后调用，C++ 中可以用函数指针、lambda、函数对象、`std::function` 或模板参数实现。函数指针轻量但表达能力有限，`std::function` 灵活但有类型擦除开销，异步和跨线程回调要特别注意捕获对象生命周期。
