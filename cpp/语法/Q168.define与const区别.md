# Q168. define 与 const 区别

`#define` 和 `const` 都能表达“常量”，但它们属于完全不同的机制：`#define` 是预处理阶段的文本替换，`const` 是 C++ 语言层面的带类型对象。

## 1. 核心区别

| 对比项 | `#define` | `const` |
| --- | --- | --- |
| 处理阶段 | 预处理阶段 | 编译阶段 |
| 本质 | 文本替换 | 有类型的常量对象 |
| 类型检查 | 没有 | 有 |
| 作用域 | 从定义处到 `#undef` 或文件结束 | 遵循 C++ 作用域规则 |
| 调试信息 | 通常没有变量符号 | 通常可以调试查看 |
| 地址 | 不能取宏本身地址 | 必要时可取地址 |
| 副作用风险 | 宏参数可能被重复求值 | 表达式求值规则正常 |

示例：

```cpp
#define SQUARE(x) ((x) * (x))

const int limit = 1024;
constexpr int buffer_size = 4096;

int a = 3;
int b = SQUARE(++a); // ++a 可能被展开两次，容易出错
```

## 2. define 的特点

`#define` 适合做条件编译、平台开关、头文件保护和少数必须在预处理阶段完成的宏：

```cpp
#define ENABLE_TRACE 1

#if ENABLE_TRACE
// trace code
#endif
```

但普通常量和函数逻辑不推荐用宏：

1. 宏没有类型安全，`MAX(a, b)` 这类宏可能出现重复求值。
2. 宏只做文本替换，不遵守命名空间和类作用域。
3. 宏污染全局，容易和第三方库符号冲突。
4. 编译错误常出现在展开后的代码里，可读性差。

## 3. const、constexpr 和 enum

C++ 中优先使用语言级工具：

1. `const`：运行期不可修改的对象，是否编译期常量取决于初始化表达式和上下文。
2. `constexpr`：要求能在编译期求值，适合数组大小、模板参数、编译期计算。
3. `enum class`：适合定义一组具名离散值，避免普通宏污染作用域。
4. `inline constexpr`：C++17 后适合在头文件中定义全局常量，避免多重定义问题。

```cpp
namespace net {
inline constexpr int kDefaultPort = 8080;
}

enum class Role {
    User,
    Admin,
};
```

## 4. 易错点

1. `const int n = runtime_value;` 不一定是编译期常量。
2. 头文件里的非 `inline` 全局 `const`、`extern const` 要注意链接属性和 ODR。
3. 宏函数参数必须加括号，但加括号也不能解决重复求值问题。
4. 宏定义常量无法被命名空间隔离，工程中容易造成污染。
5. C++ 中很多宏都可以被 `constexpr` 函数、模板、`using`、`enum class` 替代。

## 5. define 和 inline 的区别

`#define` 宏函数和 `inline` 函数都可能减少函数调用开销，但机制完全不同。

| 对比项 | 宏函数 | `inline` 函数 |
| --- | --- | --- |
| 处理阶段 | 预处理文本替换 | 编译器语义分析后决定是否内联 |
| 类型检查 | 没有 | 有完整类型检查 |
| 作用域 | 宏定义范围内全局替换 | 遵守命名空间、类作用域和访问控制 |
| 调试 | 错误常出现在展开后代码 | 更接近普通函数 |
| 副作用 | 参数可能重复求值 | 参数只按函数调用语义求值 |
| 是否一定内联 | 展开是文本层面的 | `inline` 只是建议和 ODR 语义，编译器可拒绝 |

示例：

```cpp
#define MAX(a, b) ((a) > (b) ? (a) : (b))

inline int maxInt(int a, int b) {
    return a > b ? a : b;
}

int x = 1;
int y = MAX(++x, 10); // ++x 可能被求值多次
```

现代 C++ 中，普通宏函数优先改成 `inline` 函数、`constexpr` 函数或模板函数。宏仍适合条件编译、编译器属性包装、跨平台开关等必须发生在预处理阶段的场景。

## 6. 面试回答模板

`#define` 是预处理阶段的文本替换，没有类型检查、不遵守作用域，适合条件编译和头文件保护，但普通常量和函数逻辑不推荐用宏。`const` 是 C++ 语言层面的带类型常量，编译器会做类型检查，遵守作用域，也更利于调试。需要编译期常量时优先用 `constexpr` 或 `inline constexpr`，需要一组枚举值时用 `enum class`。宏函数和 `inline` 的区别是：宏是文本替换，`inline` 仍是函数语义，有类型检查、作用域和调试信息；是否真正内联由编译器优化决定。
