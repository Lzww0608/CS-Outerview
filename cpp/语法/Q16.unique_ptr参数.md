# unique_ptr

`unique_ptr` 相比于手工 `new` 与 `delete` 应为一个零额外开销的智能指针（相比于 raw pointer）。因此，如何销毁对象，对 `unique_ptr` 来讲，默认作为一个静态信息存放在模板的参数里。在使用静态删除器时，它的动态信息，每对象的空间开销，则只有一个指针的大小。删除器的额外开销对 `shared_ptr` 来讲则不是大问题：本来就需要额外分配内存放控制块，再多点信息也就没什么大不了了。所以相对于，`shared_ptr` 来讲 `unique_ptr` 多了一个静态信息。

代码示例如下：

```c++
//x86-64 gcc 13.2
//-std = c++20 -pthread - O3
#include <cstdio>
#include <memory>

using namespace std;

struct file_closer {
    void operator()(FILE* fp) const
    {
        fclose(fp);
    }
};

void test1(const char* filename)
{
    unique_ptr<FILE, file_closer> ptr{fopen(filename, "r")};
    printf("sizeof of unique_ptr<FILE, file_closer> is %zu\n", sizeof ptr);
}

void test2(const char* filename)
{
    unique_ptr<FILE, void (*)(FILE*)> ptr{fopen(filename, "r"),
                                          [](FILE* fp) { fclose(fp); }};
    printf("sizeof of unique_ptr<FILE, void (*)(FILE*)> is %zu\n", sizeof ptr);
}
#if __cplusplus >= 202002L
//lambdas in unevaluated contexts ——C++20 supports
void test3(const char* filename)
{
    unique_ptr<FILE, decltype([](FILE* fp) { fclose(fp); })> ptr{
        fopen(filename, "r")};
    printf("sizeof of unique_ptr<FILE, decltype(lambda)> is %zu\n", sizeof ptr);
}

#endif

int main()
{
    test1("test.cpp");
    test2("test.cpp");
#if __cplusplus >= 202002L
    test3("test.cpp");
    auto a = make_unique<int>(5);
    printf("sizeof of unique_ptr is %zu\n", sizeof a);
#endif
}
/*The deleters of test1 ans test3 are static, determinable at compile time. The deleter of 
test3 are dynamic, allowing for reassignment and adjustment at running time. 
*/
```

上述结果如下。可见如果是静态删除器，则大小与`raw pointer`没有区别，若是动态删除器，则会增加指针的大小。

## 使用场景

`unique_ptr` 表达独占所有权：同一时刻只有一个对象负责释放资源。它不能拷贝，只能移动。

常见场景：

1. **工厂函数返回堆对象**：调用方拿到资源所有权。

```cpp
std::unique_ptr<Foo> createFoo() {
    return std::make_unique<Foo>();
}
```

2. **类成员拥有资源**：类析构时自动释放，避免手写析构逻辑。

```cpp
class Session {
public:
    Session() : buffer_(std::make_unique<char[]>(4096)) {}

private:
    std::unique_ptr<char[]> buffer_;
};
```

3. **多态对象独占持有**：基类指针指向派生类对象，要求基类析构函数为 `virtual`。

```cpp
std::unique_ptr<Base> p = std::make_unique<Derived>();
```

4. **管理非内存资源**：配合自定义删除器管理 `FILE*`、socket fd、数据库连接等。

```cpp
using FilePtr = std::unique_ptr<FILE, decltype(&fclose)>;
FilePtr fp(fopen("a.txt", "r"), &fclose);
```

5. **容器中保存不可拷贝对象**：例如 `std::vector<std::unique_ptr<Task>>`，容器管理指针，任务对象不被复制。

## 和 `shared_ptr` 的选择

1. 默认优先使用 `unique_ptr`，因为所有权清晰、开销低。
2. 只有确实存在多个 owner，且最后一个 owner 才能释放资源时，才使用 `shared_ptr`。
3. 如果只是临时借用对象，传 `T*` 或 `T&`，不要为了传参把 `unique_ptr` 升级成 `shared_ptr`。
4. 从 `unique_ptr` 可以移动构造 `shared_ptr`，反过来不行，因为共享所有权不能无损恢复成独占所有权。

## 易错点

1. `unique_ptr` 不能拷贝，函数传参如果要转移所有权应使用 `std::move`。
2. `unique_ptr<T[]>` 用于数组，普通 `unique_ptr<T>` 不应用来管理 `new T[]`。
3. 自定义删除器会影响 `unique_ptr` 类型和对象大小，静态删除器通常更省空间。
4. 不要返回裸指针让调用者猜测是否需要释放；所有权转移用 `unique_ptr` 更明确。

## 手写 `unique_ptr` 的关键点

实现一个简化版 `unique_ptr` 时，核心不是引用计数，而是**独占所有权和移动语义**：

1. 成员变量至少需要一个 `T* ptr_`。
2. 析构函数里 `delete ptr_`。
3. 删除拷贝构造和拷贝赋值，防止两个对象同时拥有同一块内存。
4. 实现移动构造和移动赋值，把指针转移过来，并把源对象置空。
5. 提供 `operator*`、`operator->`、`get()`、`release()`、`reset()`、`swap()` 等基础接口。
6. 如果支持数组和自定义删除器，还要区分 `delete` / `delete[]`，并把删除器纳入类型或对象状态。

面试写代码时可以先实现单对象版本，再说明标准库还处理删除器、数组特化、空基类优化、异常安全和 constexpr 等细节。
