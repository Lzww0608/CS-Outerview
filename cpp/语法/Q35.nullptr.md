# 为什么引入 `nullptr`

在 C++11 之前，空指针通常写成 `0` 或 `NULL`。问题在于 `NULL` 本质上通常是整数常量 `0` 或 `0L`，它既能表示空指针，又会参与整数重载和模板推导，容易产生歧义。

## `NULL` 的问题

```cpp
void f(int);
void f(char*);

f(NULL);    // 可能匹配 f(int)，不一定匹配指针版本
f(nullptr); // 明确匹配 f(char*)
```

主要问题：

1. **类型模糊**：`NULL` 可能被当作整数，而不是指针。
2. **重载歧义**：同时存在整数重载和指针重载时，`NULL` 不一定选择指针版本。
3. **模板推导不清晰**：模板参数可能被推导成整型，而不是指针类型。
4. **可读性差**：`0` 既可能是数字 0，也可能是空指针。

## `nullptr` 的语义

`nullptr` 是 C++11 引入的空指针字面量，类型是 `std::nullptr_t`。

特点：

1. 可以隐式转换为任意指针类型。
2. 可以隐式转换为任意成员指针类型。
3. 不能隐式转换为整数类型。
4. 在重载、模板和泛型代码中能更准确表达“空指针”语义。

```cpp
int* p = nullptr;

if (p == nullptr) {
    // p 没有指向有效对象
}
```

## 面试回答模板

`NULL` 在 C++ 中通常是 `0` 或 `0L`，本质偏整数，遇到函数重载时可能匹配到 `int` 版本；`nullptr` 是 C++11 引入的空指针字面量，类型是 `std::nullptr_t`，可以转换成任意指针类型，但不能转换成整数类型。因此现代 C++ 中应优先用 `nullptr` 表达空指针，避免重载和模板推导歧义。
