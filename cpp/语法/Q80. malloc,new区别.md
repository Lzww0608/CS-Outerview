# Q80. malloc, new区别

1.  `malloc`, `free`是`C`语言中的库函数， `new`, `delete`是`C++`中的运算符
2. `new`自动计算分配内存的大小，`malloc`需要手动计算分配内存的大小
3. `new`返回对象类型的指针，`malloc`返回的是`void*`类型，需要显式类型转换
4. `new`分配失败抛出异常，`malloc`分配失败返回`NULL`
5. `new`是在自由存储区（堆）进行分配，`malloc`通常在堆上分配(**`malloc`分配的空间是虚拟内存，物理内存的映射对应关系在初始化的时候被分配，即“延迟分配”，物理内存首次访问的时候才被分配**)
6. `delete`需要类型对象的指针，`free`是`void*`类型的指针



#### 面试潜在问题：

1. `malloc`分配的是物理内存还是虚拟内存？

   + 虚拟内存

2. `malloc`调用后是否立刻得到物理内存？

   + 并不是，会有“延迟分配”，在初始化的时候才被分配物理内存

3. `free(p)`怎么知道该释放多大的空间？

   + `malloc`时会在分配空间地址前存储“元数据”

   + 内存管理系统会查看“元数据(metadata)”中分配的内存块的大小

4. `free`释放内存之后，内存还在吗？

   + `brk`返回内存池
   + `mmap`释放内存

#### `malloc`, `calloc`, `realloc`

`malloc`, `calloc`, 和 `realloc` 是 C 语言中用于动态内存分配的三个基本函数，它们都定义在 `stdlib.h` 头文件中。尽管这些函数都是用于分配内存，但它们在用法和行为上有一些关键的区别：

### 1. `malloc` (Memory Allocation)

分配指定数量的字节,分配的内存内容是未初始化的，可能包含任何随机数据。当只需要分配内存而不关心其初始内容时使用。

```c
void* malloc(size_t size);
// size：需要分配的内存大小，以字节为单位。
```



### 2. `calloc` (Contiguous Allocation)

为指定数量的元素分配内存，每个元素有指定的大小，并且初始化所有位为零。

```c
void* calloc(size_t num, size_t size);
// num：需要分配的元素数量。
// size：每个元素的大小，以字节为单位。
```



### 3. `realloc` (Re-Allocation)

重新调整之前分配的内存块的大小。

- 如果新大小大于原始大小，额外的内存区域不会被初始化。
- 可以扩大或缩小内存块，如果必要，可能会移动内存块到新位置。

```c
void* realloc(void* ptr, size_t new_size);
// ptr：原有内存块的指针。如果 ptr 为 NULL，realloc 的行为类似于 malloc(new_size)。
// new_size：重新分配的内存块的新大小，以字节为单位。
```

## malloc 底层实现

`malloc` 是 C 库提供的用户态分配器接口，本身不是系统调用。它会先在用户态维护堆块、空闲链表、arena、线程缓存等结构；当现有内存不够时，再通过系统调用向内核申请更多虚拟地址空间。

常见路径：

1. **小块内存**：优先从线程缓存、fastbin、small bin、arena 等用户态结构中取块。
2. **堆扩展**：较小或连续增长的堆空间可能通过 `brk/sbrk` 扩展 program break。
3. **大块内存**：大分配可能直接使用 `mmap` 创建匿名映射。
4. **释放内存**：`free` 通常先把块放回分配器缓存或空闲链表，不一定立刻还给操作系统；大块 `mmap` 可能通过 `munmap` 归还。

简化流程：

```text
malloc(size)
-> 对齐 size，并加上 chunk metadata
-> 查线程缓存或 arena 空闲链表
-> 找到合适 chunk 就拆分返回
-> 找不到则 brk/mmap 向内核申请
-> 返回用户可用地址
```

## free 怎么知道释放多大

分配器通常会在返回给用户的地址前后保存 chunk 元数据，例如块大小、状态位、相邻块信息等。

```text
[ chunk header | user memory ... ]
                 ^
                 malloc 返回给用户的指针
```

`free(p)` 会根据 `p` 反推 chunk header，从元数据中知道块大小并把它放回对应的空闲结构。

所以：

1. `free` 不需要用户传 size。
2. 对不是 `malloc/calloc/realloc` 返回的指针调用 `free` 是未定义行为。
3. 重复 `free` 同一个指针会破坏分配器元数据，可能导致崩溃或安全漏洞。

## malloc 与物理内存

`malloc` 返回的是用户态虚拟地址，不代表立刻占用对应大小的物理内存。

1. 内核可能只建立虚拟内存区域，首次写入时才触发缺页分配物理页。
2. Linux overcommit 策略可能允许申请超过物理内存和 swap 的虚拟内存。
3. 真正内存压力取决于 RSS、工作集、缺页和 cgroup 限制。

## 常见实现

1. glibc `ptmalloc`：多 arena、bin、tcache。
2. jemalloc：强调低碎片和多线程扩展性，Redis 等系统常用。
3. tcmalloc：线程缓存友好，适合高并发服务。
4. mimalloc：现代通用分配器，关注低延迟和碎片控制。

## new 一定会用到 malloc 吗

不一定。C++ 标准只规定 `new` 表达式要完成两件事：先分配足够的原始内存，再在这块内存上调用构造函数。标准没有要求底层必须调用 `malloc`。

一次普通 `new T(args...)` 可以拆成：

```text
operator new(sizeof(T))   // 分配原始内存
T::T(args...)             // 构造对象
```

一次 `delete p` 可以拆成：

```text
p->~T()                   // 析构对象
operator delete(p)        // 释放原始内存
```

很多标准库实现里的全局 `::operator new` 可能最终调用 `malloc`，但这只是实现选择。项目可以重载全局或类作用域的 `operator new`，让对象来自内存池、共享内存、mmap、固定 arena 或调试分配器。

## new 出来的对象能不能用 free 释放

不能。`new` 和 `delete` 必须配对，`new[]` 和 `delete[]` 必须配对，`malloc/calloc/realloc` 和 `free` 必须配对。用 `new` 创建的对象再用 `free` 释放是未定义行为。

原因分两层：

1. **对象生命周期不匹配**：`free` 只释放原始内存，不会调用析构函数。类对象持有文件、锁、堆内存、socket 等资源时会泄漏或破坏状态。
2. **分配/释放函数不匹配**：`new` 表达式调用的是 `operator new`，它不一定来自 `malloc`。即使某个实现里全局 `operator new` 最终调用了 `malloc`，语言规则也不允许用 `free` 释放 `new` 的结果。

基础类型也不能例外：

```cpp
int* p = new int(10);
free(p);        // 未定义行为，即使 int 没有析构函数也不允许
```

基础类型没有析构函数问题，但仍然违反了分配/释放接口的配对约定。正确写法是：

```cpp
int* p = new int(10);
delete p;
```

## new[] 释放时要不要写元素个数

不需要，也不能写。数组释放使用：

```cpp
T* p = new T[n];
delete[] p;
```

实现通常会在分配结果附近保存数组元素个数或分配大小等元数据，尤其是元素类型有非平凡析构函数时，`delete[]` 需要知道要调用多少次析构函数。C++14 以后还可能使用 sized deallocation 优化，但调用方仍然只写 `delete[] p`。

易错点：

1. `new T[n]` 必须用 `delete[]`，不能用 `delete`。
2. `new T` 必须用 `delete`，不能用 `delete[]`。
3. `delete[]` 不需要传 `n`，数组长度由实现保存或通过分配接口信息恢复。
4. 工程中优先用 `std::vector<T>`、`std::array<T, N>` 或智能指针管理数组，减少手动配对错误。

## 重载 operator new

`operator new` 只负责分配原始内存，不负责构造对象。类作用域重载可以让某一类对象走定制分配路径：

```cpp
#include <cstddef>
#include <new>

class Node {
public:
    static void* operator new(std::size_t n) {
        if (void* p = pool_alloc(n)) {
            return p;
        }
        throw std::bad_alloc();
    }

    static void operator delete(void* p) noexcept {
        pool_free(p);
    }

private:
    int value;
    Node* next;
};
```

注意事项：

1. 分配失败时，普通 `operator new` 应抛出 `std::bad_alloc`；`nothrow new` 才返回空指针。
2. 如果重载了 `operator new[]`，通常也要匹配重载 `operator delete[]`。
3. C++14 以后可能涉及 sized delete，C++17 以后还要关注 over-aligned 类型的对齐版本。
4. placement new 不分配内存，只在已有 buffer 上构造对象：`new (buf) T()`。
5. 自定义分配器必须处理对齐、异常安全、统计和多线程同步，否则很容易引入隐蔽内存错误。

## 面试回答模板

`malloc` 是库函数，不是系统调用。它底层由用户态内存分配器维护空闲块、元数据、arena 和线程缓存；小对象通常直接从缓存或空闲链表中分配，不进内核；空间不足或大块分配时才通过 `brk` 或 `mmap` 向内核申请虚拟内存。`free` 能知道释放大小，是因为分配器在用户指针附近保存了 chunk 元数据。`new` 和 `malloc` 的核心区别是 `new` 会分配内存并调用构造函数，失败默认抛异常；`malloc` 只分配未初始化原始内存，失败返回空指针。`new` 不一定必须调用 `malloc`，可以通过重载 `operator new` 改成内存池、mmap 或其他分配策略。
