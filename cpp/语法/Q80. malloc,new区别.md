# Q80. malloc, new区别

1.  `malloc`, `free`是`C`语言中的库函数， `new`, `delete`是`C++`中的运算符
2. `new`自动计算分配内存的大小，`malloc`需要手动计算分配内存的大小
3. `new`返回对象类型的指针，`malloc`返回的是`void*`类型，需要显式类型转换
4. `new`分配失败抛出异常，`malloc`分配失败返回`NULL`
5. `new`是在自由存储区（堆）进行分配，`malloc`通常在堆上分配(**`malloc`分配的空间是虚拟内存，物理内存的映射对应关系在初始化的时候被分配，即“延迟分配”，物理内存首次访问的时候才被分配**)
6. `delete`需要类型对象的指针，`free`是`void*`类型的指针



#### 面试潜在问题：

1. `malloc`分配的是物理内存还是虚拟内存？

   + 虚拟内存

2. `malloc`调用后是否立刻得到物理内存？

   + 并不是，会有“延迟分配”，在初始化的时候才被分配物理内存

3. `free(p)`怎么知道该释放多大的空间？

   + `malloc`时会在分配空间地址前存储“元数据”

   + 内存管理系统会查看“元数据(metadata)”中分配的内存块的大小

4. `free`释放内存之后，内存还在吗？

   + `brk`返回内存池
   + `mmap`释放内存

#### `malloc`, `calloc`, `realloc`

`malloc`, `calloc`, 和 `realloc` 是 C 语言中用于动态内存分配的三个基本函数，它们都定义在 `stdlib.h` 头文件中。尽管这些函数都是用于分配内存，但它们在用法和行为上有一些关键的区别：

### 1. `malloc` (Memory Allocation)

分配指定数量的字节,分配的内存内容是未初始化的，可能包含任何随机数据。当只需要分配内存而不关心其初始内容时使用。

```c
void* malloc(size_t size);
// size：需要分配的内存大小，以字节为单位。
```



### 2. `calloc` (Contiguous Allocation)

为指定数量的元素分配内存，每个元素有指定的大小，并且初始化所有位为零。

```c
void* calloc(size_t num, size_t size);
// num：需要分配的元素数量。
// size：每个元素的大小，以字节为单位。
```



### 3. `realloc` (Re-Allocation)

重新调整之前分配的内存块的大小。

- 如果新大小大于原始大小，额外的内存区域不会被初始化。
- 可以扩大或缩小内存块，如果必要，可能会移动内存块到新位置。

```c
void* realloc(void* ptr, size_t new_size);
// ptr：原有内存块的指针。如果 ptr 为 NULL，realloc 的行为类似于 malloc(new_size)。
// new_size：重新分配的内存块的新大小，以字节为单位。
```

## malloc 底层实现

`malloc` 是 C 库提供的用户态分配器接口，本身不是系统调用。它会先在用户态维护堆块、空闲链表、arena、线程缓存等结构；当现有内存不够时，再通过系统调用向内核申请更多虚拟地址空间。

常见路径：

1. **小块内存**：优先从线程缓存、fastbin、small bin、arena 等用户态结构中取块。
2. **堆扩展**：较小或连续增长的堆空间可能通过 `brk/sbrk` 扩展 program break。
3. **大块内存**：大分配可能直接使用 `mmap` 创建匿名映射。
4. **释放内存**：`free` 通常先把块放回分配器缓存或空闲链表，不一定立刻还给操作系统；大块 `mmap` 可能通过 `munmap` 归还。

简化流程：

```text
malloc(size)
-> 对齐 size，并加上 chunk metadata
-> 查线程缓存或 arena 空闲链表
-> 找到合适 chunk 就拆分返回
-> 找不到则 brk/mmap 向内核申请
-> 返回用户可用地址
```

## free 怎么知道释放多大

分配器通常会在返回给用户的地址前后保存 chunk 元数据，例如块大小、状态位、相邻块信息等。

```text
[ chunk header | user memory ... ]
                 ^
                 malloc 返回给用户的指针
```

`free(p)` 会根据 `p` 反推 chunk header，从元数据中知道块大小并把它放回对应的空闲结构。

所以：

1. `free` 不需要用户传 size。
2. 对不是 `malloc/calloc/realloc` 返回的指针调用 `free` 是未定义行为。
3. 重复 `free` 同一个指针会破坏分配器元数据，可能导致崩溃或安全漏洞。

## malloc 与物理内存

`malloc` 返回的是用户态虚拟地址，不代表立刻占用对应大小的物理内存。

1. 内核可能只建立虚拟内存区域，首次写入时才触发缺页分配物理页。
2. Linux overcommit 策略可能允许申请超过物理内存和 swap 的虚拟内存。
3. 真正内存压力取决于 RSS、工作集、缺页和 cgroup 限制。

## 常见实现

1. glibc `ptmalloc`：多 arena、bin、tcache。
2. jemalloc：强调低碎片和多线程扩展性，Redis 等系统常用。
3. tcmalloc：线程缓存友好，适合高并发服务。
4. mimalloc：现代通用分配器，关注低延迟和碎片控制。

## 面试回答模板

`malloc` 是库函数，不是系统调用。它底层由用户态内存分配器维护空闲块、元数据、arena 和线程缓存；小对象通常直接从缓存或空闲链表中分配，不进内核；空间不足或大块分配时才通过 `brk` 或 `mmap` 向内核申请虚拟内存。`free` 能知道释放大小，是因为分配器在用户指针附近保存了 chunk 元数据。`malloc` 返回的是虚拟内存，物理页通常按需分配。
