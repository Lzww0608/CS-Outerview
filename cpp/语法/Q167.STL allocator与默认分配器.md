# Q167.STL allocator 与默认分配器

`allocator` 是 STL 容器和底层内存分配策略之间的抽象层。容器负责元素语义，`allocator` 负责申请原始内存、释放原始内存，以及配合构造和析构对象。

## 1. allocator 解决什么问题

以 `std::vector<T>` 为例，容器扩容时需要的是一段能放下 `n` 个 `T` 的原始内存，而不是马上构造 `n` 个对象。典型流程是：

1. `allocator<T>::allocate(n)` 申请能容纳 `n` 个 `T` 的未初始化内存。
2. 使用 placement new 或 `allocator_traits::construct` 在指定位置构造对象。
3. 元素迁移或销毁时调用析构函数。
4. `allocator<T>::deallocate(p, n)` 释放原始内存。

这把“内存申请释放”和“对象生命周期”拆开了。`malloc/free` 只处理字节内存，`new/delete` 同时处理内存和构造析构，而 STL 容器需要更精细的控制。

## 2. 标准接口和 allocator_traits

现代 C++ 中，容器通常不直接依赖 allocator 的所有成员，而是通过 `std::allocator_traits<Alloc>` 访问分配器能力：

```cpp
#include <memory>

template <class T, class Alloc = std::allocator<T>>
class SimpleBuffer {
public:
    explicit SimpleBuffer(size_t n) : n_(n) {
        data_ = traits::allocate(alloc_, n_);
    }

    ~SimpleBuffer() {
        traits::deallocate(alloc_, data_, n_);
    }

private:
    using traits = std::allocator_traits<Alloc>;

    Alloc alloc_;
    T* data_ = nullptr;
    size_t n_ = 0;
};
```

`allocator_traits` 的意义是屏蔽不同 allocator 的接口差异，并提供默认行为。自定义 allocator 时，通常只需要实现 `value_type`、`allocate`、`deallocate` 等核心接口。

## 3. 默认分配器是什么

标准只规定 `std::allocator` 的语义，不规定它必须如何实现。不同标准库实现可以不同：

1. `std::allocator<T>` 通常最终调用全局 `::operator new` 和 `::operator delete`。
2. 全局 `operator new` 常再调用运行库分配器，例如 glibc `malloc`、jemalloc、tcmalloc 或平台自己的堆分配器。
3. 早期 SGI STL 有二级配置器，小对象走内存池，大对象走 `malloc`；这不是现代 C++ 标准对 `std::allocator` 的强制要求。
4. C++17 引入 `std::pmr` 多态内存资源，可以把容器接到单调缓冲区、同步池、非同步池等资源上。

面试里如果问“最新版 STL 默认使用什么分配器”，更稳妥的回答是：标准默认类型是 `std::allocator<T>`，具体底层由标准库实现决定；不能把 SGI STL 的二级配置器当成所有现代实现的事实。

## 4. 容器扩容时资源怎么处理

容器扩容不是简单 `realloc`。因为 C++ 对象可能有构造、析构、异常安全和移动语义：

1. 申请更大的新内存。
2. 优先移动构造旧元素；如果移动可能抛异常且拷贝可用，容器可能选择拷贝以保证强异常安全。
3. 新元素构造完成后，析构旧内存中的对象。
4. 释放旧内存。

所以 `vector` 中保存文件句柄、锁、socket 等资源对象时，正确做法是让对象实现 RAII、移动构造和移动赋值，而不是依赖容器“按字节搬迁”。

## 5. pmr 和内存池场景

`std::pmr` 适合把“分配策略”从容器类型中拆出来：

```cpp
#include <array>
#include <memory_resource>
#include <vector>

std::array<std::byte, 4096> buf;
std::pmr::monotonic_buffer_resource pool(buf.data(), buf.size());
std::pmr::vector<int> v(&pool);
```

常见场景：

1. 请求级临时对象：用 `monotonic_buffer_resource`，请求结束统一释放。
2. 大量小对象：用 pool resource 降低频繁 `malloc/free` 成本。
3. 游戏、交易、实时服务：用固定内存池控制延迟抖动。

## 6. 易错点

1. `allocator` 管的是原始内存，不等于对象已经构造。
2. `allocate(n)` 的参数是元素个数，不是字节数。
3. 自定义 allocator 必须满足容器对对齐、异常、安全释放的要求。
4. 不要假设所有 STL 默认分配器都有小对象内存池。
5. 容器扩容会使迭代器、指针、引用失效，和 allocator 是否自定义无关。

## 7. 面试回答模板

STL allocator 是容器和内存分配策略之间的抽象。容器通过 allocator 申请未初始化内存，再用构造函数在这块内存上构造对象，销毁时先析构对象再释放内存。标准默认分配器是 `std::allocator<T>`，通常最终走全局 `operator new/delete`，具体底层取决于标准库和运行库实现。现代工程如果需要控制分配延迟，可以使用自定义 allocator 或 C++17 `std::pmr` 的内存资源。
