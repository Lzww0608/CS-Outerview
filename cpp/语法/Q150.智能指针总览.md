# 智能指针总览

智能指针是用对象生命周期管理资源生命周期的 RAII 工具。它把“谁负责释放资源”写进类型系统中，减少裸指针带来的内存泄漏、重复释放、异常路径泄漏和所有权不清问题。

## 常见智能指针

| 类型 | 所有权语义 | 典型开销 | 适用场景 |
| --- | --- | --- | --- |
| `std::unique_ptr<T>` | 独占所有权，只能移动 | 通常一个裸指针大小 | 工厂返回对象、类成员独占资源、容器保存不可拷贝对象 |
| `std::shared_ptr<T>` | 共享所有权，引用计数 | 对象指针 + 控制块指针，控制块里有原子计数 | 多个模块都需要延长同一对象生命周期 |
| `std::weak_ptr<T>` | 非拥有观察者 | 依赖 `shared_ptr` 控制块 | 打破循环引用、缓存弱引用、观察对象是否仍存活 |
| `std::auto_ptr<T>` | 旧标准转移式所有权 | 已废弃 | 不应再使用，C++17 移除 |

## 核心原理

`unique_ptr` 的核心是独占所有权。它删除拷贝构造和拷贝赋值，只允许移动。对象离开作用域时析构，析构函数调用删除器释放资源，所以它通常能做到接近裸指针的零额外开销。

`shared_ptr` 的核心是控制块。控制块通常保存强引用计数、弱引用计数、删除器、分配器等元数据。复制 `shared_ptr` 会增加强引用计数，析构或 `reset()` 会减少强引用计数；当强引用计数降为 0 时销毁被管理对象，当强弱引用都为 0 时释放控制块。

`weak_ptr` 不增加强引用计数，因此不会延长对象生命周期。使用前需要调用 `lock()` 尝试获得一个 `shared_ptr`，如果对象已经释放则得到空指针。

## shared_ptr 和 unique_ptr 的性能对比

`unique_ptr` 通常是默认优先选择：

1. 对象内通常只保存一个裸指针，默认删除器下大小接近裸指针。
2. 移动只是转移指针值，析构时直接调用删除器。
3. 没有引用计数，没有控制块，没有原子自增自减。

`shared_ptr` 的成本更高：

1. 通常保存对象指针和控制块指针。
2. 控制块里维护强引用计数、弱引用计数、删除器、分配器等元数据。
3. 拷贝和析构需要修改引用计数，标准库实现通常使用原子操作，跨线程频繁拷贝会带来缓存一致性开销。
4. `make_shared` 可以把对象和控制块合并分配，减少一次堆分配并提升局部性，但对象释放和控制块释放时机不同：强引用为 0 时对象析构，弱引用也为 0 时控制块才释放。

选择原则是：能表达独占所有权就用 `unique_ptr`；只有确实需要多个所有者共同延长生命周期，才使用 `shared_ptr`。

## shared_ptr 是线程安全的吗

要分三层说：

1. **不同 `shared_ptr` 对象共享同一控制块**：多个线程分别拷贝、析构自己的 `shared_ptr` 实例，引用计数更新是线程安全的。
2. **同一个 `shared_ptr` 变量本身**：如果多个线程同时读写同一个 `shared_ptr` 对象，例如一个线程 `reset`，另一个线程赋值，仍然需要锁或 `std::atomic<std::shared_ptr<T>>`。
3. **被管理对象 `T`**：`shared_ptr` 不保证 `T` 的成员访问线程安全。多个线程通过 `shared_ptr` 同时修改同一个对象，仍然需要互斥锁、原子变量或其他同步机制。

示例：

```cpp
auto p = std::make_shared<int>(0);
std::shared_ptr<int> p1 = p;
std::shared_ptr<int> p2 = p;

// p1 和 p2 在不同线程各自拷贝/析构，控制块引用计数安全。
// 但两个线程同时 ++(*p1) 和 ++(*p2) 不是线程安全的。
```

## auto_ptr 为什么被废弃

`std::auto_ptr` 是 C++98 时代的智能指针，C++11 开始被弃用，C++17 已移除。它的问题在于“拷贝即转移所有权”：

```cpp
std::auto_ptr<int> p1(new int(1));
std::auto_ptr<int> p2 = p1; // p1 变为空，所有权被悄悄转走
```

这种语义会造成几个问题：

1. **拷贝语义反直觉**：看起来是拷贝，实际是所有权转移，源对象被置空。
2. **不适合标准容器**：容器元素拷贝、移动、重排时可能意外转移所有权。
3. **接口表达不清**：函数参数按值传递 `auto_ptr` 可能偷走调用方资源。
4. **无法管理数组**：没有像 `unique_ptr<T[]>` 这样的清晰数组特化。

`unique_ptr` 用“禁止拷贝、允许显式移动”替代它：

```cpp
std::unique_ptr<int> p1(new int(1));
std::unique_ptr<int> p2 = std::move(p1); // 显式表达所有权转移
```

因此现代 C++ 不应再使用 `auto_ptr`。需要独占所有权用 `unique_ptr`，需要共享所有权才用 `shared_ptr`，需要弱观察用 `weak_ptr`。

## 选择原则

1. 默认使用 `unique_ptr` 表达独占所有权。
2. 只有确实需要共享生命周期时才使用 `shared_ptr`。
3. 只借用对象时使用 `T&` 或 `T*`，不要为了传参随意引入共享所有权。
4. `shared_ptr` 出现双向引用时，用 `weak_ptr` 打断环。
5. 管理 `FILE*`、socket fd、连接句柄等非内存资源时，配合自定义删除器。

## 易错点

1. `shared_ptr` 的引用计数线程安全，不代表被管理对象线程安全。
2. 不要用同一个裸指针构造两个独立 `shared_ptr`，否则会产生两个控制块并重复释放。
3. `unique_ptr::release()` 只是放弃所有权并返回裸指针，不会释放资源。
4. `shared_from_this()` 只有对象已经被 `shared_ptr` 管理时才能安全使用。
5. 自定义删除器会影响 `unique_ptr` 的类型和大小，函数指针删除器通常会让对象多保存一个指针。

## 真实场景

1. RPC 请求上下文可以用 `shared_ptr` 跨异步回调保存生命周期，但请求内部独占 buffer 更适合 `unique_ptr`。
2. 连接池中的连接对象可以由池持有 `shared_ptr`，业务侧短暂借用时可以返回带自定义归还逻辑的智能指针。
3. GUI 或观察者模式中，观察者列表避免强引用对象本身，常用 `weak_ptr` 防止对象无法释放。
4. C API 返回的资源可以封装成 `unique_ptr<FILE, decltype(&fclose)>` 这类 RAII 对象，避免异常路径遗漏释放。

## 面试回答模板

智能指针本质是 RAII，把资源释放绑定到对象析构。`unique_ptr` 表达独占所有权，只能移动，通常只有一个指针大小，没有引用计数，默认优先使用；`shared_ptr` 通过控制块和引用计数表达共享所有权，最后一个强引用释放对象，但拷贝和析构要维护原子引用计数，成本高于 `unique_ptr`；`weak_ptr` 不拥有对象，用来观察 `shared_ptr` 管理的对象并打破循环引用。`shared_ptr` 的控制块计数是线程安全的，但同一个 `shared_ptr` 变量并发读写、以及被管理对象本身的并发访问都不自动安全。实际项目里要先说清楚所有权模型，再选择指针类型，不能为了方便把所有裸指针都换成 `shared_ptr`。

## 多线程下使用智能指针的注意事项

智能指针在多线程下要分清三层安全边界：

1. **控制块引用计数**：多个线程持有不同的 `shared_ptr` 实例，指向同一个控制块，各自拷贝和析构时引用计数更新是线程安全的。
2. **同一个智能指针变量本身**：多个线程同时读写同一个 `shared_ptr` 变量，例如一个线程 `reset`、另一个线程赋值或读取，需要外部加锁，或使用 `std::atomic<std::shared_ptr<T>>`。
3. **被管理对象 `T`**：`shared_ptr<T>` 只保证对象活着，不保证 `T` 的成员访问线程安全。多个线程同时修改 `T` 仍然需要 mutex、atomic 或消息投递模型。

典型写法是先复制一份局部 `shared_ptr`，延长当前操作期间的生命周期：

```cpp
std::shared_ptr<Connection> conn;
std::mutex m;

void send_message(std::string msg) {
    std::shared_ptr<Connection> local;
    {
        std::lock_guard<std::mutex> lock(m);
        local = conn;
    }
    if (local) {
        local->send(std::move(msg)); // 对象生命周期安全，send 内部仍要处理并发语义
    }
}
```

工程注意点：

1. 不要把 `this` 裸指针直接丢给异步回调，优先用 `enable_shared_from_this` 获取 `shared_ptr`，或用 `weak_ptr` 防止回调延长对象生命周期。
2. 高频跨线程拷贝 `shared_ptr` 会争用控制块里的原子引用计数，可能形成 cache line 热点；热路径可考虑对象归属单线程、传递裸观察指针加生命周期约束、对象池或 intrusive 引用计数。
3. `weak_ptr::expired()` 和 `use_count()` 在并发下只能作为瞬时观察，真正使用对象必须调用 `lock()`，并检查返回的 `shared_ptr` 是否为空。
4. 不要用两个独立 `shared_ptr` 管理同一个裸指针，否则会产生两个控制块并重复释放。
5. 跨线程释放对象时，析构函数会运行在最后一个 `shared_ptr` 析构所在的线程；如果资源必须在特定 EventLoop 或渲染线程释放，需要自定义 deleter 或投递销毁任务。
