# Q149. C++ 程序内存分布

## 1. 典型内存区域

C++ 程序运行时常见内存区域可以按生命周期和用途划分：

| 区域 | 内容 | 生命周期 |
| --- | --- | --- |
| 代码段 `.text` | 编译后的机器指令 | 程序运行期间 |
| 只读数据段 `.rodata` | 字符串字面量、虚函数表、只读常量 | 程序运行期间 |
| 已初始化数据段 `.data` | 已初始化的全局变量、静态变量 | 程序运行期间 |
| 未初始化数据段 `.bss` | 未初始化或初始化为 0 的全局/静态变量 | 程序运行期间 |
| 堆 heap | `new/malloc` 动态分配对象 | 手动释放或进程结束 |
| 栈 stack | 函数栈帧、局部变量、返回地址 | 函数调用期间 |
| mmap 区 | 动态库、文件映射、大块匿名映射 | 映射存在期间 |
| TLS 区 | `thread_local` 变量 | 线程生命周期 |

不同平台、编译器和链接方式会影响具体布局，但大方向一致。

## 2. 示例

```cpp
const int g_const = 1;      // 可能在 .rodata
int g_init = 2;             // .data
int g_zero;                 // .bss
static int s_init = 3;      // .data

int main() {
    int local = 4;          // stack
    static int local_s = 5; // .data
    auto* p = new int(6);   // p 在 stack，*p 在 heap
    const char* str = "hi"; // str 在 stack，"hi" 在 .rodata
    delete p;
}
```

## 3. 栈和堆的区别

1. 栈由编译器和运行时按函数调用自动管理，分配释放很快。
2. 堆由分配器管理，适合生命周期跨函数或大小运行期决定的对象。
3. 栈空间通常较小，大数组或深递归容易栈溢出。
4. 堆分配有元数据、锁或线程缓存成本，也可能产生碎片。

## 4. 虚函数表在哪里

虚函数表通常由编译器在编译期生成，作为只读数据放在 `.rodata` 或类似只读段中。对象里保存的是虚函数表指针 `vptr`，不是虚表本身。

对象构造时，构造函数会初始化或调整 `vptr`。在继承层次中，基类构造阶段 `vptr` 指向基类虚表，派生类构造阶段再更新为派生类虚表。

## 5. 和虚拟内存的关系

上面说的是进程虚拟地址空间中的逻辑区域。真实物理内存由操作系统按页映射：

1. 程序看到的是连续虚拟地址。
2. 物理内存可以不连续。
3. 没访问的页可能没有实际分配物理页。
4. 动态库的只读代码页可以被多个进程共享。

## 6. 面试回答模板

C++ 程序内存分布通常包括代码段、只读数据段、`.data`、`.bss`、堆、栈、mmap 区和 TLS 区。全局和静态变量生命周期贯穿程序，已初始化的在 `.data`，未初始化或 0 初始化的在 `.bss`；字符串字面量、虚函数表常在只读段；局部变量通常在栈上；`new/malloc` 得到的对象在堆上；动态库和大块映射常在 mmap 区。注意这些都是虚拟地址空间布局，真正物理内存由页表按需映射。
