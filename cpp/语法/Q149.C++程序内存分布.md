# Q149. C++ 程序内存分布

## 1. 典型内存区域

C++ 程序运行时常见内存区域可以按生命周期和用途划分：

| 区域 | 内容 | 生命周期 |
| --- | --- | --- |
| 代码段 `.text` | 编译后的机器指令 | 程序运行期间 |
| 只读数据段 `.rodata` | 字符串字面量、虚函数表、只读常量 | 程序运行期间 |
| 已初始化数据段 `.data` | 已初始化的全局变量、静态变量 | 程序运行期间 |
| 未初始化数据段 `.bss` | 未初始化或初始化为 0 的全局/静态变量 | 程序运行期间 |
| 堆 heap | `new/malloc` 动态分配对象 | 手动释放或进程结束 |
| 栈 stack | 函数栈帧、局部变量、返回地址 | 函数调用期间 |
| mmap 区 | 动态库、文件映射、大块匿名映射 | 映射存在期间 |
| TLS 区 | `thread_local` 变量 | 线程生命周期 |

不同平台、编译器和链接方式会影响具体布局，但大方向一致。

## 1.1 从低地址到高地址怎么看

典型 Linux 用户态虚拟地址空间可以按低地址到高地址理解为：

```text
低地址
  .text / .rodata / .data / .bss
  heap                 向高地址增长
  mmap 区              动态库、文件映射、匿名大块内存
  stack                向低地址增长
高地址
```

这只是概念模型。实际地址会受架构位数、PIE、ASLR、栈随机化、线程栈和 mmap 分配策略影响，不能死记具体地址。

## 2. 示例

```cpp
const int g_const = 1;      // 可能在 .rodata
int g_init = 2;             // .data
int g_zero;                 // .bss
static int s_init = 3;      // .data

int main() {
    int local = 4;          // stack
    static int local_s = 5; // .data
    auto* p = new int(6);   // p 在 stack，*p 在 heap
    const char* str = "hi"; // str 在 stack，"hi" 在 .rodata
    delete p;
}
```

## 2.1 常量存储区、全局变量和静态变量

面试里说“常量存储区”通常指只读数据段 `.rodata`，但要注意并不是所有 `const` 变量都一定放在 `.rodata`：

1. 字符串字面量通常在 `.rodata`。
2. 全局 `const` 且不需要动态初始化的对象，可能放在 `.rodata`。
3. 局部 `const int x = 1` 可能直接被编译器当成立即数优化，不一定有实际存储。
4. 需要动态初始化或有非平凡构造的 `const` 对象，可能放在 `.data`，初始化后通过页面权限或类型系统保证只读语义。

全局变量和静态变量都具有静态存储期，生命周期从程序启动到程序结束：

| 写法 | 作用域/链接属性 | 常见存储区域 |
| --- | --- | --- |
| `int g = 1;` | 全局作用域，外部链接 | `.data` |
| `int g;` | 全局作用域，外部链接 | `.bss` |
| `static int g = 1;` | 文件作用域，内部链接 | `.data` |
| `static int x;` 函数内 | 块作用域，静态存储期 | `.bss` |
| `const char* p = "hi";` | 指针变量看定义位置，字面量在只读段 | p 可能在栈/数据段，`"hi"` 在 `.rodata` |

要区分三个概念：

1. **作用域**：名字在哪里可见。
2. **链接属性**：能否跨翻译单元链接到同一个实体。
3. **存储期**：对象活多久。

`static` 可以改变链接属性或存储期，但不等于“都在栈上/堆上”。

## 3. 栈和堆的区别

1. 栈由编译器和运行时按函数调用自动管理，分配释放很快。
2. 堆由分配器管理，适合生命周期跨函数或大小运行期决定的对象。
3. 栈空间通常较小，大数组或深递归容易栈溢出。
4. 堆分配有元数据、锁或线程缓存成本，也可能产生碎片。

## 3.1 为什么栈通常比堆快

栈快不是因为“栈一定在高速内存、堆一定在低速内存”，它们最终都映射到进程虚拟地址空间和物理内存。栈通常更快，主要是管理方式更简单：

1. **分配释放只是移动栈指针**：进入函数时调整 `sp/rsp`，退出函数时恢复，接近几条指令。
2. **生命周期严格后进先出**：不需要查找空闲块，也不需要合并碎片。
3. **缓存局部性好**：栈帧连续增长，函数局部变量通常集中访问，CPU cache 命中率高。
4. **无通用分配器元数据成本**：堆分配要维护 chunk/header、空闲链表、大小类等结构。
5. **多线程竞争更少**：每个线程有自己的栈；堆分配器虽然有线程缓存，但跨线程释放、大对象分配仍可能有锁或同步成本。

堆慢的主要来源：

1. 分配器要寻找合适大小的空闲块。
2. 释放时可能要合并相邻空闲块或放回对应大小类。
3. 频繁申请释放会造成内存碎片和缓存不友好。
4. 大块内存可能走 `mmap/brk` 或触发缺页，成本更高。

易错点：

1. 栈空间有限，不能把超大数组或深递归都放栈上。
2. 栈上对象离开作用域自动销毁，不能返回局部变量地址。
3. 堆对象适合跨函数、跨线程或大小运行期决定的生命周期，但要用 RAII 或智能指针管理。
4. 现代分配器如 jemalloc、tcmalloc、mimalloc 会优化小对象分配，但仍不改变栈的 LIFO 管理优势。

## 3.2 `new` 出来的数据存放在哪里

面试里问“`new` 出来的数据在哪里”，要区分指针变量和它指向的对象：

```cpp
int* p = new int(10);
```

通常情况下：

1. `p` 是一个局部指针变量，如果定义在函数内，`p` 本身在栈上。
2. `new int(10)` 创建的 `int` 对象在堆上。
3. 堆上的对象生命周期不随函数返回自动结束，需要 `delete p` 或交给智能指针管理。

如果写成：

```cpp
auto p = std::make_unique<int>(10);
```

`unique_ptr` 对象本身可能在栈上，但它管理的 `int` 仍在堆上；离开作用域时 `unique_ptr` 析构并释放堆对象。

还要注意几个特殊情况：

1. **数组 new**：`new int[100]` 在堆上分配一段连续数组对象，应使用 `delete[]` 释放。
2. **placement new**：`new (buffer) T()` 只在已有内存上构造对象，不分配堆内存，存放位置取决于 `buffer`。
3. **自定义 `operator new`**：类或全局可以重载分配函数，对象可能来自内存池、共享内存或 mmap 区。
4. **虚拟内存视角**：`new` 底层通常经由分配器管理堆虚拟地址，物理页可能按需分配，不一定在 `new` 返回时立刻占满物理内存。

因此标准回答是：普通 `new` 创建的对象在自由存储区，通常由堆分配器管理；保存地址的指针变量在哪里，取决于指针变量本身的定义位置。

## 4. 虚函数表在哪里

虚函数表通常由编译器在编译期生成，作为只读数据放在 `.rodata` 或类似只读段中。对象里保存的是虚函数表指针 `vptr`，不是虚表本身。

对象构造时，构造函数会初始化或调整 `vptr`。在继承层次中，基类构造阶段 `vptr` 指向基类虚表，派生类构造阶段再更新为派生类虚表。

## 5. 和虚拟内存的关系

上面说的是进程虚拟地址空间中的逻辑区域。真实物理内存由操作系统按页映射：

1. 程序看到的是连续虚拟地址。
2. 物理内存可以不连续。
3. 没访问的页可能没有实际分配物理页。
4. 动态库的只读代码页可以被多个进程共享。

## 5.1 共享库映射区是做什么的

共享库通常映射在进程的 mmap 区。它的作用不是简单“复制一份库到进程里”，而是把 `.so` 文件的不同段按权限映射到进程虚拟地址空间：

1. 代码段和只读数据段通常是只读、可执行或只读映射，多进程可以共享同一份物理页。
2. 可写数据段一般是私有映射，进程写入时通过 copy-on-write 获得自己的物理页。
3. 动态链接器会处理重定位、GOT/PLT、符号绑定和懒加载。
4. ASLR 会随机化共享库加载基址，提高攻击者预测地址的难度。

因此 `top` 中的 SHR 往往包含共享库代码页。共享库能节省内存、支持独立升级，但也引入动态链接搜索路径、ABI 兼容和符号劫持等问题。

## 6. 面试回答模板

C++ 程序内存分布通常包括代码段、只读数据段、`.data`、`.bss`、堆、栈、mmap 区和 TLS 区。全局和静态变量生命周期贯穿程序，已初始化的在 `.data`，未初始化或 0 初始化的在 `.bss`；字符串字面量、虚函数表常在只读段；局部变量通常在栈上；`new/malloc` 得到的对象在堆上；动态库和大块映射常在 mmap 区。常量存储区一般指 `.rodata`，但局部 `const` 可能被优化成立即数，不一定实际占一块只读内存。注意这些都是虚拟地址空间布局，真正物理内存由页表按需映射。
