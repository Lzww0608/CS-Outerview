# Q82. 进程与线程的区别

`Linux`内核中都表示为`task_struct`

#### 本质区别：

进程是资源分配的基本单位，线程是CPU调度的基本单位

1. **定义和结构**：
   - **进程**：进程是程序的一个实例，它在其自己的地址空间中运行。每个进程至少包含一个线程（主线程），并拥有自己的虚拟内存、系统资源和独立的执行环境。进程之间互相隔离，一个进程的崩溃通常不会影响到其他进程。
   - **线程**：线程是进程中的执行单元，也被称为轻量级进程。一个进程可以包含多个线程，它们共享父进程的地址空间和资源，如内存和文件句柄等。线程主要用于实现任务的并行执行。
2. **资源共享**：
   - **进程**：进程之间不共享内存或资源，除非通过进程间通信（IPC）机制显式共享，如套接字、信号量、共享内存等。
   - **线程**：同一进程内的线程共享内存和资源，这使得线程间的数据交换和通信更为容易和快速，但也需要注意同步和互斥问题，以避免竞态条件和死锁。
3. **开销和性能**：
   - **进程**：创建和管理进程的开销相对较大，因为每个进程需要独立的地址空间和系统资源。进程切换涉及更多的时间和资源，如保存和加载不同进程的上下文。
   - **线程**：线程的创建和切换开销较小，因为它们共享相同的环境和资源。线程间的切换只需要较少的资源重新配置。
4. **通信方式**：
   - **进程**：进程间通信需要特定的机制，如管道、消息队列、共享内存等，这些机制通常涉及更复杂的设置和管理。
   - **线程**：由于线程共享同一内存空间，它们可以直接通过读写同一内存区域来进行通信，但这要求程序正确地处理同步问题，以防数据不一致。
5. **应用场景**：
   - **进程**：适用于需要独立运行和资源管理的应用，例如在需要隔离的环境中运行不同的服务时。
   - **线程**：适用于需要高效执行并行任务的情况，尤其是在计算密集型应用中，如服务器端程序、复杂算法的实现等。

## 共享资源和独占资源

同一进程内的线程共享大部分进程级资源，但每个线程也有自己的执行上下文。

| 维度 | 进程 | 同一进程内的线程 |
| --- | --- | --- |
| 地址空间 | 通常彼此独立 | 共享代码段、数据段、堆、mmap 区 |
| 文件资源 | 每个进程有自己的文件描述符表；`fork` 后表项被复制，底层 open file description 可能共享偏移量 | 共享文件描述符表，任一线程关闭 fd 会影响其他线程 |
| 栈 | 每个进程至少有主线程栈 | 每个线程有独立线程栈 |
| 寄存器/PC | 进程切换时保存恢复 | 每个线程有独立寄存器、程序计数器和调度状态 |
| TLS | 进程内可有多份线程局部存储 | 每个线程有自己的 `thread_local` 实例 |
| 信号和权限 | 进程级资源为主 | 信号处理方式通常进程共享，信号掩码可按线程不同 |

易错点：

1. “线程栈独立”不代表绝对安全。线程栈仍然位于同一个虚拟地址空间，野指针或越界写可能破坏其他线程的栈。
2. `fork` 后父子进程的文件描述符编号相同，但不是简单的“两个完全独立文件”。它们可能引用同一个 open file description，因此读写偏移量会相互影响。
3. 线程共享堆和全局变量，所以通信方便，但必须用锁、原子变量、条件变量等同步手段保证可见性和互斥。

## 多进程和多线程如何选择

选择不是看“哪个更高级”，而是看隔离性、通信成本、并行模型和故障影响。

优先多进程的场景：

1. **强隔离**：插件、脚本执行、任务沙箱、浏览器多标签页，一个任务崩溃不希望拖垮主服务。
2. **权限隔离**：不同进程使用不同用户、namespace、cgroup、seccomp 策略。
3. **规避全局状态风险**：第三方库不是线程安全的，或有大量全局变量。
4. **多语言/多运行时集成**：不同服务用不同语言实现，通过 RPC、管道、Unix Domain Socket 通信。
5. **CPU 密集且共享数据少**：进程间少量消息传递即可完成任务。

优先多线程的场景：

1. **共享内存频繁**：多个执行流需要访问同一批缓存、连接表、任务队列。
2. **低延迟通信**：线程间通过队列、锁、条件变量或无锁结构传递任务，少一次 IPC 序列化。
3. **I/O 并发**：线程池处理阻塞数据库、文件、RPC 调用，或事件循环旁路 CPU 任务。
4. **资源开销敏感**：线程创建和切换通常比进程轻，内存占用更低。

工程上常见混合模式：

1. Nginx、数据库、浏览器常用多进程做隔离，再在进程内使用事件循环或线程池。
2. RPC 服务可用一个或多个进程监听端口，每个进程内用 epoll + worker 线程池。
3. CPU 密集任务按核心数控制 worker 数量，I/O 密集任务按阻塞时间和下游容量设置线程池上限。

易错点：

1. 多线程不一定比单线程快，锁竞争、伪共享、上下文切换和缓存失效可能抵消并行收益。
2. 多进程不一定绝对安全，共享内存、文件、数据库和外部系统仍需要一致性设计。
3. 进程崩溃通常更容易隔离，线程崩溃往往导致整个进程退出。
4. 高并发网络接入层通常先用非阻塞 I/O 降低线程数，再把 CPU 或阻塞业务交给工作线程。

## 面试易错点

1. 在 Linux 内核中，进程和线程都可以用 `task_struct` 描述，区别更多体现在资源是否共享。例如线程通过 `clone()` 共享地址空间、文件描述符、信号处理等资源。
2. 进程切换通常要切换地址空间，可能导致 TLB 失效；同进程内线程切换不需要切换地址空间，开销通常更小。
3. 线程共享进程地址空间，所以通信方便，但一个线程写坏内存可能影响整个进程。
4. 进程隔离性更好，一个进程崩溃通常不会直接破坏另一个进程；线程崩溃往往会导致整个进程退出。
5. 客户端程序里常见做法是 UI 线程负责渲染和事件循环，IO/网络/解码任务放到工作线程，避免阻塞主线程。

一句话总结：进程是资源隔离和资源分配的单位，线程是调度执行的单位；线程轻量但共享内存带来同步风险，进程隔离强但通信和切换成本更高。
