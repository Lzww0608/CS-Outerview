# 构造函数初始化列表必须初始化哪些成员

构造函数初始化列表是在对象成员真正构造时给出初值。构造函数体执行时，成员已经构造完成了，所以函数体里的赋值不是初始化，而是先默认构造再赋值。

## 1. 必须使用初始化列表的成员

以下成员必须在初始化列表中初始化：

1. **引用成员**：引用一旦绑定就不能改绑。
2. **const 成员**：常量对象构造后不能再赋值。
3. **没有默认构造函数的成员对象**：无法先默认构造。
4. **基类子对象**：基类构造要在派生类构造体执行前完成。
5. **需要传参构造的成员**：例如 `std::mutex` 不可拷贝，某些 RAII wrapper 只能构造时传入资源。

示例：

```cpp
#include <string>

class File {
public:
    explicit File(int fd) : fd_(fd) {}

private:
    int fd_;
};

class Session {
public:
    Session(int id, const std::string& name, File file)
        : id_(id), name_(name), file_(std::move(file)), ref_(id_) {}

private:
    const int id_;
    std::string name_;
    File file_;
    const int& ref_;
};
```

如果把 `id_`、`file_`、`ref_` 放到构造函数体里赋值，要么编译失败，要么语义不对。

## 2. 初始化顺序

成员初始化顺序不由初始化列表书写顺序决定，而由成员在类中声明的顺序决定。

```cpp
class A {
public:
    A() : y_(x_ + 1), x_(1) {}

private:
    int x_;
    int y_;
};
```

实际先初始化 `x_`，再初始化 `y_`，因为声明顺序是 `x_` 在前。工程上应让初始化列表顺序和成员声明顺序一致，避免编译器 warning 和隐藏 bug。

## 3. 初始化列表和函数体赋值的区别

```cpp
class User {
public:
    User(std::string name) {
        name_ = std::move(name);
    }

private:
    std::string name_;
};
```

这段代码会先默认构造 `name_`，再在函数体里移动赋值。更好的写法是：

```cpp
class User {
public:
    explicit User(std::string name) : name_(std::move(name)) {}

private:
    std::string name_;
};
```

这样直接构造成目标状态，少一次默认构造和赋值。

## 4. 真实场景

1. RAII 类封装 fd、锁、内存、连接时，应在初始化列表里建立对象不变量。
2. 多线程类中的 `std::mutex`、`std::condition_variable` 不应被拷贝或赋值，只能作为成员直接构造。
3. 依赖注入时，引用成员和 const 配置必须在构造时确定。
4. 基类需要参数时，派生类必须在初始化列表显式调用基类构造。

## 5. 易错点

1. 初始化列表书写顺序不会改变真实初始化顺序。
2. `const` 和引用成员不能在构造函数体内“补赋值”。
3. 成员之间有依赖时，按声明顺序组织成员，避免后声明成员被先使用。
4. 能初始化就不要先默认构造再赋值，尤其是字符串、容器、锁和资源句柄。
5. 静态数据成员不在对象初始化列表里初始化，它属于类级对象。

## 6. 面试回答模板

必须放在构造函数初始化列表里的典型成员包括引用成员、`const` 成员、没有默认构造函数的成员对象、基类子对象，以及需要构造时传参建立不变量的 RAII 成员。初始化列表是真正的初始化，构造函数体里只是赋值。还要注意成员初始化顺序由类内声明顺序决定，不由初始化列表书写顺序决定，所以初始化列表最好和声明顺序保持一致。
