# Q97. dangling pointer

```c
int* foo() {
    int a;          // 变量a的作用域开始
    a = 100;
    char *c = "xyz";   // 变量c的作用域开始
    return &a;
}                   // 变量a和c的作用域结束
```

先来看这样一段代码。这段代码虽然可以编译通过，但是其实非常糟糕，变量 `a` 和 `c` 都是局部变量，函数结束后将局部变量 `a` 的地址返回，但局部变量 `a` 存在栈中，在离开作用域后，`a` 所申请的栈上内存都会被系统回收，从而造成了 `悬空指针(Dangling Pointer)` 的问题。这是一个非常典型的内存安全问题，虽然编译可以通过，但是运行的时候会出现错误。



我们可以通过两种方式来修改：

**1. 返回动态分配的内存**：使用动态内存分配来分配`a`，确保返回的指针在函数结束后仍然有效。

```c++
int* foo() {
    int *a = new int;  // 动态分配内存
    *a = 100;
    char *c = "xyz";   // 变量c的作用域开始
    return a;
}  // 变量c的作用域结束
// 使用完指针后记得释放内存
```



**2. 使用静态变量**：如果合适的话，可以使用静态变量，但这有可能会导致线程安全问题。

```c++
int* foo() {
    static int a;     // 静态变量的生命周期为整个程序运行期间
    a = 100;
    char *c = "xyz";   // 变量c的作用域开始
    return &a;
}  // 变量c的作用域结束
```

## 返回局部数组地址有什么问题

类似代码：

```cpp
char* get_buffer(int size) {
    char a[size];
    return a;
}
```

问题有两层：

1. `a` 是自动存储期对象，函数返回后栈帧失效，返回的指针变成悬空指针。
2. `char a[size]` 是变长数组，属于 C99 特性，不是标准 C++，一些编译器只是把它当扩展支持。

安全写法取决于所有权由谁承担。

如果调用方提供缓冲区，函数只负责写入：

```cpp
#include <cstddef>
#include <cstring>

int get_buffer(int size, void* src) {
    if (size <= 0 || src == nullptr) {
        return -1;
    }

    auto* out = static_cast<char*>(src);
    std::memset(out, 0, static_cast<std::size_t>(size));
    return size;
}
```

如果函数负责创建缓冲区，优先返回 RAII 对象：

```cpp
#include <vector>

std::vector<char> get_buffer(int size) {
    if (size <= 0) {
        return {};
    }
    return std::vector<char>(static_cast<std::size_t>(size));
}
```

不推荐返回裸指针让调用方手动 `delete[]`。真实项目里缓冲区所有权应通过 `std::vector<char>`、`std::string`、`std::unique_ptr<char[]>` 或 `span`/指针加长度明确表达。

## 野指针和悬空指针

两者都属于不安全指针，但来源略有不同：

1. **野指针**：未初始化或被错误赋值的指针，指向未知地址。
2. **悬空指针**：曾经指向有效对象，但对象生命周期已经结束，例如 `delete` 后继续使用、返回局部变量地址、容器扩容后保存旧元素地址。

典型场景：

```cpp
int* p;                 // 野指针，未初始化

int* q = new int(1);
delete q;
*q = 2;                 // 悬空指针，Use-After-Free

std::vector<int> v{1, 2, 3};
int* r = &v[0];
v.push_back(4);         // 可能扩容
std::cout << *r;        // r 可能悬空
```

## 使用悬空指针一定会段错误吗

不一定。悬空指针的本质是未定义行为，是否段错误取决于这个地址当前映射状态、权限和是否被复用。

可能不会立刻段错误的情况：

1. 释放后的堆块还留在分配器缓存里，虚拟页仍然映射，读写可能“看起来正常”。
2. 这块内存很快被重新分配给别的对象，访问会破坏别人的数据。
3. 栈上局部变量离开作用域后，栈内存仍在当前线程栈区内，读取可能得到旧值或新栈帧内容。

更可能段错误的情况：

1. 指针指向未映射页，CPU 访问触发 page fault，内核发送 `SIGSEGV`。
2. 指针指向只读页却尝试写入，例如写字符串字面量或只读映射。
3. 大块内存通过 `munmap` 归还内核后继续访问。
4. ASan、Guard Page、调试分配器把释放内存隔离或填毒，访问时主动报错。

段错误发生过程可以概括为：CPU 执行 load/store 指令访问虚拟地址，MMU 查页表发现地址无映射或权限不匹配，触发缺页异常；内核判断这是用户态非法访问后，给进程发送 `SIGSEGV`。如果进程没有处理该信号，就会终止并可能生成 core dump。

避免方式：

1. 指针初始化为 `nullptr`，释放后及时置空。
2. 用 RAII 和智能指针表达所有权。
3. 容器扩容后不要继续使用旧迭代器、指针、引用。
4. 跨线程共享对象要明确生命周期，避免一边释放一边访问。
5. 使用 ASan/UBSan/TSan、Valgrind 和 core dump 分析定位问题。
