# Q114.虚拟内存

虚拟内存是操作系统为每个进程提供的一套连续、独立的虚拟地址空间。进程看到的是虚拟地址，真正访问内存时，CPU 的 MMU 会在页表和 TLB 的帮助下把虚拟地址转换成物理地址。

## 1. 虚拟内存解决什么问题

1. **地址空间隔离**：每个进程有自己的虚拟地址空间，普通进程不能直接访问其他进程内存。
2. **简化编程模型**：程序可以认为自己拥有连续地址空间，不需要关心物理内存碎片。
3. **按需分页**：页面真正被访问时才分配或加载物理页，提高内存利用率。
4. **权限保护**：页表项可以标记可读、可写、可执行、用户态/内核态权限。
5. **共享能力**：共享库代码页、mmap 文件页、父子进程 COW 页面可以共享物理页。
6. **扩展可用空间**：配合 swap，可以把不活跃页面换出到磁盘。

## 2. 核心原理

虚拟内存通常按页管理，常见页大小是 4KB。一次地址转换可以简化理解为：

```text
虚拟地址 = 虚拟页号 + 页内偏移
虚拟页号 -> 查 TLB
  命中：得到物理页号
  未命中：按多级页表查找，填充 TLB
物理地址 = 物理页号 + 页内偏移
```

如果页表中没有有效映射，会触发缺页异常：

1. 匿名页首次写入：内核分配一个物理页并清零。
2. 文件映射页首次访问：内核从页缓存或磁盘加载对应文件内容。
3. COW 页面被写入：内核复制一份新物理页，再修改页表。
4. 非法访问：例如访问空指针附近地址、写只读页，通常触发 `SIGSEGV`。

## 3. 虚拟内存如何扩大可用内存空间

- **空间复用:** 虚拟内存允许多个进程共享物理内存，通过按需分页和交换，使得物理内存可以容纳更多进程的 *活跃* 数据。
- **逻辑扩展:** 虚拟内存提供给进程的虚拟地址空间可以远大于实际的物理内存大小，程序可以访问更大的内存空间，感觉上可用内存被扩大了。
- **高效利用:** 通过按需分页，只有程序实际使用的部分代码和数据才会被加载到物理内存，提高了内存的利用率，避免了浪费。

需要注意的是，虚拟内存并不是真正的无限内存。它的性能受到物理内存大小、TLB 命中率和磁盘 I/O 速度限制。频繁 major page fault 或 swap in/out 会导致抖动，服务 P99 延迟会明显变差。

## 4. 真实场景

1. **进程隔离**：一个进程越界写通常只能破坏自己的地址空间，不能直接写坏其他进程。
2. **动态库共享**：多个进程可以共享同一份只读代码物理页，减少内存占用。
3. **fork 的 COW**：父子进程初始共享物理页，某一方写入时才复制。
4. **mmap 文件**：把文件映射进虚拟地址空间，通过缺页按需加载。
5. **大对象申请**：`malloc/new` 返回的是虚拟地址，物理页可能在首次访问时才真正分配。

## 5. 易错点

1. 虚拟地址连续，不代表物理地址连续。
2. 申请成功不代表物理内存已经全部占用，Linux 可能存在 overcommit。
3. 缺页异常不一定是错误，按需分页和 COW 都依赖缺页异常；非法访问才会变成崩溃信号。
4. swap 能缓解内存不足，但会把内存访问变成磁盘 I/O，延迟非常高。
5. TLB miss 和 page fault 都有成本，高性能程序要关注局部性、页大小和 NUMA。

## 6. 面试回答模板

虚拟内存是操作系统给每个进程提供的独立虚拟地址空间。程序访问虚拟地址时，CPU 通过 TLB 和页表把它翻译成物理地址；如果页不存在或权限不对，会触发缺页异常，由内核分配页面、加载文件、执行 COW，或者发送 `SIGSEGV`。它的价值是进程隔离、权限保护、按需分页、共享库共享和简化连续地址模型。但虚拟内存不是无限内存，频繁缺页、swap 和 TLB miss 都会显著影响性能。
