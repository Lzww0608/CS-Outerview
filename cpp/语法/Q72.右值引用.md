# 72. C++左值引用与右值引用

首先，我们需要知道什么是值语义，什么是引用语义。

#### 值语义：

- 值语义意味着对象在被传递、赋值或拷贝时，会复制其整个数据。
- 当使用值语义时，对对象进行操作不会影响原始对象，因为操作会在副本上进行。
- 传统的内置类型（如整数、浮点数等）通常具有值语义。

#### 引用语义：

- 引用语义意味着对象在被传递、赋值或拷贝时，不会复制其整个数据，而是共享相同的数据。
- 当使用引用语义时，对对象的操作会影响所有引用该对象的变量，因为它们都指向相同的内存位置。
- 指针和引用是引用语义的典型例子。



对于GC语言，大部分变量都是引用语义，内存管理交给GC。而**值语义**可以更方便直观**控制对象生命周期**，让`RAII`使用更自然。



其次，我们需要区分一下左值与右值：

#### 左值：

+ 可以在等号左边，可以取地址，具名
+ 比如变量名，返回左值引用的函数调用，前置的自增自减，赋值运算和复合赋值运算，解引用



#### 右值：

+ 只能在等号右边，不能取地址，不具名
+ **纯右值**：
  + 字面量，返回非引用类型的函数调用，后置自增自减，算数/逻辑表达式
+ **将亡值**：
  + `C++11`引入与移动语义相关的值类型（移动构造、移动赋值运算符重载），转移**堆**上资源，不可以转移**栈**上资源



### 区别：

1. 左值引用是对左值的引用；右值引用是对右值的引用
   + `const`左值引用能指向右值，但不能修改
   + 右值引用通过`std::move()`指向左值
   + 声明出来的左值引用和右值引用都是左值
2. 功能差异：
   + 左值引用避免拷贝，如函数传参，函数返回值
   + 右值引用实现移动语义：
   + + 对象赋值时，避免资源的重新分配
     + 移动构造，移动赋值运算符重载
     + STL
     + `std::unique_ptr`
     + `std::function`



**注：`std::forward()`是与universal reference相配合使用**

## 将亡值有哪些

C++11 之后表达式值类别可以粗略分为左值、纯右值和将亡值。将亡值（xvalue, expiring value）表示“有身份、资源即将被转移”的表达式，它通常可以绑定到右值引用，并触发移动构造或移动赋值。

常见将亡值来源：

1. `std::move(x)` 的结果。
2. 返回 `T&&` 的函数调用。
3. 对右值对象访问非静态成员，例如 `makeObj().member`。
4. 对右值对象做成员函数调用后返回的右值引用。
5. 强制类型转换为右值引用的表达式，例如 `static_cast<T&&>(x)`。

示例：

```cpp
#include <string>
#include <utility>

std::string makeString() {
    return "hello"; // 返回值表达式本身通常按纯右值理解
}

std::string&& forwardString(std::string& s) {
    return std::move(s); // 返回 T&&
}

void f() {
    std::string a = "abc";

    std::string b = std::move(a);        // std::move(a) 是将亡值
    std::string c = makeString();        // makeString() 是纯右值，通常可直接构造 c
    std::string d = forwardString(c);    // forwardString(c) 是将亡值
}
```

易错点：

1. `std::move` 不移动任何数据，它只是把表达式转换成将亡值，真正移动发生在移动构造或移动赋值中。
2. 具名右值引用变量本身是左值：

```cpp
std::string&& r = makeString();
std::string x = r;            // r 是左值，调用拷贝
std::string y = std::move(r); // 转成将亡值，才可能调用移动
```

3. 被移动后的对象仍然要保持可析构、可赋值，但具体值只保证“有效但未指定”，不要依赖原值。
4. 右值引用主要转移堆资源、句柄、缓冲区所有权；不能把栈对象本身“搬到另一个栈帧”。

## `std::move` 和 `std::forward`

`std::move` 和 `std::forward` 都不真正移动对象，它们都是类型转换工具。

| 工具 | 本质 | 典型用途 |
| --- | --- | --- |
| `std::move(x)` | 无条件把表达式转成右值引用 | 明确转移资源所有权 |
| `std::forward<T>(x)` | 按模板参数 `T` 保留原值类别 | 完美转发 |

`std::move` 适合在“当前对象以后不再依赖原值”时使用：

```cpp
std::string s = "hello";
std::string t = std::move(s);
```

`std::forward` 只应该用于转发引用场景：

```cpp
#include <utility>

template <class T, class... Args>
T* makeObject(Args&&... args) {
    return new T(std::forward<Args>(args)...);
}
```

这里 `Args&&` 是转发引用。调用方传左值，就转发为左值；调用方传右值，就转发为右值。这样既不会意外移动左值，也不会把右值退化成左值。

## 引用折叠和完美转发细节

完美转发依赖两个规则：转发引用和引用折叠。

转发引用的形式通常是函数模板里的 `T&&`，且 `T` 需要由实参推导出来：

```cpp
template <typename T>
void wrapper(T&& x) {
    target(std::forward<T>(x));
}
```

调用方传左值时，`T` 会被推导为左值引用；传右值时，`T` 推导为普通类型。再经过引用折叠得到最终参数类型。

引用折叠规则可以记成：只要有一个 `&`，最终就是左值引用；只有 `&& &&` 才是右值引用。

| 形式 | 折叠结果 |
| --- | --- |
| `T& &` | `T&` |
| `T& &&` | `T&` |
| `T&& &` | `T&` |
| `T&& &&` | `T&&` |

所以如果 `a` 是 `T` 的左值引用，也就是 `T& a`，而 `T` 是 `int&&`，那么：

```cpp
T& a  // T = int&&
=> int&& &
=> int&
```

`a` 的实际类型是 `int&`。另外，无论 `a` 的声明类型最终是左值引用还是右值引用，只要 `a` 有名字，表达式 `a` 本身就是左值。

常见错误：

1. 对转发引用参数使用 `std::move`，会把调用方传入的左值也强制移动走。
2. 对普通右值引用参数使用 `std::forward` 没有必要，直接 `std::move` 表达“我要转移”更清楚。
3. 返回局部变量时写 `return std::move(x);` 可能阻止 NRVO，通常直接 `return x;`。
4. `const` 对象很难真正移动，`std::move(const_obj)` 得到 `const T&&`，大多会匹配到拷贝构造。

## 面试回答模板

右值引用是 C++11 为移动语义和完美转发引入的。左值有名字、可取地址；纯右值通常是临时值；将亡值表示有身份但资源即将被转移，比如 `std::move(x)`、返回 `T&&` 的函数调用、右值对象的成员访问。`std::move` 本身不移动，只是把表达式转成将亡值，后续由移动构造或移动赋值转移资源。具名右值引用变量仍然是左值，继续转发时要用 `std::move` 或 `std::forward`。
