# 71. C/C++建立一个线程，该线程调用join()方法后，再调用一次join()方法会发生什么？

从直觉上不难判断，这样一定是不可以的。众所周知，线程也是有状态的，调用`join()`方法之后，线程显然会进入运行的状态，此时不可以再次调用自身。所以很多C++并发编程时，都需要提前使用`joinable()`方法来判断线程的状态时候可以调用。

如果我们在调用了一次`join()`方法的基础上再次调用，则会抛出`std::system_error`异常，具体示例如下所示：

```c++
#include <iostream>
#include <thread>
#include <chrono>
#include <exception>

void threadFunction() {
    std::this_thread::sleep_for(std::chrono::seconds(1));  // 模拟工作
    std::cout << "Finished work in thread\n";
}

int main() {
    std::thread t(threadFunction);

    // 第一次调用join
    t.join();
    std::cout << "First join completed\n";

    try {
        // 尝试第二次调用join
        t.join();
    } catch (const std::system_error& e) {
        std::cout << "Exception caught: " << e.what() << '\n';
    }

    return 0;
}

```

在这个示例中，第一次调用`join()`成功地等待了线程结束。第二次调用`join()`时，由于线程状态已经是非joinable，所以抛出了`std::system_error`异常，异常信息通常是"Invalid argument"，表示传入的参数（即线程状态）无效。

### 总结

因此，正确的做法是确保对每个线程对象只调用一次`join()`。一旦一个线程结束并且已经调用过`join()`，该线程对象就变为了“非joinable”状态，此后再调用`join()`是不合法的，并且会导致运行时错误。

```c++
if (t.joinable()) {
        t.join();  // 这才是正确的调用方法
    } else {
        std::cout << "Thread is not joinable anymore\n";
    }
```

## join 和 detach 的区别

`std::thread` 对象代表一个线程句柄。只要它处于 joinable 状态，析构时如果既没有 `join()` 也没有 `detach()`，标准库会调用 `std::terminate()`，防止线程生命周期失控。

| 操作 | 含义 | 线程对象状态 | 适用场景 | 风险 |
| --- | --- | --- | --- | --- |
| `join()` | 当前线程等待子线程执行结束 | 调用后变为 non-joinable | 需要确保任务完成、回收结果、关闭前清理 | 调用线程会阻塞 |
| `detach()` | 子线程脱离 `std::thread` 对象独立运行 | 调用后变为 non-joinable | 极少数不依赖外部生命周期的后台任务 | 容易访问已销毁对象，退出期难管理 |

示例：

```cpp
#include <thread>

void work();

void run() {
    std::thread t(work);

    if (t.joinable()) {
        t.join();
    }
}
```

不建议随意使用 `detach()`：

```cpp
void bad() {
    int value = 42;

    std::thread([&] {
        // 如果 bad() 已返回，value 已经销毁，这里就是悬垂引用
        use(value);
    }).detach();
}
```

更稳的选择：

1. 使用 `join()` 明确等待线程结束。
2. 使用线程池管理后台任务生命周期。
3. C++20 使用 `std::jthread`，析构时会请求停止并自动 join。
4. 异步任务需要访问对象时，用值捕获、`shared_ptr` 延长生命周期，或用 `weak_ptr` 观察对象是否还存在。

## 线程资源由谁释放

线程结束时，用户函数返回或调用 `pthread_exit`，内核会把该线程从可运行状态中移除，并回收大部分内核调度资源。但对于 joinable 线程，线程的退出状态和一部分线程控制信息需要保留到其他线程调用 `join()` 或 `pthread_join()`，否则调用方无法取得退出结果。

可以这样理解：

1. **线程函数执行完**：线程自己的执行流结束，内核不再调度它。
2. **joinable 线程**：退出状态、线程句柄相关资源保留，直到被 `join()` 回收。
3. **detached 线程**：退出后由运行库/内核自动回收，不允许再 join。
4. **进程退出**：该进程内所有线程和进程资源都会被操作系统统一清理。

在 C++ 中，`std::thread` 对象只是线程句柄的 RAII 包装，不等于线程本体。`join()` 负责等待线程结束并回收 joinable 状态；`detach()` 表示放弃 join 权利，让线程结束时自动清理。真正的栈、TLS、TCB、内核 task 等资源由线程库和内核协作释放。

## 面试回答模板

`join()` 表示等待线程结束，调用后线程对象不再 joinable；`detach()` 表示线程和 `std::thread` 对象分离，线程后台独立运行，调用后也不再 joinable。一个 joinable 的 `std::thread` 析构时如果没有 join 或 detach，会触发 `std::terminate()`。工程上优先 join 或用线程池、`jthread` 管理生命周期，谨慎 detach，因为它很容易访问已经销毁的栈变量、对象成员或日志资源。
