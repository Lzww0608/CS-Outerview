# Q144.weak_ptr底层与使用

## 1. weak_ptr 是什么

`std::weak_ptr` 是一种不拥有对象的智能指针。它观察一个由 `std::shared_ptr` 管理的对象，但不会增加强引用计数，也不会延长对象生命周期。

它主要解决两个问题：

1. **打破 shared_ptr 循环引用**：例如父子节点、观察者模式、缓存索引。
2. **安全观察对象是否还活着**：使用前通过 `lock()` 尝试提升为 `shared_ptr`。

## 2. 常用 API

```cpp
#include <iostream>
#include <memory>

struct Node {
    int value = 0;
};

int main() {
    std::weak_ptr<Node> wp;

    {
        auto sp = std::make_shared<Node>();
        sp->value = 10;
        wp = sp;

        if (auto locked = wp.lock()) {
            std::cout << locked->value << std::endl;
        }

        std::cout << wp.expired() << std::endl;   // false
        std::cout << wp.use_count() << std::endl; // shared_ptr 强引用数量
    }

    std::cout << wp.expired() << std::endl;       // true
}
```

常用接口：

1. `lock()`：如果对象还存在，返回一个 `shared_ptr`；否则返回空 `shared_ptr`。
2. `expired()`：判断强引用计数是否为 0。
3. `use_count()`：返回当前强引用数量，调试可用，不适合做并发判断依据。
4. `reset()`：清空当前观察关系。

## 3. 底层实现

`weak_ptr` 和 `shared_ptr` 指向同一个控制块。控制块里通常有两个计数：

1. **strong count**：强引用计数，对应 `shared_ptr` 数量。
2. **weak count**：弱引用计数，对应 `weak_ptr` 数量。

生命周期分两段：

1. strong count 变为 0 时，析构并释放被管理对象。
2. strong count 和 weak count 都为 0 时，释放控制块。

因此对象可以已经被销毁，但控制块还活着。`weak_ptr::lock()` 正是通过控制块判断对象是否还存在，并在对象存在时原子地增加 strong count。

## 4. 能否设计一个 weak_ptr

简化版 `weak_ptr` 至少需要：

1. `T* ptr_`：观察的对象地址，用于 `lock()` 成功后构造 `shared_ptr`。
2. `ControlBlock* cb_`：共享控制块，用于读取 strong count、维护 weak count。

核心逻辑：

```cpp
template <typename T>
class WeakPtr {
public:
    WeakPtr() = default;

    WeakPtr(const SharedPtr<T>& sp)
        : ptr_(sp.ptr_), cb_(sp.cb_) {
        if (cb_ != nullptr) {
            cb_->weak.fetch_add(1, std::memory_order_relaxed);
        }
    }

    ~WeakPtr() {
        release();
    }

    bool expired() const {
        return cb_ == nullptr || cb_->strong.load(std::memory_order_acquire) == 0;
    }

    SharedPtr<T> lock() const {
        if (cb_ == nullptr) {
            return SharedPtr<T>();
        }

        long cnt = cb_->strong.load(std::memory_order_acquire);
        while (cnt != 0) {
            if (cb_->strong.compare_exchange_weak(
                    cnt, cnt + 1,
                    std::memory_order_acq_rel,
                    std::memory_order_acquire)) {
                return SharedPtr<T>(ptr_, cb_, AdoptControlBlockTag{});
            }
        }
        return SharedPtr<T>();
    }

private:
    void release() {
        if (cb_ == nullptr) {
            return;
        }
        if (cb_->weak.fetch_sub(1, std::memory_order_acq_rel) == 1 &&
            cb_->strong.load(std::memory_order_acquire) == 0) {
            delete cb_;
        }
        ptr_ = nullptr;
        cb_ = nullptr;
    }

private:
    T* ptr_ = nullptr;
    ControlBlock<T>* cb_ = nullptr;
};
```

这里的 `SharedPtr<T>(ptr_, cb_, AdoptControlBlockTag{})` 表示一个内部构造方式：复用已有控制块，不新建控制块。真实实现还要处理线程竞争、内存序、别名构造和类型擦除。

## 5. 典型应用

父子节点避免循环引用：

```cpp
struct Node {
    std::shared_ptr<Node> child;
    std::weak_ptr<Node> parent;
};
```

如果 `parent` 也用 `shared_ptr`，父子互相持有，strong count 永远不为 0，会导致内存泄漏。

缓存场景：

```cpp
std::unordered_map<int, std::weak_ptr<Object>> cache;
```

缓存只观察对象是否还存在，业务持有的 `shared_ptr` 消失后，对象可以正常释放；下次访问缓存时通过 `lock()` 判断是否需要重建。

## 6. 易错点

1. `weak_ptr` 不能直接 `operator->`，必须先 `lock()`。
2. `expired()` 和 `use_count()` 在并发下只能作为瞬时观察，不能先判断再裸用对象。
3. `weak_ptr` 不会解决所有泄漏，只解决共享所有权形成的引用环。
4. `weak_ptr` 仍然会让控制块保留到弱引用全部释放，因此大量长生命周期 `weak_ptr` 也有内存成本。

## 7. 除了解决循环引用还能做什么

`weak_ptr` 的核心价值是“可失效观察”，所以它不只用于打破循环引用。

常见用途：

1. **异步回调防悬空**：对象发起异步任务时，回调里捕获 `weak_ptr`，执行前 `lock()`。对象已销毁则直接返回，避免回调访问悬空 `this`。
2. **缓存弱引用**：缓存表保存 `weak_ptr`，业务侧没有强引用时对象可以正常释放；下次访问 `lock()` 失败再重建。
3. **观察者列表**：Subject 保存 Observer 的 `weak_ptr`，通知时过滤失效观察者，避免观察者忘记注销导致泄漏。
4. **父子关系中的反向引用**：子节点用 `weak_ptr` 指向父节点，表达“能找回父节点但不拥有父节点”。
5. **避免生命周期被后台任务意外拉长**：后台定时器、网络回调只弱观察对象，防止对象因为异步任务队列积压而迟迟不析构。

示例：

```cpp
class Session : public std::enable_shared_from_this<Session> {
public:
    void async_read() {
        std::weak_ptr<Session> weak = shared_from_this();
        io_read([weak](std::string data) {
            auto self = weak.lock();
            if (!self) {
                return;
            }
            self->on_read(std::move(data));
        });
    }
};
```

这里回调不强行拥有 `Session`。如果连接已经关闭并释放，`lock()` 返回空，回调安全退出；如果对象仍然存在，则局部 `self` 保证 `on_read` 执行期间对象不会被销毁。
