# Q104.进程与线程切换的区别

上下文切换是 CPU 从一个执行流切换到另一个执行流时，保存旧执行流状态并恢复新执行流状态的过程。Linux 中进程和线程都由 `task_struct` 表示，所以调度器看到的是 task；区别主要在于切换时是否需要更换地址空间和进程级资源。

## 0. 进程上下文包括什么

进程上下文不是只有寄存器。它通常可以分成几类：

1. **CPU 执行上下文**：通用寄存器、程序计数器、栈指针、状态寄存器、浮点/SIMD 寄存器等。
2. **内核调度上下文**：`task_struct`、调度优先级、运行队列状态、内核栈、阻塞原因和信号状态。
3. **内存管理上下文**：`mm_struct`、页表根、VMA 列表、用户态地址空间、TLB/ASID/PCID 相关状态。
4. **进程级资源上下文**：文件描述符表、当前工作目录、根目录、umask、凭证、资源限制等。
5. **线程私有上下文**：用户栈、线程局部存储 TLS、线程 id、取消状态等。

上下文切换时不会把所有资源都“复制一份”。内核主要保存和恢复能让任务继续执行的硬件状态，并切换当前 task、内核栈和必要的内存上下文；文件描述符表、VMA、代码段等通常只是被引用或共享，不会在每次调度时整体拷贝。

## 1. 一次进程切换会发生什么

典型过程：

1. **进入内核**：当前进程因为时间片用完、中断、系统调用阻塞、主动让出 CPU 等原因进入调度路径。
2. **保存硬件上下文**：保存通用寄存器、程序计数器、栈指针、状态寄存器等，保证之后能从原位置继续执行。
3. **更新任务状态**：把当前 task 状态改为就绪、阻塞或其他状态，并更新调度统计信息。
4. **选择下一个任务**：调度器根据调度类、优先级、vruntime、CPU 亲和性等选择下一个可运行 task。
5. **切换内核栈和 task 指针**：切到新任务的内核栈，更新当前 CPU 的 current task。
6. **切换地址空间**：如果切到另一个进程，通常要切换页表根寄存器，例如 x86 上的 CR3。
7. **处理 TLB 影响**：地址空间变化可能导致 TLB 失效；现代 CPU 可用 PCID/ASID 降低全量刷新成本。
8. **恢复上下文**：恢复新任务寄存器和执行位置，返回用户态或继续内核态执行。

简化记忆：

```text
保存旧上下文
-> 更新旧 task 状态
-> 调度器选新 task
-> 切内核栈/task_struct
-> 必要时切页表和地址空间
-> 恢复新上下文
```

## 2. 进程切换和线程切换的区别

1. **进程到进程**：通常要切换虚拟地址空间、页表、内存管理上下文，TLB/cache 影响更明显。
2. **同进程线程到线程**：共享地址空间，不需要切换页表；主要切换寄存器、栈、线程局部状态和调度信息。
3. **线程到其他进程中的线程**：本质接近跨进程切换，因为目标线程属于另一个地址空间。

| 对比项 | 进程切换 | 同进程线程切换 |
| --- | --- | --- |
| 地址空间 | 通常切换 | 不切换 |
| 页表/TLB | 可能切页表并影响 TLB | 通常不切页表 |
| 文件描述符表 | 进程级资源可能不同 | 共享同一进程 fd 表 |
| 栈 | 切换到另一个 task 的栈 | 切换到另一个线程栈 |
| 开销 | 通常更大 | 通常更小 |
| 隔离性 | 更强 | 更弱，共享内存风险更高 |

## 3. 为什么上下文切换有开销

上下文切换的成本不只是保存几个寄存器，还包括：

1. **调度器开销**：选择下一个任务、维护运行队列和统计信息。
2. **CPU cache 影响**：新任务访问的数据和指令可能不在 cache 中。
3. **TLB 影响**：跨进程切换可能让地址翻译缓存失效。
4. **内核态路径**：进入和退出内核、切换栈、处理中断和锁。
5. **锁竞争和唤醒链路**：阻塞锁、条件变量、I/O 等可能导致额外唤醒和排队。

所以线程数不是越多越好。高并发服务通常用事件循环、线程池和异步 I/O 控制可运行线程数量，避免大量线程在锁和 I/O 上频繁切换。

## 4. 线程切换要进入内核态吗

如果说的是操作系统调度的内核线程或 `pthread`，线程切换通常要进入内核调度路径。原因是调度器、运行队列、线程状态、内核栈和抢占时机都由内核维护。线程可能因为时间片用完、中断、阻塞系统调用、futex 等待、主动 `sched_yield` 等原因进入内核，随后由调度器选择下一个可运行线程。

需要区分：

1. **同进程线程切换**：也要经过内核调度，但一般不切换页表和地址空间，所以比跨进程切换轻。
2. **用户态协程切换**：如果只是用户态 runtime 保存和恢复寄存器、栈指针，不需要进入内核。
3. **系统调用不等于线程切换**：系统调用会进入内核态，但如果没有阻塞或被抢占，可能还是当前线程返回继续执行。

所以面试回答可以说：内核线程切换要进入内核态；协程切换不一定。线程切换比进程切换轻，不是因为不用内核，而是因为同进程线程共享地址空间，通常不用切页表。

## 5. 易错点

1. 系统调用进入内核态不等于一定发生进程切换；如果系统调用很快返回，可能仍然是同一线程继续运行。
2. 线程切换也有开销，只是同进程线程通常不切地址空间，所以比跨进程切换轻。
3. 协程切换通常在用户态完成，不需要调度器参与，但如果协程调用阻塞系统调用，仍可能阻塞整个线程。
4. `vmstat` 的 `cs`、`pidstat -w`、`perf sched` 可以观察上下文切换情况。
5. 上下文切换高不一定是 CPU 计算多，也可能是锁竞争、线程池过大、短连接过多或频繁定时唤醒。

## 6. 面试回答模板

进程切换会保存当前任务寄存器、PC、栈指针等上下文，更新 task 状态，由调度器选择下一个任务，再切换内核栈、恢复新任务上下文。跨进程时通常还要切换地址空间和页表，可能导致 TLB 失效；同进程线程切换通常也要进入内核调度路径，但不需要切换地址空间，开销更小。协程切换如果完全由用户态 runtime 完成，则不需要进入内核。上下文切换的真实成本还包括 cache/TLB 失效、调度器开销和锁竞争导致的唤醒排队。
