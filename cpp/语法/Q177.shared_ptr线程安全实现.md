# C++ shared_ptr 线程安全实现详解

## 1. 问题背景

shared_ptr 是 C++11 引入的智能指针，用于共享所有权管理。其线程安全性是面试和工程实践中的重要知识点。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  shared_ptr 线程安全层级：                                 │
│                                                             │
│  1. 控制块（Control Block）的引用计数 - 原子操作         │
│  2. 指针本身的操作 - 原子操作                             │
│  3. 管理对象的访问 - 非线程安全（需用户保证）           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 | 影响 |
|------|------|------|
| 引用计数竞争 | 多线程同时修改计数 | 数据竞争 |
| 悬空指针 | 对象已析构但仍被访问 | 未定义行为 |
| 双重释放 | 同一指针被释放两次 | 崩溃 |
| 性能瓶颈 | 锁竞争导致性能下降 | 高并发受限 |

## 4. 原因分析

### 4.1 shared_ptr 结构

```cpp
// shared_ptr 内部结构
template<typename T>
class shared_ptr {
    T* ptr;                    // 原始指针
    ControlBlock* cb;          // 控制块（引用计数）
};

struct ControlBlock {
    std::atomic<int> ref_count;     // 引用计数（原子）
    std::atomic<int> weak_count;    // weak_ptr 计数（原子）
    T* object;                     // 管理对象
    // 可能还有删除器、分配器等
};
```

### 4.2 引用计数原子性

```cpp
// 引用计数操作（原子递增/递减）
class ControlBlock {
    std::atomic<int> ref_count{1};
    
    void increment() {
        ref_count.fetch_add(1, std::memory_order_relaxed);
    }
    
    void decrement() {
        if (ref_count.fetch_sub(1, std::memory_order_acq_rel) == 1) {
            // 最后一个引用，析构对象
            delete object;
            // 检查 weak_count
            if (weak_count.load() == 0) {
                delete this;
            }
        }
    }
};
```

### 4.3 线程安全保证

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  shared_ptr 线程安全保证：                                │
│                                                             │
│  ✅ 安全（原子操作）：                                     │
│     • copy constructor                                     │
│     • copy assignment                                      │
│     • destructor                                          │
│     • ref_count 增减                                       │
│                                                             │
│  ❌ 不安全（需用户保证）：                                │
│     • 同时读写管理的对象                                  │
│     • 多线程修改同一个 shared_ptr（非原子）               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## 5. 解决方案

### 5.1 多线程使用 shared_ptr

```cpp
// 线程安全的使用方式

// 方式1：每个线程持有独立副本
void thread_func1(std::shared_ptr<Obj> ptr) {
    // ptr 是拷贝，引用计数安全
    ptr->do_something();
}

// 方式2：使用 atomic（需要 C++20）
std::atomic<std::shared_ptr<Obj>> atomic_ptr;

// 方式3：锁保护
std::shared_ptr<Obj> ptr;
std::mutex mtx;

void thread_func2() {
    std::lock_guard<std::mutex> lock(mtx);
    ptr->do_something();
}
```

### 5.2 make_shared 优化

```cpp
// make_shared vs new 的区别

// 方式1：分开创建
std::shared_ptr<Obj> p1(new Obj());  
// 控制块和对象分开内存分配

// 方式2：一起分配（推荐）
auto p2 = std::make_shared<Obj>();
// 控制块和对象在同一内存块，更高效
// 避免两次内存分配

// make_shared 优势：
// 1. 减少内存分配次数
// 2. 对象和控制块相邻，提高缓存命中
// 3. 异常安全
```

### 5.3 weak_ptr 打破循环引用

```cpp
// 循环引用示例
class Parent;
class Child;

class Parent {
public:
    std::shared_ptr<Child> child;  // 持有 Child
};

class Child {
public:
    std::shared_ptr<Parent> parent;  // 持有 Parent
};

// 创建时形成循环引用，对象无法释放

// 解决：Child 改为 weak_ptr
class Child {
public:
    std::weak_ptr<Parent> parent;  // 不增加引用计数
};

// 访问时需 lock()
void access_parent() {
    if (auto p = parent.lock()) {
        // 安全访问
        p->do_something();
    }
}
```

## 6. 可选方案对比

### 6.1 智能指针对比

| 特性 | shared_ptr | unique_ptr | weak_ptr |
|------|------------|-----------|----------|
| 所有权 | 共享 | 独占 | 观察 |
| 线程安全 | 引用计数原子 | 无 | 引用计数原子 |
| 大小 | 2 个指针 | 1 个指针 | 1 个指针 |
| 性能 | 中 | 高 | 高 |

### 6.2 内存管理方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| raw pointer | 性能高 | 需手动管理 |
| shared_ptr | 自动管理，线程安全 | 有开销 |
| unique_ptr | 零开销 | 不能共享 |
| scoped_ptr | 简单 | 已废弃 |

## 8. 实施步骤

### 8.1 代码审查要点

```cpp
// 检查项：
// 1. 是否存在循环引用
// 2. 是否正确使用 make_shared
// 3. 多线程访问是否安全
// 4. 是否有不必要的 shared_ptr 拷贝

// 示例：改进前
class Cache {
    std::map<int, std::shared_ptr<Obj>> items_;
public:
    std::shared_ptr<Obj> get(int key) {
        return items_[key];  // 可能创建空 shared_ptr
    }
};

// 改进后
class Cache {
    std::map<int, std::shared_ptr<Obj>> items_;
public:
    std::shared_ptr<Obj> get(int key) {
        auto it = items_.find(key);
        if (it != items_.end()) {
            return it->second;
        }
        return nullptr;
    }
};
```

## 10. 验证方式

```cpp
// 线程安全测试
#include <atomic>
#include <thread>
#include <vector>

std::atomic<int> success_count{0};
std::atomic<int> error_count{0};

void test_shared_ptr() {
    auto ptr = std::make_shared<int>(42);
    std::vector<std::thread> threads;
    
    for (int i = 0; i < 100; ++i) {
        threads.emplace_back([ptr]() {
            // 读取操作应该安全
            auto p = ptr;  // 拷贝
            if (*p == 42) {
                success_count++;
            }
        });
    }
    
    for (auto& t : threads) {
        t.join();
    }
    
    std::cout << "Success: " << success_count << std::endl;
}
```

## 11. 总结

1. **引用计数安全**：控制块引用计数使用原子操作，保证线程安全
2. **对象访问不安全**：shared_ptr 保证指针操作安全，但管理的对象需用户保证线程安全
3. **make_shared 优先**：减少内存分配，提高性能
4. **避免循环引用**：使用 weak_ptr 打破循环
5. **多线程注意**：同时修改同一 shared_ptr 需加锁
