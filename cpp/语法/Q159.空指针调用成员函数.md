# Q159. 空指针调用成员函数

面试里问“空指针是不是完全不能调用类型上的函数”，要区分静态成员函数、非虚成员函数、虚函数和函数内部是否访问对象状态。

## 1. 结论

1. **静态成员函数**不依赖对象，可以通过类名调用，也可以写成 `p->static_func()`，但后者只是语法上允许，不会解引用对象。
2. **非静态成员函数**需要 `this` 指针。用空指针调用非静态成员函数属于未定义行为。
3. **虚函数**调用通常需要先从对象地址读取 `vptr`，空指针调用大概率直接崩溃。
4. **非虚成员函数如果不访问成员**，有时看起来能运行，但仍然是未定义行为，不能依赖。

普通空指针解引用同样是未定义行为：

```cpp
int* p = nullptr;
// int x = *p; // 未定义行为，通常触发 SIGSEGV
// *p = 1;     // 未定义行为，通常触发 SIGSEGV
```

在多数现代操作系统中，地址 0 附近的虚拟页不会映射给用户进程。CPU 执行 load/store 时，MMU 查页表发现地址无映射或权限不允许，会触发缺页异常；内核判断为非法访问后向进程发送 `SIGSEGV`，如果没有处理就会生成 core dump。但 C++ 标准层面只说这是未定义行为，不能把“必然崩溃”当成语言保证。

## 2. 为什么有时不崩

示例：

```cpp
#include <iostream>

struct A {
    void f() {
        std::cout << "A::f\n";
    }

    void g() {
        std::cout << x << "\n";
    }

    int x = 1;
};

int main() {
    A* p = nullptr;
    p->f(); // 可能打印，但仍是未定义行为
    p->g(); // 通常崩溃，因为访问了 this->x
}
```

普通非虚成员函数在 ABI 层面常被编译成类似：

```cpp
void A_f(A* this);
```

如果函数体完全不使用 `this`，机器码可能不会读取地址 0，所以看起来没有崩。但 C++ 语义上，`p->f()` 已经要求通过空指针形成成员调用，行为未定义。

## 3. 虚函数为什么更容易崩

虚函数调用需要动态派发：

```text
对象地址 -> 取 vptr -> 找虚表槽位 -> 间接调用函数
```

如果对象指针是 `nullptr`，第一步取 `vptr` 就要访问地址 0 附近，通常触发段错误。

```cpp
struct B {
    virtual void f() {}
};

B* p = nullptr;
p->f(); // 通常直接崩溃
```

## 4. 静态成员函数

静态成员函数没有 `this` 指针：

```cpp
struct C {
    static void f() {}
};

C* p = nullptr;
p->f();  // 语法允许，但不推荐
C::f();  // 推荐写法
```

虽然 `p->f()` 不需要对象，但可读性差，容易误导读者以为函数依赖对象状态。工程上应使用 `C::f()`。

## 5. 真实场景

空指针 core dump 常见原因：

1. 未初始化指针。
2. 对象生命周期结束后仍持有旧指针。
3. 容器扩容导致指针失效。
4. `dynamic_cast` 失败返回 `nullptr` 后未检查。
5. 工厂函数返回空指针表示创建失败，但调用方直接使用。
6. 多线程下对象被其他线程释放。

防护方式：

1. 优先使用引用表达不能为空的参数。
2. 使用 `std::unique_ptr`、`std::shared_ptr` 表达所有权。
3. 使用 `gsl::not_null` 或断言表达非空契约。
4. 对可能为空的指针在入口处检查。
5. 用 ASan、UBSan、core dump、gdb 定位真实崩溃点。

## 6. 易错点

1. “我测试没崩”不代表合法，未定义行为不能依赖。
2. 非虚函数不访问成员也不应通过空指针调用。
3. 虚函数调用通常要读 `vptr`，空指针更容易直接崩。
4. 静态成员函数不需要对象，应使用类名调用。
5. `this == nullptr` 的成员函数防御式写法本身也不能作为可靠契约。

## 7. 面试回答模板

空指针调用非静态成员函数是未定义行为。普通非虚成员函数底层类似把 `this` 当隐含参数传进去，如果函数体不访问成员，某些平台上可能看起来能跑，但语义上仍然不合法；一旦访问成员就会解引用空地址。虚函数更危险，因为动态派发通常要先从对象里取 `vptr`，空指针会直接崩。静态成员函数没有 `this`，可以不依赖对象调用，但工程上应写 `Class::func()`，不要写 `p->func()` 误导读者。
