# Q148. const 关键字

## 1. const 是什么

`const` 表示对象或访问路径不可被修改。它既是类型系统的一部分，也是接口设计的一种约束。

常见用途：

1. 修饰变量：对象初始化后不能通过该名字修改。
2. 修饰指针：限制指针指向的对象或指针本身是否可改。
3. 修饰函数参数：避免函数内部修改参数。
4. 修饰成员函数：承诺不修改对象的逻辑状态。
5. 修饰返回值：限制调用方修改返回结果。

## 2. `const int *p` 和 `int *const p`

判断方法：从右往左读，或者看 `const` 修饰谁。

```cpp
const int* p1;   // 指向 const int 的指针
int const* p2;   // 和 p1 等价
int* const p3;   // const 指针，指向 int
const int* const p4; // const 指针，指向 const int
```

区别：

1. `const int *p`：`p` 可以改指向，但不能通过 `p` 修改指向的 int。
2. `int *const p`：`p` 本身不能改指向，但可以通过 `p` 修改指向的 int。
3. `const int *const p`：指针本身和指向内容都不能通过这个名字修改。

示例：

```cpp
int a = 1;
int b = 2;

const int* p = &a;
p = &b;     // 可以
// *p = 3;  // 不可以

int* const q = &a;
*q = 3;     // 可以
// q = &b;  // 不可以
```

## 3. const 成员函数

成员函数后面的 `const` 修饰的是隐式 `this` 指针。

```cpp
class User {
public:
    int id() const {
        return id_;
    }

private:
    int id_ = 0;
};
```

`int id() const` 中，`this` 类型近似为：

```cpp
const User* const this
```

因此函数内不能修改普通成员变量，也不能调用非 `const` 成员函数。

如果某些字段不影响对象逻辑状态，例如缓存、锁，可以用 `mutable`：

```cpp
class Cache {
public:
    int get() const {
        ++hit_count_;
        return value_;
    }

private:
    int value_ = 0;
    mutable int hit_count_ = 0;
};
```

## 4. 顶层 const 和底层 const

1. **顶层 const**：对象本身是 const，例如 `int* const p`。
2. **底层 const**：指向或引用的对象是 const，例如 `const int* p`、`const int& r`。

函数传参时，按值传递的顶层 const 通常会被忽略：

```cpp
void f(int x);
void f(const int x); // 不能和上面构成重载
```

但底层 const 是类型的一部分：

```cpp
void g(int* p);
void g(const int* p); // 可以重载
```

## 5. const 和 constexpr

`const` 只表示不能修改，不保证编译期常量。

```cpp
int n = 10;
const int a = n; // 运行期初始化，不是编译期常量
```

`constexpr` 表示可以在编译期求值：

```cpp
constexpr int size = 1024;
```

工程上：

1. 只表达只读语义，用 `const`。
2. 需要编译期常量、数组长度、模板参数，用 `constexpr`。

## 6. `const int *p` 运行时强行写会怎样

`const int *p` 的含义是“不能通过 `p` 修改指向的 `int`”。如果直接写：

```cpp
const int* p = &x;
*p = 10; // 编译错误
```

编译器会拒绝，因为当前访问路径是只读的。

如果用 `const_cast` 强行去掉 const，要看底层对象本来是不是 const：

```cpp
int a = 1;
const int* p1 = &a;
*const_cast<int*>(p1) = 2; // 合法，但不推荐，a 变成 2

const int b = 1;
const int* p2 = &b;
*const_cast<int*>(p2) = 2; // 未定义行为
```

真实风险：

1. 如果底层对象本身是非 const，只是通过 `const int*` 观察它，去掉 const 后修改通常是合法的，但会破坏接口约束。
2. 如果底层对象本身就是 const，强行修改是未定义行为，可能看起来生效，也可能被优化器忽略，还可能访问只读段导致崩溃。
3. 如果指向字符串字面量、只读映射内存或编译器放入只读段的数据，写入可能触发段错误。

面试回答时不要只说“会报错”。直接通过 `p` 写是编译期错误；绕过类型系统后可能进入未定义行为，具体结果不能依赖。

## 7. 易错点

1. `const` 不代表底层对象绝对不可变，只代表不能通过当前访问路径修改。
2. `const_cast` 去掉 const 后修改原本就是 const 的对象是未定义行为。
3. `const` 成员函数不等于线程安全，多个线程读写共享状态仍然需要同步。
4. `mutable` 要谨慎使用，适合缓存、统计、锁这类不改变逻辑状态的字段。

## 8. 面试回答模板

`const` 是 C++ 类型系统里表达只读约束的关键字。`const int* p` 表示不能通过 `p` 修改指向的 int，但 `p` 可以改指向；`int* const p` 表示指针本身不能改指向，但可以修改指向内容。成员函数后的 `const` 修饰隐式 `this`，表示函数不修改对象逻辑状态。还要区分顶层 const 和底层 const：按值传参的顶层 const 不参与重载，但指针或引用指向对象的 const 是类型的一部分。
