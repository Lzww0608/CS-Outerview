# 2. 如何避免 C++ 内存泄漏

## 1. 内存泄漏是什么

内存泄漏是指程序申请了堆内存或其他资源，但在不再使用后没有释放，导致资源生命周期超过业务需要。长期运行的服务中，泄漏会表现为 RSS 持续上涨、频繁触发 OOM、延迟抖动或被系统杀掉。

需要注意，C++ 里的“泄漏”不只包括 `new` 出来的内存，还包括文件描述符、socket、锁、线程、数据库连接、GPU buffer 等资源没有正确释放。

## 2. 核心原则：RAII

RAII 的思想是：资源的获取和对象生命周期绑定，对象析构时自动释放资源。

常见做法：

1. 堆对象优先使用 `std::unique_ptr` 表达独占所有权。
2. 需要共享所有权时使用 `std::shared_ptr`，并用 `std::weak_ptr` 打断循环引用。
3. 容器优先保存对象或智能指针，不保存裸 owning pointer。
4. 文件、socket、锁、连接池句柄都封装成带析构函数的类型。
5. 构造函数中申请资源，析构函数中释放资源，避免业务代码散落 `delete/free/close`。

示例：

```cpp
#include <unistd.h>
#include <utility>

class UniqueFd {
public:
    explicit UniqueFd(int fd = -1) : fd_(fd) {}
    ~UniqueFd() {
        if (fd_ >= 0) {
            close(fd_);
        }
    }

    UniqueFd(const UniqueFd&) = delete;
    UniqueFd& operator=(const UniqueFd&) = delete;

    UniqueFd(UniqueFd&& other) noexcept : fd_(std::exchange(other.fd_, -1)) {}

    UniqueFd& operator=(UniqueFd&& other) noexcept {
        if (this != &other) {
            if (fd_ >= 0) {
                close(fd_);
            }
            fd_ = std::exchange(other.fd_, -1);
        }
        return *this;
    }

    int get() const { return fd_; }

private:
    int fd_;
};
```

## 3. 所有权要写清楚

内存泄漏很多时候不是忘记 `delete`，而是所有权不清晰。

1. **拥有资源**：用 `unique_ptr<T>`、`shared_ptr<T>` 或 RAII wrapper。
2. **只观察不拥有**：用 `T*`、`T&`、`std::weak_ptr<T>`、`std::span`、`std::string_view`，但要明确生命周期。
3. **跨模块传递所有权**：函数签名直接表达，例如返回 `std::unique_ptr<T>` 或参数接收 `std::unique_ptr<T>`。
4. **禁止隐式复制资源对象**：拥有资源的类通常删除拷贝构造和拷贝赋值，只允许移动。

## 4. 异常安全

手写 `new` 后再执行可能抛异常的代码，很容易泄漏：

```cpp
auto* p = new Object();
mayThrow();
delete p;
```

如果 `mayThrow()` 抛异常，`delete` 不会执行。应改为：

```cpp
auto p = std::make_unique<Object>();
mayThrow();
```

智能指针随栈展开自动析构，异常路径也能释放资源。

## 5. 常见泄漏来源

1. `new/delete`、`new[]/delete[]`、`malloc/free` 混用。
2. `unique_ptr::release()` 后忘记把裸指针交给新的 owner。
3. `shared_ptr` 循环引用。
4. 同一个裸指针构造多个独立 `shared_ptr`。
5. 自定义删除器没有真正释放资源。
6. 回调、线程、定时器持有对象，导致对象生命周期被意外延长。
7. 容器只删除指针元素，没有释放指针指向的对象。

## 6. 工程检测手段

1. **编译期**：开启 `-Wall -Wextra -Werror`，配合 clang-tidy、cppcheck。
2. **测试期**：使用 AddressSanitizer/LeakSanitizer。
3. **线下压测**：使用 Valgrind、heaptrack、gperftools。
4. **线上低开销排查**：用 jemalloc profiling、tcmalloc heap profile、eBPF/bcc `memleak`。
5. **服务指标**：观察 RSS、heap、fd 数、连接数、线程数是否随请求结束回落。

## 7. 面试回答模板

C++ 避免内存泄漏的核心不是到处记得 `delete`，而是用 RAII 让资源生命周期自动化。普通堆对象用 `unique_ptr` 表达独占所有权，确实需要共享时才用 `shared_ptr`，并用 `weak_ptr` 解决循环引用。文件描述符、socket、锁、连接这类非内存资源也要封装成析构自动释放的对象。工程上再配合 ASan/LSan、Valgrind、heap profiling 和线上 RSS/fd 监控，才能在编码、测试和生产三个阶段降低泄漏风险。
