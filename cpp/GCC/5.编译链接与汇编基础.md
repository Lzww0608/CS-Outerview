# 5.编译、链接与汇编基础

面试里问“编译和链接了解吗”“学过汇编吗”，重点不是手写大量汇编，而是能说明从源代码到可执行文件的阶段、目标文件里有什么、链接器解决什么问题，以及汇编和机器指令的关系。

## 1. 从源码到可执行文件

以 C/C++ 为例，典型流程：

```text
.cpp
  -> 预处理
  -> 编译
  -> 汇编
  -> 链接
  -> 可执行文件 / 动态库 / 静态库
```

各阶段职责：

1. **预处理**：展开 `#include`、处理 `#define`、条件编译，生成预处理后的源码。
2. **编译**：把源码翻译成汇编或中间表示，完成语法/语义检查和优化。
3. **汇编**：把汇编代码转成机器码，生成目标文件 `.o`。
4. **链接**：把多个目标文件和库合并，解析符号引用，做重定位，生成最终产物。

常用命令：

```bash
g++ -E main.cpp -o main.i     # 预处理
g++ -S main.cpp -o main.s     # 编译到汇编
g++ -c main.cpp -o main.o     # 编译汇编到目标文件
g++ main.o util.o -o app      # 链接
```

## 1.0 编译原理通常包括哪些阶段

如果面试官问“编译原理了解哪些”，可以把编译器内部拆成前端、中端和后端：

1. **词法分析**：把字符流切成 token，例如关键字、标识符、字面量、运算符。
2. **语法分析**：根据文法把 token 组织成 AST，检查括号、语句结构和表达式层次。
3. **语义分析**：做类型检查、作用域解析、重载决议、访问控制、模板实例化等语言语义检查。
4. **中间表示 IR**：把源码结构转换成更适合优化的中间形式，例如 LLVM IR、GIMPLE。
5. **优化**：常量传播、死代码删除、公共子表达式消除、循环优化、内联、逃逸分析、向量化等。
6. **代码生成**：指令选择、寄存器分配、指令调度，生成目标架构的汇编或机器码。
7. **汇编和链接**：汇编器生成目标文件，链接器解析符号、重定位并合并库。

示例：

```cpp
int x = 1 + 2;
```

词法分析会得到 `int`、`x`、`=`、`1`、`+`、`2` 等 token；语法分析构造变量定义和加法表达式；语义分析确认类型是 `int`；优化阶段可能把 `1 + 2` 常量折叠成 `3`；后端再生成把 `3` 写入目标位置的机器指令。

易错点：

1. 编译器前端负责理解语言，后端负责面向机器生成代码，中间优化尽量与源语言和目标机器解耦。
2. 语法正确不代表语义正确，例如 `int* p = 1.2;` 语法结构能解析，但类型检查会失败。
3. C++ 的模板、重载、`constexpr` 会把大量工作提前到编译期，所以错误信息和编译耗时都可能明显增加。
4. 编译优化必须保持程序的可观察行为；未定义行为会给优化器更大自由，导致 Debug 和 Release 表现差异。

## 1.1 C++ 类从代码到可执行文件

类定义本身主要是编译期信息，它描述对象布局、成员函数签名、访问控制、继承关系和虚函数表规则；真正的运行期对象只有在定义变量、`new`、静态对象初始化等场景下才会创建。

以一个带虚函数的类为例：

```cpp
class Base {
public:
    virtual void f();
    int x;
};

class Derived : public Base {
public:
    void f() override;
    int y;
};
```

从代码到可执行文件可以这样理解：

1. **预处理阶段**：展开头文件和宏，类定义会出现在使用它的翻译单元里。
2. **编译阶段**：编译器根据 ABI 规则确定 `Base/Derived` 的对象布局、成员偏移、对齐方式、构造析构逻辑、虚函数调用方式和 name mangling 后的符号名。
3. **虚表生成**：如果类有虚函数，编译器会在合适的翻译单元生成虚函数表、RTTI 等只读数据；对象中只保存虚表指针，不保存虚表本体。
4. **成员函数生成**：非虚成员函数、虚函数实现、构造函数、析构函数都会变成普通机器指令，隐式 `this` 指针作为参数传入。
5. **目标文件阶段**：`.o` 中包含 `.text/.rodata/.data/.bss`、符号表和重定位信息；对其他翻译单元函数或全局对象的引用暂时是未解析符号。
6. **链接阶段**：链接器解析类成员函数、虚表、静态成员、模板实例化等符号引用，并把地址重定位成最终可执行文件或动态库中的地址。

易错点：

1. 类定义不等于对象分配内存，只有对象实例才占对象存储空间。
2. 普通成员函数不在对象内部，每个对象只保存非静态数据成员、必要的 `vptr`、虚继承指针等布局信息。
3. 模板类只有在实例化为具体类型后才会生成对应代码，很多模板链接问题本质是定义不可见或实例化缺失。
4. `inline`、ODR、虚表归属、静态成员定义都会影响链接阶段是否报 `undefined reference` 或 `multiple definition`。

## 1.2 编译期和汇编期可以合并吗

从概念上看，编译和汇编是两个阶段：

1. 编译器前端/优化器把 C++ 翻译成中间表示或汇编文本。
2. 汇编器把汇编文本翻译成目标文件中的机器码和重定位信息。

但实际工具链可以把这两个阶段合并执行。比如：

```bash
g++ -S main.cpp -o main.s  # 停在汇编文本
g++ -c main.cpp -o main.o  # 直接得到目标文件
```

`-c` 看起来一步生成 `.o`，内部仍然要完成“编译语义分析和优化”以及“生成机器码/目标文件”这两类工作，只是没有把中间的 `.s` 文件暴露出来。有些编译器后端直接生成目标文件，也不会真的落地汇编文本。

面试回答时可以说：阶段在逻辑上可区分，工程实现上可以合并流水线执行；能否看到 `.s` 取决于编译选项和编译器后端。

## 2. 目标文件里有什么

目标文件通常包含：

1. `.text`：机器指令。
2. `.rodata`：只读常量、字符串字面量。
3. `.data`：已初始化全局/静态变量。
4. `.bss`：未初始化或零初始化全局/静态变量。
5. 符号表：函数、全局变量、外部引用。
6. 重定位信息：哪些地址要等链接时再修正。
7. 调试信息：`-g` 时包含源码行号、类型等信息。

## 3. 链接解决什么

链接器主要做三件事：

1. **符号解析**：把函数调用和全局变量引用绑定到某个定义。
2. **重定位**：确定各段最终地址，修正机器指令和数据中的地址引用。
3. **库合并**：把静态库需要的目标文件拷进产物，或记录动态库依赖。

常见链接错误：

1. `undefined reference`：声明存在，但链接阶段找不到定义。
2. `multiple definition`：多个目标文件里有同名强符号定义。
3. ABI 不兼容：编译器版本、标准库、结构体布局或 name mangling 不一致。
4. 动态库运行时找不到：编译链接成功，但运行时 `LD_LIBRARY_PATH`、rpath 或系统库路径不对。

## 4. 静态链接和动态链接

| 对比项 | 静态链接 | 动态链接 |
| --- | --- | --- |
| 产物 | 库代码复制进可执行文件 | 可执行文件记录依赖 `.so` |
| 启动依赖 | 依赖少，部署简单 | 运行时需要找到动态库 |
| 文件体积 | 通常更大 | 通常更小 |
| 内存共享 | 多进程难共享同一份库代码 | 多进程可共享只读代码页 |
| 升级 | 需要重新发布可执行文件 | 可独立升级库，但要注意 ABI |

服务端常用动态链接节省内存和便于升级；基础工具、容器镜像、嵌入式场景可能偏向静态链接以降低运行时依赖。

## 5. 汇编基础

汇编是机器指令的文本形式。了解汇编有助于看懂函数调用、栈帧、寄存器、性能瓶颈和 core dump。

常见概念：

1. **寄存器**：CPU 内部高速存储，例如 x86-64 的 `rax/rbx/rsp/rbp/rip`。
2. **栈指针**：`rsp` 指向当前栈顶，函数调用会调整栈指针保存局部变量和返回地址。
3. **调用约定**：规定参数放在哪些寄存器/栈上，返回值放哪里，谁负责保存寄存器。
4. **函数序言/尾声**：建立和销毁栈帧，例如保存 `rbp`、调整 `rsp`。
5. **条件跳转**：编译器把 `if/while` 翻译成比较和跳转指令。

一个很小的函数：

```cpp
int add(int a, int b) {
    return a + b;
}
```

优化后可能接近：

```asm
lea eax, [rdi + rsi]
ret
```

`rdi/rsi` 是 System V x86-64 ABI 下前两个整型参数寄存器，`eax` 保存返回值。

## 6. 易错点

1. 编译错误和链接错误不是一回事；头文件找不到是编译期，函数定义找不到多半是链接期。
2. 头文件只提供声明，真正代码通常在 `.cpp` 或库文件里。
3. `inline`、模板、ODR 和头文件定义会影响链接行为。
4. Debug 和 Release 反汇编差异很大，优化会内联、重排、删变量。
5. 汇编依赖 CPU 架构和 ABI，x86-64、ARM64 的寄存器和调用约定不同。

## 7. 面试回答模板

C++ 从源码到可执行文件通常经历预处理、编译、汇编、链接。预处理展开宏和头文件；编译做语法语义分析、优化并生成汇编；汇编生成目标文件；链接器把多个目标文件和库合在一起，解析符号并做重定位。目标文件里有代码段、数据段、符号表和重定位信息。静态链接把库代码复制进产物，动态链接在运行时加载共享库。汇编是机器指令的文本形式，了解寄存器、栈帧、调用约定和跳转指令，有助于调试 core dump 和分析性能热点。
