# 6. C++ 函数调用与栈帧

函数调用不是简单地“跳到另一个函数执行”。编译器和 ABI 会约定参数放在哪里、返回值放在哪里、哪些寄存器由调用方保存、哪些由被调用方保存，以及栈帧如何建立和销毁。

## 1. 调用过程

以 x86-64 System V ABI 为例，普通函数调用大致过程如下：

```text
调用方准备参数
  -> 前几个整数或指针参数放入 rdi/rsi/rdx/rcx/r8/r9
  -> 多余参数、部分大对象或对齐需求放入栈上
call 指令压入返回地址并跳转
被调用方建立栈帧
  -> 保存必要寄存器
  -> 为局部变量、临时对象、溢出寄存器分配栈空间
执行函数体
返回值放入约定位置
  -> 整数/指针通常在 rax
  -> 浮点通常在 xmm0
ret 取出返回地址并跳回调用方
调用方清理调用现场
```

不同平台调用约定不同。Windows x64、System V x86-64、ARM64 在参数寄存器、栈对齐和调用者/被调用者保存寄存器上都有差异，面试回答要加上“以某 ABI 为例”。

## 2. `this` 指针和成员函数

C++ 非静态成员函数底层可以近似看成多了一个隐式参数 `this`：

```cpp
struct Node {
    int x;
    int get() const { return x; }
};
```

可以理解为：

```cpp
int Node_get(const Node* this_ptr) {
    return this_ptr->x;
}
```

因此：

1. 普通成员函数代码不存放在每个对象内部。
2. 调用成员函数时，调用方要把对象地址作为隐式 `this` 参数传入。
3. 虚函数调用会先通过对象中的 `vptr` 找到虚表，再从虚表取函数地址间接调用。
4. 静态成员函数没有 `this` 指针，所以不能直接访问非静态成员，也不能声明为虚函数。

## 3. 参数传递

常见传参方式：

1. **值传递**：调用时复制参数。小整数、指针和轻量结构通常成本低；大对象可能触发拷贝或移动。
2. **指针传递**：传的是地址，可表达可空、可修改目标对象，但要注意生命周期。
3. **引用传递**：底层通常也是地址，语义上要求绑定到有效对象；`const T&` 常用于避免大对象拷贝。
4. **右值引用传递**：用于表达可移动资源，常配合移动构造、完美转发。

示例：

```cpp
void by_value(std::string s);
void by_ref(const std::string& s);
void by_ptr(std::string* s);
```

`by_value` 需要构造形参对象；`by_ref` 只传地址且不转移所有权；`by_ptr` 可以传空指针，调用方和被调用方要约定是否允许为空。

## 4. 栈帧里通常有什么

一个函数栈帧可能包含：

1. 返回地址。
2. 保存的旧栈基址或必要寄存器。
3. 局部变量和临时对象。
4. 溢出到栈上的参数。
5. 对齐填充、异常处理和调试信息需要的辅助数据。

优化级别会显著改变栈帧形态：

1. `-O0` 下常保留帧指针，便于调试。
2. `-O2` 下函数可能被内联，栈帧可能消失。
3. 变量可能只存在于寄存器中，调试器里看到的局部变量可能被优化掉。
4. 尾调用优化可能让当前函数复用调用方栈帧。

## 5. 易错点

1. 栈上传参不是唯一方式，现代 ABI 会优先使用寄存器传前几个参数。
2. 引用不是“没有成本”，底层仍然要传地址，只是语义比裸指针更强。
3. `std::move` 本身不搬数据，只把表达式转成右值，真正移动发生在移动构造或移动赋值里。
4. 递归深度太大会不断创建栈帧，可能栈溢出。
5. 函数调用栈在 core dump、性能火焰图、异常定位中非常关键，编译时保留符号和帧指针对排查很有帮助。

## 6. 面试回答模板

函数调用要按 ABI 调用约定理解。调用方先把参数放到寄存器或栈上，`call` 保存返回地址并跳转；被调用方建立栈帧，保存必要寄存器，分配局部变量空间，执行后把返回值放到约定寄存器或内存位置，再 `ret` 回调用方。C++ 成员函数会隐式传入 `this` 指针，虚函数还会通过对象里的 `vptr` 查虚表后间接调用。优化后函数可能内联、变量可能只在寄存器里，真实栈帧会和源码形式不同。
