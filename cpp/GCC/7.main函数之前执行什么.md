# 7.main 函数之前执行什么

面试里问“`main` 之前还会执行什么”，重点是理解程序启动不是直接跳到 `main`，而是由操作系统、动态链接器、C/C++ 运行时共同完成初始化。

## 1. 大致启动链路

以 Linux ELF 程序为例，典型流程可以简化为：

```text
execve
  -> 内核加载 ELF
  -> 映射程序段和动态链接器
  -> 动态链接器装载依赖库并做重定位
  -> 进入 C 运行时入口 _start
  -> __libc_start_main
  -> 执行初始化函数
  -> 调用 main(argc, argv, envp)
  -> main 返回后执行退出清理
```

`main` 不是真正的进程第一条用户态指令。编译链接时会把启动文件（如 `crt1.o/crti.o/crtn.o`）和用户目标文件链接在一起，入口通常是 `_start`。

## 2. main 之前做了哪些事

常见工作包括：

1. **内核加载程序**：解析 ELF，映射 `.text/.rodata/.data/.bss`，建立用户栈，把参数和环境变量放到栈上。
2. **动态链接**：如果是动态链接程序，动态链接器加载共享库、解析符号、处理 GOT/PLT、执行重定位。
3. **运行时初始化**：初始化 libc、线程局部存储 TLS、栈保护、全局环境等。
4. **全局/静态对象初始化**：执行 C++ 全局对象和静态存储期对象的动态初始化。
5. **构造函数数组**：执行 `.init_array` 中注册的初始化函数，例如带 `constructor` 属性的函数。
6. **准备 main 参数**：把 `argc/argv/envp` 传给 `main`。

示例：

```cpp
#include <iostream>

struct Global {
    Global() {
        std::cout << "global ctor\n";
    }
};

Global g;

__attribute__((constructor))
void before_main() {
    std::cout << "constructor attr\n";
}

int main() {
    std::cout << "main\n";
}
```

输出中，`before_main` 和全局对象构造都会发生在 `main` 之前。它们之间的精确顺序受平台、编译器和链接规则影响，跨翻译单元不要依赖复杂初始化顺序。

## 3. main 之后还会执行什么

`main` 返回后，运行时会把返回值交给 `exit` 流程，并执行：

1. `atexit` 注册的函数。
2. C++ 全局/静态对象的析构函数。
3. 共享库卸载时的析构函数。
4. 刷新标准 I/O 缓冲区。
5. 最终通过系统调用结束进程。

如果调用 `_exit()` 或进程被 `SIGKILL` 杀死，这些清理流程可能不会执行。

## 4. 易错点

1. 不要在全局对象构造中依赖另一个翻译单元的全局对象已经初始化，这就是 static initialization order fiasco。
2. 全局构造函数里不要做复杂 I/O、启动线程或访问尚未初始化的单例，排查困难。
3. 动态库被加载时也可能执行初始化函数，不只可执行文件有 `main` 前逻辑。
4. 静态链接和动态链接的启动细节不同，但“`_start` 先于 `main`”这个事实不变。
5. C++ 局部静态对象是在第一次执行到声明处时初始化，不一定发生在 `main` 之前。

## 5. 面试回答模板

`main` 不是程序真正入口。Linux 下内核执行 `execve` 后加载 ELF，动态链接器装载依赖库并重定位，然后进入 C 运行时 `_start/__libc_start_main`，初始化 libc、TLS、栈保护等运行时状态，执行 `.init_array` 里的构造函数和 C++ 全局对象动态初始化，最后才调用 `main(argc, argv, envp)`。`main` 返回后还会执行 `atexit`、全局析构和标准 I/O 刷新。工程上要避免在全局构造里做复杂逻辑，也不要依赖跨翻译单元全局对象初始化顺序。

## 6. 如何在 main 函数前打一条日志

常见做法有三类：

1. **全局对象构造函数**：定义一个全局对象，在构造函数里打印日志。
2. **GCC/Clang constructor 属性**：使用 `__attribute__((constructor))` 注册初始化函数。
3. **链接器 init_array**：更底层地把函数放入初始化数组，通常不建议业务代码直接使用。

示例：

```cpp
#include <cstdio>

struct BeforeMainLogger {
    BeforeMainLogger() {
        std::fprintf(stderr, "before main: global constructor\n");
    }
};

BeforeMainLogger g_logger;

__attribute__((constructor))
static void before_main_log() {
    std::fprintf(stderr, "before main: constructor attribute\n");
}

int main() {
    std::fprintf(stderr, "main\n");
}
```

注意事项：

1. `std::cout` 等 iostream 对象也有初始化顺序问题，早期启动日志更推荐 `write(2, ...)` 或 `fprintf(stderr, ...)` 这类更简单的接口。
2. 不要在 main 前启动复杂线程、访问单例、依赖配置中心或进行网络 I/O，排错困难且容易踩 static initialization order fiasco。
3. 多个翻译单元之间的全局对象初始化顺序不可靠；如果日志依赖另一个全局对象，可能在它初始化前就被使用。
4. 动态库加载时也会执行 constructor，因此这类日志不一定只发生在可执行文件启动阶段。
5. 生产级日志系统通常在 `main` 里显式初始化；main 前日志只适合启动链路探针、极早期崩溃定位或面试说明机制。
