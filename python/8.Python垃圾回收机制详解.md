# Python 垃圾回收机制详解

## 1. 问题背景

Python 的垃圾回收（Garbage Collection）是自动内存管理的核心机制，负责释放不再使用的对象，避免内存泄漏。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Python 垃圾回收三大机制：                                 │
│                                                             │
│  1. 引用计数（Reference Counting）                        │
│     • 主要机制，实时回收                                   │
│     • 无法处理循环引用                                     │
│                                                             │
│  2. 标记-清除（Mark & Sweep）                            │
│     • 解决循环引用问题                                     │
│     • 定期执行                                           │
│                                                             │
│  3. 分代回收（Generational GC）                          │
│     • 新建对象在年轻代                                     │
│     • 多次存活移至老年代                                   │
│     • 减少全量扫描次数                                     │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 |
|------|------|
| 内存持续增长 | 对象未被及时回收 |
| 循环引用泄漏 | 互相引用导致无法回收 |
| GC 暂停 | 大量对象时 GC 卡顿 |
| 内存碎片 | 频繁分配释放导致碎片 |

---

## 3. 影响范围

- 长时间运行的服务
- 大量对象创建的应用
- 内存敏感场景

## 4. 原因分析

### 4.1 引用计数机制

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  引用计数原理：                                           │
│                                                             │
│  每个对象维护一个 refcount 计数器                         │
│                                                             │
│  a = []        # refcount = 1                             │
│  b = a         # refcount = 2                             │
│  del a         # refcount = 1                             │
│  del b         # refcount = 0 → 立即回收                  │
│                                                             │
│  优点：实时回收，无延迟                                   │
│  缺点：无法处理循环引用                                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.2 循环引用问题

```python
# 循环引用示例

class Node:
    def __init__(self, name):
        self.name = name
        self.next = None

# 创建循环引用
node1 = Node("node1")
node2 = Node("node2")
node1.next = node2   # node1.refcount +1
node2.next = node1   # node2.refcount +1

# 外部引用计数都是 1，但互相引用无法回收
del node1
del node2
# 两个对象都无法被引用计数回收
```

### 4.3 分代回收机制

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  分代回收原理：                                           │
│                                                             │
│  年轻代（Generation 0）                                    │
│      │ 频繁创建销毁的对象                                  │
│      ▼ 多次存活后                                          │
│  老年代（Generation 1）                                    │
│      │ 长期存在的对象                                      │
│      ▼                                                     │
│  老年代（Generation 2）                                    │
│                                                             │
│  回收策略：                                               │
│  • 0 代最频繁，2 代最少                                    │
│  • 对象存活越久，被回收概率越低                            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 4.4 标记-清除算法

```python
# 标记-清除流程

def mark_and_sweep():
    """
    标记-清除算法
    """
    # 1. 标记阶段
    # 从根对象（全局变量、栈）出发
    # 遍历所有可达对象，打上标记
    
    marked = set()
    def mark(obj):
        if obj not in marked:
            marked.add(obj)
            # 递归标记引用对象
            for ref in get_references(obj):
                mark(ref)
    
    for root in get_roots():
        mark(root)
    
    # 2. 清除阶段
    # 回收所有未标记的对象
    for obj in get_all_objects():
        if obj not in marked:
            free_object(obj)
```

## 5. 解决方案

### 5.1 避免循环引用

```python
# 方案1：使用弱引用
import weakref

class Node:
    def __init__(self, name):
        self.name = name
        self._next = None
    
    @property
    def next(self):
        return self._next  # 外部引用，不影响 refcount
    
    @next.setter
    def next(self, node):
        self._next = weakref.ref(node)() if node else None

# 方案2：使用 __slots__
class Node:
    __slots__ = ['name', 'next']  # 不创建 __dict__，减少内存
    def __init__(self, name):
        self.name = name
        self.next = None

# 方案3：显式删除引用
del node1.next
del node2.next
del node1
del node2
```

### 5.2 GC 模块使用

```python
import gc

# 手动触发垃圾回收
gc.collect()

# 查看 GC 统计信息
print(gc.get_stats())

# 查看分代对象数量
print(gc.get_count())  # (gen0_count, gen1_count, gen2_count)

# 获取无法回收的对象
unreachable = gc.collect()
print(f"回收了 {unreachable} 个对象")

# 调试模式
gc.set_debug(gc.DEBUG_SAVEALL)
gc.collect()
print(gc.garbage)  # 查看泄漏对象

# 调整 GC 阈值
# 默认: (700, 10, 10)
gc.set_threshold(700, 10, 10)
```

### 5.3 上下文管理器

```python
# 使用上下文管理器管理资源

class DatabaseConnection:
    def __enter__(self):
        self.conn = connect()
        return self.conn
    
    def __exit__(self, exc_type, exc_val, exc_tb):
        self.conn.close()  # 及时释放资源
        return False

# 使用
with DatabaseConnection() as conn:
    conn.query("SELECT * FROM users")

# 离开 with 块时自动关闭
```

### 5.4 内存优化配置

```python
import gc

# 优化 GC 配置

# 1. 调低 GC 阈值，减少暂停
gc.set_threshold(1000, 15, 15)

# 2. 禁用 GC（不推荐）
gc.disable()

# 3. 只在必要时启用
gc.enable()

# 4. 监控内存泄漏
import tracemalloc
tracemalloc.start()

snapshot = tracemalloc.take_snapshot()
top_stats = snapshot.statistics('lineno')
for stat in top_stats[:10]:
    print(stat)
```

## 6. 可选方案对比

| 方案 | 适用场景 | 优点 | 缺点 |
|------|----------|------|------|
| 引用计数 | 大多数场景 | 实时回收 | 无法处理循环引用 |
| 弱引用 | 缓存、树结构 | 避免循环引用 | 使用复杂 |
| 手动 del | 资源敏感 | 精确控制 | 侵入性强 |
| gc.collect() | 批量回收 | 主动触发 | 可能卡顿 |
| 分代配置 | 性能优化 | 减少 GC 开销 | 需调优 |

## 10. 验证方式

```python
import gc
import sys

def test_gc():
    """验证 GC 机制"""
    
    # 1. 创建循环引用
    class TestObj:
        def __init__(self, name):
            self.name = name
            self.ref = None
    
    obj1 = TestObj("obj1")

    obj1.ref = obj2
    obj2.ref = obj1
    
    # 2. 删除外部引用
    del obj1
    del obj2
    
    # 3. 检查无法回收的对象
    gc.collect()
    unreachable = gc.collect()
    print(f"无法回收的对象: {unreachable}")
    
    # 4. 使用弱引用解决问题
    import weakref
    
    obj1 = TestObj("obj1")
    obj2 = TestObj("obj2")
    obj1.ref = weakref.ref(obj2)
    obj2.ref = weakref.ref(obj1)
    
    del obj1
    del obj2
    
    # 检查
    gc.collect()
    unreachable = gc.collect()
    print(f"使用 weakref 后无法回收的对象: {unreachable}")
```

## 11. 总结

1. **三大机制**：引用计数（主要、实时）+ 标记-清除（处理循环引用）+ 分代回收（性能优化）
2. **核心问题**：循环引用导致无法回收，需要标记-清除配合
3. **优化方法**：使用 weakref、__slots__、上下文管理器、调整 GC 阈值
4. **调试工具**：gc 模块、tracemalloc、objgraph
5. **最佳实践**：避免循环引用 + 合理配置 GC + 监控内存使用
