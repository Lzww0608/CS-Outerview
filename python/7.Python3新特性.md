# 7. Python3 新特性

面试问“Python3 的新特性”时，不适合只回答“print 变函数”。更好的方式是按语言语义、类型系统、异步并发、性能和工程化工具分层说明。

## 1. 语言语义变化

Python3 相比 Python2 最核心的变化是文本和字节分离：

1. `str` 表示 Unicode 文本。
2. `bytes` 表示字节序列。
3. 文件、网络、加密、压缩等场景要明确编码和解码边界。

示例：

```python
text = "网易互娱"
raw = text.encode("utf-8")
assert raw.decode("utf-8") == text
```

其他常见变化：

1. `print` 是函数，写作 `print(x)`。
2. 整数除法 `/` 返回浮点数，`//` 才是整除。
3. `range` 返回惰性序列对象，不再直接生成完整列表。
4. `dict.keys()`、`items()`、`values()` 返回 view，能动态反映字典变化。
5. 异常写法统一为 `except Exception as e`。

## 2. 类型标注和工程化

Python3 引入并持续增强 type hints，虽然运行时默认不强制检查，但能显著提升大型项目可维护性。

```python
from typing import Optional

def find_user(uid: int) -> Optional[str]:
    if uid <= 0:
        return None
    return f"user-{uid}"
```

常见能力：

1. 函数参数和返回值标注。
2. `typing` 中的 `Optional`、`Union`、`Protocol`、`TypedDict`、`Generic`。
3. Python 3.10 的 `X | Y` 联合类型写法。
4. 配合 mypy、pyright、ruff、pytest 做静态检查和测试。

注意：类型标注不是运行时校验。接口入参仍需要 Pydantic、dataclass 校验、手写检查或框架层校验。

## 3. 异步编程

Python3 原生支持 `async`/`await` 和 `asyncio`，适合高并发 I/O 场景。

```python
import asyncio

async def fetch(uid: int) -> str:
    await asyncio.sleep(0.1)
    return f"user-{uid}"

async def main():
    users = await asyncio.gather(fetch(1), fetch(2))
    print(users)

asyncio.run(main())
```

核心点：

1. 协程通过事件循环调度，等待 I/O 时让出执行权。
2. 适合网络请求、数据库驱动、消息队列客户端等 I/O 密集任务。
3. CPU 密集任务仍会受 GIL 和单线程事件循环限制，应交给进程池、线程池或原生扩展。
4. 不要在协程里直接调用阻塞 I/O，否则会卡住整个事件循环。

## 4. 数据模型和语法增强

常见面试可提的新特性：

1. **f-string**：更快、更清晰的字符串格式化。
2. **dataclass**：简化数据对象定义。
3. **walrus operator `:=`**：在表达式中赋值，适合减少重复计算。
4. **结构化模式匹配 `match/case`**：Python 3.10 引入，适合解析 AST、协议消息、命令类型。
5. **仅关键字参数**：让函数调用更清晰。
6. **上下文变量 `contextvars`**：异步服务里保存请求上下文、trace id。

示例：

```python
from dataclasses import dataclass

@dataclass
class Player:
    uid: int
    score: int = 0

def handle(event: dict) -> str:
    match event:
        case {"type": "login", "uid": uid}:
            return f"login {uid}"
        case {"type": "score", "uid": uid, "delta": delta}:
            return f"score {uid} {delta}"
        case _:
            return "unknown"
```

## 5. 性能和运行时演进

Python3 后续版本持续优化解释器性能。Python 3.11 引入更快的 CPython 执行路径和更精确的异常位置信息，Python 3.12 继续推进解释器优化和类型系统能力。面试中不需要背每个小版本细节，但要能说明：

1. Python 仍然适合脚本、胶水层、Web API、数据处理和 AI 工程。
2. CPU 密集场景要考虑 NumPy 向量化、C/C++ 扩展、Cython、Numba、多进程或改用 Go/C++/Rust。
3. 并发 I/O 可以用 asyncio、FastAPI、aiohttp、异步数据库驱动。
4. 依赖管理可以用 venv、pip、Poetry、Conda，部署时要锁定版本和构建环境。

## 6. 易错点

1. Python3 的 `str` 和 `bytes` 不能随意拼接，网络协议和文件读写要明确编码。
2. `async` 函数调用后得到 coroutine object，必须 `await` 或交给事件循环执行。
3. 类型标注不等于运行时类型安全。
4. `dict` 在 Python 3.7 后保证插入顺序，但不要把它误认为按 key 排序。
5. GIL 不代表所有操作都线程安全，复合操作仍需要锁或线程安全队列。

## 7. 面试回答模板

Python3 的核心变化包括 Unicode 文本模型、`print` 函数、除法语义、惰性 `range` 和字典 view；工程上更重要的是 type hints、dataclass、f-string、async/await、contextvars、match/case 等能力。后端项目里我会用类型标注提升可维护性，用 asyncio/FastAPI 处理高并发 I/O，用 dataclass 或 Pydantic 表达数据结构，用 pytest/ruff/mypy 做质量控制。需要注意 Python3 的异步不适合直接跑 CPU 密集任务，阻塞调用也不能放进事件循环；性能敏感部分要用向量化、原生扩展、多进程或更合适的语言实现。
