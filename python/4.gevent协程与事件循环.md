# 4. gevent 协程与事件循环

gevent 是 Python 中基于协作式协程的并发库，底层依赖 greenlet 做用户态上下文切换，依赖 libev/libuv 做事件循环和 I/O 就绪通知。

## 1. gevent 是什么

gevent 的核心思想是：把阻塞 I/O 包装成非阻塞 I/O，当当前协程等待网络、定时器或其他事件时，主动让出执行权，让事件循环调度其他协程运行。

组成：

1. **greenlet**：轻量级协程，提供用户态栈切换能力。
2. **hub/event loop**：统一监听 fd、timer、signal 等事件。
3. **monkey patch**：把标准库 socket、time、ssl 等阻塞接口替换为 gevent 版本。
4. **协作式调度**：协程只有在 I/O 等待、sleep、显式 yield 等位置切换。

## 2. 好处和适用场景

优点：

1. 单线程内支撑大量 I/O 并发连接。
2. 写法接近同步代码，比回调风格更易读。
3. 避免大量线程带来的上下文切换和锁竞争。
4. 适合网络请求、爬虫、长连接、代理、网关等 I/O 密集场景。

不适合：

1. CPU 密集计算，因为协程不会并行利用多核。
2. 未被 monkey patch 的阻塞系统调用，可能卡住整个线程。
3. 需要强抢占公平性的场景，协作式调度依赖代码主动让出。

## 3. 什么时候切换

协程切换通常发生在：

1. `gevent.sleep()` 显式让出。
2. 非阻塞 socket 读写返回 `EAGAIN/EWOULDBLOCK`，当前协程挂起，等待 fd 可读/可写。
3. DNS、SSL、定时器等被 gevent 接管的阻塞点。
4. join、queue 等 gevent 同步原语等待时。

以发送数据为例，如果内核发送缓冲区有空间，`send` 可以立即写入并继续执行；如果 socket 是非阻塞模式且缓冲区满，`send` 返回 `EAGAIN`，gevent 会把当前 greenlet 挂到“等待可写事件”的队列里，事件循环用 epoll/kqueue 等机制等 fd 可写后再恢复它。

## 4. 如何实现自动切换

自动切换依赖 monkey patch 和事件循环：

```python
from gevent import monkey
monkey.patch_all()
```

patch 后，标准库阻塞调用会变成 gevent 版本。以 socket read 为例：

```text
recv -> 设置非阻塞 fd -> 尝试读取
  -> 如果有数据，直接返回
  -> 如果 EAGAIN，注册可读事件并切换到 hub
  -> epoll 通知 fd 可读
  -> hub 恢复原 greenlet
```

这和 Reactor 模型一致：事件循环负责等待 I/O 就绪，业务协程在就绪后继续执行。

## 5. 易错点

1. gevent 是协作式调度，不是 OS 线程抢占调度。
2. monkey patch 要尽量在导入其他网络库之前执行。
3. CPU 密集任务会阻塞整个事件循环，应放到进程池或线程池。
4. 第三方库如果内部使用未 patch 的阻塞调用，仍可能导致全局卡顿。
5. 协程切换不是任意时刻发生，通常发生在 I/O 等待或显式 yield 点。

## 6. 面试回答模板

gevent 是 Python 的协作式并发库，底层用 greenlet 做用户态协程切换，用 libev/libuv 的事件循环监听 I/O。它通过 monkey patch 把标准库阻塞 I/O 变成非阻塞 I/O；当读写 socket 遇到 `EAGAIN` 或需要等待定时器时，当前协程让出，事件循环等 fd 可读可写后再恢复。它适合 I/O 密集的高并发服务，不适合 CPU 密集计算，也要注意未 patch 的阻塞调用会卡住整个线程。
