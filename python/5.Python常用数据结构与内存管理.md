# Python 常用数据结构与内存管理

Python 面试里问数据结构和内存管理，重点不是背 API，而是理解对象模型、容器特性、引用计数、循环引用和 GIL 的关系。

## 1. 常用数据结构

| 结构 | 特点 | 常见复杂度 | 场景 |
| --- | --- | --- | --- |
| `list` | 动态数组，按下标访问快 | 下标访问 `O(1)`，尾部追加均摊 `O(1)` | 顺序数据、栈、批量收集 |
| `tuple` | 不可变序列 | 下标访问 `O(1)` | 固定记录、函数多返回值、可哈希元素组合 |
| `dict` | 哈希表，保留插入顺序 | 查询/插入平均 `O(1)` | 映射、计数、缓存、索引 |
| `set` | 哈希集合 | 查询/插入平均 `O(1)` | 去重、成员判断、集合运算 |
| `deque` | 双端队列 | 两端插删 `O(1)` | 队列、滑动窗口、BFS |
| `heapq` | 基于 list 的小根堆 | push/pop `O(log n)` | TopK、优先队列、Dijkstra |

易错点：

1. `list.pop(0)` 是 `O(n)`，频繁队头弹出应使用 `collections.deque`。
2. `dict` 和 `set` 依赖哈希，key 必须可哈希且相等对象哈希值一致。
3. `tuple` 不可变，但如果内部放的是可变对象，内部对象仍然可以被修改。
4. `dict` 平均 `O(1)` 不等于最坏永远 `O(1)`，哈希冲突和扩容会影响性能。

## 2. Python 对象和引用

Python 变量保存的是对象引用，而不是对象本身。

```python
a = [1, 2]
b = a
b.append(3)
print(a)  # [1, 2, 3]
```

这不是拷贝，而是两个名字指向同一个 list。需要复制时：

1. 浅拷贝：`a.copy()`、`list(a)`、`copy.copy(a)`。
2. 深拷贝：`copy.deepcopy(a)`，递归复制嵌套对象。

浅拷贝只复制外层容器，内部对象仍共享；深拷贝要处理循环引用，成本更高。

## 3. CPython 内存管理

CPython 主要依赖引用计数管理对象生命周期：

```text
引用增加 -> refcnt + 1
引用减少 -> refcnt - 1
refcnt 变成 0 -> 立即释放对象
```

引用计数的优点是对象释放及时，缺点是无法单独处理循环引用：

```python
a = []
b = []
a.append(b)
b.append(a)
```

即使外部不再引用 `a` 和 `b`，它们彼此引用，引用计数也不会归零。因此 CPython 还有分代垃圾回收器，专门检测容器对象之间的循环引用。

## 4. pymalloc 和内存池

Python 频繁创建小对象，如果每次都直接向操作系统申请内存，开销很高。CPython 使用 `pymalloc` 管理小对象内存，大致分层：

1. **arena**：较大的内存区域，从操作系统申请。
2. **pool**：arena 内按大小类别切分。
3. **block**：实际分配给小对象的块。

这样可以减少系统调用和内存碎片，提高小对象分配速度。需要注意：对象释放后内存可能回到 Python 内部内存池，不一定立刻还给操作系统，所以进程 RSS 不一定马上下降。

## 5. GIL 与内存管理的关系

CPython 的引用计数更新非常频繁。GIL 让同一时刻只有一个线程执行 Python 字节码，简化了引用计数和解释器内部对象状态的并发保护。

但要注意：

1. GIL 不等于业务线程安全，复合操作仍然需要锁。
2. CPU 密集型 Python 多线程不能充分利用多核。
3. I/O 阻塞和部分 C 扩展计算期间可能释放 GIL。
4. C 扩展释放 GIL 后，扩展内部必须自己保证线程安全。

## 6. 真实场景建议

1. 大量队头出队用 `deque`，不要用 `list.pop(0)`。
2. 大量字符串拼接用 `''.join(parts)` 或 `io.StringIO`。
3. 大文件处理用生成器和迭代器流式读取，避免一次性加载。
4. 需要统计 TopK 用 `heapq` 或 `collections.Counter`。
5. 内存异常时用 `tracemalloc`、`objgraph`、`gc.get_objects()` 辅助定位。

## 7. 面试回答模板

Python 常用容器里，list 是动态数组，dict/set 是哈希表，deque 适合双端队列，heapq 适合优先队列。CPython 内存管理主要靠引用计数，对象引用数归零会立即释放；循环引用由分代 GC 处理；小对象分配由 pymalloc 内存池优化。GIL 简化了引用计数和解释器内部状态管理，但不保证业务数据线程安全。工程中要按访问模式选容器，并用生成器、内存池认知和诊断工具控制大数据脚本的内存。
