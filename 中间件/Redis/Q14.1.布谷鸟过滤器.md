# Q14.1.布谷鸟过滤器

布谷鸟过滤器（Cuckoo Filter）是一种近似集合查询结构，和布隆过滤器一样用于判断“一个元素是否可能存在于集合中”。它同样允许少量误判，但相比普通布隆过滤器，一个很重要的优势是 **天然支持删除**。

## 1. 核心思想

布谷鸟过滤器来自布谷鸟哈希（Cuckoo Hashing）。它不直接保存完整元素，而是保存元素的短指纹（fingerprint）。

整体结构可以理解为：

```text
bucket array + fingerprint
```

每个元素会对应两个候选 bucket：

```text
i1 = hash(x)
i2 = i1 xor hash(fingerprint(x))
```

插入元素时，只要两个候选 bucket 中任意一个还有空位，就把该元素的 fingerprint 放进去。如果两个 bucket 都满了，就随机踢出一个已有 fingerprint，把被踢出的 fingerprint 搬到它的另一个候选 bucket。这个过程可能继续发生，直到找到空位或达到最大踢出次数。

## 2. 查询流程

查询元素 `x` 时：

1. 计算 `fingerprint(x)`。
2. 计算两个候选 bucket：`i1` 和 `i2`。
3. 只要任意 bucket 中存在相同 fingerprint，就认为元素可能存在。
4. 如果两个 bucket 都没有该 fingerprint，则元素一定不存在。

它会误判，是因为不同元素可能拥有相同 fingerprint，并且刚好落在对应候选 bucket 中。

## 3. 插入流程

```text
1. 计算 fp = fingerprint(x)
2. 计算 i1 = hash(x)
3. 计算 i2 = i1 xor hash(fp)
4. 如果 bucket[i1] 或 bucket[i2] 有空位，直接插入 fp
5. 如果都满了，随机选择一个 bucket 踢出已有 fp
6. 被踢出的 fp 移动到自己的另一个候选 bucket
7. 重复踢出过程，直到成功或达到最大次数
```

如果达到最大踢出次数还没有插入成功，说明过滤器负载过高，需要扩容或重建。

## 4. 删除流程

布谷鸟过滤器支持删除的原因是它存了 fingerprint，而不是只把多个 bit 置为 1。

删除元素时：

1. 计算元素的 fingerprint。
2. 找到两个候选 bucket。
3. 如果 bucket 中存在该 fingerprint，删除其中一个即可。

但要注意：由于 fingerprint 可能冲突，如果删除一个其实没有插入过但被误判存在的元素，可能误删另一个元素的 fingerprint。因此工程上通常要求删除操作只对确认插入过的元素执行。

## 5. 复杂度

| 操作 | 平均复杂度 | 说明 |
| --- | --- | --- |
| 查询 | `O(1)` | 只查两个 bucket |
| 删除 | `O(1)` | 只查两个 bucket |
| 插入 | 平均 `O(1)` | 高负载时可能多次踢出 |
| 空间 | 和 fingerprint 长度、bucket 大小有关 | 误判率越低，fingerprint 越长 |

## 6. 和布隆过滤器的区别

| 对比项 | 布隆过滤器 | 布谷鸟过滤器 |
| --- | --- | --- |
| 底层结构 | bit array + 多个哈希函数 | bucket array + fingerprint |
| 插入方式 | 多个哈希位置置 1 | fingerprint 放入两个候选 bucket 之一 |
| 查询方式 | 多个 bit 都为 1 则可能存在 | 两个 bucket 中有相同 fingerprint 则可能存在 |
| 删除能力 | 普通 Bloom Filter 不支持删除 | 支持删除 fingerprint |
| 误判原因 | 多个元素共享 bit，导致 bit 全部命中 | 不同元素 fingerprint 冲突 |
| 是否漏判 | 正常情况下不会漏判 | 正常情况下不会漏判 |
| 插入失败 | 一般不会，除非容量设计不够导致误判率升高 | 负载高时可能踢出失败，需要扩容或重建 |
| 空间效率 | 低误判率下通常很优秀 | 中低误判率下常见表现很好，且支持删除 |
| 扩容 | 普通实现不方便动态扩容 | 高负载时也通常需要重建或分层扩容 |
| 适用场景 | 缓存穿透、黑名单、去重预过滤 | 需要删除的集合过滤、动态集合近似查询 |

## 7. 怎么选择？

如果集合主要是追加写，删除很少，布隆过滤器更简单，工程实现也更常见。比如缓存穿透防护、爬虫 URL 去重、黑名单预过滤，都可以优先考虑布隆过滤器。

如果集合是动态变化的，并且业务明确需要删除元素，可以考虑布谷鸟过滤器。例如会频繁加入和移除的在线设备集合、短生命周期 token 集合、动态风控名单等。

## 8. 面试回答模板

布谷鸟过滤器和布隆过滤器都是近似集合查询结构，都能回答“元素是否可能存在”，并且都有误判但正常情况下不会漏判。区别在于布隆过滤器底层是 bit array，通过多个哈希函数把 bit 置 1；布谷鸟过滤器底层是 bucket array，保存元素的短 fingerprint，每个元素有两个候选 bucket。

布谷鸟过滤器查询时只需要检查两个 bucket 中是否有相同 fingerprint；插入时如果两个 bucket 满了，会通过布谷鸟哈希的踢出机制把已有 fingerprint 挪到另一个候选位置。它最大的优势是支持删除，因为删除时可以从候选 bucket 中移除 fingerprint。而普通布隆过滤器不能删除，因为一个 bit 可能被多个元素共享，直接清零会导致其他元素被漏判。
