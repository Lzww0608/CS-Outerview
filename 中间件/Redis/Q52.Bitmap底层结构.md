# Q52.Redis Bitmap 的底层结构

Redis 的 Bitmap 不是一种独立的数据类型，而是基于 **String** 实现的一种位操作视图。也就是说，Bitmap 的物理存储本质上还是 Redis 字符串对象，字符串底层由 SDS 保存一段连续的字节数组。

## 1. 物理结构

可以把 Redis Bitmap 理解为：

```text
redisObject -> SDS -> buf[] 连续字节数组
```

每个字节有 8 个 bit，Redis 通过 bit offset 定位到具体字节和具体 bit：

```text
byteIndex = offset / 8
bitIndex  = offset % 8
```

需要注意的是，Redis 的 `GETBIT` / `SETBIT` 中，offset 是从字符串第一个字节的高位开始数的，也就是一个字节内按从高位到低位的顺序定位。

```text
offset:    0 1 2 3 4 5 6 7
byte bit:  7 6 5 4 3 2 1 0
```

所以 Redis Bitmap 的核心不是“数组里每个元素存一个 bool”，而是把大量布尔状态压缩到连续二进制字符串里。

## 2. 空间复杂度

如果最大 offset 是 `n`，Bitmap 至少需要：

```text
ceil((n + 1) / 8) bytes
```

例如记录 1 亿个用户当天是否活跃，大约需要：

```text
100000000 / 8 = 12.5MB
```

这也是 Bitmap 适合做签到、在线状态、活跃用户标记的原因。

## 3. 常见命令复杂度

| 命令 | 作用 | 复杂度 |
| --- | --- | --- |
| `SETBIT key offset value` | 设置某一位 | `O(1)`，但扩容字符串时和新长度有关 |
| `GETBIT key offset` | 读取某一位 | `O(1)` |
| `BITCOUNT key` | 统计 1 的数量 | `O(N)`，N 是字节数 |
| `BITOP` | 多个 Bitmap 做 AND/OR/XOR/NOT | `O(N)`，N 是最长字符串长度 |
| `BITPOS` | 查找第一个 0 或 1 | 最坏 `O(N)` |

## 4. 面试回答模板

Redis Bitmap 底层就是 String，也就是 SDS 维护的一段连续字节数组。Redis 把这段字节数组按 bit 视角暴露出来，通过 offset 定位到第几个字节和字节内第几个 bit。它的优势是空间利用率极高，一个状态只占 1 bit，所以适合签到、日活、布隆过滤器位图这类大规模布尔标记场景。

需要注意两点：

1. Bitmap 本质是字符串，最大长度受 Redis String 限制。
2. `SETBIT` 如果直接设置很大的 offset，会导致 Redis 分配从 0 到该 offset 所需的整段字符串空间，可能造成内存突增。
