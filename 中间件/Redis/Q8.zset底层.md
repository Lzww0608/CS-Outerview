# Q8.zset底层

Redis的有序集合（Zset）是一种既可以看作是Set，又可以看作是Hash的数据结构，其底层实现主要使用了哈希表和跳跃表。

1. **哈希表**：在Redis的Zset中，每个元素是唯一的，同时与每个元素关联的还有一个分数（Score）。元素的唯一性保证可以由哈希表来实现。即Redis的Zset将元素作为哈希表的键，将对应的分数作为哈希表的值。
2. **跳跃表**：Redis的Zset还需要依据分数来对元素进行排序，这个特性是通过跳跃表来实现的。跳跃表是一种可以进行快速查找的数据结构。由于跳跃表的特性，对于分数的查找、插入、删除都具有较好的时间复杂度。

所以，Zset的基本形状就是：哈希表确保了成员的唯一性和查找的速度，跳跃表确保了有序性以及区间查找。

## 1. 编码方式

Redis zset 不是永远都用跳表。为了节省内存，小 zset 会使用紧凑编码：

1. Redis 早期使用 `ziplist`。
2. Redis 7.0 之后逐步使用 `listpack` 替代 `ziplist`。
3. 当元素数量或元素长度超过阈值后，会转成 `skiplist + dict`。

可以通过配置项理解阈值思想：

```text
zset-max-listpack-entries
zset-max-listpack-value
```

紧凑编码适合元素少、成员短的场景，内存占用低，但查找和插入需要线性扫描或移动内存；跳表编码适合数据量大、需要频繁范围查询和排名的场景。

## 2. 跳表 + 字典如何配合

跳表编码下，zset 同时维护两份结构：

1. **dict**：`member -> score`，用于 `ZSCORE`、判断成员是否存在、按成员更新分数，平均 `O(1)`。
2. **skiplist**：按 `(score, member)` 排序，用于 `ZRANGE`、`ZRANK`、`ZREVRANGE`、按分数范围查询，平均 `O(log n)`。

为什么排序键是 `(score, member)`：

1. score 相同时需要稳定的确定性顺序。
2. member 作为 tie-breaker 可以保证跳表中每个节点排序唯一。

跳表节点通常包含：

1. member 和 score。
2. 多层 forward 指针。
3. 每层 span，用于快速计算 rank。
4. backward 指针，便于反向遍历。

## 3. 常见操作复杂度

| 操作 | 复杂度 | 说明 |
| --- | --- | --- |
| `ZADD` | `O(log n)` | dict 查成员，skiplist 插入或更新 |
| `ZSCORE` | `O(1)` | dict 查分数 |
| `ZRANK` | `O(log n)` | 利用 skiplist span 计算排名 |
| `ZRANGE` | `O(log n + m)` | 定位起点后顺序取 `m` 个 |
| `ZREM` | `O(log n)` | dict 和 skiplist 都要删除 |

## 4. 为什么不用红黑树

Redis 选择跳表主要是工程取舍：

1. 跳表实现比红黑树简单，插入删除不需要复杂旋转。
2. 范围遍历天然方便，沿底层链表向后走即可。
3. 通过 span 很容易支持 rank 查询。
4. 随机层数带来期望 `O(log n)`，性能足够稳定。

红黑树也能完成有序集合，但实现 rank、范围遍历和维护代码复杂度更高。

## 5. 面试回答模板

Redis zset 底层小数据量时用 listpack/ziplist 这类紧凑编码节省内存；超过阈值后用 dict + skiplist。dict 保存 member 到 score 的映射，保证按成员查找和更新是平均 `O(1)`；skiplist 按 score 和 member 排序，支持范围查询、排名和顺序遍历，`ZADD/ZREM/ZRANK` 通常是 `O(log n)`，`ZRANGE` 是 `O(log n + m)`。Redis 用跳表而不是红黑树，主要是实现简单、范围遍历方便，并且 span 能高效支持排名。

## 6. zset 的真实应用场景

zset 适合“唯一成员 + 可排序分数”的模型，既能按 member 快速查分，又能按 score 做范围和排名。

常见场景：

1. **排行榜**：member 是玩家 ID，score 是积分、战力或通关时间。`ZREVRANGE` 查 Top N，`ZREVRANK` 查个人排名，`ZINCRBY` 增加分数。
2. **延迟队列**：member 是任务 ID，score 是执行时间戳。消费者用 `ZRANGEBYSCORE queue -inf now LIMIT 0 n` 取到期任务，再用 `ZREM` 抢占删除。
3. **滑动窗口限流**：member 是请求唯一 ID，score 是请求时间戳。先删除窗口外数据，再统计窗口内数量。
4. **时间线/最近活跃**：score 是时间戳，按时间倒序取最近事件。
5. **权重调度**：score 表示优先级、负载或下一次调度时间。

注意事项：

1. score 是 double，整数精确范围有限；需要精确大整数排序时要控制数值范围，或把 tie-breaker 放进 member。
2. score 相同按 member 字典序排序，所以排行榜要明确同分规则。
3. 大 key 的 zset 会带来内存和单线程阻塞风险，删除、范围查询、迁移时要控制批量大小。
4. 延迟队列用 zset 时，取任务和删除任务要考虑并发抢占，可以用 Lua 保证“查到期任务 + 删除”原子性。
5. zset 不是关系数据库索引，复杂多条件排序过滤应考虑冗余多个 zset、搜索引擎或数据库索引。
