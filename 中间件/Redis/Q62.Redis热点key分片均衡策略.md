# Redis 热点 key 分片均衡策略

## 1. 问题背景

在 Redis 分片场景中，热点 key（如热门商品）会导致流量集中打在单个实例上，造成负载不均和性能瓶颈。

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  问题描述：                                                │
│                                                             │
│  • 100 万商品，10 个 Redis 实例                         │
│  • 热门商品（如秒杀品）访问量占 80%                     │
│  • 所有热门商品可能分片到同一实例                        │
│  • 导致单实例过载，其他实例闲置                          │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 2. 问题现象

| 现象 | 描述 | 影响 |
|------|------|------|
| 单实例热点 | 热门 key 集中在某实例 | 实例过载 |
| 请求不均 | 流量分布严重倾斜 | 资源浪费 |
| 响应延迟 | 热点实例响应慢 | 用户体验下降 |
| 实例崩溃 | 热点实例 OOM | 服务不可用 |

## 5. 解决方案

### 5.1 哈希标签 + 虚拟节点

```python
# 方案1：哈希标签 + 随机后缀

def hash_tag_sharding(key, num_nodes=10):
    """
    哈希标签：确保 key 中特定部分参与哈希
    随机后缀：将热点 key 分散到不同实例
    """
    # 格式：{tag}:key:random_suffix
    if ":" in key:
        tag = key.split(":")[0]  # 取标签部分
    else:
        tag = key
    
    # 添加随机后缀分散热点
    suffix = random.randint(0, num_nodes * 10 - 1)
    new_key = f"{tag}:{key}:{suffix}"
    
    slot = crc16(new_key) % 16384
    return slot % num_nodes

# 使用：
# product:hot_123456:0 -> node_3
# product:hot_123456:5 -> node_7  # 分散到不同节点
```

### 5.2 本地缓存 + Redis

```python
# 方案2：热点数据本地缓存

import redis
import threading
from collections import OrderedDict

class HotDataCache:
    def __init__(self, redis_client, local_cache_size=1000):
        self.redis = redis_client
        self.local_cache = OrderedDict()
        self.local_cache_size = local_cache_size
        self.lock = threading.Lock()
    
    def get(self, key):
        """先查本地缓存，再查 Redis"""
        # 1. 查本地缓存
        with self.lock:
            if key in self.local_cache:
                # 移到末尾（最近使用）
                self.local_cache.move_to_end(key)
                return self.local_cache[key]
        
        # 2. 查 Redis
        value = self.redis.get(key)
        
        if value:
            # 写入本地缓存
            with self.lock:
                self.local_cache[key] = value
                if len(self.local_cache) > self.local_cache_size:
                    # 删除最旧项
                    self.local_cache.popitem(last=False)
        
        return value
    
    def invalidate(self, key):
        """删除缓存"""
        with self.lock:
            if key in self.local_cache:
                del self.local_cache[key]
        self.redis.delete(key)
```

### 5.3 读写分离 + 热点副本

```python
# 方案3：热点数据多副本分散读取

import redis

class HotDataReplication:
    def __init__(self, redis_nodes):
        self.read_nodes = redis_nodes  # 所有读节点
        self.write_node = redis_nodes[0]  # 写节点
    
    def read_hot_key(self, key):
        """从多个副本随机读取"""
        import random
        read_node = random.choice(self.read_nodes)
        return read_node.get(key)
    
    def write_hot_key(self, key, value):
        """写入所有副本"""
        for node in self.read_nodes:
            node.set(key, value)
    
    def setup_hot_replication(self, hot_keys, num_copies=3):
        """为热点 key 设置多副本"""
        for key in hot_keys:
            value = self.write_node.get(key)
            for i in range(num_copies):
                replica_key = f"{key}__replica_{i}__"
                self.write_node.set(replica_key, value)
        
        return [f"{key}__replica_{i}__" for i in range(num_copies)]
```

### 5.4 热点 key 自动识别 + 打散

```python
# 方案4：热点自动识别 + 动态打散

import redis
import threading
import time
from collections import Counter

class HotKeyAutoSharding:
    def __init__(self, redis_nodes):
        self.redis_nodes = redis_nodes
        self.access_counter = Counter()
        self.hot_keys = set()
        self.lock = threading.Lock()
        
        # 启动热点检测线程
        self.monitor_thread = threading.Thread(
            target=self._monitor_loop,
            daemon=True
        )
        self.monitor_thread.start()
    
    def get(self, key):
        """访问时记录"""
        # 记录访问
        with self.lock:
            self.access_counter[key] += 1
        
        # 尝试从原始 key 或副本读取
        if key in self.hot_keys:
            # 从副本读取
            replica_key = f"{key}:{hash(key) % 10}"
            return self._get_from_node(replica_key)
        else:
            return self._get_from_node(key)
    
    def _monitor_loop(self):
        """热点检测循环"""
        while True:
            time.sleep(10)  # 每 10 秒检测
            
            with self.lock:
                # 找出访问量超过阈值的 key
                threshold = 10000  # 可调整
                current_hot = {
                    k for k, v in self.access_counter.items() 
                    if v > threshold
                }
                
                # 新增热点
                new_hot = current_hot - self.hot_keys
                for key in new_hot:
                    self._setup_replicas(key)
                
                # 更新热点集合
                self.hot_keys = current_hot
                self.access_counter.clear()
    
    def _setup_replicas(self, key):
        """为热点 key 设置副本"""
        value = self._get_from_node(key)
        num_replicas = 10
        
        for i in range(num_replicas):
            replica_key = f"{key}:{i}"
            self._set_to_node(replica_key, value)
```

## 6. 可选方案对比

### 6.1 方案对比表

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| 随机后缀 | 哈希打散 | 简单 | 可能破坏相关性 |
| 本地缓存 | 多级缓存 | 减少 Redis 压力 | 数据一致性难 |
| 多副本 | 读分散 | 读取能力线性扩展 | 内存占用高 |
| 自动识别 | 热点检测+动态副本 | 智能 | 实现复杂 |

### 6.2 适用场景

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  方案选择：                                                │
│                                                             │
│  • 热点 key 已知 ──► 随机后缀 / 多副本                  │
│  • 热点 key 未知 ──► 本地缓存 / 自动识别                  │
│  • 读多写少 ──► 多副本 / 本地缓存                        │
│  • 写多读少 ──► 本地缓存（注意一致性）                  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

# Redis 热点 key 监控
import redis
from collections import Counter

def detect_hot_keys(redis_client, time_window=60):
    """监控热点 key"""
    counter = Counter()
    
    # 使用 MONITOR 抓取命令（生产环境慎用）
    with redis_client.monitor() as m:
        start = time.time()
        while time.time() - start < time_window:
            cmd = m.listen()
            if 'GET' in str(cmd):
                key = extract_key(cmd)
                counter[key] += 1
    
    # 返回 Top N 热点
    return counter.most_common(100)

## 9. 风险与注意事项

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 本地缓存一致性 | 数据过期不一致 | 合理 TTL，主动失效 |
| 多副本内存占用 | 内存浪费 | 控制副本数量 |
| 随机后缀破坏相关 | 无法批量操作 | 按需使用 |

## 11. 总结

1. **问题根因**：标准分片按 key 哈希，不考虑流量分布
2. **解决方案**：随机后缀、本地缓存、多副本、自动识别
3. **推荐组合**：本地缓存 + Redis 多副本 + 热点自动识别
4. **效果**：热点流量分散到多个实例，负载均衡
5. **注意**：一致性、内存占用、监控开销
