# Q2.关系型与非关系型数据库

关系型数据库（RDBMS）和非关系型数据库（NoSQL）在数据存储和处理方面存在着一些区别。



1. **数据结构**：关系型数据库使用表格结构（二维表）来组织数据，并且表格之间可以建立关系，即通过外键进行关联。而非关系型数据库采用不同的数据模型，如键值对、文档、列族、图等，没有固定的结构。
2. **扩展性**：关系型数据库在处理海量数据时可能会面临性能瓶颈。而非关系型数据库设计用于处理大规模、高并发的数据，能够更好地水平扩展，可以通过添加更多的节点来提高系统的处理能力。
3. **灵活性**：关系型数据库需要在设计阶段定义表结构，并且需要遵循预设的模式。一旦定义后，数据的修改可能会变得复杂。而非关系型数据库更加灵活，可以随着应用需求的变化进行数据结构的调整和扩展。
4. **事务支持**：**关系型数据库支持事务，可以保证数据的一致性和可靠性**。非关系型数据库根据不同的类型和实现方式，事务支持程度可能有所不同。
5. **查询语言**：关系型数据库使用结构化查询语言SQL来查询和操作数据。非关系型数据库则使用不同的查询语言或接口，如键值对数据库使用键来访问值，文档数据库使用类似JSON的查询语法。

## NoSQL 的优点

1. **水平扩展能力强**：很多 NoSQL 从设计上就支持分片、副本和自动扩容。
2. **数据模型灵活**：文档、KV、列族、图模型可以贴近业务访问模式。
3. **高吞吐读写**：弱化复杂事务和 join 后，单条读写链路更短。
4. **适合海量数据**：日志、消息、Feed、关系边、时序指标等数据可以按 key 或时间分布到多节点。
5. **可用性优先**：部分系统在 CAP 取舍上更偏 AP，允许短暂最终一致来换高可用。

## NoSQL 的缺点

1. **事务能力弱或范围有限**：跨 key、跨分片事务通常成本高或不支持。
2. **复杂查询弱**：join、多条件过滤、临时聚合不如关系型数据库自然。
3. **一致性模型复杂**：读写可能有副本延迟，需要业务理解最终一致。
4. **数据冗余多**：为了读性能常按查询模式反复存多份数据。
5. **迁移和运维成本**：分片、压缩、修复、热点、容量规划都需要额外治理。

## 怎么选型

| 类型 | 代表 | 适合场景 |
| --- | --- | --- |
| KV | Redis、DynamoDB | 缓存、会话、计数、简单 key 查询 |
| 文档 | MongoDB | 半结构化文档、内容管理、灵活 schema |
| 列族/宽表 | HBase、Cassandra | 海量写入、时间序列、关系边、消息历史 |
| 图数据库 | Neo4j、JanusGraph | 多跳关系、共同好友、路径查询、风控图谱 |
| 搜索引擎 | Elasticsearch | 关键词检索、多条件过滤、日志检索 |

微博好友或关注关系这类场景，如果是在线关注/取关和关系查询，权威源可以用 MySQL 分库分表或 HBase/Cassandra 这类宽表；Redis 做关注状态、计数和热点列表缓存；图数据库更适合共同关注、推荐和风控等多跳分析，不一定作为高并发在线主库。

注：关系型数据库和非关系型数据库并没有绝对的优劣之分，而是根据应用场景和需求选择适当的数据库类型。关系型数据库适用于复杂的事务处理，非关系型数据库则适用于需要高可扩展性和灵活性的大数据处理。
