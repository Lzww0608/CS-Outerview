# Q19.过期键删除策略

Redis 使用过期键的删除策略来自动清除已经过期的键，以释放内存空间。过期删除和内存淘汰不是一回事：过期删除处理已经设置 TTL 的 key，内存淘汰是在 `maxmemory` 达到上限后按 `maxmemory-policy` 选择数据淘汰。

常见的过期删除策略包括：

1. **定期删除策略（定时删除）**：Redis会在每个指定的时间间隔（由配置参数`hz`决定）内，检查一批键是否过期，然后删除过期的键。这种策略不会频繁地检查每个键是否过期，因此对CPU的消耗较少。
2. **惰性删除策略（懒汉式删除）**：当访问某个键时，Redis会先检查该键是否过期，如果过期则立即删除。这种策略相对更加高效，因为它只会在需要时才进行检查和删除操作。
3. **定期删除与惰性删除的结合**：Redis同时使用了定期删除和惰性删除两种策略，在有限的时间间隔内通过定期删除来批量清除过期键，同时在读写操作中使用惰性删除来保证及时的清理。

需要注意的是，无论采用哪种删除策略，Redis并不是立即清除过期键，而是通过在查询和写入操作时进行过期键的检查和删除。因此，在过期时间到达之后，过期键可能仍然存在一段时间，直到Redis执行删除操作。如果需要确保即时删除过期键，可以使用`DEL`命令主动删除过期键。

同时，可以通过配置参数`maxmemory`来限制 Redis 使用的内存大小，当达到内存限制时，Redis 会根据 `maxmemory-policy` 淘汰一些数据以释放内存空间。

## SET NX EX 中 EX 的实现

`SET key value NX EX 30` 可以拆成两个语义：

1. `NX`：只有 key 不存在时才写入。
2. `EX 30`：写入成功后给 key 设置 30 秒过期时间。

Redis 内部不是把过期时间直接塞进 value，而是维护两张核心字典：

1. **主字典**：保存 `key -> value`。
2. **过期字典**：保存 `key -> expireAt`，`expireAt` 是绝对过期时间戳，通常按毫秒精度存储。

执行 `SET key value NX EX 30` 时，Redis 会在一次命令执行中完成以下动作：

1. 在主字典中判断 key 是否存在。
2. 如果 key 已存在，`NX` 条件不满足，命令返回空，不写 value，也不设置 TTL。
3. 如果 key 不存在，写入主字典。
4. 根据当前时间计算绝对过期时间 `now + 30s`，写入过期字典。
5. 返回 `OK`。

因此 `SET NX EX` 是原子命令，比先 `SETNX` 再 `EXPIRE` 更安全。后者在两条命令中间如果客户端宕机，可能留下一个永不过期的锁 key。

## 过期 key 什么时候真正删除

`EX` 设置的是逻辑过期时间，不代表到点一定立刻从内存中消失。Redis 主要通过两种方式删除过期 key：

1. **惰性删除**：访问 key 时先检查过期字典，如果已经过期，先删除再返回不存在。
2. **定期删除**：后台周期性抽样检查带 TTL 的 key，删除已经过期的部分 key。

这种设计是 CPU 和内存之间的折中。如果每个 key 都创建独立定时器，过期精度更高，但定时器管理成本会很大；如果完全惰性删除，冷 key 过期后长期不被访问，会继续占内存。

## 面试易错点

1. `EX` 不是另起线程睡眠 30 秒后删除 key，而是记录过期时间，再由惰性删除和定期删除配合清理。
2. Redis 的过期时间通常以绝对时间戳持久化，RDB 载入时会判断是否已经过期。
3. 主从复制下，通常由主节点产生过期删除，再把删除同步给从节点，避免主从因本地时钟差异出现明显不一致。
4. `EX` 单位是秒，`PX` 单位是毫秒；`EXAT`、`PXAT` 则直接设置绝对过期时间。
