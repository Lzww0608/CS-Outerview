# Q13.缓存击穿

缓存击穿是指当缓存中没有某个key的数据，这当然会导致缓存无法命中，然后请求就会穿透缓存层，直接访问数据库。如果这个不命中的请求不止一个，而是成千上万个同时发生，那么就会对数据库形成巨大的访问压力，可能会导致数据库访问瞬间崩溃。

最常见的缓存击穿场景就是有大量请求同时查询一个热点key，但是此时缓存中该key的数据刚好过期，于是大量的请求就会直接穿透到数据库。

针对缓存击穿问题，常见的解决方案有：

1. **设置热点数据永不过期**：这种方法适用于某些更新不频繁但是访问非常频繁的热点数据。
2. **缓存数据过期时间设置随机**，防止同一时间大量数据过期现象发生。
3. **使用互斥锁（Mutex key）**：对于同一个key，只允许一个线程去加载数据，其他线程等待加载完成直接使用即可。
4. **服务降级与熔断**：如果数据库压力过大，可以暂时拒绝部分请求，让系统在承受的压力范围内运行。

## singleflight 请求合并

`singleflight` 是 Go 生态里常见的请求合并机制，核心思想是：同一个 key 的并发加载只让一个执行者真正回源，其余请求等待这个执行者的结果。

```text
1000 个请求同时 miss user:1
  -> 第 1 个请求查数据库
  -> 其余 999 个请求挂到同一个 in-flight 调用上
  -> 第 1 个请求回填缓存并返回
  -> 999 个请求复用同一份结果
```

它和分布式锁的区别：

1. `singleflight` 通常是**进程内**合并，成本低，不依赖 Redis。
2. 分布式锁可以跨多实例互斥，但引入网络开销、锁超时、续期和误删问题。
3. 高并发热点 key 可以组合使用：本地 singleflight 减少单实例内回源，必要时再用 Redis 锁控制跨实例回源。

易错点：

1. singleflight 只合并“正在进行的同 key 请求”，不等于缓存。
2. 回源失败时不要让所有等待者无限重试，可以短暂缓存错误、限流或降级。
3. 对超热点数据，更推荐逻辑过期 + 后台刷新，让用户请求尽量不阻塞在回源上。

面试回答可以说：缓存击穿的本质是热点 key 失效后并发回源，解决思路是让回源变成单飞。单机内用 singleflight 或互斥加载，集群内可以用分布式锁或逻辑过期；热点数据还可以预热、永不过期加异步刷新，并配合限流熔断保护数据库。
