# Q7.常见数据类型

- **1. string 字符串**

字符串类型是 Redis 最基础的数据结构，首先键是字符串类型，而且其他几种结构都是在字符串类型基础上构建的。字符串类型实际上可以是字符串：简单的字符串、XML、JSON；数字：整数、浮点数；二进制：图片、音频、视频。

使用场景：缓存、计数器、共享 Session、限速。

### 缓存富文本和 Emoji 要注意什么

Redis 的 String 是二进制安全的，value 里可以放普通文本、HTML 富文本、JSON、图片二进制，也可以放 Emoji。真正需要注意的不是 Redis 能不能存，而是编码、序列化和展示安全：

1. **统一 UTF-8**：Emoji 通常是多字节 Unicode 字符，业务服务、数据库、Redis 客户端和前端都要统一 UTF-8，避免乱码或截断。
2. **不要按字节截断字符串**：如果按字节长度截断，可能把一个多字节字符切坏。应按 Unicode code point 或更严格的 grapheme cluster 处理。
3. **富文本要做安全过滤**：缓存 HTML 前后都要考虑 XSS，不能因为“数据来自缓存”就跳过消毒。
4. **序列化格式要稳定**：常见是 JSON、MessagePack、Protobuf 或压缩后的二进制。JSON 便于排查，二进制格式更省空间。
5. **大 value 要拆分或压缩**：富文本可能很大，单个大 key 会影响网络传输、复制、持久化和删除延迟。

面试里可以说：Redis String 可以缓存富文本和 Emoji，因为它是二进制安全的；但工程上要统一 UTF-8、避免按字节截断、过滤 XSS、控制 value 大小，并明确序列化格式。

- **2. Hash（哈希）**

在 Redis中哈希类型是指键本身是一种键值对结构，如 value={{field1,value1},……{fieldN,valueN}}

使用场景：哈希结构相对于字符串序列化缓存信息更加直观，并且在更新操作上更加便捷。所以常常用于用户信息等管理，但是哈希类型和关系型数据库有所不同，哈希类型是稀疏的，而关系型数据库是完全结构化的，关系型数据库可以做复杂的关系查询，而 Redis 去模拟关系型复杂查询开发困难且维护成本高。

- **3. List（列表）**

列表类型是用来储存多个有序的字符串，列表中的每个字符串成为元素，一个列表最多可以储存 2 ^ 32 – 1 个元素，在 Redis 中，可以队列表两端插入和弹出，还可以获取指定范围的元素列表、获取指定索引下的元素等，列表是一种比较灵活的数据结构，它可以充当栈和队列的角色。

使用场景：Redis 的 lpush + brpop 命令组合即可实现阻塞队列，生产者客户端是用 lpush 从列表左侧插入元素，多个消费者客户端使用 brpop 命令阻塞式的“抢”列表尾部的元素，多个客户端保证了消费的负载均衡和高可用性。

- **4. Set（集合）**

集合类型也是用来保存多个字符串的元素，但和列表不同的是集合中不允许有重复的元素，并且集合中的元素是无序的，不能通过索引下标获取元素，Redis 除了支持集合内的增删改查，同时还支持多个集合取交集、并集、差集。合理的使用好集合类型，能在实际开发中解决很多实际问题。

使用场景：如：一个用户对娱乐、体育比较感兴趣，另一个可能对新闻感兴趣，这些兴趣就是标签，有了这些数据就可以得到同一标签的人，以及用户的共同爱好的标签，这些数据对于用户体验以及曾强用户粘度比较重要。

- **5. zset（sorted set：有序集合）**

有序集合和集合有着必然的联系，它保留了集合不能有重复成员的特性，但不同得是，有序集合中的元素是可以排序的，但是它和列表的使用索引下标作为排序依据不同的是：它给每个元素设置一个分数，作为排序的依据。

使用场景：排行榜是有序集合经典的使用场景。例如：视频网站需要对用户上传的文件做排行榜，榜单维护可能是多方面：按照时间、按照播放量、按照获得的赞数等。

## 底层编码总览

Redis 对外暴露的是数据类型，对内会根据元素数量、元素大小和操作特征选择不同编码。这样做的目的不是让类型变复杂，而是在小数据量时节省内存，在数据变大后保证操作效率。

| 数据类型 | 常见底层编码 | 核心特点 |
| --- | --- | --- |
| String | `int`、`embstr`、`raw`，底层是 SDS | 二进制安全，支持计数器、位图、缓存值 |
| List | quicklist/listpack | 两端 push/pop 高效，兼顾链表操作和内存紧凑性 |
| Hash | listpack、hashtable | 小对象用紧凑编码，大对象转哈希表 |
| Set | intset、hashtable | 全整数小集合可用 intset，普通集合用哈希表 |
| ZSet | listpack、skiplist + dict | 小集合紧凑存储，大集合用跳表按分数排序，同时用 dict 做成员查找 |
| Bitmap | String | 本质是字符串上的位操作 |
| HyperLogLog | 稀疏/稠密结构 | 近似基数统计，牺牲少量精度换固定空间 |
| Stream | radix tree + listpack | 适合消息流、消费组和按 ID 范围读取 |

面试里要能说清楚“类型”和“编码”不是一回事。例如 ZSet 作为类型支持按 score 排序和范围查询；当数据量小的时候可能用 listpack 节省内存，当数据量变大后会转成 `dict + skiplist`，其中 dict 支持按 member `O(1)` 查 score，skiplist 支持按 score 范围查询和排名。
