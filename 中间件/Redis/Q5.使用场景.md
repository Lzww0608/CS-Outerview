# Q5.使用场景

1. 缓存：Redis最常见的使用场景是作为内存型键值存储来构建缓存。由于Redis的性能非常高，可以处理大量的读写操作，因此非常适合用于缓存场景。

   例如，可以缓存从数据库查询出来的数据，后面再需要这些数据时，可以直接从Redis中读取，而不需要再次进行数据库查询，从而提高性能。

2. 消息队列系统：Redis也可以作为消息队列使用。其PUB/SUB模型可以用来创建实时的消息系统。

   例如，一个电商网站，用户下订单后，可以把订单任务放入Redis的消息队列，然后有专门的工作线程负责处理这些订单任务。

3. 计数器：Redis可以非常方便地实现计数器功能。比如用来记录网站的点击次数，或者用户的行为次数。

   例如，社交网络网站可以用Redis来记录用户发布的消息数量，或者用户被赞的次数。

4. 实时系统：由于Redis的高性能特性，也经常被用于构建实时系统。比如实时统计用户的行为、游戏的实时排行榜等。

   例如，一个在线游戏，可以使用Redis来存储用户的分数，然后使用Redis的排序功能，实时生成用户的排行榜。

5. 分布式锁：使用 `SET key value NX PX timeout` 可以实现基础互斥，适合控制定时任务、库存扣减入口、缓存重建等场景。生产环境要注意锁过期、续期、误删和主从切换问题。

6. 限流和频控：用 `INCR + EXPIRE`、滑动窗口、令牌桶或 Lua 脚本实现接口限流、短信验证码频控、登录失败次数限制。

7. 会话和临时状态：存储 session、登录态、验证码、短期 token、幂等 key 等带过期时间的数据。

8. 位图和签到：Bitmap 适合用户签到、活跃统计、布尔标签等大量二值状态；HyperLogLog 适合 UV 估算；GEO 适合附近位置查询。

## 游戏服务端中的 Redis 场景

游戏服务端使用 Redis 时，通常看重低延迟、原子操作和带过期时间的数据结构：

1. **玩家会话和在线状态**：保存玩家所在网关、房间、最后心跳时间，配合过期时间处理掉线。
2. **排行榜**：用 ZSet 维护战力榜、积分榜、活动榜，按 score 排序和分页。
3. **限流和防刷**：验证码、登录失败、拍卖行秒杀、接口频控可以用计数器或 Lua。
4. **临时状态和冷却时间**：技能 CD、活动参与状态、短期幂等 key 可设置 TTL。
5. **分布式锁或资格抢占**：活动奖励、限量商品、拍卖成交可用 `SET NX PX` 或 Lua 做原子控制。
6. **缓存热点配置和玩家摘要**：降低数据库读压力，但资产变化仍要以数据库或权威服务为准。
7. **Pub/Sub 或 Stream**：用于轻量通知、跨服广播、异步事件，但关键资产消息要考虑可靠投递和补偿。

注意：Redis 不能替代数据库事务。货币、道具、拍卖成交这类资产数据要有幂等、落库和补偿机制，不能只把 Redis 当最终账本。

面试里回答“项目中 Redis 用来干什么”时，最好结合业务说清楚：缓存什么 key、TTL 怎么设置、如何保证和数据库一致、缓存异常时怎么降级，以及热点 key 和雪崩怎么处理。
