# 19.RabbitMQ交换机与队列

在RabbitMQ中，交换机（Exchange）和队列（Queue）是消息传递过程中的两个不同实体。它们的主要区别和配置方法如下：

1. **交换机（Exchange）**：交换机是消息路由的中枢，它决定了消息从生产者发送到哪些队列。交换机有不同的类型，比如直接（Direct）、主题（Topic）、扇出（Fanout）和头部（Headers），每种类型根据消息属性、路由键或其他标准来路由消息。
2. **队列（Queue）**：队列是存储消息的缓冲区。消费者从队列中获取消息并处理。在RabbitMQ中，消息总是先发送到交换机，然后由交换机路由到一个或多个队列。

以下是使用Java代码进行交换机和队列配置的一个简单示例，使用了`RabbitMQ`的Java客户端库：

```java
import com.rabbitmq.client.Channel;
import com.rabbitmq.client.Connection;
import com.rabbitmq.client.ConnectionFactory;

public class RabbitMQExample {
    private static final String EXCHANGE_NAME = "test_exchange";
    private static final String QUEUE_NAME = "test_queue";
    private static final String ROUTING_KEY = "test_routing_key";

    public static void main(String[] argv) throws Exception {
        ConnectionFactory factory = new ConnectionFactory();
        factory.setHost("localhost");
        try (Connection connection = factory.newConnection();
             Channel channel = connection.createChannel()) {

            // 声明一个交换机
            channel.exchangeDeclare(EXCHANGE_NAME, "direct");

            // 声明一个队列
            channel.queueDeclare(QUEUE_NAME, false, false, false, null);

            // 将队列绑定到交换机
            channel.queueBind(QUEUE_NAME, EXCHANGE_NAME, ROUTING_KEY);
        }
    }
}
```

在这段代码中，我们创建了一个名为`test_exchange`的直接交换机，一个名为`test_queue`的队列，并使用一个路由键`test_routing_key`将它们绑定起来。这样，发送到交换机的、路由键匹配的消息就会被路由到队列中。

实际应用中，你可能需要设置更复杂的路由规则、交换机属性（如持久化）、队列属性（如持久化、排他性、自动删除等）以及更多的安全和性能相关配置。这些设置需要根据应用的具体需求来调整。

## RabbitMQ 队列是怎么实现的

RabbitMQ 的核心链路是：

```text
Producer -> Exchange -> Binding -> Queue -> Consumer
```

交换机只负责路由，一般不保存消息；队列才是消息暂存、顺序读取、确认删除和持久化的主体。生产者把消息发布到交换机，交换机根据 binding 和 routing key 找到目标队列，队列再把消息投递给消费者。消费者处理完成后发送 `ack`，RabbitMQ 才能安全删除这条消息；如果消费者异常断开且没有确认，消息会被重新入队。

常见队列实现可以从三个层面理解：

1. **内存结构**：队列维护待投递消息、未确认消息和消费者状态。消息进入队列后先在内存中参与投递，消费者的 `prefetch` 会限制同一消费者最多同时拿到多少未确认消息，避免单个消费者被压垮。
2. **磁盘持久化**：队列和消息都声明持久化时，消息会写入磁盘日志或消息存储文件。持久化队列只说明队列元数据可恢复，消息本身还需要生产者发布时设置 persistent。
3. **复制高可用**：经典队列可以单副本或镜像部署；新版本更推荐 quorum queue，它基于 Raft 日志复制，队列有 leader 和 followers，写入先进入复制日志，再由 leader 对外提供投递。

经典队列适合普通异步削峰、任务队列和短暂堆积；quorum queue 更适合对数据安全要求高、希望故障切换语义更清晰的场景。代价是 quorum queue 写入路径更长，吞吐和磁盘压力通常比单副本经典队列更重。

## 队列实现里的易错点

1. 交换机不负责持久保存消息，没有匹配队列且没有 alternate exchange 时，消息可能直接丢弃或返回给生产者。
2. 队列 durable 不等于消息 durable，消息也要设置持久化属性，并且生产者最好配合 publisher confirm。
3. 单个队列内部可以保持入队顺序，但多个消费者并发处理时，业务完成顺序不一定等于入队顺序。
4. 大量重试消息会造成 CPU 和磁盘抖动，通常要用死信队列、延迟重试、最大重试次数和幂等消费配合处理。
5. `prefetch` 太大容易造成单消费者囤积消息，太小会降低吞吐，需要结合处理耗时和消费者数量压测。

面试回答 RabbitMQ 队列实现时，可以先说交换机负责路由、队列负责存储和投递，再展开 ack、prefetch、持久化、死信队列和 quorum queue。这样既能说明逻辑模型，也能覆盖真实线上可靠性问题。
