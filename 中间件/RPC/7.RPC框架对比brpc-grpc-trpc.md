# RPC 框架对比：brpc vs gRPC vs trpc

## 一、概述

### 1.1 三大 RPC 框架定位

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  框架定位对比：                                             │
│                                                             │
│  brpc      ─── 百度自研高性能 RPC，适合 C++ 服务间通信    │
│  gRPC      ─── Google 开源，跨语言，适合多语言微服务      │
│  trpc      ─── 字节自研，无类型约束，适合 TypeScript 服务  │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

---

## 二、核心对比

### 2.1 框架特性对比

| 特性 | brpc | gRPC | trpc |
|------|------|------|------|
| 母公司 | 百度 | Google | 字节跳动 |
| 语言 | C++ | 多语言 | TypeScript/Node.js |
| 协议 | baidu_std/grpc等 | HTTP/2+gRPC | HTTP |
| IDL | protobuf | protobuf | TypeScript |
| 连接复用 | 支持 | HTTP/2多路复用 | 支持 |
| 负载均衡 | 内置 | 需配合 | 无 |
| 性能 | 极高 | 高 | 中等 |
| 适用场景 | C++ 高性能服务 | 跨语言微服务 | TypeScript 全栈 |

## 三、brpc 详解

### 3.1 brpc 架构

```text
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  brpc 核心架构：                                           │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐  │
│  │                  bvar（监控）                        │  │

│  ├─────────────────────────────────────────────────────┤  │
│  │              IO 层（epoll/kqueue/...)                │  │
│  └─────────────────────────────────────────────────────┘  │
│                                                             │
│  特点：百度内部广泛使用，支撑搜索、广告等核心业务         │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 brpc 示例

```cpp
// hello.proto
message HelloRequest {
    string name = 1;
};

message HelloResponse {
    string message = 1;
};

service HelloService {
    rpc Hello(HelloRequest) returns (HelloResponse);
};
```

```cpp
// server.cpp
#include <brpc/server.h>
#include "hello.pb.h"

class HelloServiceImpl : public HelloService {
public:
    void Hello(::google::protobuf::RpcController* controller,
               const HelloRequest* request,
               HelloResponse* response,
               ::google::protobuf::Closure* done) {
        response->set_message("Hello " + request->name());
        done->Run();
    }
};

int main() {
    brpc::Server server;
    HelloServiceImpl hello_service;
    
    server.AddService(&hello_service);
    server.Start(8080, NULL);
    server.RunUntilAskedToQuit();
}
```

### 4.2 gRPC 示例

```protobuf
// hello.proto
syntax = "proto3";

package helloworld;

service Greeter {
    rpc SayHello (HelloRequest) returns (HelloReply);
}

message HelloRequest {
    string name = 1;
}

message HelloReply {
    string message = 1;
}
```

```python
# server.py
import grpc
from concurrent import futures
import hello_pb2
import hello_pb2_grpc

class Greeter(hello_pb2_grpc.GreeterServicer):
    def SayHello(self, request, context):
        return hello_pb2.HelloReply(message=f'Hello {request.name}')

server = grpc.server(futures.ThreadPoolExecutor(max_workers=10))
hello_pb2_grpc.add_GreeterServicer_to_server(Greeter(), server)
server.add_insecure_port('[::]:50051')
server.start()
server.wait_for_termination()
```

```python
# client.py
import grpc
import hello_pb2
import hello_pb2_grpc

channel = grpc.insecure_channel('localhost:50051')
stub = hello_pb2_grpc.GreeterStub(channel)
response = stub.SayHello(hello_pb2.HelloRequest(name='World'))
print(response.message)
```

### 5.2 trpc 示例

```typescript
// server/index.ts
import { initTRPC } from '@trpc/server';
import * as trpcExpress from '@trpc/server/adapters/express';

const t = initTRPC.create();

const appRouter = t.router({
    greeting: t.procedure.query(async () => {
        return 'Hello World';
    }),
    
    user: t.router({
        getById: t.procedure
            .input(z.string())
            .query(async ({ input }) => {
                return { id: input, name: 'John' };
            }),
    }),
});

export type AppRouter = typeof appRouter;

// Express 适配器
export const createExpressHandler = () => {
    return trpcExpress.createExpressMiddleware({
        router: appRouter,
    });
};
```

```typescript
// client/index.ts
import { createTRPCProxyClient, httpBatchLink } from '@trpc/client';
import type { AppRouter } from '../server';

const client = createTRPCProxyClient<AppRouter>({
    links: [
        httpBatchLink({
            url: 'http://localhost:3000/trpc',
        }),
    ],
});

// 强类型调用
const greeting = await client.greeting.query();
const user = await client.user.getById.query('123');
```

## 八、面试常见问题

### Q1: 为什么 brpc 性能比 gRPC 高？

brpc 使用 C++ + bthread 协程 + 零拷贝 IO + 多种高效协议；gRPC 基于 HTTP/2 + C-core，跨语言代价带来一定性能损耗。

### Q2: trpc 和 gRPC 的本质区别？

trpc 不需要 IDL 定义，使用 TypeScript 直接定义 router；gRPC 必须用 .proto 文件生成代码。trpc 前后端类型共享更容易。

### Q3: 什么情况下不用 gRPC？

1. 浏览器直接调用（用 gRPC-Web 或 REST）
2. 简单 CRUD 接口（REST 更直观）
3. 团队不熟悉 Protocol Buffers

### Q4: brpc 可以在其他公司使用吗？

可以，brpc 已开源（Apache 2.0），但内部依赖（如 bvar）可能需要适配。

## 九、总结

1. **brpc**：百度自研，C++ 高性能服务，内部生态完善
2. **gRPC**：Google 开源，跨语言，Kubernetes 原生
3. **trpc**：字节自研，TypeScript 零约束，前后端类型共享
4. **选型原则**：C++ 选 brpc，多语言选 gRPC，TS 全栈选 trpc
