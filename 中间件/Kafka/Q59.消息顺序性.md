# Q59.消息顺序性

Kafka 的顺序性边界是 **单个 partition 内有序，跨 partition 不保证全局有序**。这是 Kafka 用分区换吞吐的核心取舍：分区越多，并发能力越强，但全局顺序越难保证。

## 1. Kafka 顺序性的来源

Kafka 中消息顺序性的体现主要依赖于分区、日志和 offset：

1. **分区顺序**：一个 topic 可以划分为多个 partition；同一个 partition 内的消息按追加顺序写入日志。
2. **offset 单调递增**：每条消息在 partition 内有一个递增 offset，消费者按 offset 顺序拉取。
3. **消费者组分配规则**：同一个 consumer group 内，一个 partition 同一时刻只会分配给一个 consumer 实例。
4. **顺序读写日志**：Kafka 对 partition log 追加写、顺序读，天然适合保持单分区顺序。

因此更准确的说法是：Kafka 可以保证单分区内的写入顺序和读取顺序，但不能保证多个分区之间的全局顺序。

## 2. 同一用户事件如何保证有序消费

如果希望同一个用户触发的事件有序消费，常见设计是按用户维度做分区路由：

```text
producer send(topic, key = userId, value = event)
-> Kafka partitioner: hash(userId) % partitionCount
-> 同一个 userId 的事件进入同一个 partition
-> 同一个 consumer group 内该 partition 只由一个 consumer 消费
-> consumer 按 offset 顺序处理
```

实现要点：

1. **生产者设置 key**：用 `userId`、`orderId`、`tenantId` 这类需要保序的业务 key 作为 message key，而不是随机 key。
2. **不要跨分区处理同一 key**：同一用户的事件必须稳定路由到同一 partition，否则顺序边界被破坏。
3. **消费者单分区顺序处理**：同一 partition 内不要把消息随意扔进多线程并发处理；如果要并发，可以按 key 做串行队列。
4. **处理成功后再提交 offset**：否则失败重启后可能跳过未处理事件。
5. **业务幂等兜底**：重试、rebalance、超时都可能导致重复消费，状态更新要能重复执行。

## 3. 为什么全局唯一 ID 不能解决顺序消费

给每条消息生成全局唯一 ID 可以用于幂等、追踪和去重，但它不能天然提高 Kafka 的顺序消费能力。

原因：

1. Kafka 的消费顺序由 partition log 的 offset 决定，不由消息 ID 决定。
2. 如果为了全局顺序把所有消息都放进一个 partition，吞吐会退化为单分区。
3. 如果消息分散到多个 partition，即使 ID 全局递增，消费者也很难在不等待其他分区的情况下按全局 ID 合并输出。
4. 全局递增 ID 生成本身可能引入中心化依赖或额外协调成本。

所以实际工程更常做“局部有序”：按用户、订单、会话、设备等业务 key 保证同一实体内有序，而不是追求全局有序。

## 4. 可能破坏顺序的场景

1. 生产者未指定 key，同一用户消息被轮询到不同 partition。
2. 同一 partition 的消息被消费者内部多线程并发处理，完成顺序和拉取顺序不一致。
3. 失败消息跳过或进入重试 topic 后，后续消息先被处理。
4. rebalance 发生时，旧消费者未提交完成，新消费者接管后重复消费。
5. 生产者重试配置不当，旧批次重试成功晚于新批次。
6. 修改 partition 数后，`hash(key) % partitionCount` 结果变化，后续同一 key 可能进入新 partition。

## 5. 面试回答模板

Kafka 只能保证单个 partition 内有序，不能保证 topic 全局有序。因为同一 partition 是追加日志，消息有递增 offset，同一个 consumer group 内一个 partition 同一时刻只会被一个 consumer 消费。要保证同一个用户的事件有序，我会让生产者用 `userId` 作为 message key，使同一用户稳定进入同一个 partition；消费者按 partition 顺序处理，处理成功后再提交 offset。如果消费者内部要并发，也要按 userId 做串行化，不能让同一用户事件并发乱序。全局唯一 ID 适合追踪和幂等，不适合用来强行保证全局顺序；追求全局顺序通常会牺牲分区并行度和吞吐。
